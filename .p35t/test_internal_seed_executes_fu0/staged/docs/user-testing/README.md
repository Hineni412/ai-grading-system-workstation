# P3.5 用户实际体验与讨论

P3.5 暂停推进 Phase 4，集中改进当前前端。验收以用户亲自操作实际页面、说明感受并与 Codex 讨论为主，不再沿用 Phase 1/2 的版本化门槛清单。

## 每批怎么进行

每批聚焦一组直接相关的界面改进：

1. Codex 简要说明这批改了什么、哪些页面可看，以及是否存在数据、费用或删除风险。
2. Codex 准备可访问的页面并给出地址；启动或构建只是为了展示页面，不是验收门槛。
3. 用户完成 3–7 个真实任务，例如找到一场考试、查看一份答卷、调整一个筛选、确认一条评分或返回上一层。
4. 用户边操作边说明哪里清楚、哪里别扭、哪里希望调整；不需要逐控件对照旧界面。
5. 本批结束时，用户明确回复“满意”或“有问题”，有问题时说明实际阻碍或希望变化的方向。

下一批根据讨论继续调整。没有必要为了形成文档而重复已经确认的操作。

## 用户负责什么

- 使用自己平时会采用的操作顺序完成真实任务；
- 判断页面是否容易理解、效率是否合适、信息是否好找；
- 发现问题时说明“正在做什么、看到了什么、希望怎样”；
- 每批明确给出“满意”或“有问题”。

用户不需要运行命令、检查代码提交、阅读日志、判断自动测试，也不需要编辑 Markdown。

## Codex 负责什么

- 准备并关闭本次展示页面；
- 说明改动范围和可能影响；
- 把用户反馈整理为下一批可执行修改；
- 遇到异常时先说明是否需要停止，以及数据是否受到影响；
- P3.5 默认不运行代码复审或自动测试；只在展示真实页面所需时启动服务或执行构建。
- 如果排查某个具体故障确实需要专项诊断，先说明目的并由用户决定是否运行。

## 不再要求的流程

P3.5 前端体验改进默认不要求：

- 为每批创建版本化 checkpoint；
- 绑定验收 SHA 或维护机器结果块；
- 在用户查看前完成代码复审；
- 运行固定的全量或五视口自动测试；
- 把启动、构建、lint、typecheck 或测试数字写成用户通过条件；
- 逐屏、逐控件、逐点击复刻旧 Streamlit 或历史 Vue 页面。

启动或构建可以在准备页面时使用；代码复审和自动测试不会自行恢复。专项诊断只有在用户另行同意后才运行，
并且不能代替用户实际操作和讨论。

## 数据、费用与不可逆操作

界面浏览和普通无副作用操作可以直接进行。以下行为每次都必须由用户针对本次操作明确授权：

- 读取或写入真实业务数据；
- 发起可能产生费用的模型调用；
- 删除学生、考试、题目、文件或其他业务记录；
- 执行不可逆迁移、覆盖或清理；
- 使用真实答卷、姓名、密钥或未脱敏材料。

以前的授权、历史验收通过或“继续修改前端”的决定，都不能自动扩大为上述授权。

需要真实数据时，Codex 先说明使用原件还是副本、可能改变什么、如何备份和如何停止。出现真实数据误用、意外费用、数据损坏或删除目标不清楚时立即停止。

## 反馈方式

正常反馈可以很简短：

```text
满意：现在能直接看到待复核题目，返回也很自然。
```

或：

```text
有问题：我在找整班批改入口时绕了两层，希望考试页面直接显示下一步。
```

截图可帮助说明问题，但如果包含姓名、答卷、密钥或其他敏感内容，应先脱敏；原始截图只用于当前排查，不提交 Git。

## 记录

需要保留讨论结果时，使用 `USER_TEST_TEMPLATE.md` 写一页简短记录。记录只服务后续修改，不是正式发布门槛，也不要求进入 `checkpoints/`。
