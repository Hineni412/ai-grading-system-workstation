# Worktree 与分支协作手册

本文只规定 P3.5 当前拓扑和未来正式 Phase 的最小 Git 安全规则。当前状态见 `EXECUTION_INDEX.md`。

## P3.5 固定拓扑

| 位置 | 职责 |
|---|---|
| 根目录 | 保持本地 `main`，不承载 P3.5 修改 |
| P3.5 worktree | 长期分支 `codex/p3.5-interactive-refinement`，承接用户全部改进批次 |

P3.5 不使用滚动执行包 worktree、短功能分支、integration worktree、三包里程碑或并行通道。未经用户明确授权，不创建第二条 P3.5 实现分支。

## 日常协作

1. 每批开始前确认当前目录仍在 `codex/p3.5-interactive-refinement`，并查看工作树中已有修改，避免覆盖用户或前一批未完成内容。
2. 用户逐批提出需求；同一 worktree 直接继续修改，不做执行包领取、交接块或 integration 转运。
3. 可以按需创建本地检查点提交，便于回退和保存进度；不要求每批单独提交。
4. 可以按需启动或构建应用给用户查看，但不把自动测试、构建或复审设为合并前门槛。
5. 用户提出新反馈时继续在同一分支调整；未经用户同意不扩张到 Phase 4。

## 最终收口

只有用户明确表示 P3.5 整体满意后，才按以下顺序收口：

1. 冻结新增需求。
2. 在同一长期分支做一次统一精简，只处理本阶段产生的明显重复、临时绕行和无用内容。
3. 启动或构建需要展示的最终版本，由用户进行最终人工确认。
4. 用户明确确认通过后，才允许 push 当前分支并创建以 `main` 为目标的 PR。
5. PR 合并后同步 `origin/main` 和本地 `main`；是否清理 P3.5 worktree/分支另行核对。

禁止直接 push `main`、force push，或在用户最终确认前把 P3.5 合入其他分支。

## 数据与破坏性操作

- P3.5 worktree 不应包含真实 `user_data/` 的本地副本、修改、暂存或 stash。
- 读取、复制、写入、迁移或删除真实业务数据前必须取得本次具体授权。
- 真实模型调用、费用、数据库迁移、永久删除和不可逆文件操作也必须逐次授权。
- 任何获准的高风险操作都要先确认精确目标、备份和回退；不得把真实数据或密钥写入 Git。

## 未来正式 Phase

用户明确恢复正式 Phase 后，再根据当时工作量选择最小拓扑：

- 单一工作项：一个短功能分支直接通过 PR 合入 `main`。
- 多个确实独立且需要组合验证的工作项：可建立独立短分支和一个临时 integration 分支。
- 文件所有权、依赖、测试和复审门槛在当次范围内冻结，不从 P3.5 或历史里程碑自动继承。
- 只有当前 Index 明确激活的正式 Phase 才能创建相应实现通道。

## 安全清理

删除或重新分配 worktree/分支前必须确认：

1. 工作树没有未知修改或真实数据项。
2. 独有提交已经进入 `origin/main`，或用户明确决定保留/丢弃。
3. 没有指向工作目录外部的 junction、symlink 或 reparse point。
4. 精确 worktree 路径已经核对。

满足条件后只使用 Git worktree 命令清理；禁止手工递归删除 linked worktree。
