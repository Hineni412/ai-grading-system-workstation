# 教师工作台视觉与可访问性原则

本文件只约束视觉语言、内容可读性和通用可访问性，不定义业务能力、导航结构、页面清单、字段、状态含义、权限、快捷键或操作流程。

P3.5 可以根据教师实际使用反馈重新组织布局、控件和交互。旧页面、历史验收卡、概念图和当前组件形态都不是必须复刻的模板；业务结果、数据语义和安全边界由现有代码、契约和用户决定约束。

## 1. 视觉方向

界面应当：

- 安静、专业、清楚、克制；
- 适合教师在 Windows 工作机上长时间使用；
- 信息密度高但不拥挤；
- 让试卷、答卷、评分证据和当前任务成为视觉重点；
- 通过字号、对齐、留白和分隔表达层级，而不是依赖装饰。

避免营销式大标题、蓝紫渐变、强阴影、卡片海洋、聊天气泡中心化、数据大屏风格和无关插画。

## 2. Token 与一致性

颜色、字号、间距、圆角、阴影和动效通过 `frontend/src/styles/tokens.css` 及主题映射集中管理。页面和组件不要反复写任意值；需要新增视觉值时，先判断能否复用现有 Token。

### 色彩

- 应用背景使用低干扰浅灰，主要内容表面保持清楚；
- 全局只保留一个主要强调色；
- 正文使用高对比深灰，辅助文字仍须可读；
- 成功、警告、危险和信息色只表达对应语义；
- 状态不得只靠颜色区分；
- 不使用大面积高饱和背景或装饰性渐变。

### 字体

优先使用：

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei",
  "Noto Sans CJK SC", system-ui, -apple-system, BlinkMacSystemFont,
  "Segoe UI", sans-serif;
```

- 页面标题通常为 22–24px；
- 区块标题通常为 18–20px；
- 面板标题通常为 15–16px；
- 默认正文为 14px；
- 高密度数据可使用 13px；
- 辅助文字可使用 12px，但不应承担大段正文。

正文行高通常为 1.5，长内容可放宽到 1.7。日常工作页不使用挤压工作空间的超大标题。

### 间距、边界和表面

- 优先使用 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48` 的间距层级；
- 同组内容靠较小间距和稳定对齐关联，区块之间使用更清楚的分隔；
- 普通面板使用轻边框和小圆角；
- 阴影只用于菜单、浮层、模态框或拖拽对象；
- 不要把每段说明、统计或表单都包装成独立卡片；
- 留白应帮助理解分组，而不是单纯减少可用工作面积。

## 3. 内容层级

- 主要工作内容获得最大可用面积和最清楚的对比；
- 辅助信息通过轻背景、窄分隔或较弱文字层级呈现；
- 风险和确认结果只在需要时使用语义色；
- 同一操作区通常只有一个视觉主按钮；
- 长中文、长文件名、长反馈和极端数字不能破坏布局；
- 重要信息不能只在 hover 中出现。

采用一栏、两栏、三栏、侧栏、抽屉或弹窗，由当前任务和用户反馈决定。本文件不固定页面几何结构，也不要求沿用旧布局。

## 4. 控件

### 按钮

- 主、次、危险操作有清楚层级；
- 加载、禁用、聚焦和按下状态可辨认；
- 按钮文字具体，图标不作为唯一说明；
- 危险操作不能因视觉弱化而被误触。

### 输入

- 标签常驻，placeholder 只作示例；
- 焦点、错误和禁用外观保持一致；
- 错误说明靠近对应字段；
- 长文本保持可读行高，不使用过小固定区域。

### 标签与状态

- 使用低饱和背景和清楚文字；
- 普通属性不全部做成彩色胶囊；
- 状态同时提供文字、图标或形状信息；
- 同一数据行避免堆叠过多醒目标记。

### 表格与高密度列表

- 表头和数据列严格对齐，行高稳定；
- 选中、悬停、聚焦和禁用状态可区分；
- 长内容若被截断，要明确仍有更多内容；
- 行内操作保持克制；
- 加载、空白和失败状态与内容区域对齐。

### 浮层

- 标题、内容和操作之间不能互相遮挡；
- 关闭控件和键盘焦点清楚；
- 多个浮层同时出现时保持明确层级；
- 是否使用浮层、能否嵌套及关闭后的业务结果由当前功能设计决定。

## 5. 图像、文档和图表

### 图像与文档

- 试卷、答卷和扫描内容保持原始比例与清楚对比；
- 工具条和叠层不能遮住关键内容；
- 纸张边界清楚，但不使用舞台式强阴影；
- 失败、低清晰度或不可用状态提供文字说明。

### 图表

- 一个图回答一个清楚问题；
- 标题、单位、图例和数据标签层级一致；
- 不使用 3D、发光、装饰性渐变和无意义动画；
- 趋势、风险、空数据和小样本提供文字说明；
- 颜色不是唯一编码。

## 6. 可访问性

- 键盘焦点始终明显；
- 图标按钮具有可访问名称；
- 正文、控件和风险提示保持足够对比度；
- 状态不只靠颜色；
- 错误与对应字段在视觉上关联；
- 点击目标稳定，不因精简样式而过小；
- 图表有文字摘要，图像内容在工作流中可辨认；
- 尊重 `prefers-reduced-motion`。

动效只用于解释状态，通常控制在 80–240ms。禁止大面积弹跳、庆祝动画和持续背景动画。

## 7. 窗口与检查方式

当前产品面向 Windows 桌面浏览器。视觉修改首先在用户实际使用的窗口中讨论和调整。

不再默认要求每次修改都检查固定五个视口。只有改动可能影响页面宽度、共享布局、导航、长内容或紧凑桌面时，才补充有针对性的其他尺寸检查；具体尺寸和数量由本次改动决定。

无论窗口大小如何，都应避免：

- 意外的整页横向溢出；
- 文字、控件和数据列互相遮挡；
- 主要操作不可见或不可达；
- 固定区域遮住长内容；
- 加载、空白、错误、禁用和焦点状态不可读。

## 8. 视觉参考

视觉参考只可帮助判断颜色、字体、密度、间距、边界、圆角、阴影和控件外观。不得从参考图推导业务字段、按钮、状态、导航、快捷键、流程或未来功能。

无需在仓库长期保存完整概念图。若确需保留局部片段，应裁去导航、业务文案、示例数据和完整页面结构，并记录允许借鉴的视觉属性。

## 9. P3.5 讨论重点

与用户查看实际页面时，优先讨论：

- 第一眼能否看懂当前任务和主要操作；
- 内容是否清楚、紧凑且不压迫；
- 重要信息是否容易找到；
- 长时间使用是否舒适；
- 页面切换、返回和恢复是否自然；
- 哪些区域可以删减、合并、移动或重新表达。

用户对实际页面的感受是 P3.5 视觉改进的主要输入。符合本文件不等于用户满意，用户满意也不允许降低数据安全或业务结果的正确性。
