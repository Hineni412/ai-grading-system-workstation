# 本机存储与维护策略

本文件说明当前数据放在哪里、默认保留什么，以及执行审计、归档或去重前必须遵守的授权流程。路径描述来自代码约定；阅读本文件不需要也不得打开真实 `user_data/`。

## 随源码分发的知识资料

`question_bank/taxonomy/catalogs/` 保存随代码分发的知识标准、受控词表、技能定义与来源快照。加载器按修订号选择配对文件，旧文件仍用于构建链和兼容读取，不能因版本较小删除。五维定义修订保留原词条编号与停用状态；新修订不在启动时自动覆盖已有活动标准。

生成资料通过 `tools/build_release_v3.py` 的共用写文件函数输出：较短记录同一行，较长结构保持缩进。此排版保留全部字段、顺序和字符串；知识发布的内容哈希按规范化 JSON 计算，排版空白不改变发布身份。外部来源快照及人工编写的技能定义保留原格式。

## 开发目录中的隐藏文件夹

`.` 开头表示目录名称的习惯，不表示目录一定是缓存。以下目录是否存在取决于本机开发与测试情况。

| 目录 | 用途 | 清理条件 |
|---|---|---|
| `.git/` | Git 历史、提交索引、分支和仓库设置 | 保留；删除会失去本地版本管理与恢复能力 |
| `.github/` | GitHub 自动检查、贡献指南、Issue 与 PR 模板 | 保留；属于项目源码 |
| `.agents/` | 项目内代理技能目录 | 不影响应用启动；先确认没有自定义技能或链接 |
| `.codex_artifacts/`、`.codex-review/` | 本机调查、原型、文档及图片材料 | 逐项核对独有资料与链接，不能当作普通缓存整目录删除 |
| `.p35t/` | 旧的隔离测试与代码副本 | 先检查数据库、独有文件与使用状态 |
| `.playwright/` | 本机浏览器测试工具配置 | 需要使用该配置时保留；删除后须重新设置 |
| `.playwright-cli/` | 浏览器操作留下的页面快照与日志 | 工具空闲、无需继续排错时可清理；可能包含页面内容 |
| `.portable_runtime_cache/` | 便携 Python 构建缓存，可能链接到正式运行时 | 先确认真实路径与链接；不能递归清理链接指向的运行时 |
| `.pytest_cache/` | pytest 的失败记录与测试索引 | 测试结束后可清理，下次自动生成 |
| `.ruff_cache/` | Python 静态检查缓存 | 检查结束后可清理，下次自动生成 |
| `.test-runs/` | 当前及历史合成测试沙箱 | 先确认无活动测试，核对数据库、未知脚本与目录链接；不能整目录盲删 |
| `.tmp/` | 项目临时目录 | 空目录可移除；非空时先确认文件归属和使用状态 |

清理这些目录仍按 `AGENTS.md` 的授权要求执行。忽略文件中的排除规则只限制 Git 跟踪，不会自动删除本地文件。

## 数据类别

| 类别 | 默认位置 | 当前用途 | 默认处理 |
|---|---|---|---|
| 核心数据库 | `user_data/databases/` | 考试、批改、题库等正式状态 | 始终保留，不参与自动归档或去重 |
| 原始业务文件 | `user_data/exams/`、`user_data/templates/`、`user_data/question_bank/` | 试卷、样卷、模板、题库原件及衍生素材 | 原件默认保留；只有明确可再生成的副本才进入维护候选 |
| 题库导入暂存 | `user_data/question_bank/import_staging/` | 上传副本、上传说明和重试请求 | 完整导入或匹配已有试卷后，上传说明改为引用 `raw_papers/` 内已核对的正式原件，再回收上传副本；保留小型说明和请求记录；失败、取消、待 OCR 或不完整导入保留上传副本 |
| 知识标准与标签任务资料 | `user_data/question_bank/` 下的 `knowledge_releases/`、`chapter_type_runs/` | 配对发布文件、整理请求正文、刷新对照、回执与只读摘要；活动库内同时保存不可变标准和词表 | 业务资料，普通备份及恢复包含；不由代码更新覆盖，不按缓存淘汰 |
| 批注残留与导出 | `user_data/cache/annotated_pages/`、`user_data/annotated/`、`user_data/reports/` | 旧版本生成的批注图残留、成绩表和报告 | 批注图已不再生成，两处旧图由教师在设置页明确清理；导出保留门槛见下 |
| 本地学情快照 | `user_data/reports/.training_diagnosis/entries/`、`user_data/reports/.training_diagnosis/recent_requests.json` | 已有考试与训练记录计算出的逐生诊断、群体汇总、概览、图谱、含小组的完整诊断公开响应、班级组卷的考试证据与候选结果，以及后台刷新重放的最近请求记录，供重启后首次读取 | 每个请求一份 `.entry` 文件，目录最多 240 份且总量不超过 512 MiB，超出时删除最旧文件；磁盘结果以低等级无损压缩减少重复内容，完整公开响应沿用已有压缩；读取后按原始大小计入内存上限，重复命中不再解压；小组还核对全部设置、日期和题目资源元数据；旧缓存标识、废弃概览版本、来源版本或自然周失效的结果由空闲后台回收，小组结果还按日期与素材状态回收；无法核实来源时保留，下次再检查；早期单文件 `profiles.cache` 不再使用，可手动删除 |
| 题库技能读取缓存 | `user_data/cache/question_bank_skills.cache` | 当前题库技能投影，每题版本号与次序键（用于只重算版本变化题目并跨重启增量合并）；兼容输入仍可含历史正文摘要，普通读取不重算正文哈希，供应用重启后恢复浏览统计 | 应用读取时保存，单文件上限 16 MiB；数据库、计算规则或素材状态不符时重新校验并计算，文件损坏或保存失败不阻断读取；不进入普通业务备份，不删除题库原件 |
| 章节考情缓存 | `user_data/cache/chapter_exam_profiles.cache` | 题库按册统计的章节考情、同源卷组和典型题引用，供重启后首次试卷评价与题库考情读取复用；不含学生成绩 | 完整册读取时保存，最多 8 册且单文件不超过 16 MiB；核对本册题目版本、贡献试卷资料和共享标准版本，无关册的题目修改不使本册失效；试卷评价只准备涉及小节的结果，优先复用完整册缓存，部分结果仅保留在现有进程缓存中；旧整库版本条目在原来源仍有效时继续命中；缺失、损坏、超限或来源变化时重算，保存失败不阻断读取 |
| 试卷评价缓存 | `user_data/cache/paper_reviews/` | 每场考试的试卷评价计算结果（逐题与班级汇总，不含学生姓名与逐生分数），供重启后首次打开直接显示 | 每场一份 `.entry` 文件，最多 64 份且总量不超过 64 MiB；核对成绩、题库材料与训练证据域，以及错因状态、评分标准、证据快照和计算代码；任务进度与训练草稿不使结果失效；可安全删除 |
| 页面上次结果 | `user_data/reports/.training_diagnosis/last_display/` | 各只读接口最近一次返回给页面的结果及其来源版本 | 每个请求一份 `.entry` 文件，正文压缩保存，最多 128 份且总量不超过 256 MiB；来源版本仍有效时直接复用，来源改变或旧条目没有版本时先等最多 1 秒，已完成则直接返回新结果，否则显示旧结果并继续后台重算；小组还核对素材清单和日期；超出容量删除最旧文件，缺少条目时等待首次计算 |
| 场次错因缓存 | `user_data/reports/.training_diagnosis/sessions/` | 每场考试已校验的学生错因记录，供诊断与组卷跨重启复用 | 每场一份 `.entry` 文件，最多 64 份且总量不超过 256 MiB，超出时删除最旧文件；磁盘结果以低等级无损压缩保存；旧标识、已删除场次及输入失效的结果由空闲后台回收；可安全删除，删除后按原流程重新计算 |
| 推荐候选池缓存 | `user_data/cache/recommendation_pools/` | 全库候选池快照及去重前每题条目，供重启后首个推荐复用及按题增量合并 | 每份池一份 `.entry` 文件，最多 16 份且总量不超过 512 MiB；优先核对共享输入版本与每题版本号，仅版本变化的题重算；版本覆盖可用时不扫描素材目录，覆盖缺失时回退到文件状态；题库内容、技能素材或计算状态不符时重算；空闲后台回收当前读取器不能使用的旧整体版本格式及全局版本过期条目，逐题版本变化的条目保留用于增量合并，无法确认来源的条目保留；可免费重算 |
| 题目身份摘要缓存 | `user_data/cache/question_identity.cache` | 题干图片像素摘要、公式规范化结果、候选图片字节摘要，以及合格候选的整题判重标识和图片身份，供查重与推荐身份计算跨重启复用；不保存图片正文 | 单文件最多 20 万项，超出时删除最旧项；单素材摘要按来源文件状态复用，整题候选身份按已有题目版本、更新时间和精确去重标识复用，同题新版本替换旧版本；缺失时补算，保存失败不阻断读取；采用、冻结与导出仍读取完整资料；可安全删除 |
| 临时与工具输出 | `user_data/temp/`、`user_data/outputs/` | 临时文件、基准和比较结果 | 达到保留门槛后只列为候选，不自动删除 |
| 备份与归档 | `user_data/backups/`、`user_data/archives/` | 数据库快照、完整备份和维护工具生成的压缩包 | 自动完整备份只保留最新 3 份；手动备份不自动删除，教师可在恢复列表逐份删除；归档只建副本不删原件 |
| 保护操作暂存 | `user_data/runtime_state/ops/operations/<编号>/staging/` | 更新、恢复、导入的暂存文件与更新前数据库副本（`migration-backups/`） | 操作成功应用后删除更早已结束操作的暂存，只保留最近一次；失败的操作保留暂存供人工恢复；操作记录本身保留 |
| 配置与密钥 | `user_data/config/`、`%LOCALAPPDATA%\AIGradingSystem\config\` | 上传配置、本机设置和模型 profile；`运行.bat` 默认把 API profile 放在前一个目录 | 视为敏感配置，不进入项目仓库或业务导出 |
| 敏感模型诊断 | `logs/llm_diagnostics.jsonl*` | 本机排错所需的请求与响应正文 | 受控查看、限量轮转，不进入 Git |

学情、场次错因和推荐池等 `.entry` 文件共用现有持久条目读取器。同一文件被替换或由读取器淘汰时，释放该文件旧修订的解析对象。每个读取器的解析缓存最多 512 项，按条目文件字节数估计的保留量不超过磁盘字节上限与 32 MiB 两者的较小值；这不是实际进程内存上限。超出该预算的单条文件仍可读取，但不保留解析缓存。磁盘保留规则不变。

新条目文件名以 `v2-` 开头，按请求值生成，不依赖字符串或容器是否共用同一个内存对象。兼容输入：旧文件先按原文件名查找，未命中时按条目保存的请求值建立进程内索引；兼容读取不移动或重写文件。新写入使用稳定文件名，旧文件继续受原容量上限及失效维护约束。

章节分组的初始匹配使用进程内 ResultCache，最多保留一份且序列化数据不超过 64 MiB；容量不等于整个进程的内存上限。新输入替换旧输入，超大结果不保留但可供已等待的同键请求使用，各请求解码为独立对象。此缓存不写入 `user_data` 或其他文件，应用重启后重新建立。题数、每项技能题数和解答题数量调整可共用匹配；其他匹配输入、知识发布或题库数据版本变化后重算。

试卷评价的进程内结果复用同一 ResultCache，最多 8 份、序列化结果不超过 32 MiB，不另写文件。浏览器内存保留最多 8 个诊断范围与 16 个概览范围；题库按已有册别保留有效索引、章节考情、参照摘要和补齐预览。成功写入与已跟踪任务结束后使相关浏览器结果失效；退出页面不会把这些结果另存为正文副本。

学情计算与场次错因缓存的维护复用后台预热线程：启动、来源版本或日期变化后检查，并在空闲时每小时检查一次。逐文件检查前让出前台读取、页面刷新和排队或运行中的任务；中断后下轮继续，不在页面刷新请求中扫描目录。维护只读取已有数据库版本和文件状态，不复制数据库，不计算掌握度，不调用模型。

有效旧缓存在空闲时改存为紧凑格式。小于 4 KiB 或压缩节省不足 10% 的结果保留原格式，避免重复压缩已有压缩响应。旧格式仍可读取，写入采用临时文件与原子替换；失败保留原文件，读取失败按原流程重建。页面上次结果继续保留，用于新结果准备期间的显示。上述缓存均可免费重算，不另建缓存备份；原始 Word、正式数据和已付费报告正文不参与此维护。

## 读取与保存版本

名单、考试删除预演和成绩导入使用已有数据库版本；题目编辑使用每题版本；组卷草稿保存递增修订号。配置使用已有文件的修改时间与大小，样卷模板使用按正反面排序的不可变版本路径。图谱响应使用知识发布、数据域和范围版本，掌握度参数直接使用参数值。这些标识只用于比较是否变化，不重新计算正文哈希。

配置素材在激活写入时核对内容，普通查看不重复计算素材哈希。题库去重标识写入后复用，原件与题目富文本由导入流程管理；直接在应用外修改这些素材不属于支持的编辑流程。内容哈希仍用于去重、模型输入复用和已有跨数据库交接。历史预测错法保留旧来源识别，新预测使用保存的来源状态，答案写入同步失效标记。

兼容输入：部分数据库列和 API 字段仍沿用 `fingerprint` 或 `command_hash` 名称。已停用的本地操作哈希列只写兼容占位值，不参与判断；已有草稿、冻结卷和已付费分析不因此改写。旧付费模板绑定仍可按历史格式读取。运维预演改用文件更新时间与大小后，旧待执行计划须重新预演；备份、恢复与回退记录仍保留。

## 默认保留规则

维护工具的保留门槛只用于生成“待确认候选”。下载副本按以下规则回收：

- 核心数据库、样卷/模板/题库原件默认一直保留。
- 答卷扫描增强成功后只保留工作图，不再另存未处理原图。
- 样卷上传只保留必要的正反面图、分析资料与来源标识，不再额外保存全班 PDF 副本。
- 系统不再生成复核批注图。此前生成的 `cache/annotated_pages/session_N/` 与 `annotated/session_N/*_annotated.jpg` 不自动删除；教师在设置页“AI 与数据”中普通确认后一并清理，相关旧路径同时置空。数据库中的旧路径引用仅用于清理与统计，不再用于查看。
- 成绩表、批注原卷 PDF、教师额外导出的训练 zip/docx/md、讲义和错题本 Word/ZIP 下载成功后删除本机副本，需要时再生成；生成批注原卷 PDF 所用的逐生页面图在 PDF 生成后即删除；讲义临时文件位于报告目录的 `training_handouts/`，错题本位于 `wrong_question_books/`。
- 可重新生成的任务下载副本，在任务完成和文件最后修改均超过 7 天后自动回收，包括上述导出及新的个人报告批量导出；历史个人报告 HTML、组卷导出、备份和数据迁移包不适用。应用启动后检查一次，此后每小时检查，不在页面刷新时扫描；文件占用导致删除失败时保留引用，下次重试。
- 在线个人报告直接读取已有叙述和原卷裁切，不新增持久文件。叙述位于 `reports/.personal_reports/session_<场次>/<学生>.json`，每名学生保存一份最新叙述（含输入指纹、提示词版本与生成时间），查看不写文件。旧版键值缓存目录已在升级时迁入该目录并删除；一次性迁移备份保留在 `reports/backup/report-results-*/`。
- 新的个人报告批量导出副本位于 `reports/personal_report_bundles/job-N/`，HTML 或 ZIP 下载成功后删除，需要时只读缓存再次导出；历史留存的个人报告 ZIP 保持原规则，可重复下载，由教师明确删除。只生成叙述的任务结束时回收暂存 HTML，不进入文件历史。
- 个性化训练每人保留一份冻结 PDF，供打印和回收扫描，不因下载删除。
- 训练批次的 `papers.zip` 和 `frozen-papers.zip` 下载后回收，未下载的 ZIP 在最后修改超过 7 天后回收；删除前核对包内清单所列原 Word 或 PDF 是否仍在，审核稿还要求原批次清单与包内清单相同，缺失时保留 ZIP。重新下载时利用保留的逐人 Word、冻结 PDF 和批次清单重新打包，不重新选题、不调用模型。批次清单、逐人文件及历史实例继续保留。
- `user_data/outputs/` 中 `benchmark_*` 目录超过 7 天、名称含 `comparison` 的目录超过 14 天后可列为归档候选。
- `user_data/temp/` 中超过 1 天的项目可列为归档候选。
- 更新、导入、恢复、应用前及考试前后的自动完整备份只保留最新 3 份：新自动备份发布成功或受保护操作成功应用后，删除更旧的自动备份；有待执行的受保护操作时不删除任何备份。手动备份不会自动删除，教师可在“从备份恢复”列表中经普通确认逐份删除。
- `grading_before_*.db` 快照至少保留最新 20 份；只有排在其后且超过 14 天的快照才列为候选。
- 模型诊断日志单文件约 32 MiB 时轮转，保留当前文件和最近 3 个轮转文件。

当前归档操作只在 `user_data/archives/` 创建 ZIP 副本，不删除原文件。是否随后删除原件必须作为另一项精确操作单独设计并另行授权。

## 教师主动清理原卷

设置页“AI 与数据”只读统计 `user_data/` 内受控文件的逻辑字节数，并列出各场考试的扫描文件、页面及旧批注图残留。统计不包含程序、开发输出和测试沙箱；同一内容若由多个硬链接路径引用，仍按每条路径计入，数值不代表磁盘实际分配量。暂时无法读取的文件夹不计入汇总，并显示统计未包含这些文件的提示。页面分类依次为学生原卷、题库资料、报告与导出、缓存、备份、更新前副本、数据库、其他；缓存指 `cache/` 全部、`temp/` 与 `reports/.training_diagnosis/`，更新前副本指 `runtime_state/ops/operations/` 下各操作的 `staging/` 目录。存在运行任务、未匹配答卷、没有成绩或正在替换答卷时，列表中即显示不能清理；是否有未完成复核在教师打开清理确认时核对并显示原因，提交清理时仍强制拦截。

- “释放扫描文件”使用普通确认，只删除已完整拆成页面的扫描 PDF 和无人读取的全班样卷 PDF 副本；未完成拆页的 PDF 保留。页面图、配置、成绩和作答 JSON 保留，AI 续跑、重试和补批仍可使用已有页面，重新扫描归卷停止。
- “清除原卷”要求输入“确认清除”，删除该考试受控目录内的原卷 PDF、页面图和批注图；保留正反面样卷、题框、作答 JSON、评分明细、成绩与教师最终分锁。清理后允许教师改分及生成数据报告；原卷查看、裁剪、AI 批改和批注原卷导出停止。
- 清理前展示最近 ZIP 备份时间，并核对备份是否晚于本场答卷写入和扫描释放时间。只有归档中包含本场当前待清理的全部扫描文件和原卷页面，且路径、大小及文件修改时间符合时，才提示备份覆盖原卷；可再生成的批注图不计入覆盖范围。归档缺失、损坏或只含部分文件时不作覆盖保证；覆盖结果不作为强制拦截。立即备份无输入确认；恢复备份保留“确认恢复”的文字保护。
- 不删除其他考试引用的文件、不跟随符号链接或 Windows 目录联接、不处理数据根目录外文件。清理进度以原子替换方式记录在 `exams/session_N/originals_receipt.json`；中断时保持“清理中”，重新确认可继续，重复完成请求不再删除文件。回执损坏时按“清理中”保护。
- 清理期间和完成后媒体请求返回明确的不可用状态；界面保留作答与分数，不反复加载已删除的图片。替换答卷成功后重置本场清理回执。

## 草稿正文与维护工具去重

训练推荐草稿按草稿编号与修订号保存一份固定 JSON 正文，不压缩正文。主记录引用当前修订，历史事件引用当时的修订并保留编辑差异；再次提交生成请求仍复用已有草稿，读取当前修订。旧库通过受保护迁移转存正文并移除重复字段；同一修订存在不同正文时中止并回滚，不择一覆盖。SQLite 回收出的空页可供后续写入复用，数据库文件不会仅因删除重复字段就立即缩小。

维护工具的文件去重只使用硬链接：两个路径仍然存在，但在同一磁盘上共用一份相同内容。当前工具只为同时满足以下条件的文件生成候选：

- 位于 `annotated`、`templates`、`reports` 或 `exams` 顶层目录；
- 扩展名为 `.jpg`、`.jpeg`、`.png` 或 `.pdf`；
- 文件大小至少 128 KiB，且最近 24 小时未修改；
- 位于同一磁盘，内容指纹完全一致；
- 不在 `databases` 或 `config` 目录中。

数据库、JSON、YAML、配置文件、最近修改的文件和跨磁盘文件不参与维护工具的硬链接去重。硬链接会改变重复文件的底层存储关系，因此即使内容不变，也属于真实数据写入操作。

## 备份与维护入口

- 普通备份由 `update_tools/backup_core.py` 实现，范围为 grading（阅卷及题库）；排除模型密钥、诊断日志、SQLite 临时文件，以及可免费重算的 `reports/.training_diagnosis/` 学情缓存和 `question_bank/personalized_papers/image_cache/` 排版图片缓存；已保存的个人报告正文、教师修改、题库原件与冻结训练资料继续包含。完整安装包包含数据与密钥，不能当作普通备份分发，见 `docs/maintenance/packaging.md`；单条数据删除不会追溯删除已有备份副本。
- 词表状态虽可位于账户配置目录，普通备份仍明确包含状态主文件、其 `.bak`、审核回执、建议记录及技能候选记录，归档成员固定为 `config/taxonomy-governance/` 下的五个文件；离线恢复与恢复前安全备份均把这些成员映射到本机 `taxonomy_state_path` 及配套文件，不复制相邻的模型密钥；兼容输入：旧备份没有这些成员时不改变现有词表状态。
- `tools/maintain_question_bank.py` 统一题库定期维护：`errors --sessions 3 4 5` 在副本上预演既有考试错因回挂，只接纳与当前证据匹配的成果，重复执行不重复记录；`standard --release <发布文件>` 预演标准变化和受影响题目。
- `tools/maintain_question_bank.py source-scores` 在真实题库原位置只读预览题干开头分值的显示差异，复用显示与导出规则；只输出题目计数、分值标记差异、格式结构核对、按原文保留作答空间的数量及已有分析记录数量，不保存题干正文、不调用模型、不复制数据库。该操作不支持 `--apply`，不修改历史题目、答案、富内容或分析版本。
- 标准修订的 `--links <关联文件>` 是数组，每项含 `question_id`、`evidence_version_id` 和完整 `points`；各点含 `part_id`、`evidence_point_id`、`links`，每个链接含 `term_id`、`stable_key`、`role` 和可选 `weight`；必须覆盖全部受影响题及其当前判定点，未变化题不能夹带进来；生成或人工整理这些关联仍沿用既有版本工具。
- 上述错因和标准维护默认只读取真实数据库，在临时副本上预演，不调用模型；正式执行需先关闭应用并取得本次批量操作授权，添加 `--apply` 后先在 `user_data/backups/question_maintenance_<时间>/question_bank_before.db` 创建题库快照，再执行、检查数据库完整性和引用；考试库、原答卷、分数及场次分析文件不改写。
- 标准先准备候选关联再启用；执行中断时保留快照及已完成记录，错因回挂可幂等续跑，标准失败需先核对活动版本和候选记录再重试；恢复覆盖快照按 `AGENTS.md` 另行授权；既有一次性脚本不自动归档或删除。

以下工具会读取真实数据：只读审计和预览自动允许；向 `user_data` 写入结果、应用硬链接或归档等改变真实数据状态的操作仍按 `AGENTS.md` 授权；预览不等于批准应用。

| 工具与参数 | 作用 |
|---|---|
| `tools/storage_audit.py`，--root . | 审计并将报告写入 user_data/reports/storage_audit/ |
| `tools/storage_maintenance.py`，--root . | 仅打印维护计划 |
| 同上，加 --apply-hardlinks | 按候选执行硬链接去重 |
| 同上，加 --apply-archives | 创建归档 ZIP，不删除原件 |

使用项目便携 Python 执行。应用前核对精确候选；删除原件属于另一个操作，不包含在归档内。
