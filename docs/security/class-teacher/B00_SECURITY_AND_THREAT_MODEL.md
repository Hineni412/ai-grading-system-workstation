# B00 安全、加密、威胁与恢复规格

> 2026-08-02 调试覆盖：用户已明确接受调试期明文、无 PIN/锁定、进入普通备份与普通模型诊断的风险。本规格保留为恢复隐私保护时的目标基线，不描述当前生产 feature；当前唯一启用的隐私门是学生内容外发前的本机匿名预览与教师单击确认。见 [ADR-0007](../../adr/0007-use-plaintext-class-teacher-debug-mode.md)。

> 状态：用户已于 2026-07-30 确认，B00 通过
>
> 适用范围：班主任工作台 B01—B11
>
> 风险等级：高

## 1. 安全目标

即使普通备份泄露、数据库文件被复制、浏览器页面被恶意访问或应用异常退出，攻击者也不能从磁盘、日志、缓存和错误响应直接读取学生姓名、事务正文、观察、成绩、草稿或密钥。

本规格不承诺抵御已经完全控制 Windows 管理员权限、能够读取进程内存或安装键盘记录器的攻击者。对这类风险，系统通过缩短解锁时间、最少保留和离机备份降低影响，并明确提示残余风险。

## 2. 环境调查与冻结方案

2026-07-30 对当前便携运行环境的只读检查结果：

- Python 3.12.1；
- SQLite 3.43.1；
- 已有 `cryptography==49.0.0`；
- 没有 SQLCipher、`pysqlcipher3`、`sqlcipher3`、Argon2、PyNaCl 或系统 keyring；
- 当前 SQLite 不支持 `PRAGMA cipher_version`。

因此 B01 冻结为一套生产方案，不同时维护两套：

**随机保险箱主密钥 + 每对象内容密钥 + Scrypt 密码派生 + AES-256-GCM 字段/对象级认证加密。**

### 2.1 密钥层次

1. 初始化时生成 256 位随机保险箱主密钥 `VMK`；
2. 模块密码经 Scrypt 和随机盐派生密码包装密钥 `KEK-password`；
3. 离线恢复密钥经独立 Scrypt 参数和随机盐派生 `KEK-recovery`；
4. `VMK` 分别由两个 KEK 认证加密包裹；
5. 每个学生、事务或独立敏感对象使用随机内容密钥 `CEK`；`CEK` 由 `VMK` 包裹；
6. 修改密码只重新包裹 `VMK`；
7. `VMK` 和正在使用的 `CEK` 只在解锁会话内存中存在，锁定时清除引用和缓存；
8. 密码、恢复密钥、KEK 和明文 VMK/CEK 不写入磁盘、日志、错误或备份。

Scrypt 参数使用版本化配置。B01 首次实现以 `N=32768, r=8, p=1` 为最低基线，并在目标便携工作机上测量；只有在不低于该基线且单次派生约 250—750 毫秒时才可调整。参数和盐可以明文保存，派生结果不得保存。恢复密钥是高熵随机值，仍使用独立盐和版本，避免与密码包装材料混用。

### 2.2 数据加密

- 学生姓名、班级、事务正文、观察、判断、成绩、草稿、摘要和搜索材料全部使用 AES-256-GCM；
- 每个加密字段/对象使用独立随机 nonce；
- AAD 至少包含模块 ID、对象类型、对象 ID、字段名和格式版本，防止密文跨字段替换；
- 严禁 nonce 重用；
- 解密认证失败时停止读取并报告通用“数据完整性错误”，不返回半解密内容；
- 临时文件、导入区、导出区和恢复暂存区使用同一保护级别。
- 单个学生删除时销毁其专属 CEK 包装；多人事务把参与者专属陈述分别加密，共享事实使用事务 CEK；
- 删除会重新加密仍需保留且可能关联被删除学生的共享事实，并轮换事务 CEK。

### 2.3 可能可见的最小元数据

字段级加密不能隐藏 SQLite 文件存在、表结构和密文长度。允许明文存在的内容只限：

- 格式、Schema 和迁移版本；
- 随机盐、KDF 参数和包裹密钥密文；
- 随机内部对象 ID；
- 表示密文类别的非敏感代码；
- 密文长度和完整性版本；
- 不含学生身份的数据库健康标记。

姓名、班级、状态说明、时间线标题、正文、成绩、模型草稿和搜索词不得明文保存。若后续整库加密组件通过便携环境验证，可另立安全迁移任务；不得在 B01 中暗中切换方案。

## 3. 会话和浏览器边界

- 模块 API 默认锁定；
- 解锁令牌只适用于 `class-teacher`，不得复用全应用长期令牌；
- 令牌短时有效、绑定当前应用实例，并支持服务端立即失效；
- 闲置 5 分钟、程序关闭、服务重启、手动锁定或改密后全部旧令牌失效；
- 受保护响应使用 `Cache-Control: no-store`；
- 前端不把受保护正文写入 localStorage、IndexedDB、URL、路由参数或浏览器日志；
- 锁定时清空状态仓库、草稿、预览、虚拟列表、搜索结果和可返回的页面历史；
- 错误响应不包含学生姓名、正文、路径、SQL、密钥或密文；
- 只允许受信本机来源访问，严格校验 Origin/Host 和请求头；
- 对状态改变请求使用一次性操作 ID，避免重复点击。
- 敏感正文默认不提供通用复制/剪切和“复制整档”控件；确需复制最小片段时必须显式确认并显示系统剪贴板风险；
- 锁定时仅在浏览器许可且能确认剪贴板仍为本模块最近写入内容时尝试清除；无法安全清除时显示“请清空剪贴板并锁定 Windows”的提示，不声称已经清除。

## 4. 威胁模型

| 威胁 | 可实际发生的过程 | 影响 | 必须控制 | 残余风险 |
|---|---|---|---|---|
| 同机他人查看 | 教师离席，浏览器仍开着 | 看到学生正文 | 5 分钟自动锁定、手动锁定、页面缓存清理 | 5 分钟窗口内仍需教师锁屏 |
| 设备丢失或数据库被复制 | 他人复制工作目录或硬盘 | 批量泄露学生档案 | 所有敏感字段认证加密；无明文密钥 | 弱密码可能被离线猜测 |
| 密码暴力尝试 | 攻击者反复提交密码 | 解锁保险箱 | Scrypt、高强度长密码、递增延迟 | 拥有文件者仍可离线尝试，依赖密码强度 |
| 恢复密钥泄露 | 恢复纸张与电脑一起存放 | 绕过模块密码 | 初始化时提示离机保管；密钥不进备份 | 用户保管不当无法由软件完全阻止 |
| 恶意网页访问本地 API | 浏览器打开恶意网站向 localhost 请求 | 读取或修改数据 | Origin/Host 白名单、短时令牌、CORS 拒绝、操作 ID | 浏览器或系统已被完全控制时仍有风险 |
| 本机恶意程序 | 恶意程序读取磁盘或解锁进程内存 | 泄露密文或内存明文 | 磁盘加密、短时解锁、最少保留、不生成明文临时文件 | 管理员级恶意程序不在完整防御能力内 |
| 普通备份泄露 | 现有备份把 B 数据一起打包 | 大规模泄露 | F0/B01 备份预览排除；B 使用独立受控根 | 外部工具手工复制目录仍需用户保护 |
| 专用备份泄露 | `.ctbackup` 被复制 | 离线破解与数据泄露 | 备份全程密文、完整性校验、无明文密钥 | 弱密码和恢复密钥泄露仍有风险 |
| 日志泄露 | 异常把请求、响应或路径写入日志 | 敏感正文扩散 | 专用无正文诊断器、错误类别白名单、测试扫描 | 第三方库未知日志需持续验证 |
| 模型泄露 | 完整学生上下文被发送给外部模型 | 不可控外传和费用 | 默认关闭、字段白名单、预览、一次确认、零自动重试 | 教师在系统外自行复制无法由模块阻止 |
| 崩溃和断电 | 写入、备份或恢复中途终止 | 数据损坏或部分完成 | 原子事务、临时密文、启动恢复、原库后替换 | 存储介质物理故障依赖备份 |
| 重复操作 | 重复点击创建、模型调用或恢复 | 重复事务、重复费用、覆盖 | 操作 ID、幂等账本、恢复二次确认 | 跨设备多用户不在首版范围 |
| 两页同时修改 | 两个标签页修改同一记录 | 静默覆盖 | 版本号/ETag、冲突提示、人工合并 | 用户需处理冲突 |
| 删除不完整 | 主记录删了，摘要、旧页、WAL、CEK 包装或备份仍在 | 被删除学生仍可恢复 | 删除影响图、销毁专属 CEK、共享事务换钥、WAL 截断、原子重建、备份清单、核对报告 | 文件系统/SSD 底层取证擦除不作绝对承诺 |
| 截图和剪贴板 | 教师复制或截图敏感内容 | 系统外泄露 | 默认不提供整档复制、最小片段显式确认、可验证时清理剪贴板、明显隐私提示 | 操作系统截图和无法验证的剪贴板无法完全阻止 |

## 5. 故障与恢复规则

| 场景 | 预期结果 |
|---|---|
| 重复创建 | 同一操作 ID 只创建一个对象 |
| 两个页面同时保存 | 第二个保存收到版本冲突，不自动覆盖 |
| 写入中途退出 | 事务全部成功或全部失败，启动后不出现半条记录 |
| 重新启动 | 模块保持锁定；未完成密文暂存被安全清理或继续恢复 |
| 密码失败 | 只递增延迟；不泄露“密码错误还是数据损坏”，不删除数据 |
| 密码遗忘 | 使用离线恢复密钥解锁并设置新密码 |
| 密码和恢复密钥都遗失 | 明确不可恢复，不提供后门 |
| AI 失败、取消或超时 | 保留教师原始输入草稿；不自动重试，不产生第二次费用 |
| 专用备份中断 | 不发布不完整备份；删除临时密文 |
| 恢复中断 | 原库保持不变；隔离暂存可安全清理 |
| 完整性校验失败 | 拒绝恢复或读取；不以损坏数据覆盖现有库 |
| 删除中断 | 删除事务回滚；不得报告“已删除” |
| 删除后发现旧备份 | 显示未完成，不签发零残留报告 |
| 删除后 WAL/旧页仍有密文 | 销毁对象 CEK，执行 `wal_checkpoint(TRUNCATE)`，从存活逻辑记录原子重建数据库，再替换原库 |
| 模块改密后恢复旧备份 | 使用备份创建时设置的独立备份密码或稳定离线恢复密钥；当前模块密码不保证有效 |
| 其他实例的专用备份 | 显示源实例 ID 差异，只允许教师确认后完整替换，不自动合并 |
| 普通恢复包包含 B 数据 | 拒绝整个普通恢复，原数据不变，提示使用 B 专用恢复/交接流程 |
| 部分完成 | 明确保留未完成项，不伪装为完成 |
| 数据来源冲突 | 停止自动关联，等待教师选择 |
| 程序关闭 | 不提供后台提醒；紧急流程可从离线学校清单执行 |

## 6. 专用备份恢复演练

B11 最终验收至少演练：

1. 使用合成数据初始化保险箱；
2. 创建 `.ctbackup`；
3. 证明普通备份预览不包含 B 受保护根；
4. 证明用普通 SQLite 工具不能读出姓名和正文；
5. 使用错误密码恢复，确认不改变现有库；
6. 使用恢复密钥恢复到隔离暂存；
7. 中断恢复，确认原库完好；
8. 完整恢复并核对对象数、版本和密文完整性；
9. 删除一个合成学生，列出并处理受影响备份；
10. 证明学生专属 CEK 已销毁、WAL 已截断、原子重建后存活库中不存在可解密的被删对象；
11. 修改模块密码后，分别用旧备份密码和离线恢复密钥恢复旧备份；
12. 尝试恢复其他实例备份，确认不能静默合并；
13. 将含 B 标识的包送入普通恢复，确认整个恢复被拒绝；
14. 扫描普通日志、错误响应、缓存和临时目录，确认无合成敏感正文。

## 7. 上线前仍需逐次授权

- 安装新的整库加密组件或改变依赖；
- 读取或迁移真实学生数据；
- 创建、恢复或删除真实专用备份；
- 修改真实模块密码或恢复密钥；
- 调用真实模型或产生费用；
- 对真实数据执行删除、覆盖或恢复。
