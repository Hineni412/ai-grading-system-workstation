# 教师 AI 工作台前端设计规范

> 适用范围：AI 阅卷、人工复核、考试管理、成绩分析、题库、个性化训练，以及未来的教师智能体工作台。  
> 本文件约束视觉语言、信息层级和通用交互；业务流程、接口和代码架构仍须根据现有项目单独设计。

---

## 1. 最高原则

出现冲突时，按以下顺序处理：

1. 数据准确、评分安全、教师最终决策权；
2. 教师真实工作流与连续操作效率；
3. 可理解性、可访问性和错误恢复；
4. 本设计规范；
5. 参考产品的局部模式；
6. 装饰性效果。

参考产品只用于提取设计语言和局部交互，不用于直接复制页面结构。若参考界面与阅卷效率冲突，以教师业务为准。

---

## 2. 产品定位

### 2.1 当前产品

核心任务包括：

- 创建考试、导入试卷和学生名单；
- 答卷识别、切题和图像质量检查；
- AI 初评与人工复核；
- 处理低置信度、人机冲突和异常结果；
- 记录错因、知识点和评分修改；
- 查看班级、题目和学生分析；
- 根据薄弱知识点匹配题目并生成训练卷。

### 2.2 未来教师智能体工作台

教师智能体不能退化成“中央大聊天框”。AI 必须依附于明确上下文：

- 当前班级、考试、学生、题目；
- 当前批改任务和待办事项；
- 当前知识点和可执行动作。

AI 应嵌入工作流：解释误判、生成讲评、推荐训练题、检查评分标准、总结学生变化、执行经教师确认的批量操作。

---

## 3. 视觉定位

整体视觉关键词：

- 安静、专业、清晰、克制；
- 高信息密度但不拥挤；
- 适合教师长时间使用；
- 以工作区、任务和状态为中心；
- 教师判断始终高于 AI 建议。

本产品不是营销落地页、娱乐化产品、纯笔记工具，也不是聊天优先的通用 AI 产品。

### 核心体验原则

1. **一屏保留上下文**：尽量同时看到学生、题目、答卷、评分标准、AI 建议、教师最终分和下一步。
2. **连续处理优先**：避免多余跳转、深层弹窗和重复确认。
3. **异常优先暴露**：低置信度、裁剪异常、人机冲突和失败结果必须易于发现。
4. **稳定位置**：评分细则、最终分数、提交按钮等关键元素位置保持稳定。
5. **渐进式披露**：模型日志、完整技术细节放入二级区域。
6. **教师最终负责**：AI 结果必须标注为“建议”“初评”或“待确认”。

不要在同一页面明显拼贴所有参考产品。

## 5. 信息架构

建议一级导航不超过 7 项：

1. 工作台
2. 阅卷
3. 考试
4. 学生
5. 分析
6. 题库与训练
7. 智能体与自动化

设置、帮助和账号放在侧栏底部或用户菜单。

### 5.1 工作台

只展示能驱动行动的信息：今日待处理、进行中的阅卷、待复核、异常、最近考试、智能体待确认动作和重要班级变化。不要做成堆满图表的数据大屏。

### 5.2 阅卷

- 阅卷任务
- 单题批改
- 整卷复核
- 待人工复核
- 异常处理
- 已完成记录

### 5.3 分析

- 班级分析
- 题目分析
- 学生分析
- 知识点分析
- 错因分析
- 评分质量分析

### 5.4 题库与训练

- 题库
- 标签与知识点
- 试题审核
- 组卷
- 个性化训练
- 训练效果追踪

### 5.5 智能体与自动化

- 教师任务
- 智能体运行
- 待确认动作
- 自动化规则
- 执行记录
- 权限与风险设置

## 6. 应用外壳 App Shell

推荐桌面结构：

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部栏：面包屑 / 当前对象 / 搜索 / 全局动作 / 用户菜单     │
├────────────┬──────────────────────────────┬────────────────┤
│ 左侧导航   │ 中央主工作区                 │ 右侧检查器     │
│ 220–256px  │ 弹性宽度                     │ 320–400px      │
└────────────┴──────────────────────────────┴────────────────┘
```

### 顶部栏

- 高度 56–64px；
- 不放营销口号和超大标题；
- 显示当前位置和业务上下文；
- 页面主要操作可放在内容标题行。

### 左侧导航

- 默认约 232px，可收起至 56–64px；
- 当前选中清楚但不过度高亮；
- 数量徽标只用于真正需要注意的项目；
- 底部固定帮助、设置和账户入口。

### 中央工作区

- 是第一视觉重点；
- 不套无意义的大卡片；
- 列表支持固定表头和稳定滚动；
- 主任务区域获得最大空间。

### 右侧检查器

用于评分细则、AI 建议、属性、关联记录、历史活动、智能体动作和审计信息。应可收起；阅卷页中教师最终评分始终易于访问。

### 滚动

- 顶部栏稳定；
- 左侧、中央、右侧可按需独立滚动；
- 避免难以判断归属的嵌套滚动条；
- 主要提交按钮不能被长内容推到不可见位置。

## 7. 单题阅卷与人工复核页

推荐布局：

```text
┌────────────┬────────────────────────────────┬────────────────┐
│ 学生/异常  │ 学生答卷、题目截图或整卷       │ 评分与复核     │
│ 队列       │ 原题 / 作答 / 批注 / 缩放       │ 评分标准       │
│            │                                │ AI 初评        │
│            │                                │ 风险提示       │
│            │                                │ 教师最终评分   │
│            │                                │ 确认并下一份   │
└────────────┴────────────────────────────────┴────────────────┘
```

### 左侧队列

显示：学生姓名、编号、批改状态、置信度、异常、进度。  
支持：状态筛选、搜索、键盘切换、定位下一条高风险记录。  
避免：大头像、过多标签、始终可见的多个次要按钮。

### 中央答卷区

必须支持：适应宽度、原始比例、缩放、旋转、拖拽、查看原卷、查看切题边界和图像异常。不得被侧栏压缩到难以阅读。

### 右侧评分区

推荐顺序：

1. 题目与满分；
2. 评分细则；
3. 学生作答摘要；
4. AI 初评分数；
5. AI 依据与置信度；
6. 异常或冲突；
7. 教师最终分；
8. 错因与知识点；
9. 教师备注；
10. 确认并进入下一份。

教师最终分必须比 AI 初评更醒目。“确认并进入下一份”是本区域唯一主要按钮。

### 建议快捷键

- `J` / `K`：上一份、下一份；
- 数字键：输入分数；
- `Enter`：确认；
- `Shift + Enter`：确认并下一份；
- `R`：标记待复核；
- `Z`：适应宽度；
- `+` / `-`：缩放；
- `/`：搜索。

输入框聚焦时不得误触快捷键。

## 8. 教师智能体工作台

### 8.1 三种入口

1. **上下文动作**：分析本题误判、生成讲评、推荐训练题、总结学生变化。
2. **命令面板**：用自然语言搜索并发起结构化任务。
3. **右侧智能体检查器**：展示计划、上下文、待执行动作、审核结果和执行记录。

### 8.2 禁止结构

- 默认中央大聊天框；
- AI 对话遮挡核心业务数据；
- 未说明上下文就给出结论；
- 自动执行不可逆写操作；
- 不显示 AI 使用了哪些对象和数据；
- 所有功能都包装为自由聊天。

### 8.3 智能体状态

草拟中、分析中、等待教师确认、执行中、部分完成、已完成、失败、取消、权限不足、存在风险。写操作必须说明影响范围。

## 9. 设计 Token

所有常用值通过 CSS Variables、主题对象或 Token 管理，禁止在页面中反复写任意颜色和无规则间距。

### 9.1 建议色彩

```css
:root {
  --color-bg-app: #f6f7f8;
  --color-bg-sidebar: #f2f3f4;
  --color-bg-surface: #ffffff;
  --color-bg-subtle: #f8f9fa;
  --color-bg-selected: #eef2f6;

  --color-border-subtle: #e7e9ec;
  --color-border-default: #d9dde2;
  --color-border-strong: #b9c0c9;

  --color-text-primary: #20242a;
  --color-text-secondary: #5c6470;
  --color-text-muted: #8a929d;

  --color-accent: #365f7d;
  --color-accent-hover: #2d526d;
  --color-accent-subtle: #eaf1f5;

  --color-success: #2f7a55;
  --color-success-subtle: #eaf5ef;
  --color-warning: #9a6718;
  --color-warning-subtle: #fff4da;
  --color-danger: #b04444;
  --color-danger-subtle: #faecec;
  --color-ai: #5e628d;
  --color-ai-subtle: #efeff7;
  --color-teacher: #255f49;
  --color-teacher-subtle: #e9f3ee;
}
```

规则：一个主要强调色；AI 和教师有独立但克制的语义色；风险色只用于需要处理的状态；状态不得只靠颜色；禁止无意义蓝紫渐变。

### 9.2 字体

优先系统字体：

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei",
  "Noto Sans CJK SC", system-ui, -apple-system, BlinkMacSystemFont,
  "Segoe UI", sans-serif;
```

| 层级 | 字号 | 用途 |
|---|---:|---|
| Display | 28–32px | 少量总览标题 |
| H1 | 22–24px | 页面标题 |
| H2 | 18–20px | 大区块标题 |
| H3 | 15–16px | 面板标题 |
| Body | 14px | 默认正文 |
| Dense | 13px | 高密度列表 |
| Caption | 12px | 辅助信息 |

日常应用页不使用超大标题；正文不大面积使用 12px；字重以 400、500、600 为主。

### 9.3 间距

统一使用：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。避免 13px、19px、27px 等无规律数值。

### 9.4 圆角

- 4px：标签、小控件；
- 6px：按钮、输入框；
- 8px：菜单、面板；
- 10–12px：重要浮层。

禁止所有容器使用 16–24px 大圆角。

### 9.5 阴影

普通区域优先用边框和背景层级。阴影只用于菜单、浮层、模态框、拖拽对象等脱离文档流的元素。

## 10. 通用组件

### 按钮

- 每个操作区最多一个主要按钮；
- 文案说明结果，如“确认并下一份”；
- 处理中显示加载；禁用时说明原因；
- 危险操作不与主要按钮同级竞争。

### 输入框

- 标签常驻，不只依赖 placeholder；
- 错误信息紧邻字段；
- 评分输入支持键盘；
- 长备注自适应高度。

### 卡片

默认不使用。仅当内容是独立操作单元、需整体选中、有明确状态、需拖拽或画廊比较时使用。普通说明、统计摘要和表单不得为了装饰套卡片。

### 标签

用于状态、风险、知识点、错因、置信度和智能体状态。每个列表项默认不超过 3 个可见标签；其余折叠。标签必须含文字。

### 表格

必须支持固定表头、排序、筛选、列控制、批量选择、空状态、加载、错误恢复和分页或虚拟滚动。避免每行始终显示大量按钮。

### 右侧检查器

宽度 320–400px；长内容内部滚动；关闭后保留上下文；重要提交固定底部；不要嵌套多层抽屉。

### 模态框

只用于高风险确认、重要对象创建或短流程。普通详情、长报告和连续评分使用侧栏或页面。

### 反馈

成功提示短暂显示；失败必须说明影响范围并可重试；批量任务显示进度和部分失败；提交后可提供撤销。

## 11. 业务状态体系

### 阅卷状态

未开始、处理中、AI 已完成、待人工复核、人机冲突、教师已确认、需要返工、批改失败、已归档。

### 图像状态

正常、模糊、裁剪偏移、作答缺失、多页错配、方向错误、无法识别、需查看原卷。

### 评分风险

高/中/低置信度、评分标准缺失、AI 与规则冲突、AI 与教师历史冲突、分数越界、需二次检查。风险不能只显示百分比，必须说明原因和建议动作。

### 教师决策状态

AI 初评、教师草稿、教师最终确认、教师修改过 AI、管理员或教研员复核。

---

## 12. AI 信息层级

从高到低：

1. 教师最终决定；
2. 原始证据；
3. 评分标准；
4. 风险与异常；
5. AI 建议；
6. AI 详细解释；
7. 模型日志和技术参数。

AI 建议应包含建议分、置信度、依据、疑点、是否需复核和评分标准版本。不得把 AI 初评称为最终结果，不得隐藏教师修改痕迹，不得用长篇模型推理替代清楚判断。

发生人机冲突时，并列展示 AI 结果、教师结果、差异、标准依据、类似样本和最终确认入口。

---

## 13. 报告与可视化

报告采用清楚标题、上下文信息、顶部摘要、可跳转目录、分节内容、图表、证据明细、教师建议和导出入口。

图表原则：一个图回答一个问题；标题、单位、图例清楚；不使用 3D；不使用装饰性渐变；风险和趋势配文字结论；支持查看明细；小样本需说明。

工作台只显示可驱动行动的指标，不堆装饰性 KPI。

---

## 14. 响应式

- **≥1280px**：完整三栏，中央答卷最大化；
- **1024–1279px**：左栏可收起，右栏缩窄；
- **768–1023px**：左栏改抽屉，右栏改切换面板；
- **<768px**：主要用于查看任务、进度、报告、学生信息和简单确认，不要求完整批量阅卷。

---

## 15. 可访问性与动效

必须支持键盘核心操作、明显 focus、图标按钮可访问名称、状态不只靠颜色、足够对比度、合理点击目标、错误与字段关联、图表文字摘要和图片缩放。

动效只解释状态：hover 80–120ms，普通过渡 120–180ms，抽屉 180–240ms。禁止大面积弹跳、庆祝动画和长时间背景动画。

---

## 16. 空、加载和错误状态

### 空状态

说明为什么为空、用户可做什么、是否需导入或调整筛选、是否有权限限制。

### 加载状态

列表用骨架；AI 任务显示阶段；批量任务显示完成数量；尽量保留已有内容，避免页面闪空。

### 错误状态

提供清楚说明、影响范围、是否已保存、重试、安全返回和必要时复制详情。批改失败时必须保留教师已输入内容。

---

## 17. 反面设计清单

以下默认不合格：

- 蓝紫渐变成为主视觉；
- 应用内部出现营销 Hero；
- 所有内容都套卡片或强阴影；
- 大圆角和大量彩色胶囊标签；
- 超大标题挤压工作空间；
- 只用图标不写文字；
- 一个区域多个同级主按钮；
- AI 建议比教师最终评分醒目；
- 重要信息只在 hover 中出现；
- 为简洁隐藏必要字段；
- 用大量聊天气泡替代结构化任务；
- 把知识图谱作为所有业务默认入口；
- 不考虑长姓名、长题目、长反馈和大数据量；
- 只做静态页面，不做加载、空、错、禁用状态；
- 复制参考站代码、品牌和素材；
- 未经说明增加大型 UI 依赖；
- 为重做前端改写稳定后端；
- 一个任务无边界重构全部页面。

## 18. 实施顺序

1. 建立 Token；
2. 建立 App Shell；
3. 统一按钮、输入框、标签、菜单、表格和反馈状态；
4. 改造一个样板页；
5. 提炼公共组件；
6. 逐页迁移。

首个样板页应为“单题阅卷与人工复核”。禁止一次性全量重写。每次任务必须写明范围、不修改范围、验收条件、测试方法和回滚方式。

## 19. 视觉验收

至少验证：

- 1440×900
- 1280×800
- 1024×768
- 768×1024
- 390×844

通用检查：溢出、导航稳定、检查器遮挡、长文本、主要操作、状态理解、加载/空/错/禁用、focus、对比度、任意颜色、过度卡片化和重复组件。

阅卷检查：答卷清楚、缩放顺畅、教师最终分持续可见、AI 初评明确、低置信度易发现、冲突有原因、提交进入正确下一项、快捷键有效、失败保留输入。

智能体检查：上下文明确、使用对象可见、写操作需确认、影响范围清楚、可取消、有执行记录、部分失败可恢复、避免聊天框中心化。
