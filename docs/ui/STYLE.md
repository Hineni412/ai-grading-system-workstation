# 教师工作台视觉规范

> **适用范围：** 本文件只约束视觉语言与通用呈现质量。
> **不属于本文件：** 导航、页面、字段、操作、状态含义、快捷键、流程、权限、接口和产品功能。
> **业务来源：** 上述内容必须来自现有 Streamlit 行为、服务实现、数据库契约、测试，或用户留下日期与范围的明确决定。

---

## 1. 使用边界

### 1.1 本文件可以决定什么

- 颜色与对比度；
- 字体、字号、字重与行高；
- 间距、密度、对齐和留白；
- 边框、圆角、阴影和表面层级；
- 控件的视觉层级、焦点、禁用和反馈外观；
- 图像、表格、图表和长内容的通用可读性；
- 桌面视口下的视觉适配；
- 动效节奏与减少动效支持；
- 加载、空白、警告和错误的通用呈现方式。

### 1.2 本文件不能决定什么

- 一级或二级导航有几项、叫什么；
- 系统需要哪些页面、面板或入口；
- 页面显示哪些业务字段、按钮、标签或统计；
- 某个动作如何保存、跳转、确认、撤销或继续；
- 业务状态集合、状态机和状态含义；
- 键盘快捷键及其业务结果；
- AI、教师或系统在具体流程中的权限；
- 当前不存在的未来功能或占位入口。

任何设计稿、参考图、演示数据或历史计划都不能单独为这些内容提供依据。没有业务来源的功能元素不进入实现。

### 1.3 与其他资料冲突时

按以下顺序处理：

1. 数据准确、安全边界和教师明确决定；
2. 当前生产行为、服务、数据库契约和测试；
3. 当前页面经批准的功能溯源表；
4. 本视觉规范；
5. 外部产品或局部视觉参考；
6. 装饰性效果。

本文件只能在第 4 项范围内发挥作用，不能覆盖前 3 项。

## 2. 视觉方向

整体关键词：

- 安静、专业、清楚、克制；
- 高信息密度，但不拥挤；
- 适合教师在 Windows 工作机上长时间使用；
- 以内容和证据为视觉重点；
- 通过层级而不是装饰表达重要性。

视觉上避免营销网站、娱乐化产品、聊天气泡中心化和数据大屏风格。页面不依赖大标题、大面积渐变、强阴影或成排卡片制造“高级感”。

本产品的辨识度来自“批注纸张般的清楚内容面 + 教务表格般的稳定密度”：背景安静，分隔精确，主要内容具有充足面积，风险和确认结果只在需要时使用语义色。

## 3. 视觉参考的使用方法

可以借鉴的仅是局部视觉属性：

- 浅色低干扰背景；
- 轻边界和稳定分隔；
- 高密度列表的行距与对齐；
- 长内容的标题层级和正文宽度；
- 表格、筛选器和属性区域的视觉秩序；
- 关系图或画布的局部聚焦方式；
- 控件、菜单、浮层和焦点的细节。

禁止借鉴：

- 完整页面框架；
- 导航名称和分组；
- 可读的业务文案或示例数据；
- 字段、按钮、状态、快捷键和操作顺序；
- 参考产品的品牌、素材和专属交互；
- 参考图中看似合理但当前系统没有依据的功能。

不同来源不得在同一界面明显拼贴。视觉选择必须能解释为当前教师工作场景服务，而不是“图里有，所以照做”。

## 4. 设计 Token

常用值必须通过 CSS Variables、主题对象或 Token 管理。页面不得反复写任意颜色、间距、圆角、阴影和动效时长。

### 4.1 色彩

```css
:root {
  --color-bg-app: #f6f7f8;
  --color-bg-sidebar: #f2f3f4;
  --color-bg-surface: #ffffff;
  --color-bg-subtle: #f8f9fa;
  --color-bg-selected: #eef2f6;

  --color-border-subtle: #e7e9ec;
  --color-border-default: #d9dde2;
  --color-border-strong: #b9c0c9;

  --color-text-primary: #20242a;
  --color-text-secondary: #5c6470;
  --color-text-muted: #8a929d;

  --color-accent: #2563eb;
  --color-accent-hover: #1d4ed8;
  --color-accent-active: #1e40af;
  --color-accent-subtle: #eff6ff;

  --color-success: #2f7a55;
  --color-success-subtle: #eaf5ef;
  --color-warning: #9a6718;
  --color-warning-subtle: #fff4da;
  --color-danger: #b04444;
  --color-danger-subtle: #faecec;
  --color-info: #496579;
  --color-info-subtle: #edf3f7;
  --color-ai: #5e628d;
  --color-ai-subtle: #efeff7;
  --color-teacher: #255f49;
  --color-teacher-subtle: #e9f3ee;
}
```

规则：

- 全局只使用一个主要强调色；
- 普通文字以深灰而不是纯黑呈现；
- 风险色只用于确实需要注意的内容；
- AI 与教师可以使用独立但克制的视觉角色色，具体何时出现由业务来源决定；
- 状态不能只靠颜色表达；
- 禁止无意义的蓝紫渐变和大面积高饱和背景。

### 4.2 字体

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei",
  "Noto Sans CJK SC", system-ui, -apple-system, BlinkMacSystemFont,
  "Segoe UI", sans-serif;
```

| 层级 | 字号 | 视觉用途 |
|---|---:|---|
| Display | 28–32px | 极少量总览标题 |
| H1 | 22–24px | 页面级标题 |
| H2 | 18–20px | 大区块标题 |
| H3 | 15–16px | 面板或分组标题 |
| Body | 14px | 默认正文 |
| Dense | 13px | 高密度数据行 |
| Caption | 12px | 辅助信息 |

字重以 400、500、600 为主。正文行高使用 1.5，长内容可放宽到 1.7；紧凑标题可使用 1.35。日常工作页不使用超大标题，正文不大面积降到 12px。

### 4.3 间距与密度

统一使用：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。

- 控件内部优先 8–12px；
- 同组内容优先 8–16px；
- 区块之间优先 20–32px；
- 数据密集区域依靠对齐、细分隔和稳定行高，而不是挤压文字；
- 避免 13px、19px、27px 等无规则间距；
- 留白必须表达分组关系，不能只为“显得高级”浪费工作空间。

### 4.4 圆角与边框

- 4px：标签、小控件；
- 6px：按钮、输入框；
- 8px：普通面板、菜单；
- 10–12px：重要浮层；
- 普通分隔使用 1px 轻边框；
- 选中、聚焦或危险状态可以提升边框强度，但不能造成厚重色块。

禁止所有容器统一使用 16–24px 大圆角。

### 4.5 阴影

普通区域依靠背景和边框分层。阴影只用于脱离文档流的菜单、浮层、模态框或拖拽对象，统一使用克制的覆盖层阴影，例如：

```css
--shadow-overlay: 0 8px 24px rgba(32, 36, 42, 0.14);
```

## 5. 表面、布局与滚动外观

- 应用背景与内容表面形成轻微层级，不使用大面积纯白卡片海洋；
- 主要内容获得最清楚的对比和最大可用面积；
- 辅助区域通过轻背景、细边框或窄分隔识别，不靠强色块抢注意力；
- 普通说明、统计摘要和表单不为了装饰套卡片；
- 若功能设计包含固定表头、标题或操作，其固定与滚动状态之间不得发生视觉跳动；是否固定由功能溯源决定；
- 若功能设计包含多个滚动区域，各区域必须有清楚视觉边界；滚动归属和嵌套方式由功能设计决定；
- 长内容不得因遮挡、裁切或固定区域而变得不可读；完整内容的访问方式由功能设计决定；
- 具体采用一栏、两栏、三栏、侧栏还是弹窗，由页面功能溯源和真实任务决定，本文件不作规定。

当前代码中的几何 Token 可以继续服务已实现布局，但它们不是所有页面必须采用相同结构的依据。

## 6. 通用控件外观

### 6.1 按钮

- 同一操作区最多一个视觉主按钮；
- 主按钮使用强调色，次要按钮使用轻背景、边框或文字样式；
- 危险按钮使用危险色，但不与普通主按钮并列争抢；
- 加载、禁用、聚焦和按下状态必须清楚；
- 按钮文字保持具体、简短，图标不能成为唯一可见说明。

### 6.2 输入控件

- 标签常驻，placeholder 只作示例；
- 默认高度使用 32、36 或 40px Token；
- 边框、焦点环、错误和禁用外观保持一致；
- 错误说明紧邻控件，不依赖页面顶部统一提示；
- 长文本输入保持可读行高，避免过小固定高度。

### 6.3 标签与徽标

- 使用低饱和背景和清楚文字；
- 同一数据行默认不超过 3 个醒目标签；
- 普通属性不一律做成彩色胶囊；
- 颜色旁必须有文字、图标或形状信息；
- 标签的业务名称和含义不由本文件定义。

### 6.4 表格与高密度列表

- 表头与数据列严格对齐；
- 行高稳定；若功能设计截断长内容，视觉上必须清楚提示仍有内容，完整内容的访问方式由功能溯源决定；
- 选中、悬停、聚焦和禁用状态可区分；
- 分隔线轻，斑马纹仅在确实提高跨行阅读时使用；
- 行内操作默认保持克制，避免每行出现一排同权按钮；
- 空白、加载和失败状态与表格宽度对齐，不突然变成独立大卡片。

### 6.5 面板、抽屉与模态框

- 普通面板使用 8px 圆角以内的轻边框；
- 浮层使用统一覆盖层阴影；若功能设计包含关闭控件，其焦点外观必须清楚；
- 多个浮层同时出现时必须保持清楚的层级与遮罩关系；是否允许嵌套由功能设计决定；
- 若功能设计包含浮层内部滚动或固定区域，其标题、内容和操作之间不得发生视觉遮挡；
- 模态框只是一种视觉容器，何时使用必须由业务任务决定。

### 6.6 通用反馈

- 成功信息简短、低干扰；
- 警告和错误使用浅色背景、深色正文与明确图标；
- 加载尽量保留原有内容结构，避免整页闪空；
- 空白状态使用简短说明和足量留白，不使用大型营销插画；
- 反馈文案的业务结果、恢复方式和操作由真实流程决定。

## 7. 图像、文档与图表外观

### 图像与文档

- 纸张、答卷和扫描内容优先保持原始比例与清楚对比；
- 工具条和叠层不能遮住关键内容；
- 深浅背景要让纸张边界可辨，但不制造舞台式强阴影；
- 加载失败、低清晰度和不可用状态应有文字说明，不能只显示破图图标。

### 图表

- 一个图只承担一个清楚的视觉问题；
- 标题、单位、图例和数据标签使用一致层级；
- 不使用 3D、装饰性渐变、发光或无意义动画；
- 风险和趋势配文字摘要，颜色不是唯一编码；
- 小样本和空数据使用克制的视觉提示；
- 图表类型、指标和结论必须来自业务设计，本文件只约束外观。

## 8. 已批准视口的视觉验收

产品支持平台和最小视口由 `AGENTS.md`、`ARCHITECTURE.md` 与对应执行包定义，本文件不新增或删除支持范围。当前已批准的前端视觉验收覆盖以下 Windows 桌面视口：

至少验证：

- 1920×1080
- 1440×900
- 1366×768
- 1280×800
- 1024×768

通用要求：

- 页面没有意外横向溢出；
- 文字、控件和数据列不互相遮挡；
- 长名称、长正文和极端数值不破坏层级；
- 主要内容在紧凑桌面下仍可辨认；
- 必要时可收紧间距或隐藏纯装饰，但不能据此删除业务字段；
- 具体区域如何重排由页面功能设计决定。

## 9. 可访问性与动效

- 键盘焦点必须明显；
- 图标按钮必须有可访问名称；
- 状态不能只靠颜色；
- 正文、控件和风险提示保持足够对比度；
- 点击目标大小稳定；
- 错误与对应字段在视觉上关联；
- 图表提供文字摘要；
- 图像内容在支持的工作流中保持可辨认。

动效只用于解释状态：

- hover：80–120ms；
- 普通过渡：120–180ms；
- 抽屉或浮层：180–240ms；
- 尊重 `prefers-reduced-motion`；
- 禁止大面积弹跳、庆祝动画和持续背景动画。

## 10. 参考资产规则

当前活动参考集不保存完整 AI 页面概念图。未来若需要局部视觉片段，必须满足：

1. 裁去完整页面框架、导航和所有可读业务文案；
2. 不包含可被误读为需求的字段、按钮、状态、快捷键或流程；
3. 文件名描述视觉属性，不使用业务功能名；
4. 配套记录来源、裁剪范围、允许借鉴的视觉属性和禁止推导的业务含义；
5. 片段只能辅助视觉判断，不能进入功能溯源表的“业务来源”列。

具体目录规则见 `docs/ui/references/README.md`。

## 11. 反面设计清单

以下视觉表现默认不合格：

- 蓝紫渐变成为主视觉；
- 应用内部出现营销 Hero；
- 所有内容都套卡片或强阴影；
- 大圆角和大量彩色胶囊；
- 超大标题挤压工作空间；
- 只用图标不写文字；
- 一个区域出现多个同级主按钮；
- 重要信息只在 hover 中出现；
- 为“简洁”把文字压得过小；
- 用聊天气泡替代清楚结构；
- 大面积装饰图压缩真实内容；
- 不考虑长中文、长反馈和大数据量；
- 只有静态正常态，没有加载、空白、错误、禁用和焦点外观；
- 复制参考站的品牌、素材和完整页面结构；
- 为截图临时加入与产品无关的装饰或假内容。

## 12. 视觉验收

每个可见前端任务至少检查：

- 是否只使用 Token，没有散落任意颜色和间距；
- 字体、层级、行高和密度是否稳定；
- 边框、圆角、阴影和表面层级是否克制；
- 主要内容是否获得足够空间；
- 长文本、极端数据、加载、空白、错误、禁用和焦点是否可读；
- 对比度和状态的非颜色信息是否足够；
- 五个规定桌面视口是否无意外溢出或遮挡；
- 是否出现从参考图抄入、却没有业务来源的可见功能。

业务正确性、流程完整性和用户验收必须使用当前页面的功能溯源表与版本化清单，不能用“符合 STYLE.md”替代。
