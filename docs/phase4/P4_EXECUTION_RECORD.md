## 4. P4-01 稳定身份与关系语义

纯本地契约：

- `question_bank/relations/contracts.py`
- `tests/phase4/test_relation_contracts.py`

### 稳定身份

- 已治理的内置知识使用现有规范 `KP_*` 编码，读取时统一为小写 `kp_*`；
- 教师批准的新本地知识使用不含名称语义的 `ki_` 加 32 位十六进制随机身份；
- `knowledge_point:中文名称`、旧技能 ID 和自由文本不能成为 P4 稳定身份；
- 显示名、别名和教材显示名可以变化，不改变 stable key；
- 退役身份保留历史关联，但不能新增活动关系或参与新推荐；
- P4-02 迁移只对能精确映射到已治理编码的现有标签建立身份；未知或冲突标签保持待治理，不自动造 ID。

### 关系方向

| 类型 | 保存方向 | 首版含义 |
|---|---|---|
| `parent` | 子知识点 → 父知识点 | 结构归属 |
| `prerequisite` | 目标知识点 → 先修知识点 | 学习目标通常需要的基础 |
| `related` | stable key 排序后的无向对 | 经常共同出现，但不是父子或先修 |

### 冲突与循环

- 自环拒绝；
- 完全重复的活动关系拒绝；
- `parent` 和 `prerequisite` 的反向活动关系拒绝；
- 同一无序知识对首版只能有一种活动语义；改类型时先退役旧关系；
- `parent` 和 `prerequisite` 各自在自己的有向子图中禁止循环；
- `related` 不参与有向传播，也不能误作先修；
- 只有 `confirmed` 关系参与活动图、冲突和循环判断；
- `suggested/rejected/retired` 保留历史，但不阻塞新的合法活动关系。

### 允许的状态影响

- `suggested`：只进入审核队列；
- `confirmed`：可进入图谱查询和推荐；
- `rejected`：保留建议与教师决定，不进入活动图；
- `retired`：从新推荐移除，历史训练卷和审计仍可解释。

掌握度 v2 首版只使用关系生成解释或先修推荐，不把父子或相关关系自动换算成掌握分。

## 5. 故障场景

完整矩阵位于 gold set。当前 P4-00—P4-02 的直接规则：

| 场景 | 当前预期 |
|---|---|
| 重复操作 | 相同关系身份返回重复冲突；后续 operation 使用稳定幂等键 |
| 同时操作 | P4-02 起使用 revision，旧 revision 失败关闭 |
| 中途退出 | 当前纯函数无写入；后续事务回滚、文件保留 staging |
| 重新启动 | 当前契约确定性重建；后续 Job/归卷/判定/outbox 从明细恢复 |
| 失败重试 | 教师显式触发；成功投影不重做，模型不自动追加请求 |
| 取消 | 已发布结果保留，未完成项不变成 0 或未达成 |
| 部分完成 | 标签、判定点、题目结果和跨库发布分别显示状态 |
| 数据缺失 | 不造关系、判定点、页面或掌握证据 |
| 数据冲突 | 身份、方向、revision、页面签名和教师锁冲突均失败关闭 |

## 7. P4-03 AI 关系建议与离线评估

- 每批模型失败只失败一次，不自动重试；显式重试产生新的请求记录；

## 8. P4-04 教师关系审核与审计

### 审核能力

- 审核队列明确展示模型建议或教师建议、理由、模型/提示版本、置信度、
  当前冲突标记和 revision；
- 影响预览说明是否可执行、会加入还是移出活动图、是否立即退出后续推荐；
- 单条支持确认、拒绝、修改关系语义、退役和恢复；
- 修改只允许发生在 `suggested`，保留修改前后 stable key、关系类型、教师、
  理由、时间和 revision；
- 单次批量最多 20 条；批量确认先整体检查候选之间的反向、类型和循环冲突，
  互相冲突的候选均不生效；
- 其他批量项按独立 revision 执行并返回 `applied/partial/failed`，一条过期
  不覆盖新决定，也不阻止无冲突的当前项；
- 前端/API 只能调用审核服务，不能直接写关系表；
- 每条决定时间线合并建议、修改、确认、拒绝、退役和恢复事件，能回答
  谁、何时、基于什么理由作出决定。

### API

- `GET /api/graph/relations/review-queue`
- `POST /api/graph/relations/{relation_id}/impact`
- `POST /api/graph/relations/{relation_id}/review`
- `POST /api/graph/relations/review-batch`
- `GET /api/graph/relations/{relation_id}/timeline`

revision 冲突返回 409 和当前 revision；关系冲突返回 409 和可见冲突类型；
无效状态变化返回 422；存储故障使用统一安全错误，不返回本机路径。

- P4-09 已有结构严格的 `TrainingCriteriaDraft` 和独立分析账本，但当前草稿

- 回填范围：接口必须收到 1—500 个明确题目 ID 和幂等 token；不提供“自动
  全库回填”入口；
- 模型与费用：默认零自动重试；本轮只用 Fake 和合成题验证，不调用真实模型。

## 15. P4-11 个性化推荐草稿

### 冻结任务边界

- 目标：让教师按学生、训练目标、题量、预计时长和难度范围生成可复现、

- 包含：直接巩固、先修补强、迁移应用三类配额；只读已确认关系；只使用

  理由和证据链；教师锁定、排除、替换；安全降级；确定性排序和版本；
- 明确不包含：新题生成、模糊标签补题、未确认关系、自动发布、P4-12
  冻结卷和打印、训练答卷判定、B 线数据、真实学生或真实题库写入；
- 验收条件：相同输入和来源版本得到相同草稿内容；5 名合成学生得到有
  差异且可解释的推荐；循环、孤立点、候选不足和低证据安全降级；教师
  替换后保留原因和历史；现有普通训练组卷行为不变；
- 风险等级：高。推荐结果跨越掌握证据、关系、题目和判定点多个状态，
  但当前实现与检查只使用合成数据和临时数据库，不执行真实迁移。

### 集中调查与冻结问题

- 现有训练预览只按可变中文标签精确匹配，同一批候选主要靠难度分阶段，
  不能承担 P4 的稳定身份、确认关系和批准判定点规则；
- 现有训练任务快照没有 P4 判定点版本，P4-11 因此只生成可审核草稿，
  不提前复用 P4-12 的冻结卷语义；
- P4-08 已提供稳定知识身份、活动关系和掌握度 v1/v2 投影，P4-10 已提供
  “当前内容一致且已批准”的判定点可用性；P4-11 只消费这些正式投影；
- 旧训练预览、确认、历史和导出接口继续保留，P4-11 使用独立草稿接口和
  页面区域，避免改变普通组卷与现有训练任务含义；
- 问题清单在本节记录时冻结。P4-08 已登记的历史标签移动兼容问题继续
  作为独立事项，不扩大到 P4-11。

### 故障场景

| 场景 | P4-11 预期 |
|---|---|
| 重复操作 | 相同请求令牌和相同输入返回原草稿；同令牌不同输入明确冲突 |
| 同时操作 | 修改必须携带当前 revision；只有一个旧 revision 操作可成功 |

### 集中调查与冻结决定

- P4-12 已把卷实例、版本、页码、总页数和本地签名写入逐页二维码，并在

- 一个扫描批次必须先明确选择预期的冻结卷实例。这样可识别完全缺失的卷，
  也能把签名有效但不属于本批次的页面标成“批次外页面”，而不是悄悄归入；
- 每个 PDF 可含多页，JPEG/PNG 视为单页；页面按上传先后记录，但最终顺序
  一律由已验证页码决定，乱序会被自动纠正并留下审计，不作为人工阻塞；
- 相同 operation 与相同文件返回原结果；同 operation 不同内容明确冲突。
  同批完全相同文件视为幂等上传；不同文件中出现同一页面仍记为重页并阻塞，
  不重复计入提交；
- 同一卷页码出现不同图像时，系统不自动选择。教师只能对明确选中的扫描页
  执行“替换该页”；旧页保留为历史，不删除原文件；
- OCR 姓名在本包不参与自动归组。候选学生和卷只来自教师选定的冻结卷，
  页面身份不可读时必须人工选择；
- 每次人工匹配、替换、忽略或取消都核对批次 revision。提交开始判定后若
  页面再变化，必须增加 submission revision，旧版本页面关系继续可追溯；
- 预览接口只允许读取数据库登记且仍位于训练答卷受控目录内的页面，不返回
  本机路径；普通日志和 API 不包含学生答卷正文、绝对路径或签名密钥；
- 问题清单在本节记录时冻结。P4-08 已登记的历史标签移动兼容问题继续作为
  独立事项，不扩大到 P4-13。

### 故障场景

| 场景 | P4-13 预期 |
|---|---|
| 重复操作 | 相同 operation 和相同输入返回原结果；令牌被不同输入复用时明确冲突 |
| 同时操作 | 人工处置必须携带批次当前 revision；旧 revision 不能覆盖新决定 |
| 中途退出 | 未完成文件只可能成为未引用孤儿，不登记半页；已提交事务可完整恢复 |
| 重新启动 | 批次、上传、页图、归组、缺页、冲突、revision 和审计从数据库恢复 |
| 失败重试 | 文件哈希和 operation 双重幂等；已归组页不重复计入 |
| 取消 | 只取消明确选中的提交；其他学生卷和原扫描文件保持不变 |
| 部分完成 | 已识别卷分别显示 ready 或缺页；一个坏页不伪装成整批成功 |
| 数据缺失 | 身份不可读、卷实例不存在、缺页或预览文件缺失时失败关闭 |
| 数据冲突 | 签名不符、批次外页、同页不同图和人工并发冲突均进入显式状态 |

## 18. P4-14 独立整卷训练判定

### 编码前冻结边界

- 目标：通过 `assess(submission_id, expected_revision)` 一个高层接口，从已经
  完整归卷的训练答卷加载冻结题目、冻结判定点和排序页面，以一名学生最多
  一次物理模型请求生成逐点四态候选，并由本地计算每题达成点数/总判定点数；
- 包含：答卷和冻结卷一致性检查、受控页面读取、一次整卷请求、`met` /
  `not_met` / `uncertain` / `unreadable` 四态、简短可核对依据、point ID
  完整性/重复/未知检查、逐题候选、运行账本、用量与失败分类、Fake 模型
  Adapter；
- 明确不包含：教师改判与最终锁、失败后的显式重试和重启接管、训练证据
  发布、掌握度刷新、下一轮推荐、任何分数/总分/等级/排名、真实模型调用、
  真实数据库迁移或真实答卷；
- 验收条件：完整答卷一次调用不超过一次物理请求；合法题每个冻结点恰好
  一个合法结果；漏点、重复点、未知点或非法状态只让对应题进入人工队列，
  其他题仍保留候选；`uncertain/unreadable` 不按未达成处理；模型失败、
  取消、坏 JSON、超时或上下文超限不留下半份正式证据；普通考试批改语义
  不改变；
- 风险等级：很高。该批涉及模型费用上限、答卷文件、数据库状态和部分成功
  语义，但开发和检查只使用临时数据库、合成页面和 Fake 模型。

### 集中调查与故障场景

- P4-13 已提供只有 `ready` 且页面无异常时才能取得的 submission 快照；
  P4-12 已冻结题目、答案、判定点版本和整卷预算，P4-14 不回读当前题库
  内容替代快照；
- 新模块的外部接口保持只有答卷 ID 和预期 revision。数据库、文件路径、
  题号映射、判定点、模型名称和结构化协议全部隐藏在模块内部；模型调用是
  内部可替换 seam，自动检查使用 Fake Adapter；
- 运行账本先取得 `submission_id + submission_revision` 的唯一执行权，
  再发起物理请求；重复点击返回已有运行，不追加请求。P4-15 再补充失败
  重试、暂停、取消和重启恢复规则；
- 页面是不可受信任输入。提示明确把学生书写内容当证据而不是指令，题目、
  参考答案、判定点和结构化协议使用冻结的可信快照；
- 每题单独做集合完整性检查。漏点、重复点、未知点、未知题码、非法状态或
  无法核对的空依据不会进入该题候选；其他题不被连带回滚；
- 重复操作：同一答卷 revision 返回原运行，`request_count` 不增加；
- 同时操作：数据库唯一约束和答卷锁只允许一个调用取得模型执行权；
- 中途退出/重启：已登记运行和请求次数不丢失，不猜测模型成功；自动接管
  留给 P4-15；
- 失败/超时/上下文超限/取消：整卷运行记录真实失败或取消，不自动拆卷、
  不自动重试、不产生点候选；
- 部分完成：结构合法的题形成候选，结构异常题进入人工队列，整卷状态如实
  显示需要复核；
- 数据缺失或冲突：答卷非 ready、revision 不符、页面缺失/哈希变化、冻结
  卷或判定点快照无效均在模型请求前失败关闭。

### 实现结果

- 新增独立 `TrainingAssessmentModule`，外部只需答卷 ID 和预期 revision；
  模块内部加载冻结题目、参考答案、判定点版本和受控答卷页，不允许调用者
  传入分值、题号映射、模型名或本机路径；
- 新增运行、逐题候选和逐点候选三类表。`submission_id + revision` 只允许
  一个运行；重复和同进程并发点击返回同一结果，运行中断时保留请求次数，
  不猜测成功、不自动追加请求；
- OpenAI Adapter 使用严格结构化输出和 `allow_retry=False`，Fake Adapter
  支持完全离线检查；提示把答卷页面标记为不可信证据并拒绝其中的指令，
  只允许四态，不允许分数、等级、排名或总分；
- 每题独立核对 point ID 集合、重复、未知、四态和可核对依据。结构异常题
  不落逐点候选并进入人工队列，其他合法题仍保存候选；达成、未达成、
  不确定和无法辨认数量全部由本地统计；
- 模型超时、上下文超限、取消、坏 JSON 和其他失败均保持一次请求账本并
  清除候选；页面非 ready、revision 冲突、文件缺失/越界/哈希变化或冻结
  快照含分值字段均在请求前拒绝；
- 相邻 P4-13 回归发现 OpenCV 在严重裁切页上可能直接抛二维码轮廓异常；
  已统一按“身份不可读”安全降级到人工队列。合成多页 PDF 夹具同步恢复
  正常页面比例，并在二维码库偶发未识别清晰页时验证人工匹配兜底，不放宽
  产品像素上限或归卷门禁。

## 19. P4-15 教师复核锁、幂等与恢复

### 编码前冻结边界

- 目标：让教师能按答卷 revision、题目和判定点修正候选并形成最终锁；
  覆盖数由冻结判定点明细重算；失败运行只能显式重试，中断运行可安全
  恢复且不会偷偷追加模型请求；
- 包含：教师逐点复核、乐观并发冲突、操作 token 幂等、最终锁优先、
  运行尝试账本、暂停/恢复/取消、失败显式重试、退出后接管、逐题完成/
  待复核/失败状态和可行动中文说明；
- 明确不包含：P4-16 证据发布、掌握度回流和下一轮推荐；前端发布页面；
  普通考试评分语义；真实模型、真实答卷、真实数据库迁移及任何费用；
- 验收条件：重复响应不新增记录或请求；并发旧 revision 明确冲突；教师
  改判后本地计数正确且模型候选不能覆盖；退出后不猜测模型成功；部分完成
  和取消不把缺失点计作未达成；每种故障给出教师可执行的下一步；
- 风险等级：很高。涉及并发、重试、费用边界、状态恢复和数据库一致性，
  但本包只使用临时数据库与 Fake Adapter 检查。

### 集中调查与故障场景

- P4-14 已按 `submission_id + submission_revision` 取得首次执行权，但旧运行
  表只容纳一次请求，不能表达显式重试尝试；P4-15 新增独立尝试账本，
  保留首次运行身份，不放宽“一次自动请求”；
- 教师锁不能依赖候选点行存在。模型漏点或整题结构异常时仍须从冻结卷中的
  判定点快照复核，因此最终锁使用四段非空稳定身份独立存储；
- 重复操作/响应丢失：相同 token 与相同输入返回既有结果；相同 token
  携带不同输入拒绝；
- 同时操作：运行级 `review_revision` 作为并发版本；两页从同一版本提交时，
  仅首个成功，后一个收到当前版本并重新加载；
- 中途退出/重启：请求尚未发出可标记为可重试失败；请求已经发出但结果
  未落库时标记为“结果未知”，不自动再次收费；
- 失败重试：只允许教师显式操作，每次尝试最多一次物理请求；已有可用候选
  时只做本地复核，不以重跑覆盖；
- 暂停/取消：保留已有候选和教师锁；未完成点保持待复核，不补零；
- 部分完成：每题依据冻结点、候选与教师锁明细重算，完整题可完成，其他题
  独立显示待复核或失败；
- 数据缺失/冲突：答卷 revision 改变、判定点不在冻结快照、旧页面提交、
  token 冲突或运行状态不允许时均拒绝写入；新 revision 不能更新旧锁；
- 文件/数据库部分失败：文件仍只在 P4-14 请求前校验；数据库写入使用单
  事务，候选写入失败不形成半题正式结果，恢复不重新读取或搬移真实文件。

### 实现结果

- 在训练判定深模块中新增逐点复核、查询、暂停、恢复、取消、失败显式重试
  和退出接管接口；外部仍只使用稳定业务 ID、revision、操作 token 和教师
  动作，不接触数据库表、本机路径、模型参数或计数算法；
- 新增尝试账本、教师最终锁和动作审计。首次运行身份保持不变，每次显式
  重试单独记录“一次物理请求”；相同 token/输入在响应丢失后返回原结果，
  token 复用为不同动作则拒绝；
- 最终锁独立于模型候选，以答卷 revision、稳定题码和判定点定位。模型漏点
  或整题结构异常时，教师仍可从冻结判定点快照完成；候选保留原值，读取时
  锁永远优先，覆盖数和题目完成状态从明细实时重算；
- `review_revision` 保护两个页面同时提交；旧页面、答卷新 revision、未知
  冻结点和不允许的运行状态均明确冲突，不覆盖旧锁；
- 失败不自动重试；请求发出后退出会标记“结果未知”，只允许教师确认后显式
  重试。暂停保留已发出的响应安全收尾，取消拒收迟到响应；已有候选和锁不
  因暂停、取消或恢复丢失，缺失点不补为未达成；
- 结果同时给出运行状态和由逐题明细推导的完成/部分完成/待复核/失败状态，
  并为超时、上下文、格式、存储、中断和取消提供可行动中文说明；
- P4-16 的证据发布、掌握度回流、学生反馈和下一轮推荐仍未实现；未接真实
  模型、真实答卷或真实数据库。

## 20. P4-16 训练证据、反馈、掌握度与下一轮

### 编码前冻结边界

- 目标：把 P4-15 的最终逐题明细可靠发布为可追溯训练证据，刷新掌握度 v2，
  形成学生个人反馈和待教师确认的下一轮推荐草稿；
- 包含：按题证据、outbox、幂等投递和补偿重放、撤回/教师修正后的重算、
  难度与证据时间/来源、掌握度前后解释、学生反馈、下一轮草稿及变化原因，
  以及供教师查看和操作的受控接口；
- 明确不包含：跨题累加成总分、正式考试分数/排名、自动确认或冻结下一份
  训练卷、自动打印/发送、读取 A/B 数据、真实模型、真实答卷、真实数据库
  迁移或任何费用；
- 验收条件：已完成题可独立发布，未复核/不确定/无法辨认题不发布也不补零；
  中断后 outbox 可重放且重复投递不重复证据；教师修正或撤回后可收敛重算；
  训练证据能解释掌握度与下一轮草稿变化；v2 关闭时证据仍可读但不改变 v1；
  下一轮只停留在草稿；
- 风险等级：很高。涉及幂等、并发、补偿重放、掌握度口径、跨模块状态和
  学生反馈，但实现与检查只使用临时数据库和合成学生。

### 集中调查与故障场景

- 证据身份固定为答卷 revision 与稳定题码的一题一条；判定点只在题内计算
  覆盖比例，不因某题判定点更多而获得更大权重；
- 冻结推荐快照中的 `matched_key` 是本题训练目标的稳定知识身份；难度、
  预计时间、来源题、判定点版本和教师锁均从冻结快照与最终明细取证，不回读
  当前可变题目替代历史事实；
- 教师锁定为 `uncertain/unreadable` 表示复核动作已完成，但仍不是可用于
  掌握度的确定证据；该题保留在反馈中并说明原因，不按 `not_met` 发布；
- 重复操作/响应丢失：相同 operation token 与输入返回当前同一反馈；不同
  token 也由稳定 evidence ID 和 payload hash 收敛，不生成重复证据；
- 同时操作：发布先核对 assessment `review_revision`；教师修正与发布并发时，
  旧版本发布失败关闭，新版本使用新 outbox 修订；
- 中途退出/重启：先在来源事务登记 outbox，再通过独立投递 Adapter 写证据
  投影；投影成功但确认状态未写回时，重放凭稳定 ID 幂等收敛；
- 失败重试：outbox 只重放本地证据，不调用模型、不产生费用；失败项保留
  明确状态和中文行动说明；
- 取消/部分完成：已发布题保留，未完成题保持待复核；撤回使用新修订，不
  物理删除历史 outbox 或审计；
- 教师修正：P4-15 新 `review_revision` 产生新证据修订，覆盖旧投影并重算
  掌握度/反馈/下一轮；旧候选和旧 outbox 仍可追溯；
- v2 关闭：训练证据照常保存和展示，掌握度预览可解释，但活动 v1 值不变；
  下一轮明确标注当前口径，不把训练覆盖伪装成 v1 分数；
- 数据缺失/冲突：冻结稳定知识身份缺失、来源 revision 变化、同 revision
  不同 payload、题目仍含不确定态或推荐来源不可重建时均安全降级或拒绝；
- A/B 隔离：不读取备课或班主任目录/数据库；本包不新增任何跨工作台写入。

### 实现结果

- 新增按题证据 outbox、稳定证据投影、同步操作审计和学生反馈快照；证据
  身份固定为答卷 revision 与稳定题码，一题只形成一条 mastery evidence，
  判定点只在题内计算覆盖比例；
- 已完成题可独立发布；未复核、`uncertain` 和 `unreadable` 题留在反馈中，
  不发布、不补零，也不伪装成未达成。教师新修订会更新仍有效的题并自动撤回
  已失效题，显式撤回不物理删除历史；
- outbox 先登记再投影，投递失败保留失败状态；重放只处理未收敛项，稳定
  evidence ID 防止重复。相同 operation token 在状态未变化时返回已保存反馈，
  响应丢失后不会生成不同时间戳版本；
- 训练证据带冻结知识身份、每题覆盖比例、难度权重、预计时间、来源卷、
  判定点版本、最终逐点结果和教师修正，可追溯到具体题与判定点；
- 掌握度解释同时给出 v2 前后值、变化方向、活动口径和参数版本；v2 关闭时
  证据仍保存并可预览，但不改写 v1。个性化推荐来源版本已纳入活动训练证据，
  同日新增证据使用实际发生时刻重算，不被日初时间截断；
- 每次收敛形成学生个人反馈、题目发布状态、掌握度变化和审计时间线；来源

### 集中测试发现与统一修复
