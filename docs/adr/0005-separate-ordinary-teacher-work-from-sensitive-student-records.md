# Separate ordinary teacher work from sensitive student records

Ordinary calendar actions and SOP work graphs do not require an unlock and are stored outside the encrypted student-affairs vault. Sensitive student records are not mounted or fetched until the teacher opens the protected entry. The two stores use opaque references rather than cross-database foreign keys, and a local safety router must decide the destination before a write.

Ordinary-work classification, semantic decomposition, dependencies, follow-up questions, and backward scheduling are proposed by the configured AI for the teacher's current context. Local code does not encode meeting, collection, PPT, or other domain-step templates. It only rejects or reroutes sensitive text, extracts an explicit final date as a constraint, presents the complete model payload and a credential-free provider/endpoint/model destination for per-call confirmation, binds both to the confirmation fingerprint, prevents duplicate physical calls, validates every returned question, assumption, node, date, and edge, and requires a second teacher confirmation before persistence. If the model is unavailable, fails, returns an unknown result, or needs more information, the system does not fabricate a local plan.

The protected entry uses a teacher-created six-digit PIN as a quick application gate, while a random high-entropy vault key is protected with Windows current-user scope and an independent high-entropy recovery route. The PIN alone is deliberately not treated as encryption strength. Existing password-protected data remains compatible and is never automatically migrated or rewrapped.

Every ordinary planning call likewise requires an exact preview of the complete JSON payload and explicit confirmation for that physical request; adapters may not append a hidden business prompt. A durable operation receipt is claimed before dispatch. Browser timeout or reload recovery may poll only that same operation ID and may not resend the task; a destination change invalidates the preview before network dispatch. Sensitive text may reach a configured external model only after local minimization and anonymization, an exact per-request send preview, and explicit confirmation. Consent is not remembered, failures do not retry automatically, and all model output remains a draft until the teacher confirms it. Keeping all teacher work behind one vault was rejected because it makes ordinary work unusable; local keyword decomposition was rejected because examples would become brittle business rules; using a six-digit PIN as the sole encryption key and granting blanket model consent were rejected because they expose student data to trivial guessing or uncontrolled disclosure.
