# 项目文档入口

本页只列当前仍有权威作用的文档。项目更改历史看 Git，不在当前文档中重复保存。

## 权威顺序

内容发生冲突时，按以下顺序判断：

1. 用户当前明确指令；
2. 根目录 `AGENTS.md` 的长期协作、安全与授权规则；
3. 根目录 `ARCHITECTURE.md` 的当前已实现事实；
4. 根目录 `CONTEXT.md` 的当前统一词义；
5. 对应产品、安全、存储、测试或界面的专项权威文档；
6. 源码、schema 与当前测试提供的专项证据。

README 负责帮助用户启动和理解系统，不覆盖安全红线或代码事实。

专项文档只在自己的主题内拥有权威；它不能无来源地改变相邻模块的业务含义。

## 根目录入口

### `README.md`

面向非技术用户的当前使用说明，包括启动、关闭、四条常用流程、数据、备份和外部模型风险。

### `AGENTS.md`

面向编码代理的长期协作规则，包括调查、冻结范围、复用、授权、worktree、安全、验收和文档纪律。

### `ARCHITECTURE.md`

系统当前事实的总入口，包括运行形态、模块、路由、数据、schema、任务、重放、业务不变量、备份和限制。

### `CONTEXT.md`

当前统一词汇，定义阅卷、知识训练、班主任工作对象以及可靠性术语。

### `CLAUDE.md`

兼容工具入口，只指向 `AGENTS.md` 和上述当前权威文档，不重复规则。

## 三个产品入口

## 专项权威入口

### `docs/security/SECURITY.md`

当前信任模型、敏感数据、路径安全、模型出站、诊断、班主任明文风险和逐次授权边界。

### `docs/maintenance/storage-policy.md`

当前数据目录、文件归属、备份范围、排除项、恢复要求和保留规则。

### `docs/maintenance/packaging.md`

当前完整安装包、增量更新与数据库 schema 迁移的机制、安全规则和未覆盖范围。

### `docs/testing/README.md`

当前测试分层、命令入口、隔离数据要求和交付前验证方式。

### `docs/ui/STYLE.md`

当前视觉、布局、组件状态、交互和可访问性规范。它不定义业务流程或数据含义。

### `frontend/README.md`

当前前端工程结构、开发命令、路由与组件约定。

## 文档内容规则

当前文档只保留能从页面、代码、schema、配置或稳定业务规则验证的事实。

文档中不保存：

- 阶段计划、任务拆包或实施顺序；
- 编码日记、交接过程或迁移执行流水；
- 验收流水、已完成清单或临时检查结果；
- 提交号、分支头、合并记录或远程请求编号；
- 容易过期的测试通过数量、文件数量和覆盖率快照；
- 已被当前入口替代的操作说明；
- 只为一次讨论存在的分析稿或决策草稿。

需要追溯“何时、为何、由谁改变”时查看 Git 记录。

需要表达当前重要取舍时，直接写当前约束、原因和影响，不复制变更过程。

## 更新规则

- 先找到本页列出的主题权威文档，再修改对应一份。
- 当前事实变化时同步更新 `ARCHITECTURE.md`；词义变化时同步更新 `CONTEXT.md`。
- 面向用户的启动、数据或风险变化时同步更新根目录 `README.md`。
- 不新建与现有权威文档并列的第二份总说明。
- 删除或移动文档前，先检查代码、脚本、测试和当前文档中的引用。
- 兼容格式只写成“兼容输入”，不恢复成当前主流程说明。
- 内容寻址的兼容发布包可以保留指向 Git 中已退役文件的来源路径字符串；它们是发布载荷和内容指纹的一部分，不是当前文档链接。不为了让这类字符串可打开而恢复旧文档，也不在不新建发布身份的情况下改写它们。
