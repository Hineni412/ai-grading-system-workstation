# AI 输入、输出与本机诊断

本文件说明当前应用会把什么交给 AI、期望 AI 返回什么，以及返回标签怎样进入题库。它不保存真实请求、真实响应、学生信息或密钥。

## 调用内容

| 用途 | 发送给 AI | 期望返回 |
|---|---|---|
| 姓名识别 | 答卷姓名区域图片；需要匹配时附有限候选名单 | 识别文字或候选学生结果 |
| 分批生成评分依据 | 当前批次题号、程序提取的题干和答案片段、题型及其是否经教师确认；DOCX 同时附带按题归属的题目、答案和解析图片，PDF 只附题目/答案裁图 | 同一批题目的题型、标准答案、可接受答案、评分单元和步骤；不生成知识点或题库标签 |
| 整卷生成评分依据 | DOCX 的整份可读文本和按题号标明归属的关联图片，或 PDF 按页排列的整页图片 | 全卷完整评分依据和总分；结果必须一次完整返回，不生成知识点或题库标签 |
| 评分依据人工结构精修 | 当前完整评分依据和教师已经作出的拆分/结构决定 | 保留教师结构的完整新版本 |
| 答卷批改 | 正式评分依据、参考答案素材和学生答卷图片 | 各题得分、理由、证据、置信信息和可供复核的结构化结果 |
| 题库 AI 标注 | 题干、答案、题型、年级/学期/试卷背景、是否含图、已有标签值，以及当前词表版本和按题意筛出的教材归属、知识点、能力、解题方法、数学思想、数学模型、特殊题型候选；“是否含图”只发送布尔值，不发送题目图片正文 | 七个维度的规范词 ID/名称、难度、易错点、先修内容、适合学生层级、理由、置信度；知识点完全无匹配时最多另列 1 个新词候选 |

只有明确包含图片的调用（例如姓名识别、DOCX/PDF 评分依据生成和答卷批改）才会把图片作为模型请求的一部分发送给用户当前配置的模型服务。题库 AI 标注目前只发送“是否含图”这个事实。供应商如何保存和使用已发送的数据，取决于用户所配置服务的政策。

### 题库标注的字段边界

题库标注输入按一题一个对象组织，主要包含 `question_id`、题号、题型、题干、答案、年级、学期、试卷类型、区县、`has_images` 和已有标签值；提示词还附带当前 `taxonomy_revision`（词表版本）和按题干、答案等内容筛出的七维规范词候选。候选只包含稳定 ID 和规范名称；别名及被合并的旧词只参与本地召回与归并，不暴露为可自由输出的新词。已有标签只是参考，不能绕过受控词表。

AI 返回对象包含：教材归属、知识点及稳定编码、能力、解题方法、数学思想、数学模型、特殊题型、难度、易错点、先修内容、适合学生层级、理由、置信度和原样回显的词表版本。AI 不再生成教学阶段、子技能、主要技能或辅助技能。

七个正式筛选轴全部严格收敛：教材归属只到“某年级上/下册第某章”；知识点、能力、解题方法、数学思想、数学模型和特殊题型必须来自各自维度的规范词。解题方法回答“具体怎么做”，数学思想回答“用什么通用策略思考”，数学模型回答“复用了什么稳定数量关系或几何结构”。先修内容也按知识点维度校验；易错点和适合学生层级继续使用各自现有的有限规则，但不进入这套七维词表。

只有知识点确无匹配时，AI 才能在 `proposed_tags` 中提出最多 1 个候选，并说明名称、定义、提出理由、最接近的规范词以及为什么不能复用。方法、思想、模型等维度不允许自由造词；未知值会在本地被剔除。候选不会混入普通标签字段，也不会因为 AI 返回一次就成为正式词。

## 请求次数

- 分批生成：每批一次；所有批次完成后统一配分一次。失败批次只有教师明确操作后才会重试。
- 本地质量门拒绝某题后，教师明确重试会把该题的旧结果、具体问题和可修改范围交给模型做一次定向修复；
  未失败题不重发。修复后同一问题原样存在时停止继续请求并提示人工处理；同题最多进行两次定向修复。
- 证据结构尚未通过本地质量门时不调用统一配分，避免对注定不能发布的结构增加一次模型费用。
- 整卷生成：一次物理模型请求，本地只做 JSON 解析、结构校验和总分规范化。失败不自动重试，不发布半成品。
- 评分依据生成的本机等待时间为 240 秒。该设置不能延长外部供应商或其代理自身的超时；外部先返回超时后，
  本机只记录失败并等待教师决定是否重试。
- 不把坏 JSON 自动交给另一次模型“修复”；允许不产生费用的本地 JSON 修复。
- 其他调用是否允许有限网络重试，取决于对应调用策略；每次尝试都会单独出现在 AI 调用记录中。

## 标签收敛

新的题库 AI 标注按以下顺序处理：

1. 每批任务开始时冻结一个词表版本，避免同一批题目使用两套词表；
2. AI 只能从提示词中七个维度各自的候选 ID/名称中选择；
3. 程序再按规范词 ID、规范名称、已登记别名和隐藏旧词映射严格核对；全部统一到当前规范词；
4. 未知词从普通标签中剔除；只有每题最多 1 个未知知识点保存到本机待审核清单，同一请求重复提交不会重复造词；
5. 教师在题库页或试卷导入页打开“AI 新词审核”，可直接批准、改名后批准、合并到已有词或拒绝；
6. 批准或合并后的名称及别名从下一个 AI 请求起进入可选词表，也能兼容筛选历史别名；拒绝词不会进入正式词表，同名内容再次出现时也不会反复生成隐藏待审任务。

规范词基础目录随代码只读发布，教师决定保存在当前 Windows 账户的本机配置目录，并采用版本号冲突检查、幂等请求、临时文件原子替换和上一版本备份。运行时不会再访问外部题库网站。

该规则只影响今后经过正式 AI 质量流程的新结果，不批量迁移历史标签，也不覆盖教师手工标签。历史教学阶段和子技能仍留在数据库中以保证旧数据可读，但不再出现在组卷筛选入口。批准新词也不会自动回填关联题目的旧标签；题目下次正式打标时才能使用它。生成评分依据不请求或生成知识点，题库标签只由独立的题库打标签与人工治理流程产生。

## 本机 AI 调用记录

“设置 → AI 服务 → 调用记录与排查工具”展示，并可按来源、工作台、具体功能和调用结果筛选：

- 用途、模型、协议、开始/结束时间、耗时、请求编号和重试情况；
- 实际文本请求和模型原始文本响应；
- 本地解析出的 JSON、解析状态和本地修复步骤；
- 错误分类、HTTP 状态和下一次重试等待时间；
- 图片用途、字节数和 SHA-256 指纹。

安全边界：

- 不保存 API Key、Authorization、完整服务 URL、本机绝对路径或图片/base64 正文；
- 文本请求和响应可能包含试卷、答案或学生作答内容，属于本机敏感诊断数据；
- 文件只保存在 Git 已忽略的 `logs/`，不会进入代码提交；
- 单个日志约 32 MiB 时滚动，保留当前文件和最近 3 个轮转文件。
- 记录功能只覆盖升级后新发生的调用，不补写升级前的历史调用。
- 升级前已有的工作台任务若仍在共同任务表中，只能显示安全状态摘要；当时没有落盘的实际发送正文和模型原文无法事后恢复。
