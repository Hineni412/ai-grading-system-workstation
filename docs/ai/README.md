# AI 输入、输出与本机诊断

本文件说明当前应用会把什么交给 AI、期望 AI 返回什么，以及返回标签怎样进入题库。它不保存真实请求、真实响应、学生信息或密钥。

## 调用内容

| 用途 | 发送给 AI | 期望返回 |
|---|---|---|
| 姓名识别 | 答卷姓名区域图片；需要匹配时附有限候选名单 | 识别文字或候选学生结果 |
| 分批生成评分依据 | 当前批次题号、程序提取的题干和答案片段、题型及其是否经教师确认、相关题目/答案图片、有限原文 | 同一批题目的题型、知识点说明、标准答案、可接受答案、评分单元和步骤 |
| 整卷生成评分依据 | DOCX 的整份可读文本，或 PDF 按页排列的整页图片 | 全卷完整评分依据和总分；结果必须一次完整返回 |
| 评分依据人工结构精修 | 当前完整评分依据和教师已经作出的拆分/结构决定 | 保留教师结构的完整新版本 |
| 答卷批改 | 正式评分依据、参考答案素材和学生答卷图片 | 各题得分、理由、证据、置信信息和可供复核的结构化结果 |
| 题库 AI 标注 | 题干、答案、题型、年级/学期/试卷背景、是否含图、已有标签值，以及知识点、章节、方法、能力、数学模型等候选词表；“是否含图”只发送布尔值，不发送题目图片正文 | 知识点及稳定编码、章节、方法、能力、数学模型、难度、易错点、训练技能、理由和置信度 |

只有明确包含图片的调用（例如姓名识别、PDF 整卷生成和答卷批改）才会把图片作为模型请求的一部分发送给用户当前配置的模型服务。题库 AI 标注目前只发送“是否含图”这个事实。供应商如何保存和使用已发送的数据，取决于用户所配置服务的政策。

### 题库标注的字段边界

题库标注输入按一题一个对象组织，主要包含 `question_id`、题号、题型、题干、答案、年级、学期、试卷类型、区县、`has_images` 和已有标签值；提示词还附带受控的知识点稳定编码、章节、方法、能力、数学模型候选表。已有标签只是参考，不能绕过受控词表。

AI 返回对象包含：知识点和稳定编码、方法、能力、数学模型、难度、易错点、先修内容、教材章节、教学阶段、适合学生层级、细分技能、主要/辅助训练技能、理由和置信度。程序随后执行本地质量检查，不把模型返回文本直接写成正式标签。

当前严格收敛的是题库主要筛选轴：知识点、能力、方法、数学模型和教材章节。细分技能、主要/辅助训练技能、易错点和先修内容仍允许更细的描述，不宣称已经形成完全封闭的词表；它们仍需通过质量状态和教师核对管理。

## 请求次数

- 分批生成：每批一次；所有批次完成后统一配分一次。失败批次只有教师明确操作后才会重试。
- 整卷生成：一次物理模型请求，本地只做 JSON 解析、结构校验和总分规范化。失败不自动重试，不发布半成品。
- 不把坏 JSON 自动交给另一次模型“修复”；允许不产生费用的本地 JSON 修复。
- 其他调用是否允许有限网络重试，取决于对应调用策略；每次尝试都会单独出现在 AI 调用记录中。

## 标签收敛

新的题库 AI 标注按以下顺序处理：

1. AI 从提示词中的候选词和知识点稳定编码表选择；
2. 程序再对规范词、编码和已登记别名做严格匹配；
3. 已知别名统一为规范词，例如“全等三角形”“三角形的全等”统一为“三角形全等”；
4. 能力、方法、数学模型和教材章节也按各自候选词表与保守别名收敛；
5. 未知词保留在本次分析中供教师查看，同时标记为冲突，不能自动保存为新的筛选标签。

该规则只影响今后经过正式 AI 质量流程的新结果，不迁移历史标签，也不覆盖教师手工标签。评分依据中的知识点说明和题库筛选标签是不同数据；生成评分依据不会直接创造新的题库筛选标签。

## 本机 AI 调用记录

“设置 → 大模型 API 配置 → AI 调用记录”展示：

- 用途、模型、协议、开始/结束时间、耗时、请求编号和重试情况；
- 实际文本请求和模型原始文本响应；
- 本地解析出的 JSON、解析状态和本地修复步骤；
- 错误分类、HTTP 状态和下一次重试等待时间；
- 图片用途、字节数和 SHA-256 指纹。

安全边界：

- 不保存 API Key、Authorization、完整服务 URL、本机绝对路径或图片/base64 正文；
- 文本请求和响应可能包含试卷、答案或学生作答内容，属于本机敏感诊断数据；
- 文件只保存在 Git 已忽略的 `logs/`，不会进入代码提交；
- 单个日志约 32 MiB 时滚动，保留当前文件和最近 3 个轮转文件。
- 记录功能只覆盖升级后新发生的调用，不补写升级前的历史调用。
