# 相似题向量检索验证实验

用途：验证向量能否补充当前相似题排序，并测量本机精确检索成本。本文件记录实验方案与结果，不是已上线产品规则。

## 范围与复用

复用 `tools/experiment_similar_questions.py` 的只读数据读取、题目与有效小问资料投影、盲评候选池及配对评价；复用 `tools/experiment_similar_questions_v2.py` 的数学文本处理和排除开发题及近模板题的留出抽样；直接复用当前 `similar_question_ranker.py`。

旧实验的固定比较路线不适合加入向量后改写参数，因此新增 `tools/experiment_vector_similarity.py` 作为隔离实验入口。正式题库、推荐、学生分组、评分与训练流程不变。

## 固定比较方案

- 候选语料：只读读取当前未删除且所属试卷未删除的题库题目；内容只在进程内使用，不复制数据库或导出题目原文。
- 查询样本：24 道留出题，先按现有规则排除开发样本及文字上相近的模板题，再按题型和难度均衡抽样；覆盖选择、填空与解答题。抽样方法不保证数学考法完全独立。
- 当前算法：正式采用的 B 排序，另与应用相似题入口逐题核对。
- 纯向量：精确余弦检索前 6 题，不把相似度解释为同题概率。
- 混合算法：当前排序与向量各取前 80 题，按 0.75/0.25 权重进行 RRF 排名融合，沿用当前规则分至少 0.25 的候选要求。它不能解决被原规则门槛排除的所有漏检。
- 向量输入：题干、现有小问作答要求、答案解析，不放入预测错因或学生掌握度；固定字段词元预算，总长最多 512，记录截断数量。图片不参与向量编码。
- 评价：隐藏路线的候选合并池，0 无关、1 部分相关、2 可用练习、3 接近替代、null 资料不足。按查询比较每 6 个位置的可用题数和池内 nDCG；不能将池内评价宣称为全题库召回率。
- 性能：分别记录资料读取、模型加载、首次向量生成、三条路线排序耗时、原始向量大小与进程峰值内存。这里只测精确内存检索，不推断其他数据库的性能。
- 自造边界题：12 组三题对比，明确同一训练任务应排在改变任务的干扰题之前，检查解方程与根条件、勾股定理与逆定理等边界；只是诊断样本，不代表全题库质量。

## 实际模型与授权范围

本次使用 BAAI `bge-small-zh-v1.5` 的公开 ONNX 转换版 `Xenova/bge-small-zh-v1.5`，下载版本为 `75c43b0`。原模型为中文 512 维向量模型；作者示例采用 CLS 词元向量和单位长度归一化，相似任务可以不添加检索指令。

来源：[原模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[ONNX 文件](https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/main/onnx)。全精度模型文件约 94.9 MB，另需本地分词文件；实验只使用本机 CPU，不需要密钥，不调用收费接口，不上传题目。

用户已明确授权本次免费本地模型实验。实际对 1,334 道现有题及 36 道自造边界题编码一次，共 1,370 条、172 个本地批次；远程模型请求为 0。题库只读，源数据代次与知识标准代次在实验前后保持一致。模型、匿名评价和汇总保存在本次 `output/` 实验目录，未保存题目原文或向量。依据项目 `AGENTS.md`，以后再次执行真实模型实验仍须针对该次操作单独授权。

## 质量结果

只读语料为 1,334 道题，其中 1,333 道有当前有效小问资料。查询排除了 30 道旧开发题和 207 道文字近模板题，再从 1,097 道合格题中抽取 24 道：6 道选择、9 道填空、9 道解答。24 道基线结果全部与正式相似题入口一致。

三路线合并后共 247 个查询内候选，由 Codex 隐藏路线评价；本轮没有资料不足的 null 评价。评价依据题面和解析中的训练任务，不等于逐图核对题目正确性，也不是教师独立验收。多任务题覆盖一个主要训练部分可记 2 分，遗漏其他部分不记为整题的接近替代；只有共同背景或共同知识名词记 1 分。

| 指标 | 当前正式算法 | 纯向量 | 混合 |
| --- | ---: | ---: | ---: |
| 每条路线推荐位置数 | 144 | 144 | 144 |
| 可用练习数（评价至少 2） | 110 | 94 | 114 |
| 可用比例（每题固定 6 个位置） | 76.39% | 65.28% | 79.17% |
| 接近替代数（评价 3） | 53 | 44 | 55 |
| 每题平均可用练习数 | 4.58 | 3.92 | 4.75 |
| 池内 nDCG@6 | 0.8940 | 0.7723 | 0.9122 |

池内 nDCG 表示较有用的题是否排在前面，理想顺序只来自本轮候选池；它不是全题库召回率。144 个位置也不是 144 个独立样本，同一道候选可以出现在不同查询中。

- 纯向量相对当前算法：5 道查询变好、7 道相同、12 道变差，可用比例下降 11.11 个百分点。按查询配对重采样的探索性 95% 区间为 -21.53 至 -1.39 个百分点。
- 混合相对当前算法：4 道变好、19 道相同、1 道变差，可用比例增加 2.78 个百分点；探索性区间为 -0.69 至 6.94 个百分点，包含零。它支持继续研究，尚不足以确认稳定提升。
- 三路线的排序列表均有变化；“列表变了”与“可用题变多”是不同指标。

## 任务边界诊断

12 组预先固定的自造边界题，纯向量有 8 组把同任务练习排在改变任务的干扰题之前。4 组失败情况如下；这些是自造诊断题，不含题库原文。

| 目标与干扰关系 | 同任务相似度 | 改变任务相似度 | 结果 |
| --- | ---: | ---: | --- |
| 解方程 / 求参数使根满足条件 | 0.62125 | 0.80462 | 更偏向改变任务的题 |
| 证明三角形全等 / 求三角形内角 | 0.56332 | 0.62551 | 更偏向改变任务的题 |
| 解负系数不等式 / 解相同文字的方程 | 0.69831 | 0.77798 | 更偏向改变任务的题 |
| 两个作答任务 / 只保留其中一个任务 | 0.75486 | 0.82634 | 更偏向遗漏任务的题 |

真实样本也出现了相同问题：相同光学场景中的求角与求函数式、几何折叠与普通对称作图、统计量的不变性与直接计算统计量，不能仅凭文字或场景接近互相替代。保留现有任务规则的混合路线缓解了部分误推荐，但没有全部解决。

## 本机成本

| 项目 | 实测 |
| --- | ---: |
| 资料读取与验证 | 11.276 秒 |
| 本地模型加载 | 1.018 秒 |
| 1,370 条首次编码 | 201.724 秒（约 3 分 22 秒） |
| 1,334 题原始向量 | 512 维 float32，2.605 MiB（约 2.7 MB） |
| 整个实验进程峰值内存 | 2,187.11 MiB（约 2.3 GB） |
| 当前排序中位数 / P90 | 112.455 / 129.132 ms |
| 纯向量排序中位数 / P90 | 2.227 / 2.697 ms |
| 混合排序中位数 / P90 | 122.163 / 145.364 ms |

排序在同一进程、同一语料、相同查询上测量，逐查询随机执行路线次序。排序耗时排除了模型编码、共用资料读取和正式应用缓存，不能当作页面完整响应时间。混合方案保留现算法计算，因此没有获得纯向量检索的速度优势。当前算法在另一次无模型基线运行中中位数为 68.188 ms；本机并行任务会造成耗时波动，不把两次运行差异归因于模型。

峰值内存包含题库读取、资料处理、现有索引与模型运行，不能把它全部记为向量索引内存，也不能通过不同进程的峰值相减得出精确模型增量。

字段预算导致 159 条题干、454 条作答要求、1,296 条解析发生截断。这是本轮输入配置的明显限制，尤其长解答题可能丢失后面的小问或关键推理。结果评价的是“小型 BGE 模型 + 本轮字段截断方案”，不能推广到所有向量模型或所有输入方法。

## 决策与未实现内容

本轮建议保留当前正式算法，暂不以纯向量替换，也不迁移到向量数据库。混合方案增加 4 个可用位置，但效果尚不稳定，并增加首次编码与运行内存成本。本次 1,334 题的精确向量排序已足够快，实验没有发现必须依靠向量数据库才能解决的检索性能问题；这不是向量数据库与 SQLite 的直接性能比较。

若继续研究，优先按小问组织向量输入并保留题目条件和作答任务，再扩大未使用样本、由教师复核，之后再考虑更强模型及索引管理。本轮评测样本已经被观察过，以后调参不能仍将其宣称为未使用验证集。

尚未实现正式向量持久化、增量更新、数据库迁移、聚类或去重合并；未验证图片向量、多模型、近似索引、大规模题库、学生选题资格及实际学习效果。正式产品行为没有变动，也没有真实数据改写需要恢复。
