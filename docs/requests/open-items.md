# 尚未完成的待办

用途：汇总仍未完成的事项（2026-09-30 按当前代码核对）。本文只列待办，不描述已实现功能；已实现规则以产品文档为准。原始方案与调查记录保留在 Git 历史中。

## 已确认待实现的新功能

- [学生错题本导出](wrong-question-book.md)
- [训练推荐规则面板与讲义模式](recommendation-rules-panel.md)

## 错因

- 典型错法没有“关联技能”字段；“判定点”触发只在自动回挂带判定点编号的整理结果时产生。
- 学生错因记录没有逐条“来源”字段，教师也不能逐个学生调整错因。
- 旧题库标签自由文本的“仅预测候选”没有页面展示入口（读取函数已有）。
- 班级 AI 讲评的输入仍按原始扣分理由归并，未改用新错因；改动会使已有讲评缓存失效并产生费用，需单独决定。
- 批改提示词仍要求旧的错误类别，教师确认分数未写批语时错误类别仍写为“已复核”；新错因链路不读取该字段，但报告、成绩表和薄弱点统计在题目未整理错因时仍以它兜底。

## 题库导入

- 题库导入完成后，页面不区分“完全同题已关联”“相似或变式供核对”“答案冲突需处理”，也不列出本卷题号与已有来源（接口已返回匹配类型与匹配来源）。整卷重复上传时完成提示不显示同题数量。
- 扫描版 PDF 经本机识别入库的题目全部进入复核，但扫描页原图没有写入题目图片，复核时只能对照归档原卷。

## 报告

- 个人报告中的“报告分析提示”（原卷与评分理由冲突）只写在各学生 HTML 里，没有汇总到复核入口；教师需要逐份文件查看。

## 静默失败

2026-09-30 审查“捕获所有异常”时发现约 30 处失败会被静默吞掉，重点：

- 客观题标准答案加载失败时按空答案继续识别（`objective_batch_recognition_service.py`）。
- 评分依据文件读取失败时预检、复核分值显示、薄弱点与知识标签统计按空内容继续（`grading_service.py`、`backend/review/service.py`、`backend/repositories/results.py`、`integration/mastery_adapter.py`）。
- 正反面配对状态文件读取失败时默认按奇数页配对（`grading_service.py`）。
- 批改运行记录写入失败被忽略，可能出现已批改但运行记录缺项（`grading_service.py`）。
- 评分依据生成作业中断时若草稿摘要失败，任务不会被标记失败而停在“运行中”（`backend/jobs/config_generation.py`）。
- 评分规则中的正则表达式编译失败时退化为按字面匹配（`score_policy.py`）。
