# 尚未完成的待办

用途：汇总原 `docs/requests/` 各方案、调查与验收记录中仍未完成的事项（2026-09-29 按当前代码核对）。本文只列待办，不描述已实现功能；已实现规则以产品文档为准。原始方案与调查记录保留在 Git 历史中。

## 错因

- 典型错法没有“关联技能”字段；“判定点”触发只在自动回挂带判定点编号的整理结果时产生。
- 学生错因记录没有逐条“来源”字段，教师也不能逐个学生调整错因。
- 旧题库标签自由文本的“仅预测候选”没有页面展示入口（读取函数已有）。
- 班级 AI 讲评的输入仍按原始扣分理由归并，未改用新错因；改动会使已有讲评缓存失效并产生费用，需单独决定。
- 批改提示词仍要求 `error_category`；教师确认分数未写批语时“错误类别”仍写为“已复核”（新错因链路不读取该字段）。

## 题库导入

- 题库导入完成后，页面不区分“完全同题已关联”“相似或变式供核对”“答案冲突需处理”，也不列出本卷题号与已有来源（接口已返回 `match_kind` 与匹配来源）。整卷重复上传时完成提示不显示同题数量。
- 阅卷归档入库（`question_bank/services/grading_paper_intake_service.py`）调用导入时不传本地文档管线，扫描版 PDF 在该路径仍按无文字层处理；扫描页原图未写入题目图片，复核对照依赖归档原卷。

## 报告

- 个人报告中的“报告分析提示”（原卷与评分理由冲突）只写在各学生 HTML 里，没有汇总到复核入口；教师需要逐份文件查看。

## 结构改进候选

2026-09-29 架构检查提出、尚未实施的改进，按建议顺序（学情诊断快照与移除工作台空壳已完成）：

1. 调用方直接使用成绩库具名仓储，收掉 `DBManager` 与 `GradingRepositoryAccess` 的转发外观。
2. AI 批改收拢为一条执行路径；整卷批改、混合批改只保留历史结果读取，不再续跑或新建（用户已确认）。
3. 把场次分析数据从 `analysis_report_exporter.py` 中独立出来，内容生成模型设置移到模型配置一侧。
4. 确认配置页“重新整卷生成／重新分批生成”是否保留后，收窄评分依据生成作业的旧模式。
5. 确认是否还需查看旧 AI 组卷会话后，移除已无页面入口的 AI 组卷前后端。
6. 联合分析中 `training_criteria/in_memory.py` 按业务含义改名，合并重复的并发上限判断。
