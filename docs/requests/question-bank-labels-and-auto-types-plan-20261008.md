# 题库标签体系与新册自动题型方案

用途：记录 2026-10-08 与用户讨论确定的题库标签调整、新教材册自动题型、按章切换训练目标，以及对其他模块的影响和修改范围。本文保留讨论时确定的方案与完成标准。标签分层、按章训练目标、自动题型发布、五维定义、旧题受限刷新入口及维护界面的代码已实现，并完成相关合成验证；真实外部模型质量回测仍须另行报价与授权。八上旧题由已授权的 Codex 离线判断经受限刷新程序执行，具体输入、差异、保存状态与待核对原因以题库受控回执为准。当前可验证的产品行为以 [题库、组卷与个性化训练](../product/KNOWLEDGE_AND_TRAINING.md) 为准。上一轮题型改版的依据见 [题型改版方案](question-type-redesign-plan-20261006.md) 与 [交接](question-type-redesign-handoff-20261007.md)。

## 1. 已确认的决定（2026-10-08）

| 问题 | 决定 |
|---|---|
| 教师在新册的操作 | 教师只负责导入试卷；知识点、题型、技能和其他属性全部由系统自动完成 |
| 学科网知识点 | 保留；恢复为可写到判定点的标签，整题自动汇总显示 |
| 题型与知识点的关系 | 题型按整题核心任务定义，不定义为知识点组合；每个题型显示“常涉及的知识点”，由该题型下题目的知识点统计得出 |
| 题型挂在哪 | 只挂整题：主题型 1 个，次题型最多 2 个 |
| 新册题型清单 | 系统按章自动整理并直接发布，不经教师审核 |
| 自动整理的费用确认 | 并入导入时已有的费用确认，不增加操作步骤 |
| 尚未形成题型的章 | 按章切换：该章临时用学科网知识点作训练目标，形成题型后自动换成题型 |
| 八下试卷 | 用户已有 10 份以上，可在开学前集中导入 |
| 技能 | 继续由导入分析自动生成，不再作为教师的主要待办 |
| 其他五维属性 | 能力、数学思想、解题方法、数学模型、特殊题型或考法必须保留，并提高模型打标质量 |
| 八上旧题补标 | 学科网知识点回填与五维刷新合并为一次重打，先抽样对比再全量；动手前报价并单独授权 |
| 题库维护的重心 | 判定点（评分依据）为底座，整题标签与判定点两块呈现 |
| 实施顺序 | 按第 6 节阶段 1 到 6；开学前完成阶段 2、3 |

### 2.2 本方案要解决的问题

1. **学科网细项知识点写不进判定点。** `question_bank/taxonomy/governance.py` 在标准中存在任何活动技能时，把细项知识点标为“仅供检索”，判定点只能关联技能和本册小节。该规则对整份标准生效，不分册，所以导入八下同样受影响。
2. **五维词表只有名称。** `tag_vocabulary_v10.json` 中能力 10、思想 13、方法 23、模型 41、考法 12 条词条均没有定义、纳入或排除范围；候选合同对这五维只传编号和名称。题型与技能则带定义和锚题。
3. **只有八上有题型。** v9 标准共 100 个题型，全部在八上；八下有 0 个题型、1 个技能，九上 0 个技能，七上 2 个。八下按现规则进入技能模式，诊断与推荐几乎为空。
4. **建题型清单和发布标准都靠离线操作。** 题型词表由代理离线整理、用户逐章审核，再用 `tools/build_type_release.py` 生成；新标准文件要在 `question_bank/knowledge_graph_release/loader.py` 的代码映射中登记，启用时要停止应用。
5. **题库维护仍按技能口径。** 页头显示技能数，页签为“按技能”，题目状态为“未挂技能”；“AI 补齐”只查标签、解题证据、判定点和技能关联；“待处理”以技能缺口为主。缺题型的题（当前 42 道）都有技能关联，判定点无待审时显示为完整。
6. **新题型提议批准后不生效。** 模型找不到合适题型时提出的新词，进入知识点新词待审；按 `question_bank/services/taxonomy_review_service.py` 的代码，批准或归并只给勾选的题加一条题目标签，不新建题型节点，也不写判定点关联；未实际操作验证。
7. **题型存了两份。** 整题标签与判定点关联各存一份主题型：考试证据投影读整题标签，推荐候选读判定点关联。题目详情把主题型显示为普通“知识点”标签，次题型不显示；教师手改时两份可能不一致。

## 3. 目标设计

### 3.1 教师看到的两块

1. **整题标签**：章节；题型（主题型、次题型）；知识点（判定点上学科网知识点的汇总）；能力、思想、方法、模型、考法。全部直接显示，都可用于找题。
2. **判定点（评分依据）**：按小问分组列出判定点，小问标题处显示作答方式和小问难度；每个判定点旁用小字标出本步的技能、知识点和前置知识，由系统自动生成。

小问只表示题目结构，不再作为一层标签。典型错法保留在原错法区。存储不迁移：题目标签表中混存的技能、题型与知识点，仍按稳定标识在显示和统计时分开。

### 3.2 题型

- 整题标签是主题型和次题型唯一可编辑的来源。主题型在判定点上的副本由系统根据整题标签自动同步，不单独编辑；推荐、掌握度和考试投影等现有读取处继续读副本，含义保持“整题任务”。
- 教师可在题目详情修改主题型；保存时同一事务更新整题标签与当前判定版本上的全部副本，沿用修订冲突保护。
- 每个题型显示“常涉及的知识点”，按该题型题目的判定点知识点统计，只读，不参与掌握度。

### 3.3 学科网知识点

- 取消“存在技能时细项知识点仅供检索”的规则：本册细项知识点可作为判定点的直接关联，更早册别只作前置知识；技能、本册小节的现有关联规则不变。
- 整题“知识点”由判定点关联汇总，题目本身不另存一份可编辑的知识点。
- 知识点的直接关联会进入小节归属、跨章判断和教学进度检查。为避免更多题被判为跨章而退出章节专项推荐，实施时须先在副本上比较这些结果；细则见第 7 节。

### 3.4 五维属性

- 为 99 条词条补齐定义、纳入范围、排除范围与 1–2 道锚题，格式与题型词表一致，以新的词表修订安装。按全自动原则，不要求教师审核。
- 候选合同对这五维同时传递定义与范围；提示词升级版本，已有题不因升级自动重打。
- 保持“只能照抄候选编号”“能力只标 1–2 项”“解答题子类按产出形式判定”等现有约束；拿不准时留空，不凑标签。

### 3.5 新册按章自动整理题型

流程：

1. 导入试卷照旧，自动生成判定点、学科网知识点、技能与五维属性。
2. 每次导入分析结束后，系统统计各章已有可用判定资料的题数和来源试卷数。某章首次达到门槛（建议初值：至少 30 道题、来自至少 3 份试卷；实施时用八上数据回测后确定），或已发布题型的章累计足够多未归类题时，安排“整理本章题型”后台任务。
3. 整理任务按章调用题库打标所用模型：输入该章题干、答案、判定点和知识点，输出题型清单（名称、定义、纳入、排除、锚题）以及每道题的主题型和次题型。只发送题目资料，不发送学生信息。
4. 本地检查通过后直接发布为新标准版本，并写入每道题的整题题型和判定点副本。检查项：每个题型至少 3 道题且有锚题；本章每道可用题都有主题型；名称不重复；稳定标识符合规则。检查不通过时不发布，保留上一版，在任务结果中说明原因。
5. 发布后新导入的题在同一次联合分析请求中选题型（现有能力）。找不到合适题型的题记为“待归类”，留给下一次整理本章时处理，不进入知识点新词待审。
6. 每次整理生成一份只读摘要（新增题型、各题型题数、待归类题数），教师可以不看。

稳定性约束：

- 已发布的题型标识不改名、不重新编号；后续整理只能新增题型、给待归类题分配题型，不自动拆分或合并已有题型。拆分、合并以后作为单独操作另行设计。
- 发布标准前须等待已排队和进行中的联合分析结束。现有写入在活动标准变化时会拒绝落库（`write_question_type_labels` 校验标准未变），不能让发布打断导入。

费用：整理任务的预计请求次数，在导入时已有的费用确认中一并显示，例如“本次导入后第 2 章将整理题型，约 N 次请求”。门槛未达到时不显示、不请求。

### 3.6 按章切换训练目标

- 训练目标由“按册判断”改为“按章判断”：某章在活动标准中有题型时，该章以题型为目标；没有时，以本章学科网细项知识点为目标。已有技能目标的往届册保持技能规则，不受本节影响。
- 知识点目标的配题沿用题型模式的分层思路：同知识点，再到同小节且题面相似度至少 0.6 的相近题；推荐理由写明所在层。细则实施时与题型规则共用同一实现。
- 一章从知识点切换到题型后，考试证据通过“考试题 → 已确认题库题 → 当前主题型”自动改按题型计算。已发布的训练证据记录的是发布时的目标，需要同样按训练题对应的题库题读取当前题型，读取时换算，不改写原记录。

### 3.7 题库维护页面

- 页头：显示本册题数，以及题型、知识点的覆盖情况，不再显示技能数。
- 找题：“按技能”页签改为“按标签”，在题型、知识点、技能、五维属性之间切换，沿用该页签现有的技能、知识主题、标签切换方式。
- 题目状态与“待处理”：判定点待审核、缺题型、缺知识点三类。技能缺口与技能候选入口保留，但不计入主要待办。
- “AI 补齐”：缺口类型增加题型和知识点；仍逐题列出缺口及无法处理的原因，沿用现有确认、请求编号与不自动重试规则。

### 3.8 技能

- 判定点上的技能关联继续由导入分析在同一次请求中生成，不增加费用；在已有题型的章不参与掌握度和推荐排序。
- 以后可考虑的用途（本方案不实施）：讲评时定位同一题型中全班失分集中的步骤；跨题型的共性薄弱；题型与技能组合异常时提示可能标错题型。

### 3.9 章节考情与考频

章节考情的“主要技能”、技能 × 难度档频次、典型题单元，以及题库列表的考频，改为按主题型统计。期中、期末分列，同源卷组、出卷率和难度分档口径不变。

## 4. 对其他模块的影响与修改

本节按模块列出受影响的入口与要修改的地方。文件路径以 2026-10-08 本地 `main` 为准，实施时再逐处核对；“不变”表示该模块的数据语义与结果保持原样。

### 4.1 考试阅卷（考试、答卷、评分、复核、报告与结果）

| 环节 | 影响 | 修改 |
|---|---|---|
| 扫描、批改、复核、教师最终分锁 | 不变；评分只读判定点与本场分值，不读标签 | 无 |
| 考试配置“分析入库” | 是导入入口之一，费用确认要加上整理题型的预计请求 | `frontend/src/views/SessionConfigView.vue`、`frontend/src/components/config/ConfigGenerationPanel.vue` 显示合并后的预计请求；后端估算复用整理任务的同一估算函数 |
| 考试快照 | 配置考试时冻结当时的判定点关联（`question_bank/solution_evidence/evidence_snapshot.py`），不改 | 无；在已改用题型的章，投影层按题库题当前题型覆盖（已有）。用知识点兜底时，投影需要同样补上题库题当前的知识点关联，否则规则修改前已冻结的考试没有知识点证据 |
| 班级报告、个人报告 | 现在按册判断“题型分析”或旧显示（`backend/reporting/report.py`、`analysis_report_exporter.py`、`backend/session_analysis.py`、`backend/report_assets/personal_knowledge.*`）。一场考试可能横跨已改版章与兜底章 | 改为逐题按所在章选择题型或知识点分桶；分数、排名、教师最终分锁不变；实施时核对报告输入指纹能否反映目标类型的切换 |
| 考试错因与典型错法 | `backend/class_analysis.py` 给错因记录补技能、`question_bank/services/error_pattern_service.py` 从触发判定点读技能；这两处只用于说明 | 不变 |

跨模块说明：考试阅卷模块只被只读引用；修改集中在 `integration/` 投影与报告分桶，因为考试快照属于考试模块，题库模块内部无法给已冻结考试补关联。

### 4.2 题库（导入、分析、标签、找题与维护）

| 入口 | 修改 |

## 5. 八上旧题合并重打

- 范围：八上可用判定资料的题。每题一次请求同时返回判定点的学科网知识点关联与五维属性；不重写判定点正文、技能、题型、小问难度和作答方式，不新建判定版本。
- 保护：教师人工修改过的判定版本与教师手工标签保留，冲突转人工核对；只写当前活动标准下的关联；写入沿用修订冲突保护与失败不自动重试规则。
- 顺序：先抽样一批题，比较新旧两版标签的差异，抽样结果给用户过目后再全量执行。
- 授权：抽样与全量都调用真实模型、写真实题库，执行前报价，每次单独授权，并先备份。
- 影响：八上以题型为目标，知识点不进入八上的掌握度；但知识点关联会影响小节归属与跨章判断，须先在副本上比较章节考情、教学进度检查和推荐候选的变化。

## 6. 实施阶段、完成标准与授权点

| 阶段 | 内容 | 完成标准 | 授权点 |
|---|---|---|---|
| 1 知识点恢复可写 | 第 3.3 节规则、提示词与校验 | 合成导入中，判定点带本册知识点；八上同输入下学情与推荐结果不变；副本上比较小节归属与跨章变化 | 不调用模型、不写真实数据 |
| 2 自动整理题型与应用内发布 | 第 3.5 节、第 4.3 节 | 合成数据中一章从无题型到有题型全程无需教师操作；检查不通过不发布；失败回到发布前的标准；导入中途不发布 | 新增存储表属于数据库迁移，单独授权；用八上一章回测整理效果需调用真实模型，单独授权 |
| 3 按章切换与知识点兜底 | 第 3.6 节、第 4.4、4.5 节 | 同一册中已改版章与兜底章混合时，学情、推荐、组卷、报告都给出结果并标明目标类型；八上全部章结果与改动前一致 | 不调用模型 |
| 4 题库维护两块 | 第 3.1、3.2、3.7 节，第 4.2、4.6 节 | 页面的三类缺口数与后台统计一致；修改主题型后整题标签与判定点副本一致；页面原型先经用户确认 | 不调用模型 |
| 5 五维定义与八上重打 | 第 3.4 节、第 5 节 | 词表修订安装后新导入题使用定义；抽样对比经用户过目；全量后只读核对未改动资料逐题保持 | 抽样与全量分别报价、授权并备份 |
| 6 章节考情与考频 | 第 3.9 节 | 同一批试卷下，卷组、出卷率与难度分档口径与改动前一致，只改统计对象 | 不调用模型 |

开学前完成阶段 1 到 3。八下试卷宜在阶段 1 完成后再集中导入；阶段 2 完成后，已导入的题由整理任务直接分配题型，不需要重打。

## 7. 风险、待核实与实施时再定的细则

- **全自动的题型质量没有人工验收。** 八上题型清单经用户逐章审核并做过盲评，八下没有。建议在阶段 2 用八上一章做回测：只给整理任务该章题目，比较它的输出与已审核清单的一致程度（需单独授权模型调用）。
- **门槛与题量。** 题少时整理出的题型会偏粗；不自动拆分已有题型可以保证稳定，但粗分类会一直保留，直到另行设计拆分。
- **知识点直接关联扩大跨章判断。** 更多题可能被判为涉及其他章，从而退出章节专项推荐。实施时先测量，再决定跨章判断是只看训练目标，还是保留现规则。
- **未确认题库关联的考试题。** 这类题没有题型，也补不上知识点；当前占比尚未查证，阶段 3 前只读统计。
- **规则修改前已冻结的八下考试。** 依赖第 4.1 节的投影补关联；若题库题后来重新分析，按现有来源核对规则判断是否可用。
- **应用内标准的存放方式。** 数据库表或受控目录二选一，取决于备份、恢复和升级流程的现有约束，实施阶段 2 前确定并说明理由。
- **费用估算。** 整理任务每章请求数与八上重打总请求数尚未测算；五维定义会使每次分析的输入变长，费用略增，实施时实测后再报价。
- **其他教材册。** 七上、七下、九上没有教学安排时不处理；需要时沿用同一流程。
