## 3. 后端接口

两个接口都放在 `backend/api/routers/reports.py`，响应模型放在班级分析响应模型所在的 schema 文件中。

### 3.1 `GET /api/sessions/{session_id}/paper-review`

- 只读。场次不存在返回 404。没有参考学生时返回 `status:"no_data"`，其他字段为空。
- 响应不含学生姓名、学号或逐生分数。

```text
{
  status: "ready" | "no_data",
  session_id, title, graded_at, full_score,
  students: 参考学生数, classes: {班名: 人数}, small_sample: bool,
  total: int | null,
  dimensions: [{key, name, weight, score: int|null, detail: {...}}],   // 顺序与键名见 4.2
  items:  [{id, parent_id, type, max, stem, answer, rate, class_rates, r_rest,
            predicted_difficulty, predicted_source, quadrant, pred_flag,
            lost_students, errors:[{reason, category, count}] (前5), typical_error|null,
            distractors|null}],
  groups: [{id, parts:[...], max, rate, class_rates, r_rest, predicted_difficulty,
            quadrant, pred_flag, top_error:{part_id, reason, count}|null, flagged: bool}],
  coverage_types: {题型键: {covered_by:[...], secondary_by:[...], typical:[{role, stem}]}},
  review_lists: {fix:[{id, reason}], keep:[{id, reason}]},
  marks: {父级题号: "keep" | "fix"}
}
```

- `items` 按卷面评分项顺序排列（即 `data.questions` 的顺序）。
- `quadrant`、`pred_flag`、`typical_error`、`review_lists` 都在后端算好，前端只负责显示，规则见 4.3。

### 3.2 `PUT /api/sessions/{session_id}/paper-review/marks/{parent_question_id}`

- 请求体 `{mark: "keep" | "fix" | null}`；`null` 表示清除。返回最新的 `marks`。
- 写入 `ClassAnalysisStateStore.save(session_id, paper_review_marks=...)`，值为 `{父级题号: {mark, bank_question_id|null, updated_at}}`。先读取，修改这一项，再整体写回。
- 父级题号不在本场时返回 422。
- 不另加令牌或指纹（本机单用户，见 `AGENTS.md` 防护边界）。

### 3.3 性能

- 打开页面时计算，不做后台预计算，也不改动首页或其他页面的加载。
- 实施后测量三场考试各自的接口耗时，写进回复。超过 3 秒时先和用户讨论，不要自行加缓存。

## 4. 计算规则（必须与原型 `scores.py` 一致）

### 4.1 共同输入

- **学生：** `assemble_session_analysis` 给出的参考学生，教师最终分优先；未出分、失败的评分项不纳入。
- **评分项满分：** 取各评分项 `max_score`；全卷满分 = 纳入评分项满分之和。
- **得分率 `rate`：** 该项全体参考学生得分之和 ÷（人数 × 满分）；各班同样按班计算。
- **区分度 `r_rest`：** 本项得分与“其余题总分”的皮尔逊相关系数。
  - 其余题总分里，要把同一大题的全部小问一起去掉（用 `parent_question_id` 判断同属一题），避免兄弟小问互相抬高。
  - 人数少于 3 人或方差为 0 时为 `null`。
- **大题合并（`groups`，2 个及以上小问才合并）：**
  - 得分率：整题得分之和 ÷（人数 × 整题满分），即按分值加权。
  - 区分度：整题得分与“总分减去整题得分”的相关系数。
  - 预估难度：用题库整题难度。
  - 各班得分率：按分值加权；任一小问缺少该班数据时为 `null`。
- **四舍五入：** 维度分和总分都用 Python `round()`，与原型一致。

### 4.2 五个维度（`key` / 名称 / 权重）

1. `coverage` 典型题覆盖，20。
   - 参与对照的小节：本卷有 2 个及以上评分项、并能归到所属章节的小节。
   - 每个小节内的题型按 `group_count`（期中、期末出现套数）从高到低排序，只取套数 ≥2 的题型。
   - 本卷对某题型的得分 `credit`：作为主题型考到记 1；只作为次要题型考到记 0.5；没考记 0。
   - 题型常见难度：章节考情中该题型 `cells` 内各题题库难度的中位数，保留 1 位小数。`hard` 表示常见难度 ≥7。
   - 设本节选中的题型（credit > 0）有 k 个：
     - 理想集合：从“已选题型，或不是偏难的题型”中，按套数取前 k 个。
     - 本节比例 = min(1, Σ(选中题型套数 × credit) ÷ Σ 理想集合套数)。
   - 维度分 = 100 × Σ(本节比例 × 本节理想套数) ÷ Σ 理想套数。
   - 显示用字段：
     - `floor`：本节选中题型的最低套数。
     - `shown`：选中，或套数大于 `floor`。
     - `skipped`：没选、套数大于 `floor`、且不是偏难。
     - `missing`：所有小节的 `skipped` 按套数从高到低取前 3 个名称。
   - 没有可对照的小节时，维度分为 `null`。
   - `detail` 结构：`{sections:[{section, floor, ratio, types:[{key, name, group_count, credit, difficulty, hard, shown, skipped}]}], missing}`。
2. `time_fit` 题量与时间，15。
   - 按总分排序，取中间一半学生（下标 `n//4` 到 `n - n//4`），称为中档生。
   - 对每名中档生，从卷面最后一个评分项往前，累计连续空白评分项的满分。累计达到全卷满分 15% 的，算“疑似没做完”。
   - 空白按第 2 节的确定性规则判断。
   - 维度分 = 线性映射：疑似没做完的比例 ≤5% 得 100，≥40% 得 0。
   - `detail`：`{mid_students, unfinished, share, last_item, last_item_blank_mid}`。
3. `distribution` 分数分布，15。三项子分取平均：
   - 均分率：在 0.60–0.80 之间得 100；低于 0.60 时，从 0.40（0 分）线性升到 0.60（100 分）；高于 0.80 时，从 0.80（100 分）线性降到 0.95（0 分）。
   - 标准差：在 0.12–0.25 之间得 100；低于 0.12 时，从 0.05（0 分）线性升到 0.12（100 分）；高于 0.25 时，从 0.25（100 分）线性降到 0.40（0 分）。
   - 两端人数：100 − 200×max(0, 满分段占比 − 0.10) − 200×max(0, 低于 40% 占比 − 0.10)，结果限制在 0–100。满分段指得分率 ≥95%。
   - `detail`：`{mean, sd, ceiling_share, floor_share, bins: 10 段人数, parts:{mean, spread, extremes}}`。
4. `basic_hits` 易错暴露，35。
   - 基础题：预估难度 < 4 的评分项。
   - 考出问题：得分率在 0.40–0.85 之间，且区分度 ≥0.30。
   - 维度分 = 考出问题的评分项满分之和 ÷ 基础题满分之和 × 100；没有基础题时为 `null`。
   - `detail`：`{basic_items, hit_items, too_easy(得分率 >0.85), weak(其余得分率 ≤0.85 的基础题)}`。
5. `discrimination` 题目区分，15。
   - 按分值加权：区分度 ≥0.4 记 1；0.3–0.4 记 0.8；0.2–0.3 记 0.4；<0.2 或为空记 0。
   - `detail`：`{low: 区分度 <0.3 的评分项}`。

总分 = 非空维度按权重加权平均；为空的维度不计入，权重按剩余维度重新分配。

### 4.3 逐题判断与两张题卡

- **`quadrant`（类别）：**
  - 得分率 ≥0.7：区分度 ≥0.4 为 `good`（基础能区分），否则为 `free`（送分）。
  - 得分率 <0.7：区分度 ≥0.4 为 `high`（有难度·能区分），否则为 `suspect`（可疑）。
- **`pred_flag`（与预估比较）：**
  - 预估难度 <4 且得分率 <0.6：`harder`（比预估难）。
  - 预估难度在 4–7 之间且得分率 ≥0.85，或预估难度 ≥7 且得分率 ≥0.7：`easier`（比预估容易）。
  - 没有预估难度：`none`。其余情况：`fit`。
- **`typical_error`：** 已保存错因中人数最多的一条，人数 ≥5 且至少占本项失分学生的 30% 时才算。
- **`review_lists.fix`（可能要改的题，最多 3 道）：**
  - 先列 `suspect` 的评分项，再列 `basic_hits.weak` 的评分项，去重。
  - 原因文字：
    - `suspect` 且区分度 ≥0.3：“区分度略低（靠近误差范围）：可抽查题面或批改”。
    - `suspect` 其余情况：“难度中等却分不开强弱：查题面或抽查批改”。
    - `weak` 且得分率 <0.40：“基础题却很少人做对：查是否超纲或还没教到”。
    - `weak` 其余情况：“基础题分不开强弱”。
- **`review_lists.keep`（值得保留的题，最多 3 道）：**
  - 从 `hit_items` 中排除所有符合“可能要改”条件的项。
  - 按 `errors[0].count` 从多到少排序；没有错因时用失分人数。
  - 原因文字：“{人数}人同错：{错法}”；没有错因时为“基础题，考出了差距”。
- **`groups[].flagged`：** 任一小问符合“可能要改”条件时为真。
- **`groups[].top_error`：** 各小问 `typical_error` 中人数最多的一条。

### 4.4 维度为空与小样本

- 维度为空时页面显示“数据不足”，不计入总分；不能把缺少证据显示成低分。
- `small_sample` 为真时，页面顶部提示“人数较少，区分度等指标仅供参考”，各维度照常计算。

  4. **难度与区分度散点图：** 单独占一整行；右侧放四个区域的说明（文字同原型）；坐标轴标题分别为“得分率（越右越容易）”“区分度（越高越能分出强弱）”，两条虚线分别标 0.7 和 0.4。默认每道大题一个点，大题的点外加一圈；勾选“按小问显示”时每个小问一个点。点圆点跳到表格对应行。
  5. **逐题评价表：**
     - 列：题号、得分率（附各班刻度）、区分度、类别、预估（↑ / ↓ / 空白）、错法（“⚠ N人”）、标记。
     - 大题行：显示“Q14 · 8小问”，默认收起，点击展开小问行。大题行的数据来自 `groups`；有小问需要注意时加一个红点；“留 / 改”按钮只放在大题行。
     - 点小问行或单题行，展开题干、前 5 条错法和选项分布。
     - 筛选：全部 / 可疑 / 比预估难 / 暴露典型错误 / 要改。“全部”计数为题数；其余筛选按评分项平铺显示并计数。
     - 表头写“全部 N 题（M 个小问）”；表下写原型中的合并口径说明。
  6. **高频题型覆盖：**
     - 每个小节一张卡，标题“{小节} · 选题效率 {比例%}”，旁边注明“本卷选了 k 个题型”。
     - 只显示 `shown` 为真的题型色块：
       - 已选：实心；只作为次要题型考到：半实心，标“次要”。
       - 更高频未选：橙色框，标“更高频未选”。
       - 偏难未选：灰色虚线框，标“偏难·可不选”。
       - 每块显示套数和难度标签（<4 基础，4–7 中档，≥7 偏难），已选色块附本卷题号。
     - 题号合并到大题，按题号从小到大排列，完整小问列表放在悬停提示里。
     - 点“更高频未选”或“偏难·可不选”的色块，弹出一道参考典型题。
     - 被折叠的题型收在“另有 N 个题型低于本卷最低频选题（{floor}套），未列出”里，可以展开。
     - 不显示任何内部标识；未归入章节的小节合并成一行“另有 N 个小节未关联章节，未做对照”。
  7. **页脚：** 一行口径说明：“本页依据本场学生作答，反映这批学生做这张卷的情况，不等于题目的绝对难度”。下面是可折叠的“评分规则”，内容为第 4 节规则的通俗版，文字以原型 `app-core.js::RULES` 为准。
