# 题库待处理：交互原型

用途：保留处理去向的三种结构供比较。本目录为独立合成原型，不接入真实题目和模型请求。正式题库已采用用户选择的 B 方案，按基础分析、题型与关联匹配、题型／标准整理展示；实际规则以题库产品文档为准。

打开 `index.html`，底部切换 A / B / C，也可用左右方向键。右上角可切换完整流程示例与当前 13 题的初始状态分布。所有题面、编号、试卷名及演示结果均为合成内容；只有 12 + 1 的初始分类数量沿用此次只读核查。

| 方案 | 结构 | 适用判断 |
|---|---|---|
| A（推荐） | 处理动作 → 题目列表 → 原因与下一步 | 日常处理时，先区分可补齐、待整理、核对原题 |
| B | 基础分析 → 已有题型匹配 → 同章整理，另列标准与题源问题 | 说明题型归类在基础分析之后，解释流程依赖 |
| C | 逐题总表，按去向筛选，只勾选可补齐题 | 集中核对与批量处理 |

## 原型表达的规则

- 缺少基础分析或可核验的匹配结论：可补分析与匹配。
- 明确无匹配：保留待题型／标准整理，并写明题型或知识词表的具体缺口。在题目、候选范围和标准未变时，不反复补打。
- 题源条件不足：先由教师补足题源，再重新分析。不能把所有未归类题都放入人工逐题归类复核。
- 题型在判定点、知识点等基础标签分析之后处理。已有题型可匹配；无合适题型时，才进入按章整理。
- 八下按章整理的示例使用现有实现的门槛：已有题型章节累计 30 道待归类题，且满足可用资料与试卷来源条件。八上尚未接入自动整理，原型明确显示“待安排整理”，不显示已进入自动任务。
- 知识标准整理入口属于拟议交互；此原型不代表正式系统已实现该处理状态或操作。

## 可操作内容

题目切换、类别切换、流程节点、总表筛选与勾选、补齐清单、预设结果分流、章节整理条件、标准缺口说明、原题补充条件、场景切换与重置。页面刷新会丢弃所有演示状态。

## 复用判断与隔离范围

| 现有候选 | 原型采用方式与限制 |
|---|---|
| `QuestionBankView.vue` | 沿用题库栏目和应用导航语境；不增加正式路由，避免把未确认结构接入实际操作 |
| `QuestionBankTodo.vue` | 保留“题目原因与下一步”概念；另做三种可比较结构，不覆盖现有组件 |
| `QuestionRepairDialog.vue` | 沿用先看补齐范围的操作；全部改为内存中的合成演示，不连接付费接口 |
| 现有主题与样式变量 | 延续米白、深青导航、青色操作与中文系统字体；独立样式不影响正在运行的正式前端 |

因此使用独立静态文件，不建立生产模块、服务或接口，不构建共享 `frontend/dist`。

预览命令（从项目根目录运行）：

```powershell
.\runtime\python\python.exe -m http.server 8038 --bind 127.0.0.1 --directory docs/requests/question-bank-todo-prototype-20261015
```

然后打开 `http://127.0.0.1:8038/index.html`。也可直接在浏览器打开本目录的 `index.html`。
