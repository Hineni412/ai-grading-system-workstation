# 全系统重复检验、查询与重算删减计划

2026-10-10。用途：按用户要求全面排查数据库相关的重复工作，并提出删除计划。本文件描述当前源码中已核实的行为与尚未实施的建议。本轮不修改业务代码，不开展刷新耗时或提速实验。

## 结论与目标

重复工作确实跨越多个模块。问题不只在 AI 补齐计数。普通查看仍可能加载生成用的全部题面、重新派生已有判定点、复核旧来源、重复装配同场数据，或在缓存命中后再次解码和编码。

删减目标是：保存结果直接读取，同一次操作共用同一份读取结果，相关输入变化后才重算所需范围。已核实的重复工作全部进入实施清单。不能把搜索命中数量当成运行次数，也不能把不同提交边界上的检查当成同一次重复。

本次没有测量整体慢主要由哪一项造成，也不承诺具体秒数。掌握度拟合、选题和排版本身需要的计算不属于本轮删除对象。

## 普通读取采用一套规则

| 操作 | 计划采用的行为 |
|---|---|
| 打开已保存报告、错因、草稿、训练结果和判定资料 | 按考试、学生、题目或训练编号读取保存内容。不先核对整题摘要、分析方法版本或全部题库。 |
| 同一次查看需要成绩、明细、教师确认和题库关联 | 在现有请求读取范围中各读一次，后续统计、显示和提醒共用。 |
| 浏览一页题目、一名学生或一个章节 | 先确定本次范围，再读取资料。不先装配全库再筛选。全班相对指标需要全班基准时，单独准备一次并共用。 |
| 打开已有临时汇总 | 直接复用。只有相关成绩、证据、标准或题目变化，才刷新受影响结果。任务进度等无关写入不触发全模块重算。 |
| 生成新结果、采用判定资料或实际提交 | 在实际边界检查对象归属、教师确认、修订和授权。后续内部函数消费已检查的结果。 |
| 启动、升级和恢复 | 集中执行结构就绪或完整性检查。普通读取和每个对象构造不再重复初始化、回填或检查迁移历史。 |

“直接读取”仍包含一次必要的格式解析。损坏数据明确显示读取原因。格式解析不应在每个内部层重复执行，也不应因为资料不是最新而丢弃已保存内容。

全量索引覆盖 361 份业务及根目录 Python 源码、67 份维护 Python 源码、324 份前端业务源码。索引含 257 个路由声明、1391 个 SQL 调用位置、897 个前端读取或生命周期触发候选。源码解析失败数为 0。

数据库结构通过原位置只读连接核对。阅卷库有 17 张表，题库库有 90 张表，共 107 张表，包含维护与旧版兼容表。23 张表没有匹配到字面 SQL 引用，另行核对兼容名单、动态检查和维护归属。

上述数量是静态覆盖单位，不是页面执行次数。全量索引不会自动证明两条查询在同一路径运行。人工复核区分了普通读取、实际生成、提交、恢复和互斥分支。

没有运行所有真实页面或并发写入流程。实施阶段须用现有合成测试验证删除后的结果、范围和写入边界。未复现的候选不得直接删除。

## 实施顺序与完成标准

| 顺序 | 删除范围 | 完成标准 |
|---|---|---|
| 1 修正已存资料误报 | 普通读取后的第二次来源或版本拦截；查看时准备生成用资料；已存判定点的重复派生 | 已存结果仍可打开和统计。AI 补齐按实际缺口计数。拒绝、损坏与未保存三种情况保持区分。 |
| 2 共用请求内读取 | 同场结果、教师确认、题库关联、原始标签、原卷与规范化明细的重复查询 | 一次操作只准备一次相同输入。成绩、排名、错因归属、题目顺序和显示内容保持。 |
| 3 收口初始化和回填 | 服务构造与普通查询里的重复结构门槛、全库身份初始化、兼容回填 | 启动集中准备一次。普通读取不初始化或修改数据库。缺库、旧库和恢复失败仍明确报错。 |
| 4 收窄资料和重算范围 | 先全库后筛选、逐学生重查整场、单页更改重算整个批次 | 只处理本次需要或实际受影响的范围。全班基准、同卷题序和小问判定规则仍完整。 |
| 5 删除缓存恢复与显示往返 | 同一缓存多次解码、再编码、重复表示和重复规范化；无关整库提交造成的重建 | 命中后直接消费已恢复结果。坏缓存可回退。教师改分与相关输入变化后能更新；任务进度不刷新业务汇总。 |
| 6 合并提交内重复准备 | 同事务重复标签查询、难度公式重复计算、反馈发布重复刷新、批量导出重复读取 | 保留实际提交时的一次检查与计算。幂等、教师锁、回执与原子保存保持。 |
| 7 验证并删除旧入口 | 所有调用迁移到已有共享入口后，删除仅供重复路径使用的帮助函数和旧测试准备 | 每个删除项有结果与范围验证。文档只描述当前实现。全部候选逐项确认或排除，不保留无主重复路径。 |

每个实施单元先完成该单元的验证，再继续下一单元。优先删无效准备和重复调用，不先增加通用框架、策略层或另一套缓存服务。

## 现有复用入口与模块边界

| 现有能力 | 本计划怎样复用 |
|---|---|
| `RequestReadContext` 与仓储的外部只读连接 | 一次请求共用两库读取范围。跨数据库捕获前后的提交检测仍保留。 |
| `QuestionBankReadService` 批量资料、技能索引与读取范围 | 提供当前页或指定题号的资料，复用已读档案、关联、标签和修订，不另写一套读取服务。 |
| `TrainingCriterionModule` 和解题证据读取 | 统一已保存资料的可用判定。生成或采用时才明确核对新来源。 |
| `PersonalReportStore`、班级状态与既有报告上下文 | 一次加载保存正文和索引，同场及批次共用。更新提示与能否读取分开。 |
| `DiagnosisProfileService`、`ResultCache`、`PersistentEntryStore` | 删除调用链中的重复恢复与重复签名准备。公开返回值的独立性仍按原契约保留。 |
| 已有写入修订、任务完成事件和缓存清理入口 | 先覆盖各业务写入影响范围，再移除无差别整库失效。恢复或替换数据库时统一重置临时结果。 |

跨模块重复读取不能只在一个页面内部修正。成绩与教师锁仍归阅卷模块，题目与训练资料仍归题库训练模块。共享输入通过现有只读上下文和显式参数传递，不让模块直接写另一个模块的数据库。

班主任工作台不在本项目范围内。本计划不建立其接口或自动同步。

## 必须保留的实际边界

教师最终分锁继续优先。成绩、排名、原考试分值与训练达成点数保持各自语义。

提交时保留对象归属、预期修订、幂等令牌、教师保护、费用授权和原子保存。异步模型或长计算之前与写入时，输入可能发生变化，写入时的重读不能按“相同 SQL”直接删除。

备份、升级和恢复保留一次完整性、外键及结构检查。重复的同文件检查可以合并，实际保护不能取消。文件权限、加密与受控引用沿用现有规则。

已保存业务结果与可丢弃的临时汇总分开。临时汇总失效不应使旧报告、旧作答或已确认判定资料消失。

本计划删除重复代码和重复工作，不清理真实记录，不迁移或重写真实数据库。
