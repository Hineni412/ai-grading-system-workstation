# 页面首次刷新性能调查与优化实测

用途：记录 2026-10-03 的调查基线、按用户确认顺序完成的内部优化、实测结果与剩余问题。本次已修改业务读取代码和现有测试；没有修改或复制真实数据，没有调用真实模型。正式应用没有重启，下一次正常启动才会加载改动。

用户关注题库、组卷工作台的班级组卷、知识与训练、考试批改页。主要触发是首次刷新；部分情况是页面结构出现后，数据仍缓慢加载。

## 首轮实现与结果

本节记录首次优化的测量。后续针对知识概览、知识图谱和训练诊断的 2 秒目标，见 [专项实测与剩余方案](knowledge-training-two-second-performance-20261003.md)。

真实范围仍为八年级上册、2 个班、91 名学生、3 场考试。以下是组件读取耗时，不是完整页面时间。首次各 1 次；连续为后续 5 次的中位数。单位为秒。操作系统文件缓存没有清空，单次首次样本会受机器负载影响。

| 读取组件 | 原首次 | 当前首次 | 原连续 | 当前连续 | 结果核对 |

班级组卷采用一次请求内的来源准备和记录索引，取消学生循环里的重复全班计算。受控恢复对照为原函数 12.354 秒、当前函数 2.370 秒、恢复原函数 10.894 秒，三次完整输出一致。指纹仍覆盖整场考试，学生证据哈希、旧版本兼容及教师最终分锁不变。

题目列表仅为当前页加载资料，当前册仅加载其归属题目。真实库存基本都属于当前册，按册缩小范围本身不能明显降低全库首次构造。原、当前技能索引和试卷目录完整输出均一致；全库统计保留原资料校验，没有只凭数据库记录推定有效证据。

完整技能投影增加一份本地缓存，位于 `user_data/cache/question_bank_skills.cache`，上限 16 MiB。复用原投影、文件读取工具和原子替换；不新建数据库表或另存评分规则。题目修订号未覆盖全部资料版本，不能替代全库校验。数据库内容版本复用原学情快照算法，移到已有 `integration/data_generation.py` 供两处只读调用。

真实只读缓存实验中，约 2.95 MiB 的缓存首次准备 8.459 秒，恢复 0.581 秒；模拟物理文件状态变化后，额外核对 SQLite 内容版本，恢复 1.051 秒。三次输出一致。**真实缓存文件读写仅在内存中模拟，没有写入真实缓存。** 真正的缓存文件、新进程恢复与 WAL 归档后恢复在隔离合成环境测试。缺少有效缓存或业务内容改变后仍需重新准备全库；不能把恢复耗时称为无缓存首次耗时。

训练公开响应合并字段处理与公共清理，复用同一响应内的键和文本检查。相同真实输入的转换为原函数 2.615 秒、当前 1.373 秒、恢复原函数 3.010 秒，完整输出一致，输入未被修改。未减少选择、填空作答结果或解答题逐点结果，也未缩减响应字段。响应体积仍是后续限制。

本地学情快照按文件标识复用已解包内容，签名与条目仍逐次校验。分类名称的纯文本规范化使用有容量上限的复用。批改两个未完成计数在同一次摘要里共用一次查询，下一次摘要重新读取。后两项属于局部节省，不能解释此前未复现的严重慢加载。

## 调查基线结论

1. 班级组卷、知识概览与知识图谱共用的错因读取存在大量重复计算。真实只读输入的临时实验把组卷考试证据读取从 10.84 秒降到 2.02 秒，完整输出一致。优先正式消除该重复工作。
2. 题库冷读取会构造全题库资料快照。当前册技能索引首次约 9.11 秒，连续读取中位数仅 0.006 秒。主要优化对象是加载范围和快照构造依赖；图片摘要重复很少。
3. 训练诊断有第二个瓶颈：91 名学生的公开响应约 40.1 MiB。即使核心计算已命中缓存，整理、校验和序列化仍需数秒。
4. 本次未复现考试批改页的数秒至十余秒慢加载，也未复现整个页面长期空白。批改页只能报告已测组件与合成页面，不能据此断定用户的慢加载已经定位。

## 测量口径与边界

- 复用 `tools/performance/dataset.py`、`runner.py`、`scenarios.py`、`backend/performance/metrics.py`，使用当前工作区源码。工作区已有其他任务的改动，本次保留原状。
- 真实数据只在原位置读取。复用 `tools/experiment_training_fit.py` 的只读连接，使用 `mode=ro` 和 `query_only=ON`，禁止向真实数据文件写入。学情快照持久化关闭；现有快照仍按原逻辑读取与校验。
- 真实范围为当前八年级上册、2 个班、91 名学生、3 场考试。阅卷库有 4,547 条题项结果；题库有 1,336 道题、67 份试卷和 12,861 条标签记录。报告不保存身份、题目正文、答卷或分数。
- 合成环境复用现有数据生成器：91 名学生、3 场考试、5,460 条题项结果、1,336 道题、14 份试卷。补充合成考试的当前学期日期和九年级上册归属。图片、当前资料和错因状态不等同于真实库存，因此绝对耗时不能与真实数据直接相减。
- 每个接口先测独立进程首次查询，再测 5 次连续查询。在合成库提交一次更新后，再测首次查询及 5 次连续查询。没有手动清空缓存。
- 首次指进程内首次执行该范围的查询。测量关闭后台预热，没有清空操作系统文件缓存，也没有计入服务启动时间。因此这不是电脑重启后的磁盘冷启动测试。
- 真实测量是业务读取组件；部分路径另计正式公开字段转换、响应模型校验和 JSON 序列化。没有执行真实 HTTP 请求的阅卷库临时副本流程，没有计入 HTTP、线程调度、网络传输或浏览器渲染。不能把真实表中的数字称为完整接口或页面耗时。
- 合成接口走真实 FastAPI 路由。浏览器走当前源码的独立生产构建、独立动态端口和合成数据，没有重建共享 `frontend/dist`，没有启动或重启正式服务。
- 浏览器“结构出现”是主区域标题可见；“数据接收完成”是本轮业务请求及 JSON 读取完成的时间。它不保证所有图表渲染和所有操作已完成。排除持续任务轮询。
- 基准请求按顺序执行。分析器另行运行，避免分析开销污染基准。分析器中的函数累计时间存在嵌套和线程重叠，不相加，也不直接当成优化收益。

## 内部耗时与受控实验

### 1. 错因来源校验在学生循环内重复执行

代码位置：`backend/class_analysis.py` 的 `student_error_map`（约 1201 行）和 `session_error_records`（约 1267 行）；调用方为 `integration/diagnosis_profile_service.py` 的 `_error_cause_index`（约 1218 行）。

当前逻辑对每名学生重新遍历同一场考试的全部来源，再重复生成来源指纹、判断兼容输入并整理按步骤拆分前的来源。来源包含整场证据，因此这里不只是多一次字典查找。

真实连续组卷读取的分析记录：总计约 13.34 秒，错因索引约 12.74 秒，占该次分析计时约 95.5%。3 场考试合计调用 `student_error_map` 256 次、来源指纹 29,395 次、来源匹配 13,641 次、兼容来源整理 5,946 次。256 是学生在各考试中的参与记录数，不是不同学生数。

同一共享路径也出现在知识概览首次查询：该次分析总计约 20.05 秒，错因索引约 11.84 秒。两份分析记录支持它是知识训练冷查询的主要成本之一；不能把组卷的改善比例直接套用到知识概览。

受控实验只在独立只读进程临时替换三个纯计算函数，让同一次请求内的同一来源对象复用结果。每次请求结束恢复原函数，不形成跨请求缓存。

| 条件 | 实测耗时 | 来源指纹实际计算次数 | 兼容来源实际整理次数 | 来源匹配实际计算次数 |
|---|---:|---:|---:|---:|
| 原逻辑 | 10.840 秒 | 29,395 | 5,946 | 13,641 |
| 请求内临时复用 | 2.015 秒 | 206 | 53 | 106 |
| 恢复原逻辑 | 10.154 秒 | 29,395 | 5,946 | 13,641 |

三次完整输出在内存中比较，结果一致。相对第一组基线，此次实验耗时减少 81.4%，约省 8.83 秒；相对恢复对照约省 8.14 秒。这是一组当前输入的验证，不是正式实现的性能承诺，也不能替代兼容版本、证据更正和教师最终分锁的回归测试。

正式实现应把每个来源的准备工作移出学生循环。每名学生仍按原规则计算自己的证据哈希。来源指纹仍使用整场考试数据，不能先按班级裁剪。可再按学生、题目和证据哈希建立请求内查找表，减少对已保存记录的反复扫描。

### 2. 题库当前册和目录依赖全题库资料快照

代码位置：`question_bank/services/question_read_service.py` 的 `_skill_snapshot`（约 1147 行）、`list_papers`（约 1234 行）；`question_bank/solution_evidence/part_assessments.py` 的 `load_profiles`；训练输入读取位于 `question_bank/training_criteria/adapters.py`。

当前册技能索引仍先准备全题库快照，再输出当前册结果。试卷目录也依赖同一快照，计算技能未关联题数。真实首次查询记录 3,656 次文件打开事件和 68 次目录扫描；连续命中缓存后没有相同规模的文件读取。分析记录显示约 1,334 道活动题进入富文本与当前资料校验路径。

进一步的图片计数实验记录：冷查询 7.632 秒；构造 2,320 个图片输入，其中 2,318 个不同摘要，只有 2 次重复摘要构造；累计处理图片字节约 94.5 MiB。图片构造的单次计时累计约 0.717 秒。线程内累计时间不等于请求总耗时占比，但这些计数足以排除“同一张图片反复算哈希是主要瓶颈”的假设。

因此，不能把扩大图片摘要缓存作为主要方案。应先核对当前册、当前页、目录统计各自需要哪些题目资料，减少不参与该结果的完整内容加载。跨册关联、相似题折叠、当前资料有效性和目录未关联题数必须保持一致。若某项统计确实需要全部当前资料，再考虑复用已有缓存或增加逐题可失效的本地索引。

现有文件字节、解析结果、题库读取结果缓存和快照并发合并已经存在。方案应复用这些能力，避免再造一套全局缓存。内容哈希仍用原字节算法校验，处理后图片的摘要不能代替原图摘要。

### 3. 训练诊断命中核心缓存后，仍重复整理大响应

代码位置：`backend/api/routers/training.py` 的 `_public_training_mapping`（约 1774 行）；它先递归处理训练公开字段，再调用 `backend/public_data.py` 的公开数据清理。

真实诊断范围是 91 名学生，正式公开结构序列化为 42,060,847 字节，约 40.1 MiB。连续 5 次读取：核心计算中位数 0.224 秒；公开字段转换与模型校验中位数 3.906 秒；序列化中位数 0.977 秒；整体中位数 5.321 秒。各阶段中位数不能相加后代替整体中位数。

合成连续请求的另一次分析中，公开字段转换约 3.61 秒，诊断路由约 3.95 秒。两个递归过程各遍历约 711,360 次。这个数字是容器及字段值的访问次数，不是证据条数或题目数。

优先在训练模块内合并重复遍历，并检查是否能按现有源版本复用已经完成清理的公开结果。保留私有字段、路径与敏感内容清理，以及题面来源分数移除规则。不能直接删证据、跳过公开清理或改变评分口径来缩短耗时。

把首屏摘要与学生证据详情分开获取，可能进一步减少传输和浏览器解析；但这是接口与页面契约调整，尚未论证和实现。它应作为第二阶段方案确认，先完成保持当前响应语义的内部优化。

### 4. 次要成本与尚未定位的批改页

- 知识概览首次分析中，读取本地学情快照 2 次，累计约 2.07 秒；其中源版本检查包含整库内容版本计算，累计约 1.05 秒。两项存在嵌套，不能相加。先复用同一只读事务内的校验和解包结果，再评估增量版本机制；不能弱化恢复后源版本校验。
- 合成题库分类目录连续约 0.256 秒。分析中仍合并和整理全部分类词条，名称规范化约 19,769 次。它低于前述数秒瓶颈，列为后续优化。
- 已捕获的训练概览 SELECT 从首次约 60 条降到连续 2 条；图谱学期查询从 61 条降到 2 条。计数只覆盖现有记录器接入的连接，不代表所有模块 SQL。当前最强证据是重复来源计算、全题库资料构造与响应整理，尚无证据支持先大规模增加数据库索引。
- 真实 3 场考试的上传清单各约 956 字节、2 个文件。清单读取与公开字段整理首次约 1–11 毫秒，连续约 0.6–0.8 毫秒；运行账本读取约 2–7 毫秒。重复执行两次未完成结果读取，连续中位数约 40–77 毫秒。`backend/api/dependencies.py` 的两个计数回调确实各读取一次相同结果，但当前收益不足以列为主要优化。
- 真实批改组件测量没有执行替换恢复、批次恢复、任务管理器查询或完整 `get_workspace`。该入口可能自动完成恢复写入，不能作为纯只读实验直接调用。本次保留其恢复行为，使用现有清单和读取组件测量；合成批改页也没有真实的大批上传与恢复状态。

## 调查时确定的优化顺序与验收依据

优先级依据调查范围的耗时和可验证收益。下表保留调查时的验收目标；本次已完成请求内证据准备、题库范围读取与本地投影缓存、训练公开转换、学情文件解包复用和两个局部复用。实际收益以上方复测为准，不把目标当作已经达到的结果。

| 顺序 | 优化内容与证据 | 修改范围 / 复用候选 | 验收方法 |
|---|---|---|---|

### 缓存取舍

- 当前已经有题库读取缓存、文件字节及解析缓存、学情内存缓存、本地学情快照和并发合并。连续知识图谱约 36 毫秒、概览约 71 毫秒，说明不能把问题概括为“没有缓存”。
- 第 1 项请求内准备属于消除重复算法工作，不需要新增跨请求本地缓存，也没有跨请求失效问题。
- 第 2 项若仍必须核对全库存，再考虑逐题资料索引或持久化复用。第 3 项若公开转换仍重，再考虑有容量上限的公开结果缓存。先用小实验确认缓存实际命中的阶段。
- 新增或复用缓存必须沿用原数据版本、知识标准、资料版本、范围和语义版本。更新、删除、恢复、文件替换、错误缓存及并发读取均需验证。不以只等固定过期时间代替源版本失效，也不为加速跳过内容哈希、评分或证据规则。
- 不通过删减评分、选择 / 填空作答结果、解答题逐点结果、训练证据或保存 / 恢复记录来减少工作量。不改变教师最终分锁、幂等令牌和恢复优先级。
