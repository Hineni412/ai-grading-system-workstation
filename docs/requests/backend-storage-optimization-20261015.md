# 后端读取与存储优化验证

用途：记录本次实现、同输入测量及未完成目标。日期：2026-10-15。此前只读调查见 [调查报告](backend-storage-readonly-investigation-20261015.md)。本文不代替存储政策。

## 本次结论与边界

此前规则确实没有覆盖全部旧实现。普通读取、保存冲突和免费操作仍存在重复内容指纹、整份请求摘要、去重索引重新核对及重复素材扫描。本次修改这些实际执行路径；去重、已付费结果复用与跨数据库交接仍保留必要标识。

当前源码通过现有后端 114 项、前端 15 项测试，以及前端类型检查和独立目录构建。真实数据只读测量通过；本轮没有再次整理、删除或迁移真实数据，没有调用模型。1 秒目标尚未达到，不能把磁盘缓存命中当成无结果缓存的首次读取。

同项目另有活动任务。按项目共享服务规则，本轮没有重建共用 `frontend/dist` 或重启正式服务；新前端仅构建到本任务的隔离目录。现有正式服务健康检查正常，这不代表本轮源码已经在正式服务生效。未提交混有其他任务修改的工作区。

## 真实读取测量

测量使用原位置的 SQLite 数据库，强制只读并禁止真实文件写入及联网。每个样本先确认域版本与每题版本可用；缺少版本支持时直接终止，避免误测回退路径。修改前代码从本任务保存的源码副本加载，不覆盖工作区。最终对照每项、每种缓存状态各测一对，随后各测 5 次内存命中，共 20 个首次样本及 100 次随后读取。

“无结果缓存”绕过被测结果磁盘缓存；操作系统文件缓存与已有去重素材摘要仍保留。“新进程”保留实际已有磁盘缓存，缺少条目时仍完整计算。计时是后端函数，不含进程启动、预先导入、HTTP 和页面渲染；函数内部发生的延迟导入计入。没有把预热后的读取写成首次计算。机器还有其他工作，单次样本不能证明固定延迟上限。

| 范围 | 无结果缓存：修改前 → 后 | 新进程：修改前 → 后 | 新进程组内存命中：修改前 → 后 |
|---|---:|---:|---:|
| 八上技能索引 | 5.170 → 2.116 s | 1.464 → 0.761 s | 27.4 → 27.9 ms |
| 八上章节考情 | 2.748 → 2.242 s | 0.112 → 0.073 s | 52.7 → 48.5 ms |
| 单场试卷评价 | 7.990 → 6.498 s | 4.482 → 3.871 s | 4.9 → 3.8 ms |
| 一份来源有效的候选请求 | 13.537 → 7.758 s | 0.671 → 0.501 s | 95.3 → 55.9 ms |
| 无筛选全库候选（实验范围） | 34.964 → 18.233 s | 33.121 → 21.499 s | 222.2 → 302.9 ms |

表中首次耗时为本轮单次值；内存命中为随后 5 次的中位数。试卷评价的新进程只命中两份基础缓存，完整评价仍重新计算；全库候选两侧均没有匹配的结果缓存。技能、章节及来源有效的候选请求成功复用已有磁盘条目。

技能、章节、试卷评价的完整输出摘要前后一致。全库候选仍为 1,303 题，没有增加或删除题目，关系一致；9 题的 `difficulty_features` 字段改为读取保存的活动特征，因此不能声称候选完整输出前后完全相同。旧候选磁盘缓存读取时也补入相同活动特征，修改后的重算与缓存命中结果一致。该差异来自删除读取时内容哈希筛除，不是删除或改写真实难度数据。

此前受控环境中，全库候选测得 26.166 → 10.263 秒；最终轮机器负载和耗时更高。两个阶段都表明尚未达到 1 秒；不挑选较快样本作为最终保证。全库候选的最终内存样本也有变慢，另做同进程交错验证，结果见下。

此前“维护前/后”测量没有确认版本号监测可用。已定位到沙箱中的真实路径解析失败会关闭版本监测并走额外文件扫描。原表只能作为排查线索，不能归因为 VACUUM 或硬链接造成性能回退，也不能据此保证维护后的缓存不退化。本轮重新测量修正了权限和版本检查条件。

## 同进程缓存对照

在同一进程内先准备修改前后两份完整候选，再交错读取 20 对，奇偶轮交换顺序。每次结果均与各自首次结果相同。修改前内存命中中位数为 217.5 ms，修改后为 222.9 ms，差约 5.4 ms；两侧 CPU 时间中位数均为 218.8 ms。样本范围分别为 201.2–276.7 ms 与 200.2–329.7 ms。

本轮没有证据表明缓存增加了明显计算开销，但这不是严格的全应用性能不退化证明。不能用较快单点掩盖最终轮的波动。此对照只覆盖全库候选的内存命中。

## 尚未完成的性能目标

没有结果缓存的五条路径都没有降到 1 秒内，也没有全部降到原来的 10%。剩余开销包括题目素材读取、富文本处理、候选装配、知识关联和完整试卷评价计算。进一步压到 1 秒需要在现有写入环节保存可直接读取的必要投影，并按题版本更新；这项写入时准备方案尚未实施，不能冒充本轮成果。需同时核对新增存储大小、写入耗时、同题结果及首次缺失补齐，不能仅增加一次后台预热。
