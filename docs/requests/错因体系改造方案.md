# 错因体系改造方案（方向已确认，分阶段实施）

用途：整理“错因”从实际批改中产生、聚类、回挂题目、进入学生学情与报告的改造方案。
状态：2026-09-23 用户已确认第 8 节各项决定。P0–P4 已实现（见第 10 节实施记录）。文中“现状”是 2026-09-23 对本机代码与数据的只读核对结果。

## 1. 现状

系统里现在有四套互不相通的“错因”，词表都不收敛：

| 来源 | 位置 | 词表 | 实际情况 |
|---|---|---|---|
| 批改时的错误类别 | `session_details.error_category`，由批改提示词要求输出 | 12 类固定（概念理解错误、计算错误、审题错误……其他） | 第4周 2112 条小题记录：空 1509、其他 326、需复核 144、未作答 132，真正分到类的只有 1 条；`error_summary` 里另有 434 条英文内部码（`blank_or_no_valid_work` 等） |
| 题库错因标签 | `question_tags` 中 `tag_type='error_type'` | 11 类受控 + 自由文本 | 1448 题共 3419 条，全部是入库时 AI 预测；1252 种不同写法，只有 63% 落在 11 类里，其余是“把9的算术平方根写成±3”这类具体描述 |
| 考试侧“整理错因” | 班级分析页手动任务，结果存 `reports/.class_analysis/{场次}.json` | 性质 5 种（数学错误/过程缺项/作答状态/前问延续/待核对）+ 每题自由命名 | 只有第2周做过（旧版 v1，15 题 45 个不同名称，每题各起各的名，跨题不能合并）；结果只在考试侧，不回挂题库和学生 |
| 个人报告 AI 叙述 | 报告缓存 | 自由标题 | 不带错因类型 |

下游依赖：学生薄弱点的 `error_types` 取自批改错误类别，推荐打分再拿它去匹配题库错因标签（`question_bank/recommendation/scoring.py`）。由于批改错误类别基本为空，这条链路现在实际不起作用。

结论与用户判断一致：题目入库时预测的错因，不等于学生实际犯的错；错因应当以实际批改证据为准，先聚类，再回挂。

## 2. 目标

1. 每名学生每道失分题，能落到“哪一类错”和“本题哪种具体错法”，有原始证据可查。
2. 同一道题跨考试积累“典型错法”，下一次考试能直接复用，名称收敛。
3. 结果进入个人报告（重点跟进卡片带错误类型、跨考试识别“同类错误反复出现”）、班级讲评、学生薄弱点和训练推荐。
4. 不改变分数、教师最终分锁和掌握度数值。

## 3. 核心设计：两层错因

**第一层：错因大类（全系统固定，约 7 类，给家长和统计用）**

已确认采用以下 7 类：

| 大类 | 含义 | 对应现有考试侧“性质” |
|---|---|---|
| 概念理解 | 概念、定义、公式定理本身理解或记忆有误 | 数学错误 |
| 计算与化简 | 运算、符号、化简、结果没化到最简 | 数学错误 |
| 审题与条件 | 读错题意、漏用条件、读图有误 | 数学错误 |
| 方法与思路 | 选错方法、缺辅助线、漏分类讨论、不会建模 | 数学错误 |
| 过程与依据 | 关键步骤或理由没写、推理断裂、未完成求解 | 过程缺项 |
| 书写与规范 | 答句、单位、格式、书写辨认 | 过程缺项 |
| 未作答 | 空白、全部作废、仅无关内容 | 作答状态 |

“前问延续”和“待核对”保留为标记，不单独成类：前问延续只算在源头那一问，不重复计错；待核对不进入家长报告和统计。
现有题库 11 类和批改 12 类各给一张换算表（例如“运算化简错误→计算与化简”“公式/定理误用→概念理解”“辅助线思路缺失→方法与思路”），旧数据按表读取，属于兼容输入。

**第二层：本题典型错法（挂在题库规范题上，逐题积累）**

例如“除以根式时，根号部分没有取倒数”“64 的平方根只写 8”。每条记录：所属大类、名称与说明、触发方式（某个选项／某个错误答案／某个判定点）、关联技能、状态（候选／已确认／已合并）、在哪些考试出现过多少人。

## 4. 按题型产生错因

| 题型 | 考前 | 考后 |
|---|---|---|
| 选择题 | 入库或配置考试时，对每个错误选项做一次“选这个说明什么”分析，存为该题典型错法（触发＝选项） | 按学生所选选项直接对应，不再调用模型；未分析的选项记“原因未明” |
| 填空题 | 不预测 | 把同一题的错误答案按现有 `answer_normalizer` 规范化后分组；已在该题典型错法库里的答案直接对应；新出现的答案组交给整理错因任务命名，命名后存入库（触发＝错误答案），下次自动复用 |
| 解答题 | 不预测 | 用批改已有的逐步判定（每一步的达成情况和错误说明）作为证据，交给整理错因任务；输出要带大类、对应判定点，并优先复用该题已有的典型错法名称 |

整理错因任务在现有 v2（按题、按相同证据合并、校验证据映射）基础上升级为 v3，增加三点：
- 必须从固定大类中选一类；
- 解答题尽量标出对应的判定点编号，便于和技能证据对上；
- 输入里附上该题已有典型错法清单，要求同义时复用原名称，确实是新错法才新建（新建的记为候选）。

## 5. 结果存放与回挂

- **考试侧**：新增“学生错因记录”：场次、学生、题号、大类、典型错法引用、判定点、来源（选项对应／答案对应／整理任务／教师调整）、版本。成绩或作答证据变化时只重算受影响的题。P1 实现时为避免新增迁移触发既有库的受保护维护流程，记录暂存于各场次 `.class_analysis` 状态文件的 `error_records` 字段（含输入指纹，证据变化即失效重建）；P4 如需跨库查询再迁入正式表。
- **题库侧**（question_bank.db）：新增“题目典型错法”表。考试结果通过现有考试与规范题的关联，以快照加操作令牌写入，重复提交不重复计数；两个数据库之间没有原子事务，按回执对账。
- **学生学情**：学生薄弱点的错误信息改为取自“学生错因记录”的大类与典型错法；掌握度数值不变。
- **推荐**：推荐打分从匹配“题库预测错因”改为匹配“学生实际错因大类或典型错法”。
- **报告**：个人报告重点跟进卡片显示错误类型；识别“以前同一类错误也出现过”（按大类或典型错法跨考试比对，比现在按知识点更准确）；班级讲评按题展示各类人数。
- **旧的题库错因标签**：11 类的值换算成大类；自由文本转为“候选典型错法（仅预测）”，不作为学生证据。批改提示词里的 `error_category` 在新链路稳定后可以去掉，节省输出量。

## 6. 教师参与（尽量少）

- 班级分析页的错因列表中，教师可以改大类、改名、合并两条典型错法；**必须经教师确认后才写入题库**并在以后的考试中复用（已确认）。
- 未确认的候选只在本场考试的班级页和报告中使用。
- 不要求教师逐个学生确认错因。

## 7. 分阶段实施

| 阶段 | 内容 | 费用 |
|---|---|---|
| P0 | 教师确认分数时不再用“人工复核已确认”覆盖原扣分理由（见第 9 节）。优先实施 | 无 |
| P1 | 固定 7 类大类与两张换算表（首次在此阶段使用，不单独提前建）；整理错因 v3；学生错因记录；生成个人报告时先整理错因再生成报告；个人报告和班级页展示错误类型 | 每场约为失分题数次请求（第4周 24 个计分小题，最多约 24 次），已有且输入未变的题不重复请求。✅ 已实现 |
| P2 | 选择题选项分析与自动对应，范围只做八年级上册（`bnu24-math-g8-upper`）考试用到的选择题 | 一次性：每道选择题一次请求，可走批量通道；之后每次考试不再花钱 |
| P3 | 填空题错误答案库自动复用 | 无额外费用（用 P1 结果积累） |
| P4 | 写入题库典型错法、学生薄弱点与推荐改用新错因、旧标签换算 | 无模型费用；涉及数据库结构升级，按迁移流程执行并先备份 |

## 8. 已确认的决定（2026-09-23）

1. 第一层大类采用第 3 节的 7 类名称。
2. 触发方式：教师点击“生成个人报告”时，先对该场考试运行整理错因，完成后再生成个人报告。生成前的确认弹窗需同时列出两部分预计请求次数；已整理且输入未变的题不重复请求；整理失败的题不自动重发，个人报告照常生成、该题不显示错误类型。班级分析页原有的手动“整理错因”入口保留。
3. 典型错法写入题库前必须经教师确认。
4. P2 选择题选项分析只做八年级上册。
5. P0 优先实施。

## 9. 相关问题复核：教师改分后的信息丢失

用户提出的“教师改分后丢失步骤归因”问题，核对结果如下：

- 系统已经有教师逐步给分的复核方式（复核页的分步分数，存入 `teacher_reviews` 并被学情按 `teacher_step_review` 读取）。但现有三场考试的数据里没有一条逐步复核记录：全部 459 次教师确认都只给了总分，这些题在学情里按整题证据、权重降低处理。失分题中占比：第2周 69/484（14%）、第3周 86/454（19%）、第4周 186/740（25%）。
- 另一处类似问题仍在：教师确认分数时若没写批语，系统把扣分理由和错误类别写成固定的“人工复核已确认”“已复核”（`backend/review/service.py` 的 `REVIEW_CONFIRMED_*`）。第2、3、4周分别有 95、119、245 条扣分理由被这样覆盖，原来 AI 写的具体错因只在原始批改记录里还有残留。这会直接削弱错因整理和报告的证据，P0 修复：教师未写批语且确认分仍有扣分时保留原扣分理由，确认满分时不保留扣分理由，填写的批语作为最终理由；确认状态由教师最终分锁表达。已被覆盖的历史记录不在 P0 中改写。
- 批改记录里的英文内部码（434 条）会进入整理错因的输入和学生薄弱点的原因列表，建议在 P1 读取时统一转成中文或剔除。（已在 P1 实现：`backend/error_causes.py` 的 `clean_cause_text` 负责整理输入层，报告展示层由 `_REASON_CODE_LABELS` 翻译。）

## 10. 实施记录

- **P0（2026-09-23 完成）**：教师确认分数但未写批语且确认后仍有扣分时，保留原扣分理由；确认满分记“人工复核已确认”。涉及 `backend/review/service.py` 与复核页面前端，历史已覆盖记录未改写。
- **P1（2026-09-23 完成）**：
  - `backend/error_causes.py`：7 类固定大类、批改/题库两套旧词换算表、内部英文码清理；未知词与占位词返回空，不猜。
  - `backend/class_analysis.py`：整理错因升级 v3（`CAUSE_ANALYSIS_VERSION = "class_error_causes_v3"`）。提示词要求 error/process/response_state 三类必须输出 7 类之一，解答题可引用评分判定点 `step_id`；`known_patterns` 携带本场已整理与跨场次同题（经题库 `grading_question_links` + `question_duplicate_links`）的错法名，模型同义必须复用；归一化严格校验大类、证据引用、判定点引用与前问来源。
  - 学生错因记录物化到 `.class_analysis/{session}.json` 的 `error_records`（偏离第 5 节“新增数据库表”的原方案，理由见该节）；每条含输入指纹与证据哈希，证据变化自动失效。
  - 编排：`report_export` job 对 `personal_analysis_html` 先执行 `run_cause_analysis(retry_failed=False)` 再导出报告；整理异常不阻断导出，结果记录 `cause_analysis` 摘要。preflight 增加 `cause_call_count`/`cause_total_questions`/`cause_estimated_tokens`，确认弹窗分开展示两部分次数。
  - 展示：个人报告跟进卡片、答题详情与失分附录显示“错误归类（AI 辅助）”，并支持跨场次“同类错误以前出现过”徽章；班级分析页错因条目显示大类徽章，v2 旧版结果标记“旧版整理 · 待升级”。
- **P2（2026-09-24 完成）**：选择题选项诊断，仅八年级上册（`bnu24-math-g8-upper`）。
  - `backend/error_patterns.py`：选项字母解析（`parse_option_letters`）、学生选项规整（`normalize_option_answer`）、选项诊断提示词与严格校验（`OPTION_ANALYSIS_PROMPT` / `normalize_option_analysis`）、`synthesize_option_result` 把学生所选项直接映射为错因分组；识别不到字母或该选项无诊断条目的记入 `uncertain_ids`，标“原因未明”，不猜。
  - 存储：每题的选项诊断结果存场次 `.class_analysis` 的 `option_analysis`（含题目内容指纹 `question_fingerprint`），同题库题（经 `grading_question_links` + `question_duplicate_links` 家族扩展）跨场次复用，指纹一致才命中；失败记录按指纹抑制报告前置阶段重发，手动整理仍重试。
  - 编排：`run_cause_analysis` 按 `plan_cause_question` 分流——八上且已关联题库的选择题走 `option`（诊断未有时一次调用），其余选择题退回 v3 整题整理；`build_analysis_preflight` 复用同一 plan 口径估算。
- **P3（2026-09-24 完成）**：填空题错误答案库。
  - 学生作答经 `normalize_answer_text` 规整分组（`normalize_wrong_answer`，截断 80 字）；库中已有的错误答案直接映射错法（`synthesize_answer_result`，零调用），与正确答案等价的失分记录不入库、退回 v3 判断；空白作答归“未作答”。
  - v3 整理产出的新错法按规范化答案回写本场 `answer_patterns` 候选库（`additions_from_v3_result` + `record_answer_patterns`，幂等）；合并题库已确认条目（`trigger_kind='wrong_answer'`）时确认优先。
- **P4（2026-09-24 完成）**：题库典型错法表 + 教师确认 + 链路切换。
  - `migrations/question_bank/042_add_question_error_patterns.sql`：`question_error_patterns` 表（题、触发方式 option/wrong_answer/step/observation、触发值、错法名、大类、出现快照 JSON、状态、确认令牌与操作者）；`question_bank/services/error_pattern_service.py` 提供确认写入（按“题+触发+错法名”幂等，重复提交追加出现快照不重复建行）、驳回、按题列出；读取侧可把旧 `error_type` 标签换算为“仅预测”候选展示（`include_predicted`），不写回标签数据。
  - 教师确认：`POST /api/sessions/{id}/class-analysis/causes/confirm`（`CausePatternConfirmRequest`，extra=forbid）。触发条件由证据推导：选择题全组同一选项字母 → `option`；填空题全组同一答案 → `wrong_answer`；否则 `observation`。未关联题库题（422 `cause_pattern_unlinked`）或该题未完成 v3 整理（409）时拒绝。
  - 前端：班级分析页错因条目显示“已入库”徽章与“写入题库”按钮（仅 `bank_confirmed=false` 且该题已关联题库、kind 可确认时显示），确认对话框可改错法名称/大类/本题表现后提交，成功后重新加载。
  - 链路切换：`integration/diagnosis_profile_service.py` 学生薄弱点新增 `error_categories`/`error_patterns`（来自 `.class_analysis` 物化 `error_records`， `_error_cause_index`）；`question_bank/recommendation/practice_plan_service.py` 推荐候选合并题库已确认错法为 `error_pattern`/`error_category` 维度，旧 `error_type` 标签经词表换算为大类参与匹配。
