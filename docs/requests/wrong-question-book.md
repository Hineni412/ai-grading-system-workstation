# 方案：学生错题本导出

用途：交给开发代理实现的已确认方案。本文内容**尚未实现**；实现完成后，把规则写入 `docs/product/KNOWLEDGE_AND_TRAINING.md`（放在“共享证据范围”或“诊断与推荐”中关于学生作答证据的位置），然后删除本文。

## 目标

教师选择学生和考试范围，一键导出 Word 错题本：每名学生一份，内容是该生在所选考试中失分题目的**题库原题**，答案解析集中放在末尾。多名学生打包成一个 zip 下载。

用户已确认：

- 产出形式：Word 错题本，每人一份，多人打包；
- 每题内容：原题 + 答案解析（末尾）。**不含**本人得分、扣分原因、作答截图，也不留重做空白。

## 现状与复用

| 能力 | 位置 | 用法 |

| 后台任务与下载 | JobManager；`backend/files/service.py` 的 `JOB_FILE_RULES` | 新增一个任务类型，`consume_after_download=True`，与训练额外导出一致：下载后删除本机副本 |

## 流程

1. 教师在“学生作答证据”页（单个学生模式）点击“导出错题本”，弹出对话框：
   - **学生**：当前学生（默认）/ 该生所在班级全部学生；
   - **考试**：列出当前教学学期内该范围学生有成绩的考试，默认全选，可取消勾选；
   - 显示预计：学生数、错题数、没有题库原题而无法导出的题数。
2. 点击“导出”后提交后台任务，页面显示进度；完成后下载单个 .docx（一人）或 .zip（多人）。
3. 群体模式和知识点模式（页面上的另外两种视图）暂不提供入口。

## 取题规则

- **错题**：有效明细中 `score_awarded` 有值、且低于满分的题。**未评分、失败或结果未知的明细不算错题**，与“未评分不能解释为零分”一致。
  - 注意：现有 `_is_deducted` 会把缺分当 0 分处理。实现时要先确认 `get_active_assessment_evidence` 是否会返回这类行，并显式排除。
- 教师最终分优先：沿用有效明细的现有口径，不另算。
- 多小问题按父题关联题库原题（现有 `_lookup_bank_question_id` 已处理）；同一场考试同一原题只出现一次。
- 同一原题在多场考试中都错：只保留最早那场的一份，后面的不重复出题。
- 没有已确认题库关联的题：不导出；在对话框和结果中列出“考试名 + 题号”。
- 题目顺序：按考试时间从早到晚分段（段标题为考试名称），段内按原卷题号排序。

## 输出格式

- 每名学生一份 Word：标题“{姓名} 错题本”，页眉写教学学期和考试范围；答案解析放末尾。
- 版式沿用组卷导出的默认 `ExportConfig`，不新增版式设置。
- 文件名：`{学号}_{姓名}_错题本.docx`；zip 名写班级和日期。
- 错题数为 0 的学生不生成文件，在结果中列出。

## 后端

- 新增一个提交接口（放在 students 路由附近），参数为 `student_ids`（或“按班级”）、`session_ids`、请求令牌。按现有写请求约定：超时后用令牌查询结果，不自动重发。
- 新增后台任务类型，例如 `wrong_question_export`：逐个学生取题、生成 Word，多人时打包 zip。某名学生失败不影响其他学生，结果中列出失败名单。
- 只读成绩库和题库。**不写入**训练证据、掌握度、组卷记录，也不计入“近期原题排除”的活动次数。
- 错题本由知识与训练模块只读成绩结果，沿用 students 路由已有的跨库读取方式，不新增跨模块写入。

## 前端

- “导出错题本”按钮放在现有“只看错题 / 全部作答”模式按钮旁，不新增面板。
- 对话框用现有设计系统组件；提交后显示任务进度与下载，沿用现有任务下载组件的做法。

## 不做

- 不含得分、扣分原因、作答截图、重做空白（用户已确认）；
- 不生成相似题或推荐题（那是个性化训练的职责）；
- 不改变“学生作答证据”页现有的查看逻辑。

## 验收

- 合成数据：两场考试，其中一题两场都错、一题没有题库关联、一题未评分、一个多小问题只错一问、一名学生全对。检查导出题目集合、分段顺序、去重、未导出清单和空学生清单都符合上述规则。
- 打开生成的 Word，确认题目与答案解析分离，答案在末尾，公式和图片正常显示。
- 多人 zip 下载后本机副本被删除。
- 测试优先扩展现有的学生成绩接口测试和组卷 Word 导出测试，不新建测试文件，除非确无归属。
