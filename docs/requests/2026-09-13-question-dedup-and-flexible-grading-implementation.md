## 1. 接手方式与范围

用户希望减少重复分析和人工确认，保留解答题的大评分步骤，同时允许 AI 根据实际完成程度给出有依据的整数部分分。

用户在其他软件中要求“按本文实施”后，按第 5 节依次完成代码、针对性测试和页面验证。已确认的产品规则见第 2 节，不重新发起完整需求讨论；一般实现细节由执行模型决定。发生真正无法从本文和代码确定的产品含义冲突时，先完成不依赖该答案的工作，再集中说明。

先读根目录 [AGENTS.md](../../AGENTS.md)，然后按本次范围读取 [考试阅卷规则](../product/GRADING.md)、[架构](../../ARCHITECTURE.md)、[测试入口](../testing/README.md)。涉及题库来源关系时再读 [题库与训练](../product/KNOWLEDGE_AND_TRAINING.md)，涉及模型正文与存储时读 [安全与诊断](../security/SECURITY.md)。

执行边界：

- 在当前项目本地 `main` 工作，写入前检查未提交改动和其他可获取的任务状态。文件中混有其他修改时保留并协调；不自动创建分支、worktree 或清理未跟踪文件。

- 本次不改训练判定的“达成/未达成”含义，不改掌握度计算、推荐算法、班主任模块或教师最终分锁，不批量重新批改历史考试。

## 2. 最终确认的产品规则

本节覆盖此前讨论中的旧建议；实现和测试以这里为准。

| 编号 | 已确认的规则 | 具体边界 |
|---|---|---|
| R1 | 考试上传、题库导入两个入口均在正式题目入库及模型分析前查重 | 文件接收和解析可以先发生；不能先新建重复题、先分析，再补查重 |
| R2 | 重复题直接关联已有题目并使用已有标签、答案和可用判定点 | 不为重复题重新生成标签、判定点或发送模型赋分；保留每张试卷使用该题的来源记录 |
| R3 | 查重要快，也要区分同题与同类变式 | 数学内容相同的格式变化可复用；改数值、运算、条件、选项或图形含义不能直接合并 |
| R4 | 不采用原卷分值 | 不从题干中的“3分”、原卷标分、旧考试分值恢复配分；保留本场 100 分及现有合理配分约束，不能把选择/填空固定为 3 分 |
| R5 | 减少教师对本地题型猜测的确认 | 本地与模型意见不同本身不构成人工处理条件；先根据题面核对并解决，只有无法确定且影响批改要求的冲突才需要教师 |
| R6 | 修复把公式下标等当成小问的错误 | `S_(1)`、`S_(2)`、指数、分数、函数参数等不能生成虚假小问；真实小问仍须完整保留 |
| R7 | 需要过程的解答题，只有正确答案且没有有效过程时，统一给 1 分 | 以现有独立评分单元为落地边界：单问题或已经独立评分的一个小问；不是每个步骤各送 1 分。正确答案且无过程不等于未作答 |
| R8 | 有有效过程的解答题按步骤完成情况给分 | 不套“只有答案 1 分”的限制；数学上成立的等价表达、其他正确方法及合并书写可完整达成评分目标 |
| R9 | 保留若干大评分块，允许块内部分分 | 每块约 3 分是粒度方向，不是所有题、所有块必须恰好 3 分；不得为实现部分分而把每块拆成一串 1 分点 |
| R10 | 新批改和保存的业务得分均为整数 | 包括步骤分、小问分、总分、候选得分和人工新录入得分；不产生 0.5 分档，不把小数成绩静默四舍五入 |
| R11 | 每个评分块输出可核查的给分依据 | 说明学生实际完成的内容、缺漏及给几分；理由来自可见作答，不只写“酌情扣分” |
| R12 | 修改实际批改链路，而不只改提示词 | 题目评分规则、模型输出、两种 AI 批改入口、本地校验、保存和复核页面使用同一口径 |

R7 的 1 分规则只适用于过程题。选择、普通填空保留原有客观判分；直接求值的一步结果如果已经完成该评分目标，可以得到对应分，不能仅因没有复述定义就标为“无过程”。不要增加小问来重复领取 1 分。

R10 约束业务得分，不把置信度、比例、统计平均分等改为整数，也不批量转换历史记录。已有人工确认成绩继续按原值展示和使用。

## 3. 已定位的故障机制

以下是源码行为和隔离复现结论，不是要求重新读取真实数据。

### 3.1 查重发生得太晚，且比较了非数学差异

- `backend/jobs/config_generation.py` 当前先调用联合分析，再执行题库入库，最后整卷 AI 配分。仅在导入器里查重，不能阻止第一次模型请求。
- `question_bank/importers/batch_importer.py` 的 `_load_duplicate_index` 每次加载所有题，`exact_question_key` 会读取富文本和图片。按次全量重建是性能瓶颈。
- `question_bank/models/question.py::duplicate_question_key` 与 `question_bank/services/duplicate_analysis_copy_service.py::_question_content_key` 把题干文本、原始公式 XML 和图片像素组合比较。
- 原卷分值前缀、减号字符、Word 公式的等价属性写法及图片尺寸变化可以造成漏匹配。
- `link_exact_duplicate` 当前先保留新题行，再复制标签。它不等于“同一道题共用一个题库身份”。

### 3.2 题型判断正确，也可能生成错误评分结构

`question_bank/training_criteria/analysis.py::QuestionAnalysisInput.explicit_part_labels` 用括号数字寻找连续小问。合成文本“面积为 S_(1)，另一个面积为 S_(2)，请选择正确选项”会被识别为两问。

随后 `objective_response_shape_for` 因存在小问标记返回 `unknown`，请求中携带 `expected_part_count=2`。模型即使在 `question_type_suggestion` 中回答“选择题”，仍可能生成“过程分析 + 选择答案”两个部分。

考试路径在 `in_memory.py::_govern_deferred_analysis_item` 中处理结果，随后 `compose_generated_config` 根据生成的 parts 再推断评分题型。必须检查这条实际路径，不能只修改普通题库分析中处理 `question_type_suggestion` 的另一条路径。

故障由错误小问输入、模型内部矛盾和后续校验遗漏共同造成。不要把它归结为“模型把选择题认成证明题”，也不要要求教师再点一次“选择题”来规避。

### 3.3 零分占位值被固化为答案上限

`backend/config_generation/normalization.py::_ensure_solution_hard_rules` 在 `part_score=0` 的未配分结构上计算上限，会将默认值截成 0；后来配分时看到字段已存在，继续保留 0。

隔离复现顺序：构造分值为 0 的过程题 → `normalize_new_generated_config_payload` → 赋正分并再次规范化 → 答案上限仍为 0。最终应按 R7 变为 1，而不是恢复旧的 25% 默认值。

### 3.4 部分分不是被数值类型禁止，而是规则和证据表达僵硬

- `ai_grader.py` 的提示词仍含“缺少某条件，该踩分点不得给分”等硬表达。
- `rubric_skeleton_from_solution_evidence` 把参考解释、答案锚点和可见证据一起拼进 `required_elements`，又把整小问扣分规则复制到每个步骤，容易导致形式依赖和重复扣分。
- `_validate_and_convert` 能接收普通数值，包括 1、2、2.5。新增整数业务约束需要真正落在接收与保存路径，不能只在提示词中要求。
- `solution_answer_guard.py` 还会用局部文本特征判断有无过程并限制分数。新增步骤判断不能在这里被旧规则覆盖。

两处现成能力不能误用：

1. `question_frequency_service.py::build_question_fingerprint` 基于知识、题型和风格等信息用于题频/题型统计，不是数学原题身份；不能用相同知识标签判为重复题。
2. `questions.paper_id` 当前只指向一张试卷。多张卷复用一个题目时，不能反复覆盖该字段或原题题号。需要稳定的“试卷出现记录 → 规范题目”关系；现有考试关联可以复用，普通试卷出现关系及持久查重索引是否需要新表，由执行者核对现有 schema 后做最小扩展。不要占用训练卷表来存普通原卷关系。

当前模块内部可完成的逻辑留在模块内。改共享的 `score_policy.py`、题目读取或结果模型前，说明直接调用者及受影响范围。新建文件/表前记录已评估的复用候选和不足，不做假想扩展。

## 5. 按顺序实施，每步有明确完成条件

### A. 修复题目结构识别与一致性检查

1. 修复公式中的括号数字误识别。优先使用已有富文本/公式结构来区分公式与题目编号；纯文本回退规则也要覆盖下标、指数、分数、函数值与图号引用。
2. 本地题型、作答形态和小问数量必须相互一致。不可靠的猜测作为提示，不写成必须服从的事实。
3. 新题继续用原联合分析请求取得题型、标签和判定点，不增加单独的 AI 判型请求。
4. 检查模型的题型建议、题面选项/真实小问以及 evidence parts 是否一致。明确的单项选择只有一个客观评分单元，参考解题过程可保留为解析，不新增过程分。
5. 对确定的机械结构问题本地修复；无法确定是否改变题意的，进入现有待处理流程并说明具体冲突，不自动追加付费请求。
6. 保留教师主动改题型的能力；一般题目不逐题索要确认，不以“本地与模型不同”直接弹人工处理。

完成条件：第 7 节 S 组通过；题型、评分结构和题库类型一致；真实多问没有被合并，公式下标没有被拆为小问。

### B. 提前查重、建立稳定题目复用

1. 把已解析的待入库题转为同一查重输入；暂存文件可以存在，正式重复题行和模型请求都尚未发生。
2. 建立可复用的持久内容索引。首次构建与每次查询分开；已有题的内容或图片变化时按其既有修订更新索引，不每次解码全库图片。
3. 文本比较统一空白、题号、题前分值、等价的全半角符号及减号；保留数学符号角色，不能用“删除所有标点”代替公式理解。
4. 公式比较忽略字体、字号、XML 空白及等价属性写法，保留根指数、上下标、分子分母、正负号和运算次序。优先复用已有公式转换能力；不能只拼所有文本节点，导致平方与普通数字混淆。
5. 图片使用候选缩小后的内容核对：允许不改变题义的缩放、压缩或淡水印差异；标签、长度、角标、线条或阴影变化属于不同内容。单纯图像相似分数不直接授权复用；不能确定时作为待核对候选。
6. 查询结果至少区分“确定复用”“新题”“需核对”。确定复用直接指向旧题、保留本卷题号与出现记录；同批重复和再次导入同文件也保持幂等。
7. 复用已有标签、答案及与题目内容相符的判定版本。旧结果不足或冲突时显示缺项，不能把重复题偷偷放回模型队列；教师显式后续处理沿用既有入口。
8. 多个旧候选完全相同时优先采用已有有效人工确认版本，其次完整且与当前题目相符的版本，再用稳定 ID 决定；无法解决的内容冲突交现有待处理流程。不得按“最新模型结果”覆盖旧题人工标签。
9. 保留已存在的历史题号及引用。此次修复不顺便合并、删除真实库中的历史重复题。

伪代码只约束顺序，不要求建立同名新类：

```text
parsed = 现有来源解析器(上传来源)
matches = 共同查重能力(parsed)
reused = 读取 matches 中确定同题的旧标签、答案、判定点
new_inputs = 只选 matches 中的新题
analysis = 新题按现有入口需要执行的分析(new_inputs)
保存本卷出现关系(旧题关联 + 合格新题)
exam_structure = 将复用结果与新结果按原卷题号组合
```

普通题库导入是否自动分析新题沿用其当前用户选项；不因这次修改给原来只导入的操作增加模型调用。

完成条件：第 7 节 D 组通过；两入口命中重复题时不新增规范题目、不重新写其标签；题目来源、图片和题号仍能正确展示。

### C. 接通考试入库状态、本地配分与 1 分规则

1. 调整考试 bundle/检查点契约，使复用题与新分析题都能组成完整题目结果。复用题不需要伪造 model request、成功的模型回执或当次新模型来源。
2. `question_bank_sync.py` 不能把复用题交给当次模型标签写入器覆盖。整卷就绪按每个来源题是否已经有可用关联和评分依据判定，不按新增题数判定。
3. 返回统计至少能分清本卷题数、新增题数、复用题数、待处理数。全卷复用时新增数为 0 仍可成功；只重试失败/缺失项。
4. 为满足“重复题不发模型赋分”，本方案使用现有本地配分能力组合整卷分数，移除这条考试主流程对整卷 AI 配分的依赖。新题分析仍生成无分判定点。不能在全卷结构摘要里再次把重复题发送给模型。
5. 不采用原卷分值作为权重或默认值。本场配分从既有题型、有效数学步骤和工作量约束出发，复用 `score_policy.py` 的整数分配/质量检查。自动权重只能来自判定结构和已存分析；算法固定、同一输入结果可复现。以合成小测检查选择/填空可以高于 3 分。
6. 保留现有每题上限、同类客观题同分和总分 100 等约束；“约 3 分的大块”不覆盖这些总分约束。约束无解时用既有配置错误提示说明，不能暗改总分、编造评分块或退回原卷分值。
7. 未配分结构不计算答案得分上限。新规则的过程评分单元在配分后设置 `answer_only_max_score=1`，错误答案且无有效过程为 0，客观单元不套此字段限制。
8. 排查 normalization、`score_policy.py`、编辑器默认值、评分防护及两种批改提示词中的旧 25% 和 0 分默认路径，使新规则一致。只修一个生成函数不算完成。
9. 完整/部分有效过程不受答案上限压分。`answer_is_blank_or_no_valid_work` 不能把“答案正确但无过程”当空白判零。
10. 正式发布仍通过现有配置发布入口。题分、小问分、步骤分逐级相等；题型修复后的整卷重新配分，不能保留之前误增过程对应的旧题分。

完成条件：第 7 节 C 组通过；全复用卷可完成配置且模型调用数为 0；混合卷模型输入只含新题；新评分依据不再自动产生 0 分或 25% 答案上限。

### D. 改为大步骤完成度评分与可核查理由

1. 在判定点转评分结构时区分“参考解法说明”“定位答案的锚点”“学生必须达成的数学目标”。`answer_anchor` 不要求逐字复现；`required_elements` 不把整段参考解释列成必写清单。
2. 保留有数学意义的大评分块。定义块的目标、最高分、允许的等价达成方式；不按参考答案行数拆分，不为部分分新造更多块。
3. 保留小问通用规则在小问层；步骤规则只包含该步相关内容。去掉整段通用扣分政策复制到每步造成的重复扣分。
4. 更新共同评分规则、整卷提示词和混合批改提示词，以及新评分依据中的对应文字。清理与部分分冲突的“一有缺漏整步不给分”等旧命令。
5. 同一次模型请求返回每步状态、可见作答依据、整数得分及理由。不要另发一轮模型请求来生成解释；解释是简短的评分依据，不是要求模型输出长篇内部思考。
6. 模型按第 6 节格式输出，接收器验证题号/步骤身份、范围、整数及总和；数学完成程度由模型依据作答判断，不由关键词数量或正则表达式代判。
7. 同一关系可等价完成多个既有评分目标，每块只计一次。前一计算错误引起的后续数值错误，不反复扣同一原因；沿用该数值且方法正确的后续步骤保留对应方法分。独立新错误另计。
8. 空白、无有效成果或核心关系完全不成立的块可以为 0；不能为任何有字迹的步骤自动保底给分。真正直接作答的小问仍按原规则评分。

完成条件：第 7 节 G 组通过；一个 3 分块可以得到 0/1/2/3，各档有可核查依据；同一规则同时覆盖整卷和混合批改。

### E. 整数保存、理由回读与现有页面展示

1. 在 AI 结果转换和人工保存服务入口校验整数，前端输入同步使用整数步长与校验。不能仅靠 HTML 的 `step=1`。
2. 数值上为整数的 `3.0` 可规范成整数 3；2.5 等非整数、布尔值、非有限值、负数、越界值不保存成有效新成绩。不要静默四舍五入或截断。
3. 无效模型评分沿用现有失败/待复核路径，不把格式失败视为学生 0 分，不自动付费重试。人工录入非法值时保留草稿并提示。
4. 复用现有结果 raw_json/detail_metadata 保存评分块明细，让 API 与 `frontend/src/api/review.ts` 传递到评分检查器。核查读取端是否过滤新字段。
5. 在现有“评分依据/扣分原因”区域显示“目标、满分、实得分、完成情况、依据与理由”。不新建评分页面，也不增加一排开关；展开明细即可。
6. 教师修改后的最终成绩仍为真值；模型步骤明细标明是 AI 判定，不因人工改总分而伪造对应步骤理由。既有 AI 原分与教师最终分区分继续保留。
7. 重新进入页面、后端重新读取以及导出成绩时，新业务得分仍为整数，步骤理由不丢失。统计均分可继续为小数。
8. 历史记录缺少步骤明细时显示“暂无步骤评分依据”，不从总分反推、补造过程，也不自动重新调用模型。

完成条件：第 7 节 P 组通过；从模型输出到保存、回读和教师检查形成完整链路，页面内容与保存的分数一致。

## 6. 模型评分输出契约与可直接采用的规则

### 6.1 一个 3 分块的尺度

| 状态 | 得分 | 解释 |
|---|---:|---|
| 完整达成或等价达成 | 3 | 目标已完成；省略可核验的简单算术或合并书写不扣分 |
| 主要关系、方法成立，局部错误或次要缺漏 | 2 | 保留主要成果，并说明具体扣掉的 1 分 |
| 有明确有效进展，关键目标尚未完成 | 1 | 指出实际成立的部分，不能凭“思路大概对”给分 |
| 未作答或没有成立的相关数学成果 | 0 | 指出缺失目标或无效依据，不能为了灵活强行给部分分 |

其他满分的块保持相同原则，在 0 到该块满分之间使用整数；不要用全局固定百分比换算完成程度。

可写入共同规则的核心文字：

> 每个步骤表示数学目标及最高分，而不是必须照抄的参考答案行。先核对学生实际作答是否完整或等价完成目标；完成给满分，部分完成按有效成果和具体缺漏给整数部分分。只因表达形式、合并书写或省略可核验的简单运算，不得扣分。扣分必须对应当前目标中的真实缺漏，同一错误不重复扣。只有正确最终答案且没有有效过程的过程评分单元统一给 1 分，不在各步骤重复给 1 分。所有步骤得分不得超过对应满分，总分为步骤分之和。

### 6.2 在现有 grading_details 中扩展，不另建结果体系

以下为建议的最小字段契约，实施前核对现有同义字段；已有字段可复用，但两种批改模式、存储及前端必须一致。

```json
{
  "question_id": "Q1",
  "score_awarded": 2,
  "deduction_reason": "本块3分：关系建立正确，计算出现局部错误，扣1分。",
  "answer_only_correct": false,
  "step_assessments": [
    {
      "step_id": "S1",
      "achievement": "partial",
      "score_awarded": 2,
      "student_evidence": "学生写出了与本题对应的正确方程，随后计算错误。",
      "missing_or_error": "局部计算结果错误。",
      "reason": "主要关系已建立，按本块完成程度给2分。"
    }
  ]
}
```

- 示例只演示契约，不是一个需要真实模型判断的数学样本。
- `question_id` 使用现有规范父题/独立小问 ID，`step_id` 来自该评分单元的 rubric，不能根据作答重新编号。
- `achievement` 使用 `full / equivalent / partial / none`。满分、部分分与状态一致；满分也应给出简短作答依据。
- 每块最高分从本场 rubric 读取，不能相信模型另造满分。每个有效块恰好一项，不丢块、不重复；当前独立评分单元的总分等于块得分之和。
- `answer_only_correct=true` 表示过程题仅有正确最终答案且没有有效过程：该单元总分为 1，归于已有的结果对应块，其余无证据块为 0，不能每块加 1。不新造“奖励分”块。结果对应块可以是包含最终求解的大块，不要求额外拆出纯答案块。此时先应用整个评分单元的 1 分特殊规则，再检查步骤加总；不能因最终数值正确，把结果块标为完整过程并给满分。由模型明确核对答案正确性并说明依据；本地不只凭 `x=数字` 就当完整过程。
- 对已经有有效过程的 `partial` 作答，不能因一个未完成块而套用答案上限。
- `student_evidence` 引用学生实际写出的关系或作答位置，不能把参考答案内容当学生证据。看不清时进入现有低置信/复核处理，不编理由凑数。
- 现有 `evidence_steps / missing_steps / candidate_scores` 的兼容性保留；新步骤结果是明确来源，不能从旧总分推造。候选得分也用整数。
- 缺字段、未知步骤、分数不守恒或非整数使用现有失败/待复核机制；不要无上限追加模型修复请求。

### 6.3 完整的合成数学样例

题目：矩形周长为 20，面积为 24，求两条边长，并写出求解过程。该独立评分单元共 9 分，已有三个大块：S1 建立边长和为 10 的关系（3 分）；S2 建立面积关系并联立（3 分）；S3 求解并回答边长（3 分）。

| 合成学生作答 | 预期步骤分与理由 |
|---|---|
| 设一边为 x，另一边为 10−x；x(10−x)=24；解得 x=4 或 6，因此两边为 4 和 6。 | 3+3+3=9；三个目标均已完成，不强求单独展开每行算术 |
| 两边 a、b 满足 a+b=10、ab=24，所以 a、b 为 4、6。 | 3+3+3=9；表达简洁但和、积关系及求解结果完整，不因未照参考方法设元而扣分 |
| 设两边 x、10−x，列 x(10−x)=24，得 x²−10x+24=0；误算 Δ=16，解得 x=3 或 7，答两边为 3、7。 | 3+3+2=8；只在 S3 对判别式的局部计算错误扣 1 分，后续按该判别式求根不再重复扣同一错误 |
| 仅写“两边为 4 和 6”，没有任何关系或计算。 | 0+0+1=1，answer_only_correct=true；S3 为部分得分，明确写明仅答案正确，不能推测学生完成了建模过程 |
| 空白，或者只写错误边长且没有有效过程。 | 0+0+0=0；不能自动赠送答案分 |

该样例固定了本项目期望的判分口径。用模型替身检查上述明细不会被本地防护压成 0、全块扣分或丢失理由；真实模型能否遵循该口径仍按第 7 节要求单独验收。

## 7. 必须有明确预期的验收案例

测试位置可复用第 8 节文件，不要求每个案例单建文件。合成测试里的题目、公式、图片由本地生成，禁止拿真实试卷做写入式验证。

### D：两入口的提前查重

| 案例 | 输入与预期 |
|---|---|
| D1 | 同题仅题号、空白、分值前缀和等价减号变化：关联同一规范题，旧标签保持一致 |
| D2 | 同一个 Word 根式只有字体、XML 空白和 `1/on` 等价开关变化：同题；平方改成立方根：不是同题 |
| D3 | 同一合成图缩放、压缩或有淡水印而内容不变：可确认复用；只改一个点名、线段数值、角标或阴影：不能直接复用 |
| D4 | 题干相似但数值、选项顺序、正确选项、关键关系不同：不得直接沿用旧答案与评分点 |
| D5 | 所有题均复用：新增规范题为 0，本卷出现记录完整，考试入库 ready，模型请求为 0 |
| D6 | 新题与重复题混合：请求捕获器证明重复题的正文、图片、标签分析任务和配分摘要均未发送；原题顺序与题号保持 |
| D7 | 同批重复、同文件重复导入、取消后续作：不新增重复规范题、不重复覆盖旧标签、不重发已成功题 |
| D8 | 旧题标签/判定点缺失或内容冲突：明确待处理，不暗中发送模型，不把整卷标成可批改 |
| D9 | 两卷使用同一题后，按现有删除/恢复入口处理其中一卷：另一卷仍可读取题目、图片、标签和已发布评分快照；所有验证在临时库 |
| D10 | 原有来源题库列表、原卷题号、预览和题频统计仍能表达“两张卷使用同一道题”；不能因共用身份把来源次数算丢 |

性能验收使用同一台机器、同一份合成输入比较前后。建议基准：2,000 道已建索引题，导入 20 道含重复/新题及配图的题；分开报告首次构建与后续查询。热运行 5 次，中位查询时间目标不超过 2 秒，并快于原实现。该数字是实施验收目标，尚未测得；若未达到，定位具体瓶颈，不把首次全库构建偷偷排除为“已完成”。另用调用计数证明未改旧题不再每次重新读取全库公式/解码全库图片。

### S：题型与小问

| 案例 | 预期 |
|---|---|
| S1 | `S_(1)、S_(2)`、`x^(1)、x^(2)`、`f(1)、f(2)`、`(1)/(2)`、图(1)/图(2)引用不产生小问 |
| S2 | 行内或换行的真实“（1）求值；（2）证明”保留两问，分数和评分项正确对应 |
| S3 | 单选题模型回复“选择题”，却返回过程分析和选择两个 parts：不按两问配分；解析内容不会成为过程分 |
| S4 | 本地猜成填空、模型根据真实两问建议解答题：不因意见不同就强制人工；最终按题面真实要求组织 |
| S5 | 真正无法确认的题意/图片冲突：只要求处理相关题，并显示具体原因；正常题无需逐题确认 |

### C：配分和答案 1 分

| 案例 | 预期 |
|---|---|
| C1 | 未配分过程题从 0 分结构走到正分结构：最终答案上限为 1，不残留 0；再次保存/读取仍为 1 |
| C2 | 所有题完全相同，只改变原卷标注“3分/5分”：本场配分结果相同，题库判定点仍无分 |
| C3 | 合成小测含 6 道同类选择、2 道普通填空、2 道各有 3 块的解答题：合计100，各层整数守恒；选择/填空允许高于3分，不继承源卷值 |
| C4 | 正确最终答案、无有效过程：独立过程单元恰好1分；错误答案且无有效过程为0；空白为0 |
| C5 | 三个3分块中两个完整、一个部分：按3+3+2=8计，不受“仅有答案1分”压分 |
| C6 | 选择/填空答对仍满分；原子求值已经完成目标时按该目标给分；不得机械要求展开一行平方或立方运算 |
| C7 | 多小问题保持原有独立评分身份；不额外拆小问获得多个答案1分；普通考试分数不写回训练判定点 |

### G：整数部分分及解释

| 案例 | 预期 |
|---|---|
| G1 | 满分3的块有完整正确依据：3；同方法等价表达或合并书写：仍为3 |
| G2 | 在一个“建立关系并计算”的3分块中，关系正确且只发生局部计算错误：固定合成预期2分，说明具体错误 |
| G3 | 该块存在有效起步，但关键关系尚未建立：固定合成预期1分；只有无关文字或完全错误依据：0 |
| G4 | 两份合成作答只相差是否单写简单算术展开：数学依据一样时同分，不按书写行数扣分 |
| G5 | 前面单次算错后，后续沿用数值且方法正确：保留后续方法分；前面没有任何有效关系、后面只猜答案不得因此获得过程分 |
| G6 | 理由必须对应学生作答：模型引用学生没写过的算式不作为通过案例。使用已知合成作答人工核对预期，不能只检查 reason 非空 |
| G7 | 一个块返回2.5、未知步骤、重复步骤、漏块或总分不等于步骤之和：不保存成有效新成绩，不静默取整，不自动追加模型请求 |
| G8 | 用同一组合成作答/模型替身分别走整卷和混合批改：分数、答案1分规则、整数校验、步骤理由保存一致 |

模型替身测试只能证明契约和数据流；它不能证明真实模型一定按尺度判断。真实模型的评分一致性验收需要另获用户授权，使用合成作答并事先说明预计请求量，未执行时明确标为未验证。

### P：保存与页面

| 案例 | 预期 |
|---|---|
| P1 | 保存3+2+1的步骤记录后重新进入：6分总分、每块依据与扣分理由完整一致 |
| P2 | 人工输入整数可保存；输入2.5阻止保存并保留草稿。旧已有小数成绩只读展示不被批量改写 |
| P3 | 教师修改最终分后重新进入：最终分是教师值，AI原分与AI步骤解释保留且清楚区分 |
| P4 | 无步骤明细的旧结果显示暂无依据，不编造明细；不影响查看已有成绩 |
| P5 | 配置、检查器和批量录分在常用窗口宽度可用，长理由能展开查看；无逐题确认堆叠，无另起评分页面 |
| P6 | 重新配分发布后走现有样卷/预检修订规则，不用过期映射静默开始批改 |
