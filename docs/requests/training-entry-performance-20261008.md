# 训练与班级组卷进入页面性能评估

本记录回答进入页面或切换班级时，能否明显缩短等待。评估及实施日期为 2026-10-08。用户已授权实施四项优化：正文计算复用、指定题读取、限制后台预取和精简页面显示数据。产品修改与相关回归验证已完成，正式产品的同输入测量和8035页面验收结果见下方实施验证；早期评估与候选实验单列，不作为正式产品验收。

## 四项实施内容

| 内容 | 当前实现 | 保持的规则 |
|---|---|---|
| 正文计算复用 | 来源快照范围内按完整内容复用；每线程最多1024项，键为32字节摘要，请求结束释放 | 正文、图片、答案、修复和知识标准变化刷新；失败不缓存 |
| 指定题读取 | 六类初始表按题号读取，每批最多64题；总题号数不截断 | 完整资料、技能、历史版本优先级及来源版本保持一致；空题号仍用全范围路径 |
| 后台预取 | 只准备当前目标的下一个目标；筛选、分页、切目标及离页停止旧预取 | 选中正在预取的同一目标时复用请求，前台操作优先 |
| 显示数据 | 既有诊断入口使用显式display模式和严格解码；全部学生、知识项和小组保留 | 默认完整响应与旧摘要兼容；采用及出卷另取完整依据；旧草稿和未知请求恢复沿用原令牌 |

正文与来源摘要在训练判定、作答任务和推荐之间共用，不能只在页面模块消除重复。因此本次修改三个现有模块的共享摘要函数与推荐来源快照入口。没有新增服务、数据库表或迁移，评分、训练证据、原题排除、难度、配额和教师最终分锁规则保持原义。

## 实施前定位的重复工作

章节进入和切班经现有诊断路由，先建立完整诊断，再计算章节小组。`include_student_detail:false`只减少返回的点详情，不改变内部诊断和小组输入。左栏使用全册小节统计，已学进度也使用其他章的有效证据；不能为了加速只诊断第一章。

同一题的正文指纹在题目输入属性、当前判定版本、兼容正文、题型别名和小问画像中重复计算。上一轮有界Word缓存保持128项，候选强制重建仍会因不同正文交错而淘汰。请求内按完整内容复用是本轮候选实验；单纯按对象编号复用不能证明嵌套字典改变后仍刷新。

班级组卷前台先读考试依据，再读首项目标候选，随后读首批12题的富内容。页面准备好后还会逐项目标预取候选和首批题面。合成重放中，3个不同目标分别准备诊断、活动及选题3次；7名合成学生、3个目标会进入逐生候选评估21次。这是工作次数证据，不是耗时测量。

指定12题的组卷预览会进入来源快照；其初始查询先读取5张全范围表，再在内存筛选题目。在1000题合成库重放真实首段查询，原读取每表1000行，按题号下推后每表12行，选中题的规范化SQL输入相等。尚未据此证明完整候选描述、来源版本和真实请求耗时相等。
