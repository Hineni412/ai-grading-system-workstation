# 任务二：按章节推荐跨班训练小组实施方案

日期：2026-09-08\
用途：明确候选分组、教师采用流程、多人同卷衔接与验收。\
状态：方案，尚未实现。本次只编写文档，没有读取真实学生数据或生成真实推荐。\
前置任务：[知识图谱掌握度精细化实施方案](2026-09-08-mastery-refinement-implementation-plan.md)。

## 1. 已确认目标与范围

用户已确认：

- “按学生训练”继续服务一人一卷。
- “按章节训练”服务群体训练，系统先推荐相似水平、相似薄弱点的学生组，由教师核对后采用。
- 默认将教师选中的多个班一起推荐，用于统一安排课后训练。
- 总分筛选不再是推荐小组的前提；不需要教师反复猜一个分数区间。

本任务要回答：在选定章／小节中，哪些学生适合围绕共同目标做同一份训练，以及为什么。

本轮不做固定能力分班、全校长期学生分层、自动发送作业、自动采用小组、课程表、复测台账或班主任流程。训练题量、时长、打印回收仍沿用现有范围；少量课堂短题属于另外的产品改动。

## 2. 使用流程

### 2.1 主流程

1. 教师进入“按章节训练”，选择一个或多个班、考试证据范围，再选择章／小节。
2. 系统在这份范围中生成候选小组，不要求输入总分上下限。
3. 先展示少量最有共同训练价值的小组；其他候选按需展开，不强迫教师逐人查看。
4. 教师点开一组，查看共同知识目标、名单、班级分布、证据与组内差异。
5. 教师可增减成员、删减共同目标；系统重新检查该组是否仍适合做同卷。
6. 采用该组时，预选共同目标并给出适合该组的出卷设置；教师调整后进入现有草稿审核和出卷。
7. 继续使用现有逐生冻结实例、扫描回收、训练判定、复核与证据回流。

首版一次采用一组、生成一份共同选题草稿；不自动批量生成所有候选组的试卷。返回章节页时恢复原跨班范围，方便继续处理其他组。

### 2.2 页面主次

- 顶部主要条件：班级、考试范围、章／小节。
- 推荐小组是主要结果；原热力图用于展开核对和手动选择，避免同时新增多块常驻面板。
- 每组主操作为“查看并采用”；展开后提供成员与目标调整。
- 分数筛选保留在辅助条件中；启用时明确显示“在该分数范围内推荐”，不能把以前页签遗留的分数条件悄悄带入默认分组。
- “按学生训练”的一人一卷行为保持。

### 2.3 候选组应展示的信息

以下为示例，人数和描述均非真实数据：

> 平方根相关基础练习｜8人，来自3个班\
> 共同目标：区分根号求值与平方方程的解。\
> 归组依据：相关直接考查题存在失分，运算题表现相对接近。\
> 证据说明：6人有多次相关作答，2人仅有一次作答，需要教师核对。\
> 展开：成员、班级、来源题、组内差异及可用题目情况。

名称和理由由实际知识目标及证据生成。“概念混淆”“运算粗心”等错因只有被原证据明确支持时才能使用，不能从百分比或标签自动推断。

## 3. 为什么依赖任务一

现有诊断接口已提供学生身份、细知识点、掌握度、证据数量、来源题和层级，可以复用。当前小问共用整题标签时，相反的薄弱结构却可能生成相同百分比；此时算法只能重复上游的混淆。

正式启用分组前，所选范围至少具备：

1. 有效的小问／细点归属，或明确区分的粗粒度与缺失标记。
2. 同一版本的当前掌握度和有效证据强度。
3. 对难度未知、仅有综合表现、无证据学生的可见说明。
4. 可用题库候选和现有训练判定资料。

不是要求整个题库全部补齐。准备好的章节可以先推荐；主要只有粗粒度资料的范围，应提示补齐或使用人工选择，不能包装成准确的小组。

页面和分组计算可先用合成契约开发，但正式数据结果依赖任务一。两项都在当前项目 main 上实施，共用诊断、训练接口和推荐代码，默认顺序修改；不能只因文档分成两个任务就安排同文件并行写入。

## 4. 分组依据

### 4.1 输入

使用同一份受控范围与来源修订：

- 教师明确选中的班级和学生边界；
- 选定考试与当前既有历史参考规则；
- 所选章／小节内的活动细知识点；
- 每生每点的当前掌握度、直接证据数、有效权重、证据粒度；
- 相关基础或综合任务的实际表现；资料不足时保留未知；
- 本地可练题库的目标覆盖、难度和既有练习排除条件。

学生以内部分配的稳定身份区分，显示班级、姓名及必要的学号；跨班同名不能合并。

考试总分不进入默认相似度计算。章、节与细点的重复汇总不一起计算；只使用选定范围内的细点。

### 4.2 决定能否同卷的顺序

1. **先有共同训练目标。** 至少有一个有证据支持、对成员确实有训练意义的共同目标。
2. **再看目标上的水平是否接近。** 基础不稳与基础已稳定、仅综合任务失分，不能仅因总分接近合并。
3. **检查证据支持程度。** 缺失不按零；只有粗粒度综合失分，不认定为明确的基础薄弱。
4. **检查有没有适合共同使用的题。** 有相似学生但题库暂无合适材料时，明确报缺口。

### 4.3 首版算法建议

采用可解释的本地分组计算，放在现有训练推荐模块内，不引入大模型聚类、算法注册表或常驻服务。

具体过程：

1. 从现有“需巩固”口径产生候选训练需求，结合证据强弱形成每生的目标需求列表。75%沿用当前显示口径，仅作候选排序参考，不解释为科学确定的掌握线。
2. 对学生两两比较“共同需求的重合程度”和“共同目标上的掌握差异”；没有共同有效目标时不能形成相似关系。
3. 以共同目标为起点形成候选组；加入成员后重新检查全组共同目标、水平跨度与最不相似成员对。防止甲像乙、乙像丙，就把实际上差异很大的甲丙硬合并。
4. 只有一个人的候选不作为群体训练组，可提示使用一人一卷。没有可靠共同点的人保留在“暂未推荐”说明中。
5. 给候选组排序：共同目标覆盖、成员相容性、证据支持、题库可用性综合考虑；不按人数最大或总分最低单独决定。
6. 合并成员与共同目标几乎相同的重复候选；首屏展示前3—5个，更多可展开。不能为凑足组数硬分所有学生。

可供首版实验的相似度形式：共同需求采用加权交集／并集，水平差异只在共同可用细点上计算；将目标相似度作为主要项、水平接近程度作为次要项。初始可采用70%／30%组合，在合成边界场景通过后固定参数版本。

具体合并阈值、证据强度上限和水平跨度由实现者用合成反例校验，作为内部参数，不增加教师必须调试的滑块。不能只给一个综合分而隐藏“哪些知识共同薄弱、哪些成员差异较大”。

### 4.4 缺失、小样本和多重归组

- 无证据学生不进入该目标的薄弱组；无证据不等于不会。
- 只有一次清晰直接作答，可以形成“证据较少”的候选供核对；只有不明综合失分则不够。
- 学生只在不同且不重合的知识点上有证据时，不能因为其余位置都为空而判为相似。
- 一个学生可能适合多个不同目标的候选。采用前显示与本轮已采用小组的成员及目标重合；同目标重复训练默认不安排，由教师调整。
- 不把某次归组写成学生永久能力标签。证据更新后重新建议，不悄悄改动已经采用并出卷的名单。

## 5. 群体选题必须配套调整

### 5.1 当前需要修改的行为

现有多人同卷会在遍历学生时先选出各阶段题目，再让后续学生复用；目标难度可来自首名学生。这能保持同卷内容一致，但不足以证明内容适合全组。[当前推荐实现](../../question_bank/recommendation/personalized.py)

本任务需改为先形成群体训练画像，再选一次共同题目，最后为每名成员保留各自实例与来源说明。

### 5.2 群体选题规则

- 共同目标以采用后、重新校验的目标清单为准。
- 每个目标先计算组内掌握分布，使用对极端值不敏感的组内代表水平估计适用难度，并检查较弱成员是否被明显超出。
- 同一目标差距过大时建议拆组或调整成员；不让一个离群成员把全组难度拉到极端。
- 训练难度设置可以由教师修改，修改前后显示适用性变化。
- 题目只选择一次；名单顺序、班级排列或同名学生的显示顺序不能影响题目集合与顺序。
- 继续沿用知识范围、可练判定点、题型、难度、时长、卷内去重和近期已练排除规则。
- 多班成员较多时，“有人已练过就排除”的既有同卷规则可能缩小共同题池。缺题时明确说明原因，不自动放宽既有规则或隐式把成员踢出小组。
- 仅有部分成员需要的个别目标，不自动塞进全组共同卷；可由教师另行使用一人一卷。
- 首版继续使用现有训练题量与阶段比例；不把本任务扩展为短题诊断或新打印系统。

候选组预览可做只读的题池覆盖检查，不必提前生成完整草稿或PDF。正式选题仍在教师采用后执行。

## 6. 复用、接口与保存

| 现有候选 | 如何复用／为什么需要扩展 |
|---|---|
| DiagnosisProfileService | 复用学生范围和掌握度资料，不能新增第二份掌握度算法 |
| 现有训练 diagnosis 接口 | 优先增加可选 grouping 请求参数和候选组响应；只有明确请求章节分组时才计算，不让其他页面读取诊断都触发分组 |
| TrainingRecommendationsView、ChapterTrainingMatrix | 在按章节页呈现候选组，热力图作为核对依据；不新建群体训练工作台 |
| EvidenceScopeFilters | 复用多班与考试选择；调整章节分组的默认主条件，不继承隐藏总分筛选 |
| PersonalizedRecommendationModule | 复用多人同卷、目标匹配、题池与出卷规则；修正为真正的群体选题依据 |
| 现有推荐草稿和范围快照 | 保存教师实际采用的成员与共同目标，不把临时候选当成已经安排的训练 |
| 现有页面会话与草稿恢复 | 恢复跨班来源范围、所选章节及采用位置；不建立另一套学生分组数据库 |

首版不新建独立分组服务，不添加独立数据库。预计在现有 diagnosis 请求／响应及草稿快照中扩充字段；候选组无需另建长期业务表。

### 6.1 响应应包含

- 来源范围与掌握度版本；
- 每组候选身份、成员稳定身份和班级分布；
- 共同目标、成员差异与可追溯原因；
- 证据稀疏、粗粒度或题池不足提示；
- 未形成推荐的学生及原因；
- 建议的群体难度依据。

完整成员与证据仍保留在现有受控会话和服务端对象，不放入地址栏或公共任务摘要。采用时使用原有来源修订检查，不新建额外权限或校验机制。

### 6.2 采用与恢复

候选展示范围与正式出卷成员分别保留：查看一个候选组不修改原跨班选择；采用后，草稿使用这组成员的精确范围并重新计算群体依据。

教师修改名单后，原推荐理由可能失效，必须重新检查共同目标；不存在共同目标时保留编辑结果并提示调整，不盲目生成同卷。

来源更新、教师改分、训练证据回流或题库变化时，候选组标明需要刷新。刷新建议不覆盖已生成草稿或冻结卷。

刷新页面、切换到其他入口再返回，应恢复原跨班范围；如候选过期则重新计算，不将旧卡片当成当前事实。接口失败保留当前选择和编辑内容。

## 8. 验收场景

| 场景 | 正确结果 |
|---|---|
| 总分相同，一人弱在A，一人弱在B | 不因总分相同进入同一共同目标组 |
| 总分不同，在所选章节中有相同薄弱点且水平接近 | 可以跨班形成候选组 |
| 基础题稳定，仅综合应用失分；另一人基础题频繁出错 | 区分训练需求，不仅按章节平均百分比合并 |
| 所选三个班有同名学生 | 按稳定身份分别展示、选取、保存和出卷 |
| 学生缺考或某点没有证据 | 按既有历史参考规则显示来源；缺失不填零，不据此强行归组 |
| 仅共享一个低可信综合失分记录 | 显示依据不足，不输出确定错因或强制薄弱组 |
| 甲像乙、乙像丙，但甲与丙水平差距大 | 不能仅靠相似关系连成一大组 |
| 没有合适共同题／共同题被已练规则排除 | 如实显示缺口，不自动放宽或生成不相干题 |
| 改变学生输入顺序和班级排列 | 候选成员、目标及同组正式选题保持一致 |
| 教师增减成员 | 重新核对共同目标、难度与题池；原名单可恢复 |
| 同一学生被多个已采用目标重复覆盖 | 出卷前显示重合，由教师调整，不静默多发同目标作业 |
| 采用一组出卷 | 每名成员有自己的实例，题目相同且顺序一致 |
| 切页／刷新／返回章节页 | 原跨班范围和采用状态可恢复，过期候选提示刷新 |
| 分组接口或草稿生成失败 | 保留选择，不留下被误当成正式训练的半成品名单 |
| 已有一人一卷与手动多人同卷 | 保持原入口可用，群体选题修正有对应回归验证 |

后端复用个性化推荐、训练接口与诊断测试；前端检查章节页、范围筛选、采用、保存恢复和出卷。性能使用同机合成跨班输入前后对比：分组不得逐对重复查库或调用模型；完成必要检查后不默认扩大到完整发布套件。

## 9. 费用、数据影响与回退

候选分组、理由整理和本地选题本身不需要真实模型调用；题库缺资料的补分析属于任务一，训练判定继续沿用原有模型费用。

本任务不要求重新处理整库题目或重算考试成绩。它依赖任务一已经提供的当前证据；读取真实学生范围进行试用仍需本次明确授权。

未采用的候选仅是建议；采用结果保存于现有草稿和冻结实例。失败时保留当前草稿，不自动发送、打印或批量冻结。

回退时恢复原章节热力图与人工选人入口，已生成训练卷仍可回收。应在合成数据中验证新增可选快照字段的兼容读取；涉及真实恢复覆盖或正式服务重启，仍按[项目规则](../../AGENTS.md)单独确认。

完成标准是教师能在选定多个班和章节后直接看到可解释的小组，核对一次名单便能进入共同训练；分组数量多、算法术语复杂或页面卡片多，都不是完成标准。
