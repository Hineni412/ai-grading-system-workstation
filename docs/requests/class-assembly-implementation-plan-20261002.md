# 班级组卷重新设计 · 实施方案

- 用途：交给实施方按此方案改造组卷工作台的“学情组卷助手”，使其成为“班级组卷”。
- 状态：P1 依据与布局、P2 出卷设置、P3 快速起草及 P4 全班固定选题训练入口、草稿衔接和批改费用确认已实现。真实模型批改和实际打印未验收。原型：`docs/requests/class-assembly-prototype-20261002.html`（合成数据，浏览器直接打开），截图：`docs/requests/assets/class-assembly-prototype-20261002.png`。
- 实施前先读：`AGENTS.md`、`ARCHITECTURE.md`、`CONTEXT.md`、`docs/product/KNOWLEDGE_AND_TRAINING.md`（“手动选题与学情组卷助手”一节）、`docs/security/SECURITY.md`、`docs/testing/README.md`。

## 1. 用户已确认的决定

1. 增加“快速起草”：按出卷设置的题数，为还没配题的失分题各配 1 道最合适的题，之后教师可以逐题替换。这条规则推翻现行产品规则里“助手不生成自动初稿”一句。
2. 班级组卷读取考试的逐题数据：本班得分率、关联的题库原题、错因 7 大类人数。只读，不改考试的分数、排名、报告和教师最终分。
3. 班级卷可以进入训练闭环（审核题目 → 打印试卷 → 回收批改）。手动选题只用于**全班级别**的训练卷：所选班级的全部学生做同一套卷。个人卷和小组卷仍由个性化训练自动选题，本次不为它们增加手动选题。
   - 费用：回收批改会调用模型、产生费用；生成训练卷和打印不产生费用（以用户说明为准）。
4. 用途（讲义 / 训练卷）和选题规则放在右侧同一张“出卷设置”卡里。规则有默认值，用户可以修改；进不进回收批改，由用户在“用途”里选。
5. 可以多选班级，看合并后的整体结果；依据考试可以“全选”。

## 2. 现状（改造起点）

- 页面：`frontend/src/views/QuestionAssemblyView.vue`，两个页签：“试卷篮与导出”（`AssemblyEditorWorkspace.vue`）和“学情组卷助手”（`components/question-assembly/AssemblyAssistantPanel.vue`，状态在 `stores/assembly-assistant.ts`）。
- 助手接口：`POST /api/question-assembly/assistant/candidates`（`backend/api/routers/assembly.py` 的 `compute_assistant_candidates`）。它只接收一个 `class_id`，内部已经组装 `scope={"mode":"class","class_ids":[class_id]}`。考试范围固定为 `exam_scope={"mode":"semester","session_ids":[]}`，也就是本学期全部考试，不能指定具体考试。
- 规则：试卷草稿上只有一个布尔值 `practice_rules`（`backend/api/schemas/assembly.py`），校验由 `PersonalizedRecommendationModule.validate_paper_questions` 完成（`question_bank/recommendation/personalized.py`）。这个函数**写死了**难度 1–8、解答题 ≤ 2、同技能 ≤ 1。保存草稿、提交导出（`assembly.py`）和导出任务（`backend/jobs/assembly_export.py`）都会调用它。
- 个性化训练已有同名可调规则：`RecommendationRulesRequest`（`backend/api/schemas/training.py`），包括 `purpose`（training/handout）、`question_count`（训练卷 8–12）、`max_questions_per_skill`、`max_written_questions`、`recent_activity_count`、`difficulty_max`（1–10）。前端面板是 `components/knowledge-training/PaperSettingsPanel.vue`。
- 考试逐题数据已经存在：考试模块的班级分析（`backend/class_analysis.py`，前端类型见 `frontend/src/api/class-analysis.ts` 的 `ClassAnalysisQuestion`）每题都有 `class_rate`、`bank_question_id`、`cause_category_counts`（7 大类去重人数）。本机真实数据里，3 场考试的全部题目都已关联题库，错因也都已整理。
- 发现但不在本次范围：9 班“求直角边长”（14 人需关注）的候选题，排在前面的是“同小节补充、只适合 3 人、暂无难度依据”的题，候选排序值得另开任务排查。

## 4. 页面规格（以原型为准）

### 4.1 顶部依据栏

- **班级**：可多选的标签，最前面一个“全选”，至少保留一个。多选时显示“合计 N 人”。
- **依据考试**：只显示所选班级参加过的本学期考试（跟随侧栏的教学学期）。最前面一个“全选”，至少保留一场；默认选最近两场。多班时，只有部分班参加的考试标“仅10班”。切换班级后，已选但不再可见的考试自动取消，至少留一场。
- “叠加训练掌握情况”勾选框：只影响“按技能”视图的掌握度口径说明，考试题视图不受影响。
- 换班级或考试时**保留试卷**，提示“试卷保留；覆盖情况按新依据重算”。

### 4.2 左栏“要补的点”

- 两个视图：**按考试题**（默认）和**按技能**。
- **按考试题**：
  - 列出所选考试里得分率低于阈值的题。阈值可选 70%（默认）、80%、60%、全部；排序可选“失分最多优先”（默认）或“按考试和题号”。
  - 每行显示：考试简称 · 题号（小问写成“14(8)”）、题型、得分率和进度条、人数最多的两类错因、技能简称。
  - 状态标记：配上题后显示“已配 N 题”；两道题共享技能、且这个技能已配题时，显示“与 X 同技能，一起覆盖”；没关联题库的题显示“未关联题库 · 仅按技能配题”；错因没整理的显示“错因未整理”。
  - 多班时，每行再加一行各班得分率，比如“9班 43 · 10班 38”；只有部分班参加的写“仅10班参加”。
- **按技能**：按章、节分组，默认只显示需关注人数大于 0 的项，可以展开全部。口径沿用现有助手：需关注人数为“还不稳”和“明显薄弱”之和，需关注为 0 的项标“可搭配巩固”。
- “快速起草”按钮放在栏头，见 4.5。
- 保留 W / S 键切换。

### 4.3 中栏“配题”

- 选中考试题时，上方显示**原题块**：
  - 表头：考试 · 题号 · 题型 · 分值 · 本班（多班时写“合计”）得分率；多班时再加一行各班明细，比如“9班 43%（47人） · 10班 38%（43人）”。
  - 题干默认收起两行，可以展开。
  - 错因 7 大类的堆叠条和图例，类别顺序固定：概念理解、计算与化简、审题与条件、方法与思路、过程与依据、书写与规范、未作答。
  - 一句规则化提示：最多的错因是未作答时，提示“可能偏难或时间不够，建议配更基础的题”；是计算与化简时，提示“适合配同类型计算变式”；其他情况提示“以「X」为主，建议配同技能变式”。这句话由固定规则生成，不调用模型。
  - 技能标签。
  - 原题处理：“近期原题排除次数”大于 0 时，显示“本班最近 N 次已做过原题，按出卷设置不重复出”；等于 0 时，显示“加入原题”按钮，原题和其他题一样计入规则。没关联题库的题不能加原题。
- 下方是**候选题**：
  - 难度筛选：更基础 / 相当 / 更难，相对原题难度判断，阈值 ±0.8 级。原题难度取题库里关联题目的难度，没有难度时隐藏这组筛选。另有题型筛选。
  - 候选卡显示：题型、难度（附相对原题的关系）、适合人数 / 补弱 / 巩固 / 新练习（多班时按合并后的学生计算）、匹配等级标签、高度相似提示。按钮为“加入 / 已加入”。
  - 加入被规则拦下时，题卡上直接说明原因。同技能达到上限时提供“替换”按钮。
- 选中技能时不显示原题块，候选卡只标绝对难度。

### 4.4 右栏“这张卷”（随页面固定）

- 标题：自动生成，单班为“八年级9班 第4周补偿练习”，多班为“八年级9、10班 补偿练习”。用户改过标题后不再自动覆盖。标题写入草稿现有的 `title` 字段。
- 摘要：题数、预计时长（选择 2 分钟、填空 3 分钟、解答 8 分钟，仅作提示）、用途标签。
- 题型构成：解答题显示“2/2 已满”或“3/2 超出”。另有难度分布、“覆盖失分题 X/Y”。
- 卷面题目列表：每题显示来源，比如“补 第4周·14(8)”或“原题 第4周·14(8)”，可以“换一题”（跳回来源题）或“移出”。超出设置的题标红，显示“超出：解答题最多 1 道”。
- **出卷设置卡**（右下，靠近主按钮）：
  - 收起时显示一行摘要，展开后可编辑以下字段，字段名、范围、默认值对齐个性化训练：

    | 字段 | 默认 | 范围 |
    |---|---|---|
    | 用途 | 讲义 · 只打印 | 训练卷 · 回收批改 / 讲义 · 只打印 |
    | 每卷题数 | 10 | 训练卷 8–12；讲义 ≥ 1 |
    | 难度上限 | 8 | 1–10 |
    | 同一技能最多 | 1 | ≥ 1 且 ≤ 题数 |
    | 解答题最多 | 2 | ≥ 0 且 ≤ 题数 |
    | 近期原题排除次数 | 3 | ≥ 0，0 = 不排除 |

  - 与默认值不同时显示“已改动”，提供“恢复默认”。
  - 设置随试卷草稿保存（见 5.3），说明文字为“改动只对这张卷生效”。
  - 卡内保留实时检查清单：题数和目标、同技能、解答题、难度、近期原题与相似题。
- **改小限制不自动移出已选题**，只标红并禁用主按钮，按钮下写原因。
- 主按钮：
  - 讲义：“去整理与导出 →”，进入现有编辑导出页。提示“讲义不回收、不更新掌握度”。
  - 训练卷：“生成训练卷 →”，要求 8–12 题且没有超出项。提示“全班同一套卷，进入训练流程：审核题目 → 打印试卷 → 回收批改，批改结果更新这些学生的掌握度，考试分数不受影响。回收批改会调用模型、产生费用，批改前在训练页确认。”

### 4.5 快速起草

- 按当前排序遍历没配题的失分题，每题取通过当前出卷设置、适合人数最多的候选，补到“每卷题数”为止。完成后报告“已起草 X 题，试卷共 N / 目标 题”，以及跳过原因的统计（同技能已配、解答题已满、难度超限、相似、无可配题）。
- 起草结果通过试卷篮现有的保存流程写入，一次批量保存，沿用修订冲突保护。被拒绝时保留原草稿。
- 不调用模型，不产生费用。

## 5. 后端改动

### 5.1 候选接口支持多班和指定考试

`AssemblyAssistantRequest` 增加两个字段：

- `class_ids: list[str]`（1–N 个）；旧的 `class_id` 作为兼容输入，转成单元素列表。
- `session_ids: list[int]`，为空时表示本学期全部考试，保持现有行为。

在 `compute_assistant_candidates` 中：

- `scope.class_ids` 直接使用 `class_ids`。
- 考试范围在指定考试时改用已有的 `exam_scope` 模式。实施方需要确认 `manual` 和 `cross_exam` 哪个语义是“仅这些考试”（参考 `integration/diagnosis_profile_service.py` 第 257–282 行附近，以及个性化训练前端的用法），**不新增模式**。
- 结果缓存键、`record_request` 预热参数、前端 `cacheSignature` 都要加入 `class_ids` 和 `session_ids`。
- 合并多个班级时，人数统计（适合人数、补弱等）按合并后的学生集合计算，不按班级相加后再去重估算。

### 5.2 新增只读接口：考试逐题视图

`POST /api/question-assembly/assistant/exam-questions`

- 请求：`{class_ids, curriculum_volume_id}`。
- 返回：
  - `exams`：所选班级本学期参加过的考试，每项含 `session_id`、标题、日期、参加班级、合并人数和均分。
  - 每场考试的逐题列表，每题含：题号（含小问）、题型、分值、合并得分率、各班得分率和人数、错因 7 大类人数（没整理时为 `null`）、`bank_question_id`（可为 null）、题库题难度、关联技能的稳定标识。
- 数据来源：优先用 `DiagnosisProfileService` 已加载的考试证据和 `_error_cause_index`。这一层已经在“知识与训练”的只读路径上，跨模块边界已经存在。不要从组卷模块直接调用考试模块的班级分析接口或写入任何考试数据。如果确实必须读 `backend/class_analysis.py`，按 `AGENTS.md` 先说明为什么不能在模块内完成、影响哪些模块，并在 `ARCHITECTURE.md` 写明这条只读依赖。
- 得分率口径：沿用班级分析，教师最终分优先；未评分、失败或结果未知的不计入。多班合并按有成绩人数加权。
- 错因只用已整理的结果；部分题整理失败时，按题标“错因未整理”，不把缺失当作 0。
- 不调用模型，不写数据库。

### 5.3 出卷设置写入草稿，校验参数化

- 草稿字段 `practice_rules: bool` 扩展为可选对象 `practice_rules: {purpose, question_count, difficulty_max, max_questions_per_skill, max_written_questions, recent_activity_count} | null`。
  - 兼容输入：旧的 `true` 读成默认对象，`false` 或缺失读成 `null`（普通手工组卷不受限制）。已完成的历史导出记录不追溯改变。
  - 前端 `decodeAssemblyDraft`（`frontend/src/api/assembly.ts`）要同步放行新结构。
- `validate_paper_questions(question_ids, rules)`：去掉写死的 8 / 2 / 1，改读参数。默认参数下的行为和报错文案保持不变，保证现有测试通过。高度相似和重复题限制保持不变。
- 近期原题排除：`recommendations.current_exam_question_ids` 背后的 `_recent_question_ids` 要能接收 `recent_activity_count`（0 表示不排除），候选接口请求同步增加这个字段。实施方先确认默认的 3 是在哪里定义的，再参数化，不改变默认结果。
- 保存草稿、提交导出、导出任务三处都按草稿里的设置校验。
- 改小限制后，**保存草稿时**不能因为已有超出项而拒绝保存设置本身（否则用户没法先改设置再调整题目）。建议做法：允许保存，导出和生成训练卷时拦截；接口返回逐题超出信息供前端标红。

### 5.4 快速起草接口

`POST /api/question-assembly/assistant/quick-draft`

- 请求：`class_ids`、`session_ids`、`curriculum_volume_id`、阈值、排序、当前试卷题目、出卷设置。
- 返回：建议加入的 `question_id` 列表（附来源考试题），以及跳过统计。**只返回建议，不写入试卷篮**（保持“查询不写试卷篮”的规则），由前端调用试卷篮的保存流程写入。
- 内部对每道失分题复用 `shortlist_candidates` 的评价与排序，规则检查复用 5.3 的参数化校验。

## 6. 训练卷衔接

- 适用范围：只有**全班级别**的训练卷用教师手动选的题。学生范围固定为所选班级的全部学生（`scope.mode="class"`、`class_ids`），不支持按成员挑选、拆组或一人一卷。个人卷和小组卷继续使用个性化训练现有的自动选题，入口和逻辑都不改。
- 现有的 `PersonalizedRecommendationCreateRequest`（`paper_mode="shared"`）会自动选题，**不能接收教师指定的固定题目列表**。需要新增一个仅用于全班卷的入口，比如 `POST /api/training/personalized-drafts/from-assembly`：
  - 请求：`request_token`（幂等）、`class_ids`、试卷草稿修订号 `draft_revision`、出卷设置。服务端从这个修订号读取题目和题序，不接收前端传来的题目列表，避免和草稿不一致。
  - 生成一份 `paper_mode=shared`、学生为这些班全部学生、全部题目锁定的草稿，`config` 里记录来源“班级组卷 · 全班”、依据考试和试卷草稿修订号（作为快照）。
  - 审核步骤按公共卷的现有约束整卷编辑（统一题目与题序），不提供按学生换题。
  - 之后完全走现有流程：审核题目 → 打印试卷 → 回收批改 → 训练证据与掌握度。
- 费用：回收批改会调用模型、产生费用；生成训练卷和打印不产生费用。组卷页只做文字提示，不新增扣费或模型调用；批改前的费用确认沿用训练页现有流程（实施方核对确实存在这个确认步骤，如果没有，需要补上并取得用户同意）。测试一律用合成数据和模拟模型，不调用真实模型。
- 前端点“生成训练卷 →”后，调用这个入口，再跳到个性化训练页（`/training?mode=paper`）打开这份草稿。组卷页第二个页签在训练卷用途下显示“审核与回收”，只做入口和状态提示，**不复制训练页的工作区**。
- 必须保持：
  - 训练判定点不带考试分值，结果按“达成点数 / 总判定点数”表达。
  - 考试分数、排名、报告、教师最终分不变。
  - 模块数据库之间没有原子事务，靠 `request_token` 幂等、草稿修订号快照和来源记录对账。
  - 同一试卷修订号重复提交时，返回已有的训练草稿。

## 7. 前端状态要点

- `assembly-assistant.ts` 的筛选状态：`class_id` 改为 `class_ids`，增加 `session_ids`、`threshold`、`sort`、`view`（exam/skill）、当前选中项。本机只记住班级和考试的选择，沿用现有 localStorage 键，并升级版本号。
- 换班级或考试时取消旧请求，保留试卷，清空候选缓存（沿用 `changeScope` 的做法）。
- 出卷设置是草稿的一部分，读写走 `stores/assembly.ts`，不放在助手的 store 里。
- 规则提示文案统一从一个地方生成，左栏、题卡、检查清单和题库页头试卷篮抽屉（`QuestionBasketDrawer.vue` 现在写死了“同技能最多 1 道、解答题最多 2 道”）都读同一份设置。

## 8. 保持不变

- 助手和起草都不调用模型。
- 候选评价和个人卷、小组卷共用同一入口。
- 试卷篮的修订冲突保护和拒绝添加时保留原草稿的行为不变。
- 普通手工组卷（`practice_rules` 为空）不受规则限制。
- 已导出记录不变，来源“AI 组卷”的兼容标注保留。`mode=ai`、`mode=assistant`、`skill=` 链接继续可用：`skill` 只在当前结果里预选，不改班级和范围。
- 真实 `user_data` 不暂存、不提交，也不写入文档和日志。

## 9. 建议分阶段

1. **P1 依据与布局**：5.1、5.2，前端顶部依据栏、左栏两种视图、中栏原题块和候选、右栏卷面（先保留现有固定规则）。
