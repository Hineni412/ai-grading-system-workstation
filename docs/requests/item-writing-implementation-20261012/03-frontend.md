# 03 前端：教研提升第二页签“命题训练”

页面结构与交互以原型 `docs/requests/item-writing-prototype-20261012/index.html` 为准；样式按 `docs/ui/STYLE.md`，用现有设计组件（`PageHeader`、`StatePanel`、`FeedbackBanner`、`AppButton`、`AppDialog`、`AppField`、`StepProgress`、`StatusBadge`、`useConfirm`），不引入图表库，雷达图手写 SVG（参考试卷评价的 `PaperScatter.vue` 写法）。

## 1. 页签与路由

- `frontend/src/views/TeachingResearchView.vue` 页头 `#navigation` 插槽从单个“试卷评价”标签改为两个页签：试卷评价、命题训练。当前页签记在地址参数 `tab`（`paper` 默认、`authoring`），切换时保留另一页签的地址参数（试卷评价的 `session`）。
- 把现有试卷评价内容整体移到 `components/paper-review/PaperReviewTab.vue`，只做搬移，不改其逻辑和数据请求；命题训练放 `components/authoring/AuthoringTab.vue`。两者都按需加载，切换页签不重新请求另一页签的数据。
- `navigation.ts` 中教研提升的 `description` 改为“回看已批改试卷，练习命题”。

## 3. 三屏

### 3.1 选材料

- 材料列表即本机情境库，顶部状态页签带数量：可用、待核对、已停用（不适用的抽取结果在已停用下，显示停用原因）。筛选：情境类别、章。
- 材料卡片：类型与情境类别标签、标题、情境描述、来源小节、“需配图”徽章、`local_issues` 显示为“待核对：…”、“来源 N 题，原题评价后显示”、修订号（r2 起显示）。操作按状态：待核对 → 标为可用 / 编辑 / 停用；可用 → 开始命题（已有作品时“继续命题”）/ 编辑 / 停用；已停用 → 改为可用。编辑带修订号保存。
- “开始命题”先弹“命题要求”：范围（默认来源小节所在章）、题型（默认解答题）、分值（默认 10）、小问（默认 2–3 问）、情境要求（默认材料情境类别）、限时（默认 60 分钟），均可改；系统自带材料用它自带的要求作默认值。确认后写入 `task_card_json.requirement` 与材料快照；材料之后被编辑，已开作品仍按快照显示。
- “录入材料”：弹窗填写类型、标题、正文、情境类别、小节。
- 同屏下方“我的作品”（成长档案）：每个作品一行，显示材料标题、状态（作答中 x/8 步、已评价第 N 版 xx 分、已转入题库及题号）、各版本总分、“继续”。
- “从题库抽取情境”按钮放在材料列表上方工具条，打开弹窗：
  1. 学期：教材册下拉，默认取页面当前教学学期（复用 `stores/curriculum-scope`），只列有候选题的册。
  2. 章：读取 `extraction-scope`，每章一行复选框，行内显示“符合 X 道 · 已抽过 Y 道 · 待抽 Z 道 · 约 N 次请求”；待抽为 0 的章禁用。提供“全选有待抽题的章”。
  3. 本次上限：数字输入，默认等于所选章待抽总数，可改小。
  4. 底部实时显示预估（调用 `extraction-preview`）：“本次抽取 Z 道，共 B 批，预计 N 次模型请求；题干与选项会发送给模型，答案、解析与配图不发送。”下方折叠“筛选规则”，用通俗话列出 04 第 1.1 节的五条规则。
  5. “确认抽取”：再弹一次确认，文案同第 4 项，确认后提交任务，交给任务中心跟踪；弹窗关闭。409 时提示“题库已变化，请重新查看”并刷新预估。
- 抽取任务进行中，按钮置灰显示“抽取中”。
- 任务结束后刷新材料列表并切到“待核对”页签，顶部结果卡列出新建的待核对材料数、不适用题数；有批次失败时写明“第 b 批失败，后续 k 批未执行；已完成的批次已保存，未完成的题下次仍会出现在待抽中”。

### 3.2 命题作答

- 左栏材料面板随滚动保持可见：情境句子、表格或母题、命题要求、计时（已用 X / 限时 60 分钟）。计时从作品 `started_at` 算起，刷新后继续。
- 中栏八步表单，字段与输入方式照原型；单选与多选的选项从 `GET /rubric` 读取。
- 右栏进度条：八步完成状态（可点击跳转）、本机自检列表、“去评价”。
- 自动保存：输入停止 2 秒后、切换步骤时、离开页面前保存草稿；页头显示“已保存 · 时间”或“保存中”。409 冲突时保留本地草稿并提示“作品在别处更新过，请刷新后再改”，不自动覆盖。
- 第 5 步“上传图片或文档识别”：上传后调用识别接口，结果填入题干输入框，`uncertain` 片段在预览中高亮，横幅写“识别结果待核对”；识别不可用时提示手动录入。配图上传后在题干下方预览。
- 第 8 步“根据前面各项生成说明草稿”在本地拼字符串，不调用模型，模板照原型 `render-form2.js`。

### 3.3 评价

- 自评（可选）：九个维度各四个水平按钮，显示水平描述；选择随草稿保存在 `self_eval`。
- “AI 评价”：先请求评价预估；有阻断原因时只显示原因。否则弹窗：“预计 N 次模型请求：题目分析、独立解题、量表评分。确认后发送；失败或结果不确定时不自动重发。”确认后提交任务，页面显示进度，结束后读取评价记录。
- 结果：
  - 总分（标明“满分 100，维度得分＝权重×水平÷4”）。
  - 九维雷达：AI 水平实线，自评虚线。
  - 独立解题表：小问、模型解答、与你的答案对照，“不一致”“存在多解风险”红色。
  - 声明与分析对照表：知识点、情境类别、预估难度、各问 SOLO，不一致的行标出。
  - 九张维度卡：AI 水平及描述、自评水平（相差 2 级及以上提示）、依据原文（`quote_found=false` 时写“依据未在作品中找到”）、建议、得分、“去修改”（跳回该维度对应步骤，见 `rubric.py` 的 `step`）。
  - `cap_violations` 非空时，顶部提示“评价与规则不一致，建议重新评价”。
  - 评价完成后显示“来源原题”：情境材料显示来源题题干，自带或录入材料写“无来源原题”。
  - 失败或结果不确定时显示原因与已完成的步骤，提示到“调用记录”核对；“重新评价”需再次确认费用。
- 版本条：列出各版本及其评价总分；修改已评价版本会生成新版本，页面写明这一点。
- “转入题库”：只对有成功评价的版本显示；二次确认文案写明“将写入题库试卷《命题训练作品》，之后会出现在题库与组卷中”。

## 4. 不做

- 不在前端保存量表或选项副本。
- 不在本页显示模型原始返回；需要时从设置页“调用记录”查看。
- 不做评委模式、多人档案、语音输入。

## 5. 验收要点（页面）

- 正式应用 8035 打开教研提升，两个页签切换正常；试卷评价页内容和请求与改动前一致。
- 1440、1280、1024 三种宽度截图：选材料、作答（第 1、5、6 步）、评价结果。
- 刷新后作品内容、计时、当前步骤保持；两个浏览器标签同时编辑同一作品时，后保存的一方看到 409 提示且草稿不丢。
- 浏览器控制台没有错误。
