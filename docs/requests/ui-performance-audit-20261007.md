### U03 预检的合法计数字段被拒绝

复现方式是打开已有已批改考试的考试批改页。页面显示“服务器返回了无法识别的数据”。预检区域还会显示重新运行预检的空状态。本轮没有点击重新预检。

工作区和预检 GET 都返回 HTTP 200，均通过当前后端响应模型校验。预检实际带有整数 `appended_file_count`。前端解码允许该字段，但解码之前的通用检查会拒绝包含独立 `file` 词段的键，仅特许 `file_count` 等少数名称。即使新增数量为 0，也会失败。

证据见 [预检解码](../../frontend/src/api/scan-grading.ts)、[通用键名检查](../../frontend/src/api/validation.ts)、[后端预检字段](../../backend/api/schemas/scan.py)。直接调用实际 `fetchPreflight` 的内存合成输入，不带新字段时成功，加入该字段后产生与页面相同的错误。

原 API 测试的模拟预检没有新增字段。页面测试虽有字段，但直接模拟 store，绕过了解码。现已特许这个精确计数字段，并扩展既有 API 测试；真正路径字段仍被拒绝。

### U01 与 U02 定位没有预留固定区域

U01 复现方式是从本场赋分切到考试草稿。名称输入框顶边落在页面 `y=0`，56 像素高的固定页头盖住该区域。滚回顶部后可以看到原内容，数据没有丢失。

U02 复现方式是在本场赋分左侧点击一个中间小问。在 1366×768 下，目标标题顶边约为 `y=13`。页头占 0 至 56 像素，评分工具栏占 56 至 151 像素。标题和首行评分内容落在固定区域后面，左侧高亮还会转到后一个可见小问。最后一个题组因滚动到页尾而有不同表现，不能据此否定中间题组的遮挡。

阶段和题号定位都使用 `scrollIntoView` 的顶边对齐，缺少固定区域的滚动留白。证据见 [阶段定位](../../frontend/src/views/SessionConfigView.vue)、[题号定位](../../frontend/src/components/config/RubricEditorTable.vue)、[页头](../../frontend/src/components/design-system/PageHeader.vue)、[评分样式](../../frontend/src/styles/session-config.css)。上传与分析锚点共用阶段定位，具体遮挡未逐一测量。

建议在现有滚动容器或锚点上预留实际固定区域高度。修复后复查草稿、上传、分析、评分小问及页尾，不新增页面或组件。

### P01 工作台重新准备完整资料

一次隔离进程先暖读，再分析核心读取。带分析开销的总时间约 1041 毫秒，个人报告摘要约占 58%，整场复核资料约占 33%。分母是这次隔离核心读取，不是现场页面等待。

首次检查时，个人报告摘要补充原题、图片和公式，并整理逐生报告指纹。复核摘要重新装配整场作答条目。最终摘要只有约 3.4 KB。证据见 [工作台服务](../../backend/workbench/service.py)、[报告状态](../../backend/personal_reports.py)、[复核汇总](../../backend/review/service.py)。该证据支持复用状态输入与摘要，不能作为修复后的速度预测。

### P02 章节响应与未命中计算

默认 10 题补充样本每次返回 25,393,438 字节，约 24.22 MiB。学生诊断字段占约 93.9%，分组字段仅约 1.5%。43 条学生记录中包含 19,740 条程序 `weak_points` 记录。这些记录包含不同诊断状态，不能全部称为明显薄弱项。其主要体积不是图片或证据正文。

响应构造先序列化完整学生诊断，再附加章节分组。章节参数没有把基础响应裁到当前章节。证据见 [诊断响应](../../backend/api/routers/training.py) 和 [训练页面](../../frontend/src/views/TrainingRecommendationsView.vue)。建议让现有章节读取返回页面真正消费的摘要，逐生详情按现有证据入口读取。评分结果和诊断语义必须保持一致。

一次只读隔离复算的进程缓存初始为空，持久缓存读取 4 次、命中 0 次。题库候选快照累计约 59.6 秒，其中正文指纹调用 4503 次，Word 内容解析调用 78,582 次。累计时间有包含关系，不能相加。分析工具使该次核心读取耗时约 99 秒，这不是用户现场等待。

已核实该未命中路径的热点在候选快照和 Word XML 正文指纹。证据见 [候选快照](../../question_bank/recommendation/personalized.py)、[正文处理](../../question_bank/training_criteria/analysis.py)、[内容指纹](../../question_bank/training_criteria/versioning.py)。现场首样本的缓存状态及阶段占比没有观测，不能把 13 秒全部归给某一函数。建议调查请求内资料复用和指纹失效条件，并在同等输入下复测。

### O01 请求计时没有输出

请求中间件写 INFO，但正常启动的 `ai_grading.api` 有效日志级别为 WARNING，也没有接收器。因此源码里有计时调用，不代表当前服务已经保存计时。证据见 [中间件](../../backend/api/app.py) 与 [启动配置](../../backend/api/launcher.py)。建议沿现有日志记录路由、状态、请求编号和耗时，不加入业务正文。
