# 题库“按标签”多维筛选重设计方案

用途：记录 2026-10-08 与用户确认的题库管理“按标签”页重设计，交给实施代理使用。本文内容全部尚未实现。交互原型见 [原型网页](question-bank-tag-filter-prototype-20261008.html)：只用合成数据，不连接后端，在浏览器中直接打开即可。

本方案取代 [题库标签与新册自动题型方案](question-bank-labels-and-auto-types-plan-20261008.md) 第 3.7 节“找题”一条中“沿用现有技能、知识主题、标签切换方式”的写法；该方案的其他内容不受影响。当前可验证的产品行为仍以 [题库、组卷与个性化训练](../product/KNOWLEDGE_AND_TRAINING.md) 为准。

## 1. 已确认的决定

| 问题 | 决定 |
|---|---|
| 多维筛选的交互方式 | 左栏按维度分组勾选，每项显示实时题数；右侧顶部列出可删除的已选条件；进入页面默认显示本学期全部题 |
| 同一维度勾选多项 | 有其中任一项即算（沿用后端现有规则，后端不改这一点） |
| 知识主题与知识点 | 合并为一个“知识点”维度，按章、节分组显示；页面上不再出现“知识主题” |
| 章节范围 | 作为筛选维度之一，可同时勾选多个章或节；去掉顶部章节下拉和“整个学期 / 本章 / 本小节”按钮 |
| 退役“按技能”的范围 | 去掉本页的技能入口、题卡上的技能显示和“按班级学情挑这个技能的题”跳转；待处理页的技能维护项暂不改，后台技能数据保留 |

## 2. 现状（只读核对）

数据范围：2026-10-08 真实题库八年级上册，1334 道题。数字通过应用自身的只读接口和只读数据库连接获得，只适用于当日输入；其他任务正在刷新标签，实施时数字可能变化，需要重新核对。

### 2.1 页面问题

入口文件为 `frontend/src/components/question-bank/QuestionSkillBrowser.vue`，由 `frontend/src/views/QuestionBankView.vue` 的“按标签”页签加载。

1. **两套入口，各管一部分维度。** 左栏有 8 个维度页签（题型、能力、特殊考法、思想、方法、模型、知识点、错因），每次只能单选一个标签，切换维度时清掉已选标签。结果区的“标签筛选”弹窗可以多选，但只有能力、方法、模型、思想、特殊考法 5 个维度。
2. **已选条件看不全。** 左栏所选标签只出现在标题里；弹窗所选的才在第二行显示为可删除的小块。
3. **必须先选一个标签才显示题目。** 不选时右侧只有“在中间列选择一个标签”。
4. **章节范围有两层且互相矛盾。** 顶部下拉显示某一小节，下面的范围按钮可能是“整个学期”；选到知识点时，“本章 / 本小节”按钮不可用。
5. **长列表平铺。** 本册题型 100 个、知识点 191 个，按题数平铺在同一列。
6. **按技能在八上已不参与训练。** `question_bank/question_types.py` 的 `chapter_target_kinds` 对八上各章都返回题型目标，技能不参与八上的掌握度与推荐。底部“未挂技能 9 题”实际全部是“没有可用判定资料”的题，缺直接技能链接的是 0 题。

### 2.2 知识主题与知识点

两者读同一份数据：题目标签表中 `tag_type='knowledge_point'` 的整题知识点（由判定点关联汇总）。

| 对比项 | 按知识主题 | 按标签 → 知识点 |
|---|---|---|
| 数据接口 | `/api/question-bank/skill-index` 的 `sections[].topics` | `/api/question-bank/facets` 的 `knowledge_points` |
| 数量 | 192 个 | 191 个 |
| 相同的值 | 177 个 | 177 个 |
| 只在一边出现 | 15 个，都是整节级别（如“2 平面直角坐标系”） | 14 个，都是七年级前置知识（如“倒数”“点到直线的距离”） |
| 显示方式 | 按小节分组 | 整个学期平铺 |
| 题数口径 | 不折叠重复题（“无理数”49 题） | 折叠重复题（“无理数”47 题） |

“知识主题”不是 `CONTEXT.md` 中的词汇；它来自技能目标时代的情境匹配，八上按题型训练后不再使用。那 15 个整节级的值在新设计中由“章节”维度覆盖。

### 2.3 后端现有能力与缺口

- **组合规则已具备。** 同一维度多选在 SQL 中为 `IN`（有其一即可），不同维度各自一条 `EXISTS`（同时满足）。分面计数（facets）对每个维度只排除本维度的已选值，其他条件照常生效。实测（不折叠重复题）：题型“根式化简与四则运算”（`kp_bnu24_math_g8_upper_2_3_t15`）加方法“公式法”为 13 题；方法“坐标法”或“图象法”合计 212 题。
- **默认范围规则会改写知识点条件。** 题目列表和分面接口的 `scope_mode` 默认是 `primary`（主考小节）。在这个规则下，`_question_filter_parts` 把章、节和知识点合并成一组小节集合（`_scope_mode_selection`），再按“主考小节在集合内”匹配（以下两例均折叠重复题）：
  - 知识点“无理数”：精确匹配 47 题；`primary` 下返回该小节全部主考题 83 题。
  - 同时选“第二章第 2 节”和第 1 节的知识点“无理数”：`primary` 下是两节的并集 168 题；`any`（按标签精确匹配）下是 1 题。
  - 现有“按知识主题”列表用的就是默认 `primary`，所以列表出的题和左栏写的题数对不上。新设计一并消除这个问题。
- **主考小节互不重叠。** `question_scope_summary.primary_section_id` 每题一个值。八上 1328 道题的主考在本册小节，其余少数在其他册；没有题的主考落在“章本身”。第二章按主考统计为 334 题（不折叠重复题），等于三个小节 85 + 92 + 157 之和。
- **章节分面口径不同。** 现有 `curriculum_sections`、`curriculum_chapters` 分面按 `curriculum_section` 标签统计（一道题可涉及多个小节），取值是目录编号（如 `bnu24-math-g8-upper-c02-s01`），还包含其他册的小节；它不是主考口径，不能直接作为新章节维度的计数。
- **题型没有小节字段。** `skill-index` 的 `types[]` 只有 `value`、`label`、`count` 等；题型稳定标识目前等于“小节知识标识 + `_tNN`”（如 `kp_bnu24_math_g8_upper_2_3_t15`），但不应依赖字符串格式。
- **题卡需要的字段已存在。** 列表请求带 `include_skills=true` 时，每题返回 `labels.primary_type`、`labels.secondary_types`、`labels.knowledge_points`。

## 3. 目标设计

### 3.1 布局

页头与页签不变（章节考情、按标签、按试卷、待处理）。“按标签”内容区分两栏：

```text
┌ 筛选 · 已选 3 项   清空 ┐┌ 筛选结果  共 14 题 · 已折叠 2 道重复题 ───────────────┐
│ 章节        已选 1   ▾ ││ [章节：第二章 实数 ×] [题型：… ×] [题型：… ×] 清空条件 │
│  ▸ ☑ 第二章 实数   334 ││ 搜题干 | 全部 选择 填空 解答 | 难度 | 来源 | 教学进度 │
│  ▸ ☐ 第三章 …   （灰）0 ││ 折叠重复题 | 更多                                     │
│ 题型        已选 2   ▾ │├──────────────────────────────────────────────────────┤
│  [搜题型]              ││ 题卡：题干 / 题型 · 知识点 / 判定点 N / 操作           │
│  第二章 · 1 认识实数    ││ 题卡 …                                               │
│  ☐ 辨识无理数       44 ││                                                      │
│ 知识点 / 能力 / 思想 /  ││                                                      │
│ 方法 / 模型 / 特殊考法 /││                                                      │
│ 错因（可折叠）          ││                                                      │
└────────────────────────┘└──────────────────────────────────────────────────────┘
```

展开题卡阅读时，左栏沿用现有的“收窄为细栏”行为，细栏按钮显示“筛选 · N”。

### 3.2 筛选维度

| 维度 | 选项来源 | 分组显示 | 请求参数 | 匹配规则 |
|---|---|---|---|---|
| 章节 | `skill-index` 的 `chapters[].sections[]`（知识标识，如 `kp_bnu24_math_g8_upper_2_1`） | 章 → 节树，章可展开 | `curriculum_sections`（章或节的知识标识），`scope_mode=primary` | 题目的主考小节落在所选章节内；与章节考情“主考题”同口径 |
| 题型 | 分面 `task_types`；名称取 `skill-index` 的 `types[].label`，去掉“题型·”前缀 | 按 `types[].section_id`（第 4.3 节新增）归到章 → 节 | `type_keys` | 主题型或次题型命中（现有规则） |
| 知识点 | 分面 `knowledge_points`（本册细项，含往届前置知识） | 按值的路径段归到章 → 节；非本册的值归入“前置知识（往届教材）” | `knowledge_points` | 整题知识点精确命中（第 4.1 节修改后） |
| 能力、思想、方法、模型、特殊考法 | 对应分面 | 不分组，按题数从多到少 | `abilities`、`thoughts`、`methods`、`models`、`special_types` | 现有规则；思想沿用“思想或方法标签中出现”的兼容匹配 |
| 错因 | 分面 `error_pattern_categories` | 不分组 | `error_pattern_categories` | 已确认典型错法的错误大类；组内提示一句“按已确认典型错法的错误大类统计” |

通用规则：

- 同一维度多选为“有其一即可”，不同维度之间为“同时满足”。
- 每项右侧的数字是“在其他维度已选条件下带这一项的题数”，与分面接口现有口径一致，并随折叠重复题、搜题干、作答形式、难度、来源、教学进度一起变化。
- 章节项始终全部列出，题数为 0 时灰显；其他维度只列题数大于 0 的项和已选项（已选项即使为 0 也保留，便于取消）。
- 选中一章等于选中该章全部小节，请求只发章的标识；一章的小节全部勾上时合并为章；在已选的章下取消一节时，改为发送其余小节。
- 已选章节时，题型和知识点组只列所选章节内的分组，并提示“只列所选章节内的项”；在组内搜索时不受此限制。未选章节时默认显示前 4 个分组，其余用“显示其余 N 组”展开。
- 章的数字等于其小节数字之和（主考小节互不重叠）。主考小节不在本册或尚未确定的题，在章节组底部只显示一句“另有 N 题的主考小节不在本册”，不可勾选。
- 默认展开“章节”和“题型”两组，其余折叠；组标题显示“已选 N”。

### 3.3 结果区

- 标题：未选条件时为“本学期全部题目”，有条件时为“筛选结果”；后接“共 N 题”，折叠重复题时追加“已折叠 X 道重复题”（沿用现有计数）。
- 已选条件行：按维度顺序列出全部条件，形如“题型：根式化简与四则运算 ×”，章节条件写章名或“第二章 · 1 认识实数”；末尾“清空条件”。没有条件时显示一句“未选条件，显示本学期全部题目”。
- 筛选行保持现有内容：搜题干、全部/选择/填空/解答、难度、来源、折叠重复题、教学进度、更多（标签完整度、判定点待审核、多选题、排序、选择本页）。删除“标签筛选”弹窗及其下方的已选小块行。
- 只选了一个题型时，在条件行下方保留现有的“常涉及的知识点（按主题型题目统计）”折叠说明。
- 没有结果时，用 `StatePanel`（compact）显示“没有同时满足全部条件的题”，操作按钮为“清空条件”。
- 分面读取失败时，左栏显示“标签计数暂时无法读取”和重试，题目列表照常显示。

### 3.4 题卡与标注区

本节改动作用于共用组件，按试卷、章节考情中的题卡同样生效。

- 收起状态：删除“技能：……”整行和黄色“未挂技能”。标签行改为：作答形式 · 难度 · 主题型小块（`labels.primary_type`）· 次题型小块 · 最多 2 个知识点小块（`labels.knowledge_points`）及“+N”。没有 `labels` 时沿用现有的整题知识点标签，但不显示题型标识和 `sk_` 值。
- 底部统计由“判定点 N · 技能 N”改为“判定点 N”。
- 展开的标注区：判定点旁删除直接技能小块和“未挂技能”字样，保留知识点与前置知识；“全部质检通过”的条件去掉“每个判定点都有直接技能”这一项，其余条件不变。
- 判定点编辑界面（`TrainingCriterionReview`）中的技能信息不在本次范围。

### 3.5 删除与保留

删除：左栏“按技能 / 按知识主题 / 按标签”切换、维度页签、“整个学期 / 本章 / 本小节”按钮、顶部章节下拉、技能排序下拉（含掌握度排序及其后台读取）、技能定义说明、“⚠ 未挂技能”入口（底部按钮和细栏按钮）、“AI 补挂技能”按钮、“按班级学情挑这个技能的题 →”跳转。

保留：待处理页的技能缺口、技能候选、题量少技能与“缺技能关联”筛选；“AI 补齐”面板中的技能缺口类型；相似题理由中的“同技能”；考频与章节考情对旧技能标准的兼容；`skill-index` 接口中的技能与知识主题字段（待处理页和旧链接换算仍在使用）；组卷工作台自身的 `?skill=` 入口。待处理页“题量少技能”的“查看题目 →”跳转到按标签页时，带旧链接技能条件（见第 5 节）。

## 4. 后端修改

`question_bank/services/question_read_service.py` 是题库读取的共用热点文件，修改前查看未提交改动，与并行任务错开；四处修改都不改变数据库内容，不需要迁移。

### 4.1 知识点改为始终精确匹配

- 位置：`_question_filter_parts` 与 `_scope_mode_selection`。
- 修改：调用 `_scope_mode_selection` 时不再传入知识点，由它只处理 `exam_scopes` 与 `curriculum_sections`；知识点条件无论 `scope_mode` 取何值，都作为 `knowledge_point` 标签的精确匹配加入（即把 `("knowledge_point", expanded_knowledge)` 移出 `scope_clause is None` 分支）。`requested_knowledge and not expanded_knowledge` 时仍返回空结果。
- 已知调用方：本页（新设计依赖此行为）、`integration/training_prewarm.py`（第 4.4 节同步修改）。实施时用 `knowledge_points=`、`knowledgePoints`、`knowledge_point=` 再搜一遍前后端与测试，确认没有依赖“知识点换算成小节”的其他调用。
- 效果：章节维度按主考小节、知识点维度按精确标签，两者按“同时满足”组合。

### 4.2 新增主考小节分面

- 位置：`_list_facets`。
- 修改：新增分面 `primary_sections`，来源为 `facet_source(curriculum_sections=(), exam_scopes=())`（排除章节维度自身），在同一筛选结果上按 `question_scope_summary.primary_section_id` 分组计题数；没有摘要行的题计入值为空字符串的一项。计数沿用其他分面的折叠重复题处理。
- 接口：`backend/api/routers/question_bank.py` 的 `QuestionFacetsResponse` 增加该字段；前端 `frontend/src/api/question-bank.ts` 的 `QuestionBankFacets` 类型与解码同步增加。
- 现有 `curriculum_sections`、`curriculum_chapters` 分面保持不变，其他页面可能在用。

### 4.3 题型返回所属小节

- 位置：`question_bank/services/question_skill_index.py` 的 `skill_index`。
- 修改：`types[]` 每项增加 `section_id`：取 `skill_anchor_ids(node, volume)` 中第一个小节级锚点；只有章级锚点时取章标识。前端按此分组，不解析稳定标识字符串。前端解码中该字段可缺省，缺省时归入“未归小节”。

### 4.4 预热改为新的首屏

- 位置：`integration/training_prewarm.py` 约第 700–720 行，目前预热“第一个训练目标”的列表与分面。
- 修改：改为预热新页面不选条件时的首屏请求：列表与分面使用与前端完全相同的筛选字段（本学期、难度 1–10、折叠重复题、`scope_mode=primary`、`include_skills`、第 1 页 20 题、默认排序、标签完整度“全部”）。读取缓存以筛选对象整体为键，任何字段不同都不会命中，实施时逐字段对照前端 `requestFilters`。

### 5.2 请求组装

- 已选条件以地址栏为唯一来源，变化时用 `router.replace` 写回；筛选行的其他条件沿用组件内状态，不写入地址栏（与现状一致）。
- 列表与分面使用同一筛选对象：`curriculumVolumeIds`、`curriculumSections`、`scopeMode: 'primary'`、`typeKeys`、`knowledgePoints`、`abilities`、`thoughts`、`methods`、`models`、`specialTypes`、`errorPatternCategories`、旧链接时的 `skillKeys`，以及现有的搜题干、作答形式、难度、来源、折叠重复题、教学进度、标签完整度、判定点待审核、排序与 `includeSkills: true`。
- 沿用现有 250ms 去抖、请求取消与读取版本号；切换条件时清除题目选择并回到列表顶部，与现状一致。

## 6. 地址与旧链接兼容

新地址：`?tab=tag&sec=…&type=…&kp=…&ability=…&thought=…&method=…&model=…&special=…&error=…`，多选时重复同名参数；`question=` 保留。

| 旧地址 | 新行为 |
|---|---|
| `tab=skill` | 视为 `tab=tag`，用 `replace` 改写 |
| 没有 `tab`，但带 `skill`、`topic` 或 `tagDim` | 进入按标签 |
| `tagDim=X&tag=V` | 转为对应维度的一个条件（`typeKeys`→`type`、`knowledgePoints`→`kp`、`abilities`→`ability`、`specialTypes`→`special`、`errorPatternCategories`→`error`，其余同名） |
| `section=S` 且 `scope` 为空或为学期 | 忽略（旧版中只是浏览位置） |
| `section=S&scope=section`、`section=S&scope=chapter` | 分别转为 `sec=S`、`sec=S 所在章` |
| `topic=K` | 在 `skill-index` 的 `topics` 中找 `stable_key=K` 的 `filter_value`，转为 `kp=`；找不到时忽略，并用一句提示说明该知识点不在当前学期 |
| `skill=sk_…` | 保留为“技能：名称（旧链接）”条件，样式为提醒色，可删除；左栏不提供技能分组 |
| `skill=unlinked` | 转到 `tab=todo` |
