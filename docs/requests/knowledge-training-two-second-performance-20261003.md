# 知识概览、知识图谱与训练诊断的两秒目标

用途：记录 2026-10-03 的专项优化、测量边界和后续方案。用户要求优先减少重复读取与计算，允许复用本地缓存。本文中的后续方案尚未实现。本次没有调用真实模型，没有修改或复制真实数据，没有启动或重启正式应用。

## 目标与当前结论

用户已确认：目标是进入页面或刷新后，小组结果和全部逐题证据一起在 2 秒内加载完成，保持一次加载。摘要先行、来源明细按需加载的方案不采用。页面标题出现、首屏内容出现、全部请求结束是不同指标。本次分别记录，不能只用页面结构出现的时间验收。

本次已减少重复考试证据投影、逐生重复扫描、关联资料统计扫描、完整 JSON 构造和前端重复检查。已复用现有 `profiles.cache` 保存概览、图谱及含小组的完整公开诊断响应。隔离数据中，准备完成后的三个页面首次完整加载均在两秒以内。无有效缓存和数据更新后立即重算尚未达到目标；真实来源的完整浏览器两秒目标尚未验收。

项目中另一任务正在实现学情总览与知识结构改版。该任务已增加概览字段和知识点—技能关联读取，并让新版知识结构使用概览接口。本专项较早测量的 `/api/graph/query` 页面不能代表新版知识结构。本文分开记录，不把旧版页面数据称为新版验收。

## 测量方式与范围

真实只读测量范围：八年级上册、2 个班、91 名学生、3 场考试。数据库留在原处，使用只读连接；文件审计拒绝真实数据写入。真实完整响应仅留在进程内存，调查文件只保存耗时、数量、字节数和输出一致性结论。

本地缓存恢复实验在内存中模拟缓存文件读写，仍执行原数据库内容版本与来源签名核对。没有向真实 `user_data/cache` 写文件。真实新进程、磁盘读取及完整浏览器首次进入不能据此直接声称验收。

浏览器实验使用带 TEST 名称的隔离数据：3 场考试、91 名学生、5,460 条题项记录、1,336 道题。复用项目性能数据工具、API 和独立前端构建。关闭后台预热；每页使用新的后端进程与浏览器上下文。首次和更新后各 1 次，连续刷新各 3 次。更新只提交隔离数据库一条扣分原因，随后使用原请求，不手动清缓存。未改考试分数。

时间从浏览器导航开始计算。数据就绪记录跟踪请求的 JSON 读取结束时间。早期训练页包括随后的同质小组诊断请求；当前默认章节页一次请求返回完整诊断与小组。早期内容时间取自动化等待返回时刻，会受轮询间隔影响，是可见时刻的上界。最终复测在页面动画帧内直接检查主要内容区域的尺寸与可见状态，记录实际显示时刻；取数据齐全和内容出现两项中的较晚值验收。接口与页面时间不能直接相加。文件缓存未清空，单次首次样本会受本机负载及同时运行任务影响。

## 已实现的内部优化

| 修改 | 原瓶颈与证据 | 当前行为 | 规则边界 |
|---|---|---|---|
| 一次复用学期证据 | 同一全部学生、同一学期请求中，空的保留考试列表导致证据投影调用 2 次 | 调用 1 次；选择学生仍只筛结果，拟合仍用完整学期人群 | 不改变观测、权重、难度、档位和教师最终分锁 |
| 掌握度按学生建立索引 | 每名学生反复扫描全部 33,865 个学生—知识项掌握结果 | 一次建索引，随后读取该生结果 | 完整输出与原函数、恢复原函数一致 |
| 概览与图谱内部摘要 | 两个接口不展示逐题评分来源，原输入仍加载原因文件及完整题目资料 | 摘要输入跳过来源细节；完整诊断、图谱证据、推荐继续使用完整输入 | 摘要与完整输入的概览、图谱、掌握度结果一致；页面改版新增关联读取另计 |
| 完整公开响应复用 | 训练诊断连续请求仍重复公共清理、响应校验和 JSON 构造；真实响应约 40.3 MiB | 保留 8 个压缩响应条目，命中后返回完整 JSON；后台保存含小组请求 | 所有字段与原公开模型输出一致；压缩只用于缓存存储 |
| 小组响应恢复 | 恢复基础诊断后，仍构造模块、读取完整诊断并计算小组 | 复用同一签名缓存保存完整小组响应；命中后不构造模块或完整诊断 | 校验数据库内容、计算代码、全部设置、成员、目标、日期与资源文件元数据；资源不可读或含链接时按原路径计算 |
| 小组复用完整诊断 JSON | 普通诊断与小组诊断分别转换并校验同一份逐题证据 | 复用同一来源下已完整校验的基础 JSON，只处理并校验新增小组字段 | 原完整模型构造与当前返回的字节一致；仍一次返回全部数据 |
| 一次获取完整小组诊断 | 页面先取完整基础诊断，再传输同样的证据获取小组 | 默认章节页首次调用已有小组端点；组件复用同一份完整响应 | 小组失败时保留原基础诊断回退；采用小组时仍重新读取来源核对；恢复编辑的自定义名单仍按原规则核对 |
| 直接生成 JSON | 先构造一份完整字典，再遍历字典编码 | 已有响应校验模型直接生成 JSON，减少一次大对象构造 | 空值省略、完整字段和有限数值相同；拒绝 NaN／Infinity 及被校验模型转换的异常数值字符串 |
| 关联资料读取 | 为判断能否复用题库投影，先统计 5 个完整来源表 | 复用现有题库文件代次，并在读中来源变化时拒绝发布缓存 | 原地标签更新即使数量与时间字段不变也失效；完整关联输出一致，不增加索引或迁移 |
| 公共清理减少标量处理 | 相同字段名重复大小写处理；数值、空值和重复文本反复进入通用清理 | 字段判定每个名称做一次，原样复用标量与已检查文本 | 禁止字段、路径文本、训练题面去分值与空容器省略规则不变 |
| 按完整模型输入复用掌握度 | 只修改扣分说明也使学期掌握度重新拟合 | 2 个进程内条目保存相同完整模型输入的结果；诊断本身仍刷新来源说明 | 观测结果、题库来源、计算代码、知识版本、参数、计算周和排除证据变化仍重新计算；同一人群拟合不变 |
| 概览与图谱本地投影 | 新进程只恢复大诊断对象，随后仍重新聚合 | 复用同一 `profiles.cache` 保存最终投影与诊断 JSON；最多 12 条，优先保留页面投影 | 数据库内容、计算代码、时间和原因目录变化仍失效；不新建业务表 |
| 前端字段检查 | 大响应对每次出现的字段名重复规范化与正则检查 | 每次响应内按字段名复用判断，并用对象栈检查全部嵌套对象 | 禁止字段与 4 个原有例外不变，后出现的嵌套对象仍检查 |
| 诊断展示与矩阵索引 | Vue 为完整诊断建立大量深层代理，矩阵多次线性查找学生与弱点，小组来源检查重复编码同一份结果 | 诊断与小组按完整只读快照替换；矩阵建立学生与知识项索引；同一只读快照复用检查依据 | 当前快照整体更新而不原地改写；新的结果对象重新检查；采用前核对、筛选、草稿、保存和恢复规则不变 |

本地缓存读取先拒绝计算版本或原因目录不匹配的旧文件，避免随后无用的整库内容核对。相同来源与相同条目不重复写文件。后台预热复用现有任务队列检查、来源失效和日期规则，准备默认图谱、完整诊断及首章默认小组；新访问的请求也触发空闲准备，相同请求不反复触发。小组日期继续使用原模块的 UTC 日期，学情日期继续使用中国日期，后台分别检查两者。

| 组件 | 缓存恢复 | 连续中位数 | 完整输出核对 |
|---|---:|---:|---|
| 知识概览 | 0.604 | 0.0157 | 一致 |
| 知识图谱查询 | 0.530 | 0.0162 | 一致 |
| 无小组的完整训练诊断 | 0.740 | 0.0846 | 字节一致，42,283,945 字节 |

无缓存训练样本的页面结构首次在 0.996 秒可见，全部数据在 7.620 秒完成，主要内容在 7.866 秒可见；说明更新后数据在 4.885 秒完成，主要内容在 5.041 秒可见。更新仅改变一条合成记录的扣分说明。评分或训练观测变化仍需重新拟合，不能把说明更新结果外推到这些更新。

同一合成输入的首次诊断剖析中，完整诊断核心累计约 5.33 秒，公共清理约 2.58 秒，模型校验与直接编码约 1.56 秒。证据投影仅调用一次，三场考试投影约 0.13 秒；记录的文件打开 30 次、目录扫描 1 次。剖析增加运行开销，各嵌套累计耗时不能相加，也不能代替正常浏览器时间。剩余主耗时集中在完整人群计算与大响应处理，并非反复扫描文件。

题目关联读取的相同真实输入受控对照共 1,334 个题目资料项：原函数首次 3.336 秒、连续 0.0932 秒；当前函数首次 0.936 秒、连续 0.00163 秒；恢复原函数首次 1.285 秒、连续 0.0882 秒；再次当前函数首次 0.865 秒、连续 0.00164 秒。首次原函数包含首轮磁盘和库加载成本，不能把 3.336→0.865 当作纯代码收益；恢复原函数与再次当前函数更适合比较。四次完整资料与关联输出一致。

完整公开 JSON 的相同真实输入编码对照为 42,283,945 字节：原来的字典构造加编码为 1.246 秒，直接模型编码为 0.413 秒；恢复原函数为 1.341 秒，再次直接编码为 0.391 秒。四次输出字节完全一致。该项只测编码，不包含前面的公开清理、模型校验和有限数值检查。

前端字段检查的受控对照使用相同 74.3 MiB 合成对象：原函数 1.620 秒、当前函数 0.224 秒、恢复原函数 1.606 秒、再次当前函数 0.236 秒。9 组允许或拒绝结果一致。这是单项检查时间，不是完整页面时间。

公共清理的相同真实输入受控对照：原函数 1.972 秒、减少标量和字段重复处理后 1.040 秒、恢复原函数 2.036 秒、再次优化函数 1.566 秒。完整输出一致。通用容器身份复用的实验反而更慢，未采用。掌握度相同状态的局部结果复用实验只节省约 0.07～0.11 秒，未修改模型公式实现。

真实来源内部对照中，完整诊断核心为原函数 7.613 秒、当前函数 7.072 秒、恢复原函数 8.292 秒；摘要输入为 5.144 秒。完整诊断、掌握度和公开输出核对一致。单项嵌套耗时不能相加，且 Python 垃圾回收会影响样本。主要收益是取消重复工作和后续复用，不能据此声称首次重算已到 2 秒。

## 尚未达到的范围与下一步

当前不能声称所有情况下首次完整加载都低于 2 秒。有效缓存恢复已达到目标；无有效缓存和更新后立即刷新仍未达到。正式服务的真实数据完整浏览器验收尚未进行。

按剩余实测影响排序：

1. **完整诊断的增量公开投影与校验。** 首次剖析中大响应清理和校验约 2.58 秒及 1.56 秒，包含剖析开销。可以按不变的学生、知识项和证据来源复用已校验的公开片段，改变的证据仍经过原清理与模型校验；不能跳过来源核对或减少返回证据。修改范围是已有诊断响应与来源投影，不新增业务接口。验收要比较完整字节、路径字段与非有限数值拦截，并测试教师改分、训练更新和恢复后仅改变部分证据的行为。尚未实现，具体收益未知。
2. **按考试复用已投影的证据，更新后只重读改变的考试。** 复用冻结评分结果、稳定标识、来源指纹与本地缓存；按同一考试、同一评分版本保存计算输入。汇总后仍运行原完整学期人群拟合，不能改为逐生或逐考试拟合。最新合成剖析的题目投影仅约 0.13 秒，单独优化该部分不会把 7.87 秒降到 2 秒；较多考试和真实评分行的增量收益需实测。验收教师最终分、训练发布、知识版本和原因文件更新的失效，记录更新 1 场考试后实际重读数量，并核对完整输出。尚未实现。
3. **正式规模的启动恢复和更新验收。** 完整小组持久化、模块延迟初始化、关联资料复用和启动默认小组准备已实现。当前独立浏览器使用合成来源，真实来源实验只验证读取组件及完整输出相等。需要在允许运行的正式服务时段，通过应用自身流程准备快照，再测真实页面首次、连续和实际数据更新后刷新；不能把内存缓存实验当作真实磁盘或浏览器验证。无有效缓存仍需保留慢样本，不能只报命中的快样本。

后台准备先处理各班，再处理默认全部学生范围；新增访问范围也在空闲时准备。启动后立即进入或更新后立即刷新可能赶在准备完成之前。后台准备不能替代这些条件的验收。
