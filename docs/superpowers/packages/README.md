## 安全底线

以下动作始终逐次授权：

1. 读取、复制、修改、迁移或删除真实 `user_data`。
2. 调用真实模型、使用真实密钥或产生费用。
3. 数据库迁移、批量覆盖、永久删除或其他不可逆操作。
4. 操作真实教材、PPT、教辅、学生档案、成绩、训练卷或答卷。
5. push、PR、合并、同步主线或丢弃未合并历史。

真实数据不得进入 Git、stash、文档、普通日志或公开 API。数据写入和不可逆操作要先明确目标、备份和回退。

## 正式工作项规则

1. 开始前根据当前源码冻结目标、包含、不包含、验收和风险。
2. 涉及状态一致性、并发、重试、文件、费用或跨库时，先列故障矩阵。
3. 每条业务线只修改自己的所有权范围；公共热点走 F0 或独立地基修正。
4. P4、A、B 完成小任务后只记录进度和必要检查点，连续推进后续任务；不逐包运行正式测试或正式复审。
5. 只有故障阻塞继续实现时，才做最小范围诊断；诊断结果不等于包级验收。
6. 整条业务线到达用户最终验收阶段后，冻结同一候选，集中运行测试、构建和交叉冒烟，并进行一次需求符合性复审和一次代码质量复审。
7. 首轮有阻塞问题时统一修复一次，再进行一次限定最终复审。
8. 影响功能结果且无法从项目查明的问题及时询问用户；先汇总当前全部已知问题并给推荐方案，回答后才产生的依赖问题可以分步再问。
9. 真实数据、费用、迁移和不可逆操作不因计划存在而获得授权。
10. 候选经用户人工验收后，才申请 push、PR 和合并。

F0 作为一次性公共地基整体完成后集中测试、复审和验收一次；它合入后即结束，不成为长期第四条业务线。

## 安全停机

出现以下任一情况时停止当前实现并请求用户决定：

- 需求改变评分、训练证据、学生记录、安全或恢复语义；
- 需要真实数据、真实模型费用、迁移或不可逆操作；
- 业务线必须修改公共热点或另一个模块；
- 无法确定目标文件、数据对象、费用上限或回退；
- B 线试图在 B00/B01 安全关口前保存敏感正文；
- P4 试图把训练覆盖度写成正式考试分数。
