# Phase 2 执行包地图：Vue SPA 与前端切换

> **阶段目标：** 用 Vue 3 + TypeScript + Vite + Element Plus + Pinia 实现教师工作台，并在真实流程验收后退役 Streamlit UI。
> **阶段启动条件：** P1 review/media 切片满足门槛后可提前开始 P2-01 至 P2-08。
> **阶段继续条件：** 完成 P2-08 后，其后的复杂页面必须先通过本文定义的 Phase 2 前端来源重校准门槛。
> **业务权威：** 现有 Streamlit 行为、服务实现、数据库契约、测试，以及带日期和范围的用户明确决定，只约束用户任务、业务能力、数据语义、业务结果、状态、权限、安全、持久化、危险操作保护、失败恢复、幂等和审计；不要求新前端复刻旧导航、页面结构、控件位置或点击顺序。
> **UX 设计：** 在业务能力可达、数据语义和结果等价、安全边界不降低的前提下，新 Vue SPA 可以主动重组导航、合并或拆分页面、调整布局、控件、呈现顺序和操作步骤；组件复用只是实现偏好，不能凌驾于已批准的 UX 主动重设计。
> **视觉权威：** `docs/ui/STYLE.md` 只约束视觉 Token、密度、控件外观、视觉可访问性（如对比度、可见焦点、文字可读性）和通用视觉质量；交互语义、键盘操作、上下文连续性和错误恢复仍由 UX 与业务验收约束，不由 STYLE 定义。参考图不定义功能。所有 UI 包必须使用 `frontend-design` skill，并以真实浏览器验证。
> **不修改：** 前端迁移不重写稳定后端，不新增未经确认的业务字段或状态。
> **夜间资格：** 所有包级标记以 `NIGHTLY_ELIGIBILITY_MATRIX.md` 为唯一权威，本文件不重复维护。

## 工程与设计系统

### P2-01 前端工程、依赖锁与质量命令

- **依赖：** P1-10，API 可启动。
- **目标：** 建立可重复安装、构建、测试和静态检查的 `frontend/` 工程。
- **主要范围：** Vue/TypeScript/Vite、Element Plus、Pinia、Vue Router、ECharts、测试与 Playwright 配置；锁文件纳入仓库。
- **子任务：** 开工时核验依赖的最新官方文档，选择并锁定兼容版本；定义 dev/build/lint/typecheck/test/e2e；代理 `/api`；生成空应用；验证 dist 可由便携发布流程携带。
- **不修改：** 不做页面视觉，不切换 `运行.bat`，不要求最终工作机安装 Node。
- **验收：** 干净安装、lint、typecheck、unit、build 全绿；无浮动依赖；构建产物不含密钥。
- **回退/风险：** 纯增量目录，风险低。

### P2-02 Token、Element 主题与基础控件

- **依赖：** P2-01。
- **目标：** 把 STYLE.md 的颜色、字号、间距、圆角、阴影和状态外观变成唯一设计 Token；状态集合和含义仍来自现有契约。
- **主要范围：** CSS variables、Element Plus theme、按钮/输入/状态徽章/空加载错态/反馈组件及展示页。
- **子任务：** 固定 accent；建立 Token 守卫；收紧圆角和阴影；实现 focus/禁用/错误状态；用长中文和极端数据验证。
- **不修改：** 不复制旧 `shared_styles.py` 蓝紫色板，不做营销 Hero、渐变或卡片堆叠。
- **验收：** 组件测试；颜色/间距无散落魔法值；键盘 focus 和对比度检查；展示页多视口无溢出。
- **回退/风险：** 前端样式可独立回退。

### P2-03 App Shell、路由与全局会话上下文

- **依赖：** P2-02、sessions API。
- **目标：** 实现顶部栏、可收起左导航、主工作区和可收起右检查器，并统一当前 session 上下文。
- **主要范围：** App Shell、路由、导航权限空态、session store、面包屑和响应式栏位。
- **子任务：** 七项导航与设置入口；session 选择/持久化；404/错误边界；1024–1279 紧凑桌面策略；右栏稳定尺寸；明确低于 1024px 不受支持。
- **不修改：** “智能体与自动化”只保留禁用/未来入口，不实现聊天或任务功能。
- **验收：** 路由/状态单测；刷新保留 session；长名称不遮挡；所有规定视口无横向溢出。
- **回退/风险：** 新前端内部变更，风险低。
- **来源重校准说明：** P2-03 至 P2-08 的现有 Vue 行为共同构成待核验能力清单、审计输入和复用候选，不是业务事实来源；七项导航、固定栏位和未来禁用入口只保留为 P2-03 的历史实现事实，不能单独证明后续页面需要相同结构或入口。复用只是实现偏好，不能凌驾于已批准的 UX 主动重设计；若现有外壳妨碍信息架构、清晰度、可访问性、上下文连续性、错误恢复或批量效率，可以在说明理由并提供验证与回退后重构或替换。

### P2-04 API Client、错误契约与 Job Store

- **依赖：** P2-01、P1-10/P1-11。
- **目标：** 所有页面通过类型化 API client、统一错误解析和可恢复 job store 访问后端。
- **主要范围：** Axios/fetch wrapper、OpenAPI 类型生成或受控手写类型、request ID、轮询、取消、退避和通知。
- **子任务：** 统一 base URL；处理 422/404/500；job 刷新恢复；停止轮询；网络断开重试；禁止页面直接拼 URL。
- **不修改：** 不引入第二套状态库，不把 API key 存入浏览器。
- **验收：** mock API 测试；刷新后续查 job；取消竞态；错误保留已有页面内容。
- **回退/风险：** 纯前端网络层，风险中等。

## 单题复核样板页

### P2-05 复核队列、筛选与连续导航

- **依赖：** P2-03/P2-04、P1-12。
- **目标：** 左栏显示学生、状态、置信度和异常，并能定位下一条高风险记录。
- **主要范围：** question selector、学生队列、搜索、筛选、排序、当前项和上一/下一项。
- **子任务：** URL/Store 同步；空队列；长姓名；低置信优先；已复核回流；虚拟滚动或分页按数据规模选择。
- **不修改：** 不在列表执行调分，不显示大头像或多余操作按钮。
- **验收：** 1000 行生成数据下交互稳定；筛选后当前项正确；键盘切换不丢上下文。
- **回退/风险：** 只读页面切片，风险低。

### P2-06 答卷证据查看器

- **依赖：** P2-05、P1-13。
- **目标：** 中央区域清楚查看裁剪图和原卷，支持适应宽度、原比例、缩放、旋转、拖拽和切换边界。
- **主要范围：** image viewer、加载/失败、原卷入口、裁剪边界/图像异常叠层。
- **子任务：** 稳定画布尺寸；预加载相邻项；缩放中心；键鼠操作；错误重试；高 DPI/大图内存检查。
- **不修改：** 不把 3D/canvas 装饰引入主体验，不修改原始图片。
- **验收：** Playwright 图片像素非空检查；缩放/旋转/拖拽测试；侧栏切换不挤坏答卷。
- **回退/风险：** 只读媒体，风险中等。

### P2-07 评分检查器、草稿与确认

- **依赖：** P2-05/P2-06、review confirm API。
- **目标：** 右栏按评分标准、证据、AI 初评、风险、教师最终分的优先级完成安全复核。
- **主要范围：** rubric、AI 建议、分数输入、错因/知识点、备注、本地草稿、确认并下一份。
- **子任务：** 分数边界；未保存提示；提交禁用；部分失败保留输入；教师结果高于 AI；活动记录占位契约。
- **不修改：** 不展示模型隐藏推理，不把 AI 初评称为最终分，不新增评分规则。
- **验收：** 输入聚焦时快捷键不误触；失败后草稿仍在；成功跳到正确下一份；长 rubric 可滚动且提交固定。
- **回退/风险：** 写评分结果，风险高；旧 Streamlit 复核仍保留。

### P2-08 样板页集成、快捷键与视觉门槛

- **依赖：** P2-05 至 P2-07。
- **当时目标：** P2-08 合并时以单题复核页作为后续页面的组件和交互范式，并在当时门槛通过前禁止扩散。
- **主要范围：** J/K、Enter、Z、+/-、搜索；Shift+Enter 明确无动作；得分框聚焦全选与“确认并下一份”；焦点管理；响应式；业务全流程；`docs/user-testing/checkpoints/P2-08-*.md` 版本化正式清单。
- **子任务：** 固定演示数据集；加载/空/错/禁用；长内容；刷新恢复；截图与像素检查；控制台错误检查；页面可运行后生成并执行 30-45 分钟用户清单。
- **不修改：** 不开始其他复杂页面，不为了截图添加假数据到生产路径。
- **验收：** 1920x1080、1440x900、1366x768、1280x800、1024x768；无重叠或横向溢出；复核流程通过；正式清单 Blocker/Major 清零且用户明确标记 `passed`。平板和手机不进入验收。
- **回退/风险：** 新页面可整体隐藏；业务写入用临时库或用户授权副本。
- **来源重校准说明：** 上述实现、合并和验收事实保持不变；P2-03 至 P2-08 的现有 Vue 行为只作为待核验能力清单、审计输入和复用候选，不是业务事实来源，其中“后续组件和交互范式”的未来效力已由 2026-07-14 前端来源重校准门槛撤销。复用只是实现偏好，不能凌驾于已批准的 UX 主动重设计；若现有组件妨碍信息架构、清晰度、可访问性、上下文连续性、错误恢复或批量效率，可以在说明理由并提供验证与回退后重构或替换。

- **阻断：** 门槛未通过时，P2-09、P2-13、P2-14、P2-16、P2-19 及其所有后续依赖不得开始；Phase 1 总门槛通过也不能绕过。

- **业务能力与 UX 设计溯源：** 对 P2-03 至 P2-08 当前 Vue 行为使用下表逐项核验；`STYLE.md`、概念图、演示数据和历史计划不能单独充当业务来源。

|---|---|---|---|---|---|---|
| 开工时逐项填写 | Streamlit、服务、数据库契约或测试 | 明确不可丢失或改义的内容 | 允许重新设计 | 说明效率、清晰度或可访问性依据 | 仅业务边界变化时必填 | 自动检查、浏览器证据与用户验收 |

- **阅卷修正：** 按题号批量比较和复核必须作为默认可达的业务能力，但不固定 Streamlit 的布局或点击顺序；单份详情能力作为可选入口或异常深查，现有三栏仅是一种可复用原型。批量主视图与单份详情之间的进入、返回、保存和继续处理按任务效率与上下文连续性重新设计，同时保持评分结果、安全确认和失败恢复语义。
- **验收：** 文档与图片活动集重置完成；“业务能力与 UX 设计溯源表”通过审查；必要修正具备可回退实现和浏览器证据；规定桌面视口、错误恢复和受影响回归通过。验收必须同时证明业务能力、数据语义、结果和安全边界没有丢失，新信息架构与操作比旧原型更清楚、高效且可恢复；不要求逐屏、逐控件或逐点击一致，只有业务边界变化才要求专项用户决定。按 `docs/user-testing/PHASE2_FRONTEND_RECALIBRATION_TEST_TEMPLATE.md` 生成版本化清单并由用户明确确认批量复核的默认地位及修正后页面；门槛通过状态只在 `EXECUTION_INDEX.md` 记录。
- **不修改：** 不回写 P2-08 为未完成，不篡改其正式验收证据；不新增正式包编号；不改变评分规则、后端契约、Schema、模型调用或真实 `user_data/`。
