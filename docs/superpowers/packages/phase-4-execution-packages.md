## 1. 这条分支要交付什么

P4 线要把当前“离散知识点掌握分布”升级成一条可以反复运行的个人训练闭环：

```text
知识点稳定身份与教师确认关系
→ 掌握度 v2 与旧口径对照
→ 题库题生成无分值训练判定点
→ 每名学生形成不同的推荐草稿
→ 教师确认后冻结一人一卷
→ WPS审核并打印
→ 混合扫描后自动归卷
→ 每名学生一次整卷训练判定
→ 教师处理不确定项
→ 回流掌握证据并解释下一轮变化
```

最终必须交付：

1. 教师确认后才生效的知识关系；
2. 可解释、可对照和可回退的掌握度 v2；
3. 题库题目的训练判定点版本和质量门；
4. 基于现有题库的一人一卷推荐与冻结实例；
5. 可在 WPS 审核的 DOCX 和用于打印扫描的冻结 PDF；
6. 每页机器身份、混合扫描归卷和异常队列；
7. 不使用分数的整卷训练判定；
8. 教师最终判定锁、幂等恢复和跨库补偿；
9. 按题训练反馈、掌握度刷新和下一轮推荐解释；
10. 普通考试批改、成绩、排名和报告完全保持原义。

## 2. 冻结的任务边界

### 2.1 包含

- 知识点稳定身份、别名和退役；
- `parent`、`prerequisite`、`related` 三种关系；
- AI 关系建议、教师审核和关系审计；
- 图谱 2.0 查询、下钻和交互；
- 掌握度 v2 纯函数、对照和功能开关；
- 标签与训练判定点的联合题目分析请求；
- 标签和判定点的独立投影、独立状态和独立重试；
- 训练判定点版本、教师审核和旧题回填任务；
- 直接巩固、先修补偿和迁移练习推荐；
- 个性化训练卷实例、题目快照和判定点快照；
- WPS 可审核 DOCX、冻结 PDF 和页面机器身份；
- 混合扫描的归卷、补扫和人工匹配；
- 每名学生一次整卷训练判定；
- `met/not_met/uncertain/unreadable` 四态结果；
- 本地计算达成点数/总判定点数；
- 教师最终判定锁；
- 训练证据发布、掌握度刷新、反馈和下一轮推荐。

### 2.2 明确不包含

- AI 自动出新题；
- 正式考试评分规则的改写；
- 把训练结果换算成 100 分、等级或排名；
- 在普通 `AIGrader` 中增加训练模式；
- 无身份外部练习纸的自由批改；
- 学生端、家长端、云端作答或多人协作；
- 自动打印、自动发卷或自动发布下一轮；
- 使用班主任档案、家庭、心理或德育信息选题；
- 备课工作台写入题库或掌握度；
- 自动确认 AI 关系或自动覆盖教师判定；
- 全量重标真实历史题库；
- Phase 5 的教师命题与自动生成新题；
- 跨三个工作台的统一首页或事件总线。

### 2.3 完成定义

使用合成数据，至少 5 名学生能够：

- 因不同掌握证据得到不同题目；
- 各自生成一份冻结训练卷；
- 页面被打乱扫描后仍正确归卷；
- 每人最多一次整卷模型请求；
- 每道题得到达成点数/总判定点数；
- 不确定项由教师修正并形成最终锁；
- 训练证据回流后掌握度和下一轮推荐产生可解释变化；
- 普通考试批改与成绩报表没有回归。

### 2.4 连续迭代与最终集中验收

P4-00—P4-17 是范围、依赖和完成清单，不是 18 个独立测试或复审关口。执行时冻结以下节奏：

1. 小任务或执行包完成后，只更新进度、实现说明和必要的本地检查点；
2. 不逐包运行正式自动测试，不逐包启动需求符合性复审或代码质量复审，不等待包级人工验收；
3. 如果故障已经阻塞后续开发，只运行能定位和解除阻塞的最小检查，随后继续推进；
4. 各包“验收”条目先累计为 P4-17 的最终验证清单，不要求在该包结束时实际跑完；
5. P4-01—P4-16 连续完成并进入用户最终验收阶段后，才冻结完整候选，在 P4-17 集中运行受影响回归、P4 全套测试、必要构建和跨模块冒烟；
6. 对同一个冻结候选并行进行一次需求符合性复审和一次代码质量复审，再完成用户人工验收；
7. 如有阻塞问题，只统一修复一次、复测修复范围并进行一次限定最终复审。

执行小任务时，能从源码、文档、测试契约和本计划查明的事实自行查明。会改变产品结果、范围、真实数据、模型费用或不可逆结果的问题要及时询问用户；先集中调查并尽量一次列出当前全部已知问题，同时给出推荐答案和影响。后续问题只有在上一轮回答后才能确定，或需要根据实际页面/纸卷效果继续调整时，可以明确依赖并分步骤询问。等待回答只暂停受影响部分，其他可安全推进的 P4 工作继续。

## 3. 开始实施前的集中调查结论

### 3.1 已有能力

- 当前题库打标签会按复杂度动态合批，不是固定每题一次请求；
- 当前评分依据生成可以先产生答案、步骤和证明义务，再单独配分；
- 当前整卷批改已经是一名学生一次物理模型请求；
- 当前训练任务项有稳定 `task_item_code` 和题目快照；
- 当前图谱是 tag-only，关系边为空；
- 当前掌握度是历史证据按满分加权的得分率；
- 当前训练尝试写入仍是 stub，尚未形成真实回流。

### 3.2 不能直接复用

- 正式评分依据强制分值逐层相等和全卷总分；
- 普通批改结果强制题分、总分和正式成绩语义；
- 当前 `training_task_items` 没有判定点版本和快照；
- 当前训练结果的可空唯一字段不能可靠阻止重复回流；
- 当前打标签上下文只知道“有图片”，未必携带实际题图；
- 当前一个普通考试会话中的所有学生共享同一份题目和评分依据；
- 当前扫描配对默认基于同一套试卷的页面结构。

### 3.3 冻结结论

- 新建 `TrainingCriterionModule` 和 `TrainingAssessmentModule`；
- “1 分占位”只能存在于内部兼容 Adapter，不能成为数据库和界面语义；
- 标签与判定点可共享一次物理请求，但必须分别校验和保存；
- 个性卷必须冻结判定点版本和内容哈希；
- 扫描必须先按页面身份归卷，再调用模型；
- 模型逐点判定，系统本地计数；
- 普通考试和训练只在最终掌握证据层汇合，不共享分数对象。

实际目录以开工时源码为准，但所有新对象必须留在 P4 领域内，不散入备课或班主任模块。

### 4.2 P4 不得修改

除三路总索引规定的共同地基修正外，P4 不修改：

- `backend/teaching_prep/**`；
- `backend/class_teacher/**`；
- 两个工作台的前端目录、迁移、数据库和测试；
- 两个工作台的产品设计；
- 全局导航、路由、应用壳和模块注册文件；
- 工作台公共模型安全入口；
- 普通考试 `AIGrader` 的分数语义；
- 班主任敏感数据、加密、SOP 或学生支持档案；
- 备课 WPS 课件改编逻辑。

### 4.3 只读边界

- 备课工作台将来只能通过稳定 Adapter 只读已发布题库和匿名班级证据；
- 班主任工作台不读取训练判定正文、个性卷或知识关系；
- P4 不读取 `teaching_prep.db` 或 `student_affairs.db`；
- 三条业务线之间不建立跨数据库外键或直接写入。

## 7. P4-00：范围、基线、gold set 与故障矩阵

### 7.1 目标

把当前实现事实、旧掌握度输出、关系样本、判定点样本和端到端成功标准冻结成可重复基线。

### 7.2 包含

- 当前标签、图谱、训练任务、批改和扫描契约清单；
- 关系正例、反例和冲突样本；
- 选择、填空、计算、证明、作图题判定点样本；
- v1 掌握度 golden 输出；
- 5 名合成学生的一人一卷场景；
- 缺页、重页、错页、模糊图、等价解法、模型漏点等故障样本；
- 普通考试不回归基线；
- 模型次数、费用、性能和隐私指标；
- 阶段成功阈值。

### 7.3 排除

- 不建表；
- 不调用真实模型；
- 不读取真实学生或真实答卷；
- 不改变当前推荐和掌握度。

### 7.4 验收

- 每个执行包能映射到至少一个样本和验收断言；
- 关系、判定点、个性卷和回流都有正反例；
- 明确旧口径如何并列、回退和停止使用；
- 故障矩阵覆盖重复、并发、中断、重启、失败、取消、部分完成、缺失和冲突。

## 8. P4-01：知识点稳定身份与关系语义

### 8.1 目标

把可变显示名与稳定知识点身份分开，冻结三种关系的含义、方向和禁止组合。

### 8.2 包含

- stable key 生成或迁移规则；
- 名称、别名、教材显示名和退役；
- `parent/prerequisite/related` 定义；
- 自环、重复、反向冲突和循环规则；
- 关系来源、理由、状态和版本；
- 关系对掌握度与推荐的允许影响。

### 8.3 验收

- 改名不改变历史证据；
- 未治理新词不能直接成为关系节点；
- 每种关系有教师认可的正反例；
- related 不被误作先修；
- 退役关系不再参与活动推荐但历史可追溯。

## 9. P4-02：关系 Schema、Repository 与迁移

### 9.1 包含

- 稳定身份、别名和关系表；
- `suggested/confirmed/rejected/retired` 状态；
- 来源、模型版本、教师决定、revision 和审计时间；
- 事务 Repository；
- 空库、历史库、副本迁移和完整性检查；
- 重复边、并发确认、退役和恢复；
- 活动关系只读投影。

### 9.2 关键规则

- `suggested` 永远不进入活动图；
- 不复活旧技能/概念 ID；
- 不删除当前 `question_tags`；
- 迁移失败回滚，不形成半套身份；
- 对真实题库迁移必须另行授权、备份和副本预演。

### 9.3 验收

- 所有合法/非法状态转换有测试；
- 唯一性、外键、循环检查和幂等通过；
- 旧题库不丢标签；
- 关闭新功能时当前图谱和组卷行为不变。

## 10. P4-03：AI 关系建议与离线评估

### 10.1 包含

- 受控候选范围；
- 小批请求、结构化输出和理由；
- 未知 stable key 拒绝；
- 候选去重与冲突标记；
- gold set precision、coverage 和错误类型；
- 取消、失败、显式重试和恢复；
- 模型、提示版本、请求次数和用量记录。

### 10.2 规则

- 不发送学生信息；
- 只保存 suggested；
- 模型失败不自动重试；
- 低质量候选不为提高覆盖率而放宽；
- 相同 operation 不重复付费。

### 10.3 验收

- Fake 模型覆盖合法、未知、重复、冲突和坏 JSON；
- 达到 P4-00 阈值；
- suggested 清空后活动图完全不变；
- 普通日志不保存敏感正文和密钥。

## 11. P4-04：教师关系审核与审计

### 11.1 包含

- 建议队列、来源和理由；
- 关系影响预览；
- 单条确认、拒绝、改关系和退役；
- 受限批量操作；
- revision 冲突和部分失败；
- 教师决定时间线。

### 11.2 排除

- 自由拖拽式图编辑器；
- AI 自动确认；
- 前端直接写关系表；
- 批量确认互相冲突的边。

### 11.3 验收

- 教师能区分 AI 建议和已确认关系；
- 并发页面不会覆盖；
- 退役后推荐立即不再使用；
- 审计能说明谁、何时、基于什么决定。

## 12. P4-05：图谱 2.0 查询服务与 API

### 12.1 包含

- 只读取 confirmed 关系；
- 学生、班级、考试和知识点范围；
- 节点、边、掌握证据和缺失说明；
- 多层先修深度限制；
- 循环保护、孤立节点和多父结构；
- 证据分页、响应版本和请求级缓存；
- v1/v2 掌握度并列字段。

### 12.2 验收

- API 不推断缺失边；
- suggested 不泄漏；
- 节点、边和证据数量一致；
- 大图性能不低于 P4-00 基线阈值；
- 删除或退役关系后缓存正确失效。

## 13. P4-06：图谱 2.0 UI 与证据下钻

### 13.1 包含

- 父子、先修和相关关系的不同视觉；
- 掌握证据热力和非颜色状态；
- 范围筛选、聚焦、路径查看；
- 节点证据、来源和缺失下钻；

### 13.2 验收

## 16. P4-09：标签＋训练判定点联合题目分析

### 16.1 目标

在长度允许时，同一次题目分析请求同时返回六维标签投影和训练判定点投影。

### 16.2 包含

- `combined-v2` 结构化输出契约；
- 保留现有 `tag-only-v1` 兼容 Adapter；
- 实际题图、答案图和富内容上下文；
- 按预计输入和输出长度动态合批；
- 短客观题小批、普通解答题小批、长题/证明/图片题单题；
- 标签与判定点分别规范化、质量校验和保存；
- 标签成功/判定点失败的部分成功状态；
- 每个投影独立重试；
- 从已确认正式评分依据本地转换的 Adapter。

### 16.3 关键规则

- 不给现有 `TagAnalysis` 直接塞评分字段；
- 判定点不保存分值；
- 产品操作上先完成普通标签治理，再在题库同一道题的详情中审核训练判定点；
  同一次物理请求共享只用于减少请求数，不改变这一题库归属和操作顺序；
- 模型漏图时图片题失败关闭；
- 一题的受控标签候选不能被同批另一题借用；
- 失败不自动产生修复请求；
- 真实批次和费用另行授权。

### 16.4 验收

- 一次响应能安全拆成两个投影；
- 一个投影失败不回滚另一个已成功投影；
- 重试失败投影不重复调用成功投影；
- 五类题型有合成样本；
- 请求数、模型和用量准确；
- 无真实图片正文进入诊断日志。

## 19. P4-12：冻结训练卷实例、WPS DOCX 与 PDF

### 19.2 规则

## 20. P4-13：页面身份、混合扫描归卷与补扫

## 21. P4-14：独立整卷训练判定模块

### 21.1 Interface

```text
assess(submission_id, expected_revision) -> TrainingPaperOutcome
```

调用者不传 rubric 路径、模型名、分值或题号映射。模块内部从冻结 submission 取得全部身份与判定点。

### 21.2 包含

- 完整页面和冻结判定点组装；
- 一名学生最多一次物理请求；
- 模型逐点返回四态和可核对依据；
- point ID 完整性、重复和未知检查；
- 本地统计 `met_count/total_count`；
- 模型失败、取消、坏 JSON 和超时；
- 运行时上下文超限时整卷失败，不自动拆卷或追加请求；
- 等价解法、空白、涂改和提示注入保护；
- 每题独立候选结果；
- Fake 模型 Adapter。

### 21.3 排除

- 不复用普通 `GradingResult`；
- 不生成分数、总分或排名；
- 不自动重试；
- 不让模型直接返回并决定计数；
- 不发布漏点或非法结构结果。

### 21.4 验收

- 每名学生物理请求数不超过 1；
- 每个预期点恰好一个合法结果；
- 漏点、重复点和未知点的题进入人工队列；
- `uncertain/unreadable` 不算未达成；
- 其他完成题可独立形成候选；
- 模型故障不留下半份正式证据；
- 普通整卷批改测试保持通过。

## 22. P4-15：教师复核锁、幂等与恢复

### 22.1 包含

- 重新计算覆盖数；

- 重复、并发和响应丢失；
- 判定运行账本；
- 暂停、取消、失败重试和重启恢复；
- 已完成题、待复核题和失败题状态；
- 文件/数据库部分失败补偿。

### 22.2 规则

- 教师锁永远覆盖 AI；
- 修正本地完成，不产生模型费用；
- 取消保留已发布结果，不把未完成项当 0；
- 新页面 revision 不能覆盖旧教师决定；
- 不能依赖旧含 NULL 的唯一约束防重；
- 完成状态由明细重算，不只相信 Job 状态。

### 22.3 验收

- 重复点击不产生第二条结果或第二次请求；
- 两页同时修改明确冲突；
- 应用退出后状态可恢复；
- 教师改判后覆盖数正确；
- AI 重跑不能覆盖锁；
- 部分完成和取消如实显示；
- 每个故障均有可行动中文说明。

## 23. P4-16：训练证据、反馈、掌握度与下一轮

### 23.1 包含

- 最终题目结果转训练证据；
- outbox、幂等发布和补偿重放；
- 每题覆盖比例、难度、时间和来源；
- 未复核证据不发布；
- 掌握度 v2 重算；
- 训练前后差异解释；
- 学生个人反馈；
- 下一轮推荐草稿和变化原因；
- 教师确认后才发布下一轮任务；
- 训练历史和审计时间线。

### 23.2 规则

- 不把点数简单跨题相加；
- 不写正式考试分数或排名；
- 题库、阅卷库之间不声明分布式事务；
- 重放 outbox 不重复证据；
- 证据撤回或教师修正后可重算；
- 备课工作台只读取得教师选择的匿名班级摘要；
- 班主任工作台不自动取得训练正文。

### 23.3 验收

- 训练结果真实改变 v2 和下一轮草稿；
- 每个变化能追溯到具体题和判定点；
- 发布中断后可重放；
- 重复重放无重复证据；
- 关闭 v2 开关仍能读历史训练证据但不改变 v1；
- 教师不确认时不会自动生成下一份正式卷。

## 24. P4-17：全闭环验收与阶段门槛

P4-17 是整条 P4 线唯一的正式测试、正式复审和用户人工验收阶段；前面各包的验收条目都在这里集中兑现。

### 24.1 稳定候选检查

- P4-00 阈值全部有结果；
- 迁移只作用于临时或授权副本；
- 关系 suggested/confirmed 边界有效；
- 判定点没有数值分值；
- 5 名学生一人一卷闭环通过；
- 页面身份、归卷和补扫通过；
- 每名学生最多一次判定请求；
- 教师锁、幂等、重启和 outbox 通过；
- v1/v2 可并列和回退；
- 普通考试批改、成绩和报告通过受影响回归；
- 备课和班主任模块禁用/启用时 P4 不受影响；
- 没有真实数据、密钥、模型正文或输出文件进入 Git。

### 24.2 正式复审

P4 属于高风险。冻结同一个候选提交后并行进行：

1. 需求符合性复审：核对产品设计、执行包和三路隔离；
2. 代码质量复审：重点检查迁移、身份、幂等、并发、文件、模型次数、人工锁和跨库恢复。

等待全部意见后统一去重。只有本次引入或当前任务遗漏的 `Critical`、`Important` 阻塞。若有阻塞，统一修复一次、复测受影响范围，再进行一次限定最终复审；最终仍有阻塞时停止并请用户决定。

### 24.3 用户人工验收

先使用合成学生和纸张：

1. 审核几条知识关系；
2. 对照 v1/v2；
3. 审核五类题目的训练判定点；
4. 为 5 名学生生成不同训练卷；
5. 在 WPS 查看 DOCX，并冻结 PDF；
6. 打乱、漏放、重复放入部分扫描页；
7. 完成人工归卷和补扫；
8. 启动整卷训练判定；
9. 修正一个不确定点；
10. 查看每题达成点数/总判定点数；
11. 查看掌握度和下一轮变化；
12. 确认正式考试成绩没有变化；
13. 模拟模型失败和应用重启；
14. 关闭模型后用 Fake/人工方式重复主要流程。

真实小范围试点需要重新确认：

- 精确学生和题目范围；
- 工作机数据库备份与回退；
- 真实模型供应商和费用上限；
- WPS、打印机和扫描仪；
- 试点数据保存和删除方式；
- 失败后是否允许再次付费请求。

### 24.4 合并关口

只有 P4 完整候选进入最终验收阶段并集中完成测试、复审和用户人工验收后，才申请 push、PR 和合并。合并前同步最新 `main`，运行 P4 全部检查，并对两个工作台的模块注册和只读 Adapter 做冒烟；不把未验收的 A/B 分支合进 P4。

## 25. 整条 P4 线故障场景总表

| 类别 | 必须验证的结果 |
|---|---|
| 重复操作 | 关系建议、题目分析、生成卷、归卷、判定和证据发布均幂等 |
| 同时操作 | revision 或执行锁阻止静默覆盖 |
| 中途退出 | 事务回滚；文件留在可识别 staging；正式版本不变 |
| 重新启动 | Job、归卷、判定、outbox 可恢复或安全收口 |
| 失败重试 | 教师显式触发；模型不自动追加费用 |
| 取消 | 已发布证据保留；未完成项不伪装为错误或 0 |
| 部分完成 | 标签/判定点、题目结果和跨库发布分别显示真实状态 |
| 数据缺失 | 关系、判定点、页面或证据缺失时降级或阻断，不补造 |
| 数据冲突 | 题目版本、页面身份、教师锁和跨库版本冲突均失败关闭 |
| 文件失败 | 不覆盖旧卷，不发布损坏 DOCX/PDF |
| 模型失败 | 不发布非法结果，不影响普通考试 |
| 页面错误 | 模型调用前进入人工队列 |
| 教师修正 | 最终锁优先，重算可重复 |
| 跨库失败 | outbox 重放收敛，不重复证据 |
