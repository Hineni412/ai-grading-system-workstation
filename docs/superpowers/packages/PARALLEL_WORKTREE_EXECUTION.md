# 三路 Worktree 与分支协作手册

本文只规定 F0、P4、A、B 的 Git 拓扑和同步安全规则。业务边界见 `../../product/TEACHER_WORKSPACES_PARALLEL_IMPLEMENTATION.md`，动态状态见 `EXECUTION_INDEX.md`。

## 1. 固定拓扑

| 位置 | 分支 | 职责 |
|---|---|---|
| 根目录 | `main` | 只同步已合入主线；不承载三路开发 |
| F0 worktree | `codex/parallel-module-foundation` | 短期公共插槽地基 |
| P4 worktree | `codex/phase4-personalized-training-loop` | 图谱与个性化训练 |
| A worktree | `codex/teaching-prep-workbench` | 备课工作台 |
| B worktree | `codex/class-teacher-workbench` | 班主任工作台；B00 获批后才建业务分支 |

根目录存在真实 `user_data` 或未知修改时，不清理、不切分支、不暂存。所有开发在独立 linked worktree 中进行。

## 2. 起点

1. 本组设计文档合入后的稳定 `main` 记为 M0。
2. F0 从 M0 创建。
3. P4 可从 M0 创建并只先做 P4-00/P4-01。
4. A00/B00 可以从 M0 做 Gate 或文档，不创建正式业务数据。
5. F0 合入后的稳定 `main` 记为 M1。
6. P4 在进入 P4-02 前同步 M1。
7. A01 从 M1 创建。
8. B01 只有 B00 获批后从包含 M1 的稳定 `main` 创建。

每条线在执行记录中保存完整 SHA，不使用“最新 main”。

## 3. 日常协作

1. 每包开始前确认分支和 worktree。
2. 查看已有修改，避免覆盖用户或上一包内容。
3. 只修改本线拥有的文件。
4. 公共热点需要变化时暂停，另建小型地基修正。
5. P4/A/B 每包只更新进度和必要的本地检查点，随后继续下一包；不逐包运行正式测试或正式复审。
6. 只在包边界同步已稳定 `main`。
7. 不复制文件同步，不合入另一个未验收业务分支。
8. 不 force push。

如果故障阻塞下一包，可以运行最小范围诊断；这不是包级验收。影响功能结果且项目内无法查明的问题应及时汇总询问用户，优先一次问完当前已知问题；确实依赖前一轮回答的问题可以分步再问。

## 4. 候选与合并

1. F0 内部连续实现；整个公共地基候选完成后集中测试、双复审和用户验收一次，随后先合入并结束 F0。
2. P4、A、B 各自连续推进到整条线完整候选，不在小任务或包边界停下来做正式测试和复审。
3. P4 与 A 以实际完成顺序进入最终集中验收。
4. B 默认最后进入最终集中验收，但不以 P4/A 功能为业务依赖。
5. 后完成的线在冻结最终候选前同步最新 `main`。
6. 进入最终验收阶段后，集中运行本线完整检查和已合入模块的启动、导航、只读边界冒烟，再做双复审和用户人工验收。
7. 用户明确批准对应业务线后，才 push、创建 PR 和合并。
8. PR 合并后同步 `origin/main` 与本地根目录 `main`。

## 5. 数据与费用

- worktree 不包含真实 `user_data` 副本、修改、暂存或 stash。
- 自动测试使用临时数据库、合成资料和 Fake 模型。
- 真实文件、真实数据、真实模型、费用、迁移和不可逆操作逐次授权。
- P4 的打印扫描试点、A 的 WPS 代表文件、B 的真实学生试点分别有独立 Gate。
- 真实数据和密钥不得写入提交、PR、文档、普通日志或公开响应。

## 6. 冲突处理

发现冲突先判断来源：

- 同一业务线内部：在该线解决并继续推进；只有问题阻塞后续实现时才做最小诊断，正式回归留到整线最终候选；
- 两条线同时修改公共热点：停止，改为独立地基修正；
- 一条线修改另一条业务目录：撤回该越界修改，不建立依赖；
- main 已合入另一模块：同步后只适配公共契约，并做交叉冒烟；
- 真实数据出现在工作树：立即停止，不暂存、不提交。

如果 Git 已经处于真实 merge/rebase conflict，按仓库的冲突解决流程处理；不得用 `reset --hard`、强制 checkout 或手工递归删除 worktree。

## 7. 安全清理

删除或重新分配 worktree/分支前必须确认：

1. 工作树没有未知修改或真实数据项；
2. 独有提交已经进入 `origin/main`，或用户明确决定保留/丢弃；
3. 没有指向工作目录外部的 junction、symlink 或 reparse point；
4. 精确 worktree 路径已经核对。

满足条件后只使用 Git worktree 命令清理。禁止手工递归删除 linked worktree。
