# P2-09 会话、配置与 Rubric 编辑设计

**日期：** 2026-07-15

**状态：** 已获用户逐节批准，等待书面规格复核

**执行包：** P2-09

**适用范围：** Vue SPA 中的考试草稿、试卷接收与本地拆题、配置生成任务、Rubric/Answer Key 编辑与安全保存

**批准记录：** 用户明确允许在评分依据生成前保存可恢复考试草稿；在三种页面组织方案中选择 A“连续配置工作台”；随后逐节批准主流程、系统结构、功能覆盖、失败恢复和验收边界。

## 1. 目标与边界

P2-09 在现有 Vue SPA 中增加真实可用的“考试配置”入口，完成以下教师任务：

1. 创建、选择和重命名考试草稿；
2. 上传 DOCX/PDF 试卷并在不调用 AI 的前提下核对本地拆题结果；
3. 通过现有 `config_generation` Job 生成评分依据，查询进度并重试失败题；
4. 以结构化高密度表格编辑 Rubric 与 Answer Key；
5. 经过服务器权威校验后原子保存，并在必要时刷新已有样卷映射；
6. 在网络、任务、刷新、版本冲突和部分发布失败时保留可恢复现场。

本包不改变评分政策、总分口径、生成 prompt、模型供应商、数据库 Schema、题号身份、模板几何算法或批改算法。旧 Streamlit 配置入口继续保留，直到后续切换与退役包完成。

实现和验证只使用临时数据库、临时数据根、合成 DOCX/PDF 与假模型，不读取、写入或复制真实 `user_data/`。

## 2. 现状调查与设计动因

### 2.1 已实现能力

- `web_app.py` 已提供 DOCX/PDF 上传、本地拆题、题型修正、错拆题排除、逐题生成、整卷单次请求、失败题重试、评分单元编辑、统一评分表和配置保存。
- `backend/api/routers/sessions.py` 已提供考试列表、详情、创建、重命名、软删除和恢复。
- `backend/api/routers/config.py` 已提供配置读取/保存，以及 P1-17 的生成与失败题重试 Job。
- `backend/jobs/config_generation.py` 已保证生成输入只以服务器引用进入 Job，部分结果不绑定考试，完整成功才发布并绑定配置。
- Vue 已有同源 API Client、Job Store、当前考试 Store、错误净化、过期响应隔离和未保存草稿保护模式。

### 2.2 当前缺口

- 浏览器不能安全地产生现有 `CreateSessionRequest` 要求的服务器配置路径；新建考试与生成 Job 之间形成接口环。
- P1-17 的生成接口假定调用方已经拥有 `confirmed_blocks`、文档文本和题图，但浏览器没有受控上传与本地拆题 API。
- 当前配置响应会返回存储路径；新页面不应依赖或展示这些内部路径。
- 统一评分行投影及反向写回逻辑仍位于 Streamlit 页面，若直接移植到浏览器会让前端重算业务规则。
- 当前保存 API 没有配置 revision，多个页面或任务并发更新时可能覆盖较新版本。
- Streamlit 在保存评分依据后会刷新现有样卷映射；新 API 必须保留这一联动及其部分失败事实。

## 3. 已比较的页面方案

### 方案 A：连续配置工作台（批准方案）

一个页面内按“考试草稿 → 上传与拆题 → AI 生成 → 评分依据”推进。阶段进度始终可见，刷新后回到当前阶段，评分依据阶段切换为大面积高密度编辑表。

优点是上下文连续、失败恢复清楚、适合长流程与频繁回看；代价是页面状态管理和阶段完成判定较完整。

### 方案 B：考试列表与详情标签页

左侧管理考试，右侧在“基本信息、上传与生成、评分依据”之间切换。多考试管理直观，但生成状态、错误和未保存草稿分散在多个标签页，恢复时更容易丢失上下文。

### 方案 C：全屏分步向导

每次只展示一个步骤。首次使用认知负担低，但回看、跨步骤修正、长表编辑和任务恢复效率较差。

用户于 2026-07-15 选择方案 A。

## 5. 批准的信息架构与主流程

业务导航在 P2-09 完成后为：

```text
AI 阅卷系统
├── 考试配置
│   ├── 当前考试与草稿名称
│   ├── 1. 考试草稿
│   ├── 2. 上传与拆题
│   ├── 3. AI 生成
│   └── 4. 评分依据
└── 评分复核
```

`/sessions` 是考试配置工作台；根路由重定向至 `/sessions`。`/grading` 继续保留现有评分复核。开发用设计系统路由不进入业务导航。

### 5.1 阶段一：考试草稿

- 教师输入非空名称，服务器创建普通 `created` 会话和服务器拥有的占位配置文件。
- 不新增数据库状态；“尚未生成评分依据”由配置内容和工作台事实派生，不写入新的业务枚举。
- 草稿立即成为当前考试，刷新后可恢复。
- 模板和批改仍受现有前置校验保护；占位配置不能通过评分依据保存或批改准入。

### 5.2 阶段二：上传与拆题

- 上传采用 `application/octet-stream` 流式请求和独立安全文件名头，只接受 `.docx` 或 `.pdf`，单文件硬上限为 200 MiB；无论是否提供 `Content-Length`，服务器都在流式读取时执行同一上限。临时文件、原子发布与路径守卫复用题库上传模式。
- 每次上传生成不透明 `source_id` 和原子 manifest；manifest 保存于受控配置暂存目录，以便刷新或进程重启后恢复。
- 服务器本地解析 DOCX/PDF，完整正文、富文本关系、内部图片路径和题图 base64 不进入公开响应。
- 公开预览只返回题号、题型、文本摘要、答案存在性、人工核对标记及受控媒体 URL。
- 教师可以修改题型和排除错拆题；不在前端修改题号身份或构造图片路径。
- 替换文件产生新的 source revision。旧 Job 完成时若 source revision 已变化，必须 fail closed，不能覆盖新来源。

### 5.3 阶段三：AI 生成

- 默认使用本地拆题后的逐题生成；高级备用模式复用整卷单次请求。
- 新的安全提交端点只接受 `source_id`、source revision、生成模式和有界教师差异；服务器从 manifest 还原完整输入，再调用现有 P1-17 暂存函数。
- Job 数据库继续只保存 `session_id`、模式、服务器输入 ID、源 Job ID 和失败题号等安全标量。
- 部分结果只发布服务器草稿，不绑定考试；完整成功时先原子发布 rubric/answer 文件和来源归档，再在一个数据库事务中绑定配置、来源与 Job 成功状态。
- 文件发布后数据库绑定失败时，当前考试仍指向旧版本；本次新文件是未引用的服务器产物，按精确创建记录补偿清理，不删除复用的历史归档。
- running Job 继续采用协作式取消；模型调用返回前不伪装为已取消。

### 5.4 阶段四：评分依据

- 服务器把当前配置投影为带隐藏稳定 ID 的编辑行，并返回 revision、来源摘要、总分、问题清单和可编辑字段元数据。
- 前端保存行编辑和评分单元命令，不直接生成或持久化嵌套 Rubric JSON。
- 普通保存把 revision、行编辑和结构命令一次提交；服务器在当前配置副本上应用、检查总分和全部现有规则，再原子发布。
- 人工评分单元结构需要 AI 完善时，复用 `config_generation` Job 的显式 refine 模式；服务器先应用教师结构，AI 不得改变 part ID。
- 保存成功后返回新 revision，以及样卷映射刷新结果。

## 6. 后端结构与接口边界

即时实现计划可以根据现有模块边界确定源码文件名，但以下服务职责和公开路由保持固定：

### 6.1 会话草稿服务

- 创建名称非空的普通会话；
- 在受控配置目录原子创建占位 rubric/answer 文件；
- 失败时不留下只有一半文件或无效数据库行；
- 不接受客户端路径。

公开接口：

```text
POST /api/sessions/drafts
PATCH /api/sessions/{session_id}
```

### 6.2 配置来源接收与解析服务

- 流式接收、大小/扩展名/内容基本校验；
- 原子发布源文件与 manifest；
- 本地解析及受控题图预览；
- source revision 和过期 Job 保护；
- 成功生成后的精确归档与来源绑定。

公开接口：

```text
POST /api/sessions/{session_id}/config/sources
GET  /api/sessions/{session_id}/config/sources/{source_id}
GET  /api/sessions/{session_id}/config/sources/{source_id}/questions/{question_id}/assets/{asset_kind}
POST /api/sessions/{session_id}/config/generate-from-source
```

`asset_kind` 只允许 `question` 或 `answer`。公开来源摘要只返回安全文件名、文件类型、字节数、12 位内容指纹摘要、source ID 和 source revision，不返回完整路径、正文或图片编码。

同一考试的 source manifest 按 source ID 精确管理。替换来源不会删除仍被活动 Job 引用的旧来源；新配置完成绑定且旧来源不再被任何 Job 引用后，只清理服务器为该 source ID 创建的精确暂存文件，不做目录级递归删除。进程重启后从原子 manifest 恢复，旧 running Job 仍按现有规则转为 failed。

### 6.3 配置编辑应用服务

从 `web_app.py` 提取统一评分行投影、反向写回、评分单元命令、质量检查和样卷刷新编排。Streamlit 和 FastAPI 都调用该服务，避免两套规则漂移。

公开接口：

```text
GET  /api/sessions/{session_id}/config/editor
PUT  /api/sessions/{session_id}/config/editor
POST /api/sessions/{session_id}/config/editor/refine
```

`GET` 返回不透明 revision、`configured`、行列表、来源摘要、总分和问题列表，不返回 rubric/answer 文件路径。新草稿的占位配置返回 `configured=false` 和空行，不能进入编辑或批改准入。`PUT` 和 `refine` 必须比较 revision，冲突返回 409；422 问题使用稳定字段/行 ID，供前端定位。

现有 `/api/sessions/{id}/config` 和 P1-17 生成/重试接口保持兼容；新 Vue 页面只使用安全的来源和编辑接口。

## 7. 前端组件与状态

### 7.1 页面组件

- `SessionConfigView`：工作台容器、标题、阶段选择和恢复入口；
- `ConfigStageRail`：四阶段事实状态，不创造数据库状态；
- `SessionDraftPanel`：新建、重命名和当前考试摘要；
- `ConfigSourceUpload`：上传、替换、解析进度和来源摘要；
- `QuestionBlockReview`：拆题列表、题型修正、排除与长内容展开；
- `ConfigGenerationPanel`：模式选择、Job 进度、部分失败和重试；
- `RubricEditorTable`：高密度行编辑、问题定位和固定保存状态栏；
- `ScoringUnitEditor`：按需编辑 part/step 的次级工作区；
- `ConfigSaveResult`：配置保存与样卷映射刷新结果的分层反馈。

### 7.2 状态仓库

专用 Store 保存：

- 当前 session ID 与阶段；
- source ID、source revision 和安全来源摘要；
- 教师题型/排除差异；
- 当前 config Job ID；
- editor revision、行草稿和评分单元命令；
- 每阶段最近成功事实和可恢复错误。

当前考试仍由现有 Session Store 负责；Job 轮询仍由现有 Job Store 负责。新 Store 不复制网络层或任务状态机。

浏览器只持久化无敏感正文的工作现场。完整题干、答案、题图和模型输入不写入 `localStorage`；刷新后从受控 source API 重新获取公开投影。

## 8. 配置 revision 与并发

- revision 由服务器基于当前 session、rubric 内容、answer key 内容和 source binding 生成不透明摘要；不包含或泄露路径。
- 每次人工保存、完整生成绑定或 AI refine 成功都会产生新 revision。
- 旧人工编辑保存返回 409，服务器不做自动合并，前端保留草稿并提供“重新加载最新版本”前的明确影响说明。
- 生成 Job 的输入同时记录 expected config revision 和 source revision。人工保存、替换来源或更快 Job 先完成后，旧 Job 不得绑定。
- 同一写请求不自动重放；重复点击由提交禁用和服务器幂等/冲突保护共同处理。

## 9. 失败与恢复语义

| 场景 | 必须显示的事实 | 恢复方式 | 禁止行为 |
|---|---|---|---|
| 上传中断或超限 | 文件未接收成功，考试草稿仍在 | 选择文件后重新上传 | 使用残缺暂存文件 |
| 本地解析失败 | 来源已接收或解析失败的明确边界 | 替换文件；可在支持时选择整卷备用模式 | 自动调用 AI 或退回不透明路径 |
| 逐题生成部分失败 | 成功题数、失败题号和可重试性 | 只重试失败题 | 覆盖当前可用配置、重发成功题 |
| 整卷模式失败 | 单次请求失败且未更新配置 | 教师明确重新提交 | 自动重试 |
| 页面刷新 | 已持久考试、source manifest 和 Job 终态 | 恢复阶段；running 重启后按现有规则显示 failed | 把浏览器候选当服务器事实 |
| 保存校验失败 | 阻断问题与对应行/字段 | 修正草稿后再次保存 | 发布半成品 |
| revision 冲突 | 服务器存在较新版本，本地未保存 | 保留草稿；教师决定重新加载 | 静默覆盖或自动合并 |
| 配置发布失败 | 当前可用配置未改变 | 修正故障后重试 | 更新数据库到缺失文件 |
| 配置成功、样卷刷新失败 | 评分依据已保存；样卷映射需要重新确认 | P2-10 完成前回旧入口处理 | 误报评分依据保存失败 |
| 任务取消竞态 | 只有安全边界确认后才显示 cancelled | 终态后决定重提 | 强杀模型线程或只改状态 |

## 10. 安全与隐私

- 所有生产接口继续绑定 loopback；P2-09 不改变部署边界。
- 上传接口不接受客户端目标路径，解析和媒体访问只使用 session/source/question/asset 等语义 ID。
- 公开响应、Job payload/result、日志和文档不得包含绝对路径、密钥、完整试卷正文、题图 base64、富文本关系文件位置或原始异常。
- 浏览器不保存 API Key、完整题干、答案或图像到持久存储。
- 生成、重试和 refine 均通过现有活动 API profile 与统一 LLM Gateway，不新增直连或无限超时。
- 测试和演示只使用临时数据根与假模型；实现任务开始和结束均比较真实两库大小、UTC 时间与 SHA-256，必须不变。

## 11. 视觉与可访问性

- 遵守 `docs/ui/STYLE.md`，使用现有 Token；不增加渐变、营销 Hero、卡片海洋或超大标题。
- 工作台以连续分隔、稳定阶段栏和大面积编辑区组织，不让辅助信息压缩评分表。
- 同一操作区只有一个主按钮；高级整卷模式、评分单元和 AI 完善均为次级入口。
- 字段标签常驻，错误紧邻对应行/字段；状态不只依赖颜色。
- 编辑表支持长中文、长答案、多 part、多 step 和横向信息密度，但页面本身不得产生意外横向溢出；表格内部如需横向滚动必须有清楚边界。
- 所有按钮和图标有可访问名称；键盘焦点可见；输入区域不触发业务快捷操作。
- 验证 1024×768、1280×800、1366×768、1440×900、1920×1080 五档 Windows 桌面视口。
