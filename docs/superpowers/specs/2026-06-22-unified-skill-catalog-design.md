# 统一具体技能目录与错题训练重构设计

日期：2026-06-22
状态：已通过方案讨论，待用户审阅书面规格

## 1. 背景与问题结论

当前系统不是单纯“匹配算法不够准”，而是三套知识身份从源头分离：

- 阅卷评分标准生成临时 `G7_XX` 知识编号和自由文本名称；
- 题库使用 `KP_*` 标准编码、知识点、前置知识、子技能等多种标签；
- 中间的标准知识点库主要是较粗的大类，依靠事后文本映射连接两侧。

真实数据审计结果：

- 当前题库有 477 道题、4,581 条标签；
- 312 道题有 `knowledge_point`，295 道题有 `canonical_knowledge_id`；
- 题库出现 25 种标准编码，但只有 11 种完成确认；
- 标准概念有 70 个，知识关系记录为 0；
- 当前阅卷侧有 17 个活跃薄弱术语、1,326 条聚合证据；
- 现有确认把多个具体技能压入粗大类，例如“角平分线性质”落到“线段与角”，“三角形外心作图”落到“切线与圆的综合”。

因此，即使把确认页面做得更简单，后续选题仍会不贴切。根因是身份和粒度架构不一致，不能继续依靠事后文字桥接解决。

## 2. 已确认的产品决策

用户已确认以下方向：

1. 采用共享“具体技能目录”，允许推翻现有知识图谱匹配实现；
2. 内置初中数学技能目录，遇到本校新技能时自动补充；
3. 普通教师不维护知识图谱，系统内部维护相近技能关系；
4. 新试卷和新题库默认自动归一，只有新增歧义或冲突才要求处理；
5. 现有 477 道题和历史阅卷数据一次性全部迁移；
6. 精确题不足时不静默扩大范围，而是提示教师一次：补入相近题，或保持较少的精确题。

## 3. 设计目标

### 3.1 核心目标

- 同一数学技能在试卷、学生错题和题库中始终使用同一个稳定 `skill_id`；
- 日常导入、批改和生成练习不要求普通教师维护映射；
- 推荐题必须能解释为“这道题直接训练该具体技能”，而不是仅属于同一大类；
- 歧义项不得静默参与精确推荐；
- 历史数据完整保留，迁移可重复、可验收、可回滚。

### 3.2 非目标

- 不建设面向普通教师的可编辑知识图谱；
- 不要求教师理解标准编码、命名空间、置信度或关系权重；
- 本阶段不实现训练结果自动回流更新掌握度；
- 首期内置目录聚焦初中数学，但数据模型允许后续扩展学科。

## 4. 核心模型：统一技能卡

“具体技能卡”是系统中唯一可用于诊断与训练推荐的知识身份。

示例：

```text
技能名称：角平分线性质
所属主题：三角形
适用年级：七年级
稳定标识：skill_id（仅系统内部可见）
别名：角平分线的性质、角平分线定理
来源：内置目录
```

普通教师只看中文主题和技能名称。内部编号、别名、来源、置信度和迁移证据仅用于系统维护。

### 4.1 数据表

#### `skill_topics`

表示适合教师理解的两级目录上层，如“方程”“一次函数”“三角形”“轴对称”。

主要字段：

- `id`
- `stable_key`
- `name`
- `subject`
- `grade_min`、`grade_max`
- `status`

#### `skills`

表示可直接诊断和训练的具体技能。

主要字段：

- `id`
- `stable_key`
- `topic_id`
- `name`
- `aliases_json`
- `grade_min`、`grade_max`
- `origin`：`builtin` 或 `local`
- `status`：`active`、`merged`、`archived`
- `redirect_skill_id`：技能合并后的稳定跳转
- `created_at`、`updated_at`

#### `assessment_item_skills`

记录评分标准中每个题目或小问实际考查的技能。

主要字段：

- `grading_session_id`
- `source_question_id`
- `skill_id`
- `role`：`measured` 或 `supporting`
- `raw_knowledge_id`、`raw_knowledge_label`
- `source`、`confidence`、`evidence_json`
- `status`：`resolved` 或 `conflict`

一道题可有多个 `measured` 技能，但必须至少有一个。学生错题证据直接继承该表，不再创建独立的“学生错题知识图谱”。

#### `question_skill_links`

记录题库题目能直接训练哪些技能。

主要字段：

- `question_id`
- `skill_id`
- `role`：`measured` 或 `supporting`
- `source`、`confidence`、`evidence_json`
- `status`：`resolved` 或 `conflict`

精确推荐只使用 `measured` 链接；`supporting` 只能参与教师明确同意的相近题补足。

#### `skill_resolution_conflicts`

保存真正需要人工判断的少数项目。

主要字段：

- `source_type`：试卷题、题库题或历史术语
- `source_ref`
- `raw_label`
- `candidate_skill_ids_json`
- `reason`
- `state`：`open`、`resolved`、`ignored`
- `resolved_skill_id`、`resolved_by`、`resolved_at`

#### `skill_neighbors`

系统内部维护相近技能，仅用于题量不足时生成补足建议。

主要字段：

- `source_skill_id`
- `target_skill_id`
- `kind`：同主题相近、前置、进阶或共同考查
- `weight`
- `source`：内置、统计或管理员确认

该表不作为普通教师可编辑的“图谱”。

## 5. 自动归一服务

统一服务接收原始名称、题干、答案、评分点、年级和已有标签，输出以下三种结果之一：

```text
resolved_existing：绑定现有技能
created_local：自动创建本校技能并绑定
conflict：不绑定，进入冲突队列
```

### 5.1 确定性通过规则

以下情况无需 AI、直接通过：

1. 已有稳定技能编号一致；
2. 规范化后的名称完全一致；
3. 与已登记别名完全一致；
4. 已有历史来源明确指向一个仍有效的技能，且没有合并冲突。

### 5.2 上下文自动通过规则

文字不完全一致时，AI 必须同时读取题干、答案、评分点、年级和已有标签。仅当同时满足以下默认条件时自动绑定：

- 第一候选置信度不低于 0.92；
- 第一候选比第二候选至少高 0.15；
- 候选年级和主题与上下文一致；
- 没有命中歧义词规则；
- 候选技能不是已归档技能。

不满足任意一项即进入冲突队列，不得以“最接近大类”代替具体技能。

### 5.3 自动新增本校技能

系统允许自动补充本校技能，但必须同时满足：

- 名称具体，能够表达明确数学对象或动作；
- 不是“性质、计算、作图、综合、应用”等单独宽泛词；
- 与现有技能及别名均不等价；
- 能归入一个现有知识主题；
- 有评分点、题干或题库题目的实际证据；
- AI 给出的新技能判断不低于 0.92，且没有竞争候选。

新技能创建后立即获得稳定 `skill_id`，试卷和题库后续均复用。若后来发现重复，通过 `redirect_skill_id` 合并，不修改历史证据引用。

### 5.4 AI 不可用

AI 不可用时仍执行编号、名称和别名的确定性匹配。无法确定的项目进入冲突队列，不阻断试卷批改或题库导入，但在解决前不能参与训练推荐。

## 6. 三条业务数据流

### 6.1 试卷与评分标准

1. 系统生成或导入评分标准；
2. 每道题和小问通过统一归一服务选择技能卡；
3. 无冲突时只显示“已自动识别 N 个训练技能”；
4. 冲突题可以继续批改，但不会用于训练推荐；
5. 评分结果只保存题目证据，技能身份来自 `assessment_item_skills`。

新的评分标准可以保留原始 `G7_XX` 作为显示或来源编号，但它不再承担跨系统知识身份。

### 6.2 题库导入与重新打标

1. 读取题干、答案、解析、已有标签和年级；
2. 为每道题产生至少一个 `measured` 技能，可附加少量 `supporting` 技能；
3. 确定项自动保存；
4. 歧义项进入管理员冲突队列，不要求普通教师逐题确认；
5. 原始 `knowledge_point`、`canonical_knowledge_id` 等标签保留为迁移证据，但不再直接决定推荐资格。

### 6.3 学生薄弱技能与训练推荐

1. 学生得分证据按 `assessment_item_skills.skill_id` 聚合；
2. 题库候选按 `question_skill_links.skill_id` 精确连接；
3. 精确候选仅接受 `role = measured`；
4. 在精确候选内部按难度适配、错误类型、方法多样性、考频和去重排序；
5. 精确候选不足时，不自动使用相近技能；
6. 页面提示“还差 N 道精确题”，教师一次选择：补入相近题，或保持较少的精确题；
7. 补入题必须显示相近技能名称和补入原因，并保存在任务快照中。

## 7. 普通教师体验

### 7.1 默认流程

1. 导入或批改试卷；
2. 系统提示“已自动识别 N 个训练技能”，无冲突时无需点击确认；
3. 选择学生和考试；
4. 查看薄弱技能与精确题数量；
5. 若题量不足，只进行一次“补入相近题 / 保持精确题”选择；
6. 预览、保存并导出练习。

### 7.2 普通教师不再看到

- 知识图谱维护入口；
- 原始词到标准知识点的批量映射表；
- `suggested`、`confirmed` 等英文状态；
- 标准编码、命名空间和置信度阈值；
- 关系编辑器和权重滑杆。

### 7.3 冲突处理

普通教师只在当前操作确实需要时看到中文二选一，例如：

```text
“作图”可能表示：
○ 尺规作图
○ 轴对称作图
```

历史批量冲突由管理员页面集中处理，不进入普通训练流程。

## 8. 管理员能力

原“知识点整理（高级）”替换为“技能目录与冲突”，包含：

- 按主题浏览具体技能；
- 查看本校新增技能及证据；
- 合并重复技能；
- 处理未解决冲突；
- 查看题库和评分标准的技能覆盖率；
- 查看一次性迁移报告和回滚状态。

管理员也不直接编辑完整知识图谱。相近技能关系默认由内置目录和统计生成，只允许查看或停用明显错误关系。

## 9. 一次性历史迁移

### 9.1 迁移范围

- 当前题库全部 477 道题；
- 所有有效评分标准中的题目和小问；
- 当前 17 个活跃阅卷技能；
- 历史训练任务继续使用原任务快照，不重写题目内容。

### 9.2 迁移步骤

1. 停止写入并完整备份两个数据库及评分标准文件；
2. 建立内置初中数学主题与技能目录；
3. 导入现有可靠标准编码和别名作为辅助证据，不直接继承错误映射；
4. 以题干、答案、评分点和旧标签重新标注全部题库题目；
5. 以评分标准上下文迁移全部试卷题目技能；
6. 将旧 `G7_XX`、`KP_*` 和映射记录保存到证据字段；
7. 生成自动通过、自动新增、冲突、无可用证据四类报告；
8. 处理开放冲突；
9. 运行覆盖率、准确率和端到端验收；
10. 验收通过后切换推荐读取路径。

### 9.3 迁移安全

- 迁移先支持 `dry-run`，只生成报告不写数据；
- 正式迁移具有唯一批次号和数据库备份；
- 重复运行同一批次结果必须一致，不产生重复技能或链接；
- 旧 `knowledge_source_mappings` 与 `knowledge_relations` 在首个稳定版本内保留只读，不再参与推荐；
- 回滚时恢复数据库备份并切回旧读取路径；
- 不删除原始标签、评分标准编号、教师历史决定或训练任务快照。

## 10. 错误与边界处理

- **技能歧义**：标记冲突，排除该项精确推荐，不影响其他题；
- **题库无精确题**：显示缺题并提供一次相近题补足选择；
- **新技能过宽**：禁止自动创建，进入冲突队列；
- **技能重复**：合并并建立永久重定向，历史引用仍可解析；
- **题目多技能**：允许多个 `measured` 技能，但不得把一般解题方法冒充主要技能；
- **旧任务导出**：继续从固定快照导出，不受技能迁移影响；
- **AI 服务异常**：确定性规则继续运行，其余项目等待处理；
- **题库数据库不可用**：允许查看诊断，但禁用训练生成，不使用宽泛题凑数。

## 11. 验收标准

### 11.1 数据验收

1. 100% 的有效评分题目和题库题目必须处于“已绑定技能”或“明确冲突”状态，不存在静默未知；
2. 当前 17 个活跃阅卷技能全部进入新目录或冲突报告；
3. 所有精确推荐均能通过同一个 `skill_id` 追溯到评分题和题库题；
4. 自动迁移覆盖率目标不低于 95%；低于该值不得切换生产读取路径；
5. 对自动通过结果抽取不少于 100 条人工金标准，精确率不低于 98%；
6. 迁移前后题目数、评分结果数、学生数和历史任务数一致；
7. 同一迁移批次重复运行不产生额外记录。

### 11.2 用户体验验收

1. 无冲突的试卷或题库导入无需教师确认；
2. 普通训练页面不出现知识图谱、映射、编码、命名空间或置信度术语；
3. 精确题不足时最多要求一次选择；
4. 补入相近题时明确显示“相近补入”，不能伪装成精确匹配；
5. 普通教师日常维护操作数为 0，只有实际歧义产生额外操作。

## 12. 测试策略

### 12.1 单元测试

- 名称、编号、别名的确定性归一；
- 第一候选阈值和候选差值边界；
- 宽泛名称禁止自动建技能；
- 本校技能创建、合并和重定向；
- `measured` 与 `supporting` 推荐资格；
- 相近题补足必须显式授权。

### 12.2 集成测试

- 评分标准题目 → 学生错题证据 → 同 `skill_id` 题库推荐；
- AI 不可用时确定性归一仍工作；
- 冲突题不阻断其他题批改和推荐；
- 技能合并后历史错题和题库链接继续解析；
- 精确题不足时任务快照保存教师选择和补足原因。

### 12.3 迁移测试

- `dry-run` 不修改数据库；
- 正式迁移前自动备份；
- 迁移幂等；
- 旧标签和证据完整保留；
- 关键案例金标准覆盖角平分线、外心作图、最短路径、轴对称、一次函数和全等三角形；
- 回滚后旧系统仍能读取原数据。

### 12.4 页面测试

- 普通教师页面只显示中文主题和技能；
- 无冲突时无确认按钮；
- 冲突时只显示局部中文选择；
- 精确题不足时只出现一次补足决策；
- 管理员页面与普通训练入口隔离。

## 13. 发布顺序

1. 新增技能目录和链接表，不切换现有推荐；
2. 实现统一归一服务，并在新导入数据上双写；
3. 对历史数据运行 `dry-run`，形成冲突和准确率报告；
4. 正式迁移并处理冲突；
5. 新旧推荐并行比对，不向普通教师展示旧映射；
6. 达到验收标准后切换推荐读取路径；
7. 稳定运行一个版本后，移除旧映射逻辑的写入能力；
8. 旧表继续只读保留，直到单独批准清理。

## 14. 方案取舍结论

不选择继续修补现有文本映射，因为它无法消除三套身份和粒度差异；不选择完全依赖 AI 向量相似度，因为结果不稳定且难以解释。共享具体技能目录是唯一同时满足精确、可解释、低操作量和可迁移性的方案。
