**日期：** 2026-07-16
**执行包：** P2-10
**设计基线：** `cdf74012faf1decb60b2d76b6bd5f6714d7734c3`
**依赖：** P2-09、template/regions API、Phase 2 前端来源重校准（均已进入 `origin/main`）
**风险级别：** 高
**数据影响：** 写入考试专属样卷文件、答题区草稿和既有答题区表；无数据库迁移
**已由权威资料确定：** P2-10 包含样卷上传与正反面选择；P2-11 才负责整班答卷上传、扫描预检和批改任务。

## 1. 页面任务与范围

本页服务于本机单用户教师。它只有一个任务：在正式批改前，把扫描 PDF 的前两页确认为样卷正反面，并把每个作答区域准确绑定到已保存的题号或小问。

完整成功结果必须同时满足：

1. 当前考试已有受控的正反面样卷；
2. 每个正式答题区都在对应样卷范围内，并已绑定题号；
3. 同题多框已经人工确认；
4. 提交时使用的样卷没有被替换；
5. 数据库正式答题区与 confirmed snapshot 一致；
6. `DBManager.is_template_ready(session_id)` 为真，后续扫描与批改才可开始。

本包不上传或处理整班答卷，不启动扫描/批改 Job，不改变题号、评分规则、几何校验算法或数据库 Schema，也不退役旧 Streamlit 编辑器。

| 自动与手动题号绑定 | `load_question_binding_catalog()`、`_bind_only_new_unbound_regions()` | 只使用当前已保存 rubric/answer key 中的题号与小问；新框按未使用候选顺序自动绑定 | 无候选时保持未绑定；不猜造题号 | 右侧题框清单可定位、绑定、删除；状态同时用文字和颜色 |
| 同题多框确认 | `validate_regions()`、旧编辑器 `multi_region_confirmed` | 一个题号对应多个框必须经教师确认 | 未确认时阻止完成，草稿仍可保存 | 在题框清单中按题号聚组确认 |
| 保存草稿 | `AnswerRegionDraftService.save()`、现有 draft API | 草稿不是正式批改输入；revision 只表示当前草稿演进 | 并发锁或网络失败不丢浏览器内编辑；重载后比较服务器草稿 | 完成一次画框/移动/缩放/绑定后延迟保存；显示保存中、已保存、保存失败 |

| 重试待处理快照 | `retry_pending_snapshot()`、`regions_snapshot_pending` | 只补写已提交正式区域的本地快照，不重复提交区域 | 仍失败时保留待处理状态 | 只读确认态提供单一“重试生成确认快照”操作 |

## 3. 方案比较与采用方案

### 方案 A：全部塞入现有 `/sessions` 长页面

优点是少一个路由；缺点是 P2-09 的上传、拆题、AI 生成、评分依据表格与大画布共享滚动，1024px 下很难判断当前操作属于哪一阶段，也无法可靠恢复编辑器焦点。不采用。

### 方案 B：配置页增加第五阶段，并进入考试专属专注路由（采用）

`/sessions` 在评分依据已保存后显示第五阶段“样卷与答题区”，当前考试卡片提供状态摘要和“准备样卷/继续标定/查看已确认版本”。实际编辑进入 `/sessions/{sessionId}/regions`，仍归属“考试配置”导航，不新增主导航栏目。该路由可刷新、深链接、返回配置页，并给画布稳定的可用高度。

### 方案 C：全屏弹层

实现接线较少，但刷新、浏览器返回、错误恢复和焦点陷阱都不清楚；提交成功后的只读确认态也没有稳定地址。不采用。

## 4. 页面结构与视觉计划

主题是“教师在批改前校准扫描坐标”，不是通用图片标注器。页面使用项目既有 Token：纸面白 `#ffffff`、工作台灰 `#f6f7f8`、墨色 `#20242a`、边界灰 `#d9dde2`、选择蓝 `#2563eb`、警告棕 `#9a6718`。字体继续使用 Inter / 苹方 / 微软雅黑系统栈；不引入字体、渐变、发光或装饰动画。

唯一的辨识性元素是“装订边状态尺”：画布左缘以窄竖列按正面/反面显示已绑定、待处理和异常题框数量，像教师在纸卷边缘贴的索引签。它只编码真实状态并可点击切面，不增加业务含义。其余界面保持安静。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← 返回考试配置  当前考试 / 样卷与答题区   草稿状态  [完成标定]       │
├──────────────────────────────────────────────────────────────────────┤
│ 未上传时：PDF 上传 + 第一页面别 + 安全说明 + 当前模板状态             │
├──────┬───────────────────────────────────────────────┬───────────────┤
│正面  │                                               │ 题框列表      │
│ 8/1  │       可缩放、可拖动的样卷画布                │ 题号绑定      │
│反面  │       框标签、选中手柄、创建预览              │ 校验问题      │
│ 7/0  │                                               │ 同题多框确认  │
├──────┴───────────────────────────────────────────────┴───────────────┤
│ 当前模式 / 坐标 / 缩放 / 自动保存状态 / 下一项建议                   │
└──────────────────────────────────────────────────────────────────────┘
```

- 1280px 及以上：状态尺 + 画布 + 约 320px 题框清单；画布拥有最大面积。
- 1024px：状态尺收窄，题框清单可折叠为覆盖抽屉；页面不横向溢出。
- 只允许画布和题框清单两个清晰滚动边界；工具栏与状态栏固定在编辑器自身边界内。
- 键盘焦点可见；`Delete` 只在画布焦点且已选择框时删除；`Esc` 取消当前绘制；撤销/重做与页面返回不冲突。
- 动画只用于抽屉短暂过渡，并尊重 `prefers-reduced-motion`。

自检结论：没有采用营销 Hero、卡片海洋、超大标题或任意渐变；“装订边状态尺”来自双面试卷校准任务，若移到普通后台页面便失去意义，因而不是通用模板装饰。

## 5. 后端契约设计

### 5.1 样卷上传与安全读取

- 新增浏览器可用的 `POST /api/sessions/{id}/template`：受控流式接收 PDF、`first_page_role` 和客户端请求令牌；限制扩展名、MIME、字节数和至少两页。
- 复用 P2-09 的请求令牌保留/查询/放弃模式，写请求不自动重放。响应丢失时先按令牌查询；只有服务器原子保留一个从未使用的令牌后，页面才允许解除未知状态。
- 转换、映射包生成和替换在考试专属临时目录与 `AnswerRegionSessionLock` 内完成；失败不得覆盖旧正式模板。
- 新模板成功激活时，旧正式区域仍可作为历史确认版本读取，但不得被标为当前可批改；与新指纹不兼容的草稿不自动恢复。
- 新增 `GET /api/sessions/{id}/template/pages/{front|back}`，只从当前考试模板解析文件并流式返回受支持图片；响应和错误不暴露路径。
- 现有 PUT 本机路径绑定只保留给兼容测试/内部调用，不作为 Vue 入口；公开模板响应改用安全文件名、受控 URL、尺寸、指纹和状态，不返回绝对路径。

### 5.2 编辑工作区读取

新增单一读取入口 `GET /api/sessions/{id}/regions/workspace`，返回：

- 当前模板 ID、指纹、正反面尺寸和受控图片 URL；
- 正式区域、草稿状态与兼容草稿；
- 自动题号候选与手动题号选项；
- 当前校验 issues、`template_ready`、`regions_snapshot_pending`；
- 安全状态文案所需字段，不返回草稿路径、快照路径、rubric 路径或内部 JSON。

损坏草稿仍由服务隔离，但 API 只返回 `corrupt` 及“从正式版本重新开始”的动作，不返回隔离文件路径。不兼容草稿返回 `incompatible`；丢弃必须是显式写操作。

### 5.3 草稿与提交

- 草稿 PUT 增加 `expected_template_fingerprint` 和 `expected_revision`；模板已替换或服务器 revision 已前进时返回 409，不覆盖较新草稿。
- 提交继续复用 `AnswerRegionCommitService`，并把 lock timeout、模板变化和校验 issues 映射为稳定错误代码。
- 正式提交成功而快照补写失败继续返回 `committed=true, snapshot_pending=true`，前端进入只读确认态。
- 新增安全的快照重试端点，只消费 session ID 和当前模板指纹。
- 所有写接口只操作测试临时目录或产品考试专属目录；开发验证绝不指向根工作区真实 `user_data/`。

## 6. 前端状态与核心复用

- Vue 组件复用 `components/answer_region_editor/editor.js` 的坐标换算、边界夹取、UUID 对账、撤销历史和 DOM 编辑控制器；允许把 Streamlit 的 `setStateValue/setTriggerValue` 适配为 Vue emit，但不复制或重写几何算法。
- 页面 store 只持久化 session ID、当前模板指纹和无敏感视图状态；区域草稿以服务器为恢复来源，浏览器内未保存编辑只驻留内存。
- 每次完整画框、移动、缩放、删除、绑定和同题多框确认后增加本地 revision；短暂合并后保存，切换考试或离开页面前若尚未保存则明确提示。
- 旧请求必须按 session ID + template fingerprint + load generation 隔离，不能把上一考试或上一模板的草稿写入当前画布。
- 提交成功后编辑控件变为只读，保留正反面查看、缩放、题框定位和确认摘要；重新编辑必须通过明确动作从正式版本建立新草稿。

## 7. 状态、失败与恢复

| 状态 | 页面行为 |
|---|---|
| 无考试 | 返回考试配置并提示先创建考试 |
| 无评分依据 | 显示 P2-09 尚未完成，不允许上传样卷 |
| 无样卷 | 显示上传步骤，不渲染空编辑器 |
| 上传中 | 锁定重复上传；离开页面前提示；不显示未激活临时模板 |
| 上传结果未知 | 按请求令牌查询；不能直接重传 |
| 兼容草稿 | 要求选择继续草稿或从已确认版本重新开始 |
| 不兼容/损坏草稿 | 不进入编辑；允许显式丢弃并从正式版本开始 |
| 草稿保存失败 | 保留浏览器内编辑、显示重试；不称为已保存 |
| 409 冲突 | 停止自动保存，提供加载服务器版本或保留当前内容供人工处理，不自动覆盖 |
| 校验失败 | 打开题框清单并定位所有 issues；一次展示全部去重问题 |
| 已提交、快照待处理 | 进入只读确认态，明确“正式区域已保存”，仅重试快照 |
| 完全确认 | 显示可进入 P2-11 的事实状态，但不实现 P2-11 操作 |

## 8. 建议测试缝（待用户确认）

`tdd` 只在以下公开边界写测试：

1. **HTTP API：** 从上传 PDF、读取安全工作区、保存草稿到正式提交/快照重试，观察公开响应与随后公开读取结果。
2. **编辑器组件：** 通过原生 JS/Vue 组件的输入、用户事件和输出验证原图坐标、正反面、绘制/移动/缩放、绑定、撤销与只读态；不测试私有函数调用次数。
3. **页面工作流：** 在 Vue 路由层验证 P2-09 后进入第五阶段、刷新恢复、旧响应隔离、冲突和失败文案。
4. **真实浏览器：** 用匿名合成 PDF 和临时数据库完成上传—画框—绑定—提交，覆盖不同图片尺寸和五档桌面视口。
5. **持久化一致性：** 通过 `AnswerRegionCommitService` 与 `DBManager` 的公开读写接口验证正式区域、模板 ready 状态和 snapshot 内容一致。

不把实现内部 helper、DOM 查询顺序、CSS 类数量或 mock 调用次数作为测试边界。

## 9. 验收、回退与停止条件

- 包内聚焦：模板上传服务、API 契约、既有 answer region models/draft/lock/commit、editor core、Vue unit 与 P2-09 受影响回归。
- 浏览器：至少覆盖 1920×1080、1440×900、1366×768、1280×800、1024×768；不同模板尺寸；鼠标与键盘；刷新；并发冲突；快照补写失败。
- 稳定候选后并行进行需求复审和代码质量复审；Critical/Important 统一汇总后成批修复，只复测影响面并做一次最终复审。
- 功能分支交接前运行快速冒烟；integration 合并后只运行一次完整门槛和前端全套命令，并比较真实两库指纹。
- 回退为撤销 P2-10 功能提交并继续使用旧 Streamlit 编辑器；不删除既有模板、正式区域或草稿。
- 若发现必须改变评分规则、题号语义、区域几何算法、数据库 Schema，或需要真实数据/真实模型验证，立即停止并请求用户决定。
