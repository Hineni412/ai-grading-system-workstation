# P2-14 工作台与分析总览设计

## 1. 目标与边界

P2-14 把现有考试进度、待复核、异常卷、最近考试、班级/题目/学生分析和知识标签覆盖情况组织成一个只读教师工作台。教师先看到当前考试最需要处理的事实，再从同一上下文进入已有复核、异常详情、题目明细、学生明细或知识证据。

本包采用用户于 2026-07-15 确认的“精修方案 B”：分析总览优先，动作条紧邻关键数字，每个图表都必须有可执行的下钻或等价文字明细。页面不是装饰性数据大屏，不新增 KPI、统计口径、业务状态、自动建议或写操作。

P2-14 只增加必要的只读聚合接口和 Vue 展示。它不修改评分、复核、异常处理、Job 取消/重试、会话配置、Rubric、数据库 Schema 或真实业务数据。

## 2. 权威依据与已确认决定

- `AGENTS.md`、`ARCHITECTURE.md` 和 Phase 2 来源重校准结果规定业务事实、安全边界与前端迁移原则。
- `docs/superpowers/packages/phase-2-execution-packages.md` 定义 P2-14 的稳定目标、范围、依赖、验收和回退边界。
- `docs/ui/STYLE.md` 只约束安静、专业、高密度、适合 Windows 工作机的视觉质量，不单独证明任何业务能力。
- `web_app.py` 的考试阶段摘要、按题号复核、异常卷处理、`render_export_tab`、`_build_session_question_analysis` 及其辅助函数是现有可见行为与统计口径来源。
- `DBManager`、`backend/review/service.py`、Job Store、Graph 服务、现有 API schemas/routers 和相应测试是数据语义、筛选、排序、脱敏和错误契约来源。
- 用户于 2026-07-15 明确确认：P2-14 的既有依赖满足，可以与 P2-09 并行开始；采用精修方案 B；允许补齐只读工作台、Job 列表、异常明细和现有分析口径接口，但不得新增 KPI、数据库结构或写语义。

## 3. 业务能力与 UX 设计溯源表

| 可见能力 | 业务事实来源 | P2-14 呈现与动作 | 明确边界 |

| 班级/学生入口 | 会话结果、班级字段与现有筛选行为 | 从总览进入当前考试的班级、题目、学生分析明细 | 不引入学生画像、跨考试推断或 Phase 6 身份体系 |

| 报表导出入口 | Streamlit 报表导出既有能力与 Job 文件契约 | 仅在已有可达页面存在时提供明确跳转 | P2-14 不生成或下载新报表，不伪造未来入口 |

任何没有进入本表且无法回溯到上述事实来源的业务字段、状态、按钮或分析结论都不得进入实现。纯布局、信息层级和只读下钻控件可以在不改变结果的前提下重组。

## 4. 方案比较与选择

### 方案 A：任务列表优先

先呈现进行中任务、待复核和异常卷，再把分析压到页面下方。它适合纯操作队列，但教师查看学情时需要更多滚动，分析与动作之间距离较远。

### 方案 B：分析总览优先（采用）

当前考试、已有关键计数和紧邻动作条构成首屏；下方用班级/题目分析、学生明细和标签覆盖形成连续阅读路径。所有图表同时提供文字摘要、样本量和明确下钻。

精修后采用该方案，因为它兼顾“先判断现状”和“立即进入处理”，同时避免卡片海洋和装饰性大屏。它不改变任何业务结果，只重组已经有依据的只读信息。

### 方案 C：图表画布优先

以大面积可视化为中心。它会挤压高频操作和表格证据，容易制造“高级但不可执行”的展示，也更可能诱发无来源指标，因此不采用。

## 5. 页面信息架构与视觉方向

### 5.1 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 工作台 / 当前考试选择 / 数据更新时间 / 刷新                 │
├──────────────────────────────────────────────────────────────┤
│ 批改进度    待复核    异常卷    最近任务                    │
│ [查看批改]  [去复核]  [看详情]  [查看任务]                  │
├───────────────────────────────────┬──────────────────────────┤
│ 班级与题目分析                    │ 最近考试                 │
│ 班级筛选 / 文字摘要 / 样本说明    │ 状态、时间、进度         │
│ 得分率分布或等价表格              │ 切换当前考试             │
│ 题目矩阵 → 题目/学生明细          │                          │
├───────────────────────────────────┼──────────────────────────┤
│ 当前题目学生明细 / 证据入口       │ 标签覆盖 / 证据列表入口  │
└───────────────────────────────────┴──────────────────────────┘
```

- 使用现有 App Shell、设计 Token、字体和控件，不创建第二套导航或视觉系统。
- 首屏只有一组紧邻数据的动作，不用成排大圆角卡片、渐变、强阴影、营销式标题或装饰图标。
- 图表只在比表格更易比较时使用；每个图表必须同时有可读标题、样本量、口径说明、文字摘要和表格/明细入口。
- 颜色不是唯一信息编码。状态同时显示文字，图表差异使用标签、数值或形状辅助。
- 1024px 桌面宽度下改为单列连续区块，保持筛选器、摘要和主动作可见；不做移动端产品适配。

### 5.2 首屏数字

首屏只展示已有接口能直接支持且教师能采取动作的事实：

- 现有批改进度与组成计数；
- review API 返回的待复核数量；
- 现有异常类别计数；
- 当前考试关联 Job 的既有状态摘要。

不得把缺失数据推导为 0，不得自行计算同比、环比、风险分、质量分、排名、预测完成时间或“AI 建议”。小样本必须显示实际样本量和“样本较少，仅供核查”的说明。

### 5.3 视觉系统与识别性元素

本页不另创全站主题，颜色直接取自现有教师工作台 Token，并限制为六个有职责的值：应用背景 `#f6f7f8`、内容表面 `#ffffff`、主文字 `#20242a`、轻边界 `#d9dde2`、行动强调 `#2563eb`、确有异常时使用的警示 `#9a6718`。成功和危险色只在对应既有状态出现，不能用于装饰图表。

字体不新增网络资源。中文正文沿用 `PingFang SC / Microsoft YaHei / Noto Sans CJK SC`，英文和数字沿用 `Inter / Segoe UI`；数据使用等宽数字特性 `font-variant-numeric: tabular-nums`，让进度和分数纵向对齐。页面标题 22—24px，区块标题 18—20px，正文 14px，密集数据 13px，辅助说明 12px，均取自现有规范。

页面唯一的识别性元素是“批改进度—行动带”：用一条连续、低对比的水平基线串联批改进度、待复核、异常卷和最近任务；每个节点只显示已有事实、状态文字和一个紧邻动作。它借用教师检查试卷时从“完成、待核、异常、后续”逐项过目的真实节奏，不是四张互不相关的统计卡。1024px 下它转为带有同一基线语义的纵向列表。

动效只用于考试切换后一次 120—180ms 的内容淡入，以及进度值更新的轻微过渡；遵循减少动效设置，不使用滚动揭示、数字翻牌或持续动画。

通用仪表盘风险复核：大数字卡片、彩色图标、渐变背景、均匀四宫格和无动作图表均已排除。方案的辨识度来自连续进度—行动带、题目矩阵和证据下钻这一组与阅卷任务直接对应的结构；其他区域保持安静，让唯一的视觉强调服务“下一步去哪儿”。

## 6. 只读数据与 API 设计

### 6.1 分层原则

采用三层只读数据模型：

1. 工作台概览：快速返回当前考试和最近考试所需的已有计数、状态与动作上下文。
2. 会话分析：按班级、题目和学生返回与 Streamlit 现有公式等价的分析行和明细。
3. 标签证据：直接复用 P1-21 Graph API，不复制 Graph 计算或提前实现 P2-15。

概览先加载；分析和标签证据独立加载。一个区块失败不得阻塞其他区块，也不得把错误伪装成空数据。

### 6.2 工作台概览接口

新增只读 `GET /api/workbench/overview`，以可选 `session_id` 和 `recent_limit`（1—20，默认 5）为输入。响应只包含前端展示所需的稳定摘要：

- 当前考试的 session summary 和现有 progress；
- review questions 汇总得到的待复核题目数、明细数；
- 现有异常类别计数与可用只读明细标识；
- 与该考试关联的最近 Job 安全摘要；
- 最近考试的 session summary 与可用 progress 摘要。

服务层复用 sessions/review/jobs 的既有查询和状态，不通过内部 HTTP 自调用。响应不得返回数据库路径、文件路径、模型请求正文、原始 Job payload/result/error、学生正文或其他不需要的敏感字段。

### 6.3 Job 列表接口

新增只读 `GET /api/jobs`，为工作台补齐 Job 列表能力。它必须：

- 支持按 `session_id`、已有 `job_type`、已有 `status` 过滤和稳定分页；
- 只返回 Job ID、类型、状态、进度、阶段、脱敏详情和时间字段；
- 用现有 Job Store 的倒序/稳定排序规则，不新建第二套任务状态；
- 关联考试时只读取既有 payload 中已经存在且可安全解析的 `session_id`，不修改 payload；
- 不提供取消、重试、提交或下载动作，不回显内部错误和路径。

现有 `GET /api/jobs/{job_id}` 契约保持兼容。列表响应使用专门的安全摘要 schema，不能直接复用包含 payload/result/error 的完整 `JobResponse`。

### 6.4 异常卷只读接口

新增只读 `GET /api/sessions/{session_id}/anomalies`，补齐当前考试的异常卷明细读取。接口只返回 Streamlit 现有预检/异常处理已经识别的类别、受控显示名、只读状态和安全标识，支持稳定分页。

接口不得接收或返回任意文件系统路径，不读取图像正文，不改变匹配、空白/无效标记、预检或重跑状态。若当前存储只能提供计数而无法安全列出明细，页面显示“有异常记录，请进入既有异常处理页查看”，不得构造虚假列表。

### 6.5 会话分析接口

新增只读 `GET /api/sessions/{session_id}/analysis/questions`，支持班级筛选、题目筛选和稳定分页；新增 `GET /api/sessions/{session_id}/analysis/questions/{question_id}/students`，按可选班级筛选返回该题学生得分、扣分和受控证据标识。两个接口共享同一分析服务和规范题号规则。

统计规则必须从现有函数抽到可复用服务并保持等价：

- 以 `(class_name, canonical_question_id)` 分桶；缺失班级仍显示“未分班”；
- 子题按 `_canonical_question_id_for_score` 归并到已有 score map 的父题；
- 同一规范题号的得分相加，超过已有满分时按原规则封顶；
- 满分优先使用 score map；无法取得满分时沿用现有非负回退；
- 班级得分率为 `score_sum / full_sum * 100`，保留两位小数；
- 平均得分为 `score_sum / attempt_count`，保留两位小数；
- 失分判定继续使用 `deduction > 0.01`；
- 失分人数和学生扣分来自同一明细，不新增“难题”“薄弱生”等结论；
- 排序继续使用班级和 `_question_sort_key`，综合视图继续使用现有合并规则。

API 对“无数据”“未批改”“满分配置缺失”“样本较少”使用明确状态/说明。未知或不可计算值返回 `null` 与原因，不自动返回 0。

### 6.6 Graph API 复用

标签覆盖区调用现有 graph profiles/rows/evidence 契约。P2-14 只显示 tag-only 的覆盖数字、文字摘要和证据列表入口，不在工作台生成力导向图、关系推断、掌握度新模型或训练建议。

## 7. 前端数据流与组件职责

### 7.1 加载顺序

1. 从 App Shell 当前考试上下文读取 `session_id`。
2. 请求工作台概览，首屏可用后立即呈现。
3. 独立请求当前会话分析；教师更换班级/题目时只刷新对应分析数据。
4. 标签区进入视口或明确展开时读取 Graph 摘要/证据。
5. 切换考试时取消或作废旧请求，重置筛选到该考试的有效默认值。

每类请求拥有独立 loading/error/empty/stale 状态。请求世代或 `AbortController` 必须保证旧考试响应不能覆盖新考试内容。

### 7.2 建议职责划分

- `frontend/src/views/WorkbenchView.vue`：编排页面区块、当前考试上下文和 URL 筛选，不包含统计公式。
- `frontend/src/components/workbench/WorkbenchSummary.vue`：进度、复核、异常、Job 安全摘要与紧邻动作。
- `frontend/src/components/workbench/RecentSessions.vue`：最近考试和上下文切换。
- `frontend/src/components/analysis/QuestionAnalysisPanel.vue`：班级/题目筛选、文字摘要、图表或等价表格。
- `frontend/src/components/analysis/QuestionAnalysisTable.vue`：旧口径题目矩阵和稳定选择。
- `frontend/src/components/analysis/StudentAnalysisDetail.vue`：当前题目的学生明细与证据/复核跳转。
- `frontend/src/components/analysis/TagCoverageSummary.vue`：Graph 摘要和证据入口。
- `frontend/src/services/workbench.ts`、`analysis.ts`：响应运行时校验和脱敏错误转换。
- 独立 Pinia store 或组合函数只保存当前浏览器会话中的筛选和最后成功响应，不写 localStorage，不缓存学生正文。

具体文件可在即时实现计划根据最新源码调整，但不得把后端统计公式复制到 Vue。

## 8. 动作与路由边界

- “去复核”进入已实现的阅卷复核页，携带当前 `session_id`，有题目上下文时附带受控题目筛选。
- “查看异常”打开只读异常明细；真正处理、匹配或重跑仍进入 P2-11 的既有/后续安全流程。
- Job 只允许查看状态和安全详情；P2-14 不出现取消、重试或提交按钮。
- 点击题目图表/矩阵行，在同页或已定义分析路由展示该题学生明细；点击学生可进入现有证据/复核上下文。
- 点击标签覆盖进入现有证据列表；完整知识图谱交互留给 P2-15。
- 点击最近考试只切换当前考试上下文，并重新加载对应只读数据。
- 若目标页面尚未由已合并包提供，显示不可误解的说明，不创建能点击但没有业务结果的未来入口。

所有跳转参数都使用已验证 ID/枚举，不接受路径、任意 URL 或原始查询片段。

## 9. 加载、空态、部分失败与恢复

- 首次加载使用稳定骨架或行占位，不让页面结构跳动。
- 无考试、考试未批改、确实无待复核、确实无异常、无标签、分析无明细分别使用不同文案。
- 单区块失败时保留其他成功区块；若该区块曾成功，保留最后成功内容并标记更新时间和“数据可能不是最新”，提供重试。
- 切换考试立即标记旧内容失效；不得在新考试标题下继续显示旧考试数字。
- 401/403、404、数据库暂不可用、响应格式不符和普通网络失败使用现有安全错误契约，不显示堆栈、内部路径、SQL、模型正文或响应原文。
- 图表加载失败时文字摘要和表格若仍有数据则继续可用；视觉组件失败不能吞掉原始明细。
- 刷新只重试失败或过期的只读请求，不触发任何 Job 或写操作。

## 10. 可访问性与桌面视口

- 所有数字都有文字名称和单位；图表有同义文字摘要、样本量和表格替代。
- 交互图形元素可键盘聚焦并有可见焦点，Enter/Space 的结果与点击一致。
- 状态、异常和选择不只依赖颜色；颜色对比度、焦点和减少动效遵循 `docs/ui/STYLE.md`。
- 表格使用真实表头、排序说明和可读的当前选择；长学生姓名、班级和题号不覆盖操作。
- 验证五档桌面视口：1024×768、1280×720、1366×768、1440×900、1920×1080。
- 1024px 下允许内容纵向排列和表格受控横向滚动，但不能隐藏主要筛选、摘要、下钻动作或错误恢复。

## 11. 测试与验收

### 11.1 后端契约与公式等价

- 用临时数据库构造多班级、未分班、父子题、满分封顶、零/缺失满分、正常/失分、空结果和小样本。
- 对同一合成输入比较抽取后服务与原 `_build_session_question_analysis` 的班级、题号、满分、得分率、平均分、失分人数、排序和学生扣分结果。
- 验证 overview、Job 列表、异常明细和分析接口的过滤、分页、稳定排序、404/空态、数据库故障与响应脱敏。
- 验证 API/OpenAPI 不暴露路径、原始 payload/result/error、学生作答正文或其他不需要字段。
- 验证只读请求前后临时双库指纹不变，不调用模型、不创建 Job、不写文件。

### 11.2 前端组件与状态

- 运行时 schema 拒绝缺字段、错误枚举和非有限数字；错误详情不原样渲染。
- 概览先显示，分析/Graph 延迟或失败时其他区块仍可操作。
- 快速切换考试、班级和题目时旧响应不能污染新上下文。
- 最后成功内容、更新时间、过期提示和重试行为正确。
- 无数据、未批改、未知、小样本、部分失败和真实 0 分别显示，不混为 0。
- 每个动作导航到已有目标并保留受控上下文；没有未来空链接。

### 11.3 浏览器与视觉

- 使用完全合成、匿名、固定种子的演示数据覆盖正常、空白、小样本、部分失败、长中文和密集列表。
- Playwright 验证五档桌面视口、键盘顺序、焦点可见、图表文字替代、表格滚动和路由下钻。
- 截图和非空像素检查确认不是空白占位；人工检查无装饰性大屏、卡片海洋、渐变和被遮挡动作。
- 用户验收清单只有在功能实现并验证后创建，绑定最终候选 SHA 和明确关闭方式。

任何测试、截图或演示不得读取或写入真实 `user_data/`；只使用临时数据库、合成数据和受控假服务。

## 12. P2-09 并行所有权与集成规则

P2-09 与 P2-14 可以从同一最新共同基线并行，但不在同一功能 worktree 实施。

| 范围 | P2-09 所有权 | P2-14 所有权 | integration 所有权 |
|---|---|---|---|
| 后端业务 | 会话/配置/Rubric 的读取与写入、上传/生成流程 | 工作台、分析、Job 安全列表、异常只读聚合 | `backend/api/app.py` 路由注册、共享依赖/OpenAPI 的最终合并 |
| 前端页面 | 考试配置与 Rubric 编辑相关页面、服务和测试 | 工作台与分析组件、只读服务和测试 | `navigation.ts`、router、App Shell/Topbar、共享 session/jobs 接线 |
| 工程文件 | P2-09 专属依赖与测试配置 | P2-14 专属依赖与测试配置 | `package.json`、锁文件、Playwright/Vite 等共同配置的最终合并 |
| 文档 | P2-09 即时计划、证据与验收 | P2-14 即时计划、证据与验收 | `ARCHITECTURE.md`、`EXECUTION_INDEX.md` 和组合证据 |

功能分支不抢改对方专属文件。无法避免的共享入口只提交最小接线改动，并在交接块列出，由 integration 一次合入一个包、解决冲突、运行组合回归和完整冒烟。任何共享文件冲突不得用整文件覆盖解决。

## 13. 数据安全、回退与非目标

### 13.1 数据安全

- 所有开发、测试、截图和冒烟只使用临时副本或合成数据。
- 不修改、暂存、提交、stash 或打包真实 `user_data/`。
- 不记录内部绝对路径、数据库连接、Job 原始内容、学生作答正文、密钥或模型请求。
- P2-14 不包含数据库迁移；若实现发现必须改 Schema，立即停止并重新评审包边界。

### 13.2 回退

P2-14 是只读增量。回退时移除 Vue 路由/导航接线、只读 router/service/schema 和对应测试，保留现有 sessions/review/jobs/graph 接口及 Streamlit 行为。因为不做迁移和写入，回退不需要恢复业务数据。

### 13.3 非目标

- 不实现消息中心、智能体建议、自动诊断、趋势预测或新 KPI。
- 不实现 P2-09 的会话配置/Rubric、P2-10 的考试管理写操作、P2-11 的异常处理写操作。
- 不实现 P2-15 的完整知识图谱、P2-17 的组卷、P2-18 的训练推荐或 Phase 6 学生画像。
- 不修改评分算法、复核判断、报表公式、Job 状态机、权限、安全确认或数据库结构。
- 不用视觉概念图、演示数据或前端已有占位能力反向定义业务事实。
