# 题库打标签配置只读化设计

## 背景与根因

题库页已经显示本机配置文件路径，但左侧控件和打标签启动校验仍以 Streamlit `session_state` 为主要来源。页面只在会话键首次不存在时读取磁盘，因此旧会话中的空值会覆盖本地文件内已经保存的完整配置，造成“文件已配置、界面为空、无法开始打标签”。

本次只修复题库打标签配置的读取、展示和启动判断，不改变配置字段、AI 打标签业务流程、数据库结构或 API 调用协议。

## 已确认目标

- `%LOCALAPPDATA%/AIGradingSystem/config/api_profiles.json` 是题库打标签配置的唯一可信来源。
- 每次进入题库页及页面交互重跑时，重新读取当前配置；旧会话值不能覆盖磁盘值。
- 左侧展示现有 `tagging_*` 字段，不新增重复配置字段。
- 所有配置控件只读。API Key 使用密码遮罩，并保留临时查看能力；其余字段直接展示。
- 页面不再提供保存或清除入口；配置变更只能通过本地文件完成。
- 打标签启动校验、并发与 RPM、写入进程环境以及实际 AI 服务使用同一份最新磁盘配置。

## 实现设计

### 配置读取

复用 `ApiProfileStore` 和现有活动配置选择规则读取最后一个配置方案。页面每次重跑都生成一份当前配置快照，不把 `session_state` 当成持久化来源。

为了兼容现有调用，页面可以把快照同步到已有的 `tagging_*_input` 会话键和进程环境，但同步方向只能是“磁盘到会话/环境”。就绪判断和运行参数仍直接依据本次磁盘快照，避免会话状态重新成为第二套事实来源。

### 只读界面

保留当前配置区域和文件路径提示，将 API Key、Base URL、模型、最大并发、RPM、Thinking 及复核模型字段设为禁用状态。移除“保存打标签配置”“清除打标签 API 密钥”及其确认状态逻辑，并明确提示“如需修改，请编辑上方本机配置文件后刷新页面”。

### 启动流程

用户点击批量打标签时会触发页面重跑，因此先重新读取文件，再执行就绪校验。配置完整时直接开始；缺少 API Key、Base URL 或模型时阻止调用并列出缺失项。并发与 RPM 从同一快照读取并保持至少为 1。

### 错误处理

- 文件不存在：提示本机配置文件不存在，阻止打标签。
- 主文件和备份均无法解析：显示可理解的读取错误，页面其他题库功能继续可用。
- 必填字段缺失：列出缺失字段，不输出任何密钥内容。
- 配置完整：显示“已从本机配置加载”，允许打标签。

## 测试与验证

- 回归测试：预置完整磁盘配置和空会话值，确认磁盘值覆盖旧会话值。
- 就绪判断测试：完整配置可启动；缺少任一必填字段时不可启动并给出对应提示。
- UI 契约测试：配置控件为只读，页面内不再出现保存和清除入口。
- 现有配置存储、题库打标签和导入流程相关测试全部通过。
- 在真实 Streamlit 页面验证：只读字段显示最新配置、API Key 默认遮罩、按钮可进入实际打标签流程且控制台无相关报错。

## 兼容性与范围

- 不迁移或改写现有 JSON 文件。
- 不修改 `api_profiles.json` 字段结构。
- 不修改题库数据库、标签模型输出或并发执行器。
- 该变化属于局部配置读取与 UI 行为修复，不改变系统模块边界，因此无需更新 `ARCHITECTURE.md`。
