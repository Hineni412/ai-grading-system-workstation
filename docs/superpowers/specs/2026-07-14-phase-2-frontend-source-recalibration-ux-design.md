# Phase 2 前端来源重校准与修正 UX 设计

**日期：** 2026-07-14

**状态：** 已获用户批准，可据此生成即时实现计划

**适用范围：** P2-03～P2-08 已实现 Vue 前端的来源重校准与修正

**批准记录：** 用户在审阅三种方案及修订版方案 A 后明确回复“批准”

## 1. 目标与边界

本次工作修正 P2-03～P2-08 已实现 Vue 前端的业务来源、信息架构和复核主流程，使其重新以现有 Streamlit、服务实现、数据库契约和测试为业务事实来源。

本设计遵守以下边界：

- 按题号批量复核是默认主流程，单份详情仅作为可选深查。
- Vue 现有行为只作为待核验能力清单、审计输入和复用候选，不单独证明业务事实。
- 可以重组导航、页面、布局、控件和操作步骤，但不得删减业务能力、业务结果、失败恢复和安全确认。
- 不复刻旧 Streamlit 页面结构、不沿用 P2-08 固定三栏页、不使用 AI 参考图作为业务来源。
- 不新增没有权威来源支持的业务能力，也不推进 P2-09～P2-22。
- 不读取、写入、复制或测试真实 `user_data/`；演示和测试只使用受控的匿名固定数据。

## 2. 权威来源与审计方法

业务事实按以下顺序确认：

1. `web_app.py` 中现有 Streamlit 教师工作流；
2. `backend/review/`、`backend/api/routers/review.py`、`backend/api/schemas/review.py` 中的服务与接口契约；
3. `db_manager.py` 中的会话、明细、总分和事务契约；
4. `tests/test_review_application_service.py`、`tests/test_manual_review_atomic.py`、`tests/test_api_review_routes.py`、`tests/test_review_media_service.py` 与五流程 API 端到端测试；
5. P2-03～P2-08 已实现 Vue 代码仅用于识别待核验能力和可复用技术实现。

视觉规则只来自 `docs/ui/STYLE.md`。该文件不定义业务流程、字段、状态或结果。

## 3. P2-03～P2-08 审计结论

### P2-03 应用外壳

- 保留经 API 校验后恢复当前考试的语义；失效选择必须清除。
- 当前七个主导航入口多数仍为占位内容，不能继续表现为已迁移可用能力。
- 当前阶段只展示真实可用的“评分复核”入口；开发用设计系统入口不进入业务导航。
- 移除固定左导航与固定右检查器，把考试上下文和页面名称放在顶部。

### P2-04 API 客户端与任务状态

- 保留同源 `/api`、请求标识、超时和取消语义。
- 保留只对幂等读取请求进行有限重试；写请求不得自动重放。
- 保留错误净化、终态快照、过期请求隔离和浏览器仅记录已知任务 ID 的安全设计。
- 本次不新增没有实际业务入口的任务中心界面。

### P2-05 复核队列

- 当前实现以单条队列和单份详情为中心，与权威的按题批量复核主流程不符。
- 默认范围改为当前题的待复核记录，而不是本题全部记录。
- 搜索、风险排序、学生排序、分页和 URL 上下文具有可追溯数据来源，可以复用。
- 默认工作区改为同题答卷接触表，分批处理当前实际可见的待复核记录。

### P2-06 证据查看器

- 缩放、旋转、平移、适宽、实际尺寸、邻图预载、图片错误和过期响应隔离可以继续复用。
- 单份深查必须支持裁剪图、正反原图和正反标注图。
- 证据图始终使用服务端返回的受控媒体链接，不接受浏览器自行拼接文件路径。
- 查看器只在单份深查工作区出现，不占用默认批量复核空间。

### P2-07 教师评分

- 评分细则、AI 原分、复核原因、候选信息、最终分和可选说明均有服务契约支持。
- 教师必须可以明确确认 AI 原分不变；“没有修改分数”不能成为禁止提交的理由。
- 当前 API 接受多条确认项，前端需要使用批量确认而不是逐份写入。
- 没有服务接口支持的“活动记录”展示必须移除。
- 写入失败必须保留草稿和当前上下文，写请求不得自动重试。

### P2-08 交互、反馈与演示环境

- 固定三栏页不是业务事实，也不再作为目标布局。
- `/` 聚焦搜索、受保护的输入框快捷键、图片查看快捷键等提效行为可以保留或重组。
- 不设置危险的一键批量确认快捷键；批量确认需要明确点击主操作。
- 受控演示服务继续匿名、固定、进程内运行，但需要支持真实的批量确认契约和失败恢复演示。
- 继续覆盖 1024×768、1280×800、1366×768、1440×900、1920×1080 五档视口。

## 4. 业务能力与 UX 设计溯源表

| 业务能力 | 权威来源 | 数据语义 | 成功结果 | 失败与恢复 | 安全边界 | UX 组织 |
| --- | --- | --- | --- | --- | --- | --- |
| 选择当前考试 | Streamlit 会话选择、会话服务和相关测试 | 当前考试必须真实存在且未删除 | 后续读取和写入均绑定该考试 | 已失效选择清除；加载失败可重试 | 不创建或猜测考试 | 顶部常驻考试选择器 |
| 按题查看复核进度 | Streamlit 批量复核、`ReviewApplicationService` | 每题包含总人数、待复核人数和满分 | 教师定位当前题和下一道题 | 空题、无待复核分别说明 | 只读取当前考试 | 横向题号进度带 |
| 待复核判定 | 服务实现、数据库契约和测试 | 明确复核标记或低置信度为待复核；已确认记录不再进入 | 默认呈现真正待复核记录 | 可切换查看本题全部记录 | 前端不重写判定规则 | 默认“待复核”，可选“全部” |
| 按题批量比较 | Streamlit 答卷裁剪网格 | 同一道题的多名学生答卷并排呈现 | 教师完成同题横向比较 | 单图失败不影响其他答卷 | 只使用受控图片地址 | 连续式答卷接触表 |
| 搜索、排序和分批 | 真实学生字段、现有 Vue 测试 | 搜索姓名、学号、班级；按风险或学生排序 | 大班级可稳定处理 | 刷新失败保留旧内容 | 不扩大考试或题目范围 | 工具栏和每批分页 |

| 确认原分不变 | Streamlit 和复核服务 | 人工确认本身是有效业务结果 | 原分不变也标记为已确认 | 失败后仍保持待确认 | 必须由教师明确提交 | 批量操作允许保留原分 |
| 整批原子保存 | 数据库事务和原子性测试 | 当前请求全部成功或全部失败 | 保存明细并重算相关学生总分 | 任一归属或分数错误则整批不写入 | 服务端重核考试、结果、明细和题目归属 | 固定批量操作栏 |
| 成功后的流转 | Streamlit 自动切题、服务返回结果 | 先完成本题剩余批次，再进入下一题 | 不遗漏当前题其他待复核记录 | 刷新失败不否定已完成保存 | 不确认未展示记录 | “确认本批并继续” |
| 草稿与现场恢复 | Vue 状态测试、请求客户端 | 筛选、批次、滚动位置和未提交分数属于本地现场 | 深查或刷新后返回原位置 | 网络、超时和服务器错误保留现场 | 写请求不自动重试 | 本地草稿和离开提醒 |

## 5. 批准的信息架构

当前业务界面采用单一、真实的业务入口：

```text
AI 阅卷系统
└── 评分复核
    ├── 当前考试
    ├── 题号进度
    ├── 按题批量复核（默认）
    └── 单份深查（按需临时进入）
```

不在业务导航中展示工作台、考试管理、学生管理、分析、题库、设置、智能体等尚未完成对应迁移包的占位入口。该隐藏不改变后续包定义，也不代表删除后端能力。

## 6. 批准的主流程

### 6.1 默认批量复核状态

1. 顶部显示产品名称、页面名称和当前考试选择器。
2. 题号进度带显示每题的待复核数量和完成状态。
3. 工具栏提供身份搜索、待复核/全部范围、风险/学生排序和当前批次。
4. 主工作区用连续分隔线组织同一道题的答卷裁剪，不使用大量悬浮卡片。
5. 每份答卷显示学生身份、风险摘要、裁剪图、当前分数、题目满分和“深查”入口。
6. 教师可以修改分数，也可以保留 AI 原分。
7. 底部批量操作栏明确显示当前批次和校验状态；点击“确认本批并继续”后只提交当前实际展示的待复核记录。
8. 当前题仍有待复核批次时留在当前题；当前题清空后才进入下一道题。

### 6.2 单份深查状态

最初提出的覆盖式抽屉会遮挡答卷网格、缩窄评分区并增加误操作风险，已在用户审阅后废弃。

批准后的深查方式如下：

- “深查”把主工作区切换为临时的单份深查状态，不覆盖、不挤压批量答卷网格。
- 深查顶部提供清晰的“返回题号批量复核”操作。
- 返回后恢复原题号、范围、排序、搜索、批次、滚动位置和所有未提交草稿。
- 宽屏时深查内部使用“证据查看 + 评分信息”两栏；空间不足时上下排列。
- 教师可以返回而不提交，也可以明确确认当前单份后返回。
- 单份确认复用同一批量接口的一项请求，不引入新的业务写入语义。

## 7. 提交、失败和恢复语义

### 批量提交

- 提交内容包含当前可见待复核项的明细标识、题号、最终分数和可选说明。
- 服务端再次验证考试、结果、明细、题号归属、重复项和分数范围。
- 数据库在同一事务中更新全部明细并重算受影响学生总分。
- 任一项不合法时整批回滚，前端保留全部草稿并指出可修正的问题。

### 网络或服务器失败

- 写请求不自动重放。
- 页面保留题号、筛选、批次、滚动位置和分数草稿。
- 用户明确重试前不会再次提交。
- 过期读取响应不得覆盖较新的考试、题号或筛选状态。

### 标注图失败

- 分数事务成功后，即使标注图生成失败，分数结果仍然有效。
- 页面把结果表述为“分数已保存，标注图需要重试”，不得误报整次提交失败。
- 重试使用原有确认接口和服务端归属校验。

## 8. 视觉与响应式规则

- 遵守 `docs/ui/STYLE.md` 的颜色、字体、间距、密度、控件、焦点和对比度要求。
- 默认批量页采用安静、连续的批改工作台风格，以细分隔线组织答卷，不使用模板化卡片海洋、渐变或装饰性大标题。
- 主要操作在批量页保持单一明确；危险或高影响操作不依赖颜色或快捷键表达。
- 支持最小 1024×768 生产视口，并验证 1280×800、1366×768、1440×900、1920×1080。
- 深查状态在宽屏内部分栏，在较窄视口上下排列；任何状态不得遮挡输入、证据或操作。
- 所有交互使用原生可聚焦控件、可见标签和清晰焦点；尊重减少动画偏好。

## 9. 明确不做

- 不迁移或实现 P2-09～P2-22 的复杂页面。
- 不恢复无业务来源的七项占位导航。
- 不实现活动历史、智能建议、自动批量确认或其他没有接口和业务事实支持的功能。
- 不复制 Streamlit 的页面结构、P2-08 三栏原型或任何 AI 概念图。
- 不改变数据库 Schema、评分规则、待复核判定、事务边界或媒体安全规则。
- 不对真实 `user_data/` 执行写入、测试、迁移或演示。
