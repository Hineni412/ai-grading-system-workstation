# Phase 2 前端来源重校准门槛设计

> **工作类型：** 一次性、非编号、白天人工通过的治理与纠偏门槛；不是正式执行包。
> **插入位置：** P2-08 已合并之后，P2-09 及其他复杂页面继续迁移之前。
> **计数与自动化：** 不改变 Phase 2 的 22 包和全局 87 包计数，不进入夜间资格矩阵，不使用正式包交接块。
> **用户决定：** 2026-07-14，用户确认需要校正文档和参考图，并要求在已合并的 P2-08 之后增加修改环节。

## 1. 背景与问题

P2-08 已经通过当时的自动验证、用户验收并进入主线。该事实和证据保持不变，不回写为未完成，也不重开 P2-08。

但复盘确认，AI 生成的完整概念图虽然被标注为“视觉参考”，其中的页面结构、导航、字段、操作和工作流仍被后续计划当成了实现依据。`STYLE.md` 也混入了固定信息架构、单题三栏流程和快捷键等功能性内容，导致“参考样式”事实上扩张成了“功能设计”。

现有 Streamlit 的阅卷业务事实是按题号批量复核。P2-05 至 P2-08 已实现的单份记录三栏页可以保留为可复用能力或可选详情，但不能未经业务确认就取代批量复核成为默认主流程。

## 2. 决策

在 P2-08 和后续复杂页面迁移之间增加“Phase 2 前端来源重校准门槛”。门槛未通过时，P2-09、P2-13、P2-14、P2-16、P2-19 以及它们的后续依赖均不得开始实现或由夜间自动化领取。

这不是 P2-23、P2-08A，也不重定义 P2-09。原因是它属于一次性方向纠偏，不是新的长期产品能力；正式包编号、职责、状态和 87 包统计必须保持稳定。

## 3. 重新确立的权威顺序

前端迁移中的功能与视觉分别取证：

1. 页面功能、字段、操作、状态、快捷键和流程，以现有 Streamlit 行为、服务实现、数据库契约和测试为业务事实来源；
2. 用户在当前任务中的明确决定可以新增或改变业务行为，但必须留下日期和范围；
3. `docs/ui/STYLE.md` 只约束颜色、字体、间距、密度、边框、圆角、阴影、控件外观、焦点、动效和通用视觉质量；
4. 参考图只能帮助判断上述视觉属性，不能证明系统需要某个导航、页面、字段、按钮、状态、快捷键或流程；
5. 无法追溯到第 1 或第 2 项的功能元素不进入实现。

每个后续可见页面在设计和实现前都要建立“功能溯源表”。至少逐项记录：界面元素或行为、现有来源、是否保持不变、若改变则对应的用户决定。没有来源的条目默认删除，而不是暂时照图实现。

## 4. 门槛内容

### 4.1 文档与参考资产重置

- 将 `docs/ui/STYLE.md` 收敛为纯视觉规范，移除固定导航、页面内容、业务状态、操作、快捷键和流程定义；
- 移除 7 张完整 AI 概念图及其活动引用；Git 历史继续保留其来历，但它们不再属于当前设计输入；
- `docs/ui/references/` 只允许保存裁去功能语义的局部视觉片段，并为每个片段声明可借鉴的视觉维度；
- 校正 Master Plan、Phase 2 map、Index 和架构事实中的设计权威与阻断关系；
- 历史 P2-02 至 P2-08 设计稿、即时计划和验收清单不改写，用于保留当时为什么这样实现、当时验收了什么的证据。

### 4.2 现有功能盘点

- 以当前 Streamlit 页面、现有服务、API 契约和测试建立页面级功能清单；
- 区分“必须保留的现有功能”“只需换视觉表现的功能”“用户明确要求改变的功能”和“概念图臆造功能”；
- 导航只能由当前真实功能分组得出，不能由 7 项导航模板或未来占位项反推；
- 不把“尚未实现但计划未来开发”伪装成当前入口。

### 4.3 阅卷样板页修正

- 默认主流程回到“按题号批量复核”，保持教师一次比较和处理同一题多份答卷的工作方式；
- P2-05 至 P2-08 的队列、证据查看器、评分检查器和安全确认能力优先复用；
- 单份记录三栏页降为可选详情或异常深查入口，不作为唯一或默认阅卷模式；
- 新的批量主视图和可选详情之间如何进入、返回、保存与继续处理，必须从现有行为和用户决定推导；
- 不在本门槛中改变评分规则、后端契约、数据库、模型调用或真实业务数据。

### 4.4 用户确认

校正后的功能溯源表、导航分组和阅卷主流程先由用户审阅。页面实现完成并通过自动检查后，才按 `docs/user-testing/PHASE2_FRONTEND_RECALIBRATION_TEST_TEMPLATE.md` 生成 `docs/user-testing/checkpoints/phase-2-frontend-source-recalibration-<YYYY-MM-DD>.md`；不得提前编写操作步骤，也不得复用 P2-08 的旧清单。

该清单必须记录：用户实际测试的已复审 40 位 SHA、数据来源、启动方式、地址、可见标识、关闭方式、真实两库测试前后指纹、逐步结果、Blocker/Major、用户原始反馈和用户明确结论。只有 Blocker/Major 清零且用户明确标记 `passed` 才满足本门槛。结果块使用“门槛”而不是正式包 ID，因此不产生正式包交接块、不进入夜间矩阵，也不改变包计数。

## 5. 通过条件

门槛只有同时满足以下条件才算通过：

1. 活动文档中不再把完整 AI 概念图当作页面或功能依据；
2. `STYLE.md` 不再定义导航、页面字段、业务动作、状态机、快捷键或工作流；
3. 后续 Phase 2 页面都有可核验的功能溯源规则；
4. 当前真实阅卷功能盘点完成，批量复核被确认为默认主流程；
5. 单份三栏能力被定位为可选详情，并完成必要的前端修正；
6. 自动验证、规定桌面视口和错误恢复检查通过；
7. 专用版本化清单记录已复审 SHA、Blocker/Major 清零和用户明确 `passed`。

门槛通过前，Index 只能记录“未通过”；不能因为 P2-08 已合并、Phase 1 总门槛通过或某个后续包具备技术依赖而绕过。

## 6. 不修改范围

- 不撤销、篡改或重写 P2-08 的合并历史和当时验收证据；
- 本次文档重置不修改前端源码；
- 不新增正式执行包编号，不改变 87 包统计或夜间资格矩阵；
- 不修改评分语义、API、Schema、模型配置或真实 `user_data/`；
- 不立即制作新的 AI 全页效果图；确有需要时只制作去语义的局部视觉片段。

## 7. 回退与历史说明

文档和参考资产重置可通过单个 Git 提交回退。被移除的完整概念图仍可从 Git 历史取回用于审计，但不得在回退之外重新加入活动参考集。P2-08 代码继续保留，后续修正应以增量调整和组件复用为主；若某项复用会妨碍批量主流程，可在即时实现计划中单独说明并验证回退方式。
