# 夜间单包自动化设计

## 目标

让每天 4:00 启动的 Codex 自动化在无人值守时安全推进最多一个 Terra 执行包，同时避免接管仍在运行、等待用户或上下文不完整的任务。

## 核心决策

采用“任务协调器 + 安全执行器”模式。一次运行最多采取一个开发动作：优先唤醒一个明确可恢复的原任务；没有可恢复任务时，才在预先准备好的空闲功能 worktree 中执行一个已放行的小包。

自动化不自行生成源码级计划，不自行创建、删除或重绑 worktree，不执行 integration，不 push，不创建或合并 PR。高风险设计与计划仍由 Sol Extra High 在白天完成，Terra 只执行已经放行的计划。

## 夜间放行协议

一个执行包只有同时满足以下条件才可被领取：

1. `EXECUTION_INDEX.md` 状态为 `ready`，依赖已经进入最新 `origin/main`。
2. 已有专属、干净、从共同基线创建的功能 worktree/分支，并在并行手册中明确分配给该包。
3. 已有 `docs/superpowers/plans/YYYY-MM-DD-<package-id>-<slug>-implementation.md` 即时计划。
4. 即时计划包含以下机器可读字段：

   ```markdown
   **执行包：** P1-16
   **规划状态：** ready_for_execution
   **规划模型：** S-XH
   **允许夜间执行：** yes
   **计划基线：** <完整 Git 提交 SHA>
   ```

5. 包的执行模型为 `T-M` 或 `T-H`，且不涉及真实 `user_data/`、数据库迁移、不可逆删除、真实密钥/模型调用、用户视觉验收或业务语义裁决。
6. 即时计划的目标文件没有被其他活动任务占用；计划基线到最新主线之间不存在影响计划目标文件的漂移。

## 任务协调

若运行环境提供 Codex 任务工具，自动化先使用任务列表和任务详情判断同项目任务状态：

- 运行中、等待用户、阻塞、复核中：对应通道占用，不触碰。
- 已停止但有明确下一步、不是等待用户或阻塞：向原任务发送一次继续消息并结束本次自动化。
- 已完成并等待 integration：只报告，不开始下一包。
- 状态无法判断：视为占用。

若任务工具不可用，不得根据提交时间猜测任务是否活跃。任何非干净、存在独有提交或用途不明的现有 worktree 都视为占用。

## 执行与停机

自动化严格按即时计划使用 TDD 完成一个包，运行包内测试、受影响回归、快速冒烟和前端质量命令（若适用），并比较真实两库执行前后的大小、UTC 修改时间和 SHA-256。

遇到接口/Schema/业务语义漂移、计划文件不匹配、需要升级到 Sol、同一问题连续两次修复失败或数据指纹变化时，立即停止并报告。安全停机是成功结果，不为了产生提交扩大范围。

验证通过后只创建本地功能分支提交，输出交接报告。push、PR、main 合并和清理由白天的 integration 流程处理。

## 模型与频率

- 自动化：每天 4:00。
- 模型：GPT-5.6 Terra。
- 推理：极高。
- 运行方式：独立新任务，项目目录为本仓库根目录。

## 验收

1. 自动化配置保留原频率、模型、推理级别、项目和启用状态。
2. 配置中的提示词与项目内权威提示词一致。
3. 没有已放行包时只输出阻塞/准备清单，不修改源码。
4. 有已放行包时最多完成一个本地提交，不执行远端或 integration 操作。
