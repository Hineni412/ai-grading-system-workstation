# P2-05 复核队列、筛选与连续导航设计

## 1. 目标

在尚未切入生产的 Vue 前端中，把“阅卷”工作区的占位页替换为单题复核样板页的第一块可用切片：教师可以选择题目，查看该题的学生复核队列，按姓名、学号或班级搜索，筛选待复核记录，按风险或身份排序，并通过上一条、下一条及 `J`/`K` 连续切换当前记录。

P2-05 只建立只读队列和当前项上下文。答卷图片查看、评分草稿、调分、确认和完整快捷键体系分别属于 P2-06、P2-07 和 P2-08，不在本包实现。

## 2. 权威依据与已确认决定

- `docs/superpowers/packages/phase-2-execution-packages.md` 定义 P2-05 的稳定目标、范围、验收和不修改边界。
- `ARCHITECTURE.md`、`backend/api/routers/review.py`、`backend/api/schemas/review.py` 和 `backend/review/service.py` 是当前 Review GET 契约、题号顺序、置信度和 `needs_review` 语义的事实来源。
- `docs/ui/STYLE.md` 规定高密度左侧队列、异常优先暴露、稳定位置、键盘核心操作、加载/空/错状态和最小 1024px Windows 桌面边界。
- P2-03/P2-04 已合并的 App Shell、Session Store、原生 Fetch Client 和运行时校验模式继续复用；本包不建立第二套网络层或考试上下文。
- 用户于 2026-07-13 批准：采用前端分页，每页 100 条；上一条/下一条可以自动跨页；默认风险优先；当前题目与当前学生写入 URL；`J`/`K` 在非输入焦点时切换；中央只显示当前记录的只读摘要。

## 3. 方案比较与选择

### 方案 A：前端本地筛选、排序与 100 条分页（采用）

通过现有 Review GET API 一次读取当前题目的完整队列，在浏览器内完成搜索、筛选和稳定排序。渲染层每页只展示 100 条；连续导航跨页时自动切换页码并保持当前项可见。

该方案不改变后端契约、不增加依赖，1000 条生成数据的计算和内存规模可控，并且能用确定性单元测试覆盖筛选后选中项、URL 恢复和跨页导航。

### 方案 B：自建虚拟滚动（不采用）

可获得更连续的长列表滚动体验，但需要维护行高、滚动窗口、键盘定位和不同桌面高度下的可见区计算。P2-05 的低风险只读范围不足以支撑这部分额外复杂度。

### 方案 C：扩展后端分页、搜索与排序（不采用）

长期适合更大数据集，但会新增后端查询参数、服务排序语义和 API 契约测试，使本包从前端样板页切片扩散到 Review 后端。当前 1000 条验收规模无需承担这项变化。

## 4. 页面结构与职责

### 4.1 路由

- `/grading` 不再渲染通用占位页，改为 P2-05 的 `ReviewQueueView`。
- App Shell、全局导航、顶部当前考试选择器和右侧 `SessionInspector` 保持不变。
- 页面主工作区采用两列：左列为约 280–320px 的复核队列；右列为当前记录的只读摘要和后续 P2-06/P2-07 能力边界提示。
- 在 1024px 最小桌面视口中，沿用 P2-03 的收起导航和 320px Session Inspector；页面内部列宽必须保证无横向溢出，必要时缩紧队列列而不是改为移动端抽屉。

### 4.2 URL 状态

使用两个查询参数：

- `question`：当前题号；
- `detail`：当前复核明细 ID。

当前考试继续由 Session Store 管理，不在 URL 复制第二份 session 状态。只有已从 API 验证存在的题号和明细 ID 才能成为活动状态；无效或过期参数由页面替换为安全默认值，不显示不存在的记录。

搜索词、筛选和排序是页面临时视图状态，不写入本地存储。刷新后恢复当前题目/记录，但不承诺恢复临时搜索词。

## 5. 数据边界

### 5.1 Review API 适配器

新增单一 `frontend/src/api/review.ts` 资源适配器，复用 P2-04 `apiClient`：

- `GET /api/sessions/{session_id}/review/questions` 读取题目摘要；
- `GET /api/sessions/{session_id}/review/questions/{question_id}/items?needs_review_only=false` 读取当前题目的完整队列。

适配器对所有公开字段做运行时校验，包括题目计数、学生身份、分数、置信度、`needs_review`、候选分数、元数据和受控媒体 URL。未知或畸形响应按 P2-04 契约错误处理，不把未验证数据交给页面。

本包不调用 confirm POST，不预取图片二进制，也不新增或修改后端路由。

### 5.2 Store

新增页面专用 Pinia Review Queue Store，职责为：

- 监听当前 Session Store 的已验证考试 ID；
- 加载题目列表和当前题目队列；
- 保留最近一次成功加载的题目和队列，在刷新失败时显示错误而不闪空；
- 维护当前题号、当前 detail ID、搜索词、筛选、排序和页码；
- 计算过滤后的稳定队列、当前页、当前位置以及上一条/下一条目标；
- 取消已过期请求，防止快速切换考试或题目时旧响应覆盖新上下文。

Store 不使用 `localStorage`，不保存完整学生队列；可恢复上下文只来自已验证 Session Store 和 URL。

## 6. 搜索、筛选和排序

### 6.1 搜索

单个搜索框对以下字段做去首尾空格、大小写不敏感的包含匹配：

- `student_name`；
- `student_code`；
- `class_name`。

搜索不会匹配错误说明、评分依据或任意元数据，避免结果难以解释。

### 6.2 筛选

提供两个范围：

- “全部记录”；
- “仅待复核”。

筛选只读取后端给出的 `needs_review`，不在前端重新定义其业务语义。已复核记录通过“全部记录”重新出现，满足“已复核回流”。

### 6.3 排序

提供三个稳定排序：

1. “风险优先”（默认）：`needs_review=true` 在前；有置信度的记录按数值从低到高；无置信度排在有置信度之后；再按班级、学号、姓名和 detail ID 稳定排序。
2. “学号顺序”：班级、学号、姓名、detail ID。
3. “姓名顺序”：姓名、班级、学号、detail ID。

前端只显示后端的置信度数值和待复核状态，不把阈值重新命名为新的高/中/低业务等级。

## 7. 当前项、分页与连续导航

- 固定每页 100 条；页码只属于当前过滤结果。
- 加载新题目时，优先恢复 URL 中仍存在的 detail；否则选择过滤结果第一条。
- 搜索、筛选或排序后，若当前项仍在结果中则保持不变；若被排除则选择新结果第一条；结果为空时清空当前 detail。
- 上一条/下一条基于完整过滤结果计算，不受当前页边界限制；跨页后自动更新页码并将目标行滚动到可见位置。
- 到达首条或末条时对应按钮禁用，不循环跳转。
- `J` 选择下一条，`K` 选择上一条；焦点位于 `input`、`textarea`、`select`、按钮或可编辑区域时不触发。本包不实现 Enter、Shift+Enter、R、Z、缩放等 P2-08 快捷键。
- 当前行使用文字、边框和 `aria-current` 共同表达，不能只靠颜色。

## 8. 可见内容与状态

### 8.1 队列行

每行最多展示：

- 学生姓名；
- 学号或“未提供学号”；
- 班级（有值时）；
- `待复核` 或 `已复核` 文字状态；
- 置信度数值或“未提供”；
- 一条经截断的异常/扣分原因。

不显示头像，不放调分、确认、媒体或其他次要操作按钮；可见状态徽章控制在三个以内。

### 8.2 当前记录摘要

中央摘要显示当前题号、学生身份、当前得分/满分、置信度、待复核状态和现有错误说明。媒体链接只作为后续能力边界存在，不在 P2-05 发起图片请求或显示伪造答卷。

页面不得提供任何可编辑分数字段、保存或确认按钮。

### 8.3 加载、空与错误

- 未选择考试：说明需要先在顶部选择考试。
- 题目加载中：显示队列骨架或明确加载状态。
- 考试无复核题目：说明当前考试没有可显示的复核记录。
- 当前筛选为空：说明可清除搜索或切换“全部记录”。
- 首次加载失败：显示安全错误状态和重试按钮。
- 已有内容刷新失败：保留旧内容，显示不遮挡队列的错误反馈和重试入口。
- 切换考试、题目或离开页面时中止旧请求；取消错误不向用户显示为服务器故障。

## 9. 文件职责

- `frontend/src/api/review.ts`：Review 只读类型、运行时校验和两个 GET 资源函数。
- `frontend/src/stores/review-queue.ts`：页面状态、并发请求守卫、过滤、稳定排序、分页、选择和连续导航。
- `frontend/src/views/ReviewQueueView.vue`：页面编排、URL 同步、键盘事件、加载/空/错状态和无业务逻辑的展示绑定。
- `frontend/src/components/review/ReviewQueuePanel.vue`：题目选择、搜索、筛选、排序、分页和高密度队列。
- `frontend/src/components/review/ReviewSelectionSummary.vue`：当前记录只读摘要和后续能力边界。
- `frontend/src/styles/review-queue.css`：只使用现有 Token 的页面布局与状态样式。
- `frontend/src/router/index.ts`：把 `/grading` 定向到 Review Queue 页面，其他占位路由保持不变。

实现计划可在不混合职责的前提下合并过小组件；不得把 API 校验、过滤排序或 URL 规范化散落到模板表达式中。

## 10. 测试与验证

### 10.1 API 适配器单元测试

- 合法题目和队列响应被完整解码；
- 畸形计数、布尔值、置信度、媒体 URL、数组或缺字段被拒绝；
- question ID 使用安全路径段编码；
- 两个请求都经统一 Client，页面不直接调用 `fetch`。

### 10.2 Store 单元测试

- 风险优先、学号和姓名排序具有稳定确定性；
- 搜索只覆盖姓名、学号和班级；
- “仅待复核”和“全部记录”使用后端 `needs_review`；
- 1000 条生成数据分页正确，跨越第 100/101 条的上一/下一导航正确；
- 过滤后保留仍可见当前项，排除当前项时选择第一条，空结果清空选择；
- 快速切换题目/考试时旧响应不覆盖新状态；
- 刷新失败保留最近一次成功内容。

### 10.3 组件和浏览器验证

- URL 中有效的 question/detail 在刷新后恢复，无效值安全替换；
- `J`/`K` 切换且输入框聚焦时不误触；
- 长姓名、长班级和长错误说明不遮挡核心状态；
- 加载、无考试、无题目、筛选空、首次失败和保留旧内容错误状态可操作；
- 1000 条生成数据下搜索、筛选、排序、分页和连续导航稳定；
- 1920×1080、1440×900、1366×768、1280×800、1024×768 无横向溢出、重叠或控制项不可达；
- 浏览器无应用异常和控制台错误。

### 10.4 工程门槛

- 运行 P2-05 聚焦 Vitest、受影响 App Shell/Router 回归、Chromium P2-05 e2e、lint、typecheck、unit 和 build；
- 运行 `git diff --check` 和 `tools/smoke_check.py --skip-tests`；
- 功能分支默认不运行全量 pytest，除非测试失败、不稳定或仓库规则中的风险触发条件出现；
- 验证前后只读比较根工作区两个真实数据库的大小、UTC 修改时间和 SHA-256，必须完全不变。

P2-05 是可见前端批次，用户自测为 `quick`。短测清单只在页面实现、真实浏览器和全部自动门槛通过后生成；测试数据全部为合成数据，不读取真实 `user_data/`。

## 11. 风险与回退

- 主要风险是 URL、Store 和筛选结果形成循环更新，旧请求覆盖新考试，以及筛选后当前项跳到错误记录。通过单向规范化、请求世代/中止和确定性选择规则控制。
- 1000 条数据一次读取依赖现有 Review API；若实测在受信任工作机上不满足稳定交互门槛，停止并记录性能证据，不在本包擅自扩展后端分页语义。
- 若现有 API 字段、`needs_review` 或置信度含义与本文不一致，立即回到后端实现和测试核对，不在前端臆造新状态。
- 整体回退 P2-05 前端提交即可恢复 `/grading` 占位页；Streamlit 生产入口、FastAPI、数据库和真实业务数据不受影响。
