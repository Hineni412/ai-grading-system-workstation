# P2-06 答卷证据查看器设计

## 1. 目标

在 P2-05 已验收的只读单题复核队列中，把当前记录右侧的文字摘要升级为答卷证据查看器。教师默认看到当前题目的受控裁剪图，可以按需切换原卷正面或反面，并在同一稳定画布内执行适应宽度、原比例、缩放、旋转和拖拽。

P2-06 只读取 P1-13 已有的受控媒体 URL。所有变换都只发生在浏览器显示层，不修改原图、不生成新业务文件、不写数据库，也不提供评分、调分、保存或确认入口。

## 2. 权威依据与已确认决定

- `docs/superpowers/packages/phase-2-execution-packages.md` 定义 P2-06 的稳定目标、范围、验收和不修改边界。
- `docs/ui/STYLE.md` 第 7、14、15、16、19 节规定中央答卷区、桌面视口、键盘可访问性、错误恢复和视觉门槛。
- `ARCHITECTURE.md`、`backend/api/routers/media.py`、`backend/media/service.py` 和媒体测试是受控裁剪图、原卷页、所有权校验、文件根边界和 `no-store` 响应的事实来源。
- P2-05 已合并的 `ReviewQueueView`、Review API 适配器、Pinia Store、URL/连续导航和五视口布局继续复用；本包不建立第二套队列、网络层或考试上下文。
- 用户于 2026-07-13 明确启动 P2-06，按仓库规则持续授权既定包范围走完功能分支、复核、短测、integration、PR 和基线同步流程。

## 3. 方案比较与选择

### 方案 A：原生 `<img>` + CSS 变换 + 小型状态组合函数（采用）

浏览器直接读取后端返回的同源 `/api/` 媒体 URL。一个独立组合函数维护来源、缩放、旋转、平移、加载世代和边界计算；Vue 组件只负责工具栏、画布和错误状态。裁剪图、原卷正面和原卷反面共享同一画布，切换时只保留一个活动 `<img>`。

该方案不增加生产依赖，原图字节不进入 Pinia/localStorage，缩放和旋转只改变 CSS，能够用单元测试验证数学边界并用 Playwright 验证真实图片像素、拖拽和五档视口。

### 方案 B：引入通用图片查看器库（不采用）

成熟库能快速提供手势和缩略图，但会增加锁文件、打包体积和额外交互语义。P2-06 只需要单图查看，不需要画廊、批注或编辑；新依赖的收益不足以覆盖审计和可访问性成本。

### 方案 C：使用 Canvas 重新绘制图片（不采用）

Canvas 便于像素级叠层，但会复制大图内存、增加高 DPI 绘制与辅助技术支持难度，也容易把后续批注编辑提前带入本包。后端裁剪图已经包含题框边界，无需在前端重画业务几何。

## 4. 视觉与页面结构

### 4.1 设计方向

页面继续采用 P2-05 的安静、专业、高密度工作台。现有 Token、系统字体、边框、圆角和 App Shell 不变。新增的唯一视觉重点是“证据画布”：浅色界面中使用受控的深色中性画布底，让白色答卷边缘、红色题框和手写内容更易辨认；工具栏仍使用现有浅色表面和文字按钮，不使用渐变、阴影卡片或装饰性图标。

这项视觉选择只服务答卷可读性，不扩散为全站主题。普通内容、队列和摘要继续使用现有浅色层级。

### 4.2 页面结构

```text
┌──────────────┬─────────────────────────────────────────────┐
│ P2-05 队列   │ 上一条 / 当前位置 / 下一条                 │
│ 题目/筛选    ├─────────────────────────────────────────────┤
│ 学生记录     │ 当前学生、题号、分数、风险摘要              │
│              ├─────────────────────────────────────────────┤
│              │ 裁剪图 | 原卷正面 | 原卷反面                │
│              │ 适应宽度 100% − 75% + 左旋 右旋             │
│              ├─────────────────────────────────────────────┤
│              │                                             │
│              │               稳定证据画布                  │
│              │                                             │
│              └─────────────────────────────────────────────┤
```

- P2-05 队列宽度、独立滚动和连续导航保持不变。
- 当前记录摘要压缩为画布上方的单行/双行上下文，不再占据主要垂直空间。
- 证据工具栏固定在画布上方；长图拖拽时按钮位置不移动。
- 画布占据剩余高度，最小桌面视口仍能同时看到队列当前行、记录导航、媒体来源和主要工具。
- App Shell 右侧现有 Session Inspector 保持不变；P2-07 才引入评分检查器。

## 5. 媒体来源与安全边界

### 5.1 来源

每个 `ReviewItem.media` 已包含并经运行时校验的五个同源 `/api/` URL。P2-06 使用：

- `crop_url`：默认裁剪证据，后端已在裁剪图中绘制受控题框边界；
- `original_front_url`：原卷正面；
- `original_back_url`：原卷反面。

`annotated_front_url` 与 `annotated_back_url` 暂不进入可见切换，避免把“批注图”和“原始证据”混为一谈；后续包若需要必须另行定义展示语义。

### 5.2 安全规则

- 页面不接受客户端路径，不拼接文件系统位置，只消费 Review API 已验证的 URL。
- 图片 URL 不写入 Pinia、localStorage、日志或错误详情；Review Store 现有内存记录除外。
- 加载失败只显示“裁剪图暂时无法读取”或“原卷页暂时无法读取”，不回显响应正文、内部路径或堆栈。
- `<img>` 使用同源 URL、异步解码和不可拖出页面的浏览器默认行为；组件不请求 Blob、不创建 object URL、不修改或上传图像。
- 评分和确认 POST 仍不得调用。

## 6. 查看器状态与交互

### 6.1 来源状态

来源枚举固定为：

- `crop`：裁剪证据；
- `original_front`：原卷正面；
- `original_back`：原卷反面。

选择新复核记录或新题目时重置为 `crop + fit-width + 0° + 居中`。同一记录切换来源时也恢复适应宽度和居中，避免把上一张图的缩放/位移错误继承到尺寸完全不同的页面。

### 6.2 缩放

- `适应宽度`：按旋转后的图像宽度计算比例，保留画布内边距；画布尺寸变化时自动重算。
- `原比例`：100%，一个图片像素对应一个 CSS 像素。
- `−` / `+`：以 25% 相对步进缩放，范围 10%–400%。
- 鼠标滚轮：指针位于画布内时缩放，以指针所在位置为视觉中心；只有实际发生缩放时阻止页面默认滚动。
- 画布获得焦点后，`+`/`-` 缩放，`0` 回到原比例，`Z` 适应宽度。全局快捷键整合仍留给 P2-08。

### 6.3 旋转与拖拽

- 左旋/右旋每次 90°，只改变 CSS 变换。
- 旋转后若当前是适应宽度模式则重新适配；手动缩放模式保留比例并重新限制平移边界。
- 图片大于画布时可用鼠标/触控板按下拖拽；画布获得焦点后方向键每次平移 32px。
- 平移被限制在可解释边界内：图片较小时自动居中；图片较大时不能把整张图拖出画布，只允许保留一段可见边缘。
- 拖拽使用 Pointer Events；失去捕获、切换记录、切换来源或卸载时立即结束，防止“粘住鼠标”。

## 7. 加载、错误、切换与内存

### 7.1 加载与错误

- 图片首次读取时画布保留稳定尺寸并显示加载状态，不让队列或导航跳动。
- 加载成功后显示图片并更新固有宽高；使用非空像素浏览器检查确认不是空白占位。
- 加载失败时只替换画布内容，保留队列、当前学生、来源选择和连续导航；提供“重新加载”和其他可用来源按钮。
- 重试通过重新挂载同一受控 URL 的 `<img>` 完成，不添加任意查询参数、不绕过后端缓存/安全契约。
- 快速切换记录时只接受当前加载世代的成功/失败事件，旧图片事件不得覆盖新记录状态。

### 7.2 相邻预载

- 只预载过滤结果中的上一条和下一条 `crop_url`，帮助连续复核。
- 不预载原卷正反面和批注图，避免每条记录同时解码多张大图。
- 每次选择变化都释放旧 `Image` 引用并建立至多两个新引用；卸载时全部释放。
- 预载失败静默处理，不产生页面错误；真正选中该记录时仍走正常加载/重试状态。

### 7.3 大图内存

- DOM 中同一时间只有一个活动证据 `<img>`；无隐藏原卷页、缩略图画廊或 Canvas 副本。
- Pinia Store 不保存图片字节、natural size、缩放或位移。
- Playwright 使用受控生成的大尺寸 PNG 验证切换、缩放和回收期间页面可操作、无异常、活动证据图始终只有一个。

## 8. 组件与文件职责

- `frontend/src/composables/use-evidence-viewer.ts`：来源映射、加载世代、缩放/旋转/平移数学、适应宽度、边界限制和输入动作；不依赖 Review Store。
- `frontend/src/components/review/ReviewEvidenceViewer.vue`：工具栏、来源选择、稳定画布、图片事件、Pointer/Wheel/键盘交互、错误重试和相邻裁剪图预载。
- `frontend/src/components/review/ReviewSelectionSummary.vue`：压缩当前学生、题号、得分、置信度和异常摘要；移除 P2-06 占位提示，继续明确“评分与确认将在 P2-07 接入”。
- `frontend/src/views/ReviewQueueView.vue`：从 Store 计算当前项及相邻项，把媒体 URL 交给查看器；不持有图像变换逻辑。
- `frontend/src/styles/review-evidence.css`：只使用既有 Token，定义上下文条、工具栏、画布、焦点、加载/错误和紧凑桌面布局。
- `frontend/src/__tests__/evidence-viewer-state.spec.ts`：纯状态/数学/边界测试。
- `frontend/src/__tests__/review-evidence-viewer.spec.ts`：组件加载世代、来源切换、重试、快捷键和预载测试。
- `frontend/e2e/review-evidence.spec.ts`：真实图片、像素非空、缩放/旋转/拖拽、错误、大图、切换和五视口浏览器验证。

## 9. 测试与验收

### 9.1 单元测试

- 初始状态和记录/来源切换都恢复 `crop + fit-width + 0° + 居中`；
- 适应宽度对 0°/90° 使用正确旋转尺寸，并在容器变化时重算；
- 10%–400% 缩放边界、25% 步进和指针中心换算正确；
- 左右旋转、拖拽、键盘平移和较小图自动居中正确；
- 旧加载世代事件被忽略，重试只递增内部版本；
- 相邻预载最多两个裁剪 URL，切换和卸载释放引用。

### 9.2 组件与浏览器

- 默认加载裁剪图，来源切换只显示一个活动 `<img>`；
- 正反面原卷入口、适应宽度、100%、缩放、旋转、鼠标拖拽和画布聚焦键盘操作均可用；
- 图片成功后对画布截图执行非空像素/明显方差检查；
- 图片 404/410/422 的浏览器表现统一为安全错误和可重试入口；
- 快速切换学生时旧图片不闪回，新记录重置视图；
- 大尺寸 PNG 下连续切换仍可操作，页面无 `pageerror`、console error 或额外隐藏图片；
- 1920×1080、1440×900、1366×768、1280×800、1024×768 无横向溢出、重叠或关键控件不可达。

### 9.3 工程门槛

- P2-06 聚焦 Vitest、P2-05 受影响回归、P2-05/P2-06 Chromium e2e、lint、typecheck、unit 和 build 通过；
- `git diff --check` 与 `tools/smoke_check.py --skip-tests` 通过；
- 功能分支默认不运行全量 pytest，除非出现仓库定义的风险触发条件；
- 根工作区真实两库只读比较大小、UTC 修改时间和 SHA-256，前后必须完全不变；
- 变更不含 `user_data/`、图片缓存、截图、构建产物、临时数据库或密钥。

P2-06 是可见前端批次，用户自测为 `quick`。短测清单只在页面和专用合成媒体运行环境已经实现并验证后生成；不使用真实学生姓名、答卷或数据库。

## 10. 风险与回退

- 主要风险是缩放中心和旋转后平移边界错误、旧图片事件覆盖新记录、原卷大图同时解码过多，以及 1024px 下工具栏挤压。通过纯数学测试、加载世代、单活动图/相邻裁剪预载和五视口 E2E 控制。
- 若当前媒体 URL、题框边界或错误语义与后端事实不一致，停止并回到现有服务/测试核对，不扩展后端字段或重画几何。
- 若大图实测仍产生不可接受的浏览器内存或卡顿，保留裁剪图默认路径，停止原卷预载并记录尺寸/耗时证据；不在本包增加服务端缓存或图片重编码语义。
- 回退整个 P2-06 前端提交即可恢复 P2-05 文字摘要；P1-13 后端媒体 API、Streamlit 生产入口、数据库和真实业务数据不受影响。
