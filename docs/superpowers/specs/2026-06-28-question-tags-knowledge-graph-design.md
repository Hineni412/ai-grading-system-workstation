# 题库标签直连知识图谱与训练推荐设计

## 1. 状态与适用范围

- 设计日期：2026-06-28
- 适用分支：`codex/grading-paper-skill-workflow`
- 状态：已完成产品讨论，等待书面规格复核
- 取代范围：本设计取代 `2026-06-28-grading-paper-skill-workflow-design.md` 中把 `skill_id`、`question_skill_links`、`assessment_item_skills` 和技能消歧作为新知识图谱运行主链路的决策；原卷归档、可选入库、来源题关联、部分完成和非阻断批改等决策继续有效。

## 2. 背景与根因

已实现流程在题库 AI 打标签后，又把 `measured_skills` / `supporting_skills` 逐项交给技能目录解析。无法直接命中的名称会再次调用 AI 做上下文消歧。页面进度只覆盖首轮打标签，因此会出现进度已满但后台继续请求、状态长期不更新和 token 消耗远高于题量的现象。

这条技能目录链路还与题库现有多维标签形成两套身份来源：知识图谱依赖稳定 `skill_id`，题库展示与教学诊断依赖 `question_tags`。用户确认不再维护这套双轨逻辑，而是直接复用题库已经保存的标签。

## 3. 已确认的产品决策

1. 题库 `question_tags` 是知识图谱和训练推荐的唯一语义来源。
2. 图谱主节点使用现有 `knowledge_point` 标签，不再生成或匹配独立技能身份。
3. `sub_skill`、`method`、`ability`、`model`、`error_type`、`prerequisite`、章节、难度和学生层次继续保留，作为详情展示、错因候选和推荐排序信号。
4. 唯一需要建立的关系是“批改题对应哪一道题库题”；题库标签本身不再做名称匹配、别名匹配或 AI 消歧。
5. 题库标签修改后，历史知识图谱与训练推荐自动读取最新标签。
6. 批改本身不以题库入库为前置条件；知识图谱和训练推荐只能使用已入库且已打标签的可靠题目。
7. 部分题目完成时展示部分图谱，并明确显示完整度、缺失题号和原因。
8. 批改 AI 不再输出知识点或技能字段；系统把题库现有标签作为题目上下文传给批改 AI。
9. 每个学生每道题保存一个主错因和最多两个次要错因。候选外错因记为“其他”，只进入学生结果，不自动写回题库。
10. 图谱节点只有知识点；技能、方法、模型和错因在知识点详情中展示，不扩展为图谱子节点。

## 4. 目标与非目标

### 4.1 目标

- 删除新流程中的第二轮 AI 技能消歧和隐藏请求；
- 让图谱、批改错因和训练推荐直接共享题库标签；
- 保留现有题库标签维度和管理页面；
- 使中断、重试、进度和请求数量可解释、可核验；
- 用尽量少的新增字段完成主/次错因存储；
- 让历史图谱随题库标签编辑自动更新。

### 4.2 非目标

- 不建设新的技能目录或错因目录；
- 不对近义标签做语义合并、别名匹配或 AI 归一；
- 不自动把学生的“其他”错因提升为题库标签；
- 不在第一阶段删除旧表和旧字段；
- 不改变批改、人工复核和报告导出的可用条件；
- 不把错因或方法扩展成新的图谱节点类型。

## 5. 单一真相来源

### 5.1 题库标签

继续复用 `TagAnalysis` 与 `question_tags` 的现有映射：

| 业务维度 | `TagAnalysis` 字段 | `question_tags.tag_type` | 新流程用途 |
|---|---|---|---|
| 知识点 | `knowledge_points` | `knowledge_point` | 图谱主节点、训练候选的必要匹配条件 |
| 细分考法 | `sub_skills` | `sub_skill` | 详情展示和候选排序增强 |
| 方法 | `method_tags` | `method` | 详情展示和候选排序增强 |
| 能力 | `ability_tags` | `ability` | 学习画像与详情展示 |
| 数学模型 | `math_model_tags` | `model` | 详情展示和候选排序增强 |
| 常见错因 | `error_prone_points` | `error_type` | 批改 AI 的受控错因候选 |
| 前置知识 | `prerequisite_points` | `prerequisite` | 详情展示和训练排序增强 |
| 教材定位 | `textbook_chapter` | `exam_scope` | 章节筛选与展示 |
| 教学阶段 | `teaching_stage` | `teaching_stage` | 教学提示 |
| 学生层次 | `suitable_student_level` | `student_level` | 训练分层 |
| 难度 | `difficulty` | `questions.difficulty` | 训练梯度 |
| 教学说明 | `reason` | `questions.reason` | 教学诊断与解释 |

`measured_skills`、`supporting_skills`、`canonical_knowledge_id` 等现有数据先保留兼容，但新图谱和训练推荐不再依赖它们，也不再为它们运行解析或消歧服务。

### 5.2 图谱节点身份

图谱节点不新增数据库 ID。运行时节点键由现有标签计算：

```text
knowledge_point:<去除首尾空白后的 tag_value>
```

这是精确值复用，不是语义匹配。两个标签只有文本值相同才属于同一节点。教师在题库修改标签后，后续查询自然使用新值。

### 5.3 题目对应关系

`grading_question_links` 继续表达批改来源题与题库题的关系。对于本次刚导入的原卷，工作流直接记录导入得到的题库题 ID，并按同一原卷内的题号建立确定性关联。小问通过评分标准中的父子结构继承所属大题的题库题 ID。

若题号重复、解析数量不一致或无法确定父题，则保留为未关联并要求人工确认；不得使用标签、题干语义或 AI 猜测题目对应关系。

## 6. 运行流程

### 6.1 原卷入库

```text
原卷归档
  → 解析并导入题库
  → 对缺少完整标签的题执行一次批量 AI 打标签
  → 保存全部现有多维标签
  → 建立批改题到题库题的确定性关联
  → 重算完整度
```

流程中不存在“技能本地关联”阶段，也不调用 `SkillResolutionService`、`LLMSkillContextRanker` 或评分标准技能同步。

### 6.2 批改

批改仍由评分标准和学生作答决定分数。对已关联题目，系统从题库读取精简上下文：

- 知识点；
- 细分考法；
- 方法和数学模型；
- 前置知识；
- 常见错因候选。

批改 AI 返回得分、扣分依据、置信度、主错因和最多两个次要错因，不返回 `knowledge_id`、`knowledge_ids`、技能名或技能 ID。未入库或未关联题目仍可批改，但没有题库标签上下文，也不进入知识图谱。

### 6.3 知识图谱

```text
学生题目结果
  → session_id + question_id
  → grading_question_links.bank_question_id
  → question_tags(tag_type = knowledge_point)
  → 按最新 tag_value 聚合得分、失分、错因和学生证据
```

部分题目缺失时，只展示已经可靠关联且已有知识点标签的部分。页面同时显示已覆盖评分题数、总评分题数、缺失题号和缺失原因。

### 6.4 训练推荐

训练目标和候选题都直接读取 `question_tags`：

1. 候选题必须与薄弱证据至少共享一个完全相同的 `knowledge_point`；
2. 共享的 `sub_skill`、`method`、`model` 和 `prerequisite` 用于提高排序；
3. 难度、学生层次、题目频次和来源多样性继续复用现有排序信号；
4. `grading_question_links.bank_question_id` 用于排除本次考试原题；
5. 不使用技能邻居、技能别名或语义相似度补入候选。

## 7. 错因设计

### 7.1 题库候选

题库已有 `error_type` 标签就是常见错因候选，不新增错因目录表。批改时只向 AI 发送当前题目的候选值。

### 7.2 学生结果

尽量复用现有字段：

- `error_category`：主错因大类；
- `error_summary`：主错因具体标签，优先为题库候选中的原值；
- `deduction_reason`：学生作答证据和扣分说明；
- 主 Web 阅卷表 `session_details` 新增唯一字段 `secondary_errors_json`：最多两个次要错因，每项包含类别、具体标签和简短证据；领域对象只暴露一个 `secondary_errors` 列表。旧命令行兼容表 `grading_details` 本阶段不扩展，避免在两套历史结果表继续复制新字段。

满分题的主错因为空、次要错因为空数组。候选均不符合时，主错因或次要错因可使用“其他”，具体说明只保存在学生结果。任何学生错因都不能自动修改题库标签。

## 8. 进度、请求和重试

### 8.1 真实阶段

页面按以下阶段展示进度：

1. 解析并导入题目；
2. AI 批量打标签；
3. 保存题库标签；
4. 建立题目对应关系；
5. 重算完整度并完成。

只有第 5 步结束才能显示 100%。页面显示总题数、批次数、已发送模型请求数、失败题数和当前阶段。

### 8.2 API 约束

- 使用题库已保存的并发数和 RPM，不再读取不存在的会话键；
- 所有模型请求共享同一限流器；
- 不存在打标后的技能消歧请求；
- 批次失败不静默扩散成不受控的逐题请求；
- JSON 修复和自动重试次数固定、可计数，并计入页面请求数；
- 达到上限后保留部分结果，等待用户明确重试。

### 8.3 幂等重试

每道题只需要记录或计算三个事实：是否已导入、现有多维标签是否完整、是否已与批改题对应。点击“继续处理”只补缺失步骤：

- 已有完整标签的题不重新调用 AI；
- 已导入但未标注的题只补标签；
- 已标注但未对应的题只补题目关系；
- 已完成的题不重复写入。

中断后状态必须转为 `partial` 或 `failed`，下次打开页面不得永久停留在 `running`。

## 9. 页面设计

考试工作台、批改页和全局知识图谱继续复用同一张工作流卡片。卡片只显示：

- 未处理、处理中、部分完成、已完成或失败；
- 导入题数、完整标签题数、已对应题数；
- 当前阶段、请求数和失败数；
- “入库并打标签”或“继续处理缺失项”按钮；
- 缺失题号与原因。

页面不再显示“技能是否已本地关联”，也不把未匹配技能词条作为主待办。题库原有多维标签管理界面保持不变。

知识图谱以 `knowledge_point` 为节点。点击节点后展示：

- 得分、失分和掌握率；
- 涉及题目和学生证据；
- 细分考法、方法、能力、模型和前置知识；
- 主错因和次要错因分布；
- 对应训练题数量。

## 10. 兼容与迁移

第一阶段只切换运行读取路径，不立即删除旧数据：

- 停止新写入 `assessment_item_skills`；
- 新图谱和训练推荐不读取 `assessment_item_skills`、`question_skill_links` 或评分结果中的 `knowledge_id(s)`；
- 停止新流程调用评分标准技能同步、技能解析和技能消歧；
- 旧字段和旧表保留只读一个版本，用于回退与历史页面兼容；
- 无原卷或无题库关联的历史考试显示补充原卷入口，不回退到旧知识点匹配；
- 当前已有部分标签的原卷复用现存 `question_tags`，只补缺失题目。

运行稳定一个版本并完成数据审计后，再单独设计旧字段与旧表清理迁移。

## 11. 错误处理

- 原卷解析失败：不调用 AI，保留原卷并显示失败原因；
- 部分题目打标失败：保存成功题目，图谱只展示可靠部分；
- 标签保存失败：标记具体题目，不把进度置为完成；
- 题目对应失败：列出题号供人工确认，不调用语义匹配；
- 批改时标签上下文缺失：继续批改，不生成该题图谱证据；
- 标签被人工修改：下次查询立即反映最新值；
- 常见错因候选缺失：AI 只能返回“其他”及说明，不写回题库。

## 12. 测试策略

### 12.1 字段与提示词契约

- 题库打标继续保存所有现有标签维度；
- 批改提示词不要求 `knowledge_id`、`knowledge_ids` 或技能字段；
- 主错因、最多两个次要错因、满分无错因和“其他”均经过校验；
- 除 `secondary_errors_json` 外不新增重复标签字段。

### 12.2 请求与重试

- 使用计数测试客户端证明打标签完成后没有隐藏模型请求；
- 页面请求计数与客户端实际调用数相等；
- 进度只有完整流程结束才达到 100%；
- 部分失败后重试不会重新提交已完整标注题目；
- 保存的并发与 RPM 在三个入口一致生效。

### 12.3 图谱与推荐

- 图谱只从已关联题库题的最新 `knowledge_point` 标签聚合；
- 修改题库标签后，历史图谱无需重新批改即可更新；
- 部分标签数据只生成部分图谱并准确显示完整度；
- 推荐候选至少共享一个精确知识点标签；
- 细分考法、方法、模型和前置知识能影响排序；
- 本次考试原题能通过题目关联可靠排除；
- 新路径不读取 `skill_id`、技能邻居或旧知识映射。

### 12.4 浏览器验证

- 考试工作台、批改页和全局图谱的状态与按钮一致；
- 验证未处理、处理中、部分完成、失败、继续处理和完成状态；
- 验证标签详情、错因分布、缺失题号和训练题数量；
- 检查 1366×768、1440×900、1920×1080，无横向溢出或阻塞式弹窗；
- 浏览器控制台无相关错误。

## 13. 验收标准

1. 原卷入库只执行一次题库 AI 打标签，不再进行技能 AI 消歧；
2. 题库现有定位、知识点、方法、能力、模型、易错点等标签完整保留；
3. 知识图谱主节点直接来自最新 `knowledge_point` 标签；
4. 批改题只关联题库题，不再关联技能目录；
5. 历史图谱在题库标签修改后自动更新；
6. 批改提示词不要求模型输出知识点或技能；
7. 批改可使用题库常见错因候选，并保存一个主错因和最多两个次要错因；
8. 未完成题目不会被静默填充，部分图谱显示真实完整度；
9. 已完整标注题目重试时不会再次调用 AI；
10. 页面 100% 表示导入、标签保存、题目对应和状态重算均已结束；
11. 图谱与训练推荐使用同一组题库标签；
12. 除必要的 `secondary_errors_json` 外，不新增重复的知识点、技能或错因身份字段；
13. 批改、复核和报告导出不被题库流程阻断；
14. 旧技能链路保留只读回退期，但不参与新路径运行。

## 14. 回退策略

第一阶段不删除旧表、旧字段或旧服务。若新标签直连路径出现阻断性问题，可在功能分支上恢复旧读取入口；回退不需要逆向迁移用户数据。回退期间不得同时混合两套图谱结果，必须明确选择单一路径。
