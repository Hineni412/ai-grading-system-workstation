# 题框标定编辑器重构设计

## 1. 背景与目标

当前题框标定编辑器基于 `streamlit-drawable-canvas`，存在以下已确认问题：

- 拖动、缩放和选择题框时频繁触发 Streamlit 整页重算，操作卡顿。
- 画布对象与题框记录按列表顺序对应，删除或重排后可能写错题框。
- 画布首次初始化后不能可靠接收 Python 侧状态更新，可能出现题框不显示、选中状态不更新或显示过期。
- 画布宽度固定，左侧全局侧栏和右侧映射表展开后会压缩、遮挡或截断画布。
- 删除操作立即写数据库，而其他调整等待最终保存，正式数据可能处于混合状态。
- 当前画布依赖已停止维护的第三方组件，并需要兼容补丁才能适配现有 Streamlit。

本次重构目标是建立一个稳定、流畅、可恢复的题框标定流程：

1. 连续框选、移动、缩放和删除时保持流畅，不因鼠标移动反复重算整页。
2. 题框拥有稳定身份，任何删除、排序或跨页操作都不会影响其他题框。
3. 画布响应可用宽度变化，侧栏展开、窗口缩放后题框坐标不漂移。
4. 所有编辑先进入可恢复草稿，只有完成标定时才更新正式数据库。
5. 保留当前按评分单元顺序自动绑定题号的业务逻辑。

## 2. 已选方案

采用“方案 A：专注画布 + 临时题框抽屉”，并重做专用题框画布组件。

进入题框标定后，页面切换到专注模式：

- 默认收起全局左侧栏。
- 画布使用全部主要可用宽度。
- 题框映射表以右侧临时抽屉呈现，不长期挤压画布。
- 正常新增并自动绑定题号时，抽屉保持关闭。
- 未能绑定、发现未经确认的同题多框或教师主动点击“题框列表”时打开抽屉。

不采用以下方案：

- 不继续修补 `streamlit-drawable-canvas`，避免延续兼容性和同步问题。
- 不拆成独立于 Streamlit 的完整网页应用，避免引入过大的部署和维护成本。
- 不采用“先全部框选、再集中映射”的强制分步流程，保留教师随时检查题号映射的能力。

## 3. 页面与交互

### 3.1 顶部工具栏

顶部工具栏始终可见，包含：

- 退出专注模式
- 正面 / 反面切换
- 新增框
- 撤销 / 重做
- 适应宽度
- 缩小 / 当前缩放比例 / 放大
- 完成标定
- 草稿自动保存状态与时间

键盘操作：

- `Delete`：删除当前选中框
- `Ctrl+Z`：撤销
- `Ctrl+Shift+Z` 或 `Ctrl+Y`：重做
- 按住空格并拖动：平移画布
- `Esc`：取消当前新增框动作或关闭题框抽屉

### 3.2 连续框选与自动绑定

新增题框后，Python 继续使用现有评分单元顺序绑定规则：

```text
Q1 -> Q2 -> Q3(1) -> Q3(2) -> ...
```

规则如下：

- 正常找到下一个未使用的评分单元时，自动绑定并保持题框抽屉关闭。
- 找不到可绑定题号时，将题框标记为“未绑定”，自动打开题框抽屉。
- 新增框后，页面底部显示下一个预计自动绑定的题号。
- 教师可在题框抽屉中随时覆盖自动绑定结果。

### 3.3 题框抽屉

题框抽屉从右侧临时覆盖部分画布，但不改变画布坐标、缩放比例或题框数据。

抽屉包含：

- 当前页面与全部页面的题框数量
- 每个题框的题号、状态和定位按钮
- 修改绑定题号
- 删除题框
- 同题多框确认
- 未绑定、越界、尺寸过小等异常说明

抽屉自动打开条件：

- 新框无法自动绑定题号
- 检测到尚未确认的同题多框
- 教师主动点击“题框列表”

### 3.4 同题多框

同一道题允许合法对应多个作答框，例如跨页作答、续答区域或分散作答区域。

- 检测到同题多框时标黄提醒并自动打开抽屉。
- 教师点击“确认同题多框”后，该组不再提示。
- 已确认同题多框不阻止完成标定。
- 未确认同题多框阻止完成标定。

## 4. 状态分层与数据流

系统只保留三层状态。

### 4.1 正式数据

正式题框保存在数据库 `answer_regions`。

- 批改流程只读取正式数据，不读取草稿。
- 未点击“完成标定”前，正式数据不发生变化。
- 完成标定校验通过后，在单个数据库事务中一次性替换当前考试题框。

### 4.2 可恢复草稿

每场考试保存独立草稿：

```text
user_data/templates/session_<session_id>/region_draft.json
```

草稿记录：

```json
{
  "schema_version": 1,
  "session_id": 1,
  "template_fingerprint": "...",
  "revision": 12,
  "updated_at": "2026-06-13T21:42:00+08:00",
  "regions": [],
  "confirmed_multi_region_groups": []
}
```

草稿规则：

- 新增、移动、缩放、删除、撤销、重做和修改题号等完整操作结束后自动保存。
- 使用“写临时文件，再替换正式草稿文件”的方式，避免产生半个 JSON。
- 页面刷新或软件重启后提示恢复上次未完成草稿。
- 点击“完成标定”成功后删除草稿。
- 点击“放弃草稿”需要二次确认，并恢复正式数据库版本。
- 清空全部题框只修改草稿，不立即修改正式数据库。
- 样卷重新上传后，通过 `template_fingerprint` 判断旧草稿是否兼容；不兼容草稿不会自动套用。

### 4.3 浏览器画布状态

浏览器组件负责高频交互：

- 拖动、缩放、平移、选中和框选过程只在浏览器内运行。
- 拖动过程中不通知 Python。
- 鼠标松开、新增完成、删除、撤销或重做完成后，向 Python 提交一次最新题框状态。
- 缩放、平移和选择状态不写入草稿。

数据流：

```text
正式数据库
  -> 首次进入或放弃草稿
可恢复草稿
  -> 加载并编辑
专用题框画布
  -> 完整操作结束
更新草稿
  -> 点击完成标定并通过检查
单事务替换正式数据库
```

## 5. 专用画布组件

### 5.1 技术边界

采用 Streamlit Custom Components v2 实现专用题框画布。

组件只负责：

- 渲染试卷图片与题框
- 新增矩形
- 选择、移动、缩放和删除题框
- 缩放与平移画布
- 撤销和重做
- 将完整操作后的题框状态发送给 Python

Python 负责：

- 题号顺序自动绑定
- 草稿持久化和恢复
- 异常检测
- 正式数据库事务提交
- 批改就绪状态和正式快照

### 5.2 题框身份与结构

每个题框使用不可变 `region_uuid`，不再使用列表位置识别题框。

题框结构至少包含：

```json
{
  "region_uuid": "uuid",
  "page": "front",
  "region_order": 1,
  "x": 120,
  "y": 340,
  "w": 860,
  "h": 260,
  "mapped_question_id": "Q3(1)",
  "mapping_status": "auto",
  "multi_region_confirmed": false
}
```

`mapping_status` 允许：

- `auto`：按顺序自动绑定
- `manual`：教师手动绑定
- `unbound`：尚未绑定

数据库 `answer_regions` 新增非空且唯一的 `region_uuid` 字段。迁移时为每条旧记录生成一次 UUID 并写回数据库，此后读取和保存始终沿用该值。迁移不改变现有坐标、题号或历史批改结果。

### 5.3 坐标与缩放模型

- 所有题框坐标始终保存为原始试卷图片像素坐标。
- 组件使用 SVG `viewBox` 将原图坐标映射到当前显示区域。
- 页面宽度、侧栏状态、窗口大小和浏览器缩放不会改变题框数据。
- 缩放和平移只改变视图变换，不改变题框坐标。
- 提供适应宽度、100%、放大、缩小和按住空格平移。
- 轻微越界在操作结束时吸附到图片边界。
- 明显越界保留为异常状态，并阻止完成标定。

## 6. 校验与正式提交

### 6.1 阻止完成标定的错误

- 未绑定题号
- 题框明显越界
- 题框尺寸过小
- `region_uuid` 重复
- 同题多框尚未确认
- 草稿模板指纹与当前样卷不一致

完成标定前展示检查结果，错误必须处理后才能提交。

### 6.2 事务提交

新增数据库方法负责单事务提交当前考试全部题框：

1. 开始事务。
2. 再次校验所有题框。
3. 替换当前考试的 `answer_regions`。
4. 更新模板确认状态。
5. 在同一事务中记录“正式快照待生成”状态并提交事务。
6. 根据已提交的正式数据库内容生成题框快照与工作流状态文件。
7. 快照生成成功后删除草稿并清除“正式快照待生成”状态。

数据库写入任一步骤失败时回滚事务，原正式题框保持不变。数据库是正式题框的唯一事实来源；快照写入失败不会撤销已经成功提交的正式题框，而是保留草稿和“正式快照待生成”状态，提示教师重试生成快照。批改流程仍可读取已提交的正式数据库题框。

## 7. 异常处理与兼容策略

- 草稿 JSON 损坏时，不覆盖正式数据；提示重新载入正式版本，并保留损坏文件用于排查。
- 样卷重新上传后，旧草稿标记为不兼容，由教师选择放弃或查看，不自动恢复。
- 退出专注模式时，如有未提交改动，仅提示草稿已保存，不强迫正式提交。
- 新组件初期保留旧编辑器作为隐藏回退入口，仅用于紧急恢复和对比排查。
- 新组件完成实际使用验证后，再单独删除旧编辑器和 `streamlit-drawable-canvas` 依赖。

## 8. 代码边界

避免继续扩大 `web_app.py`，将新逻辑拆分为聚焦模块：

```text
answer_region_models.py
  题框结构、规范化、UUID 和校验结果模型

answer_region_draft_service.py
  草稿加载、原子保存、放弃和模板指纹校验

answer_region_commit_service.py
  完成标定校验、数据库事务提交和快照处理

answer_region_editor_component.py
  Streamlit Components v2 注册与 Python 包装器

components/answer_region_editor/
  专用画布的 HTML、CSS 和 JavaScript

tests/test_answer_region_models.py
tests/test_answer_region_draft_service.py
tests/test_answer_region_commit_service.py
tests/test_answer_region_editor_sync.py
```

`web_app.py` 只负责页面组合、工具栏、抽屉、状态提示和调用上述服务。

## 9. 测试与验收

### 9.1 自动化测试

必须覆盖：

- 旧题框自动补充 `region_uuid`
- 按题目顺序自动绑定新框
- 删除任意框不改变其他框坐标或题号
- 画布对象重排不影响题框身份
- 正反面分别编辑
- 同题多框确认和未确认状态
- 未绑定、越界、过小和 UUID 重复校验
- 草稿原子保存、恢复、放弃和损坏处理
- 样卷指纹不匹配时拒绝自动恢复
- 完成标定成功后正式数据库替换和草稿删除
- 模拟数据库失败时事务完整回滚

### 9.2 页面验收

- 连续新增、移动、缩放和删除 50 个框，不出现明显卡顿、丢框或错框。
- 删除任意框不影响其他框的坐标或题号。
- 展开或收起全局侧栏、改变窗口宽度后，框坐标不漂移。
- 正常新增并自动绑定时，题框抽屉不自动打开。
- 未绑定或未经确认的同题多框会打开抽屉并明确提示。
- 刷新页面或重启软件后可恢复草稿。
- 未点击“完成标定”前，正式数据库保持不变。
- 提交失败时正式数据库完整回滚，草稿仍可恢复。

## 10. 实施阶段

分四个可独立验证的阶段实施：

1. **数据与服务层**
   - 增加 `region_uuid`
   - 建立题框模型、草稿服务、校验和事务提交
   - 完成服务层自动化测试

2. **专用画布组件**
   - 实现 SVG 坐标模型、题框编辑、撤销重做和操作结束事件
   - 验证稳定身份同步和响应式缩放

3. **专注标定页面**
   - 接入工具栏、题框抽屉、顺序自动绑定、异常提示和完成标定流程
   - 保留旧编辑器隐藏回退入口

4. **综合验证与清理**
   - 浏览器交互测试、性能和恢复验证
   - 实际使用观察稳定后，另行删除旧编辑器与旧依赖

## 11. 本次不包含

- 不改变批改服务读取正式题框的业务方式。
- 不自动判断两个题框是否语义上应属于同一道题，仍由题号绑定和教师确认决定。
- 不在第一阶段删除旧编辑器。
- 不修改现有正式数据库内容，除非实施阶段执行明确的数据迁移。
