# 题库源试卷归档与可迁移路径设计

## 背景

题库当前存在两条不一致的源试卷导入路径：网页上传的试卷会保存到
`user_data/question_bank/raw_papers/`，而通过本地文件选择器导入的 DOCX
只在数据库中记录原始绝对路径。后者在原文件被删除、项目移动或换电脑后，
会导致原卷预览重建和富文本回填失去源文件。

当前题库基线包含 477 道题、4,581 条标签和 12 个仍然存在但位于项目目录外的
DOCX 源文件引用。迁移必须保持题目、答案、标签、题目 ID 和软删除状态不变。

## 目标

- 所有新导入的 DOCX/PDF 在解析前统一归档到
  `user_data/question_bank/raw_papers/`。
- 使用内容哈希去重，相同内容只保存一个归档副本。
- 数据库保存可随 `user_data` 一起移动的数据相对路径，不再依赖旧电脑盘符。
- 将现有数据库中的外部源文件安全迁入归档目录并更新引用。
- 原始外部文件只复制、不移动、不删除。
- 题库复制到新电脑后，原卷预览、富文本回填、题图显示和组卷导出能够解析旧路径。

## 非目标

- 不修改题目正文、答案、标签或标签模型结果。
- 不重新调用 AI，也不重新消耗标签分析 Token。
- 不删除现有原始文件、题图、富文本侧车或历史预览。
- 不改变 API 配置及其存储方式。
- 不在本功能中调整 Git 对 `user_data` 的跟踪策略。

## 归档结构

归档目录固定为：

```text
user_data/
  question_bank/
    raw_papers/
      原试卷名_<sha256前12位>.docx
```

归档服务计算完整 SHA256，文件名使用前 12 位以保持可读性。发现相同前缀候选时，
必须比较完整哈希后才能复用；若内容不同，则创建独立归档文件。文件复制先写入同目录
临时文件，校验大小和完整哈希后再原子替换为正式文件。

归档服务返回两个值：

- `physical_path`：当前电脑上供解析器读取的绝对路径。
- `stored_path`：相对于数据根目录的可迁移路径，例如
  `question_bank/raw_papers/试卷_a1b2c3d4e5f6.docx`。

## 组件边界

### 源试卷归档服务

新增独立服务，负责：

- 校验源文件存在且扩展名受支持。
- 计算 SHA256 和安全归档文件名。
- 复用内容相同的已有归档。
- 原子复制并验证归档完整性。
- 生成物理路径和可迁移存储路径。

该服务不连接数据库，也不解析试卷。

### 题库资产路径解析器

新增题库专用路径解析接口，规则如下：

1. 已存在的绝对路径直接使用。
2. `question_bank/...` 相对路径基于当前数据根目录解析。
3. 包含旧 `user_data` 或 `data` 片段的绝对路径重映射到当前数据根目录。
4. 最后可在 `raw_papers`、`extracted_images` 和 `previews` 中按文件名查找。
5. 找不到时返回原路径并由调用方报告明确错误，不静默选择多个同名文件。

原卷预览、富文本回填、题库题图显示和组卷导出统一使用该解析器。这样现有题图
JSON 中保存的旧绝对路径也能在复制 `user_data` 后继续解析。

### 导入协调

批量导入器在解析前调用归档服务。解析器读取 `physical_path`，写入 `papers`、
`questions` 和预览记录时使用 `stored_path`。网页上传、本地文件选择和阅卷同步入口
全部经过同一流程，不再各自复制文件。

原始外部文件始终保留。即使解析失败，已验证的归档副本也保留，供用户修复后重试。

## 新导入数据流

1. 用户选择或上传 DOCX/PDF。
2. 归档服务计算哈希并复制或复用归档副本。
3. 导入器从归档物理路径解析题目、答案、富文本和图片。
4. 题目图片继续保存到 `user_data/question_bank/extracted_images/`。
5. 数据库写入可迁移的源试卷路径。
6. 富文本侧车写入 `user_data/question_bank/rich_content/`。
7. 题目成功入库后再执行可选的 AI 标签分析。

## 现有数据迁移

新增命令行迁移工具，支持 `--dry-run` 和明确的 `--apply`：

1. 读取 `papers.source_file`、`questions.source_file` 和
   `question_previews.source_file` 的去重路径集合。
2. 对仍存在且位于归档目录外的文件计算哈希。
3. 在 `raw_papers` 中复制或复用归档副本。
4. 创建题库数据库时间戳备份。
5. 在单个 SQLite 事务中，将所有匹配旧路径的引用更新为对应 `stored_path`。
6. 提交前验证题目数、标签数、题目 ID 集合和标签行内容摘要保持不变。
7. 提交后逐一解析新路径并确认归档文件存在。
8. 输出已迁移、已去重、缺失、跳过和失败的路径统计。

缺失源文件只记录，不更新数据库。单个文件复制失败不影响其他文件；数据库验证失败则
整个数据库事务回滚。事务失败后已经复制的归档文件可以保留，它们不改变题库状态。

## 兼容性

- 旧绝对路径继续可读，迁移工具不是应用启动的硬性前置条件。
- 新代码可读取旧数据库；旧代码不保证理解新的数据相对路径，因此迁移后不得降级到
  本功能之前的程序版本。
- 完整备份继续包含 `user_data/question_bank/raw_papers/`。
- API 配置保持原状，不参与迁移。

## 安全与隐私

- 不输出源试卷内容、题目内容、学生信息或 API Key。
- 迁移日志只记录必要路径、哈希短前缀和统计数据。
- 所有写入目标必须验证位于当前 `raw_papers` 目录内。
- 不跟随目标目录外的符号链接作为归档目标。
- 数据库备份成功前禁止执行路径更新。

## 测试策略

测试使用临时目录和临时 SQLite 数据库，覆盖：

- 归档复制后原文件仍存在且内容不变。
- 相同内容、相同或不同文件名只复用一个归档。
- 同名不同内容生成不同归档。
- 哈希候选碰撞时验证完整 SHA256。
- 已在归档目录内的文件不会重复复制。
- 新导入的 `papers`、`questions` 和预览记录保存可迁移路径。
- 旧 `user_data` 绝对路径可映射到新数据根目录。
- 缺失源文件只报告、不更新数据库。
- 迁移事务失败时所有数据库路径保持原值。
- 迁移前后题目数、题目 ID、标签数和标签摘要完全一致。
- 现有 477 道题和 4,581 条标签的生产数据迁移前后只做只读校验。

## 验收标准

- 三条导入入口均不再把外部绝对路径写入题库数据库。
- 相同源试卷重复导入不会产生重复归档。
- 现有可访问外部源试卷全部归档，数据库不再引用项目外路径。
- 迁移前后题目与标签数据完全一致，无新的 AI 请求。
- 将完整 `user_data` 复制到不同项目路径后，源试卷预览、富文本回填、题图显示和组卷导出通过自动化测试。
- 外部原文件和 API 配置均未被修改或删除。
