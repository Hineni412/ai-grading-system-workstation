# 分层知识图谱与小问级标签设计

## 1. 文档状态

- **状态：** 已由用户确认总体设计，等待书面规格复核
- **日期：** 2026-06-30
- **适用项目：** AI 阅卷系统工作机版 v1.5.0
- **依据：** 当前题库标签、评分小问结构、诊断聚合代码、全局知识图谱页面、真实数据库只读抽样与浏览器复核
- **用户已确认决策：** 采用“分层界面 + 小问级标签”；历史数据由系统生成候选映射，教师确认后生效

## 2. 背景与问题

当前活动知识图谱以题库 `question_tags.tag_type = 'knowledge_point'` 的精确标签值为节点。评分小问通过来源题关联找到父级题库题目，然后继承父题的全部标签。该路径保证了标签来源确定、教师修改后可刷新、图谱查询时不重新调用 AI，但存在以下可用性和数据语义问题：

1. `knowledge_point` 候选本身是“一次函数”“轴对称”“三角形全等”等宽泛主题，题库已有的 `sub_skill`、`method`、`model`、`ability` 和 `prerequisite` 只作为附属文字展示。
2. 同一道大题的所有评分小问继承完全相同的父题标签，导致不同小问的成绩重复计入多个知识点，形成看似精确但无法区分具体考法的指标。
3. 全班总览只显示知识点卡片；点击后直接展开大量学生题次、自由文本错因和未分组支持标签，缺少“知识点 → 子技能 → 评分小问”的中间诊断层。
4. 总览与详情存在加权口径、标签命名和“扣分题次/扣分分值”表述不一致。

本设计同时解决“看得更细”和“算得更准”，但不建设完整课程知识依赖网络，不改变评分结果，也不让 AI 候选未经教师确认直接成为业务事实。

## 3. 目标与非目标

### 3.1 目标

1. 将知识图谱默认结构调整为“教材章节 → 知识点 → 主要子技能 → 评分小问”。
2. 为每个评分小问建立可审查的小问级标签映射，区分主要诊断子技能和支持标签。
3. 每个评分小问只向一个已确认的主要诊断子技能贡献一次分数，消除跨标签重复计分。
4. 为现有考试自动生成候选映射，教师确认、修改或拒绝后才进入细粒度统计。
5. 未确认、生成失败或标签失效时保留明确的粗粒度降级，不阻断批改和现有图谱。
6. 全班详情先按评分小问和子技能汇总，再按需查看分页学生证据。
7. 统一学生、全班、总览和详情的按分值加权口径。

### 3.2 非目标

1. 不建立“先修、包含、相似、迁移”等全局知识关系网络。
2. 不把方法、模型、能力或错因扩展为参与掌握率计算的平级主节点。
3. 不改变批改模型的给分规则、已保存分数、人工复核结果或报告导出条件。
4. 不改变训练推荐当前以精确 `knowledge_point` 匹配候选题的必要条件；训练推荐利用小问级标签属于后续独立设计。
5. 不自动合并近义子技能，不以本地模糊匹配或未经确认的 AI 推测替代教师决策。

## 4. 核心业务规则

### 4.1 标签角色

每个有效评分小问最多具有：

- **一个主要诊断子技能：** `tag_type = 'sub_skill'`、`role = 'primary'`，参与子技能掌握率计算；
- **多个支持标签：** 可来自 `knowledge_point`、`method`、`model`、`ability`、`prerequisite` 和 `error_type`，仅用于分组、解释、筛选和候选生成，不重复计分。

主要子技能不能由运行时默认值静默补齐。没有已确认主要子技能的小问不得生成子技能掌握率。

### 4.2 分数归属

1. 每条学生评分小问记录按其实际 `score_awarded / full_score` 参与计算。
2. 同一条评分记录只向已确认的主要子技能贡献一次分子和分母。
3. 知识点掌握率按属于该知识点的唯一评分记录直接汇总，不能通过相加子技能统计反推，以避免一个知识点下多个子技能再次重复。
4. 全班统计汇总学生评分记录，继续以分值作为权重。
5. `deduction_count / item_count` 的界面名称统一为“失分题次 / 总题次”；扣分分值另行显示时使用 `full_score - score_awarded`。

### 4.3 候选与正式数据

- `suggested` 只表示系统候选，不参与细粒度图谱。
- `confirmed` 表示教师已确认，可参与图谱聚合。
- `rejected` 表示教师明确拒绝，重新生成时默认不自动恢复同一候选。
- `stale` 表示来源题、评分小问或题库标签已变化，必须重新确认。

AI 可以提出新的 `sub_skill` 文本，但确认前不得写入正式 `question_tags`。教师确认新词时，在同一事务中写入或复用精确相同的 `question_tags`，并将对应小问映射置为 `confirmed`。

## 5. 数据模型

### 5.1 新表：`assessment_item_tag_mappings`

该表放在题库数据库，因为它同时依赖题库题目、题库标签和现有 `grading_question_links`。它表达“某场考试的某个评分小问选择了父题当前标签中的哪些语义，以及哪个子技能负责计分”。

建议字段：

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `grading_session_id` | 阅卷会话标识，沿用跨库应用层关联方式 |
| `source_item_ref` | 评分小问标识，如 `Q11(2)` |
| `parent_source_question_id` | 父级来源题标识，如 `Q11` |
| `bank_question_id` | 已确认关联的题库题目 ID |
| `tag_type` | 标签类型 |
| `tag_value` | 精确标签值 |
| `role` | `primary` 或 `supporting` |
| `status` | `suggested`、`confirmed`、`rejected` 或 `stale` |
| `confidence` | 候选生成置信度；人工确认后仅作审计依据 |
| `source` | `ai_candidate`、`manual` 或 `migration` |
| `evidence_json` | 生成依据摘要，如评分目标、步骤和候选说明，不保存学生敏感作答 |
| `model_name` | 生成候选时使用的模型名称；人工创建可为空 |
| `reviewed_at` | 最近确认或拒绝时间 |
| `created_at` / `updated_at` | 审计时间 |

约束：

1. `(grading_session_id, source_item_ref, tag_type, tag_value, role)` 唯一。
2. 同一 `(grading_session_id, source_item_ref)` 最多存在一条 `status = 'confirmed' AND role = 'primary'` 的映射，通过部分唯一索引或事务校验保证。
3. `role = 'primary'` 时 `tag_type` 必须为 `sub_skill`。
4. `bank_question_id` 必须引用存在且未删除的题库题目。
5. 映射确认时，`tag_type/tag_value` 必须对应同一 `bank_question_id` 的当前正式标签；新词先写入正式标签再确认映射。

### 5.2 不直接引用 `question_tags.id`

现有题库编辑可能删除并重建标签行。映射使用 `(bank_question_id, tag_type, tag_value)` 精确校验，避免因行 ID 重建导致无意义失效。标签值变化后，映射通过一致性检查转为 `stale`，不自动跟随改名。

### 5.3 迁移与回退

1. 新表为空时，现有知识点图谱行为保持可用。
2. 数据库迁移只新增表、索引和必要触发/校验，不改写现有评分或题库标签。
3. 回退版本忽略新表即可继续使用原图谱；删除新表不是应用回退的必要条件。
4. 发布前备份题库数据库，并对迁移做空库、现存库和重复执行验证。

## 6. 候选生成与教师确认

### 6.1 输入

候选服务按已确认来源题关联读取：

- 评分小问 `source_item_ref`、分值、`core_goal`、`required_elements` 和步骤；
- 父题题干与答案；
- 父题当前 `knowledge_point`、`sub_skill`、`method`、`model`、`ability`、`prerequisite` 和 `error_type`；
- 同一大题的其他小问，帮助避免把全部标签分配给每个小问。

不发送学生作答、姓名、学号或原卷图片。

### 6.2 生成策略

1. 复用题库当前打标模型配置、限流器、重试上限和请求计数。
2. 每道父题作为一个候选生成单元，模型一次返回其全部小问映射，避免小问之间互不知情。
3. 输出必须包含每个小问恰好一个主要子技能候选或显式 `unresolved`，以及可选支持标签。
4. 支持标签必须从当前父题正式标签中选择。
5. 主要子技能优先复用父题已有 `sub_skill`；确实缺失时可以提出一个简短新词，并标记 `is_new = true`。
6. 模型不能直接写数据库；服务先校验题号完整性、标签类型、长度、重复项和新词数量，再保存为 `suggested`。
7. 批量失败不扩散成无限逐题请求；达到上限后保留已成功候选，并将失败小问标为待人工处理。

### 6.3 确认界面

确认页按父题分组，每个小问显示：

- 小问号、分值、评分目标和关键步骤；
- 建议主要子技能、是否为新词、置信度和简短依据；
- 方法、模型、能力、前置知识等支持标签；
- 接受、修改、拒绝操作。

教师可以从父题已有子技能中改选，也可以编辑一个新子技能。单个小问确认后立即保存；整题“全部接受”只对结构完整、无 `unresolved` 且没有重复主要技能警告的候选开放。

### 6.4 历史数据

现有考试在图谱页显示“小问标签待确认”入口。点击后执行与新试卷相同的候选生成流程。候选未确认前：

- 继续显示现有知识点级汇总；
- 小问节点可按评分目标展示实际得分率，但标记“未精确归因”；
- 不生成子技能掌握率；
- 不把候选写入训练推荐或其他业务流程。

## 7. 投影与聚合

### 7.1 小问标签投影

扩展现有标签投影服务，使每个评分小问返回：

- 父题当前正式标签；
- 已确认主要子技能；
- 已确认支持标签；
- 映射状态和缺失原因；
- 粗粒度/细粒度标记。

处理顺序：

```text
评分小问
  → 已确认来源题关联
  → 父题当前正式标签
  → 当前小问已确认映射
  → 一致性校验
  → 细粒度证据或显式粗粒度降级
```

若来源题未关联、题库题缺失或没有 `knowledge_point`，沿用现有图谱缺失原因。若仅缺少小问映射，知识点图谱仍覆盖该小问，但细粒度完整度不计入覆盖。

### 7.2 两套完整度

页面分别显示：

- **知识点覆盖：** 已关联且具有 `knowledge_point` 的评分小问数 / 总评分小问数；
- **小问精细度：** 已确认主要子技能的评分小问数 / 知识点已覆盖小问数。

两者不能合并为一个数字，以免“有知识点”被误解为“已完成精确归因”。

### 7.3 聚合结果

诊断服务输出三层统计：

1. `knowledge_points`：按唯一评分记录聚合；
2. `primary_sub_skills`：仅按已确认主要子技能聚合；
3. `assessment_items`：按 `session_id + source_item_ref` 聚合全班或保留单生记录。

支持标签作为各层上下文，不参与分子分母。所有层级保留证据数量、考试数量、失分题次、扣分分值和来源小问引用。

## 8. 分层界面

### 8.1 总览结构

默认展示：

```text
教材章节
└─ 知识点
   └─ 主要子技能
      └─ 评分小问
```

章节来自父题当前 `exam_scope`，只用于分组。一个知识点在多个章节出现时按当前筛选考试的真实证据分别展示，不创建新的全局章节身份。

默认展开风险最高的三个知识点，其余折叠。每层展示：

- 名称；
- 按分值加权得分率；
- 失分题次 / 总题次；
- 证据小问数；
- 精细度状态。

不再静默截断为固定 14 个节点。节点较多时使用“显示更多”和分页/虚拟化，不以隐藏数据换取布局整齐。

### 8.2 支持标签

支持标签分组显示为：

- 方法；
- 数学模型；
- 能力；
- 前置知识；
- 常见错因候选。

每组默认显示前三项和总数，展开后查看全部。`canonical_knowledge_id`、兼容技能名和内部字段不在普通教师界面直接混排。

### 8.3 全班详情

点击全班节点后，详情页先显示：

1. 知识点/子技能总体指标；
2. 各评分小问的得分率、失分人数、失分题次和扣分分值；
3. 前五项规范化错因及占比；
4. 分数区间或掌握风险分布；
5. 标签确认状态和候选处理入口。

详情页不得使用任意第一条学生记录作为全班标题，也不得初始渲染所有学生原卷记录。

### 8.4 学生证据下钻

选择一个评分小问后，分页显示学生记录。默认优先显示失分记录；支持按学生、得分状态和错因筛选。每条记录继续复用现有原卷高亮能力。单生模式保留当前展开式证据体验，但支持标签按类型分组，不再拼接成超长文本。

### 8.5 文案与可访问性

- “扣分 174/312”改为“失分题次 174/312”。
- 全班与单生标题明确区分。
- 粗粒度、待确认、已确认和已失效使用文字与图标双重表达，不能只靠颜色。
- 展开/折叠控件可键盘操作，具有明确可访问名称。
- 长标签换行或省略后可展开查看，不使用包含数百条原因的 `title` 属性。

## 9. 错因展示

1. 图谱统计优先按受控的 `error_category` 或题库 `error_type` 候选聚合。
2. `error_summary` 和 `deduction_reason` 作为证据文本，不直接充当全班分布的唯一分组键。
3. `manual_review_confirmed`、空值和纯系统标记不得显示为教学错因。
4. 全班默认只展示前五项错因；其余归入“其他”，但详情可查看完整证据。
5. 本设计不回写或自动提升学生错因为题库标签。

## 10. 一致性与失效处理

以下任一变化使相关已确认映射转为 `stale`：

- 来源题关联更换题库题目；
- 评分标准删除或重命名评分小问；
- 已确认主要子技能在父题正式标签中被删除或改名；
- 父题被删除。

检查发生在候选页打开、图谱查询和题库标签保存之后。`stale` 映射不参与子技能统计，但保留审计记录和原确认信息。系统显示原因并提供重新生成/人工修复入口，不静默回退为另一个标签。

## 11. 模块边界

建议新增或扩展以下职责，不把全部逻辑继续堆入 `web_app.py`：

| 模块 | 职责 |
|---|---|
| 小问标签映射仓储 | 映射增删改查、状态转换、唯一性和事务校验 |
| 小问标签候选服务 | 构造受限请求、校验模型输出、保存候选和请求统计 |
| 标签投影服务 | 将评分小问、来源题、父题当前标签和已确认映射组合成只读投影 |
| 细粒度诊断聚合器 | 按知识点、主要子技能和评分小问计算唯一证据统计 |
| 图谱视图模型构建器 | 将诊断结果转换为页面需要的分层结构和分页摘要 |
| Streamlit 页面组件 | 渲染确认工作台、分层总览和详情筛选，不承担业务聚合 |

依赖方向保持“页面 → 应用服务 → 仓储/数据库”。候选服务不读取学生作答；诊断服务不调用 AI。

## 12. 错误处理与幂等性

1. 候选请求失败：保留已成功候选，失败小问可重试，不影响批改或知识点图谱。
2. 输出缺少小问、包含未知题号或多个主要子技能：拒绝该父题候选并显示可诊断错误。
3. 重复生成：未人工修改的 `suggested` 可替换；`confirmed` 和 `rejected` 不被自动覆盖。
4. 确认新子技能：正式题库标签写入与映射确认在同一题库事务中完成。
5. 跨库读取：继续承认阅卷库与题库库没有统一事务；投影发现不一致时降级并报告，不伪造完整状态。
6. 页面数据量大：全班证据使用服务端分页/分组，不一次构造全部展开组件。

## 13. 测试与验证

### 13.1 数据与服务测试

- 新表迁移可重复执行，现存数据库数据不变，回退版本可忽略新表；
- 同一小问不能确认两个主要子技能；
- 候选不会直接进入正式统计；
- 确认新子技能时标签与映射原子保存；
- 标签删除、改名、题目关联变化和小问变化会使映射失效；
- 无映射时继续生成知识点级图谱，并准确报告精细度；
- 同一评分记录不会因多个知识点或支持标签重复计分；
- 全班、单生、总览和详情使用相同按分值加权口径；
- 候选重试不会覆盖教师确认或拒绝结果。

### 13.2 候选生成测试

- 模型输出只能引用输入父题和评分小问；
- 支持标签必须来自父题当前正式标签；
- 新子技能长度、空值、重复和数量限制有效；
- 一道多小问题能返回互相区分的主要子技能；
- 请求数、限流、失败数和重试次数与实际调用一致；
- 未配置模型时提供明确人工处理路径。

### 13.3 页面与浏览器验证

- 历史粗粒度、候选待确认、部分确认、全部确认和已失效状态；
- 全班与单生标题、统计口径和详情路径正确；
- 支持标签按类型折叠，长文本不形成巨型提示；
- 全班详情初始不渲染数百条学生记录，分页和筛选有效；
- 1366×768、1440×900、1920×1080 下无横向溢出、弹窗越界或不可读节点；
- 键盘焦点、展开按钮可访问名称、颜色对比度和文字状态提示可用；
- 浏览器控制台无相关错误或警告。

### 13.4 回归测试

- 批改、人工复核、现有知识点图谱、题库标签编辑、训练推荐和报告导出保持可用；
- 未启用小问级映射的历史考试与旧版本表现兼容；
- 题库标签修改仍能在下一次图谱查询中反映，并对失效映射给出明确提示。

## 14. 发布与回退

建议按以下顺序发布：

1. 新表、仓储和一致性校验；
2. 候选生成与教师确认页；
3. 小问标签投影和细粒度聚合；
4. 分层总览和新的全班详情；
5. 当前考试候选生成与人工确认；
6. 浏览器验收后默认启用分层界面。

发布前备份题库数据库。若细粒度路径出现问题，可通过功能开关回退到现有知识点总览；新表和已确认映射保留，不影响旧路径。回退不得删除教师已经确认的数据。

## 15. 验收标准

以当前 Q11 为代表样例，验收时应满足：

1. Q11(1)、Q11(2)、Q11(3) 可以拥有互相独立、经教师确认的主要子技能；
2. 三个小问分别显示各自实际得分率，不再把全部小问同时复制到“一次函数、函数图像、一元一次方程”的多个细粒度节点；
3. 每条学生小问成绩在子技能层只计算一次；
4. 全班点击“一次函数”后先看到小问汇总，而不是数百条学生记录和超长错因段落；
5. 未确认候选不会产生正式子技能掌握率，并有清晰的待处理提示；
6. 现有批改分数、人工复核结果和训练推荐不因本功能发生变化。
