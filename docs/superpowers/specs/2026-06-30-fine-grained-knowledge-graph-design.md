# 分层知识图谱与小问级标签设计

## 1. 文档状态

- **状态：** 已由用户确认总体设计及训练推荐扩展，等待书面规格复核
- **日期：** 2026-06-30
- **适用项目：** AI 阅卷系统工作机版 v1.5.0
- **依据：** 当前题库标签、评分小问结构、诊断聚合代码、全局知识图谱页面、真实数据库只读抽样与浏览器复核
- **用户已确认决策：** 采用“分层界面 + 小问级标签”；历史数据由系统生成候选映射，教师确认后生效；训练推荐改为小问主要子技能精确匹配和自适应难度；难度 8.0—10.0 的题不进入任何自动训练推荐；AI 按小问输出标签和一位小数难度，父题标签显示为各小问去重并集

## 2. 背景与问题

当前活动知识图谱以题库 `question_tags.tag_type = 'knowledge_point'` 的精确标签值为节点。评分小问通过来源题关联找到父级题库题目，然后继承父题的全部标签。该路径保证了标签来源确定、教师修改后可刷新、图谱查询时不重新调用 AI，但存在以下可用性和数据语义问题：

1. `knowledge_point` 候选本身是“一次函数”“轴对称”“三角形全等”等宽泛主题，题库已有的 `sub_skill`、`method`、`model`、`ability` 和 `prerequisite` 只作为附属文字展示。
2. 同一道大题的所有评分小问继承完全相同的父题标签，导致不同小问的成绩重复计入多个知识点，形成看似精确但无法区分具体考法的指标。
3. 全班总览只显示知识点卡片；点击后直接展开大量学生题次、自由文本错因和未分组支持标签，缺少“知识点 → 子技能 → 评分小问”的中间诊断层。
4. 总览与详情存在加权口径、标签命名和“扣分题次/扣分分值”表述不一致。
5. 训练推荐仅以相同 `knowledge_point` 作为入选门槛，`sub_skill`、方法和模型只影响排序；细标签不匹配和难度超出目标区间的题仍可入选。
6. 题库打标提示词虽然允许一位小数难度，但当前领域模型将难度归一化为整数，7.1 与 7.9 无法在保存后区分；整道大题也只有一组标签，不能表达各小问差异。

本设计同时解决“看得更细”和“算得更准”，但不建设完整课程知识依赖网络，不改变评分结果，也不让 AI 候选未经教师确认直接成为业务事实。

## 3. 目标与非目标

### 3.1 目标

1. 将知识图谱默认结构调整为“教材章节 → 知识点 → 主要子技能 → 评分小问”。
2. 为每个评分小问建立可审查的小问级标签映射，区分主要诊断子技能和支持标签。
3. 每个评分小问只向一个已确认的主要诊断子技能贡献一次分数，消除跨标签重复计分。
4. 为现有考试自动生成候选映射，教师确认、修改或拒绝后才进入细粒度统计。
5. 未确认、生成失败或标签失效时保留明确的粗粒度降级，不阻断批改和现有图谱。
6. 全班详情先按评分小问和子技能汇总，再按需查看分页学生证据。
7. 统一学生、全班、总览和详情的按分值加权口径。
8. 题库 AI 打标按小问输出标签、主要子技能和一位小数难度，父题标签由小问标签去重汇总。
9. 训练推荐使用已确认主要子技能作为硬门槛，并按子技能掌握率执行自适应难度硬过滤。
10. 难度 8.0—10.0 的题全局排除在自动训练推荐之外，仅允许教师明确手动选择。

### 3.2 非目标

1. 不建立“先修、包含、相似、迁移”等全局知识关系网络。
2. 不把方法、模型、能力或错因扩展为参与掌握率计算的平级主节点。
3. 不改变批改模型的给分规则、已保存分数、人工复核结果或报告导出条件。
4. 不引入在线语义检索、向量相似度或运行时 AI 猜测来补足训练候选。
5. 不自动合并近义子技能，不以本地模糊匹配或未经确认的 AI 推测替代教师决策。
6. 不在本阶段实现依赖前一小问答案的“小问单独裁切导出”；多技能综合题按整题处理并受到更严格的候选限制。

## 4. 核心业务规则

### 4.1 标签角色

每个有效评分小问最多具有：

- **一个主要诊断子技能：** `tag_type = 'sub_skill'`、`role = 'primary'`，参与子技能掌握率计算；
- **多个支持标签：** 可来自 `knowledge_point`、`method`、`model`、`ability`、`prerequisite` 和 `error_type`，仅用于分组、解释、筛选和候选生成，不重复计分。

主要子技能不能由运行时默认值静默补齐。没有已确认主要子技能的小问不得生成子技能掌握率。

### 4.2 分数归属

1. 每条学生评分小问记录按其实际 `score_awarded / full_score` 参与计算。
2. 同一条评分记录只向已确认的主要子技能贡献一次分子和分母。
3. 知识点掌握率按属于该知识点的唯一评分记录直接汇总，不能通过相加子技能统计反推，以避免一个知识点下多个子技能再次重复。
4. 全班统计汇总学生评分记录，继续以分值作为权重。
5. `deduction_count / item_count` 的界面名称统一为“失分题次 / 总题次”；扣分分值另行显示时使用 `full_score - score_awarded`。

### 4.3 候选与正式数据

- `suggested` 只表示系统候选，不参与细粒度图谱。
- `confirmed` 表示教师已确认，可参与图谱聚合。
- `rejected` 表示教师明确拒绝，重新生成时默认不自动恢复同一候选。
- `stale` 表示来源题、评分小问或题库标签已变化，必须重新确认。

AI 可以提出新的 `sub_skill` 文本，但确认前不得写入正式 `question_part_tags` 或父题汇总 `question_tags`。教师确认新词时，在同一事务中写入或复用精确相同的小问标签、刷新父题去重汇总，并将对应评分小问映射置为 `confirmed`。

### 4.4 难度精度与自动推荐上限

1. 题目与小问难度统一使用 `1.0—10.0` 的有限数值，并规范化为 `0.1` 步长；`7.1` 与 `7.9` 必须在模型、持久化、查询、排序和界面展示中保持可区分。
2. 输入为空、非数字、`NaN`、无穷大、超出范围或多于一位小数时，不能静默截断、四舍五入或夹紧到边界；应拒绝该次打标结果并提示重新生成或人工修改。
3. 多小问题的父题整体难度取所有已确认小问难度的最大值，界面标注为“整体难度（最高小问）”；父题难度不替代小问难度参与精确诊断。
4. 难度 `8.0—10.0` 的题在所有自动训练模式、阶段和掌握率档位中均先行排除，不能因标签匹配、候选不足或教师调整配比而重新进入自动候选池。
5. 难度未知或尚未通过校验的题也不进入自动训练。教师仍可在人工选题中主动选择难度 `8.0—10.0` 的题，但界面必须显示“超出针对训练范围”的明确提示。

### 4.5 训练推荐的精确目标

1. 训练目标从“宽泛知识点”改为“经教师确认的评分小问主要子技能”。同一知识点下不同小问的主要子技能必须分别建目标，不能合并成一个粗粒度目标后再随机选题。
2. 自动候选必须同时满足：同一 `knowledge_point`、同一已确认主要 `sub_skill`、难度落在当前阶段硬区间、难度低于 `8.0`、不是原题或近重复题、候选标签状态有效。
3. `method`、`model`、`ability`、`prerequisite` 和 `error_type` 只在通过硬门槛后参与排序与解释，不能替代主要子技能匹配。
4. 候选不足时显示真实缺口并引导补标、确认或人工选题，不静默退回仅匹配 `knowledge_point` 的旧逻辑。

## 5. 数据模型

### 5.1 新表：`question_parts`

该表保存题库题目的稳定小问结构和小问难度，为 AI 打标、父题汇总、阅卷小问映射和训练候选提供共同依据。

建议字段：

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `question_id` | 题库题目 ID |
| `part_ref` | 题内稳定小问标识，如 `(1)`、`(2)`；单问题使用固定值 `main` |
| `part_order` | 题内顺序 |
| `part_text` | 当前小问题干或目标摘要 |
| `difficulty_tenths` | `10—100` 的整数难度刻度；如 `71` 表示 `7.1`，避免浮点比较误差 |
| `source` | `ai_tagging`、`manual` 或 `migration` |
| `confidence` | AI 结果置信度；人工值可为空 |
| `model_name` | AI 打标模型；人工值可为空 |
| `created_at` / `updated_at` | 审计时间 |

约束：

1. `(question_id, part_ref)` 唯一，`(question_id, part_order)` 唯一。
2. AI/API 层难度必须是 `1.0—10.0` 内、`0.1` 步长的有限数值；写库前无损转换为 `difficulty_tenths`，应用层与数据库约束同时校验。
3. 小问重排不能无提示改变既有 `part_ref`；无法稳定匹配时将关联标记为待复核。

### 5.2 新表：`question_part_tags`

该表保存每个题库小问的独立标签。建议字段为 `question_part_id`、`tag_type`、`tag_value`、`role`、`status`、`source`、`confidence`、`model_name` 和审计时间；`status` 沿用 `suggested`、`confirmed`、`rejected`、`stale`。

约束：

1. `(question_part_id, tag_type, tag_value, role)` 唯一。
2. 每个小问最多一个 `role = 'primary' AND tag_type = 'sub_skill'` 的标签。
3. 父题 `question_tags` 不再接受一套与小问相互独立的 AI 输出；它是所有小问已确认标签按题内顺序去重后的兼容汇总视图或同步结果。
4. 父题汇总保留现有标签类型，完全相同的 `(tag_type, tag_value)` 只显示一次；来源小问数量可在界面下钻查看。

### 5.3 新表：`assessment_item_tag_mappings`

该表放在题库数据库，因为它同时依赖题库题目、题库标签和现有 `grading_question_links`。它表达“某场考试的某个评分小问选择了父题当前标签中的哪些语义，以及哪个子技能负责计分”。

建议字段：

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `grading_session_id` | 阅卷会话标识，沿用跨库应用层关联方式 |
| `source_item_ref` | 评分小问标识，如 `Q11(2)` |
| `parent_source_question_id` | 父级来源题标识，如 `Q11` |
| `bank_question_id` | 已确认关联的题库题目 ID |
| `bank_question_part_id` | 可为空的题库小问 ID；确认后用于训练目标和候选精确对齐 |
| `tag_type` | 标签类型 |
| `tag_value` | 精确标签值 |
| `role` | `primary` 或 `supporting` |
| `status` | `suggested`、`confirmed`、`rejected` 或 `stale` |
| `confidence` | 候选生成置信度；人工确认后仅作审计依据 |
| `source` | `ai_candidate`、`manual` 或 `migration` |
| `evidence_json` | 生成依据摘要，如评分目标、步骤和候选说明，不保存学生敏感作答 |
| `model_name` | 生成候选时使用的模型名称；人工创建可为空 |
| `reviewed_at` | 最近确认或拒绝时间 |
| `created_at` / `updated_at` | 审计时间 |

约束：

1. `(grading_session_id, source_item_ref, tag_type, tag_value, role)` 唯一。
2. 同一 `(grading_session_id, source_item_ref)` 最多存在一条 `status = 'confirmed' AND role = 'primary'` 的映射，通过部分唯一索引或事务校验保证。
3. `role = 'primary'` 时 `tag_type` 必须为 `sub_skill`。
4. `bank_question_id` 必须引用存在且未删除的题库题目。
5. 存在 `bank_question_part_id` 时，该小问必须属于同一 `bank_question_id`。
6. 映射确认时，`tag_type/tag_value` 必须对应同一题库小问的当前正式标签；历史父题标签候选需先确认到具体小问。新词先写入小问正式标签并刷新父题汇总，再确认映射。

### 5.4 不直接引用 `question_tags.id`

现有题库编辑可能删除并重建标签行。映射优先使用 `(bank_question_part_id, tag_type, tag_value)`，历史兼容期使用 `(bank_question_id, tag_type, tag_value)` 精确校验，避免因标签行 ID 重建导致无意义失效。标签值变化后，映射通过一致性检查转为 `stale`，不自动跟随改名。

### 5.5 迁移与回退

1. 新表为空时，现有知识点图谱行为保持可用。
2. 数据库迁移新增小问表、映射表、索引和必要校验，不改写现有评分；现有父题标签与整数难度保留，在完成小问候选确认前作为兼容数据读取。
3. 回退版本忽略新表即可继续使用原图谱；删除新表不是应用回退的必要条件。
4. 发布前备份题库数据库，并对迁移做空库、现存库和重复执行验证。

## 6. 候选生成与教师确认

### 6.1 输入

候选服务按已确认来源题关联读取：

- 评分小问 `source_item_ref`、分值、`core_goal`、`required_elements` 和步骤；
- 父题题干与答案；
- 父题当前 `knowledge_point`、`sub_skill`、`method`、`model`、`ability`、`prerequisite` 和 `error_type`；
- 同一大题的其他小问，帮助避免把全部标签分配给每个小问。

不发送学生作答、姓名、学号或原卷图片。

### 6.2 生成策略

1. 复用题库当前打标模型配置、限流器、重试上限和请求计数。
2. 每道父题作为一个候选生成单元，模型一次返回其全部小问映射，避免小问之间互不知情。
3. 输出必须包含每个小问恰好一个主要子技能候选或显式 `unresolved`，以及可选支持标签。
4. 支持标签必须从当前父题正式标签中选择。
5. 主要子技能优先复用父题已有 `sub_skill`；确实缺失时可以提出一个简短新词，并标记 `is_new = true`。
6. 模型不能直接写数据库；服务先校验题号完整性、标签类型、长度、重复项和新词数量，再保存为 `suggested`。
7. 批量失败不扩散成无限逐题请求；达到上限后保留已成功候选，并将失败小问标为待人工处理。

### 6.3 确认界面

确认页按父题分组，每个小问显示：

- 小问号、分值、评分目标和关键步骤；
- 建议主要子技能、是否为新词、置信度和简短依据；
- 方法、模型、能力、前置知识等支持标签；
- 接受、修改、拒绝操作。

教师可以从父题已有子技能中改选，也可以编辑一个新子技能。单个小问确认后立即保存；整题“全部接受”只对结构完整、无 `unresolved` 且没有重复主要技能警告的候选开放。

### 6.4 历史数据

现有考试在图谱页显示“小问标签待确认”入口。点击后执行与新试卷相同的候选生成流程。候选未确认前：

- 继续显示现有知识点级汇总；
- 小问节点可按评分目标展示实际得分率，但标记“未精确归因”；
- 不生成子技能掌握率；
- 不把候选写入训练推荐或其他业务流程。

## 7. AI 小问级打标与父题汇总

### 7.1 输入与输出结构

1. 服务端先从题目结构中生成稳定 `part_ref` 列表，再连同各小问题干、答案和题目上下文发送给模型；模型不能自行新增、删除、合并或重排小问。
2. 单问题也必须按一个 `part_ref = 'main'` 的小问输出，避免维护两套数据结构。
3. 模型对每个小问分别返回：`part_ref`、一位小数 `difficulty`、`knowledge_point`、一个主要 `sub_skill`、其他 `sub_skill`、`method`、`ability`、`model`、`error_type`、`prerequisite`、教材/教学/学段元数据、理由和置信度。
4. 输出结构对难度使用数值类型，范围 `1.0—10.0`、步长 `0.1`；解析后不能再经过整数归一化函数。
5. 顶层不要求模型再次生成父题标签或父题难度，避免同一语义存在两个互相冲突的来源。
6. 提示词明确要求根据每个小问的步骤数量、抽象程度和综合程度分别估计难度，并以 `7.1`、`7.9` 这类示例强调不能只输出整数档位。

### 7.2 严格校验与保存

服务端在写库前校验：

- 输入中的每个 `part_ref` 恰好出现一次，未知、缺失或重复小问均拒绝整题结果；
- 难度是有限数值、在范围内且最多一位小数，不接受字符串截断或整数化；
- 每小问最多一个主要子技能，标签类型、长度、数量和重复项符合现有题库约束；
- AI 输出只保存到对应小问，父题标签与难度由服务端派生。

整题校验通过后，在同一题库事务中替换该题未人工锁定的 `suggested` 小问 AI 标签。教师确认后才刷新父题正式汇总并允许进入自动训练候选池。人工修改、确认或拒绝的小问不被批量重打标静默覆盖；部分失败不留下父题与小问不一致的半成品。

### 7.3 父题派生规则

1. 父题标签为所有小问正式标签的去重并集，按“小问顺序 → 标签类型固定顺序 → 小问内顺序”稳定输出。
2. 完全相同的 `(tag_type, tag_value)` 只保留一次；同名但不同 `tag_type` 的标签不擅自合并。
3. 父题难度取所有有效小问难度的最大值；任一小问难度缺失时，父题显示“难度待完善”，不以其他小问平均值掩盖缺失。
4. 题库前端默认显示父题去重并集，并标明“来自 N 个小问”；展开后逐小问显示独立标签和难度。
5. 现有仅有父题标签的历史题先保留原显示并标记“未拆分到小问”，经 AI 生成候选、教师确认后再切换为派生汇总。

## 8. 投影与聚合

### 8.1 小问标签投影

扩展现有标签投影服务，使每个评分小问返回：

- 父题当前正式标签；
- 已确认主要子技能；
- 已确认支持标签；
- 映射状态和缺失原因；
- 粗粒度/细粒度标记。

处理顺序：

```text
评分小问
  → 已确认来源题关联
  → 父题当前正式标签
  → 当前小问已确认映射
  → 一致性校验
  → 细粒度证据或显式粗粒度降级
```

若来源题未关联、题库题缺失或没有 `knowledge_point`，沿用现有图谱缺失原因。若仅缺少小问映射，知识点图谱仍覆盖该小问，但细粒度完整度不计入覆盖。

### 8.2 两套完整度

页面分别显示：

- **知识点覆盖：** 已关联且具有 `knowledge_point` 的评分小问数 / 总评分小问数；
- **小问精细度：** 已确认主要子技能的评分小问数 / 知识点已覆盖小问数。

两者不能合并为一个数字，以免“有知识点”被误解为“已完成精确归因”。

### 8.3 聚合结果

诊断服务输出三层统计：

1. `knowledge_points`：按唯一评分记录聚合；
2. `primary_sub_skills`：仅按已确认主要子技能聚合；
3. `assessment_items`：按 `session_id + source_item_ref` 聚合全班或保留单生记录。

支持标签作为各层上下文，不参与分子分母。所有层级保留证据数量、考试数量、失分题次、扣分分值和来源小问引用。

## 9. 训练推荐

### 9.1 诊断目标与候选资格

训练目标按已确认的 `assessment_item_tag_mappings` 定位到具体题库小问和主要子技能。未确认、已失效或只有父题粗标签的目标不自动生成针对训练，只显示“待完成小问标签确认”。

候选进入排序前必须通过以下硬过滤：

1. 与目标具有完全相同的 `knowledge_point` 和主要 `sub_skill`；
2. 候选小问标签已确认、难度有效且 `< 8.0`；
3. 难度处于当前掌握率与训练阶段的硬区间；
4. 不是来源原题、已明确排除题或现有近重复规则命中的题；
5. 单技能题可进入基础或直接训练；多小问题仅当全部小问主要子技能一致时视为单技能题，否则只能进入迁移训练，并要求所有小问难度均 `< 8.0`。

任何硬条件失败后都不得通过“高标签重合分”重新进入候选池。系统不在生成计划时在线调用 AI 或用模糊语义猜测补位。

### 9.2 自适应难度与配比

以目标主要子技能的按分值掌握率选择默认区间和配比：

| 掌握率 | 基础巩固 | 直接训练 | 迁移训练 | 默认配比 |
|---|---|---|---|---|
| `< 40%` | `1.0—2.9` | `2.0—3.9` | 关闭 | `50% / 50% / 0%` |
| `40%—70%` | `2.0—3.9` | `3.0—5.9` | `5.0—6.9` | `30% / 60% / 10%` |
| `> 70%` | `3.0—4.9` | `4.0—6.9` | `6.0—7.9` | `20% / 60% / 20%` |

边界规则固定为：`40.0%` 进入中档，`70.0%` 仍在中档，超过 `70.0%` 才进入高档。即使教师修改阶段配比或扩大某个区间，系统最终仍应用 `< 8.0` 的全局上限。

通过硬过滤后，候选依次按“与目标难度中心的距离、支持标签重合、错因针对性、使用频率与题型多样性”排序。`knowledge_point` 不再作为排序加分，因为它已经是资格条件。

### 9.3 多目标分配与候选不足

1. 默认选择最多三个最薄弱的已确认主要子技能，按掌握率升序、扣分分值降序、证据量降序确定优先级。
2. 题量在各目标间轮转分配，防止一个候选丰富的子技能挤占整个计划；同一道题只能占用一个计划名额。
3. 候选不足时保留实际数量并显示缺口，不用较粗知识点或区间外题目凑满。
4. 教师可选择“补充/确认候选标签”“人工选题”或显式扩大某阶段区间；扩大后仍不能自动纳入 `8.0—10.0`。

### 9.4 推荐解释与分组

推荐页按“主要子技能 + 当前掌握率档位”分组，不再只显示宽泛 `knowledge_point` 标签页。每道题展示命中的主要子技能、题内对应小问、难度、训练阶段和入选原因；候选统计分别显示“标签未确认、难度不匹配、难度 8.0 以上、重复题”等排除数量，便于教师判断是缺题还是缺标签。

## 10. 分层界面

### 10.1 总览结构

默认展示：

```text
教材章节
└─ 知识点
   └─ 主要子技能
      └─ 评分小问
```

章节来自父题当前 `exam_scope`，只用于分组。一个知识点在多个章节出现时按当前筛选考试的真实证据分别展示，不创建新的全局章节身份。

默认展开风险最高的三个知识点，其余折叠。每层展示：

- 名称；
- 按分值加权得分率；
- 失分题次 / 总题次；
- 证据小问数；
- 精细度状态。

不再静默截断为固定 14 个节点。节点较多时使用“显示更多”和分页/虚拟化，不以隐藏数据换取布局整齐。

### 10.2 支持标签

支持标签分组显示为：

- 方法；
- 数学模型；
- 能力；
- 前置知识；
- 常见错因候选。

每组默认显示前三项和总数，展开后查看全部。`canonical_knowledge_id`、兼容技能名和内部字段不在普通教师界面直接混排。

### 10.3 全班详情

点击全班节点后，详情页先显示：

1. 知识点/子技能总体指标；
2. 各评分小问的得分率、失分人数、失分题次和扣分分值；
3. 前五项规范化错因及占比；
4. 分数区间或掌握风险分布；
5. 标签确认状态和候选处理入口。

详情页不得使用任意第一条学生记录作为全班标题，也不得初始渲染所有学生原卷记录。

### 10.4 学生证据下钻

选择一个评分小问后，分页显示学生记录。默认优先显示失分记录；支持按学生、得分状态和错因筛选。每条记录继续复用现有原卷高亮能力。单生模式保留当前展开式证据体验，但支持标签按类型分组，不再拼接成超长文本。

### 10.5 文案与可访问性

- “扣分 174/312”改为“失分题次 174/312”。
- 全班与单生标题明确区分。
- 粗粒度、待确认、已确认和已失效使用文字与图标双重表达，不能只靠颜色。
- 展开/折叠控件可键盘操作，具有明确可访问名称。
- 长标签换行或省略后可展开查看，不使用包含数百条原因的 `title` 属性。

## 11. 错因展示

1. 图谱统计优先按受控的 `error_category` 或题库 `error_type` 候选聚合。
2. `error_summary` 和 `deduction_reason` 作为证据文本，不直接充当全班分布的唯一分组键。
3. `manual_review_confirmed`、空值和纯系统标记不得显示为教学错因。
4. 全班默认只展示前五项错因；其余归入“其他”，但详情可查看完整证据。
5. 本设计不回写或自动提升学生错因为题库标签。

## 12. 一致性与失效处理

以下任一变化使相关已确认映射转为 `stale`：

- 来源题关联更换题库题目；
- 评分标准删除或重命名评分小问；
- 已确认主要子技能在父题正式标签中被删除或改名；
- 题库小问被删除、重命名或调整到无法保持原 `part_ref`；
- 题库小问的主要子技能被删除、改名或改为未确认状态；
- 父题被删除。

检查发生在候选页打开、图谱查询和题库标签保存之后。`stale` 映射不参与子技能统计，但保留审计记录和原确认信息。系统显示原因并提供重新生成/人工修复入口，不静默回退为另一个标签。

## 13. 模块边界

建议新增或扩展以下职责，不把全部逻辑继续堆入 `web_app.py`：

| 模块 | 职责 |
|---|---|
| 题库小问仓储 | 保存稳定小问、精确难度、小问标签状态与父题去重汇总 |
| 小问级 AI 打标服务 | 构造逐小问请求、严格校验完整性和一位小数难度、保存候选 |
| 小问标签映射仓储 | 映射增删改查、状态转换、唯一性和事务校验 |
| 小问标签候选服务 | 构造受限请求、校验模型输出、保存候选和请求统计 |
| 标签投影服务 | 将评分小问、来源题、父题当前标签和已确认映射组合成只读投影 |
| 细粒度诊断聚合器 | 按知识点、主要子技能和评分小问计算唯一证据统计 |
| 训练目标构建器 | 从已确认映射生成主要子技能目标和掌握率档位 |
| 训练候选选择器 | 执行标签、难度、重复题和状态硬过滤，再完成排序与轮转分配 |
| 图谱视图模型构建器 | 将诊断结果转换为页面需要的分层结构和分页摘要 |
| Streamlit 页面组件 | 渲染确认工作台、题库小问标签、分层总览、训练解释和详情筛选，不承担业务聚合 |

依赖方向保持“页面 → 应用服务 → 仓储/数据库”。候选服务不读取学生作答；诊断服务不调用 AI。

## 14. 错误处理与幂等性

1. 候选请求失败：保留已成功候选，失败小问可重试，不影响批改或知识点图谱。
2. 输出缺少小问、包含未知题号或多个主要子技能：拒绝该父题候选并显示可诊断错误。
3. 重复生成：未人工修改的 `suggested` 可替换；`confirmed` 和 `rejected` 不被自动覆盖。
4. 确认新子技能：正式题库标签写入与映射确认在同一题库事务中完成。
5. 跨库读取：继续承认阅卷库与题库库没有统一事务；投影发现不一致时降级并报告，不伪造完整状态。
6. 页面数据量大：全班证据使用服务端分页/分组，不一次构造全部展开组件。
7. 训练候选不足：返回实际题数、各类排除数量和可处理入口，不抛出空白页，也不回退到粗标签或难度上限外题目。

## 15. 测试与验证

### 15.1 数据与服务测试

- 新表迁移可重复执行，现存数据库数据不变，回退版本可忽略新表；
- 同一小问不能确认两个主要子技能；
- 候选不会直接进入正式统计；
- 确认新子技能时标签与映射原子保存；
- 标签删除、改名、题目关联变化和小问变化会使映射失效；
- 无映射时继续生成知识点级图谱，并准确报告精细度；
- 同一评分记录不会因多个知识点或支持标签重复计分；
- 全班、单生、总览和详情使用相同按分值加权口径；
- 候选重试不会覆盖教师确认或拒绝结果；
- `7.1` 与 `7.9` 从模型解析、保存、读取到排序始终保持不同值；
- 非法难度、未知小问、缺失小问和重复 `part_ref` 会拒绝整题写入；
- 父题标签严格等于已确认小问标签的稳定去重并集；所有小问难度完整时父题难度等于最大值，否则显示待完善；
- 历史父题粗标签在小问确认前不会伪装成已拆分标签。

### 15.2 候选生成测试

- 模型输出只能引用输入父题和评分小问；
- 支持标签必须来自父题当前正式标签；
- 新子技能长度、空值、重复和数量限制有效；
- 一道多小问题能返回互相区分的主要子技能；
- 请求数、限流、失败数和重试次数与实际调用一致；
- 未配置模型时提供明确人工处理路径；
- AI 逐小问输出不会经过整数难度归一化；
- 小问 AI 候选未经确认不会进入父题正式汇总或自动训练。

### 15.3 训练推荐测试

- 同一知识点但主要子技能不同的题不会互相推荐，且候选不足时不回退到粗知识点；
- 难度 `7.9` 可进入符合条件的迁移区间，`8.0`、`8.1` 和 `10.0` 在所有模式、阶段、掌握率与配比设置下均被排除；
- 难度为空、非法或超出当前阶段硬区间的题不会参与排序；
- `40.0%`、`70.0%` 等边界选择正确档位，各档默认配比正确；
- 单技能题与多技能综合题按规定进入对应训练阶段；
- 多目标按薄弱程度轮转分配，同一道题不重复占位；
- 原题、近重复题、未确认标签和失效标签被排除，并返回准确的排除原因计数。

### 15.4 页面与浏览器验证

- 历史粗粒度、候选待确认、部分确认、全部确认和已失效状态；
- 全班与单生标题、统计口径和详情路径正确；
- 支持标签按类型折叠，长文本不形成巨型提示；
- 题库父题显示小问标签去重并集，可展开核对每个小问的标签与一位小数难度；
- 训练页按主要子技能与掌握率档位分组，显示难度和入选/排除依据；
- 自动推荐结果中不存在难度 `8.0—10.0` 的题；
- 全班详情初始不渲染数百条学生记录，分页和筛选有效；
- 1366×768、1440×900、1920×1080 下无横向溢出、弹窗越界或不可读节点；
- 键盘焦点、展开按钮可访问名称、颜色对比度和文字状态提示可用；
- 浏览器控制台无相关错误或警告。

### 15.5 回归测试

- 批改、人工复核、题库标签编辑和报告导出保持可用；知识图谱与训练推荐按本规格升级；
- 未启用小问级映射的历史考试与旧版本表现兼容；
- 题库标签修改仍能在下一次图谱查询中反映，并对失效映射给出明确提示。

## 16. 发布与回退

建议按以下顺序发布：

1. 题库小问、标签映射新表、仓储、难度精度迁移与一致性校验；
2. AI 逐小问打标、父题去重汇总和题库小问确认界面；
3. 训练候选题的小问标签历史回填与教师确认；
4. 阅卷评分小问候选生成与教师确认页；
5. 小问标签投影和细粒度聚合；
6. 分层总览和新的全班详情；
7. 精确子技能训练目标、难度硬过滤和推荐解释；
8. 当前考试候选生成与人工确认；
9. 浏览器验收后默认启用分层界面和新版训练推荐。

发布前备份题库数据库。图谱与训练推荐分别使用独立功能开关：图谱可回退到现有知识点总览；新版训练推荐出现问题时应暂停自动生成并保留人工选题，不重新启用会推荐难度 `8.0—10.0` 的旧自动路径。新表和已确认映射保留，回退不得删除教师已经确认的数据。

## 17. 验收标准

以当前 Q11 为代表样例，验收时应满足：

1. Q11(1)、Q11(2)、Q11(3) 可以拥有互相独立、经教师确认的主要子技能；
2. 三个小问分别显示各自实际得分率，不再把全部小问同时复制到“一次函数、函数图像、一元一次方程”的多个细粒度节点；
3. 每条学生小问成绩在子技能层只计算一次；
4. 全班点击“一次函数”后先看到小问汇总，而不是数百条学生记录和超长错因段落；
5. 未确认候选不会产生正式子技能掌握率，并有清晰的待处理提示；
6. 题库中 Q11 父题显示三道小问正式标签的去重并集，展开后能看到每个小问各自标签和一位小数难度；
7. 难度 `7.1` 与 `7.9` 保存、读取和展示后仍可区分，不再被整数归一化；
8. 针对训练按已确认主要子技能精确匹配，同一知识点但子技能不同的题不会混入；
9. 所有自动训练结果均不包含难度 `8.0—10.0` 的题，候选不足时显示缺口而不是用高难题或粗知识点题目凑数；
10. 现有批改分数、人工复核结果和报告导出不因本功能发生变化。
