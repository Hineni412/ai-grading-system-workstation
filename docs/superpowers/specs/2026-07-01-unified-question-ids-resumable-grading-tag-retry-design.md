# 统一题号、可暂停批改与打标签缺失重试设计

## 目标

本次改动解决四个相互关联的问题：

1. 打标签、作答区域绑定、整卷批改、混合批改和完整性审计使用同一套题号契约，页面读取配置时不再静默改写 JSON。
2. 批改支持安全暂停和恢复；恢复或重复启动时，跳过已经由同一份试卷和同一套批改配置产生的有效成绩。
3. 参考答案图片在发送前缩小并复用，同时为整卷大图请求设置独立的低并发上限，降低视觉输入成本和限流概率。
4. 题库打标签流程保留批次级错误记录，并且“继续处理缺失项”只重试尚未成功的题目。

## 已确认的现状与依据

- 当前配置可能在多个大题中重复使用局部 `P1`、`P2`、`P3`。作答区域页面对候选题号去重后只剩少数选项，批改完整性审计又把这些局部编号当作全局编号，最终出现大量重复缺题和非预期题号。
- 当前临时兼容逻辑会在加载页面或开始批改时改写 rubric、answer key 文件。这使“读取”产生持久化副作用，且无法覆盖 `Q13(1)`、`Q13(P1)`、裸 `P1` 等所有组合。
- 整卷批改当前一次性把所有学生提交到线程池，运行中只有“强制重置”，没有可恢复的暂停检查点。正常重新开始还会先清除本场结果，因此无法可靠跳过已有成绩。
- 本次试卷包含 15 张参考答案图，总像素约 1777 万；旧批次约为 12 张、599 万像素。参考图会随每名学生的请求重复发送，单次输入 Token 也从约 1.24 万增长到约 3.54 万。文本 JSON 的增长很小，成本差异主要来自视觉输入。并发不会增加单次请求 Token，但会让大量大请求同时在途，从而加重限流。
- 题库流程当前能记录请求数和失败题数，但没有保留每个批次的题号、失败阶段和原因。当前 15 题被分成 7 个批次，成功和失败呈整批分布，说明需要批次级诊断和只重试缺失题，而不是重新处理全部题目。

## 范围边界

本次会修改题号解析边界、批改运行控制、批改结果判重、参考图预处理、整卷并发配置、题库同步状态和对应页面展示。

本次不改变评分标准、分值、学生匹配业务规则、知识点口径、模型供应商或既有成绩导出格式；不自动覆盖用户原始图片；不把同一学生的不同试卷静默视为同一份答卷。

## 一、统一题号契约

### 1.1 规范格式

- 大题号：`Q<正整数>`，例如 `Q12`。
- 小问号：`Q<正整数>(P<正整数>)`，例如 `Q12(P1)`。
- 单小问大题对外仍使用大题号，例如 `Q1`，不生成没有业务意义的 `Q1(P1)`。
- 裸 `P1` 只允许作为旧配置的输入形式，必须结合所在父题才能解析；脱离父题的裸 `P1` 属于歧义输入，不得在全局集合中使用。
- `Q12(1)`、`Q12-1`、`Q12_1` 作为兼容别名接受，但进入业务层后统一表示为 `Q12(P1)`。

### 1.2 中央契约模块

新增一个不依赖页面、数据库或模型的题号模块，负责：

- 解析规范题号和兼容别名；
- 在已知父题时把裸 `P1` 转为全局小问号；
- 构建 rubric 的父题、小问题号索引；
- 根据父题展开全部小问；
- 按自然顺序排序；
- 对模型返回、区域绑定值和题库投影值进行边界归一化；
- 检测重复、歧义和无法解析的编号。

打标签投影、作答区域目录、整卷目标题号、混合批改、完整性审计、答案查找、报告聚合共同复用该模块，不再分别维护正则表达式和字符串拼接规则。

### 1.3 只读加载与显式持久化

rubric 和 answer key 的加载函数读取原始 JSON 后，返回规范化的内存副本；加载过程中不调用 `write_text`，也不改变文件时间和内容摘要。

新生成的配置和用户主动保存的配置直接写规范题号。旧文件如需持久化迁移，必须通过显式迁移入口执行：迁移前生成备份，先校验 rubric 与 answer key 的父子题集合一致，再原子替换。普通页面打开和开始批改不会触发迁移。

### 1.4 不完整或冲突数据

- 同一父题出现两个会归一化到同一规范号的小问时，阻止开始批改并列出冲突。
- 裸小问无法确定父题时保留错误位置，不猜测所属大题。
- 区域绑定到父题时，批改目标明确展开为该父题全部小问；绑定到具体小问时只选择该小问。
- 模型返回兼容别名时先转成 rubric 中的规范号，再执行重复、缺失和分数范围审计。

## 二、安全暂停、恢复与判重

### 2.1 运行状态

批改场次状态扩展为：`running`、`pause_requested`、`paused`、`completed` 和 `failed`。页面点击“安全暂停”只写入 `pause_requested`，不取消已经发出的模型请求。

整卷调度器改为有界、增量派发：在途数量不超过有效并发值，每次准备派发下一份试卷前读取暂停状态。发现暂停请求后停止派发，等待已经在途的请求完成并保存，然后把场次标为 `paused`。因此暂停后可能仍会多完成最多“当前在途数”份试卷，但不会丢弃已付费响应。

恢复时复用原有 `pending`、`failed` 和已完成记录，不重新清空本场成绩。异常退出后遗留的 `grading` 项会按现有恢复策略转为可重试状态。

### 2.2 判重身份

每份候选答卷计算三个稳定值：

- `student_id`：名单中的学生主键；
- `paper_fingerprint`：按正反面增强前的原始图片内容及固定顺序计算 SHA-256；
- `grading_config_fingerprint`：对规范化后的 rubric、answer key、作答区域、批改模式和影响模型输出的关键配置计算稳定 JSON SHA-256。

只有三者均与已有完整有效结果一致时才自动跳过。跳过不会创建新的模型请求，并记录为 `skipped_existing`。

同一学生、同一批改配置但试卷指纹不同，标记为 `conflict` 并显示两份来源，不覆盖旧成绩，也不自动批改。批改配置指纹不同则视为明确重批，允许产生新结果并按现有事务保存逻辑替换该学生本场旧结果。

### 2.3 数据兼容

为现有答卷和结果记录补充可空的试卷指纹、配置指纹与跳过/冲突原因。历史记录没有指纹时不能仅凭姓名或学号自动判定为重复；系统可在原图仍存在时补算试卷指纹，但配置指纹缺失时仍按“未确认旧结果”处理，避免误跳过。

正常启动不再调用清空本场成绩的逻辑。现有显式清理能力保留给用户主动重置，且继续先备份数据库。

### 2.4 页面行为

- 运行中显示“安全暂停”，并显示已完成、在途、待处理、已跳过、失败和冲突数量。
- 请求暂停后显示“正在安全暂停”，按钮不可重复点击。
- 暂停完成后显示“继续批改”；恢复不会重新发送已确认完成的相同答卷。
- 冲突项单独列出学生、两份试卷来源和原因，不把冲突计入失败重试。

## 三、参考图预处理、成本记录和并发

### 3.1 图片预处理

参考答案图片在创建 `AIGrader` 时处理一次并缓存为内存字节，所有学生请求复用同一份结果：

- 不放大原图；
- 默认最大宽度 960 像素、最大高度 2048 像素，等比例缩放；
- 有透明通道时铺白底；
- 使用 JPEG 质量 82 和优化编码；
- 原始文件和原始 JSON 中的 base64 内容保持不变。

当前 15 张参考图按该尺寸规则估算会从约 1777 万像素降至约 1139 万像素。实际 Token 降幅仍由模型供应商的视觉计费规则决定，因此页面和用量记录展示实际 Token，而不把像素降幅直接宣传为费用降幅。

### 3.2 请求结构与用量记录

参考图继续作为稳定前缀、学生正反面作为动态图片发送。每次模型尝试记录：参考图数量、参考图总像素、学生图数量、是否重试、实际输入/输出 Token 和模型名；不记录图片内容、API Key 或其他敏感数据。

只降低 JPEG 文件大小通常不能显著降低视觉 Token，因此本次必须包含尺寸缩放。若样例验证发现 960 像素不足以辨认数学小字，优先调高单个清晰度参数，而不是关闭整套预处理。

### 3.3 大请求并发

新增独立的“整卷大图请求并发”配置，默认值为 6。整卷实际并发取“现有整卷并发配置”和该值的较小者；RPM 节拍继续作为第二层限制。混合批改、预检和题库打标签保留各自并发配置，不被该安全上限误伤。

页面显示配置并发和实际整卷大图并发，避免用户看到旧值 200 却误以为系统仍会同时发送 200 个大请求。

## 四、打标签批次错误记录与缺失重试

### 4.1 持久化位置和结构

复用当前场次的 `question_bank_sync_details_json` 保存当前原始试卷对应的打标签运行记录，避免新增与现有题库同步状态重复的事实来源。更换原始试卷 SHA-256 时，现有绑定逻辑同时清空这些记录。

每次批次尝试记录：确定性的批次键、批次序号、题库题目 ID 列表、请求类型、尝试次数、状态、失败阶段、错误类别、经过截断和脱敏的错误信息、模型名和时间。运行记录同时保存本轮目标题、成功题、缺失题和请求数。仅保留当前原始试卷最近 100 条尝试记录，防止状态 JSON 无限增长。

错误类别至少区分：网络/超时、限流、模型返回解析失败、结构校验失败、质量不足和数据库保存失败。错误信息不得包含密钥或完整模型原始响应。

### 4.2 事件边界

`AITaggingService` 增加批次尝试事件，但不直接访问数据库。题库入库服务把批次事件和单题保存结果汇总后返回；场次工作流服务负责把结构化记录合并进现有同步状态。这样 AI 调用、题目保存和场次持久化仍保持单向依赖。

### 4.3 缺失项重试

“继续处理缺失项”开始前，以当前题库实际标签完整度重新计算缺失题集合，不直接相信上次失败列表。只为这些题重新构建自适应批次：

- 已有完整标签的题不进入请求，也不被覆盖；
- 批次请求整体失败时，批次内每题都保留同一个批次错误；
- 模型返回成功但质量不足时记录质量原因，并按现有质量重试上限处理；
- 模型结果合格但保存失败时只重试保存失败题；
- 全部缺失题补齐后重新计算题库关联和知识点投影，状态才变为 `ready`。

页面展示最近失败批次的题号、阶段和简化原因，并把按钮文案明确为“重试缺失题”，同时显示预计会发送的题目数。

## 五、错误处理与一致性

- 暂停请求采用数据库状态而非仅存在页面会话中的布尔值，页面刷新或新窗口仍能看到真实状态。
- 已发送请求无法从供应商侧可靠撤销；安全暂停只承诺停止新派发并保存已返回结果。
- 模型超时后的自动重试仍可能产生供应商侧重复计算，所有重试必须经过同一大请求并发和 RPM 限制，并在用量记录中标出尝试次数。
- 成绩去重检查和保存放在同一数据库事务边界内，防止两个并发任务同时为同一幂等键写入有效结果。
- 题号冲突、答卷冲突和标签失败均保留可理解的用户提示及可诊断记录，不静默猜测或覆盖。

## 六、测试与验收

### 6.1 自动化测试

- 题号契约：覆盖 `Q12`、`Q12(P1)`、`Q12(1)`、`Q12-1`、父题内裸 `P1`、跨父题重复裸 `P1`、单小问和歧义输入。
- 跨流程一致性：同一 rubric 在作答区域目录、批改目标、混合批改、完整性审计和题库投影中得到同一规范题号集合。
- 只读加载：读取前后文件内容、修改时间和 SHA-256 不变。
- 安全暂停：暂停后不再新增派发，已在途任务完成并保存，最终状态为 `paused`；恢复只处理剩余项。
- 判重：三元幂等键一致时跳过；同一学生不同试卷产生冲突；配置指纹变化时允许重批；历史无指纹结果不误跳过。
- 图片：验证尺寸上限、等比例、透明底处理、不放大、缓存复用和原图不变。
- 并发：无论旧整卷并发配置多大，大图在途数不超过 6；RPM 限制仍覆盖首次调用和重试。
- 标签记录：批次失败原因被持久化，错误信息脱敏且长度受限；重试只发送当前缺失题，成功题不覆盖；保存失败可以单独重试。

所有生产行为修改遵循测试先行：先运行新增测试确认其因缺少目标行为而失败，再写最小实现使其通过，随后运行相关回归测试。

### 6.2 真实页面验收

在测试数据库和模拟模型响应下验证：

- 作答区域下拉列表能显示全部父题和规范小问，绑定后批改目标一致；
- 打开相关页面不会改变 rubric 或 answer key；
- 运行中点击安全暂停，页面依次显示“正在安全暂停”和“已暂停”，恢复后跳过已有结果；
- 重复答卷和同学生不同试卷分别显示“已跳过”和“冲突”；
- 题库工作流显示批次错误并且重试请求数与缺失题批次数一致；
- 在 1366×768、1440×900、1920×1080 下检查状态面板、长错误文本和按钮无溢出。

最后用少量真实样例比较压缩前后参考答案小字可读性、完整性审计结果和实际输入 Token。未经用户确认，不使用整班真实批改作为测试，以免产生额外费用。

## 七、文档与兼容性

本次会形成新的共享题号边界、持久化运行状态和同步错误结构，属于实质性架构变化。实现完成后更新 `ARCHITECTURE.md`，只描述已经落地并验证的结构。现有未规范配置通过只读兼容层继续可用；显式迁移、数据库新增列和新配置字段均保持向后兼容并提供默认值。
