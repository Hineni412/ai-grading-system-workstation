# 三包里程碑与分层测试门槛设计

## 决定

从 2026-07-16 起，普通开发以 3 个相关执行包为一个里程碑。每包仍保留测试优先开发、包内聚焦测试、受影响回归、快速冒烟和独立复审；前序包逐包验证后进入里程碑 integration，后续包可以从 Index 记录的精确 SHA 开始。3 包结束后只做一次完整门槛，再通过一个 PR 进入 `main`。

数据库迁移、核心状态机、生产切换、正式用户验收、删除等高风险包可以单独成批。第 3 包确实受阻时，允许前 2 包形成明确记录的部分里程碑；失败包必须退回自己的功能分支，不进入 PR。

## 门槛

1. Index 在第 1 包领取前固定里程碑编号、包顺序、起始主线 SHA、integration 分支和当前已验证 SHA。
2. 第 2、3 包即时计划写入不可变的 `交接基线`；调度方把从 integration 的 Index 独立读取的当前已验证 SHA 作为可信参数传给验证器，验证器检查精确匹配、祖先关系、领取提交位置和领取后不可更改。
3. integration 每合入一个包只跑该包和受影响范围；里程碑末运行一次完整 `tools/smoke_check.py`。
4. 前端完整质量入口为 `npm run verify`，类型检查只随 build 执行一次；浏览器测试使用 `*:prepared` 复用同一 SHA 的已构建产物。
5. 测试失败退回原功能分支。Critical/Important 问题统一修复并只复测影响面；第二轮仍有重要问题时停止并汇报。

## Python 并行试点

pytest-xdist 与 execnet 只属于测试依赖并固定版本。第一个里程碑在同一 SHA 上各运行一次串行完整门槛和 2 进程完整门槛，比较收集数量、通过结果、耗时、慢测试和不稳定情况。第二个里程碑先运行 2 进程；连续两个里程碑稳定后，才可另行把 2 进程设为默认。数据库、端口、进程和其他共享资源测试始终留在串行车道。

## 暂缓事项

当前不因测试数量直接合并或删除测试。P3-01 建立覆盖率、重复覆盖和耗时基线后，再按业务能力保护范围评估测试合并或删除。
