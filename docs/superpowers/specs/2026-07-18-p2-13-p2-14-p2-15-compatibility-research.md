# P2-13 × P2-14 × P2-15 组合兼容性研究

**日期：** 2026-07-18
**调查基线：** M2-02 integration `814da298d31d3e64a905afe298b8abca8914dfb1`
**性质：** 只读调查；未修改功能代码、任务状态或真实业务数据

## 1. 冻结边界

- **目标：** 核对 P2-13 学生名单新增、编辑和永久删除与已完成的 P2-14 工作台/分析、P2-15 知识图谱组合后是否存在需要在 P2-16 前处理的问题。
- **包含：** 学生身份连接、班级/学号变更、成绩与证据传播、答卷解绑、进度与异常计数、旧 `/api/students` 契约、页面重新进入和失效范围恢复。
- **不包含：** P2-16/P2-17 实施、统计口径扩展、数据库迁移、生产 UI 切换、真实数据写入、P2-15 后续知识关系版本。
- **验收条件：** 每项结论具有可实际触发过程和源码/测试证据；区分 P2-16 前必须调整、独立后续和无需调整；自动验证只使用临时或合成数据。
- **风险等级：** 高。P2-13 的永久删除会清理成绩并解绑答卷，组合错误可能使工作台显示相互矛盾的批改状态。

## 2. 结论

发现 **1 个 `Important`、P2-16 前应先处理的组合问题**；没有 `Critical`。其余学生编辑、分析和知识图谱传播路径不需要修改。

| 分类 | 数量 | 结论 |
|---|---:|---|
| A：P2-16 前必须调整 | 1 | 永久删除学生后，答卷可同时处于“未匹配”和“已批改”，导致工作台进度数字互相矛盾 |
| B：独立后续 | 1 | P2-15 历史上按用户决定跳过最终独立复审与用户短测；这不是本次发现的功能错误，但组合修复后宜补一次限定浏览器核验 |
| C：无需调整 | 5 组 | 身份连接、编辑传播、分析/图谱删除传播、旧学生列表契约、页面失效范围恢复 |

当前判断：**P2-13、P2-14、P2-15 不能直接作为“无需处理即可继续”的组合基线；先关闭 A 项，再恢复 P2-16。**

## 3. A 项：删除后工作台同时显示“已批改 1/1”和“0%”

### 3.1 可实际触发过程

1. 某考试有一名学生和一张已匹配、已批改的答卷，工作台为 `1 / 1 份`、`100%`。
2. 在 P2-13 学生名单页查看删除影响、完成备份并永久删除该学生。
3. 删除事务清除该学生的成绩结果，将答卷 `student_id` 置空、`match_status` 改为 `student_deleted`，但没有修改答卷原有的 `processing_status='graded'`。[删除事务](../../../db_manager.py#L950)
4. P2-14 进度查询按 `match_status` 计算匹配数，却独立按 `processing_status` 计算已批改数；完成百分比又用“已批改 + 失败”除以匹配数。[进度聚合](../../../db_manager.py#L2038)
5. 临时数据库稳定复现的删除后结果为：总答卷 `1`、匹配 `0`、未匹配 `1`、已批改 `1`、进度 `0%`。
6. 工作台把 `graded_papers / total_papers` 显示为 `1 / 1 份`，同时把 `progress_percent` 显示为 `0% 已批改`。[工作台展示](../../../frontend/src/views/WorkbenchView.vue#L33)

### 3.2 违反的冻结要求

- P2-14 必须显示既有总数、已批改等计数和原进度百分比，且不得重新定义完成率；这些事实必须能被教师清楚理解。[P2-14 业务溯源](2026-07-15-p2-14-workbench-analysis-overview-design.md#L22)
- P2-13 明确保持答卷匹配和评分规则不变，删除的业务结果是清理成绩并解绑答卷。[P2-13 边界](../plans/2026-07-18-p2-13-student-roster-implementation.md#L12) [删除语义](../plans/2026-07-18-p2-13-student-roster-implementation.md#L65)
- 当前结果让同一张答卷既被工作台计入“已批改”，又被异常区列为“未匹配”，不满足组合后的结果一致性。

### 3.3 实际影响

- 教师无法从首屏判断这张答卷当前到底算已完成还是需要重新处理。
- 工作台进度行动带和异常清单给出相反信号，可能造成漏处理或重复判断。
- 这是永久删除后的正常可达路径，不是理论极端情况。

### 3.4 严重程度与来源

- **严重程度：** `Important`
- **问题来源：** 当前任务原本遗漏。P2-13 的删除事务与既有 P2-14 进度读取分别通过了各自测试，但缺少“已批改答卷所属学生被永久删除”这一组合不变量。
- **阻塞判断：** 阻塞恢复 P2-16；不否定 P2-13 其余已经通过的用户验收步骤。

### 3.5 建议的有界调整

**推荐：** 在 P2-13 同一删除事务中，解绑答卷时把已经失去学生和成绩结果的答卷恢复为可重新处理的非完成状态，并清理只属于旧批改结果的错误状态；同时增加组合回归，断言删除后 `graded_papers <= matched_papers`，工作台数字一致。

推荐该方向的理由是：它修正产生矛盾的底层答卷状态，不需要重定义 P2-14 的全局进度口径，也符合 P2-13“不修改分析口径”的边界。

**不推荐仅修改工作台计算公式：** 只让“已批改”计数过滤未匹配答卷可以消除页面矛盾，但数据库仍保留“没有学生、没有成绩结果、却是已批改”的答卷状态，其他读取者仍可能得到不一致事实。

具体采用哪个非完成状态，以及重新匹配后是否自动进入待批改，属于会改变业务行为的产品决定；实施前应冻结这一点。当前调查未擅自修改。

### 3.6 用户决定与修复边界

用户于 2026-07-18 确认：

- 永久删除学生并解绑答卷后，答卷恢复为 `pending`（待处理），重新匹配后需要重新批改；
- 回归测试锁定两个公开入口：学生永久删除，以及删除后重新读取工作台进度；
- 修复只调整同一删除事务中的答卷派生状态并增加组合回归，不修改 P2-14 进度公式、数据库 Schema、其他删除范围或 P2-16。

## 4. 无需调整的组合路径

### 4.1 编辑姓名、学号或班级不会切断历史成绩

成绩、题目明细和图谱证据的主连接使用稳定的学生记录编号；读取时再连接当前学生表取得最新学号、姓名和班级。[成绩读取连接](../../../db_manager.py#L2383) [图谱学生解析](../../../integration/diagnosis_profile_service.py#L748)

因此：

- 改姓名或学号后，历史成绩仍属于同一个学生，只更新显示身份；
- 改班级后，历史结果按当前班级进入分析和图谱筛选，这是现有服务语义，不是 P2-13 新增的第二套历史班级；
- 批量导入按已有学号更新，不会生成同学号的第二个学生。

### 4.2 永久删除后分析和图谱不会残留该学生

P2-13 在同一事务中先删除该学生的题目明细、批注、考勤和成绩结果，再解绑答卷并删除学生。[删除事务](../../../db_manager.py#L950)

P2-14 分析和 P2-15 图谱都从当前学生及仍存在的成绩/明细连接读取；选择范围中的学生已不存在时，图谱会忽略该编号并返回说明，而不是把旧证据串给其他学生。[图谱缺失学生处理](../../../integration/diagnosis_profile_service.py#L748)

### 4.3 P2-15 旧链接在班级或学生删除后会安全失效

知识图谱页面启动时重新读取学生选项；地址中的考试、班级或学生范围不再有效时会清空受控参数并要求重新选择，不会擅自选择第一个班级。[范围解析](../../../frontend/src/features/knowledge-graph/route.ts#L45) [页面重新读取](../../../frontend/src/views/KnowledgeGraphView.vue#L69)

### 4.4 旧 `/api/students` 契约仍兼容

P2-13 保留旧接口的 `items/total` 顶层和 `id/student_code/name/class_name/created_at` 学生字段；P2-15 的严格解码仍使用同一结构。[旧列表解码](../../../frontend/src/api/students.ts#L17)

### 4.5 请求串线保护仍有效

P2-13 名单、P2-14 分析和 P2-15 图谱各自使用请求世代或范围核对；切换学生、考试、班级或图谱范围后，迟到响应不能覆盖新内容。相关实现边界已记录在架构事实中。[P2-14 架构边界](../../../ARCHITECTURE.md#L23) [P2-15 架构边界](../../../ARCHITECTURE.md#L29)

## 5. 故障场景核对

| 场景 | 当前组合结果 |
|---|---|
| 重复删除 | 第二次找不到学生，不重复清理 |
| 同时编辑/删除 | 名单 revision 只允许一个赢家，冲突要求刷新 |
| 中途退出/部分完成 | 删除在事务内执行；删除语句失败会回滚，备份失败零删除 |
| 重新启动 | 名单、成绩和答卷状态从数据库恢复；本报告发现的矛盾也会持久存在，说明它不是页面缓存 |
| 失败重试 | 需重新取得当前 revision；不会按旧影响直接重放 |
| 取消 | 用户确认前可以退出；确认后的原子本地事务不提供中途取消 |
| 数据缺失/冲突 | 学生或 revision 已变化时失败关闭 |

这些保护不需要调整；A 项只涉及成功删除后的答卷派生状态。

## 11. 限定最终复审结论

统一修复候选 `fc0e63e6cb3a2192f5656daa6b07590d34e816b5` 完成了规则允许的唯一一次限定最终复审。两名原评审代理各提交 1 项 `Important`，去重后保留 2 项，来源均为“当前任务原本遗漏”：

## 12. 用户确认后的新修复任务边界

用户于 2026-07-18 明确确认实际使用规则：

- 批改任务正在运行时，不支持永久删除学生；删除接口应明确拒绝，并提示等待批改结束；
- 批改任务结束、系统空闲时，允许删除转学等不再使用的学生；
- 空闲删除必须安全处理已经结束的历史批改账本，随后答卷保持“未匹配、待处理”，等待重新匹配和主动重新批改。

冻结边界：

- **目标：** 关闭运行中删除与历史批改账本外键造成的两个阻塞问题；
- **包含：** 学生永久删除公开接口的活动批改保护、结束账本引用的安全收口、删除后工作台状态；
- **不包含：** 支持运行中强制删除、自动取消批改、自动重新匹配或重新批改、数据库 Schema 迁移、P2-14 公式、P2-15 图谱语义、P2-16/P2-17；
- **公开测试接缝：** 学生永久删除 HTTP；删除成功后工作台 HTTP；
- **验收：** 活动批改时删除无数据变化并返回可理解的冲突；完成或失败的历史账本存在时删除成功；成绩及派生证据清理、答卷解绑为 `student_deleted/pending`、旧账本不再阻止外键删除；真实业务数据不变；
- **风险：** 高。涉及永久删除、批改运行状态、账本外键与事务一致性。

与本任务相关的故障场景：

| 场景 | 冻结结果 |
|---|---|
| 重复删除 | 首次成功；再次请求按学生不存在处理，不重复清理 |
| 同时删除/批改 | 活动批改状态先被识别并拒绝删除；不自动取消任务 |
| 中途退出/部分完成 | 删除及账本收口在同一数据库事务中，失败整体回滚 |
| 重新启动 | 活动运行按既有恢复规则识别；终态历史账本不阻止空闲删除 |
| 失败重试 | 刷新名单 revision 后可重新提交；不复用旧确认 |
| 取消 | 取消尚未终结前仍视为活动；终结后方可删除 |
| 数据缺失/冲突 | 学生不存在或 revision 变化时保持原有安全失败；未知账本状态不擅自删除 |

该任务从 `15c33cd0b2b6cbf0cc99742e8e107b211421a749` 建立独立短分支 `codex/p2-13-safe-idle-delete`；此前未通过最终复审的候选不直接集成，P2-16 继续暂停。

## 13. 安全空闲删除实现候选

实现严格采用用户确认的“运行中拒绝、空闲时允许”规则：

- 永久删除事务取得写锁并复核名单 revision 后，先检查任一考试会话是否仍为 `running`；
- 若批改账本表存在，再检查 `running`、`pause_requested`、`paused` 三种非终态运行；命中时在创建备份前停止，公开接口返回 `409 / student_grading_active`；
- 名单页把该冲突显示为“批改仍在进行，请等待批改结束后再删除学生”；
- 系统空闲时，只删除该学生在终态历史批改中的账本明细，再按原顺序清理成绩、评分明细、批注、考勤、答卷关联和学生；全部操作仍在同一事务中；
- 旧数据库没有批改账本表时继续兼容原删除流程，不要求 Schema 迁移；
- 保留迟到批改发布前的答卷归属核对，作为事务竞态的第二层防护。

TDD 证据：

1. 活动批改 HTTP 删除测试先得到通用 `500`，实现后在 `running`、`pause_requested`、`paused` 三种状态均得到明确 `409`，且无备份、无数据变化；
2. 运行会话但账本不可用的兼容测试先错误进入删除，实现后同样明确拒绝；
3. 带完成态历史账本的删除→工作台组合测试先得到 `500`，实现后删除成功，答卷为 `student_deleted/pending`，工作台为未匹配 1、已批改 0、进度 0%；
4. 名单页活动批改提示测试先得到通用删除失败文案，实现后显示等待批改结束的明确提示；
5. 注入关联删除失败时，已删除的历史账本明细随同一事务回滚，学生及其他历史数据均保持不变。
