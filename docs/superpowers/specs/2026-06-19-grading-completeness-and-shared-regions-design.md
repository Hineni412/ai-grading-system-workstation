# 批改完整性、共享作答区域与请求平滑设计

## 目标

统一整卷批改与混合批改的标准答案口径；让同一大题的重叠、跨页作答区域只作为共享证据上传；在本地严格发现缺失、重复、异常题号和超满分；允许用户一键重跑不完整学生的整道大题并原子替换该大题结果；未补齐前在界面和导出中明确标记“不完整”；同时清理无效客观题参数并消除首轮请求突发。

## 不在本次范围内

- 不迁移现有旧评分配置，也不自动改写旧配置中的 `response_mode`。
- 不把题干图片或标准答案图片改为强制字段。
- 不修改既有 100 分制和单题分值规则。
- 不要求教师把天然共享的作答区域强行拆成互斥小框。

## 一、标准答案统一

建立唯一的答案形式解析入口。整卷和混合客观题都按以下顺序取得答案：

1. `accepted_forms` 中所有非空形式；
2. `canonical_answer`；
3. 兼容旧数据的 `standard_answer`、`correct_answer`、`answer`；
4. 仅当前三项都缺失时，才从模板映射文件兜底。

返回值始终为去重后的字符串列表。选择题继续做大小写归一化；填空题把整个列表交给现有等价匹配器，不再把多种等价形式压缩成单一字符串。标准答案缺失时不得直接判错，必须进入复核/不完整状态。

## 二、共享、重叠和跨页作答区域

### 2.1 逻辑模型

把“逻辑大题”和“物理裁图”分开：

- 一个逻辑大题包含一个或多个小问。
- 一个物理裁图属于某一页，可以为一个或多个小问提供证据。
- 同一小问可以引用多张、不同页面的物理裁图。
- 同一张物理裁图可以同时映射多个小问。

图集清单使用证据组表达：`page + bbox + part_ids`。模型仍必须为大题的每个 `part_id` 分别返回一个结果。

### 2.2 自动聚类

仅在同一页面内比较区域。两个区域满足以下任一条件时进入同一共享证据组：

- 交集面积 / 较小区域面积大于等于 90%；
- 两个区域坐标完全相同。

聚类具有传递性，合并后的物理框取成员区域的并集，`part_ids` 取成员对应小问的并集。不同页面永不合成一个坐标框。

预期效果：

- 当前 Q10 三个相互包含的区域合并成一张共享图，映射 Q10(1)、Q10(2)、Q10(3)。
- 当前 Q12(2)、Q12(3)合并成一张共享图，Q12(1)保持独立。
- 当前 Q11 的低重叠区域保持独立。

### 2.3 跨页规则

跨页大题按页面保留多张证据图，并在同一次大题请求中一起出现。例如：

- 第一页下方框选 Q(1)：生成第一页证据组，映射 Q(1)。
- 第二页框选共享区域并分别映射 Q(2)、Q(3)：自动聚类为第二页证据组，映射 Q(2)、Q(3)。
- 如果第二页只框一个父题区域 Q：父题区域只补充当前没有明确小问区域的 Q(2)、Q(3)，不会覆盖已经有明确区域的 Q(1)。
- 如果整道大题只有父题框，并且前后页各有一个父题框，两张图都映射全部小问，模型必须综合两页证据评分。

区域解析优先级为：明确小问区域 > 父题共享区域 > 兼容旧数据的前缀/位置推断。一个小问存在多个明确区域时全部保留，不再把不同页面坐标错误合并。

### 2.4 提示词和低置信处理

提示词明确说明共享图可能包含多个小问，学生可以上下、左右或连续书写。模型应结合题号标记、书写顺序、题目内容和推导关系分别输出各小问；不得因同一图片关联多个小问而重复计算同一得分证据。

如果能读全作答但无法可靠区分小问边界，模型必须：

- 仍返回全部小问；
- 为不确定的小问设置低置信和 `needs_human_review=true`；
- 在原因中写明“共享区域内小问边界不明确”。

本地完整性校验只保证结果齐全，不把低置信结果伪装成确定结果。

## 三、批改完整性审计

### 3.1 期望集合

从当前 rubric 建立规范化的小问全集。含 parts 的大题以所有 `part_id` 为准；无 parts 的题以父题号为准。每名已匹配且非缺考学生都必须拥有该全集中的每一项。

### 3.2 本地检查

每次模型返回后、入库前检查：

- 缺失学生；
- 缺失小问；
- 重复小问；
- 非预期题号或父题代替小问；
- 负分或超过小问满分；
- 详情分数和与学生总分不一致。

整卷返回存在任何结构问题时不作为完整结果保存。混合批改允许保存已有详情供后续补跑，但必须在 `raw_json` 中写入结构化 `grading_completeness`，将结果标记为不完整并列出受影响的大题、小问和原因。

### 3.3 状态与导出

完整性状态分为：

- `complete`：题目全集齐全且合法；
- `incomplete`：存在可补跑的缺失/失败大题；
- `invalid`：存在重复、异常题号、超满分等不可直接信任的数据。

批改页固定显示不完整面板，按学生列出缺失大题、缺失小问、最近失败原因和补跑次数。成绩导出增加“批改完整性”和“缺失题目”列；未补齐的结果显示“不完整”，不得仅凭 `processing_status=graded` 伪装成完整成绩。

## 四、一键补跑与原子替换

### 4.1 补跑单位

补跑最小单位为“学生 × 整道大题”。若 Q12 仅缺 Q12(3)，仍重新批改该学生的 Q12(1)、Q12(2)、Q12(3)。客观题没有 parts 时仍按单题补跑。

### 4.2 数据合并

补跑开始前保留旧结果。新大题通过全部结构和分数校验后，在一次数据库事务中：

1. 删除该学生该大题的所有旧详情；
2. 插入新大题全部详情；
3. 保留其他题详情；
4. 重算学生总分；
5. 重跑完整性审计；
6. 只有审计通过才清除该大题失败记录。

任何一步失败都回滚，旧结果和“不完整”标记保持不变。补跑再次失败时增加尝试记录，用户可继续点击补跑，不限制次数。

### 4.3 现有兼容

现有 `hybrid_batch_fallback` 继续识别，但统一转换为新的 `grading_completeness` 展示。旧数据没有该字段时，页面加载时根据 rubric 和详情实时审计，因此历史上静默缺题的数据也能被发现。

## 五、配置边界与客观题参数清理

删除客观题 `objective_timeout`、`objective_max_tokens` 的界面状态、保存逻辑和运行配置读取；加载旧 profile 时忽略并在下次保存时移除这两个键。

前端与后端使用同一组常量：

- 客观题批大小：1～15；
- 主观题批大小：1～20；
- 姓名预检并发：1～32；
- 整卷并发：1～200；
- 混合在途并发：1～1000；
- 请求频率：1～10000 RPM。

提示词不再写死与实际清单可能冲突的学生数量，而是使用当前 manifest 的实际人数；后端仍把客观题批大小限制为 15。

## 六、请求平滑和重试限流

现有令牌桶启动时预装整分钟令牌，导致首批请求瞬间放行。改为严格节拍限流：初始无突发容量，每个请求启动时间至少间隔 `60 / RPM` 秒。

所有实际模型尝试都必须在调用前获取节拍，包括：

- 整卷首次请求和网络重试；
- 客观题 Lite 首次请求和重试；
- 客观题 Pro 复核请求和重试；
- 主观题首次请求和内部重试。

线程池只控制最大在途数，节拍器控制启动速率，两者共同生效。等待限流时不占用全局锁睡眠，按预留的下一个时间槽公平启动。

## 七、旧版 response_mode 与图片策略

新版配置生成提示词已经强制每个 part 返回 `response_mode`，本地规范化也会推断缺失值。本次不迁移旧配置，只在检测到缺失时给出非阻断提示。

题干图和标准答案图继续保持可选：存在时上传，不存在时依赖 rubric 和 answer_key 文本。此次不增加强制图片校验。

## 八、测试与验收

必须覆盖以下自动化测试：

- 整卷和混合对同一 `accepted_forms` 列表得到相同答案集合；
- 同页 90% 以上覆盖区域聚类，不同页不聚类；
- Q10 型三框包含关系只生成一张共享裁图；
- Q12 型一个独立框加两个共享框生成两张裁图；
- 跨页小问、跨页父题框和同一小问多页证据均保留正确映射；
- 缺失、重复、父题代替小问、超满分均被完整性审计发现；
- 补跑任一小问时重跑并原子替换整道大题；失败事务回滚并保持不完整；
- 连续补跑失败后仍可再次补跑；
- 导出结果包含完整性状态和缺失题目；
- 配置界面和后端边界一致，旧 profile 保存后移除废弃键；
- 并发线程首次调用和每次重试均按节拍放行，不再出现初始突发。

验收时使用当前 0609 的区域配置验证：Q10 共享一图、Q12 两组证据、Q11 保持独立，并对现有整卷/混合结果运行一次只读完整性审计，确认历史静默缺题能在前端列出。
