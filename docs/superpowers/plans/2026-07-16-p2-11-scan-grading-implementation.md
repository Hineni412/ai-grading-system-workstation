# P2-11 扫描预检、批改进度与失败恢复即时实现计划

## Objective

在不改变扫描匹配算法、评分算法、评分模式语义和生产入口的前提下，交付独立的 Vue“批改执行”工作区：教师可以分批上传整班答卷、冻结上传批次并运行扫描预检、处理低可信和异常卷、并列启动整卷或混合批改、安全暂停/继续/取消、只重试原模式下的失败答卷，并在刷新或进程重启后看到与持久记录一致的任务、阶段、计数和恢复建议。

## Confirmed Decisions

用户于 2026-07-16 逐项确认：

1. 新增独立“批改执行”页面，从工作台和考试配置进入；评分复核继续只负责批改后的人工复核。
2. 同一上传队列允许分多次添加文件，按内容去重；预检前可移除或清空，预检开始后冻结。
3. 未处理异常卷不阻塞整班批改；启动前必须展示正常批改数与跳过数并显式确认；异常卷保留供后续匹配和补批。
4. 暂停从同一批次断点恢复；取消终结本次任务，保留已完成结果，未完成答卷不算失败，后续需要新建任务。
5. 整卷与混合批改并列同等可见；每种模式各自提供“仅重试失败答卷”，默认且必须沿用原失败任务的模式。
6. TDD 只锁定三类公开 seam：页面操作、前后端契约与刷新恢复、安全和数据边界；不测试内部代码组织。

## Public Test Seams

这些 seam 已获用户确认，写测试前不得扩大为内部实现断言：

1. **HTTP/API seam**：上传批次、预检快照与人工决定、会话批改运行摘要、启动/暂停/继续/取消/失败重试；验证错误码、乐观冲突、脱敏、幂等和模式约束。
2. **Vue user-flow seam**：四阶段页面、分批上传与冻结、异常确认、两模式并列启动、取消确认、暂停恢复、失败重试、刷新/重启恢复和旧响应隔离。
3. **真实浏览器 + 临时服务 seam**：匿名固定文件、假 OCR/LLM、临时数据库和临时数据根贯通上传到恢复；覆盖五档 Windows 桌面视口。

领域服务只通过其公开方法被 API 测试驱动；数据库允许用于测试准备和核对安全不变量，不把私有 SQL 结构作为前端行为断言。

## Planned Interface

精确 URL、Schema 字段和文件拆分在实现前通过设计文档和首个 RED 固定，预计最小接口族为：

- 会话扫描上传批次：创建/恢复、添加、列表、移除、清空、冻结；
- 会话预检：启动、读取当前脱敏快照、保存人工决定；
- 会话批改运行：读取当前运行摘要、启动两种模式、安全暂停、继续、取消、按原模式重试失败；
- 受控扫描媒体：只允许当前会话当前预检快照引用的正反面资源。

不得把 `exams_dir`、rubric/answer 文件路径、扫描结果路径、内部错误、密钥或答卷正文放入公开 payload/result。

## Rollback and Stop Conditions

- 功能回退为撤销 P2-11 提交并继续使用旧 Streamlit 批改页；不删除上传、预检、账本或已有评分结果。
- 上传/冻结/预检失败不得覆盖上一份成功快照；批改控制失败不得伪造暂停、取消或成功。
- 发现需要改变扫描匹配算法、评分算法、评分模式语义、数据库 Schema、P2-12 边界或生产入口时停止。
- 测试需要真实业务数据、真实密钥、真实模型或不可逆文件操作时停止。
- 首轮复审修复后的最终复审仍有 Critical/Important 时停止。
- 真实两库指纹、大小或 UTC mtime 未经授权发生变化时立即停止。
