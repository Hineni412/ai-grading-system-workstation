## 冻结边界

- **目标：** 修复数据包导出预检成功后，Job 因服务自身任务账本或 SQLite 瞬态文件变化而误报 `preflight resource changed`、不生成 ZIP 的问题。
- **包含：** P1-23 数据包导出资源指纹的稳定性；真实 Ops 预检、确认、Job 执行和受控产物测试；真正源资源变化时继续 fail closed。
- **明确不包含：** Vue 页面；数据库 Schema 或迁移；其他 Ops 操作语义；任意路径、目录或命令；真实业务数据写入；自动重试；P2-19 前端交接文件。
- **公开测试接缝：** 现有 `OpsWriteService.preflight` → 单次确认计划 → `JobManager`/已注册 `ops_transfer_export` handler → 公开 Job 终态及受控 ZIP。该接缝来自 P1-23 已批准契约与 Issue #59，不新增产品接口。
- **验收条件：**
  1. JobStore 位于受控临时数据根的真实调用链可稳定导出成功并生成 ZIP。
  2. 预检后修改真实导出来源时仍以 `preflight resource changed` 失败且不发布半成品。
  3. 重复确认、并发锁、取消、失败不自动重放和路径边界不降低。
  4. P1-23 Ops 聚焦测试、受影响回归、临时真实 API 与快速冒烟通过。
  5. 真实 `user_data` 未触碰，真实两库指纹与下方基线一致。
- **风险等级：** 高。过度排除资源会掩盖真实数据变化，排除不足则正常导出持续失败。

## 故障场景

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 确认令牌仍只消费一次；失败后不自动重放 |
| 同时操作 | 继续由 Ops 进程内和跨进程锁串行化 |
| 中途退出 | 未原子发布的临时 ZIP 不成为可下载产物 |
| 重新启动 | 不改变既有 Job 持久化与公开失败语义 |
| 失败重试 | 必须重新预检并由用户再次确认 |
| 取消 | 发布前继续支持协作式取消 |
| 部分完成 | 不发布半成品；临时文件按既有规则清理 |
| 数据缺失或冲突 | 真正源资源变化、丢失或新增仍拒绝执行 |
| 服务自身账本变化 | JobStore 记录提交和进度不使同一合法导出计划失效 |
