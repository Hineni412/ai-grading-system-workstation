## 冻结边界

- **目标：** 修复数据包导出预检成功后，Job 因服务自身任务账本或 SQLite 瞬态文件变化而误报 `preflight resource changed`、不生成 ZIP 的问题。
- **包含：** P1-23 数据包导出资源指纹的稳定性；真实 Ops 预检、确认、Job 执行和受控产物测试；真正源资源变化时继续 fail closed。
- **明确不包含：** Vue 页面；数据库 Schema 或迁移；其他 Ops 操作语义；任意路径、目录或命令；真实业务数据写入；自动重试；P2-19 前端交接文件。
- **公开测试接缝：** 现有 `OpsWriteService.preflight` → 单次确认计划 → `JobManager`/已注册 `ops_transfer_export` handler → 公开 Job 终态及受控 ZIP。该接缝来自 P1-23 已批准契约与 Issue #59，不新增产品接口。
- **验收条件：**
  1. JobStore 位于受控临时数据根的真实调用链可稳定导出成功并生成 ZIP。
  2. 预检后修改真实导出来源时仍以 `preflight resource changed` 失败且不发布半成品。
  3. 重复确认、并发锁、取消、失败不自动重放和路径边界不降低。
  4. P1-23 Ops 聚焦测试、受影响回归、临时真实 API 与快速冒烟通过。
  5. 真实 `user_data` 未触碰，真实两库指纹与下方基线一致。
- **风险等级：** 高。过度排除资源会掩盖真实数据变化，排除不足则正常导出持续失败。

## 根因与假设结论

1. **确认：** 生产 JobStore 使用阅卷数据库；提交和进度更新 `jobs` 表会改变整个 SQLite 文件的大小或修改时间，旧指纹因此把合法内部写入误判为业务源变化。
2. **确认：** SQLite `-wal/-shm/-journal` 是运行时边车，可能在预检连接期间出现或消失；它们既不是独立业务文件，也不应进入数据包清单。
3. **排除：** Job 专属输出暂存目录在 lean 导出中已受现有顶层跳过规则保护，不是当前失败触发源。
4. **部分确认：** 旧指纹只使用文件大小和修改时间，正是共享 SQLite 文件上的过敏判断；普通受控文件仍保留该快速代际守卫。

修复对两套受控 SQLite 数据库使用逻辑内容指纹：阅卷库的数据库结构、除 `jobs` 外的全部业务表和非 Job 自增代际参与摘要，`jobs` 行及其自增代际不参与；题库的结构、全部业务表和自增代际都参与摘要。导出时，两库都先生成 SQLite 一致性快照再写入 ZIP，确保已提交但仍位于 WAL 的最新数据不会丢失。其他文件继续按原代际守卫，SQLite 运行时边车按现有备份安全语义从导出清单排除。

## 回退与停机

- 修复保持为独立提交，可整体 revert；回退后 P2-19 继续处于外部阻塞，不伪装为通过。
- 若最小修复需要放宽真正业务源变化检测、修改数据库 Schema、改变其他 Ops 状态或接触真实数据，立即停止并请求重新裁定。
- 若统一修复后最终复审仍有当前范围 `Critical`/`Important`，停止并向用户汇报，不开启第三轮。
