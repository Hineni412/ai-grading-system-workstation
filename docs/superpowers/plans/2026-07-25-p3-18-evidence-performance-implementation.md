## 冻结边界

- **目标：** 对 review/report crop、tag projection request memo、图片压缩和热点 SQL/index 四类候选做同环境、同数据、可重复的前后实验；只合并能在目标数据规模证明收益且正确性不变的优化。
- **包含：** 生成数据基准工具与版本化报告；候选选择记录；被选候选的最小实现；p50/p95、峰值内存、磁盘占用、失效策略、并发与清理/重建验证；受影响回归。
- **明确不包含：** 不改变实时标签语义、API 结果、评分或报告口径；不做跨请求全局永久缓存；不为无数字收益的候选改代码；不操作真实模型或真实 `user_data/`；不夹带 P3-17 Issue #95 旧训练集清理、Issue #92 或 Issue #67。
- **验收条件：** 每个候选都有环境、数据规模和选择结论；纳入候选在重复运行中 p50 改善至少 20%，p95 不得退化超过 5%，输出字节/结构或业务记录完全一致；缓存有有界磁盘/内存、确定性失效、并发单发布、失败清理和可重建证据；未纳入候选明确记录原因；聚焦测试、受影响回归、快速冒烟、完整门槛、双路复审和真实两库指纹守卫通过。
- **风险等级：** 中高。缓存与文件操作涉及并发、失效和磁盘增长；只允许生成数据和系统临时目录写入。

## 集中调查

1. P1-26 提供三档、16 场景的优化前 API/DB 基线；P1-27 已在五个 Training/Graph 接口实施请求级双库只读连接，报告只证明请求内连接/语句缩减，不是容量或 SLA 结论。
2. Master Plan 的四类候选仍为：review/report crop 派生图、tag projection 请求内 memo、重复图片压缩、热点 SQL/index；稳定 Phase map 要求“无数字不优化”。
3. 当前 crop API 每次请求都重新解析源图、换色、计算区域、裁剪、画框并 JPEG 编码，没有派生缓存；该候选具有可直接构造的重复读取场景和明确字节等价判据。
4. 当前 `QuestionTagProjectionService.project_session()` 已在单次调用中批量读取确认链接、题目和标签；Diagnosis 每个 session 只构建一次投影。是否存在同一请求内重复 session 投影必须用调用计数实验确认，不能仅按计划假设实施 memo。
5. 当前 `_compress_image_for_api()` 每次将字节解码、缩放并 JPEG 编码；是否在同一有界业务请求中重复处理同一图片，须用调用身份与耗时实验确认，不能引入无界进程缓存。
6. P1-26 当前场景和题库列表查询形状可用于热点筛选；索引候选必须有 `EXPLAIN QUERY PLAN`、目标数据量和前后延迟，且不得因写放大或磁盘成本抵消收益。
7. P3-17 状态 PR 将 P3-18 误写成“瘦身与过期文档收口”；Phase map 的稳定包定义优先，本包领取时纠正为“基于证据的性能优化”，不开展开放式删除。

## 故障场景

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 相同输入命中同一有效结果，不重复扩大磁盘或内存 |
| 同时操作 | 同一缓存键最多一个发布者；其他调用得到完整相同结果，不读半文件 |
| 中途退出 | 临时文件不冒充成功缓存；下次可重建 |
| 重新启动 | 只复用经源指纹和格式验证的可再生缓存；无效项重建 |
| 失败重试 | 解码/写入失败不覆盖旧有效结果，不遗留无法清理的临时项 |
| 取消 | 基准与生产调用均不把部分结果发布为命中；不新增业务取消语义 |
| 部分完成 | 每个缓存键独立，单项失败不污染其他键 |
| 数据缺失或冲突 | 源文件、区域或版本不匹配时视为 miss；业务原错误保持不变 |
