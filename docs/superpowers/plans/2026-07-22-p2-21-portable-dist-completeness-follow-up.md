# P2-21 便携前端资源完整性后续修复

**授权：** 用户于 2026-07-22 明确授权，在 P2-21 终审发现 Important 后建立此限定修复任务。
**基线：** f5b5f4995623352b8cca9d243c484f28478b5032
**风险：** 中。仅影响生成便携包前的前端资源完整性判断，不操作真实业务数据。

## 冻结边界

- **目标：** 让便携打包与 FastAPI 启动器对 `frontend/dist` 使用相同的最小完整性标准：`index.html` 存在、`assets/` 存在且至少包含一个文件。
- **包含：** `package_v1.5.0.py` 的打包前检查，以及空 `assets/` 的回归测试和本任务证据。
- **不包含：** FastAPI 路由、缓存头、浏览器启动、批处理入口、Vue 源码、打包目录结构、数据库、模型调用、真实 `user_data/` 或 P2-22 删除。
- **验收：** 空 `assets/` 目录会使 `copy_sources()` 在复制前失败；正常构建产物仍可打包；相关打包/启动测试和快速冒烟通过。

## 故障场景

| 场景 | 预期结果 |
|---|---|
| `dist`、`index.html` 或 `assets/` 缺失 | 打包失败，不生成可误用的候选包。 |
| `assets/` 为空 | 打包失败，错误说明前端构建不完整。 |
| 正常 hashed 资源存在 | 正常复制并保留已有无 Node 工作机布局。 |
| 打包失败后重试 | 修复构建产物后可再次打包；本任务不写真实数据。 |

## 实施与验证

- [ ] 先让空 `assets/` 的打包测试稳定失败。
- [ ] 让打包检查复用与启动器相同的完整性规则。
- [ ] 运行打包/启动相关测试和 `tools/smoke_check.py --skip-tests`。
- [ ] 冻结候选并进行一次范围限定的需求与质量复审。
- [ ] 将通过的修复并回 P2-21 候选，再恢复 P2-21 的交接与 integration 流程。
