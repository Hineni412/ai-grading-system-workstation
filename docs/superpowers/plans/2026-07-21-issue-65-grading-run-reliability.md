# Issue #65 批改启动可靠性与费用保护实施计划

**状态：** final_review_pending
**基线：** `e13351141e39db1fbcd68018a0f5faa9fbb1f87b`
**分支：** `codex/issue-65-grading-run-reliability`
**关联：** P2-11 批改进度与失败恢复、P1-24 模型请求策略、P2-20 正式验收阻塞

## 冻结边界

- **目标：** 修复一次整卷批改中共同暴露的界面反馈、并发、隐藏重试和超时错位，避免教师误以为任务未启动、重复操作或产生未授权的额外模型费用。
- **包含：**
  - 点击整卷批改后，原页面立即显示“任务已提交/正在启动”，自动展示运行区，并在服务端账本出现前阻止重复提交；刷新或重新打开继续从服务器恢复。
  - 新 Vue/FastAPI 整卷批改的首次运行、恢复、失败项重试和补批默认只允许一份答卷在途；调用方仍可通过既有显式参数覆盖首次运行，混合批改不变。
  - 整卷网络、超时和限流错误不再由外层自动重试；失败后只保留用户显式重试入口。
  - 整卷模型入口显式等待 600 秒；共享 grading 默认和混合批改继续保持 300 秒。
  - 生产 `LLMClient` 的整卷请求只发一次并在本地修复 JSON，不因坏 JSON自动追加模型请求。
- **不包含：** 提示词、评分标准、评分算法、答案、分值、OCR、匹配、混合批改并发、数据库 Schema、真实业务数据、真实模型调用或重新执行已完成的 P2-20 配置生成。
- **验收条件：** 通过公开 Vue 路由、FastAPI 路由和模型客户端入口，使用假上游与临时数据证明即时反馈、重复提交保护、整卷所有控制路径默认串行、单次模型请求、600 秒策略以及刷新恢复；不执行真实网络请求。
- **风险等级：** 高。涉及后台任务状态、失败恢复、并发、重试和外部费用；实现错误可能造成重复请求、长时间等待或批改任务错误状态。

## 已确认测试边界

用户启动 P2-20 时已确认新 Vue 公共路由、真实 FastAPI/Job 公共接口和持久恢复为本阶段测试边界；本次又明确批准增加修复并要求停止反复人工测试。因此只保留以下三个公共 seam：

1. `/sessions/:id/grading-run`：点击整卷批改后的可见反馈、自动展示和重复提交保护。
2. 扫描批改 FastAPI 路由：首次运行、恢复、失败重试和补批产生的公开 Job 行为。
3. `AIGrader`/统一 LLM 策略入口：一次整卷只产生一次假模型调用，整卷显式等待为 600 秒且不改变共享 grading 默认。

## 集中调查与根因

1. 页面点击后只设置内部忙碌状态并禁用按钮，没有显示启动提示；运行表格位于按钮下方，只有服务端运行账本出现后才渲染，也不会自动滚动。生产日志已证明第一次点击返回 202 并持续轮询，随后一次重复提交被 409 拦截。
2. Vue 启动正文不发送 `max_workers`；控制类端点也不保存首次并发设置。服务最终使用大图请求默认并发 6，三份答卷在约一秒内同时出站。
3. Gateway 在该入口默认不重试，但整卷外层仍把网络、超时和限流错误默认重试一次；普通 JSON 解析失败还可能触发一次模型修复请求。这两层都不符合“自动重试 0”。
4. 整卷策略和调用入口使用约 300 秒等待，而验收转发层等待约 600 秒；调用方先失败后，上游请求继续运行，形成不可观察的在途请求。

问题清单在此冻结；相邻优化不进入本次修改。

## 故障场景

| 场景 | 预期结果 |
|---|---|
| 重复点击 | 第一次点击立刻锁定入口并显示启动状态；第二次点击不创建新请求；服务端幂等保护继续保留。 |
| 同时操作 | 同一会话仍只允许一个活动 Job；整卷答卷按一份在途串行处理。 |
| 中途关闭页面 | 后台 Job 继续；重新打开从服务端恢复，不自动补发。 |
| 重新启动服务 | 沿用既有 Job/运行账本恢复规则；本修复不伪造完成状态。 |
| 传输失败或超时 | 当前答卷失败，只记录一次模型调用；不自动重试。 |
| 用户显式重试失败项 | 只重试现有失败项，并继续按一份在途串行处理。 |
| 暂停或取消 | 停止派发新答卷；最多等待当前一份在途请求到达 600 秒边界，既有安全发布规则不变。 |
| 部分完成 | 已成功答卷保留，失败答卷保持失败；不重新请求成功答卷。 |
| 数据缺失或冲突 | 沿用现有 409/422 与 revision 保护，不新增降级。 |
