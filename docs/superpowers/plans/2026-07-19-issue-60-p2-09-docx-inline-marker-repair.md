## 冻结边界

- **目标：** DOCX 的连续主问题号位于段落中间时，考试配置上传预览仍能拆成独立题块，不能把后一题并入前一题。
- **包含：** P2-09 DOCX 富文本来源的主问题边界识别；同段连续题号；拆分后文字、公式和图片归属；不得误拆的小数、子题编号和非连续正文编号；公开上传预览回归。
- **明确不包含：** PDF 拆题；答案区语义扩展；评分规则、生成 prompt 或模型调用；Vue 页面；数据库 Schema/迁移；真实业务文件或数据；P2-20 验收工具与 formal 证据。
- **公开测试接缝：** 现有 `POST /api/sessions/{session_id}/config/sources` 上传合成 DOCX，读取同一响应中的安全 `questions` 预览。该接缝来自 P2-09 已批准契约与 Issue #60，不新增产品接口。
- **验收条件：**
  1. 合成 DOCX 中 `Q10` 段后半出现 `11.`、随后段首出现 `12.` 时，公开预览精确返回 `Q10/Q11/Q12`，且 Q11 正文不再进入 Q10。
  2. 同一富文本段落中位于 Q11 标记后的公式/图片归到 Q11，不泄漏到 Q10。
  3. 小数、年份/普通正文数字、子题 `(1)`、答案区和非连续题号不因本修复新增误拆。
  4. Config Source/API 聚焦测试、题库导入受影响回归和快速冒烟通过。
  5. 稳定候选由 Spec/Standards 两名评审者检查同一 SHA，当前范围 `Critical`/`Important` 为零。
- **风险等级：** 中高。修得过窄会继续漏题；修得过宽会把正文数字误判为新题，造成评分依据与试卷不一致。

## 根因与假设结论

1. **确认：** DOCX 富文本映射只把段首主问题号切换为新题；段中 Q11 因此留在 Q10，直到段首 Q12 才切换。
2. **确认：** 上传缓存不是原因；直接调用本地 DOCX 拆题入口仍稳定缺 Q11。
3. **排除：** 图片/公式解析不是边界丢失的起点；在正确建立 Q11 边界后，标记后的公式和图片可沿既有路径归入 Q11。
4. **防误拆约束：** 只接受从当前题号开始的连续内联序列，且该序列必须由后续段首主问题号闭合；小数、子题和非连续正文引用保持在当前题。
5. **预防措施：** 在公开上传接缝保留合成 DOCX 回归，同时保留纯文本回退回归；后续重构段落解析时无需依赖真实试卷即可捕获同类漏题。

测试时发现便携 Python 默认优先加载根目录源码；已改用显式把当前 worktree 插入 `sys.path[0]` 的测试启动方式重新取得本分支证据。一次既有 PDF 请求令牌用例在 133 项波次中间歇返回内容冲突，未经过本次 DOCX 路径；该用例随后单独连续两次通过，完整 133 项波次复跑通过，未扩大本任务修复范围。
