# Issue #62 配置整卷生成输出截断修复

**状态：** final_review
**基线：** `0a2e481dc7b02252feacff46000b78308e7a46bb`
**关联：** GitHub Issue #62、P2-20 正式验收外部阻塞

## 冻结边界

- **目标：** 让整卷单请求显式申请足够的输出预算，保留模型停止原因，并把长度截断与普通 JSON 格式错误准确区分。
- **包含：**
  - Word/PDF 整卷单请求显式发送 32,000 输出 token 上限；
  - 安全记录 `finish_reason`、输出字符数、输出哈希和既有 token 用量；
  - 模型明确因长度停止，或未返回停止原因但 JSON 结构明显截断时，返回可操作的脱敏错误；
  - 失败时不发布半成品、不自动再调用模型，并提示用户可明确选择逐题/分批生成。
- **明确不包含：**
  - 自动续写、自动重新生成或其他隐式模型调用；
  - 修改评分规则、配置结构、数据库 Schema 或 API 契约；
  - 真实模型请求、真实 `user_data/` 写入或 P2-20 验收证据修改；
  - 为不支持输出上限参数的兼容线路自动发起第二次参数回退请求。
- **验收条件：**
  - 公开 `LLMClient` JSON 单请求接口在正常、明确长度停止、未知停止原因但结构截断、普通坏 JSON四类输入下行为可区分；
  - 单次接口每次最多产生一次物理请求；
  - 使用假外部客户端证明 32,000 输出上限到达 SDK；
  - 用量事件不保存模型正文，但可观察停止原因、截断标记、字符数和哈希；
  - 受影响后端测试和 `tools/smoke_check.py --skip-tests` 通过。
- **风险等级：** 中高。该路径涉及外部费用、失败恢复和配置发布；错误实现可能增加请求次数、误发布半成品或把普通格式错误误报为截断。

## 集中调查与故障场景

已冻结三个根因：

1. 单请求接口写入 `omit_token_limit=True`，线路可能采用较小的默认输出上限；
2. Gateway 只保存 token 用量，没有保留 `finish_reason` 和安全的输出摘要；
3. JSON 解析错误只保留前 3,000 字符，调用方无法可靠区分长度截断和普通格式错误。

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 每次用户提交仍是独立的一次请求；本修复不自动重放。 |
| 同时操作 | 继续由现有配置生成 Job 锁裁决；本修复不改变并发语义。 |
| 中途退出 | 现有 Job 失败/恢复规则不变；不发布半成品。 |
| 重新启动 | 已失败 Job 保留安全错误；用户明确选择后才能新建请求。 |
| 失败重试 | 不自动重试；逐题/分批或整卷重试都由用户明确触发。 |
| 取消 | 现有取消语义不变。 |
| 部分完成 | 长度截断视为整体失败，任何可解析前缀都不发布。 |
| 数据缺失或冲突 | 普通坏 JSON 继续按格式错误处理，不伪装为长度截断。 |
