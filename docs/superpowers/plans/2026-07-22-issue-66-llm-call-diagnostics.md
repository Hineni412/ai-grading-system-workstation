# Issue #66 统一模型调用诊断日志即时计划

**Issue：** #66
**基线：** cf31ba35c608a48d5b379e1316a51e7cfbf62601
**分支：** codex/issue-66-llm-call-diagnostics
**风险等级：** 高

## 目标

在不改变任何模型业务行为的前提下，为统一 `LLMGateway` 的每一次物理出站请求写入严格脱敏、可关联的开始与终态 JSONL 事件，使配置生成、完整/混合批改、识别/OCR 和题库 AI 标注自动获得足够的本地诊断证据。

## 包含

- 新建独立 `logs/llm_api_calls.jsonl`，不复用现有 token 用量文件，避免开始事件被误算成额外请求。
- 每个物理尝试在 SDK 调用前写 `request_started`，成功后写 `request_succeeded`，异常后写 `request_failed`。
- 同一逻辑请求共用脱敏请求 ID，物理尝试号单调递增；每个终态记录是否还会重试及计划等待。
- 开始事件记录：UTC 时间、请求类型、协议、脱敏模型、仅主机名的端点、最终 timeout、重试上限、节流等待、文本字符数、图片数、图片估算字节和总请求估算字节。
- 终态记录：UTC 时间、SDK 等待耗时、结果、可取得的 HTTP 状态、安全异常类型与网络阶段、供应商请求 ID（只接受安全字符）、token、停止原因、响应字符/估算字节/摘要、实际模型，以及是否重试。
- 独立 sink 只序列化冻结 dataclass 的白名单字段；并发线程追加时保持一行一个完整 JSON。
- 增加静态边界守卫，禁止第一方代码在统一 Gateway 外新增 Chat Completions 或 Responses SDK 物理调用。
- 更新架构事实和 Index 证据。

## 明确不包含

- 不改变 Base URL、模型、提示词、评分、解析、JSON 修复、超时、重试、并发、费用闸门、API 响应或数据库 Schema。
- 不执行真实模型请求、健康检查或网络诊断，不恢复 P2-20 剩余两次额度。
- 不读取或写入真实 `user_data/`。
- 不记录 API Key、Authorization/header、完整 URL、提示词、题目、答案、学生姓名/学号、图片/base64、请求体、响应正文、原始异常文本、traceback 或内部绝对路径。
- 不修改各业务页面或在每个调用方重复埋点；统一入口能覆盖的路径不做散点日志。
- 不清理现有历史用量日志；相关既有隐私问题若需处理，单独登记，不扩大本 Issue。

## 公共测试 seam

1. `LLMGateway` 的可替换 trace sink：调用者能观察每个物理尝试的一条开始事件和一条成功/失败终态事件；事件顺序、关联、重试事实和调用结果可验证。
2. 独立 JSONL trace sink：临时文件中每行是完整 JSON，字段集合严格固定，并发写入不产生半行；任何敏感样本文本均不落盘。
3. `LLMProtocolAdapter`：只把脱敏端点主机和独立 trace sink 注入 Gateway，原请求参数、客户端和返回值保持不变。
4. 第一方 SDK 边界：静态测试只允许 `backend/llm/gateway.py` 发起两种物理 SDK `.create`。

## 故障场景

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 日志本身不触发请求；每个真实物理尝试只产生一组开始/终态事件。 |
| 同时操作 | 线程并发追加后仍是一行一个完整 JSON；事件用请求 ID 与尝试号区分。 |
| 中途退出 | 允许留下没有终态的开始事件，作为“进程在途退出”证据；不得自动补发。 |
| 重新启动 | 继续追加同一文件，不覆盖已有事件；新逻辑请求使用新 ID。 |
| 失败重试 | 失败终态先记录 `will_retry` 和计划等待，再按原策略重试；重试次数不因日志改变。 |
| 取消 | Gateway 未承诺主动中断 SDK；若进程被终止，只有开始事件，后续不得根据日志自动重放。 |
| 部分完成 | trace 写入、字段提取或 warning handler 失败均不能改变原调用的返回值、异常和重试。 |
| 数据缺失 | 无法安全取得的字段使用空值或零值，不调用 `repr`/`str(error)` 保存原对象。 |
| 数据冲突 | 不信任供应商未知文本；模型、请求 ID、主机、异常类型和供应商 ID均按严格字符/长度规则处理。 |

## 验收条件

- 所有现有第一方物理模型请求经统一 Gateway 自动覆盖。
- 每次正常物理尝试可在独立 JSONL 中关联开始和终态；进程中途结束时可识别“只有开始事件”。
- P2-20 类超时至少能从本地看到：发出 UTC 时间、主机、模型、最终 600 秒 timeout、请求规模、SDK 等待、`ReadTimeout`/read 阶段、0 HTTP 状态、0 响应字节、是否重试。
- 日志不包含任何冻结禁止内容；sink 或字段提取失败不改变业务行为。
- 假客户端聚焦测试、受影响回归、快速冒烟和同一冻结 SHA 双路复审通过；真实模型调用 0、真实 `user_data/` 未触碰。
