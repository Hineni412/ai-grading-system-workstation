# Issue #63 配置小批次生成与本地 JSON 修复

**状态：** milestone_integrated
**基线：** `25b114e83dd73000df8fcdec0442a3db0b5d4bbc`
**关联：** GitHub Issue #63、P2-20 正式验收发现的独立功能修复

## 冻结边界

- **目标：** 取消整卷单请求和逐题多请求，改为按顺序小批次生成；先在本地修复可确定的 JSON 结构错误，只为仍失败的完整批次保留手动重试，从而避免重复支付成功内容的费用。
- **包含：**
  - 新生成固定使用 `batched` 模式，默认每批 3 题并串行执行；
  - 每批每次显式提交最多一次物理模型请求，不自动重试 502、超时或格式错误；
  - 本地修复仅处理无需猜测业务内容的 JSON 标点、转义和尾逗号，再以严格题号及评分结构校验决定批次成败；
  - 成功批次即时写入私有草稿；重试只能选择一个或多个完整失败批次，已成功批次不得再次请求；
  - 全部题目完成后使用本地确定性程序统一归一化到 100 分，不再发起 AI 赋分请求；
  - API/Job、Vue 配置页及 Streamlit 当前生产界面统一展示批次进度、本地修复结果和失败批次恢复入口；
  - 成功全集才允许发布并绑定配置，部分结果继续保持私有。
- **明确不包含：**
  - 猜测、生成或补写答案、评分点、题目等业务内容；
  - 自动续写、自动重试、后台补请求或真实模型调用；
  - 改变批改模型、题库、评分结果、数据库 Schema 或真实 `user_data/`；
  - 把历史整卷失败 Job 自动转换为新批次 Job。
- **验收条件：**
  - 12 题初次生成恰好 4 次模型请求，无额外 AI 修复或 AI 赋分请求；
  - 可安全修复的 JSON 在本地成功解析且不产生第二次模型请求，修复记录不包含模型正文；
  - 单个失败批次的手动重试只增加 1 次请求，成功批次保持字节级业务内容不变；
  - 取消或进程中断后从最后一个已落盘批次恢复，未确认完成的在途批次不视为成功；
  - API/Job、Vue、Streamlit 受影响测试、浏览器验收和快速冒烟通过。
- **风险等级：** 高。该改动涉及外部费用、重试、部分持久化、取消/重启恢复、配置原子发布和两个用户界面。

## 集中调查与根因

问题清单冻结为四个直接根因：

1. 整卷单请求一旦局部 JSON 损坏只能整卷重跑，成功生成的绝大部分内容也会重复计费；
2. 旧逐题路径按题并发，并对瞬时错误透明重试，用户无法预先知道实际请求数；
3. 旧逐题路径在所有题目完成后还会追加一次 AI 总分分配请求；
4. 现有 JSON 解析只处理代码围栏、对象截取和尾逗号，缺少严格受限的本地结构修复与批次级持久化。

## 故障场景与预期

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 沿用请求令牌幂等；同一令牌不创建第二个模型任务。 |
| 同时操作 | 沿用会话配置锁；一个会话最多一个活动生成/重试任务。 |
| 中途退出 | 每个成功批次立即原子写草稿；未落盘的在途批次按失败处理。 |
| 重新启动 | 只从草稿中已确认成功的批次恢复，其他批次等待用户明确重试。 |
| 失败重试 | 仅接受失败批次的完整题号集合；部分选择、成功题号或未知题号均拒绝。 |
| 取消 | 当前请求返回后先落盘，不启动下一批；未完成批次可手动恢复。 |
| 部分完成 | 不发布、不绑定、不覆盖现有评分标准；用户可查看失败批次并继续。 |
| 数据缺失或冲突 | 缺题、重复题、额外题、题号错配或评分结构不完整均拒绝该批，不做语义猜测。 |

## 模块接口与测试策略

- 批次编排对 Job 层暴露一个窄接口：输入已确认题块、已有草稿和可选失败批次，逐批产生可原子保存的检查点，最终返回合并结果。
- 本地 JSON 修复对调用方只暴露“严格解析 + 修复报告”；报告只含操作名、字符数和摘要，不含模型正文。
- TDD 公开 seam：配置生成 Job/API、配置页可见行为；外部模型只在 LLM Client 边界使用假客户端。
- RED→GREEN 顺序：请求次数与本地修复 → 批次校验/合并 → 失败批次重试与检查点 → 取消/重启 → Vue/Streamlit。
- 稳定候选冻结后，同一 SHA 进行需求符合性与代码质量双路复审；若有阻塞意见，只统一修复一次并限定终审。
