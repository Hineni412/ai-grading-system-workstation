## Objective

在不修改原始业务数据、数据库 Schema、评分规则、API 契约、生产启动入口或 P2-09 至 P2-19 产品行为的前提下，以用户明确指定的一场考试为来源，先备份并在系统临时目录制作隔离副本，再通过新 Vue UI 完成“建会话 → 生成配置 → 确认模板与答题区 → 批改 → 复核调分 → 导出报告”全链路；同时验证刷新/重启恢复、失败恢复、五档桌面视口、浏览器控制台、性能和数据库/文件一致性，形成绑定精确已复审 SHA 的正式用户验收清单。

## Frozen Boundary

- **目标：** 证明 P2-09 至 P2-19 组合后的新 UI 能在授权考试副本上完成真实五流程，业务结果、数据语义和安全边界与当前业务事实来源一致。
- **包含：** 授权记录；源数据只读指纹；可恢复备份；系统临时目录中的隔离代码与数据副本；明确考试选择；Vue + 真实 FastAPI/Job/数据库/文件链路；浏览器控制台与网络错误；关键阶段耗时；1920×1080、1440×900、1366×768、1280×800、1024×768 五档视口；配置、模板/区域、扫描/批改、复核调分、报告下载；刷新、API 进程重启和受控失败恢复；副本内数据库/文件一致性报告；正式清单与截图证据。
- **明确不包含：** 原始 `user_data/` 写入、删除、移动、暂存、提交或 stash；未明确授权的考试；未明确授权的真实模型调用或费用；生产 UI 切换；Streamlit 删除；数据库迁移或 Schema 修改；评分、OCR、匹配、统计、推荐、导出格式等业务规则修改；P2-09 至 P2-19 现场功能修复；P2-21 启动切换；移动端/平板支持。
- **验收条件：** STYLE 视觉检查和业务能力/UX 溯源均通过；五档桌面视口无意外横向溢出或关键内容重叠；浏览器控制台无未解释错误；关键阶段刷新与 API 重启后状态可恢复；失败状态说明与实际落盘一致；最终教师分、会话进度、数据库记录、报告内容和受控文件相互一致；原始数据指纹始终不变；正式清单 Blocker/Major 清零且用户对绑定 SHA 明确标记 `passed`。
- **风险等级：** 高。本包跨越配置、文件复制、长 Job、模型费用、评分写入、刷新/重启恢复和报告导出；隔离失败可能污染原始数据，重复提交可能产生额外费用或重复结果，错误的一致性结论可能掩盖数据错乱。

## Public Test Seams

测试只观察以下公共边界，不绑定 Vue 私有组件、内部函数或数据库实现调用次数：

1. P2-20 验收启动器：只接受精确源码 SHA、系统临时工作目录、明确数据来源和授权考试标识；准备、校验、启动、停止、清理均 fail closed。
2. 新 Vue UI 公共路由：`/sessions`、`/sessions/:id/regions`、`/sessions/:id/grading-run`、`/grading`、`/files` 以及贯穿流程所需的工作台上下文。
3. 真实 FastAPI/Job/File 公共接口：通过浏览器发起并查询配置、模板/区域、扫描/批改、复核和报告任务；不从内部服务旁路触发业务动作。
4. 副本持久化证据：允许只读核对副本 SQLite 和副本文件，验证公开结果确已落盘；不得用直接数据库写入替代 UI 动作。
5. 原始数据守卫：准备前后及每个高风险阶段只读比较源两库和授权源文件指纹；任何变化立即停止。
6. 真实 Chromium：按页面可见操作执行主链、刷新/重启、错误恢复、控制台、下载与五档视口检查，证据只保存到忽略的 `output/playwright/p2-20/`。

用户启动正式 P2-20 即确认以上公开 seam 作为本包测试边界；具体考试和真实模型费用仍需分别明确授权后才能实际使用。

## Central Investigation Findings

编码前问题清单已去重并冻结为六个根因组：

1. **来源授权与隔离：** 正式包要求指定考试副本，现有 P1-29 启动器只支持匿名合成数据，不能直接承担真实考试副本；P2-19 浏览器工具也只允许固定临时空数据根。
2. **组合链路：** P1-28 已证明真实 API/Job/临时持久化五流程，但不是新 UI；P2-09 至 P2-19 各包已有局部浏览器证据，尚无同一考试、同一数据根的组合 UI 证据。
3. **外部费用：** 配置生成和真实批改可能调用外部模型；必须在提交前取得费用授权、记录请求范围并阻止重复提交。
4. **刷新与重启：** Job Store 只恢复当前浏览器记录的任务；验收必须在配置、批改和报告阶段分别验证刷新，并至少验证一次 API 进程重启后的可解释终态。
5. **一致性证据：** 公开 UI 结果必须与副本数据库、配置/快照、扫描结果和报告文件相互核对；不能只凭页面成功提示判定通过。
6. **正式用户结论：** 自动化与独立复审只能生成候选清单，P2-20 仍须用户在绑定 SHA 上完成 60–90 分钟正式清单并明确标记 `passed`。

调查中未发现需要改变产品需求的未决方案；唯一必须由用户决定的是授权考试和真实模型费用范围。其他实现细节采用最保守的 fail-closed 方案。

## Failure Scenarios

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 已健康的同一服务再次 `start` 只返回现有状态，不再创建进程；浏览器提交后锁定，配置、批改和导出不因刷新或自动化重试而重复提交。 |
| 同时操作 | 启动前检查端口与原子状态文件；已有启动中、健康或陈旧状态时拒绝第二次创建。第二个标签页只能观察，后端业务锁仍负责裁决同会话并发。 |
| 中途退出 | `start` 在创建子进程后立即登记 PID/端口；调用方退出后服务仍可由 `status` 观察和 `stop` 收口。原始数据不变，任何有费用动作不自动执行。 |
| 重新启动 | 代码 SHA、授权考试、数据副本和服务状态必须精确匹配；不匹配或状态陈旧时 fail closed，先停止并核对后才能重新启动。 |
| 失败重试 | GET/状态查询可安全重试；写操作先确认旧结果和当前持久化状态，再由用户可见入口明确重试，不复用过期确认或盲目重放。 |
| 取消 | `stop` 只在该副本写入停止请求并等待登记进程真实退出，不根据“端口暂未健康”提前宣称完成，也不强杀其他进程；业务 Job 仍按现有合法阶段取消。 |
| 部分完成 | 扫描/批改部分失败必须显示成功、失败和剩余数量；只使用现有失败项重试或补批入口，已有成功结果不重复写入。 |
| 数据缺失 | 模板、区域、扫描文件、任务记录或报告缺失时停止下游阶段，显示缺失项并保留已有副本证据。 |
| 数据冲突 | revision、批次、配置或答卷归属变化触发 409/422 时保留现场并要求重新加载；不覆盖较新状态。 |
| 源数据变化 | 任一源数据库或授权源文件指纹变化立即停止，标记源数据保护失败；不继续清理或覆盖源文件。 |
| 费用边界不明 | 没有明确金额/范围授权时不调用真实模型；若调用次数或题量超出授权，提交前停止。 |
| 部分复制或磁盘不足 | 临时副本使用完成标记和清单；复制失败的工作区不可启动，原始数据不变，可安全删除未完成临时副本。 |

## Verification Strategy

- **TDD：** 逐个公共 seam 建立 RED → 最小 GREEN；测试验收启动器和安全报告的公共命令/结果，不绑定私有函数。
- **后端：** P1-28 五流程 API E2E 与 P2-09 至 P2-12 直接受影响回归；本包不改生产行为时不重复运行无关后端测试。
- **前端：** `npm run verify` 证明 P2-09 至 P2-19 组合基线；浏览器 CLI 证明同一真实副本主链、控制台、刷新/重启和五档视口。
- **数据：** 原始数据只读指纹贯穿准备、每个高风险阶段和清理；所有写入只发生在系统临时副本。
- **功能分支：** 不运行完整 pytest；稳定候选运行聚焦测试、受影响回归和快速冒烟。P2-20 进入 integration 后完成 M2-03 批次末唯一一次完整门槛。

## Review Rules

本包为高风险正式验收包。稳定候选冻结后使用 `code-review`，让 Spec 与 Standards 两名评审代理检查同一 SHA。全部意见返回后由主代理统一去重、按根因归组并核对来源；只有本次修改直接引入或当前任务遗漏的 `Critical`/`Important` 阻塞。若有阻塞，只统一修复一次并复测受影响范围，再由原评审者做一次限定最终复审；最终复审仍有当前范围内 `Critical`/`Important` 时停止并向用户汇报。产品功能缺陷不在 P2-20 内修复，登记证据后退回对应功能包。
