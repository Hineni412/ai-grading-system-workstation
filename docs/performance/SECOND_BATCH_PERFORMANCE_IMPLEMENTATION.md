# 第二批性能优化实施清单

状态：`implemented_and_reviewed`

起点：第一批本地检查点 `06d56f8d`。

## 1. 核心目标

在不改变题库结果、备课内容、组卷结果、班主任业务规则、页面入口和模块架构的前提下，减少第二批已经确认的磁盘复制、文件解析、后台刷新和整卷重读。

本批只加深现有读取与状态模块：调用页面继续使用原来的小接口，缓存代次、失效、并发和清理由模块内部处理，不建立通用缓存框架。

## 2. 最常用的完整流程

1. 教师打开题库，页面读取试卷、筛选项和题目列表；切换筛选、分页或打开详情后，仍看到同一时点的一致结果，但不再为每个请求重复复制和检查整库、重复解析同一份知识标准。
2. 教师打开备课首页，只先读取教材、学期、课时和课时状态；进入资料库或直接打开课时链接时，再补齐资料、解析任务、目录建议和映射内容。资料解析仍可取消、恢复并显示最终预览，但不再每 350 毫秒查询一次。
3. 教师修改组卷标题、页眉、答案显示或版式并保存；题号没有变化时不再重读整卷题目。教师同时打开班主任多个互不相关的工作面时，当前明文模式不再让所有请求共用一条等待队列。

## 3. 本轮包含

### 3.1 题库知识标准按需加载和复用

- 不需要知识标准的试卷列表、计数、图片和预览路径读取，不再构造知识标准解析器。
- 需要知识标准时，以现有活动发布编号、内容摘要和词表版本作为复用依据；同一不可变发布只完整解析一次。
- 自定义词表调用绕过共享复用；失败结果不缓存，修复后下一次可恢复。

### 3.2 普通题库读取复用同一数据库代次的已验证副本

- 第一个请求仍执行现有主库/WAL 复制、逐字节比较、快速检查和必需表检查。
- 数据库未变化时，后续普通题库请求各自打开独立只读连接，但复用同一份已验证副本。
- 主库、WAL、回滚日志或代次变化后重新捕获；旧请求继续使用自己的稳定副本，最后一个使用者退出后清理旧副本。
- 只修改 `QuestionBankReadService` 的普通读取内部，不改变跨阅卷库/题库的联合读取流程。

### 3.3 当前明文班主任模式取消无关请求的全局排队

- 当前固定明文模式下，互不相关的读取和业务请求不再全部等待旧保险箱总锁。
- 如代码显式进入旧保护模式，原有锁和恢复边界保持不变。
- 同一记录的版本冲突、数据库事务和现有保存结果不变。

### 3.4 备课首页按页面需要读取

- 普通首页不读取全部资料、全部解析任务、学期资料、目录建议和目录任务，预计少 5 次请求。
- 点击资料库、继续备课，或直接打开资料库/课时深链接时，仍在页面结束加载前补齐所需内容。
- 切换学期后不得显示上一个学期的资料或任务。

### 3.5 资料解析刷新降频

- 正常查询从每 350 毫秒一次改为 2 秒起步；连续网络失败时逐步放慢，最长 30 秒。
- 保留取消、重进页面恢复、最终资料集合刷新、预览阶段按明显进度刷新，以及旧请求不能覆盖新选择。
- 不改变实际解析速度，也不自动追加模型或解析任务。

### 3.6 组卷设置保存不重读整卷

- 保存前后题号清单相同，直接使用服务端返回的新草稿和版本号，不重新读取题目。
- 新增、删除、排序题目以及恢复历史草稿仍完整读取。
- 冲突提示、分节、导出和题目顺序保持现状。

## 4. 明确不包含

- 不直接读取正在写入的在线题库来替代只读副本；不跳过第一次副本检查。
- 不共享同一个 SQLite 连接，不使用只按时间过期的缓存，不缓存失败结果或真实业务正文到额外磁盘文件。
- 不修改数据库表、迁移、题库页面既有请求和返回格式，也不修改知识标准发布/回滚规则。
- 不修改 `backend/api/read_connections.py` 的跨库一致读取。
- 不拆分备课 store，不新增页面、接口或任务类型。
- 文件中心最多 103 次请求的问题暂缓；压缩它需要改变后端列表返回内容。
- 成绩明细整张大表暂缓；真正减少渲染量需要分页或只显示当前屏幕，会改变教师查看方式。
- 不删除旧页面、旧 PIN、旧加密库识别或专用备份读取；删除边界只记录在配套清单。
- 不读取、复制、迁移、写入或删除真实 `user_data`，不调用真实模型，不启动或重启正式服务。

## 5. 页面信息、操作层级与现有复用

- 没有新页面、导航或按钮；主要操作和提示文字保持现状。
- 题库继续使用 `QuestionBankReadService` 和 `CurrentKnowledgeResolver`；代次复用隐藏在现有读取模块的实现内。
- 备课继续使用现有 `catalog` store 和原有资料接口；首页、资料库和课时深链接只声明当前需要的数据范围。
- 资料解析借用普通任务已有的“2 秒起步、失败逐步放慢”节奏，但不加入全局任务通知。
- 组卷继续使用现有 assembly store 和保存接口。
- 班主任继续使用现有路由和明文工作库；只让旧保险箱操作范围在明文模式直接放行。

## 6. 最小必要后端行为

- 知识标准复用键只来自现有不可变发布信息；新发布或回滚自然切换结果。
- 两个冷启动题库请求同时到达时，最多发布一份完成检查的副本；每个请求仍有独立连接和事务。
- 写入后下一次新请求必须看见新代次；写入前已经开始的请求保持稳定结果。
- 副本捕获、快速检查或知识标准解析失败时，不得把失败对象放入复用池。
- 明文班主任请求并发后，现有版本号和数据库冲突仍决定同一记录的写入结果。

## 7. 故障场景

- 主库或 WAL 在捕获期间变化，WAL 出现、消失或执行 checkpoint。
- 可见回滚日志、快速检查失败、必需表缺失或临时目录不可用。
- 两个冷启动请求并发，一个请求提前结束或报错，另一个仍在读取。
- 活动知识标准缺失、正文损坏、首次并发解析、启用新发布或回滚旧发布。
- 备课资料接口失败、解析任务连续断网、取消、页面退出和重进、切换资料或学期。
- 组卷保存发生版本冲突，或保存前后题号发生变化。
- 两个班主任请求同时读取，或同时修改同一条带版本号的记录。

## 8. 验收条件

- 同一活动知识发布下，约 5 MB 的发布正文和词表从 N 次完整解析降为 1 次；不需要知识标准的读取为 0 次。
- 数据库未变化时，题库首页常见的试卷、筛选项和题目列表从 3 次整库捕获降为 1 次；返回内容与优化前一致。
- 写入、WAL 变化、发布切换和回滚后，新请求不读取旧结果；旧副本在最后一个使用者退出后清理。
- 普通备课首页少 5 次资料类请求；资料库和课时深链接仍一次进入正确内容。
- 60 秒资料解析的正常状态查询约从 171 次降到约 30 次；失败时继续放慢，取消和恢复正确。
- 只改组卷设置时由“保存 + 整卷读取”降为仅保存；题目变化时仍重读。
- 明文班主任两个互不相关请求可以重叠执行；同一记录冲突规则不变。
- 受影响后端、前端测试、类型检查和生产构建通过；最终需求复审和代码质量复审没有本轮 Critical 或 Important 问题。

## 9. 风险与回退

整体风险：`medium`。

- 知识标准复用、组卷跳过无用读取为低—中风险。
- 备课按需读取、轮询退避和明文请求放行为中风险。
- 已验证题库副本复用为本批最高风险项；并发、WAL、失效和临时文件清理测试是阻塞验收条件。
- 每项均保留现有外部接口；如一致性测试失败，只回退对应模块内部复用，不改为直接读取在线数据库，也不扩大为架构重写。

## 10. 实施结果

- 普通题库读取会按数据库当前版本复用已经检查好的临时副本；试卷、筛选项和题目等不同读取仍各自查询，但数据库未变化时只复制和检查一次。每个请求仍使用独立只读连接。
- 知识标准改为真正用到时才读取；相同发布只完整处理一次。普通试卷、计数和媒体路径读取不再加载知识正文。自定义词表保持独立，失败结果不进入复用。
- 数据库写入、WAL 增长或整理、可见回滚文件、发布切换和回滚都会停止复用旧结果；正在读取的旧副本会在最后一个使用者退出后清理。
- 普通备课首页不再读取 5 类资料内容；资料库和课时深链接在展示前补齐。切换学期只更新该学期的 3 类内容，不重复读取全局资料和全部解析任务。
- 资料解析从每 350 毫秒查询一次改为 2 秒起步；连续网络失败按 2、4、8、16、30 秒逐步放慢。取消、重新进入恢复、完成刷新、预览进度与防旧结果覆盖保持原状。
- 组卷只改标题、页眉、答案显示或版式且题号顺序不变时，不再重读整卷；题号变化、分节调整和恢复历史卷仍完整读取。
- 当前明文班主任模式不再让所有无关请求共用旧总队列；显式启用旧保护模式时仍沿用原队列，同一记录的版本冲突保持不变。
