## 双入口与匿名边界

验收入口只接受可解析的完整 40 位 Git SHA，并在系统临时目录下创建空工作区。归档生成时明确排除任何已被 Git 跟踪的 `user_data`，解包前还会再次拒绝绝对路径、父目录穿越、链接、特殊成员、重复路径和任意大小写的 `user_data` 成员。

便携 Python 的固定模块搜索路径曾导致两个独立复审失败；修复后，seed、Uvicorn 和 Streamlit 共用同一个 staged-only bootstrap：

- 项目模块只能从临时精确 SHA 副本解析；
- 根仓库和功能 worktree 不参与项目模块搜索；
- 配置在任何项目模块来源发现或导入前复核；
- dotted module 来源检查不执行父包 `__init__.py`；
- API profile 与 Ops state 强制指向临时副本；
- 六类敏感 Key 环境变量在项目代码加载前清空；
- Streamlit 明确运行副本内的 `web_app.py`；
- 正常完成、启动失败和中断都会清理子进程树。

最终精确 SHA 的 API `/healthz` 和 Streamlit `/_stcore/health` 均就绪，关闭后端口立即释放。Streamlit 官方页面测试运行器确认三个 API Key 输入为空、页面异常数为 0、只出现两名合成学生及 90%/70% 总分。内置浏览器控制组件本身发生初始化兼容冲突，因此自动可见预检使用 Streamlit 官方页面测试运行器完成；真实 Streamlit 服务启动和健康检查正常，正式用户验收仍在本机浏览器进行。
