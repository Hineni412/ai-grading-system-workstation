## 1. 这条分支要交付什么

B 线要交付一个教师个人使用、默认锁定的班主任日常工作台。它只有一个左侧栏主入口，内部由四个连续的大区承接工作：

1. **行动与日历**：把会议任务、日常想法和最终 DDL 变成可以执行、倒排、等待、复查和完成的行动；
2. **德育事务 SOP**：用动态卡片处理矛盾、疑似欺凌、伤害、家校沟通、关怀谈话和学校活动；
3. **学生支持档案**：保存经教师确认、可修订、会到期的事实、转述、观察、判断和支持结果；
4. **状态与关注**：把多学科学业证据与已有记录变成“值得进一步了解什么”的可解释提示，并重新进入行动日历。

闭环如下：

```text
会议任务/临时想法/事件/成绩证据
          ↓
自然语言收件箱（先生成草稿）
          ↓
正式行动与时间节点
     ↙              ↘
普通任务          SOP复杂事务
     ↓              ↓
等待、沟通、复查、结案
          ↓
只把教师确认的结果写入学生支持档案
          ↓
证据变化产生“值得了解”的关注草稿
          ↓
教师决定跟进/观察/无需处理
          ↓
新的行动和复查日期
```

首版不把每个小功能做成侧边栏入口：

- 回执收集板从某个行动计划下钻；
- 家长群文案和电话大纲从沟通节点下钻；
- 活动分工从活动 SOP 下钻；
- 学生成绩从学生支持页下钻；
- 关注建议从首页和学生页进入；
- 语音只是统一收件箱的一种输入方式。

## 2. 冻结的任务边界

### 2.1 包含

- 模块密码、解锁、自动锁定、加密存储和访问审计；
- 普通备份默认排除和模块专用加密备份；
- 自然语言任务、最终 DDL、倒排计划和沟通草稿；
- 今日、临近、逾期、等待、复查和已完成；
- 回执、材料、报名等收集进度；
- 版本化 SOP、动态卡片、分支、并行步骤、等待和重开；
- 普通矛盾、疑似欺凌、伤害、家校沟通、关怀谈话和学校活动模板；
- 学生支持档案及记录的来源、版本、反例、复核日期和到期；
- 本地或经批准的隐私受控语音草稿；
- 多学科成绩导入与现有数学考情的只读证据适配；
- 可比性判断；
- 状态与关注草稿；
- 教师处置后回到日历；
- 按学生删除及派生数据核对；
- 敏感模型调用的发送预览、最小化、人工确认和零自动重试。

### 2.2 明确不包含

- 固定的学生性格、家庭、人际或心理标签；
- 学生风险分、红黄绿榜和全班排名墙；
- 心理诊断、欺凌认定、惩戒决定或紧急事件裁决；
- AI 自动把推测升级为事实；
- 自动给家长、学生、学校或外部机构发送消息；
- 保存身份证号、家庭住址、家长联系方式保险箱；
- 积分管理系统；
- 家长端、学生端和多人派单；
- 局域网或云端多用户；
- 普通明文导出；
- 把完整档案发送给外部模型；
- 在程序关闭后继续提醒；Windows 托盘或计划任务另行立项；
- 与备课工作台共享数据库、行动表或 AI 长期记忆；
- 自动把个体信息送入备课工作台。

### 2.3 完成定义

使用合成学生和合成事务，教师能完成：

- 一项带 DDL 的会议任务倒排；
- 一项回执收集；
- 一次学生矛盾 SOP 的推进、升级、等待、沟通、结案和重开；
- 一条阶段性观察的记录、反例、修订、到期和支持结果；
- 一份多学科成绩导入；
- 一张关注卡的人工处置；
- 一次锁定、重启、加密备份、恢复和按学生删除。

AI 完全关闭时，以上工作流仍可人工完成。

### 2.4 连续迭代与最终集中验收

B00—B11 是治理、范围、依赖和完成清单，不是逐包代码测试或逐包复审关口。执行时：

1. B00 必须先请用户确认治理、安全和学校口径，因为这些决定会改变 B01 以后的数据设计；这属于产品决策 Gate，不是代码复审；
2. B01—B10 使用合成数据连续实现，每包只更新进度、实现说明和必要的本地检查点；
3. 不在 B01 或其他小包结束时运行正式全套测试、需求复审、代码质量复审或用户验收；
4. 故障阻塞继续实现时，只运行能定位和解除阻塞的最小检查；
5. 各包“测试与验收”“故障与验收”条目累计为 B11 的最终安全验证清单；
6. 整条 B 线进入用户最终验收阶段后，才在 B11 冻结完整候选，集中运行安全回归、B 全套测试、加密/恢复/删除演练、必要构建和跨模块冒烟，并进行一次双复审；
7. 如有阻塞问题，只统一修复一次、复测修复范围并进行一次限定最终复审。

小任务中涉及学生数据范围、安全结果、密码恢复、学校流程、外部模型字段、费用或不可逆操作的不确定性，要及时询问用户。先集中调查并尽量一次列出本轮全部已知问题，每项附推荐方案和影响；如果学校口径、前一轮回答或实际页面效果决定后续问题是否成立，可以说明依赖并分步骤询问。等待回答时只暂停受影响的 B 任务，P4、A 和 B 内其他安全工作继续。

用户已经确认 B 线进入三路并行计划，但业务实现仍不能直接开始。B00 必须先满足 `phase-6-deferred.md` 和届时执行索引规定的治理条件。

- 学生记录的更正、修订、删除和导出规则；
- 普通备份、便携包、日志和 Git 的排除规则；
- 模块专用加密备份与恢复；
- 外部模型供应商、允许发送的资料类型和人工确认；
- 学校的报告链、联系人角色、时限和 SOP 口径；

## 5. 模块内部设计

### 5.1 深模块边界

```text
VaultService
  初始化、解锁、锁定、改密、自动锁定、加密备份和恢复

ActionLedgerService
  所有正式行动、依赖、DDL、等待、复查和完成的唯一来源

PlanningService
  把自然语言变成待确认行动草稿；本地完成日期计算

AffairWorkflowService
  运行冻结版本的SOP；步骤通过action_id引用行动账本

StudentSupportService
  保存经确认且可追溯、可到期、可删除的学生支持记录

AcademicEvidenceService
  导入多学科成绩并读取现有数学证据，生成不可变证据快照

AttentionService
  根据证据生成“值得了解”的草稿，教师处置后创建行动

SecureExportService
  执行受控备份、恢复、按学生删除和零残留核对
```

前端、模型和语音识别都不能直接写正式记录；必须经过对应服务的确认命令。

### 5.2 统一“草稿—确认”规则

以下内容始终先是草稿：

- AI 拆解的任务；
- 倒排计划；
- 家长群文案；
- 电话沟通大纲；
- SOP 分支建议；
- 语音解析结果；
- 学生观察摘要；
- 状态关注建议。

只有教师确认后，才能：

- 创建正式行动；
- 推进 SOP；
- 写入学生时间线；
- 保存教师判断；
- 生成跟进或复查日期。

AI 草稿不能成为行政事实、专业结论或已完成证据。

### 5.3 核心对象

| 对象 | 作用 |
|---|---|
| `VaultMetadata` | 加密方案、密钥包、版本和锁定策略 |
| `VaultSession` | 内存中的短期解锁会话 |
| `WorkPlan` | 一项目标及其行动集合 |
| `ActionItem` | 行动账本中的唯一正式行动 |
| `Reminder` | 应用打开时的提醒与复查 |
| `CommunicationDraft` | 尚未发送的群文案、个别提醒或电话大纲 |
| `CollectionBoard` | 回执、报名、材料等收集视图 |
| `SopTemplateVersion` | 已冻结的流程模板 |
| `AffairCase` | 一件事务 |
| `StepInstance` | 当前事务中的步骤 |
| `DecisionRecord` | 教师或学校作出的分支决定 |
| `StudentSubjectRef` | 与现有学生身份的松耦合引用 |
| `SupportRecord` | 事实、转述、观察、判断、专业结论或支持结果 |
| `ObservationRevision` | 阶段性观察、反例、复核和到期 |
| `SupportPlan` | 已确认的支持行动 |
| `AssessmentEvidence` | 成绩与排名语境的不可变证据 |
| `AttentionDraft` | 尚未确认的关注建议 |
| `TeacherDisposition` | 跟进、暂时观察或无需处理 |
| `AuditEvent` | 不含正文的访问与高影响操作记录 |

### 5.4 行动状态

```text
pending
in_progress
waiting
partially_completed
completed
cancelled
superseded
```

`waiting` 和“暂时观察”必须有下次检查日期。已完成行动可以重开，但不覆盖原完成历史。

### 5.5 学生记录的知识类型

每条学生记录必须明确属于：

- 已核实事实；
- 学生自述；
- 他人转述；
- 教师观察；
- 教师阶段性判断；
- 有来源的专业结论；
- AI 草稿；
- 支持行动；
- 支持结果。

类型之间不能由 AI 自动转换。教师观察与判断必须有日期、场景、依据、反例、复核日期和状态；到期后退出“当前摘要”，历史仍可追溯。

## 6. 加密、解锁和模型总规则

### 6.1 推荐加密决策

B00 必须只选择一种生产方案，不能长期维护两套：

1. 优先验证兼容当前便携 Windows 运行环境的整库加密方案；
2. 若整库加密不可用，再评估“随机数据密钥 + 高成本密码派生 + 字段级认证加密”的信封加密；
3. 修改密码只重新包裹数据密钥，不逐条解密重写全部正文；
4. 密钥只在解锁会话内存中存在；
5. 密码不以明文或可逆形式保存；
6. 锁定、超时或应用重启后旧会话立即失效；
7. 不得以“页面输入密码”代替真正的数据加密。

若最终只能做到字段级加密，B00 必须明确哪些元数据仍可见；学生姓名、事务正文、观察、成绩和 AI 草稿均不得明文保存。

### 6.2 Web 和缓存

- 受保护 API 默认 `Cache-Control: no-store`；
- 解锁 token 只用于 B 模块，不复用全应用永久令牌；
- 前端锁定时清空 Pinia、内存草稿、预览和浏览器历史可见内容；
- 页面刷新或应用重启后回到锁定态；
- 限制来源、CORS 和请求头，降低恶意网页访问本地 API 的风险；
- 错误响应不返回正文、密钥、路径或学生姓名；
- 访问审计记录时间、动作、内部对象 ID、结果和错误类别，不记录正文。

### 6.3 模型

- 使用 F0 的工作台安全模型入口；
- `allow_retry=False`；
- 使用不保存请求/响应正文的诊断器；
- 调用前展示匿名化后的实际发送内容；
- 教师确认后才产生一次物理调用；
- 重复点击使用 operation ID，不再次付费；
- 外部模型不接收完整学生档案、其他学生资料、联系方式或原始语音；
- 供应商、模型、用途、用量和错误类别可以审计，正文不能进入普通日志；
- 模型关闭或失败不阻断人工工作流。

## 8. B00：治理、威胁模型与重启批准

### 8.1 性质

B00 是唯一合法起点，只产出治理和安全规格，不写业务代码、不建库、不加页面。

### 8.2 必须产出

- 数据字段—用途—依据—保留期—复核期矩阵；
- 明确的禁止字段；
- 学生和事务记录的更正、修订、到期和删除规则；
- 毕业、转班、误建记录和身份冲突规则；
- 访问者、解锁、自动锁定和密码失败规则；
- 加密方案与便携运行环境验证计划；
- 密码遗忘和恢复密钥策略；
- 普通备份/恢复/便携包/Git/日志排除清单；
- 专用加密备份与恢复演练；
- 模型供应商、允许字段、禁止字段、发送预览和费用规则；

- 重复文件不生成第二份证据；
- 导入取消或退出不留下正式半成品；
- 原始成绩文件确认或取消后按治理规则清理；
- 现有数学适配器只读；
- 数学考试归档后旧证据快照仍有来源说明；
- 每个趋势带比较口径和局限。

## 18. B10：状态与关注闭环

### 18.1 目标

系统只提示“哪些变化值得教师进一步了解”，不评价学生是什么样的人，也不自动决定干预。

### 18.2 关注卡固定结构

- 已观察事实；
- 证据来源；
- 可比性与局限；
- 需要核实的问题；
- 低风险下一步建议；
- 证据充分程度；
- 复查建议。

教师只能选择：

- 需要跟进；
- 暂时观察，并设置复查日期；
- 无需处理，并记录原因。

前两项进入 B02 行动账本；第三项保留教师决定但不创建任务。

### 18.3 规则

- 先由本地规则判断证据是否可用；
- AI 只解释教师选中的匿名证据；
- 成绩下降最多生成“建议了解近期情况”；
- 学业变化不能自动写成心理状态；
- 单次成绩波动不能生成稳定结论；
- 证据修订或删除使旧关注草稿失效；
- 不展示全班风险榜；
- AI 关闭后教师仍可查看证据并手工创建跟进。

### 18.4 故障与验收

- 同一证据重复生成；
- AI 超时、坏 JSON 或取消；
- 证据在生成后修订；
- 教师处置响应丢失；
- 暂时观察未填日期；
- 已删除学生仍残留关注；
- 同一变化在首页和学生页出现两份正式行动。

完成门槛：每句建议可回到具体证据；没有学生风险分；跟进只创建一份行动。

## 19. B11：安全收口、恢复、删除、复审与人工验收

B11 是整条 B 线唯一的正式测试、正式复审和最终人工验收阶段；B01—B10 累积的验证条目都在这里集中兑现。

### 19.1 稳定候选检查

- B00 的治理决定均已实现或明确排除；
- 所有迁移只属于 B；
- 仅使用合成学生和事务；
- 模块锁定、解锁、自动锁定和缓存清除通过；
- 数据库、WAL、临时文件、备份、日志和错误响应中无合成敏感明文；
- 普通备份、便携包和普通导出不含受保护目录；
- 专用加密备份与恢复通过；
- 按学生删除覆盖正文、摘要、草稿、关注、语音临时物和派生数据；
- Fake 模型覆盖成功、失败、取消、超时和重复；
- AI 物理请求次数准确；
- SOP 高风险分支不能绕过；
- 前端类型检查、模块测试和构建通过；
- 模块禁用时已有系统和 A 冒烟通过。

### 19.2 故障演练

统一演练：

- 重复操作；
- 两页同时修改；
- 写入中途退出；
- 应用重启；
- 失败后教师重试；
- 教师取消；
- 只完成一部分；
- 数据缺失；
- 证据互相冲突；
- 模型不可用；
- 模板升级；
- 锁定发生在编辑、录音或导入中；
- 备份损坏和恢复失败；
- 删除中途退出；
- 普通导出尝试带走受保护数据库。

### 19.3 正式复审

B 属于高风险。冻结同一个候选提交后，并行进行：

1. 需求符合性复审：重点核对治理、SOP、安全和学生记录边界；
2. 代码质量复审：重点检查加密、密钥、日志、缓存、并发、恢复、删除和模型次数。

等待全部意见后统一去重。只有本次引入或任务遗漏的 `Critical`、`Important` 阻塞；统一修复一次，复测受影响范围，再做一次限定最终复审。最终复审仍有阻塞问题时停止并请用户决定，不自动开启第三轮。

### 19.4 用户人工验收脚本

全部先用匿名学生 A、B：

1. 初始化保险箱、锁定、解锁和重启；
2. 输入“下周五收齐回执并报年级”，检查最晚行动和群文案；
3. 让一位家长未回复，进入等待和复查；
4. 创建普通矛盾 SOP；
5. 新信息出现后转疑似欺凌核查并完成学校交接；
6. 生成不泄露另一学生的家长电话大纲；
7. 结案并在新情况出现后重开；
8. 记录一条阶段性观察、反例、修订和到期；
9. 用文本或本地语音生成草稿并逐条确认；
10. 导入合成多科成绩，处理同名、0 分、缺考和补考；
11. 审核一张关注卡并创建复查行动；
12. 自动锁定后检查页面和浏览器后退；
13. 创建专用加密备份并恢复；
14. 删除匿名学生 A，核对所有派生数据零残留；
15. 确认普通备份中不存在 B 数据；
16. 关闭模型后重复一项完整工作流。

### 19.5 真实数据关口

合成数据验收通过不等于可以直接导入真实学生。真实试点前仍需：

- 用户重新指定精确学生范围、数据类型和用途；
- 确认当前备份和回退；
- 明确模型保持关闭或本次允许的供应商与字段；
- 从最小范围、只读或可删除试点开始；
- 验证结束执行清理和删除核对；
- 不把真实数据、日志或备份提交 Git。

### 19.6 合并关口

B 在冻结前必须合并最新 `main`，运行 B 全部检查，并对当时已经合入的 P4、A 做启动、导航和只读边界冒烟。只有用户明确表示 B 验收通过，才可以申请 push、PR 和合并。

## 20. 整条 B 线故障场景总表

| 类别 | 必须验证的结果 |
|---|---|
| 重复操作 | request token 返回同一行动、事务、模型草稿或导入 |
| 同时操作 | revision 冲突，不覆盖另一页的确认结果 |
| 中途退出 | 事务回滚；临时材料可识别；正式历史不变 |
| 重新启动 | 模块保持锁定；运行状态可恢复或安全收口 |
| 失败重试 | 教师显式触发；模型绝不自动追加收费调用 |
| 取消 | 未确认草稿不进入正式行动、SOP或档案 |
| 部分完成 | 如实显示等待/部分完成，不伪装结案 |
| 数据缺失 | 显示未知并提出核实，不由 AI 补造 |
| 数据冲突 | 并列保留来源和反例，由教师判断 |
| 密钥错误/遗失 | 按 B00 冻结规则恢复或明确不可恢复 |
| 自动锁定 | 敏感缓存清空，未提交草稿按明确规则处理 |
| 备份失败 | 当前数据库不受影响 |
| 恢复失败 | 旧库保持可用，不半覆盖 |
| 删除失败 | 返回未完成清单并阻止宣称删除成功 |
| 模型泄露风险 | 调用前预览；敏感字段阻断；正文不写日志 |
| 程序关闭 | 不声称仍会提醒；首版在重新打开后补提示 |
