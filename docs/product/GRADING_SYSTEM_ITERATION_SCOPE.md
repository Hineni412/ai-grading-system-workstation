# 阅卷系统迭代分支边界与交付规则

## 1. 分支身份

- 分支：`codex/grading-system-iteration`
- 工作区：`.worktrees/grading-system-iteration`
- 共同起点：`e63136c6c5471f358cfaf11065f5b92b0f46ca10`
- 业务线：阅卷系统（含题库、知识图谱与 P4 个性化训练闭环）
- 风险等级：**高**

本文件是该分支后续 Codex 与开发者的范围约束。它规定本线可以改什么、不得改什么，以及形成完整候选后的统一验收方式。若与用户当前明确指令或仓库根目录 `AGENTS.md` 冲突，以后两者为准。

## 2. 目标

在不改变普通考试核心语义、不越界修改备课工作台或班主任工作台的前提下，持续优化阅卷系统的前端体验和端到端功能，覆盖考试配置、学生、模板、扫描、批改、复核、报告、题库、知识图谱以及 P4 个性化训练闭环。

本线采用快速连续迭代：开发阶段集中调查、成批实现和最小必要检查；整条业务线形成完整候选后，再集中做足一次测试、构建、跨模块冒烟和正式复审。快速迭代不等于不测试，也不降低合并前的质量门槛。

## 3. 包含范围

### 3.1 业务能力

- 普通考试配置、会话与学生名单管理。
- 答题卡模板、题目与答题区域配置。
- 扫描导入、答卷归属、批改任务、自动与人工批改协作。
- 教师复核、评分证据、最终分锁、异常处理与结果修正。
- 普通考试成绩、排名、统计和报告生成与展示。
- 题库导入、题目治理、标签体系、题目组卷与文档输出。
- 知识图谱关系治理、掌握度 v2、相关审核与对比能力。
- P4 个性化训练：训练判定点、推荐草稿、一人一卷、训练答卷归卷、训练判定和证据回流。
- 上述能力直接需要的前端页面、组件、状态管理、API、后端服务、作业、数据访问、迁移定义、测试和产品说明。

### 3.2 主要拥有目录与文件区域

下列区域仅按“与阅卷系统或 P4 直接相关”的文件拥有，不代表可以无条件修改整个父目录：

- `question_bank/`：题库、标签、知识关系、掌握度、训练判定与训练输出等本线实现。
- `backend/config_workspace/`、`backend/scan_grading/`、`backend/training_assessment/`：本线配置、扫描批改和训练判定能力。
- `backend/api/routers/`、`backend/api/schemas/` 及其他后端公共父目录中，只属于考试、学生、模板、扫描、批改、复核、报告、题库、图谱或训练的文件。
- `migrations/grading/`、`migrations/question_bank/`：本线数据库迁移定义。创建或修改迁移定义属于开发范围；对真实数据库执行迁移不自动获得授权。
- `frontend/src/` 中只服务于本线的页面、组件、状态仓库、API 封装、类型和路由子模块。
- `tests/` 与 `frontend/src/__tests__/` 中只验证本线行为的测试。
- 本线专属的产品、设计和验收文档。

遇到归属不清的文件，先依据 `docs/product/TEACHER_WORKSPACES_PARALLEL_IMPLEMENTATION.md` 和当前源码调查。不得仅凭父目录名称认定所有权。

## 4. 明确不包含

- 不实现或顺带优化备课工作台 A 的课时树、资料定位、备课草稿、课件改编、WPS 副本和上课包业务。
- 不实现或顺带优化班主任工作台 B 的工作图、日历、SOP、学生档案、沟通记录、加密、恢复和删除业务。
- 不修改 `backend/teaching_prep/`、`migrations/teaching_prep/`、备课工作台前端专属目录及其专属测试或文档。
- 不修改班主任工作台、`migrations/class_teacher_work/`、`migrations/student_affairs/`、学生事务前端专属目录及其专属测试或文档。
- 不直接读取、写入、迁移、复制、清理或修复 A/B 的数据库、文件和业务数据。
- 不借本线迭代重构全局导航、应用启动、公共任务框架、模块注册、模型策略、备份机制、依赖锁文件或其他公共热点。
- 不自动扩大到集中调查后冻结的问题清单之外；修改前已存在或相邻范围的问题单独记录为后续任务。

## 5. 跨业务线与公共热点规则

### 5.1 A/B 只读接口

- 本线可以维护供 A/B 使用的、已经批准的稳定只读接口，并优先保持向后兼容。
- 本线不读取 A/B 的业务数据、数据库或内部文件。若未来出现确需组合展示的产品需求，应作为三线独立合入后的跨模块整合任务，由用户另行冻结范围；不得在本分支内临时建立依赖。
- 只读接口不允许借调用产生 A/B 写入、状态推进、外发、删除或隐式副作用。
- 需要改变 A/B 数据契约、写入行为或产品语义时，停止该部分并另立任务，由用户决定边界。

### 5.2 公共热点

全局导航与路由入口、应用启动、模块 manifest/feature、公共作业和迁移入口、工作台注册与契约、模型安全策略、普通备份规则、公共依赖与锁文件，以及全局架构/执行索引均视为公共热点。

本线不得分别给公共热点打业务补丁。确有必要时，应提出一个边界明确的短期地基修正，从稳定 `main` 建立独立分支，集中验证并合入；之后本线再同步新的共同起点。

## 6. 不可改变的业务语义

- 普通考试的分数含义、计分规则和总分口径保持不变。
- 普通考试的排名口径和展示含义保持不变。
- 普通考试报告的数据来源、结论含义和可追溯性保持不变。
- 教师仍是最终评分责任人；教师最终分锁的权限、约束和最终性不得被自动任务或训练流程绕过。
- P4 训练判定点不带分值，结果表达为“达成点数 / 总判定点数”；不得把训练结果偷换成普通考试分数、排名或最终成绩。
- P4 的推荐、判定和回流不得反向改变已经锁定的普通考试最终分。

任何可能改变上述语义的方案都不属于普通迭代，必须先暂停并请用户明确决定。

## 7. 开发前集中调查与边界冻结

编码前在本线直接影响范围内完成一次集中调查，并记录：

- 本次迭代目标；
- 包含内容；
- 明确不包含内容；
- 验收条件；
- 风险等级；
- 已发现问题，按根因去重后的冻结清单；
- 下列故障场景及其预期结果。

调查结束后冻结问题清单。同一根因或直接相关的问题放在一个修改批次中处理；新发现的修改前问题、相邻范围问题或新需求单独记录，不自动扩张当前批次。

## 8. 必须覆盖的故障场景

本线涉及状态一致性、并发、重试、文件处理与可能产生费用的外部能力，至少要对下列场景给出设计结果，并在完整候选阶段用相应测试或运行证据验证：

| 场景 | 预期结果 |
| --- | --- |
| 重复操作 | 相同请求、答卷、作业或回调不得造成重复批改、重复归卷、重复回流、重复产物或重复费用；使用稳定幂等标识并返回可理解的已有结果。 |
| 同时操作 | 并发批改、复核、锁分、归卷或发布不得互相覆盖；必须串行化、版本校验或明确拒绝冲突。 |
| 中途退出 | 已持久化进度可识别，未完成结果不冒充成功，不发布半成品，不丢失原始证据。 |
| 重新启动 | 服务重启后能从持久状态恢复、重试或安全停留待处理；不得仅依赖内存状态。 |
| 失败重试 | 重试遵守同一幂等键和次数/退避规则；已经成功的步骤不重复执行，外部调用不得无界追加费用。 |
| 取消 | 取消后停止后续副作用，保留必要审计与可恢复状态；已锁定或已发布结果不被静默回滚。 |
| 部分完成 | 明确显示已完成、待处理和失败部分，可安全续作或补偿；不得把部分成功包装成整体成功。 |
| 数据缺失或冲突 | 停止受影响步骤并给出可处理提示，保留证据供人工复核；不得猜测学生、题目、答案、分值或覆盖教师最终分锁。 |

与具体批次无关的场景可以说明“不适用”并写明理由，但不得直接省略。

## 9. 快速连续迭代节奏

### 9.1 开发期

1. 完成一次集中调查，冻结范围、问题清单和验收条件。
2. 按同一根因组织小批实现，前端和对应后端功能一起推进。
3. 单个小批只做保证后续可继续开发所需的最小检查，例如受影响的单元测试、类型检查或针对性手工冒烟。
4. 不把每个页面、问题或实施小包当成正式验收关口；不在每个小批后重复运行整套测试、构建或需求/代码双复审。
5. 只有故障阻塞后续开发时，才做最小范围诊断；该诊断不等于该小批已经正式验收。
6. 连续推进，直到整条业务线形成可整体交付的稳定候选。

### 9.2 合并前集中验收

稳定候选形成后冻结同一版本，再集中完成：

- 受影响回归测试；
- 阅卷系统与 P4 的完整测试；
- 必要的前端构建和后端检查；
- 与公共入口、A/B 只读契约、备份/模型策略等直接边界的跨模块冒烟；
- 同一冻结版本上的一次并行需求符合性复审和一次代码质量复审；
- 用户要求的人工验收。

两项正式复审必须检查同一个冻结版本，复审期间不继续修改。若没有当前范围内的 `Critical` 或 `Important` 阻塞问题，候选直接通过，不再做无检查目标的反复复审。

若初审发现阻塞问题，等待全部意见返回后按根因去重，只统一修复一次；随后只复测修复影响范围，并由原评审者进行一次限定最终复审。最终复审只检查首轮问题、修复区域及直接回归，不重新开放全量审查。若仍有当前范围内的阻塞问题，停止并向用户报告，由用户决定是否另开修复任务。

因此，本线的快速迭代原则是：**开发期不反复做正式验收，合并前对完整候选集中做足一次。**

## 10. 必须逐次获得用户授权的操作

以下授权不能由本文件、分支建立或既往授权代替，每一次操作都要单独确认精确目标、风险和回退方式：

- 读取、复制、写入、移动、迁移或删除真实 `user_data/`。
- 使用真实数据库、真实成绩、真实试卷、真实答卷、真实训练卷或真实业务文件做写入式验证。
- 对真实数据库执行迁移、恢复覆盖、批量覆盖或永久删除。
- 调用真实模型、使用真实密钥、产生费用，或在失败后追加付费请求。
- 操作真实打印机、扫描仪，或对真实纸张/扫描件执行打印、扫描、归卷和批改流程。
- push、创建 PR、合并、同步 `main`，或丢弃未进入主线的提交。

自动化测试默认只使用临时数据库、合成资料、假模型和隔离产物。真实数据不得写入工作树、提交、stash、普通日志、文档或 API 响应。

## 10.1 本地页面与三合一预览

- `frontend/node_modules/` 与 `frontend/dist/` 都不进入 Git。切换分支或同步源码不代表浏览器已经加载该分支的新页面。
- 单独查看本线时，必须在本工作区重新构建页面，并确认生成文件包含当前源码的工作台入口；不得复用根目录或其他工作区的旧 `frontend/dist/`。
- 三路日常联看只通过 `codex/teacher-platform-integration` 组合预览工作区完成。本线形成可查看的小批次后先保存明确的本地检查点，再由预览区单向吸收。
- 不把备课或班主任的未验收提交合入本分支；预览区的提交也不得反向合回本分支。
- 页面构建失败、构建版本与当前代码不一致或旧端口仍被其他工作区占用时，必须停止启动并明确提示，不能继续展示旧页面冒充当前候选。

### 保留原数据体验的预览副本

- 用户已选择在三合一预览中保留原有数据体验，但预览程序不得直接连接根目录真实 `user_data/`。必须在用户逐次授权后，从稳定 `main` 数据制作一个只供预览使用的隔离副本。
- 阅卷库和题库库必须通过 SQLite 一致性快照复制，不能在数据库正在写入时直接复制 `.db`、`.db-wal` 或 `.db-shm` 文件。考试、模板、题库素材和必要配置按受控清单复制。
- 默认排除 API 密钥、模型配置正文、普通日志、历史备份、快照、临时文件、可再生成产物和整个 `user_data/workspaces/`。不得因为希望页面“看起来一样”而扩大到敏感数据或费用授权。
- 预览副本可以被预览代码迁移和修改，但任何变化都不得反向同步到根目录真实数据。重新从 `main` 制作副本会覆盖预览状态时，必须先说明影响并再次取得用户确认。
- 备课与班主任工作台数据不属于本线普通数据副本；如需保留，分别按各自文档的真实资料和敏感数据规则单独授权。

## 11. 最终验收条件

同时满足以下条件，才可把本线标记为“实现通过验收”：

- 冻结范围内的功能和前端流程完整可用，验收条件均有证据。
- 普通考试分数、排名、报告和教师最终分锁的不变量全部保持。
- P4 训练结果继续使用“达成点数 / 总判定点数”，且不污染普通考试语义。
- 未修改 A/B 专属目录与数据；跨线调用只经过批准的无副作用只读接口。
- 公共热点没有被本线私自打补丁；确需的公共改动已通过独立地基修正处理。
- 重复、并发、退出、重启、重试、取消、部分完成、数据缺失或冲突等适用场景已有预期结果和验证证据。
- 集中的受影响回归、本线完整测试、必要构建和跨模块冒烟全部通过。
- 同一冻结候选的一轮并行双复审已完成，当前范围内不存在未解决的 `Critical` 或 `Important` 问题；如发生统一修复，限定最终复审也已通过。
- 任务清单和相关设计/执行记录已更新，范围外问题、发布风险和后续独立任务已单独列明。
- 用户已完成人工验收，并明确确认候选可以进入合并流程。

实现通过验收不等于自动获准发布。即使全部检查通过，仍必须得到用户对当次 push、PR、合并和同步 `main` 的明确授权后，才能执行对应操作。
