# 备课工作台连续迭代边界

## 基线与定位

- 分支：`codex/teaching-prep-iteration`
- 独立工作区：`.worktrees/teaching-prep-iteration`
- 共同起点：`e63136c6c5471f358cfaf11065f5b92b0f46ca10`
- 业务线：A（备课工作台）
- 风险等级：中高

本分支用于备课工作台前端与功能的连续迭代。它保持与阅卷系统、P4 个性化训练、班主任工作台的数据和代码边界，先快速形成完整可验收候选，再集中验证和评审；“快速迭代”不等于不测试，而是避免在每个小改动后反复进行同一轮正式测试和复审。

## 目标

围绕教师真实备课流程，连续完善从教材和教辅资料组织、课时树与资料定位，到备课草稿、审批、课件改编、WPS 执行和上课包输出的完整体验。页面交互和后端能力在同一分支共同推进，使每次交付都能作为一条完整业务链验收。

允许迭代的业务内容包括：

## 明确不包含

- 不覆盖、替换或原地修改教师提供的源 PPTX；所有课件改编只作用于隔离副本。
- 不读取班主任工作台（B）的学生档案、事件、日历、SOP 或其他受保护数据，也不修改 B 的目录与接口。
- 不向阅卷系统或 P4 写入数据，不改变考试分数、排名、报告、评分依据、教师最终分锁、知识图谱、掌握度或个性化训练结果。
- 不直接读取或绕过题库与学情模块的内部存储。题库和教师明确选择的匿名学情证据，只能通过只读 Adapter 使用；Adapter 不得提供反向写入能力。
- 不在本分支分别修补左侧导航、全局路由、应用启动、公共任务框架、全局迁移框架、模型策略、备份入口、公共依赖及全局架构索引等公共热点。
- 不顺手修复调查中发现但不阻塞本业务线验收的修改前问题或相邻业务需求；这些内容单独记录为后续任务。

## 公共热点处理规则

如果 A 业务确实依赖公共热点变更，先冻结相关 A 侧需求并记录依赖，通过独立、短期的地基修正分支完成公共修改。该修正经验证并同步到稳定主线后，本分支再同步新的共同起点并继续开发。不得从阅卷或班主任分支复制未验收代码，也不得让三条业务线各自维护同一公共入口的不同补丁。

## 快速连续迭代流程

1. 开始一组相关修改前，在本业务线和直接影响范围内集中调查一次，汇总并按根因去重问题，冻结本轮目标、包含项、不包含项、验收条件和故障预期。
2. 将同一根因或一条完整业务链的改动作为一个连续批次实施；小任务完成后更新进度并继续，不把实施包当成独立正式验收关口。
3. 开发期间只做保障继续开发所必需的最小检查，例如受影响组件的快速检查或针对明确故障的最小诊断。只有故障阻塞后续工作时才增加诊断检查。
4. 不对每个页面、接口或小任务重复运行正式测试，不逐项启动需求复审和代码质量复审，也不因“还可以优化”而重新进行开放式审查。
5. 整条备课业务链形成稳定、完整候选后冻结版本，再集中进行受影响回归、A 业务线完整测试、必要构建与跨模块冒烟检查。
6. 对同一个冻结候选并行进行一次需求符合性复审和一次代码质量复审。只有本次修改直接引入或当前任务遗漏的 `Critical` / `Important` 问题阻塞验收。
7. 如初审存在阻塞问题，等待全部意见后按根因统一修复一次，只复测受影响范围，并由原评审者进行一次限定最终复审；不得自动进入第三轮反复复审。
8. 自动化验证只使用临时数据库、合成资料和假模型，不使用真实教师或学生数据。

## 必须逐次授权的操作

以下操作每一次都要先向用户说明精确对象、用途、可能影响、费用或回退方式，并取得当次明确授权：

- 读取、复制、移动、写入或删除真实教材、教辅及其他备课资料；
- 打开、复制、改编或输出真实 PPT/PPTX；
- 启动或控制 WPS 执行真实课件操作；
- 调用真实模型、使用真实密钥，或执行任何可能产生费用的请求与失败重试；
- 读取或写入真实数据库，执行数据库迁移、恢复覆盖或其他可能改变真实业务数据的操作。

即使获得授权，也不得将真实资料、密钥或数据库内容提交到 Git，写入普通日志、测试夹具、文档或接口响应。涉及写入或不可逆操作时，还必须先确认目标、备份和回退路径。

## 故障场景与预期结果

| 场景 | 预期结果 |
| --- | --- |
| 重复操作 | 重复点击保存、审批、生成副本、执行或打包时，不重复创建同一业务结果，不重复覆盖文件，不重复调用模型或计费；已完成结果应安全复用或明确提示。 |
| 同时操作 | 同一草稿、课件副本或上课包被并发修改时，不静默互相覆盖；系统应拒绝冲突写入、串行处理或要求教师确认可见差异。 |
| 中途退出 | 页面、服务或 WPS 意外退出时，源文件保持不变；已确认保存的草稿和步骤状态可恢复，未完成产物不得伪装成成功结果。 |
| 重新启动 | 应用重启后能识别未完成任务和已有隔离副本，不重复执行已成功步骤；无法继续时给出可理解的恢复或重新开始选项。 |
| 失败重试 | 重试只继续未成功步骤；模型请求、WPS 操作、文件复制和打包均应避免重复费用、重复副本和重复输出。自动追加真实模型请求必须重新获得授权。 |
| 取消 | 取消后停止后续步骤，保留源文件；临时产物应被安全标记或清理，已经确认保存的内容不被误删，取消状态对教师可见。 |
| 部分完成 | 多步骤流程部分成功时，逐项记录已完成、失败和可继续状态；上课包或 PPTX 未完整生成时不能标为可交付。 |
| 资料缺失 | 教材、教辅、图片、字体、源 PPTX 或引用证据缺失时停止受影响步骤，指出具体缺失项，不猜测内容、不损坏已有草稿。 |
| 资料冲突 | 资料版本、课时归属、只读证据或教师修改互相冲突时，保留双方信息并要求明确选择；不得以后台规则静默覆盖教师内容。 |

以上故障预期是本业务线验收的一部分。某个场景与具体改动无关时，可在冻结的问题清单中标记为“不适用”并说明依据，但不得未经检查直接省略。

## 完整候选的验收条件

完整候选至少满足：

- 本轮冻结的备课业务链能够从入口走到预期交付结果，页面状态与后端结果一致；
- 隔离副本机制得到验证，任何路径都不覆盖源 PPTX；
- 题库和匿名学情证据只通过只读 Adapter 使用，且不存在对阅卷、P4 或 B 的写入；
- 与本轮相关的故障场景有明确结果，并由相应测试、构建、运行证据或人工验收记录支持；
- 集中验证通过，需求符合性复审和代码质量复审完成，当前范围内不存在未解决的 `Critical` / `Important` 问题；
- 范围外问题、版本级发布风险和后续任务已单独记录，没有被混入本次修改；
- 用户完成页面与流程的最终人工验收。

## 合并边界

完成候选、集中验证和规定复审后，仍不得自行 push、创建 PR、合并或同步 `main`。只有用户完成最终人工验收并明确授权当次操作后，才可执行对应 Git 动作。合并时只包含本业务线已验收的代码、测试、迁移定义和文档，不包含真实资料、运行产物或本机数据。

### 保留原数据体验的预览副本

- 三合一预览使用自己的隔离数据目录，不直接共用根目录真实 `user_data/`。阅卷、题库和考试数据由统一预览快照提供，只读 Adapter 继续保持原义。
- 普通预览快照默认不包含 `user_data/workspaces/teaching-prep/`，因此不会自动复制真实教材、教辅、课件、备课草稿或 WPS 产物。
- 用户需要保留备课工作台原数据体验时，必须另行确认精确来源目录、目标预览目录、包含的真实资料、服务停止状态、复制方式和回退；只复制到预览副本，绝不覆盖源 PPTX，也不把预览修改同步回真实资料。
- 代码检查点和页面构建刷新不得覆盖已经授权保留的预览数据副本。需要重新制作 A 数据快照时，若会覆盖预览中的草稿或副本，必须再次征得用户确认。
- 数据快照授权不等于授权启动 WPS、调用真实模型、使用密钥或产生费用；这些动作仍逐次确认。
