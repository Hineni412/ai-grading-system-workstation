# A-I1-R7 备课工作台首页与单课时工作页实施计划

> 状态：`design_frozen_pending_checkpoint_sync`
>
> 业务线：A（备课工作台）
>
> 依赖：共同地基 `TW-F1` 及 `docs/product/teacher-workspaces/AI_TASK_AND_HANDOFF_CONTRACT.md`
>
> 权威复核位置：`codex/teacher-workspaces-design-freeze` 的完整文档候选。A 分支中的同名文件在共同文档检查点经用户授权提交并通过 Git 同步前只是工作稿，不得据此开始编码。
>
> 本文只替代旧 A-I1 规格中的页面层级、默认入口、AI 任务接入和课件修改预览。旧五段业务语义、资料契约、版本控制、源 PPTX 不可覆盖等已实现规则继续有效。

## 1. 冻结边界

### 1.1 目标

把当前“四个并列工作区 + 多块面板纵向堆叠”的体验重构为：

1. **C 型备课首页**：一眼看到近期新授课的准备状态和下一动作；
2. **A 型单课时工作页**：来源、原页/幻灯片和 AI 修改检查保持同屏；
3. **资料库**：继续作为独立管理工具，不再充当默认备课首页；
4. **共同 AI 任务**：所有可能调用模型的流程可离页、可恢复、零自动重试；
5. **可核对的修改预览**：逐项定位 AI 修改，不用文字卡片假装成真实前后对比。

### 1.2 包含

- A 专属路由状态、首页、课时页壳层和响应式布局；
- 近期课时聚合摘要和下一动作；
- 现有资料选择、候选练习、课堂草稿、课件审核和上课包能力的重排；
- A 的共同 AI Task Adapter；
- 源页/源幻灯片预览、修改定位数据和审阅动作；
- 受影响的 A API、迁移、测试和说明文档。

### 1.3 明确不包含

- 不覆盖、替换或原地修改源 PPTX；
- 不把 WPS 文件操作伪装成 AI 任务；
- 不改班主任、P4、阅卷评分、题库或学情数据语义；
- 不在 A 分支修改公共 JobManager、任务抽屉、全局顶部栏或导航热点；
- 不读取真实教材、教辅或 PPTX，不调用真实模型，不启动真实 WPS；
- 不新增“必须有参考课件”限制；无课件备课仍是完整路径。

### 1.4 验收条件

- 默认进入 C 型首页，能在一次聚合请求中显示近期 5—8 个课时；
- 点击课时或状态格可恢复地进入 A 型课时页准确阶段；
- 中央原页/幻灯片画布是主视觉区，来源和 AI 审阅不再整段向下堆；
- 未保存的资料范围不会被悄悄送给 AI，来源变化会使旧 proposal 失效；
- AI 修改可逐项定位、接受或拒绝，且明确区分方案预览和 WPS 实际结果；
- 刷新、离页、重复点击、取消、重启和响应丢失不会重复模型调用；
- 全部自动验证使用合成资料、Fake 模型和 Fake WPS。

### 1.5 风险等级

`中高`。本轮会重排备课主要入口并接入公共任务状态，但不改变源文件保护、教师审批和正式版本语义。

## 2. 现状与替代关系

### 2.1 可直接复用

- `lesson-preparation-statuses` 已聚合课时标题、排序、教师进度、系统阶段、阻塞项和最新版本引用；
- `reference preflight → selection draft → snapshot → AI candidate → review` 已具备版本化契约；
- 课时资料已经提供不暴露绝对路径的 `preview_url`；
- 教师手动状态已经区分 `not_started/preparing/ready/taught/skipped`；
- 课时、资源包、课堂草稿、课件计划、PPTX 版本和上课包已有稳定业务身份；
- A 已有部分“调用前快照、operation claim、结果不明、proposal 落库”能力，可作为共同任务 Adapter 的来源。

### 2.2 本轮替代

- `TeachingPrepHomeView` 不再承载四个同级工作区标签；
- 旧五段流程继续作为业务阶段，但只在单课时工作页中呈现；
- `LessonPreparationWorkspace` 内连续下堆的候选、人工框选、草稿和预览改为互斥工作面；
- `PresentationVersionsWorkspace` 的文字版 before/after 卡片改为源幻灯片画布与结构化覆盖层；
- A 自有的 AI 轮询改接共同任务 store；
- 资料解析、WPS 执行等非 AI 后台任务继续使用原 Job，不并入 AI Task。

### 2.3 不提前删除

实施时先用新的深 Module 包住现有能力，完成行为等价测试后再移除旧导航和重复轮询。不能为了“页面干净”先删掉仍被保存、恢复或版本审阅依赖的组件。

## 3. 信息架构与路由

### 3.1 一级入口

| 入口 | 路由状态 | 用途 |
| --- | --- | --- |
| 备课首页 | `view=overview` | 默认入口；看近期课时准备度和下一动作 |
| 单课时工作页 | `view=lesson&lesson=<id>&stage=<stage>` | 围绕一个课时完成所有备课工作 |
| 资料库 | `view=library` | 建库、解析、资料角色和课时关联管理 |

公共顶部栏由 `TW-F1` 的 manifest 子导航契约调整，不在 A 或集成分支直接补丁。A manifest 只声明“备课首页／资料库”；单课时的核资料、定方案、审课件和上课包留在 A 页面内部。A 另提供稳定的 route-state Interface。

### 3.2 单课时阶段

| stage | 页面名称 | 主要内容 |
| --- | --- | --- |
| `materials` | 核资料 | 来源范围、原页预览、候选练习、学情证据 |
| `plan` | 定方案 | 课堂目标、重点难点、活动、时间和草稿 |
| `slides` | 审课件 | 基准课件、AI 修改 proposal、逐项审阅、WPS 版本 |
| `package` | 上课包 | 定稿版本、附件、核对和交付状态 |

旧 `select` 阶段只用于“尚未选定课时”的空态；选定课时后不占一张独立页面。候选练习是 `materials` 下可深链的 `panel=exercises`，不是第五张同级页面。

### 3.3 可恢复深链

路由至少持久化：`view/semester/lesson/stage/panel/focus_ref`。正文、文件路径和 prompt 不进入 URL。页面刷新后先校验 semester 与 lesson 归属，再恢复 stage；目标不存在或已归档时回首页并说明原因，不静默选中别的课时。

## 4. C 型备课首页

### 4.1 核心问题

首页只回答三件事：

1. 我接下来要备哪些新授课？
2. 每一节卡在哪一步？
3. 我现在最合适做什么？

它不是资料库、课时编辑器或 AI 输出全集。

### 4.2 数据选择

- 依据当前个人课时树排序，不凭模型猜日期；
- 首屏显示当前焦点附近 5—8 个未跳过课时；
- 已授课课时只保留最近少量作为上下文，不能挤占全部首屏；
- 教师可以“查看全部课时”，但默认不加载全学期重页面；
- 无当前学期、无课时树、课时树尚在生成分别使用不同空态。

### 4.3 状态矩阵

首页矩阵固定四列：

1. **核资料**：资料是否确认、是否失效、是否需要教师选择；
2. **课堂方案**：草稿是否存在、是否待审、是否因来源变化失效；
3. **候选练习**：候选数、已选数、是否待核对答案；
4. **课件（可选）**：无课件、待审 proposal、WPS 处理中、可用版本或失败。

单元格统一状态：

| 状态 | 显示 | 行为 |
| --- | --- | --- |
| `not_started` | 未开始 | 打开对应阶段 |
| `in_progress` | 进行中 | 返回未完成位置 |
| `needs_teacher` | 待你处理 | 打开具体决定项 |
| `ready` | 已就绪 | 可查看，不抢占主提示 |
| `stale` | 来源已变化 | 打开失效原因和重新确认入口 |
| `failed` | 未完成 | 打开可理解错误和安全恢复动作 |
| `not_applicable` | 本节不需要 | 例如无课件备课，不计为阻塞 |

教师手动进度与系统准备度必须分开：`taught` 是教师声明的授课事实；准备度是系统根据版本和阻塞项计算的投影。系统不得因为上课包齐全自动标为已授课，也不得因教师标记已授课伪造此前步骤完整。

### 4.4 操作

- 点击课时标题：进入该课时的 `next_action`；
- 点击矩阵格：直达该阶段和具体 panel；
- 每行最多一个显著主动作；
- 首页只显示正在运行或待审的 AI 任务摘要，完整信息放共同任务抽屉；
- “资料库”是次级入口；“建立课时树”只在缺少课时树时成为主动作。

### 4.5 聚合接口

扩展现有学期状态聚合，不为每个课时分别请求。每个课时摘要至少返回：

- 现有 `lesson_node_id/title/sort_order/manual_progress/preparation_stage/next_action/blockers/latest`；
- 四个矩阵格的状态、数量摘要和目标 panel；
- 与本课时相关的安全 AI Task 摘要；
- `summary_revision`，防止旧响应覆盖更新后的状态。

禁止返回真实路径、教材正文、prompt、课件正文或完整 AI 输出。

## 5. A 型单课时工作页

### 5.1 桌面布局

```text
┌ 课时标题／教师进度／阶段导航／返回首页 ───────────────────────┐
│ 左：课时与来源       │ 中：原页或幻灯片主画布        │ 右：AI/证据/决定 │
│ 约 240—300px         │ 自适应，正常桌面不少于 50%    │ 约 320—400px     │
├───────────────────────────────────────────────────────────┤
│ 当前状态与单一主动作；次要动作进入菜单或对应侧栏              │
└───────────────────────────────────────────────────────────┘
```

- 三栏各自滚动，切换右侧检查项不能把中央画布推到页面下方；
- 课时标题、来源 revision 和 proposal 失效提醒始终可见；
- 同一时刻只展开一个主要工作面；历史、日志和长说明进入抽屉；
- 页面底部只保留一个与当前阶段匹配的主动作。

### 5.2 窄屏

- 小屏不强行保留三列；使用“来源／预览／审阅”三个页签；
- 页签切换保留当前源页、缩放和选中 change；
- 固定主动作不能遮挡内容；
- 键盘操作顺序与视觉顺序一致，所有选中和错误通过文字而不只靠颜色表达。

## 6. 核资料工作面

### 6.1 左栏：允许范围

- 按教材、参考课件、教辅、题库和教师选择的学情证据分组；
- 显示已确认范围、页/张数、解析状态和来源 revision；
- 勾选范围只修改 selection draft；
- “保存范围”和“发起 AI”是两个不同动作；
- 未保存、失效、缺页、OCR/公式待核对要明确显示。

### 6.2 中栏：原始证据

- 选择教材或教辅页，立即展示原页；
- 选择 PPT 来源，展示原幻灯片；
- 支持缩放、适合宽度、页码跳转和前后页；
- 预览通过不透明资源 ID 获取，不暴露磁盘绝对路径；
- 预览失败不影响继续编辑其他已加载内容，但不能把缺失页交给 AI。

### 6.3 右栏：范围摘要与任务

- 已选资料、页码、题目和学情证据的摘要；
- 哪些内容会发送、模型目的地安全名称和是否会保留一次发送尝试；
- 阻塞项与教师必须先核对的内容；
- 共同 AI Task 的状态和“从任务抽屉返回”；
- AI proposal 就绪后切换为逐项审阅，不与选择表单同时纵向展开。

### 6.4 候选练习

候选练习使用 `panel=exercises`：中央画布显示题目原页，右侧显示来源、答案状态、适用理由和接受/拒绝。没有答案是有效状态；只有教师要求输出答案时才必须完成答案核对。

## 7. 定方案工作面

- 复用现有 lesson draft 和 resource pack 版本；
- 左栏显示本节已确认来源与课堂约束；
- 中栏按课堂顺序编辑目标、重点难点、活动和时间，不把每块包装成全宽面板；
- 右栏显示 AI 建议、引用证据、冲突和教师决定；
- AI 修改以 diff 展示，不覆盖教师已编辑文字；
- 保存使用 revision 条件写入；冲突时展示双方变化并要求教师决定。

## 8. 审课件与 AI 修改预览

### 8.1 三段结构

1. **幻灯片缩略列**：显示页码、状态、待审 change 数和风险；
2. **源页大画布**：显示基准课件原始渲染；
3. **修改检查器**：显示选中 change 的理由、引用、风险、执行模式和教师决定。

### 8.2 change 契约

每项 proposal change 至少包含：

- `change_id`、`slide_ref`、`slide_revision`；
- `operation_kind`：新增、删除、替换、移动、样式或人工说明；
- `target`：可定位对象 ID 或归一化区域；
- `before_summary`、`after_summary`；
- `reason`、`source_refs`、`risk_flags`；
- `execution_mode`：`auto_supported` 或 `manual_only`；
- `review_status`：待审、接受、拒绝；
- 源页安全 `preview_url`。

区域坐标必须与源页宽高绑定，并在缩放时保持定位。无法可靠定位的 change 必须是 `manual_only`，不能制造一个虚假的高亮框。

### 8.3 视觉表达

- 删除：红色斜线和编号，不直接从源图抹去对象；
- 移动：原位置与目标位置轮廓及方向箭头；
- 新增：目标区域虚线框和编号；
- 文本替换：高亮原对象并在检查器显示建议文本；
- 样式修改：标记对象，检查器显示属性差异；
- 每种标记均有文字标签和列表对应项。

页面固定说明“这是修改方案预览，不是 WPS 成品”。只有 WPS 隔离副本执行并重新渲染后，才提供真实 before/after 对照。

### 8.4 教师决定

- 单项接受、拒绝；
- 对 `auto_supported` 的低风险项可以批量接受；
- `manual_only` 只能标记为教师手动处理，不能批准给自动执行器；
- proposal 审阅结果版本化保存；
- 基准 PPTX、来源范围或 prompt 合同变化后，未执行的旧 change 立即 stale；
- WPS 只接收教师已经批准且仍匹配 revision 的操作。

## 9. TeachingPrepWorkbench 深 Module

前端保留一个 `TeachingPrepWorkbench` Module 统一管理：

- `view/semester/lesson/stage/panel/focus_ref`；
- 首页聚合、当前课时和当前来源；
- 每栏的装载、错误、脏状态和 revision；
- 可恢复路由和返回位置；
- AI Task 引用与 proposal 引用；
- 页面切换竞态，阻止旧请求覆盖新课时；
- 键盘焦点和窄屏页签状态。

首页和课时页不得各维护一份课时状态。业务组件通过 Module 的小 Interface 读写，不直接拼接路由或同时调用多个仓储。

## 10. A 的共同 AI Task Adapter

### 10.1 task_kind

首版至少支持：

- `teaching_prep.semester_mapping`
- `teaching_prep.lesson_plan`
- `teaching_prep.exercise_suggestions`
- `teaching_prep.slide_change_proposal`

资料解析、预览渲染、WPS 执行和上课包导出不是 AI Task。

destination_key 由 A Adapter 固定映射：`semester_mapping` 返回 `teaching_prep.library` 审核目录映射；其余课时任务返回 `teaching_prep.lesson.*` 对应工作面。模型不能自行返回任意页面。

### 10.2 Adapter 输入

- lesson、resource pack 或 selection snapshot 的不透明引用与 revision；
- prompt 合同版本；
- 教师偏好和本次覆盖的领域引用；
- 模型目的地指纹；
- 返回的 destination_key。

共同存储不得保存资料正文。Adapter 从 A 自身数据库读取冻结 snapshot，校验后构造 prompt。

### 10.3 Adapter 输出

- 领域 proposal ID、revision、source_state_sha256；
- 安全摘要、缺失字段和 destination_key；
- 不在共同任务 API 返回完整课堂草稿或课件修改正文。

### 10.4 采用

教师 adopt 某个 Handoff 时，A Adapter 再校验 draft 与目标 revision，并用共同 Module 分配的稳定 adoption_id，在 `teaching_prep.db` 同一事务写正式对象和 Adoption Receipt。公共元数据更新前崩溃时，重放 adopt 查询该 Receipt 并返回同一对象。AI Task `succeeded` 不等于教案已确认、change 已批准或 WPS 已执行。

## 11. 实施包

这些包是一个连续实现序列，不是逐包正式测试或复审关口。

### A7-00：契约与壳层

- 同步共同地基检查点；
- 使用 TW-F1 已完成的 manifest 子导航，不在 A 分支修改 AppTopbar；
- 添加 A Adapter 合同和 route-state 类型；
- 建立 `overview/lesson/library` 两级壳层；
- 先让旧组件通过 Adapter 挂入新壳层，保持行为可比。

完成证据：路由单测、旧页面关键能力仍可从新壳层访问。

### A7-01：C 型首页

- 扩展单次聚合状态；
- 实现近期课时矩阵、空态、next_action 和深链；
- 区分教师授课状态与系统准备度；
- 合并安全 AI Task 投影。

完成证据：聚合查询计数测试、状态矩阵组件测试、刷新恢复测试。

### A7-02：A 型课时壳层

- 三栏布局、阶段导航、单一主动作；
- 迁入资料选择、候选练习和课堂草稿；
- 统一脏状态、revision 和旧请求竞态；
- 完成窄屏页签和键盘顺序。

完成证据：课时切换不串数据、未保存范围不丢失、窄屏交互测试。

### A7-03：共同 AI 任务接入

## 12. 故障场景

| 场景 | 预期结果 |
| --- | --- |
| 重复点击生成 | 同 operation 和同来源最多保留一次发送尝试；重复响应返回同任务 |
| 多窗口同时审阅 | revision 条件写入，后提交者看到冲突，不静默覆盖 |
| 切换课时时旧请求返回 | Workbench generation/token 拒绝旧响应覆盖新课时 |
| 离页或刷新 | 路由、selection draft、AI Task 和 proposal 可恢复 |
| 应用重启 | 发送后无结果进入 result_unknown；已保存 proposal 只重做本地交接 |
| 取消 | 发送前真正取消；发送后只停止后续，源文件始终不变 |
| 来源变化 | 旧 snapshot、草稿建议和 change proposal 标 stale，不能执行 |
| 原页缺失 | 指出具体页/张并停止引用，不用 OCR 文本伪装视觉预览 |
| WPS 部分完成 | 隔离副本标失败或部分完成，不成为当前版本，不覆盖基准课件 |
| 无参考课件 | slides 为 not_applicable，课堂方案和上课包仍可继续 |
| 任务抽屉恢复失败 | 保留 A 内 task/proposal 引用，允许在课时页查询，不发新模型请求 |
| adopt 后公共回执未写入即退出 | A 领域 Receipt 与正式对象已同事务保存；重放返回同一对象，不创建第二版 |

## 14. 人工验收脚本

1. 打开备课工作台，默认看到 C 型首页而非资料库或长表单；
2. 找到一节“待核资料”课时，点击格子进入该课时材料面板；
3. 切换教材页、教辅页和参考 PPT，确认中央立即展示原页；
4. 修改选择但不保存，确认“生成建议”不可悄悄使用未保存范围；
5. 发起 Fake AI 任务，离开页面后从任务抽屉返回同一课时；
6. 在课件审阅中点击三种 change，确认画布定位、理由和来源一致；
7. 接受、拒绝和标记人工处理各一项，确认未批准项不会进入 WPS；
8. 修改来源 revision，确认旧 proposal 立即失效；
9. 走无参考 PPT 路径，确认仍能完成课堂方案；
10. 检查源 PPTX hash 不变，只有隔离副本出现新版本。
