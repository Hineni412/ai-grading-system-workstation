## 2. 本轮任务边界

### 2.1 目标

把当前单路由、单巨型页面中的完整备课链路，重组为教师可理解、可返回、可核对来源、可恢复版本的工作台；同时实现用户本轮确认的课时状态、五段流程、逐条映射审核、AI 候选题主路径、冻结前参考范围选择、PPTX 版本恢复和实时 WPS 进度。

页面必须回答五个连续问题：

1. 下一节新授课是什么？
2. 本节允许使用哪些资料、页段、题目和答案？
3. 这 45 分钟怎样上，依据是什么？
4. 每一页课件准备怎样改？
5. 哪个 PPTX 和上课包是当前可信版本？

### 2.2 包含

- 一个全局“备课工作台”入口下的四个稳定内部工作区；
- `选课时 → 核资料 → 定方案 → 审课件 → 上课包` 五段可点击进度尺；
- 不依赖日期的新授课列表和醒目的授课状态；
- 资料台账、原页大预览、逐条映射审核和来源回跳；
- 教师先限定参考资料池，AI 再提出教辅、页、区域和题目候选；
- 人工框选作为修正和兜底，并支持多区域排序；
- 冻结最终授课资源包前的精确资料、题目、答案、证据和偏好选择；
- 课堂草稿的来源回跳与实时容量预览；
- 逐页课件改编的前后视觉核对、风险文字和教师决定；
- 课时级 PPTX 版本列表、可信旧版本恢复、最终预览和上课包清单；
- WPS 创建副本、执行、验证、发布的实时状态、取消和失败恢复；
- 深层操作的原位错误、保存状态、禁用原因和粘附操作栏；
- 与上述行为直接相关的 A 专属前端、后端接口、领域对象、迁移定义和自动化测试。

### 2.3 明确不包含

- 不做日期、日历或周排课字段；
- 不新增考试平均分、正确率、分布图或学生个人表现；
- 不让 AI 自动定稿课堂题、自动确认答案或自动修改 PPTX；
- 不允许 AI 扫描教师未选择的资料范围；
- 不从零生成 PPT，不扩大 A00 的 WPS 自动操作白名单；
- 不覆盖、删除或原地修改源 PPTX；
- 不自动追加可能收费的模型请求；
- 不读取或写入真实 `user_data/`，不操作真实教材、教辅、课件、考试数据或数据库；
- 不在本 A 分支直接修改全局顶部栏、全局路由、左侧栏或其他公共热点；
- 不增加八个全局入口，也不要求八张概念图一一对应八条全局路由；
- 不实现讲评课专用流程、学生个人级学情、P4 回写、B 数据读取、HTML 交互素材或多教师云协作。

### 2.4 验收条件

- 教师使用合成资料，可从新授课列表进入并走通五段流程；
- 五段都可点击进入，门禁只限制危险动作，不阻止查看阶段说明和历史；
- 返回上游修改时，历史版本不丢失，下游失效状态明确可见；
- 资料、题目、答案、草稿引用和课件建议可回到具体资料版本与原页；
- AI 候选题只来自教师允许的资料池，人工框选不再是每道题的强制入口；
- 最终资源包只包含教师接受的范围、候选题、答案状态、匿名证据和本次偏好；
- PPTX 历史、单独恢复和 WPS 实时进度均由真实状态驱动，不用静态假界面伪装；
- 所有模型和 WPS 自动化测试使用 Fake Adapter；没有真实调用、费用或真实文件操作；
- 受影响测试、A 线完整测试、前端类型检查、生产构建和必要跨模块冒烟通过；
- 稳定候选完成一次需求符合性复审和一次代码质量复审，当前范围内无未解决的 `Critical` / `Important`；
- 用户完成人工页面验收后，才讨论 push、PR、合并或真实资料试点。

### 2.5 风险等级

**高。**

原因不是视觉重排本身，而是本轮同时涉及：

- 多阶段状态和上游修改导致的下游失效；
- AI 允许范围、调用次数和费用边界；
- 不可变资源包输入变化；
- PPTX 文件版本、当前版本指针和恢复历史；
- WPS 长任务的退出、取消、重启和部分完成；
- 新接口和可能的 forward-only 数据迁移。

## 4. 目标信息架构

### 4.1 一个入口、四个内部工作区

全局左侧栏仍只有一个“备课工作台”。内部稳定工作区为：

1. **个人课时树**：学期、新授课列表、章—节—课时树和准备度；
2. **资料库**：资料台账、解析、原页预览和学期映射；
3. **本节备课**：本节来源、AI 候选题、人工校正、证据、资源包和课堂草稿；
4. **课件版本**：逐页计划、WPS 执行、PPTX 版本和上课包。

四个工作区不是四份独立业务记录。它们共享同一个当前学期、当前课时及其版本链。

### 4.2 五段可点击进度尺

固定文案：

`选课时 → 核资料 → 定方案 → 审课件 → 上课包`

阶段与工作区关系：

| 阶段 | 主要工作区 | 覆盖的概念状态 |
| --- | --- | --- |
| 选课时 | 个人课时树 | 01 学期与课时总览 |
| 核资料 | 资料库、本节备课 | 02 资料映射、03 本节来源、04 候选题、05 冻结前确认 |
| 定方案 | 本节备课 | 06 课堂草稿与容量 |
| 审课件 | 课件版本 | 07 逐页课件改编审核 |
| 上课包 | 课件版本 | 08 WPS、PPTX 版本和上课包 |

交互规则：

- 五段始终是可激活的导航项，不把未满足前置条件的段做成完全不可点击的灰块；
- 点击尚未到达的阶段，进入该工作面并显示“还缺什么”，但执行按钮继续受门禁保护；
- 当前段使用 `aria-current="step"`；完成、待确认、已失效、失败均使用文字或图标，不只靠颜色；
- 返回已完成阶段只查看或创建新版本，不自动回滚、删除或覆盖已有版本；
- 修改上游资料、资源包或草稿后，下游旧计划和输出保留历史，并标记“来源已变化，需要新版本”；
- 五段导航可通过键盘聚焦和激活；切换后焦点进入新工作面标题；
- 浏览器后退、前进和刷新应恢复仍有效的工作区、阶段和课时上下文。

### 4.3 路由与上下文

本轮不修改全局路由注册。继续使用 `/teaching-prep`，在 A 模块内部通过查询参数表达可恢复状态，例如：

```text
/teaching-prep?workspace=lesson-tree&stage=select
/teaching-prep?workspace=lesson-prep&stage=materials&lesson=<lesson-id>
/teaching-prep?workspace=versions&stage=slides&lesson=<lesson-id>&plan=<plan-id>
```

具体参数名可在实现时调整，但必须满足：

- 地址可恢复到同一课时和工作面；
- 无效或无权限的 ID 不抛出空白页，回到最近的安全状态并说明原因；
- URL 不包含本机路径、文件名隐私、数据库标识或个人学生信息；
- 未保存编辑在切换阶段、工作区、课时或浏览器返回前得到保护。

### 4.4 课时脊柱的使用规则

不要求所有页面固定一条完整课时侧栏，按概念图和当前任务使用：

- `选课时`：显示完整章—节—课时树；
- `核资料`、`定方案`：显示当前学期、章、节、课时、时长和状态的紧凑上下文；需要大画布时可收为单行；
- `审课件`、`上课包`：以当前计划、PPTX 和上课包版本为主，保留可返回课时的紧凑入口，不强占预览面积；
- 切换工作区不能静默切换课时；切换课时前必须处理未保存内容。

## 5. 四个工作区的功能规格

### 5.1 个人课时树

页面任务：回答“下一节新授课是什么”。

必须实现：

- 不引入日期字段，按教师课时树顺序展示本学期新授课列表；
- 状态至少为：未开始、备课中、已备好、已授课、本学期跳过；
- 已授课使用醒目的文字和图形状态，同时降低已完成行的操作优先级；
- 明确区分“教师手动授课进度”和“系统根据资料、资源包、草稿、计划、PPTX 推导的准备度”；教师标记“已备好”不能掩盖来源已失效等系统阻塞；
- 所选课时显示教材、参考课件、教辅、答案、资源包、草稿、PPTX 定稿的准备度摘要；
- 保留新增、改名、上下移动、停用/恢复、预计时长和进度修改；
- 提供明确主动作“开始核对资料”或“继续备课”，根据当前闸门进入对应阶段；
- 不要求先录完整册，继续支持从近期课时渐进建立。

跨课时准备度应由一个只读聚合查询返回，至少包含 `manual_progress`、`preparation_stage`、`next_action`、`blockers` 和最新资源包/草稿/计划/PPTX/上课包摘要；不允许进入列表后为每个课时分别发起整套加载请求。

不实现：

- 日期化周视图；
- 自动排课或教学日历；
- 通过大号数据卡展示统计。

### 5.2 资料库与逐条映射审核

页面任务：回答“本学期资料是什么，它们对应哪些课时和页段”。

布局：

- 资料角色和台账在左；
- PDF 页或 PPT 幻灯片大预览在中，获得最大空间；
- 课时—页码建议和教师决定在右；
- 资料缩略图只承担导航，不替代原页核对。

每条映射建议至少显示：

- 资料名称、角色和精确版本；
- 建议目标课时；
- 起止页或幻灯片；
- 用途；
- 不确定项；
- 当前教师决定：待处理、接受、已修改、拒绝。

教师可以：

- 接受单条建议；
- 修改目标课时和起止页；用途继续由资料角色和兼容规则推导，只在确有多个兼容用途时提供受限选择；
- 拒绝单条建议并可选填写原因；
- 打开建议对应的原页；
- 保存审核草稿；
- 将全部已决定的接受项一次原子写入正式课时树和资料映射。

后端规则：

- 原始模型建议不可被编辑覆盖；教师修订作为独立审核结果保存；
- 提交包含 proposal revision 和来源状态指纹，冲突时不覆盖更新后的资料；
- 页段必须在对应资料版本范围内；目标课时必须属于当前教材/学期且仍有效；
- 拒绝项保留历史但不写入正式映射；
- 写入接受项时采用一个事务，不出现一半新映射、一半旧映射；
- 模型不可用时仍可人工建立正式映射；
- 不自动重试可能收费的映射请求。

本轮逐条审核的对象是“课时—页码映射行”。初始课时树建议继续单独确认；应用映射时不得在未确认的情况下静默改写课时树。映射行可以指向已经确认的现有课时，或指向同一 proposal 中已确认创建的课时节点。

### 5.3 本节备课：参考范围、AI 候选题和资源包

页面任务：回答“本节允许 AI 看什么，AI 找到了什么，教师最终采用什么”。

#### 5.3.1 两级确认模型

本轮新增四个清楚区分的业务对象：

1. **参考范围草稿 `ReferenceSelectionDraft`**  
   教师可编辑的允许范围，包含已登记、已解析、已映射的教材、参考 PPT、普通教辅、日常作业教辅、答案册及其页段。

2. **参考范围快照 `ReferenceSelectionSnapshot`**  
   发起一次 AI 候选识别前冻结的精确输入：资料版本、页段、偏好、operation ID 和来源指纹。它不是最终授课资源包。

3. **题目候选建议 `ExerciseCandidateProposal`**  
   AI 只在快照内提出的候选：采用哪份教辅、哪一页、哪些有序区域、哪道题、可能的答案位置、教学作用、理由和不确定项。

4. **授课资源包版本 `ResourcePackVersion`**  
   教师完成候选审核后，冻结最终接受的资料、题目、答案状态、匿名证据和本次偏好。课堂草稿和课件计划只能读取这个不可变版本。

#### 5.3.2 冻结前选择参考资料

教师必须能在最终资源包冻结前：

- 勾选或取消本次允许使用的已确认资料范围；
- 对参考 PPT 页段标记保留或候选删除意图；
- 查看资料角色、版本、页段和来源变化状态；
- 选择已接受的候选题、答案状态和备用题；
- 显式选择题库摘要、历史考试匿名证据和本次课件偏好；
- 查看“将进入最终资源包”的完整范围；
- 在来源缺失或答案未确认时看到具体影响。

选择某道候选题时，它依赖的题目区域、答案区域和资料版本必须自动锁定并说明原因；如果依赖范围不在当前允许池中，则阻止冻结并引导教师重新选择，不能生成断链资源包。

本要求不是“冻结前下载安全清单”。安全资源清单继续在冻结成功后导出，因为冻结前还没有最终不可变版本。

冻结请求必须显式携带教师选择的资料关联子集，服务端验证它们都属于当前课时、仍为活动状态、已确认且版本未变化；不得继续默认捕获当前课时的全部活动范围。

#### 5.3.3 AI 候选题主路径

理想主路径：

```text
教师选择允许参考池
→ 预览本次发送范围和是否调用模型
→ 冻结参考范围快照
→ AI 在快照内定位教辅、页面、题目区域和答案候选
→ 教师接受、拒绝或修正
→ 冻结最终授课资源包
```

规则：

- AI 可以承担候选召回、区域定位和排序，但不能把候选直接变成最终课堂题；
- 正式进入课堂的题仍由教师确认，通常控制在 1—3 道；
- AI 不能读取参考范围快照之外的资料；
- 每次候选操作都有发送预览、operation ID、来源指纹和幂等键；
- 一次教师操作最多一次正式候选模型调用，不自动追加语义重试；
- 真实模型未配置、未授权或失败时，教师可以不选题继续，也可以使用人工兜底；
- 候选结果必须保留原图引用，OCR 文本只作为识别线索；
- AI 不能自动确认答案、自动加入题库、自动进入 PPT 或回写 P4。

真实模型调用和费用不由本文授权。实现和自动化验收先使用 Fake Model Adapter；未来真实试点仍须逐次确认发送范围、模型、费用和重试规则。

#### 5.3.4 人工框选和区域排序

人工画框不再是每道题的必经步骤，而是以下情况的修正或兜底：

- AI 漏掉题目、选错题或裁切不完整；
- 扫描件、多栏、跨页、图文分离或答案位置复杂；
- 教师主动新增一条模型未推荐的候选题；
- 模型不可用而教师仍希望人工建立候选题。

编辑器必须支持：

- 题目/答案模式切换；
- 一道题多个有序区域和跨页区域；
- 新增、移动、调整边界、移除区域；
- 拖动或键盘调整区域顺序；
- 打开区域对应原页；
- AI 建议框和教师修改框的来源标识；
- 修改题目或答案区域后，旧答案确认自动失效；
- 无答案可以保存，但必须明确标记“答案缺失”。

### 5.4 本节备课：课堂草稿和容量

页面任务：回答“这节课具体怎样上，为什么这样安排”。

必须实现：

- 草稿版本、目标、重难点、预计困难、课堂流程和题目取舍；
- 修改流程分钟数、题目取舍或题目预计时间后，容量在当前编辑区即时更新；
- 容量计算复用后端唯一规则，通过不创建新版本、不调用模型的本地预览接口完成，避免前后端各算一套；
- 容量显示计划分钟、课时分钟、流程、课堂题、机动和超时量；
- 每条结论和建议的来源可以点击打开具体资料版本、页或候选题；
- 保存产生新草稿版本；只有教师确认版本可生成逐页课件计划；
- 本轮继续允许本地模板；真实模型草稿仍受单次授权约束。

### 5.5 课件版本：逐页改编审核

页面任务：回答“每一页、每一个对象准备怎样改”。

必须实现：

- 左侧幻灯片缩略图、页状态和计划版本；
- 中央显示当前原页和建议执行后的视觉结果；
- 右侧显示操作类型、目标对象、原因、来源、风险、执行模式和教师决定；
- 建议执行后不能只显示文字列表；后端若没有预览 URL，应增加计划预览渲染结果；
- 逐项接受、拒绝、继续复核；低风险整页删除可以批量批准；
- 风险必须写出“低风险/中风险/高风险/不可自动处理”，不能只靠边框颜色；
- `manual_only` 对象不能被批准为自动执行；
- 引用可以回到教材、教辅或学情证据；
- 保存产生新计划版本，来源变化时旧计划保留但失效；
- “原课件不会被覆盖”持续可见。

### 5.6 课件版本：PPTX 历史、单独恢复和上课包

页面任务：回答“哪个版本可信、当前使用哪个、如何恢复”。

#### PPTX 版本列表

按当前课时展示所有已经发布并通过验证的 PPTX 版本，每项至少包含：

- 版本号、创建时间、当前/历史状态；
- 来源课件计划和资源包版本；
- 页数、文件指纹和验证摘要；
- 最终渲染预览；
- 下载、恢复为当前版本、生成/查看上课包操作。

失败、取消、被中断或未通过验证的候选只能出现在执行历史中，不能伪装成可恢复的可信 PPTX 版本。

#### 单独恢复

- 教师可以把任一已验证的历史 PPTX 恢复为当前 PPTX；
- 恢复只改变当前版本指针并记录一条激活历史，不覆盖文件、不删除较新版本；
- 恢复后仍可再次激活其他可信版本；
- PPTX 恢复不自动切换上课包。若该 PPTX 已有可信上课包，页面提供独立的“恢复对应上课包”；否则允许从当前 PPTX 生成新包；
- 后续改编从教师当前确认的 PPTX 复制新版本，不原地修改历史文件。

#### 上课包

- 展开显示实际文件清单、版本、完整性和下载状态，不只显示一句摘要；
- PPTX、学生练习、教师答案、课堂流程、来源、版本说明和离线检查结果均可核对；
- 上课包历史、同课异班和课后一分钟复盘继续保留；
- 包恢复和 PPTX 恢复分开，避免错误切换班级资料。

### 5.7 实时 WPS 进度

页面内显示四个真实阶段：

1. 创建隔离副本；
2. WPS 执行已批准操作；
3. 重开、全页渲染和放映/结构验证；
4. 发布新的可信 PPTX 版本。

要求：

- 启动接口先返回 execution/operation ID，前端再通过轮询或等价的本地事件机制获取状态；
- 具体传输机制由实现选择，用户可见结果必须实时更新且刷新页面后能够继续；
- 显示当前阶段、已完成阶段、运行时间、5 分钟预算、模型/WPS/技术重试次数；
- 运行中允许取消时明确显示取消操作；取消后不继续验证或发布；
- 失败说明失败阶段、已保存内容、源文件状态、可恢复动作和可清理暂存；
- 断网、前端刷新或应用重启后，根据服务端记录恢复显示，不能重复执行成功步骤；
- 验证未完成或失败时不出现“下载定稿”；
- 不因 WPS 失败自动追加模型调用；
- 源 PPTX 永远不覆盖。

## 6. 共同页面与交互规则

### 6.1 页面几何

- 继续遵守 `docs/ui/STYLE.md` 和 `UI_CONCEPT.md` 的视觉语言；
- 资料、题目和课件审核工作面允许突破通用 1180px 内容上限，在 A 模块主滚动区内使用接近全宽的文档工作区；
- 原页或幻灯片预览获得最大面积；侧栏负责来源、属性和教师决定；
- 不把每条说明和字段都包装成独立卡片；
- 一个操作区只保留一个视觉主按钮；
- 选中、成功、警告、危险和失效状态同时使用文字或图标。

### 6.2 粘附操作栏和保存状态

题目审核、资源包冻结、课堂草稿、课件计划等长编辑面使用底部粘附操作栏，持续显示：

- 未修改；
- 有未保存修改；
- 正在保存；
- 已保存为版本 N；
- 保存失败；
- 存在版本或来源冲突。

保存失败必须在当前操作区说明：发生了什么、哪些内容已保存、编辑内容是否仍在、下一步怎样恢复。不能只在整页顶部显示一个通用错误。

### 6.3 门禁和禁用原因

- 主要动作不可执行时，附近显示具体原因，不只把按钮变灰；
- 原因通过 `aria-describedby` 与动作关联；
- 资料缺失、答案未核对、资源包未冻结、草稿未确认、计划仍有待决定项、WPS 未启用、来源变化和验证失败使用不同文案；
- 前置条件恢复后无需刷新整页即可重新可用；
- 阶段导航本身仍可点击，门禁只限制会改变业务结果的动作。

### 6.4 响应式和无障碍

- `≥1366px`：主要画布 + 辅助栏，文档预览占主宽度；
- `901–1365px`：辅助栏可收窄或进入抽屉，主预览不退化成小缩略图；
- `≤900px`：内部工作区和五段流程仍可到达；
- `≤760px`：主内容单列，来源和属性检查器进入可展开区或抽屉；
- 浏览器 200% 缩放下核心流程仍可完成；
- 题目区域必须有键盘等价路径：选择、录入或调整边界、排序、移除；
- 所有输入有常驻标签；错误、加载、当前步骤和状态使用合适的可访问语义；
- 焦点不会被顶部栏或底部粘附栏遮住；
- 尊重 `prefers-reduced-motion`。

## 7. 现有能力、前端工作与新增接口

### 7.1 复用与差距矩阵

| 能力 | 可复用现状 | 前端工作 | 需要新增的后端/数据能力 |
| --- | --- | --- | --- |
| 新授课列表 | 学期统计、课时树、五态进度接口 | 醒目状态、下一步动作 | 跨课时准备度只读聚合，避免 N+1 加载 |
| 五段导航 | 当前课时和各阶段原始数组 | 路由查询状态、阶段闸门、未保存保护 | 原则上无 |
| 资料预览 | 资料台账、单位缩略图和预览 URL | 大画布、翻页、来源回跳 | 如现有 URL 足够则无 |
| 逐条映射 | proposal 树和 mapping 列表 | 行级审核编辑器 | 行级审核结果、冲突保护和原子 apply |
| AI 候选题 | 人工候选题、区域、答案状态 | 候选审核和人工校正工作面 | 参考快照、候选 operation、区域建议、审核提交 |
| 冻结前资料选择 | 已确认资料关联、偏好、证据选择 | 精确范围清单和发送预览 | `selected_material_link_ids` 或等价快照输入 |

| 草稿/计划引用 | citation label | 可点击来源入口 | 若当前引用 ID 不足，增加稳定来源定位投影 |
| 课件前后核对 | before 缩略图、after 文字列表 | 当前页同步对照 | 建议执行后渲染预览 URL |
| PPTX 历史 | 单次执行返回 `PptxVersion` | 版本时间线、预览、当前态 | 按课时列表、当前指针、激活/恢复、预览 |
| 实时 WPS | execution 状态机、取消、恢复 | 实时状态编排和刷新恢复 | 异步 start、状态查询/事件、阶段明细 |
| 上课包 | 包列表、恢复、manifest | 展开文件和版本关系 | 现有 manifest 可用时无需新增 |

新增契约和迁移采用 forward-only 方式，不修改已经发布的历史迁移。所有返回继续执行绝对路径和敏感键脱敏校验。

### 7.2 最小新增契约清单

下面的路径和字段名是实现建议，可以按现有 router 命名微调；业务语义和安全规则不可省略。

#### 课时准备度

```text
GET /semesters/{semester_id}/lesson-preparation-statuses
```

返回当前学期所有课时的手动进度、系统准备阶段、下一动作、阻塞原因和最新版本摘要；只读聚合，不另建一份会与真实对象漂移的“状态表”。

#### 映射逐条审核

```text
PATCH /semester-mapping-proposals/{proposal_id}/mappings/{mapping_id}
POST  /semester-mapping-proposals/{proposal_id}/apply
POST  /semester-mapping-proposals/{proposal_id}/reject
```

- proposal 中的每条 mapping 增加稳定 `mapping_id`；
- 行级审核保存 `decision`、教师修订值、可选原因和 `expected_revision`；
- `apply` 只应用已接受或已修改接受的行；仍有待决定行时拒绝提交；
- 修改和拒绝不再次调用模型、不产生费用；
- 来源状态指纹变化时整份 proposal 进入需重新核对状态。

#### 参考范围与 AI 候选题

```text
POST /lessons/{lesson_id}/reference-selection-preflight
POST /lessons/{lesson_id}/reference-selection-snapshots
POST /reference-selection-snapshots/{snapshot_id}/exercise-suggestion-preflight
POST /reference-selection-snapshots/{snapshot_id}/exercise-suggestion-runs
GET  /exercise-suggestion-runs/{run_id}
PATCH /exercise-suggestions/{suggestion_id}
```

- run 启动先持久化 operation 并返回 ID；
- suggestion 默认是草稿，包含来源版本、页、题目/答案区域、理由、不确定项和来源指纹；
- 接受 suggestion 时复用现有正式 `ExerciseCandidate` 创建和来源范围校验；
- 拒绝或修订持久化，刷新后仍存在；
- AI 不能创建 `teacher_verified` 答案状态；
- 模型未配置或未授权时，preflight 明确返回不可调用，人工路径继续可用。

#### 资源包冻结预检

```text
POST /lessons/{lesson_id}/resource-pack-preflight
POST /lessons/{lesson_id}/resource-packs
```

冻结输入至少显式携带 `material_link_ids`、`exercise_candidate_ids`、证据 ID、偏好和 preflight 来源状态指纹。服务端验证候选题依赖完整、资料属于当前课时且仍为已确认活动版本。

#### 课堂容量预览与来源定位

```text
POST /lesson-drafts/{draft_id}/capacity-preview
GET  /teaching-prep/references/{reference_id}
```

容量预览不保存新版本、不调用模型。引用解析返回安全的资料版本、单位和预览 URL，不返回本机绝对路径；如果现有引用 ID 已足够稳定，可在现有响应中直接增加定位投影而不新增独立路径。

#### PPTX 版本与异步 WPS

```text
GET  /lessons/{lesson_id}/pptx-versions
POST /pptx-versions/{version_id}/activate
GET  /pptx-versions/{version_id}/preview
POST /slide-plans/{plan_id}/pptx-executions   -> 202 + execution
GET  /pptx-executions/{execution_id}
```

- 版本列表只把通过验证的 published 文件列为可信版本；
- `activate` 采用 revision/当前指针冲突保护并记录激活历史；
- 执行 start 不同步等待整段 WPS 流程结束；
- 查询返回当前四段状态、计时、错误、恢复动作和安全下载状态；
- 若现有 execution GET 已满足查询要求，直接复用并补齐阶段投影，不重复建立接口。

## 8. 前端模块与 seam

### 8.1 原则

现有 `TeachingPrepHomeView.vue` 应变成薄的工作台宿主，不再负责整条链路的所有模板和交互。拆分目标是建立少量深 module，而不是把每张卡片机械拆成浅 module。

页面调用方只需要理解：

- 当前学期、课时、工作区和阶段；
- 每段是否可查看、可执行、需重新确认；
- 当前编辑是否已保存；
- 对应工作区提供的少量业务动作。

多请求加载顺序、来源失效、版本选择、取消恢复和路由同步应隐藏在工作台状态 module 内，不能散落在四个工作区调用方中。

### 8.2 建议 seam

#### `TeachingPrepWorkbench` module

Interface 负责：

```ts
type TeachingPrepStage = 'select' | 'materials' | 'plan' | 'slides' | 'package'

interface TeachingPrepWorkbench {
  context: WorkbenchContext
  stages: StageState[]
  openStage(stage: TeachingPrepStage): Promise<void>
  openLesson(lessonId: string): Promise<void>
  requestNavigation(target: NavigationTarget): Promise<NavigationDecision>
  refreshCurrentWorkspace(): Promise<void>
}
```

Implementation 隐藏：

- URL 查询参数和刷新恢复；
- 当前课时的数据装载与竞态保护；
- 阶段门禁和来源失效投影；
- 未保存编辑保护；
- 页面级加载、错误和重试；
- 当前版本、计划、执行和包之间的选择关系。

#### `ReferenceSelection` module

Interface 负责：编辑允许范围、预检、冻结快照、查看 operation 状态。Implementation 隐藏资料版本校验、模型发送范围、幂等、取消和失败恢复。

#### `ExerciseCandidateReview` module

Interface 负责：接受、拒绝、修正候选，建立人工候选和调整区域顺序。Implementation 隐藏 AI/人工来源差异、答案确认失效和候选版本处理。

#### `PresentationRelease` module

Interface 负责：审核计划、启动执行、观察进度、取消/恢复、列出/激活可信 PPTX、管理上课包。Implementation 隐藏 WPS operation、轮询或事件、文件验证和当前版本指针。

### 8.3 建议文件组织

文件名可在实现时按仓库习惯微调，但职责必须保持：

```text
frontend/src/workspaces/teaching-prep/
  views/
    TeachingPrepHomeView.vue             # 薄宿主
```

## 10. 故障场景与预期结果

| 场景 | 预期结果 |
| --- | --- |
| 重复点击阶段 | 只改变视图，不重复加载收费 operation，不创建重复版本。 |
| 重复保存/冻结/恢复 | 使用幂等键或 revision；安全复用结果或明确提示，不创建重复业务结果。 |
| 同时审核同一映射 proposal | 后提交者看到 revision/source hash 冲突；不覆盖先提交决定。 |
| 映射审核中资料产生新版本 | 审核草稿保留，但不能应用到变化后的来源；要求重新核对。 |
| AI 候选生成中重复点击 | 同一 operation 只调用一次模型；前端复用正在运行的任务。 |
| AI 未配置、无授权、超时或失败 | 不自动追加请求；保留参考范围和已保存人工候选；允许不选题继续或人工兜底。 |
| AI 候选引用参考池外资料 | 服务端拒绝整条越权候选并记录错误；不得进入教师审核或资源包。 |
| 教师修改 AI 建议区域 | 生成教师修订版本；旧答案确认失效；原 AI 建议仍可追溯。 |
| 冻结过程中来源变化 | 不发布半成品资源包；返回具体变化的资料和可重新确认动作。 |
| 返回上游修改已用于下游的资源 | 旧资源包、草稿、计划、PPTX 保留；下游标记需重新确认，不静默改写。 |
| 页面刷新或浏览器返回 | 恢复仍有效的工作区、课时和已保存版本；未保存内容按导航保护规则处理。 |
| WPS 执行中页面关闭 | 服务端 operation 继续或进入可识别中断；重新打开后恢复状态，不重复执行。 |
| WPS 取消 | 停止后续阶段；源文件不变；已批准计划保留；暂存按恢复动作处理。 |
| WPS 部分执行或验证失败 | 不发布可信 PPTX；显示失败阶段、已完成内容和恢复/清理动作。 |
| WPS 进度查询暂时失败 | 页面显示“状态暂不可达”并继续安全重查；不得据此启动第二次执行。 |
| 恢复历史 PPTX | 只更新当前指针并记录历史；不覆盖文件、不删除新版本、不自动切换班级上课包。 |
| 恢复版本时文件缺失或指纹不符 | 拒绝激活，保留当前版本，提示重新定位或使用其他可信版本。 |
| 应用或服务重启 | 从持久化 operation、当前版本指针和 staging 状态恢复；不能把中断显示为成功。 |

## 11. 自动化与人工验收

### 11.1 开发期间

- 每个相关批次只运行直接受影响的前端组件/store/API 测试和后端专项测试；
- 故障阻塞后续开发时才增加最小诊断；
- 不在每个页面后重复运行同一套大范围测试和正式复审；
- 所有文件、数据库、模型和 WPS 测试使用临时目录、临时数据库、合成资料和 Fake Adapter。

### 11.2 稳定候选集中验证

至少包括：

- `frontend/src/workspaces/teaching-prep/**` 受影响测试；
- `tests/teaching_prep/**` 完整测试；
- 前端类型检查和生产构建；
- 工作区查询参数、刷新恢复和未保存导航测试；
- 映射逐条审核与 revision 冲突测试；
- AI 参考池越权、重复调用、取消、失败和人工兜底测试；
- 资源包子集和来源变化测试；
- PPTX 列表、恢复、当前指针、执行刷新和中断恢复测试；
- WPS 候选未验证不得发布和源文件不变测试；
- 必要的应用壳层冒烟，确认只保留一个全局备课入口。

### 11.3 用户人工验收脚本

使用隔离页面和合成资料：

1. 打开备课工作台，查看新授课列表和已授课状态；
2. 点击五段中的每一段，确认都能进入且未满足门禁时说明明确；
3. 选择一个课时，刷新页面，确认课时和工作区恢复；
4. 导入或使用合成资料，在大预览中核对原页；
5. 对映射建议分别执行接受、修改、拒绝并应用；
6. 选择本次允许的教材、参考 PPT、教辅和答案页段；
7. 用 Fake AI 生成题目区域候选，接受一条、拒绝一条、修正一条；
8. 人工新增跨页题，调整区域顺序并确认答案；
9. 查看最终资源包发送范围并冻结新版本；
10. 修改课堂流程和题目时间，确认容量即时变化且引用可回原页；
11. 逐页查看原课件与建议执行后结果，审核风险和操作；
12. 用 Fake WPS 观察四段实时进度，刷新后继续显示；
13. 查看多个可信 PPTX 版本，单独恢复旧版本，再恢复新版本；
14. 展开上课包文件清单，确认 PPTX 恢复没有错误切换班级包；
15. 分别模拟来源变化、模型失败、WPS 取消、验证失败和应用重启；
16. 确认任何路径都未覆盖源 PPTX，也没有出现真实模型调用或真实数据读写。

## 12. 公共顶部栏依赖

当前全局 `AppTopbar.vue` 在备课页面仍显示“当前考试”。本轮产品目标是备课页面以当前学期/课时为上下文，但 `ITERATION_SCOPE.md` 明确禁止 A 分支自行修补公共热点。

处理方式：

- A 分支先完成自己的紧凑备课上下文，不让页面文案暗示“当前考试”控制备课资料；
- 另建独立的小型公共壳层任务，让工作区 manifest 声明顶部栏上下文或隐藏无关考试选择器；
- 公共修正验证并进入稳定主线后，本分支再同步；
- 不在本分支直接修改 `frontend/src/components/shell/AppTopbar.vue` 或全局路由。

这项公共依赖不阻塞四个 A 工作区和五段流程的实现，但会阻塞“备课页面不存在竞争上下文”的最终整体体验验收。
