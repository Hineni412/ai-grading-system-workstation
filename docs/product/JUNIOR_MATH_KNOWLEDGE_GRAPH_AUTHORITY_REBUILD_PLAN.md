# 初中数学知识图谱 2.1 权威化重建实施方案

> 状态：`implementation_candidate_complete`  
> 日期：2026-08-03  
> 实施分支：`codex/grading-system-iteration`  
> 起点：`fc87d470bc5c5f7decf8dfd1f3317a888dde3098`

## 1. 目标、范围与风险

### 目标

1. Codex 完成现有 294 个规范知识词的逐条处置和核心知识点映射。
2. 逐个复核原 70 个图谱稳定身份，补齐定义、边界、来源和替代规则。
3. 建立可追溯、可整体发布、可回退的项目标准知识图谱。
4. 题目批次向模型发送完整 294 词的紧凑目录，同时每题最多允许 1 个知识新词观察。
5. 教材册、章、节继续使用权威闭集，AI 不得自由创造。

### 包含

- 阅卷系统、题库、知识关系、解题证据、掌握度 v2 和 P4 推荐直接需要的目录、服务、API、页面、迁移、测试和文档。
- 294 个词的定义、包含/排除边界、课标主题、教材证据、处置类型和核心映射。
- 核心节点的 `parent / prerequisite / related` 关系与证据。
- 图谱发布版本、预演、原子启用、差异和回退。
- 新词观察的即时归并、周期聚类和版本晋升。

### 不包含

- 不修改备课工作台或班主任工作台的专属代码、迁移、数据和页面。
- 不读取或迁移真实 `user_data/`，不运行真实数据库迁移。
- 不调用真实模型、不使用真实密钥、不产生费用。
- 不重算或改写真实历史掌握度。
- 不 push、不创建 PR、不同步 `main`；后续每一步仍需单独授权。
- 不把本项目图谱宣称为教育部发布的官方唯一图谱。

### 风险等级

高。错误映射或关系会让学生证据归错、掌握度解释漂移或推荐顺序失真。

## 2. 冻结的产品决定

### 三层体系

| 层 | 用途 | 能否直接影响掌握度 |
|---|---|---|
| 核心可测节点 | 长期关系、掌握度、薄弱点和推荐 | 是 |
| 294 个精细知识词 | 逐题准确标签、检索和证据描述 | 经确认映射后参与 |
| 临时新词观察 | 发现词表缺口和积累语料 | 否 |

294 个词不强制一对一成为 294 个核心节点，也不强制压入旧 70 个节点。最终核心数由可测性、边界和数学关系决定。

### 294 个词的六种处置

- `direct_core`：词条本身是核心节点。
- `maps_to_core`：保留精细词，映射一个核心节点。
- `maps_to_many`：确实跨多个独立核心节点，并标明主要/次要作用。
- `retrieval_only`：适合搜题，不参与掌握度。
- `wrong_dimension`：实质属于方法、模型、题型或情境。
- `retired`：重复、错误或不稳定；保留历史替代去向。

294/294 必须有显式处置，不允许用空映射掩盖未完成工作。

### 两类先修

- `mathematical_required`：数学定义、推导或正确使用上的必需依赖，可影响推荐顺序。
- `teaching_recommended`：多版本教材或教师通常采用的教学顺序，只作软性提示。

两者继续复用公开关系类型 `prerequisite`，但以结构化 `basis_kind` 和 `strength` 区分，保持现有 API 的三类关系兼容。

## 3. 294 词映射由 Codex 完成

每个词必须记录：

- 原稳定 ID 和规范名；
- 一句话定义；
- 包含与排除边界；
- 课标领域、主题和内容锚点；
- 至少三个审定教材版本的定位证据或“教材不一致”说明；
- 六类处置之一；
- 一个或多个核心节点及主要/次要/上下文作用；
- 理由、来源和置信等级；
- 是否属于高影响分歧。

教师不逐行填写 294 条，只集中确认以下高影响清单：

- 旧核心节点拆分、合并或退役；
- 一对多核心映射；
- 维度纠正和超出初中常规范围的词；
- 数学必需先修与教学建议先修的方向争议。

## 4. 发布包与模块边界

发布源文件固定为：

`question_bank/taxonomy/catalogs/knowledge_graph_release_v1.json`

它原子包含：

- 发布 ID、基础词表版本和内容指纹；
- 核心节点资料；
- 294 条处置和映射；
- 关系及结构化证据；
- 旧 70 身份的保留、退役和替代；
- 来源清单。

新增一个深模块 `question_bank/knowledge_graph_release/`，对外只暴露：

- `load_release()`；
- `validate_release()`；
- `preview_install()`；
- `activate_release()`；
- `rollback_release()`。

标签、关系、掌握度和推荐不得各自解析发布 JSON；全部经此模块或现有仓库接口读取。

## 5. 数据契约

下一份题库迁移增加：

- `knowledge_graph_releases`：候选、活动、退役和失败版本；
- `knowledge_graph_node_profiles`：节点定义、边界、课标锚点和可观察证据；
- `knowledge_relation_evidence`：关系依据、强度、来源位置和适用版本；
- `knowledge_identity_replacements`：退役身份的一对一或一对多替代；
- 现有精细词映射的处置、作用和发布版本；
- 证据版本使用的 `graph_release_id`。

现有身份、映射、关系审核和审计表继续复用，不建立第二套竞争系统。

## 6. 完整 294 词批次请求

同一物理题目批次只发送一份：

- `ID + 规范名 + 课标主题`；
- 易混词的短边界；
- 当前教材册、章、节的闭集 ID。

不发送全部图谱边、历史别名和长篇定义。为兼容现有七维标签契约，模型返回受控规范名，并为主知识返回稳定 ID；
本地程序把全部规范名精确解析为精细词 ID，再确定性连接核心节点。模型不能返回目录外名称冒充正式知识点。

每题最多提出 1 个新知识词，必须包含定义、最近现有 ID 和不能复用原因。方法、思想、模型、能力、题型和教材章节均不得自由造词。

每个任务冻结 `taxonomy_revision` 与 `graph_release_id`；任务运行中发布新版本，不改变该任务的词表和映射。

## 7. 新词长期治理

1. 完全同名、确认别名和旧 ID 即时本地归并，不调用模型。
2. 其他新词按定义和代表题目聚类。
3. 30—50 个归一化候选簇或一个月先到者触发周期治理；高频或高影响词立即进入审核。
4. 200 个只作为单次批量上限，不作为必须等待的门槛。
5. AI 只返回 `exact / close / broader / narrower / related / new_core_candidate / wrong_dimension / reject` 建议。
6. 教师确认后才形成下一版词表和图谱发布包。

## 8. 故障场景

| 场景 | 预期结果 |
|---|---|
| 重复发布 | 同一发布 ID 只生效一次 |
| 并发发布 | 只有基于当前活动版本的一方成功 |
| 中途退出 | 单一事务回滚，旧版本保持活动 |
| 应用重启 | 从持久发布记录恢复，不重新调用模型 |
| 取消 | 候选保留，活动图谱不变 |
| 294 未全部处置 | 阻止发布 |
| 映射或关系冲突 | 预演列出冲突，不覆盖已有教师决定 |
| 运行任务遇到新发布 | 旧任务继续使用冻结版本 |
| 回退 | 新任务回到旧活动版，历史证据不重写 |
| 真实库有未知教师关系 | 只读预演并停止，另行请教师决定 |

## 9. 实施顺序

1. `KG-R1`：研究、领域词汇、发布 Schema、校验器和迁移。
2. `KG-R2`：Codex 完成 294 词账本、旧 70 身份处置和核心节点资料。
3. `KG-R3`：建立有证据的上下位、数学必需先修、教学建议先修和相关关系。
4. `KG-R4`：原子安装、差异、回退及历史版本固定。
5. `KG-R5`：题目批次改为完整 294 词 ID 契约。
6. `KG-R6`：新词聚类、关键分歧和发布确认页面。
7. 整体候选形成后集中测试、构建、跨模块冒烟和一次双复审。

小阶段连续实施，不逐包做正式测试或复审；只有阻塞后续开发时运行最小诊断。

## 10. 验收条件

- 294/294 有显式处置；映射核心均存在且活动状态合法。
- 每个活动核心有定义、包含/排除、课标来源和可观察证据。
- 旧 70 身份全部有保留、转上位、退役或替代记录。
- 1063 个旧名称和 1185 个旧 ID 仍可读取或明确退役。
- `parent` 和 `prerequisite` 无环；节点对不存在语义冲突。
- 每条正式关系都有证据、理由、强度、版本和审核状态。
- 批次提示只发送一份完整 294 词目录，返回只接受允许 ID。
- 新词每题最多 1 个，未晋升时不影响掌握度和推荐。
- 发布原子、幂等、并发安全且可回退。
- 历史题目、解题证据、训练判定和推荐结果保留原图谱版本。
- 只使用合成数据和临时数据库完成集中验证。

## 11. 授权边界

当前授权允许在 `codex/grading-system-iteration` 连续实现本方案。真实数据、真实模型、真实数据库迁移、服务重启、push、PR、合并集成预览或同步 `main` 仍需逐次明确授权。

## 12. 当前候选结果

- 294/294 个规范知识词已有显式处置；发布包包含 70 个活动核心节点、7 个退役旧节点、301 条映射和 48 条关系。
- 旧 70 身份逐个保留或给出退役替代；33 个高影响分歧集中进入教师账本，不要求教师逐行填写 294 条。
- 完整知识目录改为每个物理批次只发送一次；每题最多提出 1 个真正未知的知识新词。
- 候选发布、冲突预演、教师确认、原子启用、并发保护和回退已经接入后端与审核页；候选阶段不会提前启用新身份或别名。
- 运行任务和新解题证据绑定当时活动的图谱发布 ID；回退后新任务随活动版本回退，历史证据不改写。
- 本候选没有读取真实 `user_data`、没有调用真实模型、没有执行真实数据库迁移，也没有启动或替换当前服务。

## 13. 集中验证结果

- 生成一致性、Python 语法、前端类型检查和生产构建通过。
- 本任务最终直接回归：后端 92 项通过；补充发布/API 回归 13 项通过；审核页 10 项通过；并行超时的两份前端文件单独复跑 62 项通过。
- 仓库 `full` 套件结果为后端 2685 项通过、26 项失败、2 项跳过；前端 952 项通过、2 项并行时限失败。前端两项单独复跑通过；后端失败集中在本任务起点已存在的评分依据修复、班主任迁移、旧文档契约和并发时序，未据此扩大本任务。
- 因仓库全量基线仍有上述范围外失败，当前功能候选通过本任务验收，但整个版本不能据此发布；且尚未进行真实数据库迁移、真实模型试跑或教师页面人工确认。
- 本轮没有启动正式双代理复审；后续若要合入集成预览或发布，需按届时授权和仓库规则处理范围外基线失败并完成必要复审。
