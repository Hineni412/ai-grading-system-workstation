# 集成预览正式收口计划（2026-08-06）

> 分支：`codex/grading-system-iteration`
> 固定起点：`main@e63136c6c5471f358cfaf11065f5b92b0f46ca10`
> 风险等级：高（公共启动入口、全项目候选、真实数据替换、本地 `main` 合并）
> 用户授权：2026-08-06 明确授权完成必要修复、精简 BAT、全项目测试与复审、用本分支预览数据替换根目录旧数据并合并本地 `main`。

## 1. 目标

把当前集成预览收成一个可以替代旧 `main` 的稳定本地版本：关闭五册知识标准终审遗留的三个阻塞问题；只保留正式启动、集成预览和关闭系统三个 BAT；集中验证 `main...HEAD` 的完整项目差异；只修复有实际证据的 `Critical` / `Important`；建立可回退备份后，用集成工作树的隔离数据替换根目录旧数据；最后将本地 `main` 快进到通过验收的冻结提交。

## 2. 包含内容

- 修复五册知识标准最终复审登记的三个 `Important`：解题证据越界链接、运行中知识发布切换后的观察快照、提案持久化链词表修订号传递。
- 根目录最终只保留 `运行.bat`、`运行集成预览.bat`、`关闭系统.bat`；命令行测试入口继续存在，不再为测试保留 BAT。
- 去掉启动和关闭界面中的 P3.5 阶段称呼；集成预览按当前分支与当前提交构建、校验，不再依赖已经完成历史使命的“三分支检查点”组合守卫。
- 评估旧兼容代码。只删除已证明无调用方、且本次整套测试覆盖其替代路径的启动/预览阶段兼容；历史数据迁移、旧标签唯一映射和当前预览数据仍需要的读取兼容不删除。
- 运行仓库 `release` 验收车道（包含完整后端、串行隔离、前端规范/测试/构建、发布与打包检查），再以 `main` 为固定点完成需求与代码质量并行评审。
- 全部代码验收通过后，停止并核验 8035 服务；把根目录旧 `user_data` 原目录移动到同卷、工作区内、未跟踪的时间戳回退目录；在独立暂存目录中复制 `codex/integration-usability-candidate` 浏览器验收所使用的非空隔离数据，并用 SQLite 一致性备份生成数据库；校验完成后再发布为根目录新 `user_data`。当前开发工作树的 `user_data` 只有空目录骨架，明确禁止把它误当数据源。
- 本地 `main` 只允许快进到最终冻结提交；合并后再运行启动/数据边界和关键跨模块检查。

## 3. 明确不包含

- 不 push，不创建 PR，不同步远端 `origin/main`。
- 不调用真实模型，不使用真实密钥，不产生费用。
- 不用真实成绩、答卷或资料执行写入式业务验收；数据操作只做用户明确要求的整目录替换和只读完整性核验。
- 不执行额外真实数据库迁移，不激活新知识图谱发布包，不批量改写历史标签或掌握度。
- 不因“全项目复查”修复没有实际触发证据的风格建议、理论风险或范围外新需求。
- 不删除仍被现有数据、迁移链、旧标签唯一映射、回退或审计所依赖的兼容代码。

## 4. 冻结问题清单

1. 新版每题知识候选边界没有贯穿解题证据保存链，未来册或另一题知识可能残留在正式链接中。
2. 同一治理实例在 rev3 / rev4 激活或回滚后，观察快照仍可能使用构造时的旧词表。
3. 标签作业、联合分析适配器和试卷导入的提案持久化阶段没有继续携带冻结词表修订号。
4. 用户可见启动与关闭脚本仍强调已结束的 P3.5；根目录有四个不再需要的测试/冒烟 BAT。
5. 旧“三合一预览”守卫固定要求历史组合分支，最终合入 `main` 后不能作为通用预览入口。
6. 当前完整集成候选尚未以 `main` 为固定点执行一次仓库级 release 测试和双轴正式评审。
7. 根目录真实数据过旧；用户要求由本分支隔离预览数据完整替换，但替换前必须建立可回退备份并排除运行中复制、半复制和 SQLite WAL 不一致。

调查后发现的修改前问题或相邻新需求单独记录；只有本清单和后续正式评审中证据充分的当前范围 `Critical` / `Important` 可以进入统一修复。

## 5. 验收条件

1. 三个知识标准阻塞项均有实际保存链或版本切换测试，旧 rev3 兼容行为不回归。
2. 项目根目录恰有三个 BAT：`运行.bat`、`运行集成预览.bat`、`关闭系统.bat`；启动、关闭、帮助和错误提示不再把当前系统称为 P3.5。
3. 正式启动仍只使用当前工作树代码和当前 `user_data`；集成预览仍强制本工作树隔离数据、构建当前提交并拒绝旧页面冒充新页面。
4. `release` 车道通过；若存在修改前失败，必须证明来源、影响和是否阻塞，不能静默排除。
5. `git diff main...HEAD` 的需求与代码质量评审检查同一冻结提交；当前范围无未解决 `Critical` / `Important`。如初审发现阻塞，只统一修复一次并限定复审一次。
6. 数据源固定为 `.worktrees/integration-usability-candidate/user_data`，目标固定为根目录 `user_data`；两者与回退路径均为已核对的普通目录且位于预期工作区。替换前服务已停止；两个 SQLite 主库通过一致性备份与 `integrity_check`；暂存文件清单验证通过。
7. 根目录旧数据可由时间戳备份原路恢复；新根目录数据与预览源的受控文件清单一致，数据库逻辑内容来自同一一致性快照；真实数据不进入 Git 暂存或提交。
8. 本地 `main` 只做快进合并；合并后代码工作树除真实 `user_data` 和既有未跟踪本机产物外没有未知代码修改，关键启动/数据边界测试通过。

## 6. 故障场景

| 场景 | 预期结果 |
|---|---|
| 重复执行收口 | 已通过的提交和已发布数据清单可识别；不重复合并，不覆盖唯一回退备份 |
| 同时运行服务与替换数据 | 先按进程身份安全关闭并复核 8035；不能唯一识别时停止替换 |
| 数据复制中途退出 | 只留下独立暂存目录；根目录旧 `user_data` 保持原位 |
| 旧目录移走后发布失败 | 立即把已核对的时间戳目录原路恢复，不以空目录启动 |
| SQLite 存在 WAL/SHM | 通过只读连接的一致性备份生成目标主库，不直接拼接复制三个文件 |
| 失败重试 | 清理或另建明确暂存目录后从源重新生成；不在半成品上续写 |
| 取消 | 数据交换前取消不改变根目录；交换后按回退目录恢复 |
| 部分完成 | 文件清单、大小、数据库完整性或关键路径任一失败都阻止发布和 `main` 收口 |
| 源缺少目标旧文件 | 按用户“用本分支数据覆盖”要求采用镜像语义；旧文件只留在回退备份，不混入新数据 |
| Git 合并冲突或非快进 | 停止；不强制合并、不丢弃提交、不覆盖根目录未知修改 |

## 7. 发布边界

本计划只授权本机代码与数据收口。最终本地 `main` 和新 `user_data` 通过验证后仍不自动推送远端，也不自动重启服务。若需要远端发布或重新启动真实服务，另按届时明确目标执行。
