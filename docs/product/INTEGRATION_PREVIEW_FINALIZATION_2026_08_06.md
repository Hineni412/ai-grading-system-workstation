1. 新版每题知识候选边界没有贯穿解题证据保存链，未来册或另一题知识可能残留在正式链接中。

4. 用户可见启动与关闭脚本仍强调已结束的 P3.5；根目录有四个不再需要的测试/冒烟 BAT。
5. 旧“三合一预览”守卫固定要求历史组合分支，最终合入 `main` 后不能作为通用预览入口。
6. 当前完整集成候选尚未以 `main` 为固定点执行一次仓库级 release 测试和双轴正式评审。
7. 根目录真实数据过旧；用户要求由本分支隔离预览数据完整替换，但替换前必须建立可回退备份并排除运行中复制、半复制和 SQLite WAL 不一致。

调查后发现的修改前问题或相邻新需求单独记录；只有本清单和后续正式评审中证据充分的当前范围 `Critical` / `Important` 可以进入统一修复。

1. 三个知识标准阻塞项均有实际保存链或版本切换测试，旧 rev3 兼容行为不回归。

## 6. 故障场景

| 场景 | 预期结果 |
|---|---|
| 重复执行收口 | 已通过的提交和已发布数据清单可识别；不重复合并，不覆盖唯一回退备份 |
| 同时运行服务与替换数据 | 先按进程身份安全关闭并复核 8035；不能唯一识别时停止替换 |
| 数据复制中途退出 | 只留下独立暂存目录；根目录旧 `user_data` 保持原位 |
| 旧目录移走后发布失败 | 立即把已核对的时间戳目录原路恢复，不以空目录启动 |
| SQLite 存在 WAL/SHM | 通过只读连接的一致性备份生成目标主库，不直接拼接复制三个文件 |
| 失败重试 | 清理或另建明确暂存目录后从源重新生成；不在半成品上续写 |
| 取消 | 数据交换前取消不改变根目录；交换后按回退目录恢复 |
| 部分完成 | 文件清单、大小、数据库完整性或关键路径任一失败都阻止发布和 `main` 收口 |
| 源缺少目标旧文件 | 按用户“用本分支数据覆盖”要求采用镜像语义；旧文件只留在回退备份，不混入新数据 |
| Git 合并冲突或非快进 | 停止；不强制合并、不丢弃提交、不覆盖根目录未知修改 |
