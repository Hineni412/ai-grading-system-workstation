## 1. 结论

备课工作台不是一个“让 AI 从零写教案、生成整套课件”的通用工具，而是一个面向教师真实备课过程的个人工作台：

> 沿用成熟的新授流程，删除课堂容量不合适的练习，再根据教材、教辅和本班已有证据补入少量关键题，经过教师审核后，生成可以直接用 WPS 上课的 PPTX。

首版的最终成果不是一段备课文字，而是：

1. 一份来源清楚、经过教师确认的本节课资源包；
2. 一份有证据说明的重难点与课堂练习建议；
3. 一份逐页可审核的课件改编方案；
4. 一份不覆盖原文件、可在 WPS 中直接放映的定稿课件。

## 2. 设计目标与任务边界

### 2.1 目标

- 减少教师反复翻阅教材、参考 PPT 和多套教辅的时间；
- 保留已有优质 PPT 的新授流程和视觉风格；
- 根据课堂容量删除大部分不适用练习；
- 从学生实际使用的教辅中筛选少量课堂题；
- 用已有班级学情证据辅助判断，而不是代替教师判断；
- 让所有 AI 建议都能回到教材页、幻灯片、教辅题或考试证据；
- 最终生成教师愿意直接用于下一节真实课堂的 WPS 课件。

### 2.2 明确不包含

首版不建设以下能力：

- 从零生成整套 PPT；
- 一次性自动整理完整学年所有资料；
- 自动学习几十份课件并训练所谓“教师风格模型”；
- 自动编写新数学题及答案；
- 自动预测尚未学习内容的错误；
- 个体学生学习推荐；
- 新的知识先修关系、掌握度模型或训练回流；
- 自动修改复杂动画、SmartArt、视频、宏和插件对象；
- 多教师协作、云端资源共享和商业化资源分发。

### 2.3 风险等级

整体风险为中高。

主要风险依次为：

1. WPS 改编现有 PPTX 后的文件保真；
2. 教辅题目和答案的准确对应；
3. 教材页、课件页和教辅题与课时的准确映射；
4. AI 将推断写成事实；
5. 外部模型调用中的资料传输、费用和失败处理。

## 3. 教师当前真实工作流

以一节新授课为例，当前工作流通常是：

1. 根据授课课时翻阅教材对应内容；
2. 查看参考 PPT，明确新授流程；
3. 直接沿用参考 PPT 的大部分新授结构；
4. 删除其中大部分练习，因为学生没有配套纸质材料或课堂容量不足；
5. 教师亲自完成学生所用教辅中的习题；
6. 结合本班已有学情判断本节课的重难点；
7. 在课件中保留或增加少量关键题；
8. 人工调整并形成最终授课课件。

备课工作台不改变这套专业判断，而是减少其中反复定位、比较、搬运和记录的工作。

## 4. 目标工作流

```mermaid
flowchart LR
    A["选择个人课时"] --> B["确认教材页、参考幻灯片和教辅题"]
    B --> C["冻结本节课授课资源包"]
    C --> D["AI分析重难点、题型和课堂容量"]
    D --> E["生成逐页课件改编方案"]
    E --> F["教师逐项接受、修改或拒绝"]
    F --> G["WPS在课件副本上执行"]
    G --> H["预览并标记为定稿课件"]
```

工作流分成一次性准备和每节课重复使用两部分。

### 4.1 一次性准备

- 从现有教材章节树复制出个人授课结构；
- 按真实进度把一个小节继续拆成多个课时；
- 导入教材 PDF、参考 PPTX、教辅和答案册；
- 为材料建立页面或幻灯片预览；
- 将教材页、参考幻灯片和教辅范围挂到对应课时；
- 保留原材料版本和文件指纹，原文件只读。

### 4.2 每节课的五步

#### 第一步：选择下一课时

教师从个人授课课时树中选择，不必每次重新在聊天框描述章节。

#### 第二步：核对资源定位

系统可以给出候选范围，但教师必须确认：

- 本节对应的教材页；
- 参考 PPT 的基准课件和幻灯片范围；
- 多套教辅中对应的页面和题目；
- 答案或解析所在位置；
- 可使用的班级学情证据范围。

每一项都可以打开原页或原幻灯片核对，不能只显示 AI 摘要。

#### 第三步：确定重难点和课堂题

系统输出：

- 建议保留的新授流程；
- 建议隐藏或删除的原有练习页和页内对象；
- 多套教辅中的少量课堂练习候选；
- 每道候选题承担的教学作用；
- 重难点的具体依据；
- 预计课堂时间和容量提醒。

教师最终选择真正进入课堂的题目，通常控制在 1—3 道。

#### 第四步：审核课件改编方案

系统先展示逐页变更，不直接改文件。每项至少包含：

- 第几页；
- 保留、隐藏、删除、移动、改写、复制或新增；
- 涉及哪些页内对象；
- 改动原因；
- 引用的教材页、教辅题或学情证据；
- 改动后的预览。

教师可以逐项接受、修改或拒绝。

#### 第五步：生成定稿课件

- WPS 只打开课件副本；
- 只执行教师已经确认的操作；
- 生成带版本号的新 PPTX；
- 用 WPS 重新打开并渲染核对；
- 教师确认后标记为该课时的定稿课件；
- 下次修改从已确认版本复制，不从头重做。

## 5. 统一业务词汇

### 个人授课课时树

教师自己的实际授课安排。它以教材目录为主干，但允许继续拆分课时、改变顺序并加入复习课、讲评课和专题课。

### 课时节点

个人授课课时树中的一次具体授课单元，保存教师标题、顺序、预计时长和已确认资料范围。

### 授课资源包

某个课时已经由教师确认的教材页、参考幻灯片、教辅题、答案和学情证据集合。AI 只能在该范围内生成正式建议。

### 基准课件

教师选择作为本节课改编起点的参考 PPTX。系统始终修改它的副本，不覆盖原件。

### 课堂练习候选

系统从已确认教辅范围中提出、等待教师选择的题目。候选不等于会进入课件。

### 已验证答案

由教师明确核对过来源和内容的答案或解析。程序成功定位到答案页，不等于答案已经验证。

### 学情证据

来自教师明确选择的考试、题目和精确知识点标签的班级汇总事实。它不是对学生未来表现的预测。

### 课件改编方案

一组尚未写入 PPTX 的逐页、逐对象变更建议。只有教师确认的操作才能交给 WPS 执行。

### 定稿课件

教师确认可以用于真实课堂的某个 PPTX 版本。定稿是版本状态，不会覆盖基准课件。

## 6. 信息与判断必须分层

重难点和课堂题建议必须区分五类来源：

| 来源 | 含义 |
|---|---|
| 教材依据 | 教材中明确出现的目标、例题、活动和要求 |
| 参考课件依据 | 基准课件采用的新授顺序、例题和强调方式 |
| 教辅共同题型 | 多套已确认教辅中重复出现的题型或变式 |
| 班级学情证据 | 当前系统已有、覆盖范围明确的班级汇总成绩证据 |
| AI 建议 | 模型根据上述材料作出的分析，尚未成为教师决定 |

最终重难点和课堂练习选择属于教师决定。

没有相应证据时，系统必须显示“当前无可用学情依据”，不能用模型常识伪装成本班考情。

## 7. 界面结构

系统左侧已有功能下方只增加一个一级入口：

> **备课工作台**

内部包含四个工作区：

这四个工作区是围绕“课时”逐步下钻的稳定工作面，不再为每一种 AI 能力或输出物增加新的侧边栏入口。功能应在教师处理当前课时、资料、候选题或课件版本时按情境出现：

| 延伸能力 | 自然出现的位置 | 触发方式 |
|---|---|---|
| 一页纸课堂练习单和教师答案版 | 本节备课的课堂题区域 | 教师选定课堂题后，作为“生成上课包”的输出选项 |
| 课堂容量规划 | 本节备课的课堂流程和候选题区域 | 增删环节或题目时同步更新预计用时 |
| 同课异班版本 | 课时节点和课件版本 | 为同一课时创建班级变体，只覆盖差异项 |
| 课后一分钟复盘 | 已定稿课件对应的课时详情 | 课后对具体页面、题目或教学环节补充复盘 |
| 课前安全体检和离线上课包 | 已生成或定稿版本 | 输出前执行 WPS 重开、渲染和资源可用性检查 |
| 讲评课工作流 | 新建“讲评课”类型的课时节点 | 可从成绩中心带着教师选中的匿名班级证据进入本节备课 |
| HTML交互素材 | 某道候选题或某个教学环节 | 教师明确选择“需要交互演示”时才创建 |

同一能力可以从相关页面提供快捷入口，但最终都回到同一个课时、授课资源包、改编方案或课件版本，不创建另一套业务记录。

### 7.1 个人课时树

- 按册、章、小节浏览；
- 按需继续拆分课时；
- 调整顺序和预计时长；
- 关联教材官方小节，但不反向修改全局教材目录；
- 查看每个课时的资料完整度和历史定稿。

首版采用渐进建立：教师准备到哪个小节，就整理到哪个小节，不要求先录完整册。

### 7.2 本节备课

这是主要工作页，回答四个问题：

1. 本节课准备教什么？
2. 引用了哪些资料？
3. 为什么确定这些重难点和课堂题？
4. 最终准备怎样改课件？

### 7.3 资料库

- 教材；
- 参考课件；
- 教辅；
- 答案册；
- 教案和补充资料；
- 页面、幻灯片和材料版本。

资料库不做通用文件浏览器，只管理教师明确导入的教学资料。

### 7.4 课件版本

- 草稿；
- 待审核；
- 已生成；
- 定稿；
- 已废弃。

所有版本都保留来源和改编方案，原件不可被覆盖。

界面视觉继续遵守 `docs/ui/STYLE.md`：安静、专业、高密度但不拥挤，不采用聊天气泡中心化或营销式大屏。

## 8. 核心业务对象

### PersonalLessonTree

个人授课课时树。允许从教材目录建立，但独立保存教师自己的课时拆分、顺序和版本。

### LessonNode

课时节点。包含稳定身份、标题、顺序、时长、状态和可选的教材小节关联。

### Material

不可变的资料原件。记录资料类型、文件指纹、版本和处理状态。

### MaterialUnit

资料中的最小可引用单位，例如 PDF 页、PPT 幻灯片、图片或 DOCX 逻辑块。

### LessonMaterialLink

课时节点到资料单位的明确映射，记录用途、顺序、教师备注和确认状态。

### ExerciseCandidate

课堂练习候选，保存题目原图、来源、用途、答案状态和教师选择结果。

### EvidenceSnapshot

生成某次备课分析时冻结的只读学情证据，包含考试范围、班级范围、题目引用、覆盖率、缺失项和生成时间。

### LessonDraft

结构化备课草稿，引用具体资料单位、已验证题目和学情证据。

### SlidePlan

逐页课件改编方案，记录保留、隐藏、删除、移动、复制、改写和新增操作。

### PptxVersion

由某个已确认改编方案生成的课件版本。原件、草稿、已生成和定稿之间具有明确关系。

## 9. 模块设计

备课能力应成为独立的 `teaching_prep` 模块，而不是把全部资料塞进现有阅卷库或题库。

这个模块的外部 Interface（调用方必须知道的最小使用方式）只暴露五类行为：

1. 建立或调整个人课时；
2. 确认某课时的授课资源包；
3. 生成并编辑备课草稿；
4. 生成并确认课件改编方案；
5. 从确认方案生成、核对并定稿课件版本。

复杂的文件解析、题目裁图、模型提示、WPS 操作、版本管理和恢复都留在模块内部，使该模块保持较深的实现，而不是把复杂度分散到各页面。

### 9.1 与现有系统的 Seam 和 Adapter

| Seam | Adapter | 作用 |
|---|---|---|
| 教材目录读取 | 现有教材目录 Adapter | 只用于创建个人课时树的初始模板 |
| 题库候选读取 | 现有题库 Adapter | 只读取得教师明确选择范围内的候选题 |
| 学情证据读取 | 现有诊断 Adapter | 只读生成带覆盖说明的班级证据快照 |
| 模型调用 | 现有 LLM Gateway Adapter | 统一超时、费用、错误分类和禁止自动重试 |
| 演示文稿执行 | WPS Adapter | 在副本上执行已确认的课件改编方案 |

不建立跨数据库外键，不把备课失败变成阅卷或题库写入失败，也不把备课结果自动回写为新的掌握度或训练任务。

### 9.2 建议的独立保存范围

模块单独拥有：

- 课时树；
- 教师资料库及版本；
- 资料单位预览；
- 课时与资料映射；
- 题目与答案裁图；
- 学情证据快照；
- 备课草稿；
- 课件改编方案；
- 课件版本。

真实保存路径必须在实施时通过现有 `PathManager` 增加受控根，不接受客户端提交任意服务器绝对路径。

## 10. 资料定位策略

首版不以向量数据库或 RAG 为前置条件。

优先顺序为：

1. 教师确认的课时—资料显式映射；
2. 材料目录、页码、幻灯片号和题号；
3. 本地全文和关键词检索；
4. 材料规模明显增大后，再增加向量检索作为候选排序。

即使以后增加向量检索，正式授课资源包仍必须由教师确认。

## 11. 教辅题目和答案

### 11.1 题目处理

- 电子 PDF 可以尝试按题号自动定位；
- 扫描 PDF 必须提供人工画框兜底；
- 一道题可以由多个有序区域组成；
- 跨页题目允许保存多个区域；
- 公式、几何图和复杂排版优先以高清裁图进入课件，不依赖 OCR 重排。

### 11.2 答案状态

建议状态为：

- `candidate`：已找到候选答案；
- `teacher_verified`：教师已核对；
- `rejected`：教师确认不匹配；
- `missing`：当前没有答案。

只有 `teacher_verified` 可以作为正式标准答案依据。原件、页码或裁图发生变化后，验证状态自动失效。

教辅题默认只属于备课模块；只有教师明确选择“加入题库”时，才进入现有题库流程。

## 12. 学情证据边界

首版学情能力采用只读方式：

- 只读取教师明确选择的考试和班级；
- 只使用已经关联题库、且具有精确知识点标签的证据；
- 展示考试日期、题目数、学生数、覆盖率和缺失项；
- 默认只向模型发送班级聚合结果，不发送姓名、学号或答卷；
- 没有证据时不做推断；
- 不创建知识先修关系；
- 不更新学生掌握度；
- 不自动生成训练任务。

因此，备课工作台不会自己实现或写入 Phase 4。Phase 4 尚未交付时读取现有考试与标签证据；Phase 4 交付后，只通过稳定 Adapter 读取教师明确选择的已发布证据。两种情况下都不回写掌握度、训练任务或个性化卷。

## 13. AI 的职责

### 13.1 AI 可以做

- 分析教材、参考课件和教辅共同强调的内容；
- 识别参考课件中的新授流程和练习页；
- 提出重难点、题型和课堂容量建议；
- 对候选题说明教学用途；
- 生成结构化备课草稿；
- 生成逐页、逐对象课件改编方案；
- 根据教师反馈修改方案。

### 13.2 AI 不可以做

- 未经教师确认扩大资料范围；
- 把推断写成事实；
- 自动确认题目答案；
- 自动决定学生心理、家庭或能力原因；
- 直接覆盖原 PPTX；
- 未经审核执行课件改动；
- 失败后自动追加付费请求；
- 把个人学生信息发送给模型；
- 自动写回题库标签、学生掌握度或训练任务。

### 13.3 调用方式

大模型不直接操作 WPS。它返回结构化改编方案，本机工作台校验后交给 WPS Adapter 执行。

一轮典型操作为：

1. 本机提取教师确认的页面、幻灯片预览和必要文字；
2. 大模型生成结构化建议；
3. 工作台显示人类可读的变更清单；
4. 教师确认；
5. 本机执行，不再为普通删页、调序和保存产生模型费用。

## 14. WPS 课件改编

### 14.1 首版支持

- 打开基准课件副本；
- 保留原幻灯片；
- 隐藏或删除幻灯片；
- 调整幻灯片顺序；
- 在同一课件内复制现有页面；
- 修改教师确认、且通过格式预检的统一格式普通文本框；
- 删除教师确认的文字框、图片、线条或组合对象；
- 移动、缩放、裁剪或替换未绑定动画的普通静态图片；
- 从原课件版式复制练习页；
- 插入教师确认的题目裁图；
- 在现有版式上新增普通页面，并插入统一格式文本框或静态图片；
- 另存为新的 PPTX 版本；
- 用 WPS 重新打开和渲染核对。

### 14.2 暂不承诺

- 旧 `.ppt`；
- 宏课件和 ActiveX；
- 受密码保护文件；
- 跨课件复制复杂页面；
- 修改复杂公式对象内部结构；
- 自动改写包含多字体、多字号或数学混排的复杂文本框；
- 修改 SmartArt、嵌入 Excel、视频和第三方插件对象；
- 替换或重组绑定对象动画的图片；
- 自动制作或重排复杂动画；
- 在 Microsoft PowerPoint 中的完全一致性。

本系统的唯一验收环境是用户日常使用的 WPS 演示。

### 14.3 页内对象的处理方式

WPS 将普通页面拆成文字框、图片、形状、组合和其他对象。工作台应先建立对象地图：

- 对象名称和类型；
- 所在页；
- 可见区域；
- 文字摘要；
- 是否属于组合；
- 是否来自母版；
- 是否允许改写或删除。

AI 依据幻灯片截图和对象地图提出语义目标，工作台再把语义目标绑定到具体对象。教师审核时看到的是页面预览和框选区域，而不是对象编号。

如果整页本身是一张截图，系统不能直接删除图片内部某道题，只能裁剪、遮挡、替换整张图片，或由教师重新框选区域。

### 14.4 本机验证结论

已经使用一份 12 页、包含大量图片且无动画的本地 PPTX 完成 WPS 最小验证：

- 自动打开课件副本；
- 复制和移动幻灯片；
- 添加文字框和图片；
- 设置隐藏页；
- 删除测试幻灯片；
- 另存新 PPTX；
- 重新打开并渲染全部页面；
- 12 张保留页面的 WPS 渲染结果在操作前后完全一致；
- 原课件的文件内容和修改时间未改变。

同时已确认 WPS 可以逐页读取文字框、图片、形状名称、位置、尺寸和文字内容。A00 对象级 Gate 随后补充验证：

- 改写一个已有文本框；
- 删除一组已有页内对象；
- 替换一张已有图片；
- 在数学课件中验证公式、几何图和分组对象。

2026-07-30 又使用一份用户授权的 21 页初中数学代表课件完成 A00 对象级 Gate。课件包含普通文本、数学混排文字、公式、几何图、图片、母版和对象动画；所有操作只发生在授权副本和隔离输出目录中，源文件指纹保持不变。

本次 Gate 得到以下冻结结论：

- 可稳定自动执行：枚举幻灯片与普通对象、另存副本、删除或调整整页顺序、删除普通形状、增加统一格式文本框、在现有版式上新增页面、插入未绑定动画的静态图片，以及关闭后重开、逐页渲染和实际放映；
- 有条件自动执行：只对通过格式预检的统一格式普通文本框改写；数学混排文字直接整段覆盖会改变字体细节，必须先实现并验证逐文字范围的样式保留，否则只生成修改建议；
- 首版禁止：替换绑定对象动画的图片。实测中图片内容可以替换，但原动画会丢失，因此该操作不能进入自动执行白名单；
- 默认只读保留：公式内部、组合图形内部、图表、宏、音视频、母版结构和复杂动画。

随后按照教师给出的五项改动，从原版副本执行了加文本框、删页、删除题目子项、调序和新增图文页。输出共 18 页，WPS 重新打开、渲染和放映均通过，1600×900 逐页画面对比为 18/18 完全一致；原版和教师改动参考版的文件指纹均未变化。用户已确认 A00 人工验收通过。

## 15. HTML 交互课件

数学教学中少量确实需要拖动、动态变化或参数探索的题目，不强行塞进 PPT 动画系统。

建议把它定义为独立的“交互教学素材”：

- 绑定到某个课时节点和具体教学目的；
- 单独生成本地 HTML；
- 可从备课工作台打开；
- 可在 PPT 中放置链接或提示页；
- 不影响主课件的稳定导出；
- 不把 HTML 生成设为每节课的必经步骤。

因此，主课件继续追求稳定、快速和可直接授课；交互素材只服务少数真正需要动态呈现的题目。

## 16. 失败与恢复规则

| 场景 | 预期结果 |
|---|---|
| 重复点击生成 | 同一确认方案只产生一个有效任务，不重复调用模型或覆盖文件 |
| 同时打开两个课件版本 | 每个版本独立锁定；不能让后保存的旧版本覆盖新版本 |
| AI 中途失败 | 保留已确认资源和当前草稿，不发布半份改编方案 |
| 模型返回错误页码或对象 | 本地校验拒绝执行，提示教师重新确认 |
| 教师取消 | 立即停止后续步骤；已完成的付费调用如实记录，不自动重试 |
| WPS 中途退出 | 临时输出不标记为正式版本；原件和上一版不变 |
| WPS 保存失败 | 不发布目标文件，不留下伪装成定稿的损坏文件 |
| 应用重新启动 | 可以从已保存草稿或已确认方案继续 |
| 题目缺少答案 | 明确标记，不静默当作已验证题目进入课件 |
| 两套资料互相冲突 | 并列显示来源，由教师决定，不让 AI 自行抹平差异 |
| 学情证据不足 | 显示覆盖缺失，不生成伪精确结论 |
| 原材料被替换 | 创建新材料版本；旧课时映射继续固定到旧文件指纹 |

## 17. 数据、隐私和费用

- 教材、教辅、课件和裁图默认保存在本机；
- 不把真实教学资料、学生数据或本机路径写进 Git、设计文档和普通日志；
- 模型调用前显示将发送哪些页面、幻灯片和学情摘要；
- 默认不发送完整资料库；
- 班级学情默认匿名聚合；
- 模型失败不自动重试；
- 每次调用显示预计用途和实际用量；
- 供应商如何保存数据由用户所配置服务的政策决定；
- 删除资料或课件版本必须区分“移出工作台”和“永久删除本地文件”；
- 任何真实 `user_data/` 读取、写入、迁移或删除仍需逐次授权。

## 20. 首版验收

选择一节近期真实要上的新授课，准备：

- 1 份教材 PDF；
- 1 份实际使用的基准 PPTX；
- 2 套教辅及相应答案；
- 1 组可选的匿名班级汇总学情证据。

验收条件：

1. 教师能把教材小节拆成多个课时并保存顺序；
2. 本节引用的教材页、幻灯片和教辅题均可打开原图核对；
3. 每条重难点结论标明来源；
4. 每道候选题显示来源、用途和答案状态；
5. 教师能选择少量题目进入课堂；
6. 系统生成逐页、逐对象变更清单；
7. 未经教师确认的改动不进入输出文件；
8. 原课件内容和修改时间保持不变；
9. 新 PPTX 在 WPS 打开时不提示修复；
10. 保留页面的版式、字体、公式、图片、备注和已有对象保持原样；
11. 被隐藏的内容在正常放映中不出现，并可以恢复；
12. 新增题目清晰、来源准确、答案经过核对；
13. 中途失败、取消或重启后不会损坏上一版本；
14. 第二次打开同一课时可以基于已确认版本继续；
15. 教师无需重新制作一遍，就愿意把定稿课件用于下一节真实课堂。

## 21. 成效判断

首版不以“AI生成成功率”作为主要指标，而看：

- 一节新授课的总准备时间是否下降；
- 教师需要手工重新制作的页面数量；
- AI建议被教师接受、修改和拒绝的比例；
- 资料定位和题目来源是否出现错误；
- 答案是否出现未经确认进入课件的情况；
- WPS 输出是否稳定；
- 连续三节真实课是否都能完成闭环；
- 教师是否愿意继续使用已生成课件上课。

## 22. 当前冻结决定

截至本设计文档形成时，已确认：

- 产品为个人日常备课工具，不以商业化为目标；
- 新授课是首个核心场景；
- 核心不是生成教案，而是改编现有课件；
- 可直接授课的 WPS PPTX 是首版最终成果；
- 个人授课课时树比现有教材章节树更细；
- 课时与资料显式映射优先于 RAG；
- AI建议必须能回到明确来源；
- 教师在 AI 分析前确认资料范围，在 WPS 执行前确认改编方案；
- 教辅题优先使用原图裁入，答案必须由教师验证；
- 学情始终只读使用；Phase 4 作为独立业务线并行实施，备课工作台不依赖其未发布内部状态；
- WPS 是唯一验收环境；
- 复杂交互题优先单独走 HTML，不依赖 PPT 动画；
- 原资料和基准课件始终只读，输出一律另存版本。
- 左侧只增加“备课工作台”一个一级入口；练习单、容量规划、同课异班、课后复盘、讲评课和上课包均从课时工作流中按情境进入，不各自增加菜单。

## 23. 尚待后续真实材料确定

以下内容应通过代表性数学资料验证，而不是现在凭空决定：

- 一本教材小节通常拆成多少课时；
- 教辅目录到课时节点的最佳导入方式；
- 题目和答案跨页、多栏时的框选交互；
- 参考课件中“练习区域”的自动识别准确度；
- 数学公式和分组图形在 WPS 中的对象类型；
- 教师更偏好逐项确认，还是按页面批量确认；
- 定稿文件命名和版本保留习惯；
- HTML 交互素材在课堂中的打开方式。
