## 1. 这条分支要交付什么

A 线首个完整版本只解决“新授课备课”这一条主流程：

```text
选择细化课时
→ 确认教材、参考PPT和教辅范围
→ 定位可引用页、幻灯片和题目
→ 冻结本节资源包
→ 结合教师确认的学情证据分析重难点
→ 生成可审核的课堂流程与练习取舍
→ 生成逐页PPT修改方案
→ 教师逐项批准
→ WPS在副本上执行有限修改
→ 重新打开和验证
→ 发布可直接上课的课件与配套材料
```

最终必须交付：

1. 比教材目录更细的课时树；
2. 能追溯到具体教材页、PPT 页和教辅题的资源包；
3. 有来源、有不确定性说明的重难点与课堂容量建议；
4. 可以逐页批准、拒绝和修改的课件改编方案；
5. 不覆盖原文件、可在 WPS 中继续编辑和放映的 PPTX；
6. 课前检查清单、课堂练习页和教师答案；
7. 同一课时不同班级版本的独立历史；
8. 模型或 WPS 失败后可恢复、可重试但不会重复付费或发布损坏文件的过程。

## 2. 冻结的任务边界

### 2.1 包含

- 初中数学课时树和课时版本；
- 教材 PDF、参考 PPTX、教辅 PDF/扫描件的资料登记与版本指纹；
- 页、幻灯片、题目区域和答案区域的人工校对；
- 课时与资料范围的显式关联；
- 本节资源包冻结；
- 现有数学考情与题库的只读证据适配；
- AI 辅助的重难点、题型、课堂流程和取舍建议；
- 课堂容量规则；
- 逐页课件修改计划；
- WPS 副本编辑、验证、发布和版本回退；
- 新授课同课异班版本；
- 课后简短复盘。

### 2.2 首版明确不包含

- 从零自动生成整套 PPT；
- PowerPoint 桌面软件或云端 Office；
- 自动制作复杂动画；
- 自动修改公式、组合图形、图表或宏；
- 无教师审核地删除、增加或改写幻灯片；
- 自动从互联网寻找教材、课件或试题；
- 建设通用向量知识库平台；
- 自动给题目判定唯一标准知识点；
- 自动把班主任档案或心理信息用于备课；
- 学生端、家长端、多人协作和商业租户；
- 班会、家长会和德育材料；
- 跨模块“教师今日首页”；
- 真实课后录音分析；
- 程序关闭后的后台处理。

### 2.3 首版完成定义

教师能够用一套代表性资料完整走通一节新授课，并在 WPS 中直接打开最终文件。输出应保留原课件的基本版式和未触及对象，所有新增、删除和改写都能追溯到教师批准的操作；模型关闭时，教师仍能人工完成资源选择和课件计划。

### 2.4 连续迭代与最终集中验收

A00—A10 是范围、依赖和完成清单，不是逐包测试、逐包复审或逐包验收关口。执行时：

1. A00 是决定 WPS 自动编辑能力边界的产品可行性 Gate，需要用户查看代表文件结果，但不启动正式代码复审；
2. A01—A09 完成后只更新进度、实现说明和必要的本地检查点，随后持续推进；
3. 不为每个小任务运行正式自动测试，不为每个实施包启动需求复审或代码质量复审；
4. 故障阻塞后续实现时，只做能定位和解除阻塞的最小检查；
5. 各包“验收”条目累计为 A10 的最终验证清单，不要求在该包结束时逐项跑完；
6. 整条 A 线进入用户最终验收阶段后，才在 A10 冻结完整候选，集中运行受影响回归、A 全套测试、WPS 代表副本检查、必要构建和跨模块冒烟，并进行一次双复审；
7. 如有阻塞问题，只统一修复一次、复测修复范围并进行一次限定最终复审。

小任务中会改变课件编辑结果、WPS 交互、资料范围、真实文件、模型费用或不可逆结果的问题要及时询问用户。执行者先集中调查，把本轮当前已经发现的问题尽量一次列出，并给出推荐方案和影响。需要先看 WPS 输出或页面效果、后一个问题才成立时，可以说明依赖后分步骤询问；等待回答时只暂停受影响的 A 任务。

## 5. 模块内部设计

### 5.1 深模块边界

前端和 API 不直接操作数据库表或 WPS COM。业务能力集中在以下接口：

```text
LessonTreeService
  管理教材版本、细化课时树、排序和课时修订

MaterialCatalogService
  管理来源文件、不可变版本、页/幻灯片预览和课时关联

ResourcePackService
  汇总并冻结本节确定使用的教材、课件、题目和答案证据

LessonDraftService
  基于冻结资源包和教师选中的学情证据生成结构化建议

SlidePlanService
  把教师意图转换为有限、可审核、可验证的逐页操作

WpsEditOrchestrator
  只在副本上执行已批准操作，管理超时、取消、恢复和验证

UpClassPackageService
  发布最终PPTX、练习页、教师答案、清单和版本说明
```

调用 WPS、模型、PDF/PPT 读取、OCR、题库和考情的能力均以适配器注入，测试使用 Fake 适配器。

### 5.2 核心领域对象

| 对象 | 作用 |
|---|---|
| `CurriculumEdition` | 教材版本、年级、册别 |
| `LessonNode` | 章、节、细化课时；允许教师排序和停用 |
| `MaterialSource` | 外部资料的逻辑身份 |
| `MaterialVersion` | 文件指纹、类型、页数、来源时间和解析状态 |
| `MaterialUnit` | 某页、某幻灯片或某题目区域 |
| `LessonMaterialLink` | 课时与资料范围的人工确认关系 |
| `ExerciseCandidate` | 候选题、答案区域、难度与教师校对状态 |
| `EvidenceSnapshot` | 冻结的教材、题目或考情摘要 |
| `LessonPreparation` | 某课时、某班级的一次备课实例 |
| `ResourcePackVersion` | 本次模型和课件计划使用的不可变资料包 |
| `LessonDraftVersion` | AI 或教师生成的结构化备课草稿 |
| `SlidePlanVersion` | 逐页操作计划及审批结果 |
| `PptxVersion` | 源文件、副本、输出指纹和验证报告 |
| `UpClassPackage` | 最终发布物集合 |
| `PostLessonReview` | 教师的课后简短复盘 |

### 5.3 关键状态

`LessonPreparation`：

```text
selecting_sources
→ sources_locked
→ evidence_ready
→ draft_ready
→ plan_in_review
→ plan_approved
→ executing
→ verified
→ published
→ archived
```

失败状态不覆盖最后一个成功版本：

```text
analysis_failed
execution_failed
verification_failed
cancelled
```

重新开始会创建新版本或新 operation，不把旧历史改回“未发生”。

`ExerciseCandidate`：

```text
detected
→ needs_crop_review
→ needs_answer_review
→ teacher_verified
→ eligible
```

教师也可在任一步标记 `excluded`。未经教师确认答案位置的扫描题不能进入最终教师答案。

`SlideOperation`：

```text
proposed → approved/rejected → applied → verified/failed
```

模型不能直接把 `proposed` 改为 `approved`。

## 6. 数据库与文件布局

建议模块目录：

```text

├── teaching_prep.db
├── previews/
├── indexes/
├── staging/
├── outputs/
├── exports/
└── temp/
```

规则：

- 外部教材和课件默认只登记，不擅自复制；
- 用户明确选择“导入副本”时才复制到受控目录；
- 本地数据库可以保存规范化绝对路径，但公开 API 只返回资料名称和内部 ID；
- 预览、OCR 和解析缓存都可重建，不是唯一资料；
- `staging/` 只存尚未发布的课件副本；
- `outputs/` 只出现通过验证的版本；
- 临时文件带 operation ID，成功、取消或超时后清理；
- 启动时只能清理可确认属于本模块且已过期的临时文件；
- 普通系统备份默认不包含该目录；模块备份或导出以后由用户显式执行；
- 源文件指纹变化时生成新 `MaterialVersion`，不静默替换旧版本。

## 8. A00：WPS 可行性 Gate

### 8.1 目标

用一份用户选定的代表性数学课件副本验证：当前工作机上的 WPS 是否能被稳定打开、读取对象、保存为新 PPTX、重新打开和放映，并确定首版安全操作白名单。

### 8.2 代表文件要求

优先选择同时包含以下元素的副本：

- 常规标题和正文文本；
- 数学公式；
- 几何图形或组合对象；
- 图片；
- 表格或图表；
- 主题母版；
- 至少一种切换或对象动画；
- 教师希望删除的练习页和希望保留的新授页。

只对副本操作；源文件记录哈希并设为只读验证对象。

### 8.3 必测操作

- 启动或连接 WPS 演示；
- 打开指定副本；
- 枚举页和可识别对象；
- 读取页标题和对象基本属性；
- 隐藏或删除一页；
- 删除指定普通形状；
- 修改普通文本且尽量保留样式；
- 替换同尺寸图片；
- 复制一页模板页；
- 在模板占位区插入文本或图片；
- 另存为新文件；
- 关闭后重新打开；
- 导出 PDF 或逐页预览；
- 检查页数、对象数、公式、图片、母版、切换和动画是否仍在。

### 8.4 Gate 输出

形成冻结记录：

| 类别 | 结果 |
|---|---|
| 可稳定自动执行 | 进入首版白名单 |
| 可执行但有格式风险 | 只生成建议，默认不自动执行 |
| 无法稳定执行 | 首版禁止 |
| 只能整页处理 | 设计成隐藏/复制页，不处理内部对象 |

推荐首版白名单只包含已经实测稳定的操作，通常优先：

- 隐藏或删除整页；
- 删除普通形状；
- 修改普通文本框；
- 替换图片；
- 复制已存在的模板页；
- 在明确占位区插入渲染好的题目图片。

数学公式、组合图形、图表、宏、音视频和复杂动画默认只读保留。

### 8.5 失败处理与完成门槛

- WPS 卡死：终止隔离的 helper 进程，不结束教师其他 WPS 窗口；
- 文件被占用：明确提示关闭或另选副本，不强制解锁；
- 保存失败：保留源副本，删除未通过验证的 staging 文件；
- 重新打开失败：禁止发布；
- 未触及元素发生明显损坏：该操作从白名单移除；
- 若连“副本打开—另存—重开”都不稳定，A08 停止，向用户报告并决定是否改为“只生成修改清单、教师在 WPS 手工执行”。

Gate 必须有实际 WPS 人工检查结果；单元测试不能替代。

### 8.6 实际 Gate 记录（2026-07-30）

任务边界：

- 目标：确定当前工作机 WPS 的首版安全操作白名单；
- 包含：只读盘点、对象级副本修改、另存、重开、逐页渲染和放映；
- 不包含：业务页面、数据库、真实模型、批量课件处理和复杂对象内部编辑；
- 风险等级：高，主要风险是覆盖源文件、未触及内容变化和动画丢失；
- 验收条件：源文件不变，输出可由 WPS 重开和放映，教师指定改动可以准确复现。

实际验证：

1. WPS 可稳定打开授权副本，枚举 21 页及其普通对象，另存新 PPTX，关闭后重新打开、逐页渲染并实际放映；
2. 原版与参考改动版全程保持原文件指纹不变，没有被覆盖；
3. 根据教师给出的五项改动，从原版副本完成加文本框、删除原第 17—20 页、删除原第 16 页题目子项及答案、把原第 9 页移到第 7 页，以及新增第 17 页图文内容；
4. 最终输出 18 页，WPS 重开、渲染和放映均通过；与教师参考改动版按 1600×900 导出后逐页对比，18/18 页完全一致；
5. 用户已于 2026-07-30 确认 A00 通过验收。

冻结的首版白名单：

- 删除整页和调整整页顺序；
- 删除教师确认的普通形状或普通文本框；
- 新增统一格式普通文本框；
- 在现有版式上新增普通页面；
- 插入、移动、缩放、裁剪或替换未绑定动画的普通静态图片；
- 另存为新 PPTX，并强制执行 WPS 重开、全页渲染和放映检查。

冻结的限制：

- 数学混排文字直接整段覆盖会改变字体细节。只有逐文字范围样式保留经过实现和代表文件验证后，才能自动改写；在此之前只生成建议；
- 实测替换绑定对象动画的图片会丢失该动画，因此首版禁止自动替换此类图片；
- 公式内部、组合图形内部、图表、宏、音视频、母版结构和复杂动画默认只读保留；
- A08 只能执行结构化、已批准且通过白名单校验的操作，不接受自然语言直接驱动 WPS。

## 9. A01：模块壳、存储与状态机

### 9.1 包含

- A 模块 manifest、API 根路由和空页面；
- 模块启用/禁用；
- `teaching_prep.db` 的模块本地迁移；
- 仓储、事务和状态机；
- 模块专用 Job 注册；
- Fake 模型、Fake WPS、Fake 资料读取器；
- temp/staging/output 路径；
- API 错误、operation ID、请求幂等键和 revision；
- 模块内局部样式。

### 9.2 排除

- 真实资料解析；
- 真实模型；
- 真实 WPS；
- 业务页面细节。

### 9.3 验收

- 模块禁用时无导航、API、目录和数据库副作用；
- 启用后只创建 A 的目录和数据库；
- 重复启用和迁移安全；
- 两次相同创建请求只产生一条记录；
- 两个页面用旧 revision 修改时返回冲突，不覆盖；
- Job 失败和重启后状态可解释；
- 模块关闭不影响已有系统；
- 所有测试使用临时路径。

## 10. A02：细化课时树与资料库

### 10.1 包含

- 教材版本、年级、册别、章、节和多课时节点；
- 从教辅目录辅助创建更细课时树；
- 教师人工新增、改名、排序、停用和修订；
- PDF、PPTX 和图片资料登记；
- 文件指纹、大小、修改时间、页数/幻灯片数；
- 资料新版本，不覆盖旧版本；
- 资料缺失、移动和重新定位；
- 本地搜索和筛选。

AI 可以提出目录拆分草稿，但只有教师确认后写入正式课时树。

### 10.2 失败场景

- 同一文件重复导入；
- 同名不同文件；
- 文件被移动或替换；
- 扫描 PDF 无文本；
- PPTX 加密、损坏或被占用；
- 目录解析结果顺序错误；
- 教师正在编辑时另一页修改课时树；
- 应用解析中途退出。

### 10.3 验收

- 用合成教材目录建立“节下多课时”；
- 修改目录不破坏已经建立的旧备课；
- 相同指纹不重复建立版本；
- 文件替换产生新版本并提示旧关联仍指向旧版；
- 文件缺失时显示“需重新定位”，不自动猜路径；
- 无 AI 也能手工完成全部操作。

## 11. A03：定位、预览与课时关联

### 11.1 包含

- PDF 逐页预览和文本抽取；
- PPT 逐页预览、标题和基础对象清单；
- 扫描页的可选 OCR 或人工标签；
- 教材页、参考 PPT 页和教辅页与课时的范围关联；
- 一课时可关联多段不连续范围；
- 来源页的裁切与引用预览；
- 教师修正系统定位结果；
- 关联版本冻结。

解析优先顺序：

```text
文件内嵌文本
→ 已有可复用的本地解析能力
→ 教师明确授权的OCR/视觉识别
→ 人工页码与区域标注
```

数学公式识别结果必须标记为“待核对”，不能因为 OCR 有文本就当作正确公式。

### 11.2 验收

- 选择一个课时后能看到教材、课件和教辅的候选范围；
- 教师可以增加、删除和修正范围；
- 每个引用都能回到文件版本和具体页；
- 源版本变化不会悄悄改动已确认范围；
- 预览缓存删除后可以重建；
- API 不泄露工作机绝对路径。

## 12. A04：教辅题目与答案证据

### 12.1 包含

- 一页多题的区域框选；
- 题干、图形和选项的一个或多个区域；
- 对应答案或解析区域；
- 题号、页码、资料版本；
- 教师确认答案匹配；
- 难度、课堂用途、预计时间和重难点的教师标签；
- 题目去重候选，但不自动合并；
- 课堂候选、备用题和排除项。

### 12.2 关键规则

- 多栏、跨页和图文分离必须支持多区域；
- 系统推荐的裁切框只是草稿；
- 未确认答案不能进入教师答案页；
- 不把 OCR 文本作为题目唯一真实来源，保留原图引用；
- 不因题目相似就自动认定重复；
- 题库中的现有题只读引用，不回写题库。

### 12.3 验收

- 用合成双栏扫描页正确框选两道题；
- 支持一道题跨两个区域；
- 答案错配时教师可修正；
- 相同题候选显示依据并由教师决定；
- 删除资料版本不会破坏已发布课件的证据快照；
- 教师可在无模型情况下完成题目筛选。

## 13. A05：资源包冻结与学情证据

### 13.1 资源包内容

一次备课调用模型前，先冻结：

- 课时树版本；
- 教材页和核心内容；
- 参考 PPT 页及“保留/候选删除”意图；
- 教辅题与答案；
- 课堂时长、班级和课型；
- 教师选择的历史考情摘要；
- 教师补充的本班情况；
- 资料缺失和不确定项。

冻结后得到 `ResourcePackVersion`。资料有变化时创建新版本，不修改已经用于模型或课件执行的旧包。

### 13.2 只读证据接口

```text
QuestionEvidenceReader.read(query) -> versioned snapshot
AssessmentEvidenceReader.read(class, knowledge_scope) -> versioned snapshot
```

适配器只返回备课需要的班级汇总或匿名题目证据，不返回学生姓名、联系方式、班主任观察或个人心理信息。

Phase 4 尚未交付时，适配器读取当前已发布考试与标签证据；Phase 4 交付后，可读取已发布的掌握证据与训练摘要。A 线不读取 P4 的候选关系、待复核判定点、个性卷或答卷图片，也不把备课结果回写 P4。

### 13.3 验收

- 资源包能完整列出来源和版本；
- 缺少考情时仍能继续；
- 不同班级的证据不会混用；
- 来源更新后旧包保持不变并提示可生成新版；
- 读取现有库不产生任何写入；
- 可以导出一份不含内部绝对路径的资源清单。

## 14. A06：AI 草稿与课堂容量

### 14.1 AI 的输入与输出

AI 只读取教师确认的 `ResourcePackVersion`，输出严格的结构化草稿：

- 本课知识目标；
- 可追溯的重难点；
- 预计困难及证据；
- 建议保留的新授流程；
- 建议删除或移出的练习；
- 建议加入的少量课堂题；
- 每一环节预计时间；
- 课堂容量超限项；
- 不确定项和需要教师决定的问题；
- 每条建议的来源引用。

模型不得输出直接执行的 WPS 指令。

### 14.2 调用规则

```text
准备发送内容
→ 展示模型、预计范围和实际引用资料
→ 教师确认
→ 最多一次物理调用
→ 解析并本地校验
→ 保存为草稿
→ 教师编辑和确认
```

- 默认不自动重试；
- 重复点击使用 operation ID 返回同一结果，不再次付费；
- 超时、取消、坏 JSON 和内容校验失败不改变正式备课状态；
- 真实调用必须使用工作台安全诊断入口，不能保存教材正文、题目正文或模型回复正文到普通日志；
- 发送学生信息前本地最小化，首版只发匿名班级汇总；
- 教师可以完全关闭 AI。

### 14.3 课堂容量规则

时间计算由本地规则完成，不交给模型自由相加。至少包含：

- 总课时；
- 导入、探索、例题、练习、总结的最小时间；
- 每道题预计时间；
- 机动时间；
- 超时警告；
- “移到课后”“作为备用”“换成更短题”的建议。

### 14.4 验收

- 所有重难点和题目建议有来源；
- 模型编造的页码或题号被拒绝；
- 计划总时长可解释；
- 超限时明确指出需删减的部分；
- 模型不可用时教师仍可编辑本地模板；
- 同一 operation 不产生第二次模型调用；
- 普通日志中搜索合成教材正文和题目正文，结果为零。

## 15. A07：逐页课件改编计划

### 15.1 包含

- 原 PPT 每页缩略图和对象概要；
- “保留、隐藏、删除、复制、修改、插入”的逐页建议；
- 每项操作的原因、来源、预计课堂时间和风险；
- 教师逐项批准、拒绝、编辑；
- 计划版本和审批历史；
- 操作白名单校验；
- 执行前差异预览；
- 不支持对象的醒目提示。

### 15.2 操作对象必须稳定定位

不得只用“第 12 页第 3 个对象”作为长期定位。操作计划至少记录：

- 源 PPT 指纹；
- 幻灯片稳定签名；
- WPS 提供的对象 ID（若可靠）；
- 对象类型、位置和内容摘要；
- 计划生成时的页码；
- 执行前重新匹配结果。

只要源文件指纹或对象匹配发生冲突，就回到人工复核，不能猜测执行。

### 15.3 验收

- 教师能在一个页面看懂每项更改；
- 可以批量接受低风险删除，也可逐项撤销；
- 修改计划不会碰源文件；
- 不在 A00 白名单内的操作不能进入批准状态；
- 源 PPT 更新后旧计划自动失效；
- 计划本身可导出为人工 WPS 修改清单。

## 16. A08：WPS 副本执行、验证与发布

### 16.1 执行架构

WPS 自动化运行在独立 helper 进程中：

```text
已批准SlidePlan
→ 校验源指纹与文件锁
→ 创建唯一staging副本
→ helper打开WPS并逐项执行
→ 每步记录非敏感结果
→ 另存为候选PPTX
→ 关闭helper控制的文档
→ 重新打开候选文件
→ 导出预览并验证
→ 原子发布到outputs
```

主应用不能把自然语言直接传给 WPS；只能传经过校验的操作 DTO。

### 16.2 验证要求

至少检查：

- PPTX 可重新打开；
- 页数符合批准计划；
- 已批准的删除/修改存在；
- 未批准页仍在；
- 关键公式、图片和组合对象的数量或指纹没有意外变化；
- 主题、母版和页面尺寸仍可读；
- 导出的逐页预览完整；
- 输出哈希和操作报告已记录；
- 源文件哈希与执行前一致。

验证报告不能声称“数学内容正确”，内容正确性仍由教师人工检查。

### 16.3 失败、取消和恢复

| 场景 | 预期结果 |
|---|---|
| 重复点击执行 | 同一计划只创建一个 operation |
| 两页同时执行同一计划 | 一个获得执行权，另一个显示进行中 |
| WPS 卡死 | helper 超时退出；源文件不变；候选不发布 |
| 应用退出 | staging 保留为可诊断状态；重启后提示恢复或清理 |
| 文件锁定 | 执行前失败，不强制关闭教师文档 |
| 中途取消 | 完成本步安全退出；候选不发布 |
| 部分操作失败 | 整体标记失败；不能把半成品当定稿 |
| 源文件变化 | 计划失效，要求重新映射 |
| 输出文件重名 | 创建新版本，不覆盖已有输出 |
| 验证失败 | 候选留在隔离区或清理；不进入 outputs |
| 发布时磁盘失败 | 旧发布版本不受影响 |

系统不能自动追加可能收费的模型调用来“修复”WPS 失败。

### 16.4 人工验收

在取得单独授权后，使用代表性副本检查：

- 原文件时间、大小和哈希未变；
- 输出文件能用 WPS 打开、编辑和放映；
- 未批准的页、公式、图形、图片和动画未被明显破坏；
- 删除与新增符合审批清单；
- 失败演练不会在输出目录留下“定稿”；
- 可回到上一个已发布版本。

## 17. A09：上课包、同课异班与课后复盘

### 17.1 上课包

一次发布包含：

- 最终 PPTX；
- 一页课堂练习或可打印练习；
- 教师答案；
- 课堂流程与时间清单；
- 来源和版本说明；
- 课前检查结果；
- 若课件含外链或 HTML，附离线可用性说明。

### 17.2 同课异班

- 同一资源包可派生不同班级版本；
- 班级版本拥有独立课堂容量、题目取舍和 PPT 输出；
- 修改 B 班不覆盖 A 班；
- 共用来源时仍保留各自审批和发布历史；
- 学情证据只属于对应班级版本。

### 17.3 课后复盘

提供不超过一分钟的结构化记录：

- 哪一环节超时或提前；
- 哪一道题太难、太易或无效；
- 哪个重难点需要再讲；
- 下次保留、删除或调整什么。

复盘先只进入 A 模块，作为下一次同课备课的可选证据；不自动写入班主任模块，不自动形成学生判断。

### 17.4 验收

- 输出包缺少任一关键文件时不能标记完整；
- 班级版本彼此独立；
- 原始资料删除后，已发布包仍有必要的来源清单；
- 复盘可选择用于下一版，也可忽略；
- 所有输出在断网时仍能打开，外部依赖明确标出。

## 18. A10：稳定候选、复审与验收

A10 是整条 A 线唯一的正式测试、正式复审和最终人工验收阶段；A01—A09 的验收条目都在这里集中兑现。

### 18.1 A10-R2：偏好驱动改编修订

首轮真实流程只验证了副本、失败闭合和 WPS 可播放性，新增两道自拟题不符合教师实际改编习惯，
因此不构成人工验收通过。A10-R2 在不覆盖源 PPT、不绕过逐项审核的前提下增加：

1. 本机单用户个人默认偏好，带 revision 冲突保护；
2. 每次备课可勾选覆盖，冻结进不可变资源包并进入模型发送预览；
3. 逐页结构化 `slide_adaptations`，只允许引用冻结 PPT 页和教材页；
4. 本地规则只把已核对教材引用及可见页眉/页脚或教师确认的教材印刷页码转换为 28 号页码文本框，
   不把 PDF 文件页序当作教材页码；
5. 按轻度、适度、大幅三档提出课件后段练习候选删除，讲授例题优先保留；
6. 按零至三道上限补入已冻结参考题原图，默认最多两道；
7. 所有页码、删页和补题操作仍先进入 A07 审核，A08 只执行完整批准计划。

旧资源包和旧草稿继续可读；没有 `slide_adaptations` 的旧草稿按原计划逻辑兼容。真实数据库迁移、
真实模型调用和新版真实 WPS 代表课件验收仍分别需要逐次授权。

### 18.1 候选冻结前检查

- 所有实施包状态和迁移版本已记录；
- 受影响测试均通过；
- 只存在 A 与文档允许的 F0 文件变化；
- 没有真实资料、密钥、路径或输出被提交；
- 数据库、API 和日志不暴露绝对路径；
- Fake 模型覆盖成功、失败、超时、取消和坏 JSON；
- Fake WPS 覆盖重复、并发、退出、重启和部分失败；
- 使用临时目录完成端到端测试；
- 前端类型检查、模块测试和构建通过；
- 模块禁用时现有系统冒烟通过。

### 18.2 正式复审

A 属于中高风险。稳定候选冻结到一个提交后，同时进行：

1. 需求符合性复审：逐条核对本计划和产品设计；
2. 代码质量复审：重点检查文件安全、幂等、并发、恢复、模型次数和 WPS 隔离。

两名复审者检查同一提交。等待全部意见后，按根因去重；只有本次引入或本任务遗漏的 `Critical`、`Important` 阻塞。若存在阻塞项，只统一修复一次、复测受影响范围，再做一次限定最终复审。

### 18.3 用户人工验收脚本

使用匿名班级和经授权的资料副本完成：

1. 建立一个“节下分三课时”的课时树；
2. 关联教材页、参考 PPT 范围和两套教辅范围；
3. 修正一个错误页码和一个错误题目裁切；
4. 冻结资源包；
5. 用 Fake 或经授权模型生成重难点和课堂流程；
6. 删除大部分参考 PPT 练习，保留新授流程；
7. 加入两道教师确认的关键题；
8. 审核逐页修改计划；
9. 用 WPS 在副本上执行；
10. 人工检查输出可编辑、可放映、源文件未变；
11. 派生另一个班级版本；
12. 模拟一次 WPS 失败并确认半成品未发布；
13. 完成一次课后复盘并用于下一版。

### 18.4 合并关口

只有用户明确表示 A 线验收通过，才可以：

- push A 分支；
- 创建 PR；
- 合并到 `main`；
- 更新正式架构和执行索引；
- 通知仍在开发的 P4/B 线在其下一个实施包边界同步最新 `main`。

这些动作分别受届时项目规则约束，本文不提前授权。

## 19. 整条 A 线故障场景总表

| 类别 | 必须验证的结果 |
|---|---|
| 重复操作 | 创建、模型生成、WPS执行和发布均有幂等键 |
| 同时操作 | 使用 revision 或执行锁，不静默覆盖 |
| 中途退出 | 数据库事务回滚；文件留在可识别 staging；正式版本不变 |
| 重新启动 | 能恢复状态、继续人工处理或安全清理 |
| 失败重试 | 模型默认不自动重试；WPS只重启新 operation |
| 取消 | 不产生正式草稿、半成品课件或错误发布 |
| 部分完成 | 明确显示失败步骤，不能伪装为完成 |
| 数据缺失 | 展示缺少来源，允许教师手工继续 |
| 数据冲突 | 冻结旧版本并要求教师选择，不自动合并 |
| 源文件变化 | 旧页映射和SlidePlan失效 |
| 文件占用 | 不强制关闭、不覆盖 |
| 磁盘不足 | 发布前检查；旧输出不受影响 |
| 模型不可用 | 人工模板仍可工作 |
| WPS不可用 | 修改清单可导出，自动执行入口暂停 |

## 20. A 线不阻塞首版的后续方向

以下价值明确，但应在 A 首版独立合入后分别立项：

- 复习课、讲评课和试卷讲评的专用流程；
- 单题 HTML 交互课件；
- 更复杂的公式和几何对象编辑；
- 教师长期偏好学习；
- 课件模板库；
- 本地向量检索；
- 课堂录音和教学行为分析；
- 与班主任工作台的考试后双通道联动；
- 班会、家长会和活动 PPT 生成。

后续功能不得借 A 首版实施顺便进入，也不得成为 A 首次合并的验收条件。
