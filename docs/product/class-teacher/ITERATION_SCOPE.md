# 班主任工作台迭代边界

## 固定信息

- 业务线：B（班主任工作台）
- 分支：`codex/class-teacher-iteration`
- 工作区：`.worktrees/class-teacher-iteration`
- 共同起点：`e63136c6c5471f358cfaf11065f5b92b0f46ca10`
- 风险等级：**很高**。本线涉及未成年人敏感信息、加密数据、访问控制、删除与恢复，任何实现都必须以不泄露、不误删、不越权为首要条件。

本文档冻结本分支的主要职责、数据边界和交付流程。迭代中发现的相邻需求单独记录，不自动扩大本分支范围。

## 目标

以快速、连续的小批次方式完善班主任工作台的前端体验与配套功能，使普通班务和受保护的学生事务能够在清晰分区、人工确认、可恢复且可审计的前提下完成。完整候选形成前减少重复的大范围测试与开放式复审，把时间集中在实现和真实操作路径的打磨上；合并前再进行一次完整、安全导向的集中验收。

## 包含内容

本分支负责：

- 普通工作图及其班务信息组织；
- 日历、提醒和学校流程 SOP；
- 受保护的学生档案及其最小必要信息展示；
- PIN 与 Windows 本机保护、锁定和会话过期；
- 敏感数据的加密、恢复、删除和审计；
- 模型生成内容的预览与人工确认；模型输出在确认前不得执行或外发；
- 只读使用经项目规则允许的考试摘要，为班主任提供必要背景；
- 上述功能直接需要的前端、后端、迁移、适配器和测试。

## 文件所有权

本分支主要拥有：

- `backend/class_teacher/**`
- `frontend/src/workspaces/class-teacher/**`
- `migrations/student_affairs/**`
- `migrations/class_teacher_work/**`
- `tests/class_teacher/**`
- 明确只服务于 B 线的适配器和测试

“B 专属”必须能由用途、调用方和测试证据明确证明。若文件同时服务阅卷、备课或全局运行，它就属于公共区域，不因本分支需要而直接取得所有权。

## 明确不包含

- 不读取、写入或修改 A（备课工作台）的业务数据和目录。
- 不读取 P4 的训练判定正文、答卷图片或学生训练反馈；仅可只读使用明确获准的考试摘要。
- 不改变普通考试分数、排名、报告、评分依据或教师最终分锁的原义。
- AI 不作诊断、欺凌认定、惩戒决定、紧急裁决、自动外发或自动结案。
- 不让模型预览绕过教师确认、学校流程或人工责任边界。
- 不把敏感学生数据库纳入普通备份；敏感库必须继续排除在普通备份、普通日志和普通导出之外。
- 不在本分支顺带修改导航、全局路由、应用启动、公共任务、公共迁移框架、全局模型策略、备份入口、公共依赖或全局文档等公共热点。

## 公共热点处理

本线需要改变公共热点时，先暂停该部分并记录具体依赖，由一个范围明确的短期地基修正分支处理。地基修正完成并进入共同基线后，本分支再同步继续；不得在 B 线私自打公共补丁，也不得复制另一业务线尚未验收的实现来规避同步。

## 故障场景与预期结果

编码前的集中调查必须覆盖下列与本线相关的情况，并把实际处理规则落实到代码或测试中：

| 场景 | 必须达到的结果 |
| --- | --- |
| 重复操作 | 重复提交、重复确认或重复任务不会产生重复记录、重复外发、重复费用或多次不可逆处理。 |
| 同时操作 | 多窗口、多请求或多位操作者同时处理时，不静默覆盖较新的数据；冲突应被阻止或明确提示。 |
| 中途退出 | 已完成与未完成的边界可识别；不得留下看似成功但实际未完成的敏感操作。 |
| 重新启动 | 重启后能够安全识别待恢复状态，不自动重复执行已完成的外部或不可逆步骤。 |
| 失败重试 | 重试保持幂等；模型调用等可能产生费用的操作不得未经授权自动追加请求。 |
| 取消 | 取消后停止后续动作，并清楚说明哪些步骤已经完成、哪些没有执行。 |
| 部分完成 | 不把部分成功包装成整体成功；提供安全的继续、回退或人工处理入口。 |
| 数据缺失 | 缺少关键字段、密钥、权限或学校流程信息时安全停止，不猜测敏感结论。 |
| 数据冲突 | 来源互相冲突时保留证据、提示人工核对，不由 AI 自动裁决。 |
| 锁定 | PIN 或 Windows 保护触发锁定后，不通过刷新、后退、直达链接或接口调用绕过。 |
| 会话过期 | 会话过期后敏感内容立即回到受保护状态；未确认草稿不得被误当作已批准操作。 |

如某一场景与具体小批次确实无关，可以在该批次记录为“不适用”并说明原因，不需要为了穷举理论异常扩大范围。涉及恢复取舍、删除语义或学校流程且项目资料无法确定时，必须先由用户决定。

## 快速连续迭代流程

1. **集中调查并冻结清单**：开始一轮相关迭代前，一次性读取对应设计、任务清单、现有实现和测试，按根因汇总当前范围内的问题，记录目标、包含、不包含、验收条件和故障结果，然后冻结本轮清单。
2. **连续实现**：把同一根因或直接相关的问题作为一个修改批次处理。开发期间只做解除阻塞所需的最小检查和受影响范围验证，不逐项运行正式测试，不为每个小改动反复启动需求复审或代码质量复审。
3. **形成完整候选**：本线约定范围全部实现后冻结同一个候选版本，再集中运行安全回归、B 线完整测试、必要构建，以及与阅卷和备课边界有关的交叉冒烟检查。
4. **一次双复审**：对同一个冻结候选并行进行一次需求符合性复审和一次代码质量复审。只有本次修改直接引入或当前任务原本遗漏的 `Critical` / `Important` 问题阻塞交付。
5. **统一修复一次**：若有阻塞问题，等全部意见返回后去重并按根因统一修复一次，只复测受影响范围，再进行一次仅检查登记问题、修复区域和直接回归的限定最终复审；不启动第三轮开放式审查。
6. **人工验收与合并**：自动检查通过后，由用户完成最终人工安全验收；只有用户明确授权，才允许 push、创建 PR、合并或同步 `main`。

“快速迭代”表示把正式检查集中到完整候选，并不表示不测试、不复审或降低安全要求。开发期若出现可能导致敏感数据泄露、损坏、误删、越权或额外费用的风险，应立即停止相关路径并先解决或请求决定。

## 必须逐次授权的事项

以下行为每一次都需要用户单独、明确授权；此前只能使用合成数据、临时数据库和假模型验证：

- 读取、复制、写入、移动、迁移或删除真实学生资料或真实 `user_data/`；
- 使用真实学校流程、学生档案、成绩或其他真实业务文件进行验证；
- 调用真实模型、使用真实密钥、产生费用，或在失败后追加模型请求；
- 执行数据库迁移、恢复覆盖、批量覆盖、永久删除或其他不可逆操作；
- push、创建 PR、合并、同步 `main`，或丢弃未进入主线的提交。

即使获得真实数据操作授权，也不得把真实敏感数据暂存、提交、stash，或写入文档、普通日志、普通备份和 API 响应。任何写入或不可逆操作都要先确认精确目标、备份方式和回退方案。

## 验收条件

本分支只有同时满足以下条件，才算达到合并候选：

- 冻结范围内的普通工作图、日历/SOP、受保护档案和模型预览确认路径按设计可用；
- PIN、Windows 保护、锁定、会话过期、加密、恢复、删除和审计的安全边界通过集中验证；
- B 线未读取 A 数据，也未读取 P4 训练正文、答卷图片或学生训练反馈；允许的考试摘要保持只读；
- AI 禁止行为没有被页面、接口、后台任务或模型提示绕过；
- 敏感库仍被普通备份、普通日志和普通导出排除；
- 约定的安全回归、B 线完整测试、必要构建和跨模块冒烟通过；
- 同一冻结候选完成一次需求符合性复审和一次代码质量复审，限定修复流程后不存在当前范围内的 `Critical` 或 `Important` 阻塞问题；
- 用户完成最终人工安全验收，并对 push、PR、合并或同步 `main` 另行明确授权。

修改前已存在或相邻范围的问题单独记录；除非它造成版本级安全、数据损坏、文件丢失或不可逆费用风险，否则不得借此扩大当前任务或拖入反复审查。

## 本地页面与三合一预览

- `frontend/node_modules/` 与 `frontend/dist/` 不进入 Git；切换分支后必须重新确认实际运行页面来自哪个工作区，不能把旧页面当作本线候选。
- 本线达到可查看的小批次时先保存明确的本地检查点，再由 `codex/teacher-platform-integration` 预览区单向吸收并统一构建。
- 不把阅卷或备课的未验收提交合入本分支，也不把预览区的组合提交反向合回本线。
- 如需单独查看本线，必须在本工作区重新构建并校验页面版本；不得复制或复用根目录及其他工作区的旧 `frontend/dist/`。
- 构建缺失、构建版本落后或端口由其他工作区占用时必须拒绝启动。任何便利流程都不得绕过真实学生数据、迁移、模型费用和启动授权边界。
