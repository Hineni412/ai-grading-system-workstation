# 班主任旧加密两步退出：第二阶段冻结清单

范围状态：已冻结，2026-08-09。实施状态：`completed_local_checkpoint`，2026-08-10。第一阶段本地检查点：`d1403bda`。

当前决策记录：[ADR-0011](../../adr/0011-stop-reading-and-converting-legacy-class-teacher-databases.md)。

## 核心目标

当前版本彻底退出旧加密读取和转换：删除旧密码、旧 PIN、恢复密钥、旧密文打开、Windows 用户解包和转换候选生成能力。正常班主任运行只支持当前明文数据库。

保留一项必要判断：只确认数据库是不是当前支持的明文格式。这个判断不解密旧内容、不接收旧凭据，只负责避免把旧库、明密混合库或未知库当成当前库继续写入。

用户已明确开始第二阶段，但本任务仍不读取或盘点真实 `user_data`。因此，本次授权表示当前代码不再承诺转换旧库，不表示已经证明所有真实旧库均已转换。

## 三条完整流程

### 1. 当前明文工作台

教师仍从唯一的“班主任工作台”入口进入首页、日历、事务和学生四个工作面。保存、重新进入、草稿恢复、学生记录和日历结果保持不变；页面没有 PIN、解锁、改密或转换入口。

### 2. 遇到不支持的数据库

应用在补表、中断恢复和任何班主任读写之前，只读确认数据库格式。若是旧格式、明密混合格式、缺少必要结构或无法确认，全部班主任读写停止，其他模块继续运行，原文件和附属文件不变。

统一提示为：

> 班主任数据文件不是当前版本支持的格式，已停止读取和写入。请换用当前版本的明文数据；如需保留这个文件中的内容，请勿继续操作并联系维护人员。

当前版本不再提示运行迁移，也不再提供旧凭据输入或转换命令。

### 3. 普通备份与恢复

普通 ZIP 备份、普通恢复、默认包含班主任数据的范围和操作步骤保持不变。它们只复制或恢复文件，不承担旧库转换。若恢复的是不支持的旧格式，下一次访问班主任工作台时由现有格式判断停止读写。

## 页面信息层级与操作

- 一级入口仍只有“班主任工作台”。
- 二级工作面仍只有“首页、日历、事务、学生”。
- 主要操作、次要操作、文字布局和业务结果不变。
- 不新增页面、菜单、按钮、弹窗、密码框、转换链接、API 或后台任务。
- 保留现有本机页面写请求标记和日历投影跳转；它们不是旧加密会话。

## 本次包含

- 删除一次性旧库转换模块、命令入口、Windows 旧 PIN 解包和转换专用测试夹具。
- 删除旧密码计算、旧密文打开、Base64 解包和恢复密钥相关实现。
- 删除班主任模块对 `cryptography` 的直接依赖；全局依赖锁中的同名版本仍由 `google-auth` 使用，不冒充班主任旧加密残留。
- 删除只服务于旧解密的错误类型，以及已经没有调用方的空 API 模型文件。
- 当前业务仍需要的固定 JSON 排列和记录格式版本保留在现有共享位置，不复制到各业务文件。
- 把旧库提示从“请先迁移”改为“当前版本不支持且未读取或修改”。
- 更新当前架构、产品范围、执行索引和历史决策状态，删除当前代码树中的第一阶段转换操作说明。

## 本次不包含

- 不读取、列举、复制、转换、替换、移动或删除任何真实旧库或 `user_data`。
- 不修改普通 ZIP 备份、普通恢复、`.ctbackup`、当前数据库表、迁移顺序或历史业务内容。
- 不改变首页、日历、事务、学生的页面流程和业务结果。
- 不新增另一种转换、兼容或凭据处理方式。
- 不全仓重命名仍承担当前业务的 `VaultService`、`EncryptedDatabase`、历史表名和大量内部兼容参数；这会变成数据库与业务架构改造，不属于旧解密退出。
- 不启动真实服务，不调用真实模型，不推送或合并。

## 当前复用点

- 班主任根路由的统一运行门负责在所有页面操作前执行格式判断。
- 数据库模块现有的副本判断负责在不打开真实源库的情况下识别不支持格式。
- 当前记录仓库只接受 `plaintext-json-v1` 标记，并在单条读取时保留最后一道格式检查。
- 当前明文初始化、事务恢复、业务服务、四工作面和普通备份接口原样复用。
- 前端现有错误位置承接“不支持格式”提示，不建立新页面。

## 最小必要后端行为

1. 数据库不存在时，继续按当前明文规则首次创建。
2. 数据库存在时，在补表、恢复和任何班主任读写之前，只读确认它是当前格式。
3. 无法确认时返回统一的“不支持格式”结果，整项班主任操作停止，文件不变。
4. 确认是当前格式时，继续原来的初始化、保存、读取和中断恢复。
5. 生产代码不再存在打开旧密文、接收旧凭据、调用 Windows 旧 PIN 解包或生成转换候选的入口。

## 故障场景

- 旧库主文件或 WAL 中存在旧行：全部班主任读写停止，源目录成员和文件内容不变。
- 明密混合、缺表、损坏或未知格式：按不支持处理，不尝试修复、补表或创建新库覆盖。
- 当前明文库带 WAL：照常打开、保存和重进，不能误判为旧库。
- 新安装没有数据库：首次业务写入照常创建当前明文库。
- 普通恢复带回旧格式：恢复流程本身不转换；班主任下一次访问时停止。
- 删除旧依赖后仍有漏网导入：应用启动会失败，因此编译检查和全仓残留搜索是正式门槛。

## 验收条件

- 生产代码和班主任直接依赖中没有 AES、Scrypt、DPAPI、旧密码、旧 PIN、恢复密钥或转换入口。
- 转换模块、命令、旧加密测试夹具和转换测试均已删除，没有残余导入或文档操作指引。
- 合成旧库有无 WAL/SHM 时，首页、日历、事务、学生及直接业务写入全部停止，源目录摘要不变。
- 当前明文库有无 WAL 时，四工作面可打开、保存、重开并读取。
- 普通备份仍包含班主任工作区，普通恢复范围和结果不变。
- 前端仍无 PIN、解锁、改密、转换入口或旧会话请求头。
- 受影响后端、前端、备份检查、生产构建通过，并完成一次需求符合性复审和一次代码质量复审。

## 风险等级

实现风险为中等：主要删除已经隔离的旧转换代码和直接依赖，当前业务不应变化。

业务决定风险为高：第二阶段完成后，尚未转换的旧库不能再由当前版本打开。因为本任务禁止盘点真实数据，无法证明真实旧库已经全部处理。第一阶段检查点只作为本地工程回退证据，不构成当前产品继续提供转换的承诺。任何真实旧文件的盘点、处理或删除仍需针对精确路径、备份和回退另行授权。
