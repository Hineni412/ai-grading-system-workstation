## B01 冻结任务边界

### 目标

在任何学生、事务或成绩正文出现前，先建立显式初始化、默认锁定、认证加密、短期会话、无正文审计、专用密文备份/恢复和浏览器锁屏底座。

### 包含

- `class-teacher` 模块入口、受保护 API 和内存态前端；
- 教师显式初始化后才创建的独立 `student_affairs.db`；
- B00 冻结的 Scrypt、AES-256-GCM、保险箱主密钥和每对象内容密钥；
- 密码、离线恢复密钥、5 分钟自动锁定、失败递增延迟和改密；
- 无正文审计、操作 ID 幂等、敏感 Repository 边界；
- `.ctbackup` 密文备份、校验、预览和确认恢复；
- 普通备份/恢复继续排除 B 受保护根；
- 合成数据、临时路径和最小本地检查点。

### 明确不包含

- B02 以后的日历、SOP、学生支持档案、成绩和关注业务；
- 真实学生、真实成绩、真实事件、真实联系人和真实 `user_data`；
- 真实数据库迁移、真实备份恢复、真实密码或恢复密钥；
- 外部模型、费用、本地语音、普通明文导出；
- A/P4 目录、公共热点文件、push、PR、合并或同步 `main`。

### 验收条件

B01 的完成清单以详细实施计划第 9.5 节为准，累计到 B11 集中验证。当前实现阶段只记录必要本地检查点，不把 B01 单独视为最终验收关口。

### 风险等级

很高。失败可能导致敏感数据明文落盘、会话未锁定、备份泄露或恢复覆盖，因此本批次先冻结故障场景和安全边界，再统一实现。

## 集中调查与冻结问题清单

调查日期：2026-07-30。

1. F0 只提供关闭的 B 模块空壳；B01 必须拥有自己的 feature、router、service、manifest 和页面。
2. 启动期直接注册模块迁移会在教师确认前创建数据库；B01 必须允许入口存在，但只有显式初始化才创建受保护根和数据库。
3. 通用迁移器默认日志可能记录数据库路径；B01 调用迁移时必须使用无正文、无路径日志器。
4. 专用备份不能产生中间明文 ZIP；必须从 SQLite 一致性快照直接生成认证密文，并以原子文件发布。
5. 锁定不仅使 token 失效，还必须清空前端内存草稿、恢复预览和可返回的受保护状态。

问题清单到此冻结。相邻范围的新需求单独记录，不自动扩入 B01。

## B01 故障场景

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 同一 operation ID 只产生一个结果，不重复初始化、备份或恢复 |
| 同时操作 | 服务端串行化初始化、改密、备份和恢复；过期页面收到冲突 |
| 中途退出 | SQLite 事务回滚；备份只留下可清理的密文临时文件 |
| 重新启动 | 所有旧会话失效，模块回到锁定态 |
| 失败重试 | 密码失败只增加延迟；写操作不自动重放 |
| 取消 | 未确认恢复不替换数据库；前端取消只丢弃内存预览 |
| 部分完成 | 不发布半个备份，不把未替换的恢复显示为完成 |
| 数据缺失或冲突 | 密钥包、密文或实例不匹配时失败关闭，不返回半解密内容 |

## B02 冻结任务边界

### 目标

建立完全不依赖 AI 的行动账本，使首页、列表和后续 SOP/关注流程引用同一份正式行动。

### 包含

- 手工创建工作目标与行动；
- 截止时间、依赖、提醒、等待对象和复查日期；
- 待办、进行中、等待、部分完成、完成、取消、替代和重开历史；
- 日、周、时间线与列表所需的统一查询；
- 学校工作日、放学时间和锁定日期配置；
- revision 冲突、operation ID 幂等和无正文行动审计；
- 所有行动正文继续经过 B01 的认证加密 Repository。

### 明确不包含

- AI 拆解和沟通文案生成；
- SOP、学生支持档案、成绩、关注建议；
- 程序关闭后的通知、自动发送和二进制附件；
- 真实学生或真实学校日历。

### 验收条件

使用合成普通任务走通“创建—改期—等待回复—完成—重开”，同一行动在首页和日期查询中保持一致；缺少校历或放学时间时明确显示未知。

### 风险等级

中高。主要风险是重复行动、并发覆盖、状态历史被改写和未来学生关联行动正文泄露。

### 故障场景

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 同一 operation ID 只创建一份计划或行动 |
| 同时编辑 | 过期 revision 返回冲突，不自动覆盖 |
| 中途退出 | 正式行动、密文正文和审计同一事务提交或回滚 |
| 重新启动 | 从加密库恢复全部正式状态，未保存页面输入不冒充已保存 |
| 失败重试 | 写响应丢失时以 operation ID 返回原结果 |
| 取消 | 记录取消历史，不删除原行动 |
| 部分完成 | 必须保存具体结果，并保留后续未完成事实 |
| 数据缺失或冲突 | waiting 缺少等待对象或复查日期时拒绝；校历缺失不猜日期 |

### 目标

在外部模型保持关闭的前提下，把教师的一句话任务转换为可检查、可修改、尚未正式入账的本地草稿；教师确认后，再以一次事务生成正式工作目标、行动和“尚未发送”的沟通草稿。

### 包含

- 取消、重复操作、revision 冲突和重启后恢复未确认草稿；
- 合成数据和受影响范围检查。

### 明确不包含

- 任何外部模型调用、费用、自动发送或后台通知；

- B04 收集板、会议批量拆分和逐学生状态；
- B05 SOP、高风险事件判断、诊断、欺凌认定或惩戒决定；

### 验收条件

### 风险等级

## B05 冻结任务边界

### 目标

建立不依赖 AI 的版本化 SOP 状态机，使一个合成事务可按冻结模板生成当前步骤、并行步骤和后续预览，并支持人工结果、必做安全步骤、结案、重开和新一轮发生。

### 包含

- 冻结且不可覆盖的模板版本；
- 必做、可豁免、并行、被替代和安全必做步骤；
- 事务、匿名参与引用、发生轮次、步骤实例、人工决定和无正文事件；
- 当前步骤通过 `action_id` 进入 B02 行动账本，不建立第二份待办；
- 教师/学校决定与 AI 建议分层，AI 建议不能推进高影响分支；
- 模板升级不改变进行中事务；
- revision 冲突、operation ID 幂等、原子创建和重开。

### 明确不包含

- B06 深圳学校 SOP 正式基线、动态页面卡片和学校授权核对；
- 自由拖拽设计器、AI 自动分支、欺凌认定、诊断、惩戒决定或紧急裁决；
- 学生长期档案、真实姓名、真实学校流程或真实事件；
- 事务结果向 B07 学生时间线投影；
- 外部模型、费用、自动外发、真实数据迁移、push、PR、合并或同步 `main`。

### 验收条件

合成模板可证明版本冻结、并行步骤、依赖解锁、普通步骤豁免、安全必做不可绕过、结案、重开和旧事务不受新模板影响；每个可执行步骤只生成一个 B02 行动；重复操作和事务失败不制造第二份或半份数据。

### 风险等级

高。主要风险是绕过安全必做步骤、模板升级改写运行中事务、并发重复推进、事务和行动账本不一致。

### 集中调查与故障场景

1. B02 的行动表与 B05 位于同一 SQLite 库，可在同一事务中创建/更新步骤和正式行动；未来步骤保持预览态，依赖满足时才创建唯一行动。
2. 模板正文、事务正文、参与引用、步骤结果和决定正文都必须经过加密 Repository；关系表只保存随机 ID、状态码、模板键和时间。
3. B05 只提供通用合成引擎，不把任何学校规则冒充正式合规流程。

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 相同 operation ID 返回原事务、步骤结果或重开结果 |
| 同时操作 | 过期步骤/事务 revision 返回冲突，不重复激活后续行动 |
| 中途退出 | 事务、参与引用、首批步骤和 B02 行动共同回滚 |
| 重新启动 | 从冻结模板版本和加密实例恢复当前、完成及预览状态 |
| 失败重试 | 不生成第二个事务或第二份行动 |
| 取消/豁免 | 只有模板允许的普通步骤可豁免；安全必做步骤不可豁免 |
| 部分完成 | 已完成步骤保留，只有依赖全部满足的后续步骤变为可执行 |
| 数据缺失或冲突 | 缺模板、循环依赖、缺结果或未完成必做步骤时拒绝推进/结案 |

问题清单到此冻结。B06 页面和学校 SOP 内容不自动扩入 B05。

## B04 冻结任务边界

### 目标

把一段班主任会记录拆成多个可编辑、可合并、可拆分和可删除的待确认任务，并为回执、报名和材料类行动提供匿名收集板；所有正式行动仍只进入 B02 行动账本。

### 包含

- 本地按行和分隔符拆分会议记录，不调用外部模型；
- 每项草稿的目标、最终截止时间、行动、未知项和敏感字段检查；
- 教师通过完整草稿编辑完成合并、拆分和删除；
- 一次事务确认全部目标与行动，未确认内容不进入正式日历；
- 确认后可选择删除会议原文，只保留结构化结果；
- 收集板五态：待通知、待提交、已提交、需核对、已完成；
- 匿名参与引用、班级总数、状态计数、群提醒草稿和单人提醒草稿；
- 等待学校口径、家长回复和学生补交继续复用 B02 的等待状态与复查时间。

### 明确不包含

- 真实班级名单、真实会议记录、真实家长联系方式和自动发送；
- 模型拆分、自动匿名化外发、程序关闭后的提醒；
- B06 学校 SOP 模板和动态事务卡片；
- B07 学生长期支持档案及其迁移；
- 真实数据写入、费用、push、PR、合并或同步 `main`。

### 验收条件

合成会议记录可拆成不同 DDL 的多项任务并原子确认；合并后日期冲突保持未知；未确认不进入行动账本；原文可在确认后清除；收集板总数始终等于五种状态计数之和；群提醒不含参与引用，单人提醒只含当前目标；重复导入和确认不产生第二套行动。

### 风险等级

中高。主要风险是会议原文残留、未确认草稿误入日历、批量确认部分成功、收集计数与个体状态不一致及群文案泄露个体身份。

### 集中调查与故障场景

1. B04 没有指定迁移；会议收件箱和收集板可安全复用 `encrypted_objects`，避免占用 B07 从 009 开始的迁移编号。
2. B02 目标和行动与 B04 位于同一数据库，可在一次 SQLite 事务内批量确认；任一草稿无效则全部回滚。
3. 合并草稿遇到不同截止时间时不能自动选择较早或较晚日期，必须清空最终 DDL 并提示教师重新确认。

| 场景 | 预期结果 |
|---|---|
| 重复操作 | 相同 operation ID 返回原收件箱、确认结果或收集板，不重复生成 |
| 同时操作 | 过期 revision 拒绝更新，不覆盖另一页面状态 |
| 中途退出 | 批量目标、行动和原文清理共同提交或共同回滚 |
