# B00 深圳公办初中学校流程规格

> 状态：用户已于 2026-07-30 确认，B00 通过
>
> 学校类型：广东省深圳市公办初中
>
> 原则：只冻结角色和流程，不保存真实姓名、电话或私人联系方式

## 1. 已确认角色链

普通校内流转：

```text
班主任
  → 年级负责人
  → 德育/学生工作负责人
  → 分管校领导
  → 校长
```

校长是学生学校保护第一责任人，学校应指定一名校领导直接负责学生保护工作。系统中的角色名称允许学校在真实启用前替换为本校正式岗位名，但不能删除法定责任或把责任交给 AI。

## 2. 并行专业与外部通道

内部逐级流转不是紧急救助和法定报告的前置条件。

| 情形 | 立即并行加入 | 系统不得做 |
|---|---|---|
| 正在发生或迫近的人身危险 | 现场有能力教职工、学校安全负责人、校医/保健教师、110/120、监护人、分管校领导 | 等表单填完、等领导逐级批准、AI判断是否值得求助 |
| 学生受伤或突发疾病 | 现场救助、校医/保健教师、120（需要时）、监护人、学校安全报告链 | 用“已联系家长”代替救护；判断伤情等级 |
| 疑似学生欺凌 | 立即制止、班主任、年级负责人、德育负责人、学校学生欺凌治理委员会、监护人 | 班主任或 AI 直接认定欺凌 |
| 严重欺凌、涉嫌违法犯罪 | 前述角色 + 公安机关、教育行政部门 | 隐瞒、只做内部调解 |
| 疑似家庭暴力、虐待、遗弃、性侵害等不法侵害 | 现场保护、学校负责人、公安/民政/教育等依法报告通道 | 因家长可能涉事而机械先通知家长；以校内审批阻塞强制报告 |
| 明显自伤或伤人倾向、严重心理危机 | 看护/陪护、心理教师、心理危机干预领导小组、分管校领导、监护人或近亲属、专业机构；必要时公安/急救 | AI诊断、承诺保密、让学生独处、只创建普通待办 |
| 普通矛盾 | 班主任；需要时年级负责人、德育负责人 | 未调查即升级为欺凌或惩戒 |
| 家校沟通 | 班主任；需要学校决定时加入年级/德育负责人 | 自动发送、泄露另一名学生姓名 |
| 大型或校外活动 | 活动负责人、安全负责人、审批角色、校领导 | AI批准活动或确认现场安全 |

## 3. 时间规则

### 3.1 法律和安全底线

以下情况界面只显示“立即人工处置”，不得虚构统一小时数：

- 正在发生或迫近的危险；
- 需要制止的欺凌或暴力行为；
- 疑似不法侵害和强制报告线索；
- 伤害、突发疾病、自伤或伤人风险；
- 严重欺凌、涉嫌违法犯罪的报告。

“立即”意味着先采取保护、救助、制止和报告动作，再补录系统，不是先完成应用流程。

### 3.2 学校可配置时限

真实启用前，学校可补充但不得放宽安全底线：

- 年级负责人确认收到的时限；
- 德育/学生工作负责人接手时限；
- 欺凌治理委员会启动调查和反馈节点；
- 普通家校沟通、关怀谈话和复查周期；
- 活动审批、材料、家长确认和安全复核节点；
- 校内值班、替补联系人和失联升级方式。

未配置时，系统只能显示责任角色和“请按学校现行制度执行”，不能自动生成具体小时数。

## 4. SOP 基线与深圳/学校口径差异

| 事项 | 国家/广东/深圳基线 | 本产品冻结方式 | 学校真实启用前补充 |
|---|---|---|---|
| 学生保护责任 | 校长第一责任；指定分管校领导和工作机构 | 角色链固定包含分管校领导和校长 | 本校岗位正式名称 |
| 欺凌治理 | 学校成立学生欺凌治理组织/委员会并负责认定 | 班主任只报告和提供事实；收到正式决定后，以本人身份代录“学校决定引用”，不能冒充委员会决定人 | 委员会组成、召集人、记录方式 |
| 紧急伤害 | 及时救助、通知监护人、按规定报告 | 救助、通知、报告可并行；未安全交接不能结案 | 校医/保健室、值班和上报方式 |
| 心理危机 | 市—区—校干预体系；学校领导包干、专业转介 | 班主任只记录观察和报告；心理教师/领导小组负责专业流程 | 本校领导小组、转介机构和值班方式 |
| 不法侵害 | 发现或疑似遭受侵害、面临危险时及时报告 | 进入独立强制报告分支，不被家长通知或校内审批阻塞 | 本校报告备案角色 |
| 家校沟通 | 建立有效联系机制，保护学生隐私 | 只生成草稿，教师在系统外发送并手动记录结果 | 正式渠道、身份核验、群聊禁发规则 |
| 教育惩戒 | 按校规校纪和权限程序，由教师或学校有权角色决定 | AI不推荐等级；班主任不能选择学校级处分 | 本校已公布校规、决定人、申诉和归档 |
| 校外活动 | 明确安全管理、审批和应急责任 | AI只查缺项，不批准活动 | 活动审批角色、人员配置和应急要求 |
| 保存期限 | 法律要求最小必要；学校承担正式档案责任 | 个人副本按 B00 数据治理期限；正式材料只保留引用 | 学校正式档案制度 |

## 5. 六类 SOP 的系统硬限制

### 5.1 普通学生矛盾

- 分别记录各方陈述，不把转述写成事实；
- 出现反复围堵、权力不对等、持续侮辱、伤害等线索时转入“疑似欺凌”；
- 普通调解不能覆盖正在发生的危险。

### 5.2 疑似学生欺凌

- 教师先制止、保护和报告；
- 只有学校欺凌治理委员会能够作出认定；单用户工作台由教师以本人身份代录正式编号、出具组织角色、收到时间和最小结果摘要，审计 actor 始终是录入教师；
- 相关家长参与认定和处理，但系统不得自动外发；
- 严重情形不得只在校内结案。

### 5.3 学生伤害与紧急安全

- 不要求先填完整表单；
- 安全交接、救助、通知和报告可以并行；
- “学生说没事”或“已联系家长”不能自动结案；
- AI失败不影响离线人工步骤。

### 5.4 家校沟通

- 只引用当前目的所需的已确认事实；
- 排除其他学生姓名、家庭和不必要敏感信息；
- 教师批准后在系统外发送；
- 家长转述仍保存为“家长转述”，不自动升级为事实。

### 5.5 日常关怀谈话

- 记录具体观察，不诊断焦虑、抑郁、人格或家庭原因；
- 学生表达保存为“学生转述”；
- 出现安全信号时转入学校保护机制；
- “暂缓观察”必须有复查日期。

### 5.6 学校活动

- 区分班级日常活动和大型/校外活动；
- 后者必须显示安全组织、教育、人员职责、应急预案和重新审核节点；
- 活动变化使原安全确认失效时必须重新人工审核；
- AI不能批准活动。

## 6. 真实启用前学校确认清单

B01—B11 可以使用合成数据开发，但任何真实学生试点前仍须学校确认：

1. 角色链在本校的正式岗位名称；
2. 欺凌治理委员会和心理危机干预领导小组的职责边界；
3. 校医/保健、安全、德育、值班和替补角色；
4. 110、120、区教育行政部门及其他法定渠道的本校执行方式；
5. 家长通知可能增加危险时的特别规则；
6. 已公布的校规校纪、教育惩戒权限和申诉流程；
7. 正式档案保存、访问、移交和销毁制度；
8. 数据安全事件上报和设备遗失处理；
9. 是否允许任何外部模型；当前冻结值为“不允许 B 敏感内容调用”；
10. 真实试点范围、备份、回退和试点结束后的清理方式。

不保存真实联系人姓名、电话或私人联系方式，是本次 B00 的已确认决定。系统未来只在学校明确授权的受保护配置中保存角色化联系方式。
