# 班主任旧加密两步退出：第一阶段冻结清单

状态：已冻结，2026-08-09。

## 核心目标

正常使用班主任工作台时，只保留当前明文数据读写，不再出现或提供 PIN、锁定、解锁、改密、新建加密库和新增密文写入。

旧加密数据库只保留两项能力：正常启动时只读识别并停止混写；需要处理旧库时，通过不进入正常页面的一次性离线工具生成新的明文候选文件。

两步退出的边界是：

1. 第一阶段（本次）：日常加密运行能力退役，保留只读识别和一次性转换。
2. 第二阶段（以后另行授权）：确认所有需要的旧库都已转换后，再删除转换器、旧解密代码和旧格式说明。

## 最常用的三条完整流程

### 1. 当前明文工作台

教师直接打开“班主任工作台”，在首页、日历、事务、学生四个工作面继续操作。页面不询问 PIN，不出现锁定或解锁，保存结果与当前版本一致。设置中的普通备份仍默认包含班主任工作台数据，普通恢复步骤不变。

### 2. 正常启动遇到旧加密库

应用只读判断数据库仍是旧格式，不补表、不恢复事务、不更新失败次数、不写操作记录，也不尝试继续业务读写。班主任相关操作返回“需要先离线转换”，其他模块可以继续启动。正常页面不提供转换按钮或旧密码输入框。

### 3. 一次性离线转换

关闭正在使用该库的应用后，人工明确提供旧库路径、工作区之外的一个全新输出路径和一种已有凭据。工具隐藏读取凭据，先完整检查源库，再在输出目录制作临时候选；全部记录转换和复核通过后才发布输出文件。源文件永远不被覆盖，实际替换正在使用的数据库仍需另行数据操作授权。

支持的已有凭据只包括：

- 旧模块密码；
- 旧恢复密钥；
- 旧 PIN，以及显式指定的 `class_teacher_work.db`，用于在原 Windows 用户下只读取得旧内部密码。

## 页面信息层级与操作

- 一级入口仍只有“班主任工作台”。
- 二级工作面仍只有“首页、日历、事务、学生”。
- 首页主要操作仍是发送并整理、继续已有交接；日历仍查看节点和关系；事务仍推进步骤并保存教师决定；学生仍查看和补录相关记录。
- 一次性转换不占页面层级，不注册前端路由、菜单、按钮或日常 API。
- 页面中不再声称草稿保存在“加密保险箱”，但草稿位置和 7 天过期规则不变。

## 本次包含

- 删除日常 PIN 初始化、PIN 解锁、旧密码解锁、恢复后改密、锁定、续时、改 PIN、改密码及恢复密钥确认接口。
- 删除正常运行仍可创建新加密库、写入新密文的后端分支。
- 删除正常页面遗留的保险箱客户端、空会话参数和空会话请求头；保留与本机页面识别有关的现有客户端标记。
- 正常运行的记录仓库固定为明文 JSON；旧密文解读只能被离线转换模块调用。
- 正常启动对旧库只读识别，跳过会写入旧库的自动补表和中断恢复。
- 新增一个离线转换模块和一个薄命令入口；不注册为 FastAPI、页面、后台任务或工作台模块。
- 更新当前架构、产品范围和历史清理记录，消除“当前仍有日常加密保险箱”的过期描述。
- 只使用临时目录中的合成数据库进行验证。

## 本次不包含

- 不读取、复制、修改或替换真实 `user_data`。
- 不改变当前明文数据库中的业务内容、字段含义、页面操作步骤或业务结果。
- 不改变普通 ZIP 备份、普通恢复和默认包含班主任数据的范围。
- 不恢复已经退役的 `.ctbackup` 专用备份。
- 不给旧加密设计增加新的加密方式、传输方式、口令流程或兼容层。
- 不重命名历史表，也不为当前明文库执行数据迁移。
- 不自动把转换结果替换成正在使用的数据库；该动作以后必须针对精确文件另行授权。
- 不调用真实模型，不使用真实密钥，不启动真实服务。

## 复用与不复用

直接复用：

- 旧格式现有的密钥推导、密文打开和固定版本标识，只用于读取旧库；
- 旧记录原有的字段绑定规则和当前 `plaintext-json-v1` 明文标记；
- Windows 当前用户的只读解包能力，用于旧 PIN；
- SQLite 自带的一致副本、完整性检查和外键检查；
- 当前业务服务、页面、普通备份接口和数据库表结构。

明确不复用：

- 不复用 `VaultService.unlock` 或旧 PIN 服务：它们会更新源库、创建会话或包含新加密写入能力。
- 不复用数据库原地替换方法：本阶段转换必须写到全新的输出文件。
- 不复用正常页面和后台任务系统：转换不是日常业务流程。
- 不建立第二套可扩展策略或注册表；当前只有一种真实转换实现。

## 最小必要后端行为

1. 正常班主任服务始终按明文模式工作，没有启用加密的开关。
2. 正常服务首次读写前只读检查旧格式；发现旧库立即停止该次业务操作。
3. 当前明文库仍按原来的版本规则补表和恢复中断事务；旧加密库不进入这些写入步骤。
4. 离线转换器只读源库，把业务记录写入同目录的临时候选，检查通过后原子发布到尚不存在的输出路径。
5. 转换后保留记录编号、类型、版本、创建时间、更新时间和业务正文；只把存储形式改为当前明文格式，并清除候选文件内的旧锁库元数据。

## 故障场景

- 密码、PIN 或恢复密钥错误：停止，源文件和输出路径均不变。
- PIN 对应的普通工作库缺失、不是原 Windows 用户或状态损坏：停止，并提示改用旧密码或恢复密钥。
- 源文件不是支持的旧库、版本未知、存在明密混合记录、JSON 损坏、完整性或外键检查失败：停止，不发布结果。
- 源路径与输出路径相同：拒绝执行。
- 输出文件已经存在：拒绝执行；不提供强制覆盖。
- 输出路径位于正在使用的班主任工作区内：拒绝执行，避免普通备份收进第二份明文库。
- 转换中断：源文件不变；下次运行只清理本工具命名的未发布临时文件。
- 发布前失败：删除临时候选；发布后输出一定是已经完成全部检查的候选。
- 重复转换：同一输出路径已存在时不做任何写入；换一个全新输出路径可以重新执行。
- 正常启动遇到旧库：不得先执行数据库补表、锁库恢复或其他写入。

## 验收条件

- 正常后端路由中没有 `/vault/*` 日常接口，也没有取得或更新解锁会话的入口。
- 正常生产代码无法创建加密库或写入新的密文记录。
- 前端构建、路由和页面没有保险箱客户端、PIN、锁定、解锁、改密、迁移入口或空解锁会话头。
- 首页、日历、事务、学生四个工作面直接打开，页面结构、操作和业务结果不变。
- 当前明文合成库可保存、重开和读取；普通备份仍默认包含班主任工作台，普通恢复流程不变。
- 合成旧密码库、旧 PIN 库和恢复密钥路径均可转换为独立明文候选；业务记录和版本信息一致。
- 错误凭据、损坏记录、中断、目标已存在和重复执行均不改变源文件。
- 正常启动只读识别合成旧库并阻断班主任读写，不修改旧库字节和附属文件。
- 受影响测试、前端类型检查、构建和文档引用检查通过，最后完成一次需求复审和一次代码质量复审。

## 风险等级

整体风险为高。原因不是当前页面改动，而是旧库转换必须保证每条历史记录不丢失且源文件绝不改变。通过“只写新输出、没有强制覆盖、全部通过后再发布、只用合成库验收”把本阶段的实际实施风险降到可回退范围。
