## 结论

两家网站的目录都适合作为“候选词来源”。用户已经明确不做长期抓取，也不把外部目录直接作为产品词表，而是只观察一次，再由本地重新分类、去重、定义和审核。这个工作流技术上可行，不需要开发持续联网的爬虫。

- 质量上，两家的核心知识覆盖接近；菁优网的应用模型更广，学科网“组卷”的知识层级更容易逐层核验。
- 实施上，学科网“组卷”当前可在普通未登录浏览器中展开到末级，并能保留 `zsd...`、`jtff...` 来源路径；菁优网现代交互页在游客模式下会跳转登录。
- 因此本项目只选择**学科网“组卷”作为一次性参考母本**。外部树只进入来源快照和候选层，不直接成为 AI 词表。
- 不启动全量自动抓取，不调用隐藏接口，不绕过登录或验证；正式进行完整目录整理前仍需重新核验当时的网站规则和使用边界。

采集前的本地词表确实只是起步规模：70 个规范知识点、10 个能力、16 个思想方法、21 个数学模型。它不足以覆盖成熟初中数学题库，但外部树仍不能原样成为产品词表。

## 已确认的公开目录形态

### 菁优网

[初中数学知识点挑题页](https://www.jyeoo.com/math/ques/search?f=1)在未携带登录会话时可返回完整页面框架。公开页面明确提供“知识点列表”和“解题模型/方法”入口，并说明只有末级考点可选、多个考点可以按交集或并集筛选。其公开知识点页面还能看到“数与式、方程与不等式、函数、图形的性质、图形的变化、统计与概率”等一级分类，例如[初中数学知识点公开页](https://www.jyeoo.com/shiti/zsd/czsx/300/)。

## 质量比较与单一来源推荐

### 比较口径与证据等级

本节只比较“适不适合成为本项目的一次性参考母本”，不比较两家题目正文质量。统一口径是：

1. 初中数学核心知识覆盖是否可确认；
2. 层级是否清楚，叶子边界是否稳定；
3. 知识点、思想方法、数学模型和应用场景是否容易拆开；
4. 是否能保留来源节点编号、路径和版本；
5. 转成本项目五维词表所需的人工整理量。

两家都已经由公开产品页、用户截图和本次普通浏览器抽查交叉核验。菁优网公开静态页只能看到一级目录，现代交互页在游客模式下会跳转登录；学科网“组卷”当前可以在未登录状态逐层展开到末级。因此，以下判断同时考虑内容质量与用户指定的“一次人工读取、回到本地重分类”的实施成本。

| 维度 | 菁优网 | 学科网“组卷” | 当前判断 |
|---|---|---|---|
| 知识覆盖 | 六个核心一级域齐全，并有竞赛、衔接分支；公开资料表明叶子数量丰富 | 六个核心一级域齐全，另有观察/证明、实践应用、向量、五四制衔接和竞赛分支；实测代数、函数、几何、统计路径均能继续展开 | 核心覆盖基本相当，学科网本次可核验的细节更多 |
| 层级与粒度 | 明确规定只有末级考点可选，并提供目录纠错；公开静态页看不到完整深层树 | 实测可达四至五层，末级粒度非常细；父节点和筛选节点都有 `zsd...` 路径 | 学科网更适合本次逐层读取，菁优网的维护机制更明确 |
| 解题方法/模型覆盖 | 应用问题和解题模型更广，能看到行程、工程、销售、鸡兔同笼以及多种几何模型 | 几何构型和专题模型很丰富，反比例函数也有模型分支；但一般思想方法目前只看到换元法、特殊值法 | 内容广度菁优网略胜；可直接读取性学科网明显胜 |
| 分类边界纯度 | 模型树混有知识点、题型和应用场景 | 知识点树混入解法、综合题型和模型；方法树混入章节、构型、模型和具体作法 | 两家都不能原样导入，必须本地重分类 |
| 来源追踪 | 动态页需要内部标识，但未登录时不易逐层稳定记录 | 每次选中节点都会出现 `zsd...` 或 `jtff...` 路径，便于保存来源快照 | 学科网更适合这次一次性留痕 |
| 静态导出/API | 开放平台、考点标注和数据定制路径更明确 | 有开放平台，但尚未确认纯目录导出 | 若走正式数据合作，菁优网更有优势 |
| 人工转化成本 | 现代交互页当前会要求登录，公开静态页只能看到一级域；模型树仍需重分 | 未登录即可逐层展开，能直接转成层级文字；之后仍需剔除超纲节点并拆分维度 | 按用户指定的人工一次性参考方式，学科网成本更低、漏项风险更小 |

### 推荐

若只选一家，按用户已经明确的实施方式，**推荐学科网“组卷”作为这次一次性参考母本**。

这不是判断它在所有方面都优于菁优网，而是综合结论：

- 两家的核心知识点覆盖接近，学科网当前能直接逐层读取到末级，且路径中有可记录的来源编号；
- 学科网的知识树粒度足以覆盖概念、性质、定理、运算、应用和常见构型，适合先形成候选池；
- 它的解题方法树虽然在一般思想方法方面偏薄，但本项目本来就不会照抄来源分类；思想方法和能力维度应依据课程标准及本地教研规则补齐；
- 菁优网在应用模型广度和正式开放合作方面更强，但当前人工逐层读取受登录限制，且原始模型树同样存在混类，作为本次唯一母本的实际收益不足以抵消采集成本。

选择学科网后仍执行“三层分离”：

1. `source_snapshot`：只记录本次看到的原始名称、父路径、页面入口、观察日期和来源标识；
2. `taxonomy_candidate`：由本地规则拆分、去重、改名并补充定义，不直接提供给 AI；
3. `canonical_taxonomy`：人工确认后生成本项目稳定编号，才进入 AI 可选词表。

外部页面显示的节点编号即使能读到，也只进入 `source_ref`，不作为 `canonical_id`。这可以保证外部目录以后改名或改层级时，本项目已经确认的题目标签不会漂移。

## 服务规则与采集边界

### 菁优网

[菁优网 robots.txt](https://www.jyeoo.com/robots.txt)允许部分 `/shiti/` 页面，但禁止 `/api*`、`/content*` 等路径。`robots.txt` 只是爬虫访问指引，不是内容复制许可，也不能覆盖服务协议。

[菁优网服务条款](https://www.jyeoo.com/home/note)将页面内容的设计、结构、选择、协调、表达和排序列入受保护内容，并限制未经书面同意的复制、再制、传播或商业使用；用户行为规则还限制技术抓取用户数据、监测、高频访问和长期逐页抓取。

菁优网同时提供正式的[资源开放平台](https://www.jyeoo.com/open)和[题库 API 合作](https://www.jyeoo.com/open/quesapi)。其[开放平台协议](https://www.jyeoo.com/open/note)明确说明数据 API 需申请、审核、付费或线下协议，并表示未经同意采集平台数据可能导致停止服务和维权。因此，向开放平台申请“仅知识点/模型目录的单次静态导出或授权”是优先方案。

### 学科网“组卷”

[学科网用户注册协议](https://tsso.xkw.com/user/agreement)限制私自复制、发布、转卖或向第三方提供资源内容，也明确限制使用技术手段进行高频访问和长期逐页逐项抓取。协议还将界面设计、版面框架、数据、程序和文档等列为受保护信息。

该协议没有直接写明“低频、一次性目录采集一定获准”。一次性和低频可以降低系统负载风险，但不能自动解决内容授权、结构复制和后续产品分发问题。页面已经出现反自动化验证，也不应通过验证码处理、Cookie 计算、接口猜测或其他方式绕过。

[学科网开放平台](https://open.xkw.com/)确实存在，但本次无法从其公开 JavaScript 文档确认目录导出接口。若要采用该来源，应先向学科网确认是否能提供初中数学知识点树、解题模型树的静态文件或授权 API。

## 技术可行性判断

| 方案 | 技术可行性 | 合规与维护风险 | 结论 |
|---|---|---|---|
| 自动遍历公开页面/动态接口 | 菁优网中等；学科网受反自动化验证阻挡 | 高，且难以证明完整性和稳定性 | 当前不执行 |
| 人工逐项抄录完整树 | 可行但耗时，易漏层级和节点编号 | 仍存在完整结构复制风险 | 不推荐 |
| 官方静态导出或授权 API | 高，能保留稳定 ID、层级和版本 | 最低，许可范围可追溯 | 推荐 |
| 仅观察两站后自行编写新树 | 可行 | 不能机械照抄选择与编排；仍需教研校验 | 可作为无授权时的备选 |

即使取得许可，也只需要进行一次目录采集，不做定时刷新。采集程序应满足：

1. 只读取节点编号、名称、父节点、完整路径和来源版本，不读取题目、答案、解析、图片、账户或用户数据；
2. 单线程、低速运行，遇到登录、验证码、反自动化页、`401/403/429` 立即停止；
3. 不保存 Cookie、账号凭据或反自动化参数；
4. 保存授权依据、来源 URL、采集时间、源版本和文件指纹；
5. 原始来源快照与本项目规范词表分离，导入后不再联网刷新。

## 导入后的分类规则

外部树不能直接成为 AI 词表，必须先进入“候选层”，再由本项目的标签边界整理：

| 本项目维度 | 接收内容 | 不应混入 |
|---|---|---|
| 教材章节 | 七至九年级、上下册、章和节的教材位置 | 期末复习、同步练习等使用场景 |
| 知识点 | 概念、性质、定理、公式、运算及其直接应用 | 泛化能力、解题套路名称 |
| 能力 | 运算、推理、抽象、几何直观、模型观念等课程能力 | 网站知识点或题型名称 |
| 思想方法 | 数形结合、分类讨论、转化与化归、整体思想等跨知识点策略 | 具体几何构型 |
| 数学模型 | 一线三等角、手拉手、将军饮马、鸡兔同笼等可复用问题结构 | 单纯知识点、一般能力 |
| 子技能 | 不再保留 | — |

容易混淆的节点必须通过人工规则处理。例如“配方法”在特定章节可作为具体解法，但在跨题型使用时又具有方法属性；“鸡兔同笼”应作为应用问题模型，并通过关系边连接“二元一次方程组应用”，而不是成为其同级知识点。

## 知识图谱 2.0 的来源标注

取得授权并导入后，每个规范节点建议至少保存：

- `canonical_id`：本项目稳定编号，不使用网站显示名称充当主键；
- `kind`：`curriculum`、`knowledge`、`ability`、`method` 或 `model`；
- `name`、`aliases`、`definition`；
- `parent_id` 和完整规范路径；
- `source_refs`：来源网站、来源节点编号、来源路径/URL、观察时间、授权或许可编号；
- `curriculum_links`：与教材册、章、节的多对多关系；
- `relations`：`part_of`、`prerequisite_of`、`uses_method`、`instantiates_model`、`related_to`；
- `review_status`：`candidate`、`approved`、`merged`、`rejected`、`deprecated`；
- `taxonomy_version`、审核人和审核时间。

同名节点来自两个网站时，不直接创建两条正式标签：先保留两个 `source_ref`，人工确认含义一致后合并到一个内部稳定节点。名称相近但含义不同的节点必须分别定义，不能只靠字符串相似度自动合并。

## AI 新词的长期收敛机制

成熟外部词表只能降低“没有可选词”的概率，不能完全禁止新概念出现。推荐的持久规则是：

1. AI 正常标签只能选择 `approved` 节点的稳定编号；
2. 确实无法匹配时，AI 把内容放入独立的 `proposed_tags`，必须同时返回拟归属维度、定义、理由、最接近的现有节点和无法复用的原因；
3. 新词在页面中高亮显示，默认不进入正式筛选器，也不能自动成为下一批 AI 的候选词；
4. 教师可以修改、删除、驳回、合并到现有词或批准为新节点；
5. 只有批准后才生成稳定编号、登记别名、写入新词表版本，并从下一批请求开始提供给 AI；
6. 对词表的每次新增、合并和停用保留审计记录，旧题仍能按稳定编号回溯。

这样既允许词表成长，也不会让模型的一次自由发挥立即污染整个题库。
