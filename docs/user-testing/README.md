# 用户自测与正式验收

本目录面向实际使用系统的老师。技术测试、日志分析和结果记录由 Codex 负责；用户只需要按清单编号操作并判断页面与流程是否符合使用习惯。

## 你需要做什么

1. 使用 Codex 提供的唯一地址，先确认页面持续显示“用户验收模式”。
2. 按当前清单的编号逐步操作，一步只做一个动作。
3. 遇到异常时停止，并回复“步骤编号 + 看到的现象 + 截图”。
4. 正式门槛结束时明确回复通过或不通过。

你不需要运行命令、编辑 Markdown、判断技术日志或解释数据库与堆栈。

## Codex 负责什么

Codex 负责准备隔离数据、启动和关闭服务、提供地址、执行自动测试与多视口检查、记录真实数据库指纹、整理用户反馈并分析失败。需要修复时，Codex 把问题退回对应执行包，不要求用户判断内部实现。

## 测试节奏

- 可见前端批次：每批完成后安排 5-10 分钟短测。
- 纯工程或不可见改动：默认不要求用户测试。
- P1-29：当前 Streamlit 与后端改造的黑盒基线，预计 20-30 分钟。
- P2-08：单题复核样板页正式验收，预计 30-45 分钟。
- P2-20：授权副本完整五流程，预计 60-90 分钟。
- P2-21：新启动入口、刷新、重启、深路由与 Streamlit 回退，预计 15-20 分钟。

## 数据安全

- 日常短测、P1-29、P2-08 和 P2-21 使用固定、可重置的合成演示数据。
- P2-20 只使用用户对该次验收明确授权的考试副本，不直接打开原始数据。
- 页面没有持续显示“用户验收模式”时不要继续操作。
- 不在验收模式输入真实 API 密钥，也不启动清单范围外的 AI 调用。
- 真实数据库、学生答卷、导出、密钥和未脱敏截图不得提交 Git。
- 截图若包含姓名、答卷或密钥，先脱敏；原始截图默认只用于当前对话排查。

## 启动与恢复

Codex 会说明已经执行的启动动作、访问地址、预期标识和关闭方式。只有 Codex 明确要求时才重置演示数据；重置失败时不得改用真实 `user_data/`。出现 Blocker 或 Major 后保留隔离现场，关闭服务并回到对应执行包修复。

## 反馈格式

正常结果只需回复步骤编号和“通过”。异常示例：

```text
步骤 3 + 点击确认后页面一直加载，分数没有变化 + 截图
```

## 结果

| 等级 | 处理方式 |
|---|---|
| Blocker | 立即停止；启动失败、误用真实数据、数据损坏、最终分错误或核心流程无法继续都属于此级别 |
| Major | 正式门槛失败；关键状态错误、输入丢失、页面无法操作或导出不一致都要退回修复 |
| Minor | 记录不影响操作的视觉或文案问题，由用户决定是否阻塞 |

Blocker/Major 未清零时正式门槛不能通过。只有用户明确确认后，正式验收才记录为 `passed`。

## 文档结构

- `USER_TEST_TEMPLATE.md`：Codex 生成短测卡和正式清单的固定模板。
- `checkpoints/`：只保存已经实现并可运行页面的版本化清单和结果，不提前猜测未来界面。
