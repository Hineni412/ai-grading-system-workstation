# Domain docs

本项目采用 single-context 领域文档结构。

## 阅读规则

开始探索或设计前：

1. 先遵守 `AGENTS.md` 的必读顺序。
2. 阅读 `ARCHITECTURE.md` 中已经实现并核验的系统事实。
3. 如果存在根目录 `CONTEXT.md`，使用其中统一的业务术语。
4. 如果 docs/adr/ 已建立，阅读其中与当前改动相关的架构决定。
5. 正式执行包继续读取 Index、Phase map 和当前即时计划。

`CONTEXT.md` 和 ADR 不替代业务事实来源、执行包状态或用户决定。

## 建立方式

- `CONTEXT.md`：在首次真正需要统一领域术语时由 `domain-modeling` 建立。
- docs/adr/：在首次形成需要长期保留的架构决定时建立。
- 不为了初始化创建没有实际内容的空文件。
- 新文档必须避免真实学生数据、密钥、内部绝对路径和未脱敏日志。

## 使用原则

输出中的业务概念优先采用 `CONTEXT.md` 已定义名称，不随意创造同义词。如果方案与现有 ADR 冲突，必须明确指出并请求决定，不能静默覆盖。
