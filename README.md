# AI 阅卷系统

这是一个在本机运行、由教师本人使用的初中数学工作系统。它把考试阅卷、知识与训练、备课、班主任事务放在同一个页面入口中。

系统只监听本机地址，默认访问地址是：

`http://127.0.0.1:8035/`

## 启动与关闭

### 启动

双击根目录的 `运行.bat`。

在开发源码目录或 worktree 中，每次启动都会先重新构建 `frontend` 前端页面。构建成功后才会启动服务；构建失败时不会退回到其他页面。便携包不带前端源码，启动时直接检查并使用包内已构建的 `frontend/dist`。

启动需要：

- 项目随附的便携 Python，通常位于 `runtime\python\python.exe`；
- 开发源码目录还需要与当前前端依赖兼容的 Node.js 和 `npm.cmd`；仅使用完整便携包时不需要；
- 本机端口 `8035` 未被其他程序占用。

如果当前目录是项目的 linked worktree，启动脚本也会查找主项目中随附的便携 Python。

### 关闭

优先双击 `关闭系统.bat`。它使用 PowerShell 7 关闭本项目在 `8035` 端口上的服务。

也可以关闭启动时出现的服务窗口。关闭后，浏览器页面将不能继续保存或读取数据。

## 四条常用流程

### 考试与阅卷

1. 建立考试，导入学生、试卷、答卷和评分依据。
2. 确认模板与答题区域，再启动扫描归卷和阅卷。
3. 处理待复核项，教师确认最终分数。
4. 在结果中心查看统计、报告和导出文件。

AI 给出的分数只是候选结果。教师锁定的最终分数始终优先；识别失败或证据不足不会被当成零分。

### 知识与训练

1. 在题库中整理题目，并把题目连接到当前知识标准。
2. 结合已确认的考试结果和已发布的训练证据查看当前掌握度。
3. 选择学生与训练目标，生成个性化训练草稿。
4. 教师确认训练判定点，打印、扫描、判定并发布结果。

训练判定点不计考试分数，只记录达成、未达成、不确定或无法读取。缺少证据表示“未知”，不表示“零掌握”。

### 备课工作台

1. 按学期、单元和课时组织备课对象。
2. 定位教师选择的资料、题库内容和匿名学情证据。
3. 形成有来源的备课草稿与课件改编方案。
4. 需要 WPS 输出时，在隔离副本上生成结果并由教师复核。

备课工作台默认启用。它不会覆盖原始 PPTX，也不会把备课结果写回知识与训练数据。

### 班主任工作台

1. 通过持续对话记录待整理事项。
2. 把草稿分流到学生、事务、计划、流程或支持记录。
3. 教师检查 AI 建议并决定是否正式保存。
4. 教师本人决定外发、处理、结案和后续跟进。

班主任工作台当前启用。AI 不作诊断、欺凌认定、惩戒决定、紧急裁决、自动外发或自动结案。

## 数据放在哪里

运行脚本默认把数据放在当前项目或当前 worktree 的 `user_data` 中。

主要内容包括：

- 考试、题库、学生、答卷、结果和导出文件；
- `user_data\workspaces\teaching-prep` 中的备课工作区；
- `user_data\workspaces\class-teacher` 中的班主任工作区；
- 本机模型配置和运行状态。

这些目录可能包含学生姓名、成绩、答卷、备课资料和班级事务。不要把 `user_data` 上传到代码仓库、普通聊天、公开网盘或不受控日志，也不要直接移动、覆盖或删除其中的数据库文件。

班主任工作区当前使用本机 SQLite 明文保存，没有 PIN、密码解锁或自动锁定保护。能读取该 Windows 账户文件的人，可能读取其中内容；请使用受控的电脑账户、磁盘保护和访问权限。

## 备份与恢复

普通备份可以按范围选择：

- 阅卷与题库；
- 备课工作台；
- 班主任工作台。

备课和班主任工作区都不会因为位于独立目录而自动失去备份能力；是否进入某次备份取决于所选范围。

API 密钥默认不进入普通备份。模型诊断日志也不属于普通业务备份。备份完成不等于恢复一定成功，重要考试或大批量操作前应确认备份范围，并在安全副本上验证恢复。

恢复会覆盖数据，必须先确认精确目标、现有备份和回退方式。

## 外部模型与费用

只有配置并启用模型后，系统才可能把选定内容发送到对应模型服务商。一次请求可能包含题目、答卷片段、备课材料或班级事务文字，具体取决于教师启动的功能。

发送前请确认：

- 接收方、模型和账号是预期配置；
- 内容适合离开本机；
- 服务商的保存与隐私政策符合使用要求；
- 可能产生的费用和调用次数可以接受。

模型可能超时、拒绝请求、返回格式错误或给出不可靠建议。不要把模型输出直接当作最终评分、教学事实、学生诊断或处置决定。

## 出现问题时

- 启动失败：保留命令窗口中的完整提示，先检查便携 Python、端口占用和 `frontend/dist`。从源码目录启动时，还要检查 Node/npm 和前端构建。
- 页面打不开：确认服务窗口仍在运行，并访问 `http://127.0.0.1:8035/`。
- 保存失败：不要反复覆盖或手工改数据库，记录页面提示和操作时间后再排查。
- 数据或恢复问题：停止写入，保留现有文件与备份，不要自行清理 `user_data`。
- 模型调用不确定：不要重复点击；先查看任务状态和本机受控诊断，再决定是否重试。

面向开发与维护的当前事实入口见 `docs/README.md`。
